## 0. 一句话结论

配方的正确位置不是「和 spec 二选一的结构起点」，而是**「意图卡的结构起点裁决 → 故事板九节 → spec → manifest」这条链路的最上游**。项目里已经给这个位置留了字段（`structure` 三选一）和闸（`write_storyboard` 前必须见意图卡），但三选一里的「配方卡」这一档**没有任何机器判据能选中它**，且裁决结果**没有任何持久化字段承接**。所以配方从未被真正用上——不是选错了，是走不到。

补两张卡（`ORB1` 轨道演示、`DAT7` 节拍赛跑）解决的是第二个缺口：现有 58 张卡**没有一张产出 `orbit` 轨**，模型遇到「月亮绕地球」只能写脚本手改 manifest，下一轮 `scaffold_manifest` 必冲掉。卡库是配方的前置依赖，不是配套工作。

- **底层原语（位置来源三选一，互斥）**：① `orbit?: OrbitMotion{center,radius,startAngle?,periodInFrames?,direction?}`（`manifest.ts:427-438`）—— **只有单一 `radius`，求值是正圆**（`timing.ts:1003-1006`）；② `animate?: Animate | Animate[]`（`manifest.ts:235`，段结构 `:402-415` 为 `{from,to,startFrame?,durationInFrames?,easing?}`）—— **多段按维度独立选段**（`timing.ts:680-726`：取窗口含本帧的最后一段，窗口外保持首段起点/末段终点）⇒ 一条轨声明 N 段 `x/y` 接力就是**任意折线轨迹**（CV-336 的注释明写这条语义就是为「公转/环绕被钉在起点」修的）；③ `transform.x/y` 静态。**一条轨只能一个 orbit，没有多体原语、没有 cloud/壳层原语**（全仓搜 `cloud|shell|概率云|壳层` 零命中）。
- **折线能贴椭圆**（决定 ORB1 能否演「近地点/远地点」）：椭圆参数方程 `p(θ)=center+(rx·cosθ, ry·sinθ)` 采样 N 段、`easing:'linear'`、段窗首尾相接 = 真椭圆；偏差按弦高 `r·(1−cos(π/N))` 估：1920 宽、轨道半径 r≈384px 时 16 段 ≈7.4px（能看出多边形）、32 段 ≈1.9px、44 段 <1px ⇒ **默认 32 段**，或按 `N = ceil(π/acos(1−tol/r))` 自适应（tol=2px）。体积账：单点 32 段 ≈4KB，8 个绕行点 ≈34KB，可接受。折线轨的 `exit` **不会跳**（`exitStateAt` 的 `from` 取 `animateStateAt(track, window.start)`，`timing.ts:790`），这点比 orbit 好。
- **尺寸是独立维度**：`VISUAL_DIMENSIONS` 只有单值 `scale`（`timing.ts:599`），与 `x/y` 互不覆盖 ⇒「近点大、远点小」用独立 animate 段做，相位由卡内按 `periodInFrames` 算。**没有 `scaleX/scaleY`** ⇒ 不能把单个元素非等比拉长（要椭圆只能拉轨迹，不是拉元素）。
- **3D 容器备选**：`type:'group'` + `children`（`manifest.ts:1004-1021`）统一做 `perspective(1200px) rotateX/Y`，**`|角度|≤30°`**（`Group.tsx:17-19`：≈−38° 整块静默消失，契约层拦）；子轨禁止 3D 维度、时间相对组起点。语义 = 轨道面倾角，扁率上限 cos30°≈0.87。
- **反面教材**：`skills/code-driven-explainer/references/shot-cards.md:200-207` 的 `E3 公转徽标` 示例写 `animate:{from:{orbit:{angle,radiusX,radiusY}}}` —— `orbit` 是**轨级字段**、不是 `animate` 维度，`OrbitMotion` 也没有 `angle`/`radiusX`/`radiusY`。**椭圆本身能做**（见上），错的是「把 orbit 当成 animate 的维度、还写成 radiusX/radiusY」。本轮 ORB1 落地时顺手改掉该示例（改成多段 `animate` 的 `x/y`，或 `orbit` 单 `radius`）。
- **没有任何卡产出 orbit 轨**。最接近的 `UI6`（`recipe-cards-ui.ts:121-139`）画 path+draw，`FX3`（`recipe-cards-effects.ts:78-107`）画 path+draw 加 animate 折线——都是近似，不是轨道运动。
- **没有结构化数值通道**。`CardRenderContext` 无数值字段；`copy` 的「键:值」解析是各卡内联（B1 `recipe-cards.ts:430-436`、DAT3 `recipe-cards-data.ts:80-81`、DAT6 `:176-183`），且 B1 只取前 4 项、DAT3 把非数解析成序号。

## 3. 目标流程（正确用法）

### 3.1 完整链路

```
用户原话
  → 意图卡（第 3 轮）：结构起点三选一，机器判据裁决
  → write_storyboard（第 4 轮）：配方参数填进九节
  → 事实快照 / TTS 真值（§01 / §03）
  → spec（屏表 + units + carry + 句起点）—— `recipeToStoryboardSeed` 同批产 `specSeed`（§3.4.1），模型改写而非从零编
  → scaffold_manifest(specPath)
  → render_composition(draft) → R1–R6 逐层丰富
  → F6 patch_segment_tracks / rerender_segment（只做屏级增量）
  → 交付
```

**关键原则**：配方只负责「结构起点」，不负责成片；故事板是创作资产 SSOT，spec 与 manifest 从它派生；F6 只做增量，不改 spec 轨。

### 3.2 结构起点裁决规则（取代现行一行口径）

### 3.3 `list_recipes({requirements})` 规格（新增工具）

照 `list_templates` 的形态做（`src/host-tools-template.ts:41-169`），文本清单输出、不额外引入 JSON 通道。

- **入参**：`requirements{contentChars, itemCount, assetCount, stageSeconds, totalSeconds}`，字段名沿用 `list_templates` 的读取器（`host-tools-template.ts:20-39,62-78`；读取器实测 6 字段，另含 `durationSeconds`——本工具判据不消费时长项，同源照搬即可）。
- **判据**（每条给 ✅/❌ + 理由，同 `gateTemplate` 的输出风格）：
  1. 段数：配方段数 ≤ 期望屏数上限（期望屏数由 `totalSeconds / stageSeconds` 推）；
  2. 素材：`assets.length ≤ assetCount`，且 source 只能是 `user` / `library`（配方声明的素材要能在故事板 §07 落地）；
  3. 主题：`recipe.theme` 能被用户接受（缺省主题可覆盖，但要显式提示）；
  4. 表达力：配方段卡的 `assets === []` 或声明齐全；若需求含「中心体+绕行」等物理演示，必须有对应演示卡（`ORB1`）在册，否则判 ❌ 并指名缺口；
  5. 互斥：`specPath` 已给 ⇒ 本工具不参与裁决。
- **输出**：每个配方一个 block（id/title/段序列/素材/`note` + 判据逐条），尾部结论「1✅ → 可用；0✅ → 自由编排；≥2✅ → 列给用户」。
- **注册**：加入工具清单时同步更新 `tests/tool-registry.test.mjs:55-135` 钉死的全量名单（当前 55 / 关模板 54）——这是硬闸，不更新必红。
- **参数接线**：修 `src/host-tools.ts:5133`，把 `assetSlots` / `accentColor` 从工具入参传到 `planRecipe`；schema 增 `assetSlots`（`Record<segmentId, Record<slot, url>>`），避免配方素材永远降级。
- **enum 补齐**：`src/host-tools.ts:5006` 的 recipe enum 加入 `product-promo-60s`，与 `RECIPES` 的 `Object.keys` 口径一致；配套测试断言 enum 覆盖全部 `RECIPES` 键（现行门禁盲区）。

### 3.4 配方 → 故事板九节的落点契约（新增纯函数 `recipeToStoryboardSeed`）

**不做临时脚本，不做字符串拼接**。新增一个纯函数模块（建议 `src/remotion/recipe-to-storyboard.ts`），输入 `Recipe` + 需求，输出 `Partial<StoryboardSections>` 可直接喂 `write_storyboard`。**暴露载体（D7 拍板）**：seed 以 JSON 文本随 `list_recipes` 回执给出，模型原样喂 `write_storyboard` 分节参数——不新增独立工具：

| 配方字段 | 故事板落点 | 转换规则 |
|---|---|---|
| `segments[]` | §04 `scenes[].shots[]` | 一段一 scene、一 shot；`id` 用 `S<n>` / `S<n>-Sh1`（符合 `ID_PATTERN`，`storyboard.ts:854-855`）；`duration` 由权重×目标时长；`visual` 由段卡 + `visualAnchor` 生成描述；`frames = round(duration×fps)` |
| `assets[]` | §07 `assets[]` | `status:'pending'`（**记账用，不在这里拦** —— 拦截在落地，见下「必须守住」）、`neededBy:[对应 shot id]`（**修 `recipeAssetsJson` 空 neededBy 的现行行为**）、`source` 原样；`note` 并进 `name` 或 §08 |

### 3.4.1 同批产出 `specSeed`（补「故事板 → spec」这一跳）

全仓**没有 storyboard → spec 的转换器**（§1.4），`patch_spec_section` 只改既有文件。若 seed 只产故事板，配方信息传一半就断，模型得手写一遍 spec。而 `RecipeSegment` 与 `ContentSpec.sections[]` 字段几乎同构，映射成本接近零 ⇒ `recipeToStoryboardSeed` 一并返回 `specSeed`（`Partial<ContentSpec>`）：

|---|---|---|
| `segments[].id` | `sections[].id` | 原样（spec 的段 id 无 `S<n>` 约束） |
| `segments[].card` | `sections[].card` | 卡名原样，`lookupCardId` 规则不变 |

## 4. 两张补充卡

### 4.1 `ORB1` 轨道演示卡

- **类目**：新建 `ORB`（「轨道 / 中心体运动演示」），登记进 `scripts/gen-card-catalog.mjs:51-67` 的 `CATEGORIES`；新文件 `src/remotion/recipe-cards-orbit.ts`，并在 `recipe-cards-all.ts:13-23` 加 import。
- **注册**：`registerCard({id:'ORB1', title:'轨道演示', assets:[...], generate})`；`assets` 至少声明中心体与绕行体的来源（可 `required:false` + fallback）。
- **视觉语法**（不写题材结论）：中心体 circle → 椭圆轨道线（`shape:'path'`，`d` 用两段 `A rx ry` 弧凑整椭圆，`draw` 描边生长）→ N 个绕行点（每条一轨）→ 关键位置停顿 → 标注文字轨。
- **位置来源（D3-b 修订）**：默认 **多段 `animate` 折线**走真椭圆 —— 参数方程采样 32 段（或按 `N=ceil(π/acos(1−tol/r))` 自适应，tol=2px），每段 `{from:{x,y}, to:{x,y}, startFrame, durationInFrames, easing:'linear'}`，段窗首尾相接且 `Σ durationInFrames = 轨长`；`rx === ry`（正圆）时改声明 `orbit` 一行（省体积）。**绝不给 `orbit` 写 `radiusX/radiusY`**（字段不存在）。
- **近远点尺寸**：`scale` 走独立 animate 段（近点倍率由 `scaleNearFar` 给），按 `periodInFrames/2` 分两段（近→远、远→近）；与位置折线**互不覆盖**（`animateStateAt` 按维度独立选段）。**`orbit` 轨同样能加 scale 段** —— 位置互斥是**按维度**判的（`orbitPositionConflict`，`manifest.ts:1616-1636`：只拦 `from/to` 里的 `x`/`y`，`scale` 不触发），所以正圆场景不必为了尺寸脉动改写成折线。
- **轨道线必须与折线同源**：`d` 的两段弧和 32 个采样点都由同一组 `(center, rx, ry, startAngle)` 算出；两处各算一套必然不重合（这是「点不贴线」的唯一成因）。
- **轨道面倾斜（可选）**：把中心体 + 轨道线 + 绕行点打包进 `type:'group'`，容器 `rotateX ≤ 30°` 做透视（子轨禁 3D、时间相对组起点）；文字标注放 group 外，否则跟着倾斜。
- **参数注入**：见 §4.3（结构化数值通道）。至少支持 `radiusX` / `radiusY`（轨道长短半轴，画布百分比；等价入参 `eccentricity`）、`periodSec`、`startAngle`、`scaleNearFar?`、`labels`。
- **退场约束**：折线轨的 `exit` 安全（`from` 取 entrance 读数）。但**若该轨用 `orbit`**，exit 只能带 `opacity` —— 位置被 `exitState` 接管（`animated-style.ts:140-142`），且 `exitStateAt` 起点是中性坐标 ⇒ 带 `x/y/scale` 会瞬移。
- **复用边界**：单体（月亮绕地球）、多体（太阳系）用同一卡的多轨展开；**不支持 cloud / 能级**（D4 已拍板：本轮不做，目录写明边界）。
- **确定性**：同 ctx 两次 `generate()` 逐字节一致（`tests/req038-cards-catalog.test.mjs:79-86`）；产物过 `validateManifest`（`:36-51`）。

> **D3-b（2026-11-26 评审补记 · 第二版，替代同日第一版「按正圆收」的错误结论）**：椭圆**能做**，不需要改契约，也不需要 `radiusY`。三条事实：① `animate` 是**数组**、`animateStateAt` 按维度独立选段（`timing.ts:680-726`）⇒ 一条轨的多段 `x/y` 接力 = 任意折线，32 段可把椭圆拟合到 ≈1.9px（16 段 ≈7.4px，会看出多边形；r 按 384px 算）；② `scale` 是独立维度（`timing.ts:599`），与 `x/y` 不互斥 ⇒ 近远点尺寸差异可表达；③ `type:'group'` 3D 容器能做 `rotateX ≤30°` 的轨道面透视投影（`Group.tsx:17-19`）。**结论**：ORB1 位置默认走折线采样真椭圆，`orbit` 只用于正圆场景；近远点尺寸走 `scale`；轨道面倾角可选走 group。**限制**：`VisualState` 无 `scaleX/scaleY`，单元素非等比拉伸做不到（但轨迹椭圆不受影响）。约束：§4.1、§6 C2b/C2c、§7.2。
