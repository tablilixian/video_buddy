# TTS 词级时间戳接口需求（转交后端）

> 2026-10-31 · 提出方：Canvas Studio 前端（渲染能力转化批 D1）。**这是给后端的需求文档**，前端侧已把消费口备好（`caption` 轨的 `words` 显式字段，见 `src/remotion/word-timing.ts` 与 `components/Caption.tsx`）——后端一旦提供，渲染层零改动接入。

## 一、要解决的问题

`/api/v1/generate/txt2speech` 目前只返回 `{ filename, duration }`（`duration` 是**生成耗时**，不是音频时长）。前端做逐字卡拉OK字幕时拿不到每个字的发音时间，只能用**离线能量谷对齐**近似：10ms RMS 包络 → 语音区 → 字间谷切分。实测精度 **±1–3 帧 @30fps**，且只在中文慢速 TTS（语速均匀、字间谷可辨）下成立；语速快、口语连读、英文混排时谷会糊掉，退化为近均匀切分。

产品要"逐字卡拉OK"这个能力真正可靠，缺的就是**词级（字级）时间戳**这一个数据。

## 二、需求（按优先级）

### 方案 A（首选）：合成时顺带返回词级时间戳

`txt2speech` 响应增加可选字段：

```jsonc
{
  "filename": "voxcpm_00254.mp3",
  "duration": 3.16,              // 现状：生成耗时（秒）
  "audioDuration": 3.864,        // 建议 1：顺带补真实音频时长（秒）—— 目前前端要自己 ffprobe
  "words": [                     // 建议 2：词级时间戳（秒，相对音频起点）
    { "text": "凌", "start": 0.49, "end": 0.74 },
    { "text": "晨", "start": 0.74, "end": 1.00 }
    // ... 与口播字符按顺序一一对应；标点（，。！？）**不要求**包含
  ]
}
```

约束与验收：

| 项 | 要求 |
|---|---|
| 粒度 | 字级（中文单字 / 英文单词），与文本口播字符顺序一致 |
| 时基 | 秒，相对音频文件起点（前端 ×fps 换算成帧） |
| 标点 | 不要求覆盖；前端会把标点骑在前后字的间隙上 |
| 覆盖 | 覆盖有声区间即可（首字 start ≥0、末字 end ≤ 音频时长） |
| 精度验收 | 一句 12–14 字慢速中文，逐字高亮与音频对齐误差 ≤ ±66ms（±2 帧 @30fps） |
| 兜底 | 字段缺失时前端自动回退能量谷推导（不会因为后端没上而阻断） |

### 方案 B（备选）：独立对齐端点

若合成模型侧拿不到时间戳，提供一个独立端点（例如 `POST /api/v1/align`）：入参 `{ filename, text }`，出参同上 `words` 数组。前端在 `tts_voiceover` 产物落盘后调用一次。

## 三、前端现状（后端同学需要知道的处理链）

- 文本 → TTS mp3 → 前端 `AudioContext.decodeAudioData` → 10ms RMS 包络 → 谷值切分（`src/remotion/word-timing.ts`，纯函数、可单测）→ `caption` 轨逐字高亮（`src/remotion/components/Caption.tsx`）。
- **显式 `words` 永远优先**于推导：后端字段一到，前端把秒 ×fps 填进 `words` 即完成升级，能量谷只做兜底。
- 现有精度基线（能量谷，供对照）：2026-10-30 能力基准 #05 像素验收通过（bench 成片 `~/Desktop/job/VideoOut/remotion-capability-20261029/05-caption-word/cap05.mp4`）。

## 四、非目标

- 不要求音素级时间戳（字级够用；音素是卡拉OK逐内高亮之后的增强，另议）。
- 不要求改音频格式/采样率。
- 不阻塞：此需求未上线前，产品用能量谷兜底照常出片。
