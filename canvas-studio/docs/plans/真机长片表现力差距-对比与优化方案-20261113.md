# 真机 5 分钟片 vs 手写 5 分钟片 · 表现力差距分析与优化方案

- 日期：2026-11-13
- 对比对象
  - **手写版**：`playsoutapi/ops-dashboard/build-5min/`（`make-spec.mjs` 手写 31KB → `manifest-builder.mjs` → 150 轨 / 9000 帧 / 300.0s）
  - **真机版**：`/Users/wl/Desktop/job/VideoOut/new3/projects/Users wl Desktop job/`（会话 `数据解说-真机----`，deepseek-flash，223 次工具调用 / 29 版迭代 / 6 幕分别渲染后 `compose_video` 拼接 → `assets/all-time-5min-final.mp4`，304.4s / 9128 帧 / 216 轨）
- 结论先行：**不是模型画得丑，是版面范式错了一档。** 手写是「密而静」的仪表盘，真机是「疏而静」的幻灯片。两者的动效密度几乎一样，差距全在**单帧信息密度**与**元素是否累积**上。

## 1. 八个可量化维度

| # | 维度 | 手写版 | 真机版 | 差距 |
|---|---|---|---|---|
| 1 | 同屏非字幕元素（全片逐帧均值 / 峰值） | **5.88 / 12** | **2.21 / 4** | −62% |
| 2 | 元素·秒总量（Σ 各轨时长） | 1764 | 672 | −62% |
| 3 | 非字幕轨数量 / 平均停留 | 74 / **23.84s** | 68 / **9.88s** | 数量持平，停留 −59% |
| 4 | 内容包围盒（占画面比例） | **68.8%**（78.3% × 87.9%） | **25.8%**（48.2% × 53.0%） | −63% |
| 5 | 内容像素占比（luma>26） | 13.6% | 4.1% | −70% |
| 6 | 完全静止帧占比（帧差<0.35/255） | 89.6%（0–60s 同段） | 85.0%（0–60s）／83.4%（全片，最长 6.4s） | **基本持平** |
| 7 | 轨型覆盖 | 5 类（textCard / shape / chipRow / callout / chart） | 4 类（textCard / shape / chart / callout） | chipRow 0 |
| 8 | 图表变体覆盖 | 5 种（dual×2 / line×2 / gauge×3 / donut×1 / bars×2） | 2 种（bars×6 / dual×1） | gauge / donut / line 全缺 |

### 1.1 最刺眼的一组数

```
真机：68 个非字幕元素 × 平均 9.88s 停留 ÷ 304s = 2.21 个同时在场
手写：74 个非字幕元素 × 平均 23.84s 停留 ÷ 300s = 5.88 个同时在场
```

**元素数量一样多。** 差的不是"做了几个元素"，是**每个元素活了多久**。真机每 10 秒就换掉一张卡（新卡顶旧卡），手写让卡留在场上堆成版面。

### 1.2 字幕节奏反向偏差

| | 手写 | 真机 |
|---|---|---|
| 字幕条数 / 全程 | 76 | **148** |
| 平均停留 | 3.95s | **2.14s** |
| 字数中位 | 17 字 | 11 字（`MAXLEN=16` 硬切） |

真机的画面元素在变少，字幕却在变碎。观感 = **字幕一直跳、画面一直空**。

## 2. 我最初的假设被数据推翻：差距不在动效

真实机稿时先怀疑"没动画"，实测否掉：

- 手写前 60s 静止帧 89.6%，真机前 60s 85.0%。**手写更"静"。**
- 手写图表也没有 `countUp`（13 处 countUp 全在 dataCard 上），图表一样是静止铺出来的。
- 真机有 31 处 `countUp`、20 处 `animate` 入场，手写 `animate` 字段一次都没用过。

所以"加动画"不是解法。**手写一张静止的满幅 KPI 网格，比真机一张带缩放入场的小卡，信息量高 3 倍。**

## 3. 三条根因链（每条都有代码/产物证据）

### 根因 A：缺「版面基座」层 → 卡片浮在虚空里

| | 手写 | 真机 |
|---|---|---|
| 背景板 `rect`（84–94% 宽 × 50–62% 高） | **9 块**（每板块一块，`rgba(13,20,33,0.72)`） | **0** |
| dotGrid / vignette / 顶部细线 / 横向轴 | 各 1–2 条 | 0 |
| `shape` 总数 | 14 | 7（6 条是全屏渐变底 + 1 条开场琥珀细线） |

手写每一板块先把一块半透明面板铺到 90%×55%，卡片、图表都落在面板里 → 观众读到的是"一个仪表盘"。
真机只有一层全屏渐变，所有内容直接浮在黑底上 → 读到的是"一张卡摆在空房间里"。

这一条直接决定占空比 68.8% vs 25.8%。

### 根因 B：skill 的版面教条是「一屏一个点」，被原样套到 5 分钟片上

`skills/code-driven-explainer/references/explainer-patterns.md` 开篇：

> 目标：让 **30–90 秒**的解说短片「一看就懂、**一屏一个点**」。

真机把它照搬到 304 秒、64 段旁白的数据汇报上，于是：

```
act1 六张 KPI 卡：421–586 → 586–712 → 712–895 → 895–1021 → 1021–1224 → 1224–1355
                  严格首尾相接，零重叠，一张顶一张，共 934 帧（31s）
手写六张 KPI 卡：398 / 474 / 563 / 626 / 626 / 849 陆续入场，
                  全部活到 1350（45s）→ 28 秒时六张同时在屏
```

同一个内容（6 个 KPI），手写是**网格累积**，真机是**逐张过堂**。这不是模型笨，是方法论只教了后者。

### 根因 C：R0–R6 丰富度阶梯里没有「版面」这一档

`SKILL.md` 的阶梯：R0 结构 → R1 真文案 → R2/R3 视觉主体 → **R4 运动** → R5 声音 → R6 定稿。
判据全是"字幕不溢出 / 数字对 / 帧间有变化 / 句起点 ≤1 帧"。

**没有任何一档要求"画面上同时有 N 个元素"或"内容占到画面 X%"。**

真机的行为完全符合这个阶梯：R1/R2/R3/R5 都做了，R4 实质跳过（93% 轨 `fadeFrames:0`、图表无动效），R6 只做了一次"无裁切 / 无空白"抽帧扫描。它**没有失职，是判据里没有这一项**。

## 4. 四个真实缺陷（不只是风格问题）

### 4.1 图表被系统性地压在左栏 54%

`build/gen_specs.py` 的自动布局：

```python
CHART_L = {"x": 30, "y": 58, "w": 54, "h": 40}   # 左栏 3%–57%
CHART_C = {"x": 50, "y": 58, "w": 88, "h": 40}   # 居中 6%–94%
v["box"] = CHART_L if 与任一 dataCard/callout 时间重叠 else CHART_C
```

只要画面上有一张卡在，图表就掉进左栏。而真机的结构是"每句话都配一张卡"，于是 **7 张图里 5 张走了左栏**，右半屏永远空着。手写的图表盒宽是 84/76（居中满幅）。

### 4.2 折线变体的数值标签不吃 `maxValueLabels`（组件 bug，真机版因此降级了图形）

真机会话 step 3.13 自查到：

> `Chart.tsx` 中折线变体的数值标签直接使用 `values.map(...)`，完全不读取 `maxValueLabels`。

复核当前 dev 源码 `src/remotion/components/Chart.tsx:528–548`，**属实**：

```tsx
{track.variant === 'line'
  ? values.map((v, i) => ... )   // ← 全部画出，没有 pickLabelIndices 抽稀
  : null}
```

后果是 20 点折线必定糊成一团。真机的处置是把**时序数据改成柱图**（`a3-line` 实际 `variant: "bars"`，20 根细柱）。一次组件缺陷，换掉了一个图表类型。

### 4.3 三处纯背景段（"空白清零"没清干净）

| 位置 | 时长 | 原因 |
|---|---|---|
| 4.5–9.4s（act1） | 4.9s | 开场标题 136f 淡出，下一元素 281f 才进 |
| 105.7–106.3s（act2 尾） | 0.6s | 幕间空档 |
| 300.1–304.1s（act6 尾） | 4.0s | 结论卡提前退场，片子停在空场上 |

真机自检口径是"每帧有没有卡片"，而这三处都有字幕轨，所以判过了。**判了字幕 ≠ 判了画面。**

### 4.4 图表与旁白互相打脸

`a3-line`（逐月次留率）柱顶是 2025-04 的 **19.77%**，同屏旁白说的是"**最好的月是去年九月**，次留 10.91%"。
根因：2025-04 的 19.77% 只有 **17 个批次 / 35 个用户**（`facts.monthlyRetention[0].cohorts = 17, newUsers = 35`），是统计噪声，不是峰值。图把它画成最高柱，旁白又无视它。

## 5. 优化方案

分三层，按"改了就能挡住下一次"排序。每条给改哪、判据、验法。

### P0 · 组件层（1 条，立即）

**P0-1 折线数值标签接入抽稀**

- 改：`Chart.tsx:528` 的 `values.map(...)` → 与柱状分支同口径
  ```tsx
  const valueLabelIndices = new Set(
    track.maxValueLabels === undefined ? values.map((_, i) => i) : pickLabelIndices(n, undefined, track.maxValueLabels))
  ...
  {track.variant === 'line' && valueLabelIndices.has(i) ? (...) : null}
  ```
- 判据：20 点折线 + `maxValueLabels: 4` → 画面只出现 4 个数字，且互不重叠。
- 验法：扩 `tests/chart-axis-scale.test.mjs`（或新增 `chart-line-value-labels.test.mjs`），纯函数断言抽稀集合；反向变异（改回 `values.map` 全画）必须转红。
- 顺带：`explainer-patterns.md` / `manifest-fields.generated.md` 里删掉"折线不吃 maxValueLabels"这类规避说法（如果存在）。

### P0 · skill 层（3 条，本批核心）

**P0-2 长片（>120s）另立版式范式，废弃「一屏一个点」**

- 改：`explainer-patterns.md` 顶部加适用范围硬边界——`一屏一个点` 只适用于 **≤90s**；>120s 走新的 `references/longform-layout.md`（新增）。
- 新范式的最小定义（三条，可判）：
  1. **基座层必填**：每个板块至少 1 条 `shape:'rect'`，`w ≥ 88%`、`h ≥ 50%`，半透明，作为内容容器。
  2. **同屏累积**：数据卡/图表进场后**不得被下一张顶掉**，与之共存 ≥ 3s；同一板块内元素按 2×2 / 3×2 网格预排 `box`。
  3. **禁止逐张过堂**：连续 ≥3 个非字幕元素首尾相接且零重叠 = 判不合格（这正是 act1 的 KPI 段形态）。
- 判据：生成的 manifest 满足 `同屏非字幕元素均值 ≥ 4`。

**P0-3 R 阶梯补一档 R3.5「版面」**

- 改：`SKILL.md` R0–R6 表插入 `R3.5 版面 | 加基座层 + 同屏编排 | 改 spec → render(draft) | 同屏均值 ≥4、占空比 ≥45%、无纯背景段 ≥1s`
- 理由：现有阶梯从"视觉主体"直接跳到"运动"，**没有任何一档对版面结构负责**。真机版跳过 R4 也没人拦，因为 R3 的判据只有"不超框、数字对"。

**P0-4 长片必须单 manifest，禁止分幕渲染后拼接（或至少强制重叠）**

- 现状：6 幕分别 `render_composition` 再 `compose_video`，接缝处产生 3 处纯背景段 + 12 条 ML-02 硬切。
- 改：skill 明确 >120s 仍走单 `render_composition`（`clamp(片长×2000+120s, 10min, 30min)` 对 300s 片有 22 分钟窗口，真机 CSR 实测 13ms/帧 ≈ 2 分钟即可渲完，余量充足）；确需分幕时，相邻幕必须共享 ≥15 帧重叠内容。

### P1 · 校验层（2 条，挡住"看不见的单调"）

**P1-1 把"版面体检"做进 `render_composition` 回执**

新增 3 条 lint 码（现只有 ML-02 这类轨级规则）：

| 新码 | 判据 | 阈值 |
|---|---|---|
| ML-20 版面稀疏 | 逐帧统计非字幕元素数 | 均值 < 3 或峰值 < 5 → 告警 |
| ML-21 纯背景段 | 只有 `bg` 层可见的连续帧 | ≥ 30 帧（1s）→ 告警并给帧号 |
| ML-22 逐张过堂 | 连续非字幕元素首尾相接且零重叠 | ≥ 3 段 → 告警 |

实现口径：直接复用 `manifest.tracks` 的 `startFrame/durationInFrames` 做区间扫描（纯函数，可单测），不需要渲染。
27 版历史里都有这份 lint 报告，但**29 次渲染共 13 条告警，全是 ML-02，真机一次都没改**——说明"能报出来的才会被修"，报不出来的就永远不会修。

**P1-2 交付前"像素级占空比"复验**

现有 `verification.md` 要求 `spotFrames` + `read_image` 逐张看图，但看图的人（模型）只会检查"有没有裁切/空白"，不会量化密度。
补一条自动化：抽 8 帧 → 缩到 96×54 灰度 → 算 `luma>26` 占比，低于 **8%** 就判"版面过空"。
（本次测量脚本：`docs/archive/2026-11-13-playsout-5min-scripts/coverage-compare.mjs`）

### P2 · 内容与数据（2 条）

**P2-1 小样本伪峰值必须标注或剔除**

- 现象：2025-04 次留 19.77%（17 批次 / 35 人）被画成最高柱，旁白却说"最好的月是九月"。
- 改：`facts-builder` 给每个 retention 点带 `cohorts` / `newUsers`；`Chart.tsx` 支持 `annotations`（在指定点加"样本 35 人"小字），或 builder 侧直接置 `null` 断点。
- 判据：图上任何"极端值"都要么有样本量标注，要么不进图。

**P2-2 字幕按句切，不按字数切**

- 现状 `MAXLEN=16` 把 64 句旁白切成 148 条字幕（2.14s/条）。中文阅读舒适区 ~4 字/秒，11 字/2.14s 已接近上限。
- 改：长片字幕与旁白 1:1（一句一条，允许 2 行），把"碎"交给旁白断句，不交给字幕轨。

## 7. 一句话给下次立项

真机版证明了三件事：**长片链路能跑通（304s / 6 幕 / 64 段旁白 / 42 条 sfx / BGM 全程）、数据抽取准确、自检迭代有效（29 版）**。
它只输在一件事上：**版面**。而版面不是模型能力问题，是 skill 里没有对应的方法与判据——**这正是最值得修的地方：改 skill + 加 lint，比换模型便宜两个数量级。**
