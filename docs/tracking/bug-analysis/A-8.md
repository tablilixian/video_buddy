# A-8 ｜ 分镜表混入元卡片（策略笔记被当成分镜卡落卡）

> 优先级 P0（数据污染：会**原地覆写真分镜卡**）｜ 风险 T2 ｜ 依赖：无
> 截图要点：画布上出现「分镜｜镜：生成路径·参考组合」（13 字）与「分镜｜1/2/3/6·关键帧 i2v…」（62 字）——agent 的生成策略笔记被解析成分镜卡。

## 现象
分镜提交后画布出现非分镜内容的「分镜卡」：标题是生成策略描述，正文极短；「1/2/3/6」这类范围镜号被读成镜 1。

## 代码级原因
- `host-tools.ts:808-819` `parseStoryboardShots`：数据行仅三道过滤——`cells.length >= 3`、非 `---` 分隔行、首格**逐字等于**「镜号」才滤表头。任何含 `|` 的策略行全部通过。
- `host-tools.ts:882-888` `shotNumberOfCell` 用 `/\d+/` **子串**匹配：「1/2/3/6」命中 `1` → `mergeShotCards`（:959-1033，:991-1003 命中同号卡）**原地覆写**真分镜卡；「镜：生成路径」无数字 → :1005-1024 新建卡。
- `host-tools.ts:855-868` `formatStoryboardShot` 首格原文直接进标题。
- 两条提交路径（:1884 auto / :1911 confirm）都无镜号合法性校验；:1875-1877 闸门只拦「一行都解析不出」。

## 修复方案
1. 镜号**整格**校验（加在 :1869 解析后、:1875 闸门前）：数据行首格必须匹配 `/^(?:第)?\s*\d{1,3}\s*(?:镜|号)?\s*[.、：:]?\s*$/u`（放行「1」「01」「第1镜」；拒绝「1/2/3/6」「镜：生成路径」）。不合法行**整表拒绝**（all-or-nothing，防半落卡），抛 `CS-USER-ERR` 指名道姓：`分镜表第 N 行镜号「1/2/3/6」不是合法镜号（应为单个数字）——该行疑似把生成策略写进了表格；策略说明请写在表格外正文。${STORYBOARD_PARSE_HINT}`。
2. 双保险：`shotNumberOfCell`（:882-888）收紧为同一整格匹配，杜绝子串误读覆写。
3. skill 补一句（`skills/canvas-studio-creation/references/shot-format.md` 表格格式节）：「表格只放逐镜分镜行（每行一个镜号）；生成路径/参考组合等策略说明写在表格外正文」；`STORYBOARD_PARSE_HINT`（host-tools.ts:828-829）补半句「镜号列只写一个数字」。

## 改动风险
- 正则过严会把合法变体表打回 → 引发整表重提循环：需覆盖已见形态，报错必须给可行动出路（已含）。
- 存量画布已落的脏卡不受影响（校验只在提交时跑）；`mergeShotCards` 同号配对依赖镜号数字，收紧后只更稳。
- 测试：`tests/shot-cards.test.mjs` 现有解析用例需全绿；新增「策略行整表拒绝」「1/2/3/6 不覆写镜 1」两例。

## 验收
无头：单测（合法变体放行矩阵 + 非法行拒绝文案）。桌面：重提一份含策略行的分镜表 → 报错指名道姓、真分镜卡不被覆写。
