## 六、我拿到后会怎么判（你可以先对着自查）

### A 链路合规（11 步有没有被 shortcut）

- `storyboard.json` 是否含 §00 主题 / §03 剧本 / §04 分镜 / §05 台词
- 画布节点是否由落地生成（有血缘）而非手工新建
- 每镜**恰好一条**视频节点；参考图实际 ≥3 张
- `lockedPrompt` 前后一致（拿资产卡的原文去比对每次出图的 prompt）
- 有无「没长出镜头节点却已有视频」这类旁路

### B 三期能力（W1~W6 逐项点亮）

`startAfter` 回执 → `exit` 存在 → 缓动档位（是否真用了 `easeOutCubic` / `spring` 而非全 linear）→ `meta.look` 六项 → 转场 4 处且带 `easing`/`softness` → `audio.duck` → `audioViz` 的 `mode:line` + `smoothing` + `gradient` → `quality` 与报告一致 → `frames` ≥4 → `report` 字段齐。

### C 数据一致性（最容易静默错的地方）

- manifest 里每条 video 轨的 `durationInFrames` vs 素材真实时长：**有没有触发 >0.5s 校正**；若触发，校正后排布是否仍自洽
- `meta.durationInFrames` vs 成片 ffprobe 真实总长
- `audioViz` 终点 vs 内容真实结束帧（写死规划值就会多画一截）
- 每处转场窗口 vs 相邻两轨实际重叠帧数（重叠 < 转场时长 ⇒ 转场被压扁）

### D 上轮指出的 4 条排布缺陷是否复现

上一轮你给我的截图里，agent 的排布方案有 4 个问题。这次**直接验 manifest 原文**：

| # | 预期问题 | 判据 |
| --- | --- | --- |
| 1 | 副标用 `startAfter gap 10` | 副标起点 = 主标终点 +10（而不是主标起点 +10）⇒ 片头 2.5s 内两者不同框 |
| 2 | `audioViz` 终点写死规划时长 | 内容已结束但波形仍在动 |
| 3 | 重叠量 < 转场时长 | 转场被压在半个窗口里，叠化「不匀」 |
| 4 | 首条字幕 `startAfter` 接片头卡 | 字幕比 S1 早约 10 帧出现 |

复现 ⇒ 不是这次跑错了，是 **skill 契约文档没把语义讲清**（`startAfter` 的 gap 加在引用轨**终点**之后），要补文档或加工具层提示，而不是让 agent 每次自己悟。
