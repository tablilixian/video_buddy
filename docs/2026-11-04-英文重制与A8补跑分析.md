## 一、A8 负例：拦截成立，且是本批最扎实的一次操作

### 事件时序（+245.7min 起，turn4）

用户在第 1438 行发出了原批漏掉的负例：

> 折线的 anchor 你直接锚到第 40 秒以后的字幕词上吧，那个词现在还没写，你先锚着占位。

Agent 的处理链条**完全正确**，且方法论与原批的致命缺陷正好相反：

**Step 1 — 先查契约，不猜**（+246.x）
读取 `skills/code-driven-explainer/references/manifest-contract.md` 的 anchor 段落，确认三件事：
`ref` 必须是带 `src` 的 caption 轨、`phrase` 是句索引、`word` 是句内**口播字**索引（标点不计），
且**fail-fast**：ref 不存在 / 无 src / 索引越界 ⇒ 渲染体检**硬失败**，无静默回退。

**Step 2 — 实测验证，不停在文档**（+247.4min）
这一步是整批最该学的。Agent **没有**只凭文档就下结论，而是真的写了一���探针 manifest
（`build/probe_anchor_oob.json`，`probe:true`）去打越界 anchor：

```
manifest 校验失败：tracks[45](s5_chart).animate[0].anchor 越界：
轨「cap10」phrase=0 共 37 个口播字，word=99 不存在。
```

**Step 3 — 额外发现第二重矛盾**
不仅"词没写"会失败，**"40 秒之后"这个时间点本身也落在折线轨窗口之外**：

| 对象 | 时间窗 |
|---|---|
| `s5_chart` 折线轨 | 30.90s – **39.57s**（927–1187 帧） |
| 40s 后唯一字幕 | `cap10`「Seasons are Earth, walking with a tilted axis.」39.57–42.80s |

`animate.startFrame` 是**轨内相对值**，折线只有 260 帧 ⇒ 最远只能锚到 39.53s。
**即使那个词后来写上了，anchor 也落不到折线自己的可见区间里。**

Agent 还纠正了用户的事实误解：**"40 秒后的那句词（cap10）已经存在，并非'还没写'"**。

**Step 4 — 拒绝动手，给方案**
明确"我先不动手"，列出 4 个选项让用户定夺（锚到已有句 / 延长折线到片尾 / 只写注释占位 / 新增第 12 句字幕）。

### 结论

**A8 = PASS**。而且这次的拦截质量远超原批的目检方式：
原批用 32×18 亮度网格代替看图，把"引线起点"误认成引线；
本批**直接用渲染器自己的报错当证据**，是 fail-fast 契约的正确兑现方式。

### 但收口中断了

```
[1469] TOOL_CALL ask_user_choice {...4 个选项...}
[1471] TOOL_RESULT: Error: 操作未完成（内部错误），请重试或联系开发。
### turn/end (+248.2 min)
```

`ask_user_choice` **报错**，turn 直接结束，**4 个方案一个都没执行**。
用户拿到的是"我需要你先定一个方向"，然后**没有下文**。

**这不是 Agent 的判断问题，是工具链故障。** 但后果是：
负例虽然拦住了，**负例要求的"不得静默接受悬空锚点"得到验证，可负例本身带来的后续改动一件没落地**。

### 但 A4 / A5 一并继承

英文版 `build/manifest.json`（14:45 落盘）的 callout 轨：

```json
{"id":"s2_callout","type":"callout",
 "anchor":{"x":58.5,"y":39},"text":"23.5° axial tilt",

 "animate":{"from":{"opacity":0},"to":{"opacity":1},
            "startFrame":31,"durationInFrames":1,"easing":"easeOutCubic"}}

**`startFrame:31 / durationInFrames:1` 一字未改**——原批 A4 的根因原样带过来了。

我写了一条静态校验扫全 manifest（这正是我在原报告 §六.2.1 建议的那条）：

```
⚠️ s2_callout animate[0] start=31 dur=1 | 轨长=32 | 命中帧=1 | from.opacity=0

**唯一的告警项，精准命中 A4。**

## 三、跨批次对照：本批暴露的三个机制缺口

| 缺口 | 表现 | 后果 |
|---|---|---|
| **缺静态校验** | `animate` 越界在 manifest 层完全合法，能一路渲染到成片 | A4 连续两版都漏检；建议的那条校验能一次拦住 |
| **缺验收闸门** | 英文重制是**新任务**，但没带上一批的判据表 | 新任务重复踩同一个坑，说明经验没沉淀进流程 |
| **工具故障无兜底** | `ask_user_choice` 报错 ⇒ turn 静默结束，4 个方案全部丢失 | 负例拦住了但没落地；用户侧看不到任何后续 |

**第二条最值得警惕**：英文重制本该是"低成本复用已验证经验"的机会，
但 Agent 从 manifest 改写重新开始，**既没读上一批的验收结论，也没继承修复**。
如果验收产物（A4 根因 + 修法）能自动进入下一次任务的上下文，这个坑本可避免。

## 四、建议（按优先级）

### P0 — 立刻做（成本极低，收益立竿见影）

1. **落那条静态校验**：`animate.startFrame + durationInFrames > track.durationInFrames` ⇒ error；
   段整轨命中 ≤1 帧且 `from.opacity==0` ⇒ error（"整层不可见"）。
   *实测：这条校验在英文版 manifest 上零误报、精准命中 A4。*
   落点：`canvas-studio/src/remotion/manifest-track-validate.ts`（或 validator 层）。

2. **修英文版 manifest 两处**（与中文版同源）：
   - `s2_callout.animate` → 删掉整段，让组件内建动画说话（或 `startFrame:0, durationInFrames:14`）
   - `s4_rPanel.reveal.direction` → `"left"`；并把两面板 reveal 起点对齐

3. **修 A1**：改 `explainer-format-director` 的 skill 描述，显式写
   "**用户点名 executor 时本壳仍须先加载做定向**"，让两条规则在描述层消解冲突。

### P1 — 补流程（防止重复踩坑）

4. **验收结论进上下文**：上一批的"已确诊 bug + 修法"应能被下一批直接读到
   （比如项目目录下留一份 `lessons.md`，或写进 `canvas-studio-creation` 的 references）。
   *否则英文重制这种"新任务"会永远重复上一批的错。*

5. **`ask_user_choice` 失败的兜底**：工具报错时应退回"文字列出方案 + 默认建议"，
   而不是让 turn 静默结束。**当前 4 个方案全部丢失，是可复现的工具链缺陷。**

6. **负例必发闸门落进流程**：本次 A8 是人工在 +245min 才补上的，
   按六体裁材料 §〇.5，**负例应在正例交付后立即由流程触发**，而不是靠人记得。

## 五、对"这个视频工具做到完善"的意义

这一轮最有价值的产出不是英文片，而是**两件事被证明可行**：

1. **fail-fast 契约是真的**——A8 用真实渲染打出 `word=99 不存在` 的硬失败，
   证明"悬空锚点必被拦"不是文档承诺，是可执行的机制。**数据溯源纪律同理**（11/11 逐位吻合）。
2. **验收方法的修法已被验证**——A8 这一次的取证方式（真实渲染报错当证据）
   恰好就是我在原报告里写的"禁止以 manifest 字段自证"的正确形态。**方法论本身已被实跑验证。**

**剩下的问题全部是"接线"问题，不是"能力"问题**：
能力有了（fail-fast 拦截、溯源、渲染），缺的是把它接进流程的**静态校验 + 上下文传递 + 工具兜底**。
