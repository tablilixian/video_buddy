## 2. 两个问题的直接回答

### Q1：段视频没声音，是设计还是没做好？

**是明确设计，两层叠加，不是功能缺陷。**

1. **渲染层（R11-C3 / D3）**：段 manifest 剥掉 `audio`，`muteAudio: true` 恒真，Remotion 侧以 `muted: true` 关断音轨。理由写在代码注释里：直接写 `audioCodec: null` 会被 web-renderer 默认值吃回 aac，产出 -91dB 静音轨，并在拼接点造成 40ms 定格。段要被 `concatShots` 用 `-c copy` 拼接，所有段必须**流结构完全一致**，所以段一律无音轨。
2. **交互层（浏览器硬限制）**：hover 自动播放必须 muted，带声自动播放会被浏览器拒绝。这条与设计无关，换实现也绕不过。

但"成片是有声音的"——回执里的 `音轨 BGM + 旁白` 与 `✅ 音频 2 个出声源` 是整片路径的混音成果，与段文件无关。所以用户视角的"没声音"精确地说是：**分镜卡上那段预览视频没有音轨，成片有**。

要改，不是"补一行配置"，而是换一条段产物产生路径（见 §4 方案 A）。

### Q2：为什么一个分镜视频也没生成？

**两个独立断点，必须都修，只修一个用户还是看不到。**

**断点一 · 渲染层压根没进分镜路径。**
`shot-render.ts:267` 传 `allowShots: manifest.audio === undefined`。这个项目有 11 句旁白 ⇒ `false` ⇒ `shot-cache.ts:273` 第一行直接返回 `mode: 'whole'`，`runShotRender` 回 `outcome: null`、空段清单，宿主落回整片路径。会话回执里那句 `ℹ️ 分镜渲染未启用` 就是这条分支的原话。这不是段渲染失败，是**根本没进入段渲染**。
另外，会话中多数调用是 probe / spotFrames，在 `host-tools.ts:3983` 的 `if (!probe && !spot)` 之外，连 `runShotRender` 都不会调；唯一一次主片 draft 又卡死在 RenderHost 31s，没走完。

**断点二 · 清单层在 draft 档没有数据源。**
14:27:08 磁盘上已经有 11 个 `assets/seg-s*.mp4`，但**没有 `deliver/card.json`**：`host-tools.ts:4063` 只在 standard/high 写交付卡，draft 不写；而 REQ-041 的 L1 清单路由只读 `card.json`。于是 `GET /remotion/segments` 回空数组，卡上依旧是文案。
⇒ **即使修好断点一，用户最常做的「草稿快渲一版」仍然看不到视频。** 两处要一起修。

## 3. 设计约束（不可退让）

1. 成片声音零回归：整片路径、`audio-compose`、`concatShots` 的既有语义一律不动。
2. 不写 `canvas.json`、不建段节点、不新增 surface、不改点击手势。
3. 匹配只认 `ref`（spec 原文 id 经 `segmentRefOf`），仅 `aligned` 时生成；**禁止按序号配**。
4. 段副本确定性命名、覆盖写，不用 `saveLocalAssetBytes`。
5. 存量项目不回填；旧文件缺 `ref` 就是缺，清单不猜。
6. hover 恒静音（浏览器硬限制）；点击手势不变。

## 4. 方案对比

| 方案 | 做法 | 成片声音风险 | 段自带声音 | 代价 |
|---|---|---|---|---|
| **A（推荐）** | 整片路径渲出带声成片后，按 spec 帧窗从**成片** ffmpeg 精切 N 段 | **零**（整片代码一行不改） | **有**（切的是已混音成片） | 多一次切段；段不是独立渲染 |
| B | 解禁 `allowShots`，段 Remotion 无声渲 + concat，再给 concat 产物后配音频 | 中（混音全链路要回归） | 无 | 段级缓存可保留，为 N1 铺路 |
| C | 给 Remotion 段渲染内嵌对应音频 | 中 | 有 | -91dB 静音轨与 40ms 定格回归；`concat -c copy` 流结构不一致；`manifestGlobalsFingerprint` 不含 `audio`，改旁白后段声音是旧的 |

**选 A。** 它同时满足"成片有声音"和"段视频也有声音"，且把最贵的整片混音路径完全隔离在外。B 留作 N1 单段重渲时的备选；C 不推荐。

## 5. 实施步骤

### P0-a · 清单层：draft 也能出清单（先修，最小改动）

- **改什么**：`src/segment-media.ts` 的清单来源增加**派生回退**：`deliver/card.json` 不存在或无指针时，读 `build/spec.json` 的 sections 原始 id 与 `build/manifest.json` 的帧窗，调用 `planSegmentArtifacts` 现场派生 `ref`（沿用 `aligned` 判据），再 stat `assets/seg-<id>.mp4`。只读、不写盘。
- **判据**：`ref` 只能来自 `planSegmentArtifacts` 的 aligned 结果；对不齐就不给 `ref`，清单空。**不得用文件名 `seg-sN` 反推 `spec:sN`**，中文 id 与过期段表都会静默错配（`segment-artifacts.ts` 模块头已写明）。
- **不动**：`allowShots` 保持原样，整片路径保持原样。
- **测试**：`tests/req041-segment-media.test.mjs` 加 3 条行为断言——无 card 但 spec+manifest+段文件齐全时回 11 条且 ref 为 `spec:sN`；spec 与段表不对齐时回空；段文件 stat 不到时回空。反向变异：把派生改成按序号 ⇒ 必须变红。
- **验收**：对 14:27 那个项目 curl 清单回 11 条、url 全 200（无需重渲，纯粹是清单层修复）。

### P0-b · 渲染层：段产物旁路发布（保证"新产出"的段一定存在）

- **改什么**：在 `host-tools.ts` 整片渲染成功后，新增一个**只发段**的旁路调用（不改 `runShotRender` 的 `allowShots` 语义、不改 `shot-cache`）。帧窗来源与 `planShotRender` 同一函数 `resolveShotBoundaries` + `sliceByShots`，避免两套切段口径。
- **产物**：沿用 `segmentArtifacts.ts` 的确定性 id / `ref` / `assetFile`，复制两份（`deliver/segments/` + `assets/`），**覆盖写**。
- **失败语义**：切段失败不阻断成片，只记一行 note；任一段两份副本缺一份，该段不给指针（与现有 `publishSegmentArtifacts` 同口径）。
- **测试**：新测试钉死"整片渲染成功 + 切段失败 ⇒ 成片 outcome 原样、段清单空"；反向变异：把失败吞掉仍发指针 ⇒ 红。

### P1 · 段自带声音（增强目标）

- **改什么**：P0-b 的切段从"无声重渲"改为**从成片精切**：
  `-ss <startFrame/fps> -i <成片> -t <frames/fps> -c:v libx264 -crf 18 -preset veryfast -c:a aac -b:a 128k -movflags +faststart -y <目标>`
  （`-ss` 放在 `-i` 后取精切，避免关键帧对齐导致的帧窗漂移；N 段串行，一段失败不影响其他段。）
- **为什么带声**：成片已混 BGM + 旁白，按帧窗切出来的段天然就是"这一屏该听到的话"。A9（点开第 2 屏听第 2 句旁白、不从 0 起）自动成立，无需第 3 批的独立 `<audio>` 双向同步。
- **客户端**：`CanvasNode.tsx` 的 hover 仍 `<video muted>`，零改动；清单契约不变（段文件同名覆盖，URL 与 `?v=` 逻辑不动）。第 3 批 N3 step plan 需据此改写：从"video + audio 同步"降为"点开细看播带声段视频"。
- **缓存**：段来自成片 ⇒ 用成片 hash/长度做版本，**不再用 Remotion 段 hash**；重渲一次整片就重切一次。切段耗时先实测，不先为没量过的数字加复杂度。
- **边界**：段不是独立渲染的，改一屏必须重渲整片——这正是 N1 要解决的，但 N1 在 P1 之后另立 plan。

### P2 · N1 单段重渲（后续，不在本方案实现）

段带声之后，N1 比原 step plan 复杂：单段 Remotion 无声渲 + 从成片切该段音频 + ffmpeg 混流。等 P1 实测后再定，不提前设计。
