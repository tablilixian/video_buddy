# 成果判定报告模板（计划 v4 §8.4 配套）

> 每轮真机会话收到后，由 agent 按本模板产出一份判定报告并入库，供**下一轮同提示词会话差分**。
> 取证先用 `canvas-studio/scripts/probe-session.mjs <session.v4.jsonl>` 生成草稿，不要整读原始日志。
> 本模板只定义「怎么判」，不代替判断：每条结论必须附证据（回执原文 / file:line / 像素值）。

## 输入

- `session.v4.jsonl` 路径（必需）
- 体裁、测试提示词原文（或「沿用上一轮」）、质量档（draft / standard）
- 可选：原图 / 原表路径（用于 L2 像素对照、L3 逐位比对）
- 上一轮同提示词的判定报告路径（用于差分）

## 报告六段（固定顺序）

### 1. 会话元数据

| 项 | 值 |
|---|---|
| 体裁 / 轮次 | |
| 测试提示词 | 原文或「沿用第 N 轮」 |
| 时间跨度 / 事件数 / 工具调用数 | 取自探针 `summary` |
| provider / model / responseModel | 取自探针 `summary` |
| 质量档 / 产物节点 | |

### 2. 工程改动生效性矩阵（核心）

| 改动（CV / 批次） | 期望行为 | 硬证据（回执原文或 file:line） | 判定 |
|---|---|---|---|
| | | | ✅ 生效 / ⚠️ 部分 / ❌ 未验证 |

规则：**「读了文档」「源码里有这行字」都不算证据**；必须看到工具回执、渲染结果或模型行为。真机没覆盖到的改动如实标 ❌，不推断。

### 3. 判据分级结果（L0~L5）

| 级 | 判据 | 本轮结果 | 证据 |
|---|---|---|---|
| L0 可跑通 | 无未恢复的 `CS-*` / 渲染失败，有产物节点 | | |
| L1 契约与纪律 | 校验器按预期拦截/放行、`lint[]` 逐条可复算、纪律被模型执行、反向变异仍红 | | |
| L2 画面判据 | 元素存在 / 位置 / 遮挡 / 排版溢出 / 动效窗口 / 字幕覆盖，逐条有 `read_image` 或 `inspect_image` 像素证据，**禁 manifest 自证** | | |
| L3 数据保真 | 单一基准、数值与原表逐位一致、无 `pending` 事实 | | |
| L4 叙事与观感 | 旁白-画面对齐、节奏、体裁特征、审美 | | 审美项标「**待用户判**」 |
| L5 稳定复现 | 同提示词换会话复跑仍达标 + 反向变异仍红 | | 需两轮会话差分 |

**达标线**：L0~L3 全绿 + L5 成立 + L4 机器可判项全绿。审美项显式交用户，不由 agent 冒充结论。

### 4. 新问题 / 回归

清单里没有的现象、或本轮引入的问题；按严重度排序，每条附证据与首次出现时间。

### 5. 根因归类

契约层 / 体检层 / 流程层 / 工具层 / 技能编排层 / 验收机制层。只修「**产生数据的路径**」，不动历史数据与具体项目成片。

### 6. 优化清单 + 下一轮

- 按优先级列改动（含落点文件与验收判据）
- **下一轮确定性测试提示词**（尽量与上一轮一致，保证可差分；需变体时明确写出差异）
- **未决项声明**：没做的、判不了的、交给用户的，逐条写明

## 会话差分方法

两轮用**同一测试提示词**，对比：① 生效性矩阵的 ✅/⚠️/❌ 迁移；② L0~L5 各条迁移；③ 工具调用构成与耗时；④ 新问题是否复现。**只有差分能证明「优化生效」，单轮全绿可能只是碰巧跑通。**

## 判定纪律

- 负例是验收阶段验证功能生效的**可选测试手段**，不进正常流程、不强制跑、不影响结案（`verification.md §3`）。
- 后端 VLM 的文字转述只作辅助参考、**不可当事实**；精确数值以 `inspect_image` 或原表为准。
- 产物不交付、不回头修任何 app 项目里的成片；会话只是取证素材。
