## 二、路线判断（本文最重要的一节：为什么不能"先补齐再用"）

用户提出的路线是「**先把能力补齐，然后再想办法把这些能力用起来**」。**方向对，但串行执行会漏掉最关键的一环。**

实测结论：**能力不是一个层，是四个层**，而本项目最薄的**恰是后两层**：

| 层 | 现状 | 实测证据 |
|---|---|---|
| ① 契约（能表达） | **半** | `manifest.ts` 5 轨型齐、5 个白名单齐；但**无 `animate`**、`Transform` 只挂 `VideoClipTrack` |
| ② 组件（能渲染） | **半** | 8 文件 422 行；**`track.transform` 全仓唯一消费点 = `VideoClip.tsx:15`** |
| ③ **表达（agent 会不会写）** | **空** | ⚠️ `manifest-contract.md` 里**「动画」出现 0 次**，而 `host-tools.ts` 工具描述已承诺「精确动画与排版」——**承诺 > 交付** |
| ④ **反馈（写错了知不知道）** | **空** | 只有一行 `warnings` 文本；**未知字段静默丢弃**；**agent 看不到画面** |

**只补 ①② ⇒ agent 仍然不会写动画、写错了也不知道 ⇒ 前面的活白干。**
⇒ 正确路线：**以一条目标成片为锚（太阳系科普片就是那个锚），四层同批推、每档一验收。**

另一条边界：**「尽可能发挥 Remotion」应改为「在目标场景内发挥到位」**。133 个导出里有相当一部分与本产品定位无关（Lambda 分布式 / SSR / `HtmlInCanvas` / `player` 可视化编辑），按"尽可能"去补会补出一堆没人用的能力 —— 详见 §七。

**契约草案（可直接照抄起步）**：

```ts
export interface VisualState {
  x?: number; y?: number            // 百分比坐标
  scale?: number; rotation?: number; opacity?: number
}
export interface Animate {
  from: VisualState
  to: VisualState
  startFrame?: number        // 轨内相对帧，缺省 0
  durationInFrames?: number  // 缺省 = 整轨长
  easing?: 'linear' | 'easeIn' | 'easeOut' | 'easeInOut'
}
// BaseTrack 上加三行 ⇒ 5 种轨全覆盖
transform?: Transform
animate?: Animate | Animate[]
fadeFrames?: number          // 0 = 硬切；缺省 6（保持现行为）
```
