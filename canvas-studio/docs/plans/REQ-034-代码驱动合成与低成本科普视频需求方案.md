## 一、需求背景与目标

### 1.1 资料库原话与样例（需求出处）

- **需求描述（资料库行 10，2026-10-13 增）**：「学习、赶超 [OpenMontage](https://github.com/calesthio/OpenMontage)，支持 Remotion 与 HyperFrames，支持多种免费 / 低成本视频制作（wiki、科教、教育类视频）。」
- **样例（资料库所附一句话 prompt 原文）**：「"How Salt Made History" — a 100-second cinematic documentary about the mineral that funded empires, shaped trade routes, sparked revolutions, and gave us the word "salary." Real-world footage is woven together with original narration and **hand-authored motion graphics** for its etched title, etymology reveal, animated maps, historical timeline, and closing thesis.」
- **样例成片**：`../assets/library-2026-10-13/635845001-a524f02a-2d18-42ca-a2c4-d3dc09503546.mp4`（100 秒，9.5 MB）+ 同目录 7 张参考截图（`c74673d4…` / `7c8c157e…` / `bf19f0ac…` / `799f1ff9…` / `0b00115c…` / `7e5054a2…` / `cb6b4107…`，原名为资料库附件名）。
- **关联**：`../tracking.md` §REQ-034 条目（状态「未开始」，归属模块＝端到端编排 / 视频合成）。

### 1.2 能力缺口（现状 vs 样例）

| 样例里的能力 | 现状 | 本期 |
|---|---|---|
| 蚀刻标题 / 词源揭示（动态排版） | ❌ 无（`compose_video` 只能拼片段） | ✅ 标题卡 + 文字动画 |
| 动画地图 | ❌ 无 | ❌ **不在本期**（属真实素材语料库 + GIS 动画，见 §2.2） |
| 历史时间线 | ❌ 无 | ✅ 数据卡（dataCard / bullets） |
| 收尾论点卡 | ❌ 无 | ✅ 标题卡 / 要点卡 |
| 真实素材（Archive/NASA/Wikimedia）缝合 | ❌ 纯模型生成 | ❌ **不在本期**（语料库 P2） |
| 原创旁白 | ✅ `tts_voiceover`（CV-271 占位升真） | ✅ 复用 |
| BGM / 混音 | ✅ `music_generation` + `compose_video` 混音链 | ✅ 复用 |
| 逐镜头精确时长编排 | ⚠️ 弱（`clipIds` 数组 + 粗时机） | ✅ Manifest 显式时间轴 |

**结论**：本期**补齐"手作动态图形 + 精确时间轴"这一层**（样例最吃工程量的部分），**不补"真实素材语料库 + 动画地图"**（那是另一条 P2 线，见 §10 未决 3）。

## 二、范围

### 2.1 本期做（MVP）

1. **CompositionManifest 契约**（结构化"成片结构"：轨/时长/转场/音频/字体）—— 见 devdoc §4。
2. **`render_composition` Host 工具**（Remotion 渲染；与 `compose_video` **同形状**返回）—— devdoc §6。
3. **组件最小集**：`SubtitleCard`（字幕）/ `DataCard`（数据卡 / 要点列表）/ 标题卡 / `KenBurnsImage` / 基础形状 / 精确转场 —— devdoc §7.3。
4. **句级字幕**：探旁白真值总时长 + 按字数比例分配（Drama TTS 无时间戳，已核实）—— devdoc §10.3。
5. **素材轨时长口径**：video 轨取 `list_shots` 真值，禁止估算 —— devdoc §10.4。
6. **中文字体离线兜底**（随包 OFL 子集 + `delayRender` 闸门）—— devdoc §8.3。
7. **`code-driven-explainer` skill** —— 按 `docs/skill-expansion-spec.md`（CV-317~326 后的新规）落地：`SKILL.md` **≤12 KB 入口** + 细则下沉 `references/`、**`platform.yaml` 必需**（9 必填字段，`role: "decision"` / `slot: "general"`）、`src/skill-catalog.ts` 的 `BUNDLED_CATALOG` 快照同步、**不得自设审批门**（审批语义归总纲）。详见 devdoc §0 R8/R9。
8. **幻灯片风险评分**（6 维防"一堆图假装视频"）—— devdoc §9.2。
9. **登记与门禁（v1.1：3 处 → 6 处）**：① `toolchain.md` 工具表行；② `docs/canvas-studio-tools.md` 工具表行；③ `tool-registry.test.mjs` 计数 24→25；④**新** `skills/code-driven-explainer/platform.yaml`；⑤**新** `src/skill-catalog.ts` 的 `BUNDLED_CATALOG` 快照（与 platform.yaml 逐字段相等）；⑥**新** `skill-tool-refs` 全绿（skill 正文引用的 snake_case 工具名必须已在真实注册表里 ⇒ **工具与 skill 必须同批提交**）—— devdoc §11/§12.1。

### 2.2 明确不做（本期）

| 不做 | 原因 |
|---|---|
| **词级字幕（KTV 式）** | 需 Drama TTS 返回时间戳或引入 forced alignment —— **外部前置未具备**（devdoc §10.3） |
| **LLM 动态生成 Remotion 组件 JSX 并沙箱执行** | 风险高，二期 |
| **云端 / 批量并行渲染** | 商业规模再议 |
| **HyperFrames 双引擎** | 样例的"手作动态图形"用 Remotion 即可达标；HyperFrames 留作替换预案（见 `openmontage-adoption-analysis` §2 P0） |
| **真实素材语料库（Archive.org / NASA / Wikimedia + CLIP 检索）+ 动画地图** | 独立 P2 线，与"低成本"诉求相关但**不是本期的能力缺口**（§1.2） |
| **字体"自托管下载"链路** | 依赖 **Drama 后端新增 `/fonts/` 静态路由**（外部需求）；MVP 只走随包子集，离线闭环（devdoc §8.3） |
| **参考驱动创建（paste video → 变体）** | P2，跑在 REQ-022/`video2vl` 上 |

### 2.3 与相邻模块 / 需求的边界（**验收期最易扯皮处，先钉死**）

| 相邻 | 边界 |
|---|---|
| `compose_video`（现有成片主路） | **不动、不替换**。`render_composition` 是**并联旁路**；纯片段拼接仍走 `compose_video`（工具描述里要写清分流条件） |
| **REQ-022 Storyboard** | Storyboard 仍是**事实源**；Manifest 是它在**渲染层的派生**（`narration.lines` + `scenes[].shots` + 已落画布素材 → tracks）。**不双向同步、不另起第二套事实源** |
| **CV-213 字幕纪律**（"默认不把字幕烧进画面"） | 本需求是项目**第一条真正把字幕烧进画面的路径**（`subtitle_burn` 仍是占位工具）。**必须显式声明例外**：只在 `render_composition` 路径成立，不改变其它 skill 的默认纪律（devdoc §10.2） |
| **skill 审批语义（CV-317~326 新规）** | **审批语义唯一事实源 = `canvas-studio-creation` 总纲**；风格/流程 skill **不得自设 HITL 门**（`skill-progressive-disclosure.test.mjs` 会红：既禁退役工具名 `submit_screenplay` / `submit_storyboard_for_approval`，也禁"确认后才生成"这类流程门表述）。⇒ 本需求的 HITL **不放在 skill 里**，而是：① `render_composition` **工具自身**调 `assertApprovalAllowed`（与 `compose_video` 同口径，属宿主行为）；② skill 侧只用 `ask_user_choice` 做**需求澄清**（可借它展示轨道时序表），措辞不得写成流程门 |
| Sketchup / REQ-033 agent toolbar | 无交集 |
| 画布节点与版本链 | 成片走 `appendComposedVideoNode`（与 `compose_video` 同款：版本链 + 血缘避让），**不新增节点类型** |
| 质量门禁 `runShotQc` | 它是**镜头**质检；对成片是否适配**须先取证**，不适配则按降级预案（devdoc §9.1），**不许为凑复用产出假结论** |

## 五、验收标准（AC，逐条可判定）

| AC | 判据 | 判定方式 |
|---|---|---|
| **AC-1 端到端出片** | 给定一句话需求 + 一组已落画布素材（含至少 1 图 / 1 clip / 1 旁白），skill 产出 Manifest 并经审批 → 成片 video-composite 节点落画布 | 桌面实跑；看一眼产物 + 节点卡 |
| **AC-2 主干不回归** | `compose_video` 链路行为不变；`tool-registry` / `skill` 登记门禁全绿；`test:smoke` 失败集不超出基线 | 跑门禁 + 桌面回归 `compose_video` |
| **AC-3 形状一致** | 返回体与 `compose_video` 同形状；画布节点角标（画幅 / 时长 / 分辨率 / 音轨构成）正确显示 | 对比 `compose_video` 结果结构 + 看角标 |
| **AC-4 HITL 生效（v1.1 修正落点）** | ① **宿主审批门**：审批未放行时调用 `render_composition` → 被拒且不渲染（同 `compose_video` 口径）；② **澄清环节**能展示轨道时序表供用户调整；③ **skill 侧无自设门**（`skill-progressive-disclosure` 门禁绿） | ① 单测/桌面各一次；② 桌面实跑；③ 跑门禁 |
| **AC-5 静默错误防线** | 三条静默错误**均被拦**：① 漏 `calculateMetadata` → 时长不符（AC-1 会暴露）；② 素材声明时长 ≠ 真值 → 有 warning 且终值取真值；③ 素材读不到 → 显式失败不静默出空片 | 单测（纯函数）+ 故意做坏的负例各一次 |

### 6.1 已知限制与取舍（刻意为之，勿提单）

- **不做词级字幕**：Drama TTS 不返回时间戳（已核实），句级为定稿口径；词级列二期（前置见 §2.2）。
- **不做动画地图 / 真实素材语料库**：本期不覆盖样例的全部形态（§1.2 已声明），属 P2。
- **字体下载链路不在本期**：未命中随包子集时走 fallback + warning，**不阻断**（依赖 Drama 后端 `/fonts/` 路由）。
- **同步渲染**：长片（分钟级）会占用一次工具回合；异步队列留二期。
- **第一期不进风格路由**：`code-driven-explainer` 不登记进 `style-presets.md`（见 §十 未决 7），因此**澄清流程不会主动推荐它**；用户可从技能广场看到并显式调用。
- **视觉/UX 不自动覆盖**：项目铁律——最终判据是人（桌面观感）。

## 九、风险与对策

风险登记册见 devdoc §15.2（含概率 / 影响 / 缓解）。需求侧**需要知晓的三条**：

1. **打包期浏览器与平台二进制**（概率高、影响构建）：国内网络 + Electron 属 Remotion「官方未支持环境」→ 镜像导出、`binariesDirectory`、`asarUnpack`、随包预置四条对策已写明（devdoc §7.5 / §15.3）。
2. **`renderDir` 待验项**（概率中、影响 B3/B6 形态）：若不成立则退化为"每次渲染 bundle"，需以阶段 0 实测耗时决策（devdoc §15.1 决策 5）。
3. **静默错误**（概率中、影响信任）：漏 `calculateMetadata` / 素材时长估错 / 素材读不到，三者均为"无声出坏片"，已分别落成显式机制 + 校验 + warning（AC-5 / Z-7 / Z-8）。
