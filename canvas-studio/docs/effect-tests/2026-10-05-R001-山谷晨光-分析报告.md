## 一、P0-a：test-report.md 为何未落盘 → 执行器假超时（记 BUG-014）

### 三个原假设的裁决

| 交接文档假设 | 裁决 | 证据 |
|---|---|---|
| ① Host 跑旧构建（无 test-report 路由）→ 404 | **不成立** | app（Electron 主进程 PID 12995）于 **20:03 从本仓 dev 构建启动**（`dsh-plugin-desktop/lib/main.js`）；`canvas-studio/lib/routes.js` 构建于 20:03、含 `ROUTE_TEST_REPORT`（routes.ts:65）。跑批 20:04:44 开始时 Host 持有的就是带路由的新构建。另查 `~/.videobuddy/profiles` 无 canvas-studio 包副本，overlay 选择不涉及 |
| ② 追加指令回合未完成/中断 → 报告没写 | **改写为更底层的真因**（见下） | 手动停止确实没发生——回合是被执行器自己的超时判死的 |
| ③ 报告体超 readJson 上限 | **不成立** | `MAX_BODY_BYTES = 16MB`（routes.ts:76）；离线用真实快照跑 `buildAutoTestReport` 实测报告体 **22,760 字符 ≈ 32KB**，差三个数量级 |

### 真根因：turn 0 跑了 49:59.88，空闲尾巴判定被 50 分钟 deadline 截杀

会话转录（`session.jsonl.zstd`，已解包核验）给出决定性时间线：

- `turn/start` 20:04:44（turn 1）→ `turn/end` **20:54:44.167**，`reason.kind: "completed"`（**自然完成**，最后一条 assistant 消息是完整交付汇总）
- 回合实际耗时 **49:59.88s**

而 `waitAgentTurn`（`src/client/test-driver.ts:52-68`）的返回条件是「见过 running 后**连续 2 次空闲轮询**」（轮询间隔 3s），即回合结束后还需要 **≈6s** 才能确认空闲；50 分钟 deadline（`EFFECT_TEST_CASE_TIMEOUT_MS = 50*60_000`）在 `while` 条件处先到。数学上：

- 最后一次执行到循环体的轮询 ≈ 20:54:41（此刻 running 仍为 true，idleStreak=0）
- 下一次轮询应在 ≈20:54:44.4，但那正是 `Date.now() - started < timeoutMs` 翻假的时刻 → **循环退出 → `throwError('CS-EFFECT-003')`**

即：**只要某轮回合实际耗时超过 49:54（50:00 − 6s 空闲尾巴），即使回合在 deadline 前自然完成，也必然被判超时**。本轮回合 49:59.88，落在必杀区。效果上「单回合上限」的真实值比标称少 6 秒，且超时与自然完成在边界处没有仲裁。

### 后果链（一并解释了三个现象）

`CS-EFFECT-003` 从 `waitAgentTurn` 抛出 → 落入 `runAutoTestScenario` 的 catch → 执行器**在同一处**跳过了三件事：

1. turn-0 的 11 条机器断言**没有跑**；
2. `buildAutoTestReport` + `saveTestReport` **没有调** → `test-report.md` 未落盘（验收标准③直接不满足）；
3. turn 1（追加指令）**没有发送** → P0-c。

**30 秒复核指引**：app 仍在运行（就是当前这个实例）。打开浮窗步骤日志，最后两行应为「执行中断：等待 agent 回合结束超时，请重新发起测试。」与浮窗消息「场景中断（R001）：等待 agent 回合结束超时，请重新发起测试。报告与已落盘产物保留在测试项目目录。」（文案取自 errors/catalog.ts CS-EFFECT-003 + index.ts:2087）。

### 修复方向（BUG-014，S1，阻塞重跑）

- 最小改法：`waitAgentTurn` 的 deadline 判定让位于空闲判定——若「已见 running」且**当次轮询已 idle**，再给一轮（或两轮）轮询窗口用于凑满 idleStreak，而不是直接退出循环抛超时；等价地，把超时常量定义为「回合墙钟 + 空闲尾巴余量（≥10s）」。
- 语义澄清：CS-EFFECT-003 应只表示「回合真没在预算内结束」；自然完成被误判属于**假超时**，测试结论不应由它产生。
- 附带：本轮不存在「用户手动停止」，交接文档假设②中的「浮窗日志对照」请用上面的复核指引验证。

## 二、P0-b：镜位全走 video_composite → 结论 (a)，改断言（记 BUG-016）

`canvas-studio/skills/canvas-studio-creation/SKILL.md` 第 9 步：

> 默认 video_composite 多参考 Ref2VA（锚点 + 场景图 + 补足席位，**必须 ≥3 张**），仅同镜首尾转场用两图 FL2VA，都不适用才退 video_generate；……**用户计划优先（C-9）：分镜表/用户指定了某镜工具时按指定执行，不得擅自升级到 video_composite**。

### 三选一结论

**选 (a)：断言口径放宽。** 剧本没有指定工具（只写了「先出关键帧，再出视频」），skill 默认 video_composite，agent 照做——这不是 skill 纪律缺口（b），也不是剧本措辞问题（c）。是 `videos-active` 检查点把「工具名 = video_generate」当成了「镜位视频存在」的判据，与 skill 的工具选择规则直接矛盾（记 BUG-016，断言库 bug，非 skill 修复项）。

### 断言改法建议

`videos-active` 重写为「**镜位视频 = 3 且全部 active、零 supersededBy、零 retired**」，条数统计口径 `toolName ∈ {video_generate, video_composite}`；BUG-011 回归意图（废弃视频串链、单镜残片）由「零 supersededBy」+ `compose-final`（来源 ≥3）继续承担，不受影响。可选加严：对 video_composite 镜校验其 sourceUrls 中图片数 ≥3（Ref2VA 纪律的机器化）。

### 顺带发现的断言库第三处脆弱（改进项，不记缺陷）

路由前缀断言（poster-route-qwen / concept-route-krea2）依赖节点 `filename` 恰好保留后端产物名。实测 10 个 image_generate 节点里 **9 个 filename 是 `ref-*` 句柄**（画布参考句柄，无路由信息），只有 1 个保留 `krea2_00486_.png`；`generationPrompt` 参数里也没有 model/channel 字段（只有 aspectRatio/prompt/refs）。即路由断言只能对「恰好未被句柄覆写」的节点生效——krea2 断言这轮PASS 属于抽样命中。改进方向：Host 在节点或 history 里持久化后端路由/模型名，断言改为查结构化字段，而非从产物名猜。
