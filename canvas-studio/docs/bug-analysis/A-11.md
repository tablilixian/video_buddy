# A-11 ｜ 双击视频放大播放，画面上下被切

> 优先级 P2 ｜ 风险 T1 ｜ 依赖：无
> ⚠️ **无截图、未真机复现——以下为 CSS 机制推断，修复前先按「验证步骤」确认。**
> 资料库原描述：「双击视频放大播放，视频窗口视频播放面积不完整，视频上下被切了」。

## 推断的代码级原因
- 播放浮层：`VideoPlayerModal.tsx`（CV-044）——`.csVideoModalCard { width:auto; max-width: min(1280px, calc(100vw - 48px)) }`（styles.ts:5319-5322）**没有 definite height**；`.csVideoStage`（:5328-5339）`flex: 1 1 auto; min-height: 0; overflow: hidden`；`.csVideoModalVideo`（:5340-5348）`max-width/max-height: 100%; width/height: auto`。
- **机制**：CSS 中百分比 `max-height` 对「高度由内容决定（auto）」的父容器解析为 **none**。卡片高度 = 内容高度（`.csModal` 只有 max-height + overflow:hidden，styles.ts:5325-5327 注释自认「卡片沿用 .csModal 的 max-height」），因此 stage 的高度不定 → 视频 `max-height:100%` 失效 → 视频按**内在尺寸**渲染 → 超出卡片 max-height 的部分被 overflow:hidden **裁掉**（竖屏 9:16 或矮窗口下必现，横屏大视频在高分辨率屏也可能触发）。:5342 注释「百分比在 flex 定高后解析」的假设在这条链上不成立。
- 播放器代码本身无 object-fit/cover 问题（默认 fill + auto 尺寸不会裁）。

## 修复方案（给高度链一个确定值）
- 方案 A（推荐）：`.csVideoModalCard` 加 `height: min(calc(100dvh - 48px), 960px)` 并确认 `.csModal` 基类是 flex column（header/stage/controls 三段）——stage 变 definite 高度 → 视频 max-* 恢复钳制 → 任何比例都 letterbox（黑底衬边，stage 本就黑底）。横屏视频在偏高 stage 上下留黑边，属正常播放器形态。
- 方案 B（更精细）：stage 直接定高 `height: min(calc(100dvh - 200px), calc((100vw - 48px) * 9 / 16))`——横屏优先，竖屏 pillarbox。两案都只动 styles.ts 一处。

## 改动风险
低：单一消费方（VideoPlayerModal）；注意 `.csModal` 基类的 max-height 与新 height 的相互作用（取更小值）；dvh 在 Electron Chromium 版本若不支持则回退 vh。

## 验证步骤（修复前后都要做）
桌面：① 竖屏 9:16 视频（736×1280）双击 → 全画面可见、无裁切；② 横屏 1280×736 在小窗口（高度 <736）双击 → 完整 letterbox；③ 2k 视频双击 → 钳制正常。若方案 A 落地后仍裁切，则机制推断有误，回头用 DevTools 查 video 的 computed max-height 实际解析值。
