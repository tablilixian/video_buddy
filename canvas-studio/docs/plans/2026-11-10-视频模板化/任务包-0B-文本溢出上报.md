## 1. 问题（实测证据）

`原型-check-fit.mjs` 是最小复现脚本。用**仓库真实的** `subtitleFitBudget` + `fitTextPolicy` 验算本方案自己的 manifest 初稿（B1 正文盒 900×105px）：

```
fontPx = 24.2 / lines = 2 / maxLines = 1  ⇒  overflow = true
```

**而同一份 manifest 走 `validateManifest`：`ok = true, errors = [], warnings = []`。**

⇒ **零层拦截。**文字被 `overflow:hidden` 静默裁掉，契约校验说一切正常。

## 2. 设计决策

### 决策 1：抽共享纯函数 `planTextFit`，组件和体检**共用同一份逻辑**

**这是本任务的核心。**如果体检另写一份排版逻辑，必然与组件漂移 —— 体检说没溢出、成片却裁了，比没有体检更糟。

新建 `src/remotion/text-fit-plan.ts`（纯函数、零 IO、可单测）：

```ts
export interface TextFitPlan {
  /** 实际采用的字号（px）。 */
  fontPx: number
  /** 折行后的行。 */
  lines: string[]
  /** 是否超出 maxLines。 */
  overflow: boolean
  /** 基准字号（px）。 */
  baseFontPx: number
  /** 允许的最大行数。 */
  maxLines: number
  /** 是否已缩到字号下限（= base × 0.55）仍然溢出 ⇒ 最严重档。 */
  atMinFont: boolean
}

export interface TextFitPlanInput {
  variant: 'subtitle' | 'dataCard' | 'title' | 'bullets'
  text: string
  /** 轨的 box（中心+尺寸，画布百分比）；没有则 undefined。 */
  box?: { x: number; y: number; w: number; h: number } | undefined
  canvasWidth: number
  canvasHeight: number
  /** 真实字形测量器；缺省用 fitTextPolicy 的字符宽度估算（Node 侧可用）。 */
  measure?: TextMeasurer | undefined
}

export function planTextFit(input: TextFitPlanInput): TextFitPlan
```

- **`planTextFit` 内部按 variant 分派预算**，把 `TextCard.tsx` 里四个分支的「算预算」部分搬过来。
- 组件里改成：`const plan = planTextFit({...});` 然后照旧渲染 `plan.lines` / `plan.fontPx`。
- ⚠️ **组件的像素输出必须逐像素不变** ⇒ 搬完要跑既有单测 + 抽查渲染帧。

### 决策 2：精确体检放在 **prepare 阶段**（渲染前，浏览器里）

为什么不是「渲完再问组件」：
- `renderMediaOnWeb`（`src/client/remotion-render.ts:266`）在浏览器里跑完就结束，**没有回传通道**。
- 但 prepare 阶段**本来就在浏览器里**——`applyManifestFonts`（`src/client/remotion-font-inject.ts`）就在调 `document.fonts.load`。
- ⇒ **同页、同字体、同 measurer ⇒ 度量结果与渲染时一致。** 这是精确体检的唯一可靠落点。

流程：
```
prepare 阶段：
  ① 注入字体（已有 applyManifestFonts）
  ② ⭐ 新增：文本容量体检
       - 建 measurer（复用 TextCard.tsx 的 createCanvasMeasurer 逻辑，必要时抽到共享模块）
       - 遍历 manifest 的 textCard / caption 轨
       - 对每条调 planTextFit
       - 产出 TextFitPlan[]
  ③ 素材时长探测（已有 probeManifestDurations）
  ④ 能力判定（已有）
渲染阶段：（不改）
组装报告：report.textFit = 计划数组；overflow 的项并入 warnings
```

> 体检是**只读**的：不改 manifest、不改像素、不阻塞渲染（除非 measurer 建不起来 ⇒ 跳过并在 warning 里说明）。

### 决策 3：**warning + report，不拒收**

- 仓库铁律是「**不静默截断**」—— 现在是「截了但没人知道」，违反铁律。**上报即可恢复合规。**
- **不拒收**：拒收会打断渲染流水线；而且「标题就是要 3 行」可能是作者故意的（真实项目里就有意两行标题：`hook-title` = `["四季","是因为离太阳远近吗？"]`、`s6-title` = `["不是距离","而是倾斜"]`）。**硬失败会误杀有意设计。**
- **分级文案**：
  | 档 | 条件 | 文案要点 |
  |---|---|---|
  | 提示 | `overflow && !atMinFont` | 「已自动缩字号至 Npx 仍会裁掉 M 行」 |
  | 严重 | `overflow && atMinFont` | 「已缩到字号下限仍溢出，实际会裁掉 M 行 —— 请改短文案或加大 box」 |
- **警告文案必须可执行**：给出「改短到 N 字」的建议（N 由预算反算：能装下的最大字数）。

### 决策 4：Node 侧静态合同（L1）同批做，成本极低

`validateManifest` 跑在 Node 里，**没有 canvas** ⇒ 只能做**估算**。但它能查两件**不需要测量**的事：

| 检查 | 规则 | 级别 |
|---|---|---|
| 数组长度 | `textCard.text` 是数组 ⇒ 长度 ≤ 该 variant 的 `maxLines` | error |
| 字符串内换行 | `textCard.text` 是字符串 ⇒ `\n` 分隔后的行数 ≤ `maxLines` | error |
| 字数粗估 | 总字数 > `maxLines × maxCharsPerLine`（估算） | warning |

⚠️ **数组 vs 字符串必须分开判**（这是实测踩过的坑）：
- **数组 = 作者显式分行** ⇒ 校验**数组长度** + 每行 `maxCharsPerLine`。
- **字符串 = 整块** ⇒ 校验**总字数** + `\n` 行数。

这两条在配套原型里已验证（合成套件 8/8、真实四季 spec 7/7、全库 4 个真实 `manifest-spec.json` 回归 4/4），实现见 `原型-spec-limits-validate.mjs`。**注意：容量的权威声明层是 `manifest-spec.json` 的 `limits` 层，不是 manifest 层**（真实生产里 manifest 由脚本生成，spec 才是声明层）。

## 6. 已知的坑

1. **`report` schema 是 `additionalProperties: false`** ⇒ 只改组装不改 schema，字段会被静默剥掉，表现为「代码里写对了但报告里没有」。
2. **测量器要复用组件那一份**。另建一个 `ctx.measureText` 虽然也能测，但若字体没就绪 / 度量口径不同，会与实际渲染不一致 ⇒ 体检说没溢出、成片裁了。**同页同字体是关键。**
3. **`fitTextPolicy` 无 `measure` 时用字符宽度估算** ⇒ Node 侧 L1 检查只能是粗判，**不要把它写成 error 级**（会误杀合理的文案）。L1 只查**与测量无关**的硬规则（数组长度、`\n` 行数）。
4. **`title` 的 fit 宽度按画布 90% 算，`box` 不参与字号计算** ⇒ 这是**既有的**行为（也是差距 #7 的一部分），本任务**不要顺手改**，改了就破坏「老 manifest 逐像素不变」。
5. **`bullets` 的 `width: 900` 是硬编码的容器宽**（不是 `maxWidthPx`），别在体检里当成盒宽。
6. **prepare 阶段不能阻塞渲染**：体检失败（ measurer 建不起来 / 字体未就绪）⇒ 跳过体检 + 一条 warning，**继续渲**。
7. **`subtitleFitBudget` 按盒高管推 `maxLines` 和 `baseFontPx`**（`subtitle-fit.ts:60`）—— 体检与组件必须调**同一个函数**，不能各算一套。
