### 为什么判据要抽成纯函数

原判据写在组件体里，只能用「源码里有没有这行字」挡回归。抽出来后测试直接断言
「某类节点出哪几个钮、什么顺序」，反向变异可以真的变红（见 §五）。

### 分镜卡与 H3 视频卡的槽位对照

| 节点 | 判据 | 槽位 |
|---|---|---|
| H3 视频卡（kind=video + url） | 媒体卡 | `引用到对话 / 预览 / 下载` |
| 分镜卡（kind=text + segmentRef + 清单有段） | REQ-041 特批：按媒体卡 | `引用到对话 / 预览 / 下载` |
| 分镜卡（清单还没回来） | 落回 text 口径 | 仅 `引用到对话`（不出一个打不通的预览钮） |
| 普通 text 卡（有 prompt） | text 口径 | `重试 / 改提示词 / 引用到对话` |

「预览」对分镜卡 = 播清单里那一版（`seg-<id>-voice.mp4` 优先，无带声副本则无声段）；
「下载」= 同一 URL 另存，文件名取 URL 末段，不在客户端再拼一套命名。

## 二、「两边显示不一致」的根因（按影响排序）

### 1. 尺寸语义不同源（最直接）

- 分镜卡是 **text 卡**：`300×200`（项目实测，11 张全是这个尺寸）。
- H3 视频卡是 **媒体卡**：`frameSizeOf(864×480) = 864×588`，整张卡就是画面 + chrome。
- 段视频只能吃 text 卡里正文之外的**剩余空间**（`.csNodeSegmentVideoBox { flex: 1 1 auto }`），
  于是同一条 16:9 的视频，在视频卡里是主画面，在分镜卡里是一条横带。

### 2. 卡面结构不同源

| 元素 | 视频卡 | 分镜卡 |
|---|---|---|
| 主体 | `csNodeMediaBox` + `csNodeMedia`（整块画面） | `csNodeSegmentVideoBox` 一条 + `<p class="csNodeBody">` 两行文案 |
| 参数角标 | `csNodeVideoBadge`：`16:9 · 8s · 480P` | 无（段没有生成参数） |
| 脚部读数 | `0:08 · 864×480`（时长 + 分辨率） | `7.5s · 279 字`（估算时长 + 正文字数） |
| 头徽章 | 「片段」 | 「分镜」 |

两条通道各算各的读数：视频卡的读数是产物元数据，分镜卡的读数是**文案**推算
（`estSecondsOf(bodyCharCount(...))`）。

### 3. 数据模型不同源（这条是「每次都要特批一次」的根源）

段产物**不写节点**（`node.url` 恒空、URL 由清单按 `segmentRef` 派生，§9.7 不写画布）。
所有既有能力都按 `node.url` / `node.kind` 判，于是每加一个能力都要单独为分镜卡
开一次口子：本轮是工具条两项（预览 / 下载），上一批是卡面挂视频。这是**设计使然**，
不是漏改 —— 但每开一个口子都必须回到「段不是节点产物」这句话上重判一次。

### 4. 交互形态不同源

- 视频卡：`<video src=node.url preload=metadata>`，双击/预览开播放浮层（有声、有控件）。
- 分镜卡：`<video muted loop playsInline>`，hover 播放（浏览器不允许 hover 触发有声自动播放）。

## 三、可以对齐的 3 处 / 不该对齐的 2 处

| 项 | 建议 | 理由 |
|---|---|---|
| 工具条三个钮 | **已对齐**（本轮） | 用户明确要求 |
| 脚部读数：分镜卡显示段时长 + 段分辨率 | 可做，需宿主把段元数据带进清单 | 卡上有画面却读「字数」，与视频卡并排看会觉得缺读数 |
| 段视频框加参数角标（如 `16:9 · 7.5s`） | 可选 | 段没有「生成参数」，只有实测值，语义上应叫时长而不是「8s 480P」 |
| 卡尺寸拉到视频卡的 `864×588` | **不建议** | 分镜卡是「文案 + 画面」双主语；放大到 864×588 会让 11 张分镜托盘重新排布，且违反「不写画布」 |
| 双击开播放浮层 | **不建议**（点击手势已拍板不变） | 用工具条「预览」即可，手势零改动 |

## 四、P0-1 的存量污染（需用户决定）

## 六、验收前置条件（重要）

「预览」要**有声音**，依赖 `assets/seg-<id>-voice.mp4` 存在（清单优先带声副本）。
实测项目 2 的 `assets/` 里 11 个段全是无声版、`-voice` 副本 **0 个** —— 因为它是用
`manifest-noaudio.json` 走分镜路径渲的，没经过「整片渲染后旁路合声」那一步。

所以 A9（点开第 2 屏听第 2 句）的验收顺序必须是：

1. 先用**带旁白**的 spec 渲一版整片（触发 host-tools 的段发布 + 合声旁路）；
2. 确认 `assets/` 出现 `seg-s*.mp4` 与 `seg-s*-voice.mp4` 成对；
3. 再点分镜卡「预览」听声音。

否则预览能开、画面对、但没有声 —— 那不是交互坏了，是产物还没生成。
