## 2. 批次 P1 · 数据正确性三件套（约 1.5 人日，互相咬合）

### 2.1 #18 权威交付路径（0.75 人日）

**改什么**：`render_composition` 在 **quality ∈ {standard, high} 且非 probe/spot** 成功时，
宿主自动做两件事：

1. 复制成片到固定路径 **`deliver/final.mp4`**（覆盖写；卡点 K1 说明为何复制不改节点）；
2. 生成 **`deliver/card.json`**：`{ 规格(fps/分辨率/时长), 版本(anchor-state version + manifest hash),
   未决项(读 PROGRESS「已知未决」段，空则「（未填）」+ deliveredWithGaps: true),
   时长断言(|durationSec - plan.targetDuration|，>1s 标 durationMismatch), assetFile, 节点 id }`。

draft 不落（`draftTag` 已有现成判定，host-tools.ts:734）；不迁移历史散落文件。

**为什么**：31 项目仅 6 个有 final、DNS 2 四个 final 分辨率互相矛盾、香水项目 480p 草稿
当交付、PROGRESS 锚 26.6s vs 实际 45.1s——没有单一权威路径，用户与后续流程只能靠猜。

**验收**：完成的项目 `deliver/final.mp4 + card.json` 必然存在且字段齐全；draft/probe/spot
不落；覆盖写不产生 final-vN 家族。

### 2.2 #10 独立 `validate_manifest` 工具（0.5 人日）

**改什么**：新工具 `validate_manifest({ manifestPath })` —— 读盘 → validateManifest（schema
全量 errors 一次列全）+ lintMotion（C2 合并形态）+ auditTextFit（估算口径）三件套，毫秒级，
**零副作用**（不落节点不渲染）。回执结构对齐 scaffold 的三段（§编排体检 / §文字容量 / errors）。

**为什么**：手写 manifest 路径的模型仍要「调一次渲染（14s）换一行报错」；spec 通道已由
A2/A3 前置，本工具补齐另一条路。**顺带把 #15 的跨版本断言接口留出**（card.json 侧实现）。

**验收**：坏 manifest 一次列全所有 errors（不是第一处就停）；好 manifest 回执零噪音。

### 2.3 #2 handoff 强制——交付卡倒逼，不加新门（0.25 人日）

**改什么**：card.json 的「未决项」字段从 PROGRESS 读取（2.1 已含）；未决/下一步为空时
**不阻断**（渲染不陪葬），但 ① card.json 标 `deliveredWithGaps: true`，② 交付回执加一条
硬提醒（「交付卡未决项为空——把未决项写进 PROGRESS 再交付，否则下一会话无法续接」）。

**为什么**：25/25 PROGRESS 三段全空的根因是没人要求模型填；新增审批门违反铁律（不新增
需审批的门），用**交付卡结构倒逼**是零门成本的强制。

**验收**：未决项空的交付 → deliveredWithGaps 标记 + 回执提醒可见；填了 → 原文进 card.json。

**时长断言**（#15 的落地口）：`plan.targetDuration` 有真值来源（host-tools.ts:4405，
storyboard meta 同源）→ card.json 断言 |final − target| ≤ 1s，超差标 `durationMismatch`
+ 回执警告**不拒收**（混规格会话正是要被显性化暴露，DNS 2 的 45s/300s 混装就再也藏不住）。

## 3. 批次 P2 · 观感与收敛（约 1 人日，P1 后接）

### 3.1 #14 构建期错峰默认（取代「自动修复器」思路）

**改什么**：spec 通道多单元（units ≥2）时，compose 层把各单元的**入场起点统一错峰 4 帧**
（对 unit 轨 startFrame 平移，同 B4 模式，卡生成器零改动）。**不加豁免字段**——刻意齐动的
观感差异只有 3–6 帧（lint 自己的 hint 就是「错峰 3–6 帧」），真机验收把关，出现误伤样本再
加声明机制。

**为什么**：ML-01 同帧齐动 176 条的源头就是 spec 多单元同帧入场；在**产生路径上生成正确
默认值**，比事后「自动修复 manifest」（复盘建议）少一个修复器、少一类「自动改用户片子」
的哲学冲突（D-19：告警不改行为——错峰是默认值不是修复）。

**验收**：双单元 spec 入场起点相差 4 帧；单单元/卡内部动画不受影响；ML-01 真机计数下降。

### 3.2 #4 渲染次数软计数（硬口径挂账）

**改什么**：每次返回抽帧的渲染（probe/spot/普通）都递增一个会话级计数，回执带
「本会话第 N 次抽帧渲染」；N > 12 时追加建议性提示（「渲染次数偏高——按 verification.md
该转定稿，剩余问题记未决项」）。**不拦截**。

**为什么**：直接砍普通渲染的抽帧会伤迭代锚点（91 次 spotFrames 是主要质检手段），统一
硬口径可能杀掉「渲一眼」的正常流；而真正压次数的杠杆已经落了（A2/A3 前置体检 + B4 消
重渲源头）。先软计数观察真机中位数（复盘判据：9.6 → ≤4），不够再上硬口径。

### 3.3 #8 字体存在性预检（解析级挂账）

**改什么**：scaffold/validate 时检查 manifest 引用的非随包字体在 global.fonts[] 声明且
字体文件存在 → 缺失即编译期 warning（「该字体将回落随包族」），渲染前可见。

**为什么**：纸墨项目的 Noto Serif SC 案是「文件在但解析挂死」——解析级预检**自身就会
卡死**（把渲染期的坑搬进编译期），做不了也不该做（卡点 K5）；文件存在性是零风险的那一半。
