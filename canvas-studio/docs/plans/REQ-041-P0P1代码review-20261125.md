## 0. 一句话结论

数据通路是对的（真实数据 11/11 ref 命中、清单 11 条），但**按现在的代码直接跑真机验收**，会在第一次加载段视频时把 11 张卡改成 960×588 并写进 `canvas.json`；「点开第 2 屏听第 2 句」没有入口；换一个新项目则一段都不会有。三项都在下面逐条给证据与修法。

## 1. P0-1 段视频会改写卡片尺寸并持久化（会破坏用户数据）

**证据链**

| 步 | 位置 | 行为 |
|---|---|---|
| 1 | `CanvasNode.tsx:981` | 段 `<video>` 挂 `onLoadedMetadata={handleVideoMetadata}` |
| 2 | `CanvasNode.tsx:626-629` | → `handleMediaLoad` → `onMediaNatural(node.id, w, h)` |
| 3 | `StudioFrame.tsx:2156-2188` | text 卡无 `mediaWidth` ⇒ `neverMeasured` 恒真；再比 `mediaBoxOf` 比例，偏差 10.7% > 5% ⇒ 走 `frameSizeOf` 重设节点框 |
| 4 | `StudioFrame.tsx:2188` | `persistAfter(() => actions.updateNode(...))` —— **写 canvas.json** |

**实测**（`VideoOut/new4/.../超级月亮 2`）：分镜卡 `300×200`、无 `mediaWidth`；`seg-s1.mp4` 为 960×540；`frameSizeOf(960,540) = 960×588`；`mediaBoxOf(300×200) = 300×152`，比例 1.97 vs 1.78。

**后果**：清单返回 11 条的瞬间，11 张卡被放大到 960×588，产生画布版本与 undo 记录，分镜托盘按旧几何算 ⇒ 重叠。直接违反 §9.7「不写画布、不加持久字段、不产生脏版本」。

**修法**（未实施，等放行）：段视频分支只取 `duration` 做角标，不调 `handleMediaLoad`；或在 `handleMediaNatural` 开头 `if (target.kind === 'text') return`（更稳：text 卡本就不该被媒体尺寸驱动）。守卫：断言 handleMediaNatural 对 text 早退。

需求 §9.7「draft 不发段」这个问题只解决了一半：开关打开了，但整片路径不产段。

**候选方案**

| 方案 | 代价 | 风险 |
|---|---|---|
| a. 有 audio 也走分镜路径渲无声段，整片后配合声 | 一次渲染多 N 次段渲 | 混音链路动，成片声音有回归风险（违反零风险约束） |
| b. 整片渲完后按帧窗重渲各段 | ≈ 再渲一遍 | 零风险，慢一倍 |
| c. 客户端 CSR 单段渲染（N1 内核） | 中 | 与 N1 合并，最省重复投入（推荐） |
| d. 从成片切段 | 小 | 用户已否决（响度归一化影响） |

## 4. P1-4 每段台词比成片早 0.333 秒开口

- `segment-audio.ts:56-61` 完整保留 `startFrame`
- `segment-voice-merge.ts:74` 只把 `durationSec` 传给 `buildMuxArgs`，**偏移被丢弃**，音频从 0 开始

实测：s2 段窗 `[235,480)`、旁白 `startFrame=245` ⇒ 段内 10 帧 = 0.333s；s3 `480/490`、s4 `687/697` 同样差 10 帧；只有 s1（0/0）对齐。

后果：成片里台词在转场后 0.33s 才开口，卡上预览第一帧就开口；句尾多截 0.33s。与 A9「起点按段帧窗裁剪」不符。现有 5 条测试全部假设 offset=0，反向变异抓不到。

**修法**：合声加 `(voiceStart - segStart)/fps` 前置静音（`-itsoffset` 或 `adelay`）；测试补一条：偏移非零时参数里必须出现延迟。

## 7. 2026-11-25 15:50 追加：真机「视频与文字重叠」修复

**现象**：分镜卡上段视频被压成一条，正文骑在画面上下。

**根因**：`styles.ts` 里 CV-081 的 `.csNodeSelected .csNodeBody { display:block; -webkit-line-clamp:unset; overflow-y:auto }` 为长分镜稿服务，点选卡后解除折叠 ⇒ 8 行分镜稿摊进 flex，与视频抢高度；`-webkit-box` 消失后行钳失效，正文按内容撑高，视频 `flex:1 1 auto` 被压到几十像素；`.csNodeSegmentCard .csNodeBody` 只改了钳制行数，特异度低于选中态规则，压不住。

**修复**（`src/client/styles.ts`）：

1. `.csNodeSegmentVideoBox` `min-height: 0` → `64px` + `overflow: hidden`（正文再长也不压没画面）；
2. 新增 `.csNodeSegmentCard.csNodeSelected .csNodeBody` 覆盖：`display:-webkit-box` + `line-clamp: 2` + `overflow:hidden` + `flex: 0 0 auto`（选中态也不展开）；
3. CV-081 通用规则保留（长文卡能力不动）。

**守卫**：`tests/req041-segment-layout.test.mjs` 4 条源码闸（min-height 正向 / 段卡正文钳两行不许 unset / 选中态覆盖在位 / CV-081 仍在）。反向变异：把选中态选择器改名 + `min-height` 改 0 ⇒ 2 条变红，恢复后 3904 全绿。
