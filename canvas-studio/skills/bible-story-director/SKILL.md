# 圣经故事剧本导演 · Canvas Studio 适配版

一句话：**用户丢一个圣经故事名，你把它拆成九节「拍摄定稿」。**

## 角色声明

1. **轴上的位置**：**决策型**（题材剧本层）。本 skill 决定"圣经题材的剧本层怎么做"——拆解链路、考据纪律、节拍与时长账、旁白与分镜的映射。它不决定成片流程。
2. **与 `canvas-studio-creation` 的分工**：总纲是底座，本 skill 只**覆盖** `canvas-studio-creation/references/screenplay.md` 的通用叙事骨架（节拍链形态、旁白口径、压缩策略、考据约束），因为圣经题材在时代考据上有总纲没有的硬约束。**不覆盖**总纲四条安全底线（执行模式与审批门禁 / 一致性硬约束 / 工具参数硬限制 / 质检不参与过程），也不代替总纲决定审批节奏与工具参数。
3. **下级细则何时加载**：五本分册按拆解步读——`story-index.md` 在 S1、`period-guide.md` 在 S2、`narrative-framework.md` 在 S3 与 S5、`storyboard-mapping.md` 在 S4/S6/S7/S8、`templates.md` 在 S9。对照表见 §6。

## 0. 定位与边界

**只做剧本层。** 产出目标 = `storyboard.json` 的九节内容（§00–§08）。

越界即停手，以下全部**不归本 skill 管**：

| 不做什么 | 归属 |
| --- | --- |
| 生成基调样张、定妆照、场景概念图、姿态关键帧 | 总纲第 1 / 4 / 5 / 6 步 |
| 写 H3 视频提示词（`promptEn` 字段） | 第 9 步 `h3-prompt-writing` |
| 逐镜出片、BGM、成片合成、`qc_shot` | 总纲第 9 / 10 / 11 步 |
| 另建「故事大纲」「剧本」节点 | 总纲铁律——剧本内容**只进** §00 / §03 / §05 |
| 改风格预设表、改风格 GIF 网格 | 风格体系走 `style-presets.md`，本 skill 不动 |

**§04 的 `promptEn` 一律留空**。本 skill 产的是中文规划稿；英文视频提示词是出片前按 `h3-prompt-writing` 现写的，提前写会与实际参考图组合脱节。

## 1. 与总纲的关系

本 skill 属**内容层**（题材导演），不属风格层。总纲 `canvas-studio-creation` 仍是底座，本 skill 加载后：

- **覆盖**：总纲 `canvas-studio-creation/references/screenplay.md` 的通用叙事骨架——节拍链形态、旁白口径、压缩策略、考据约束，以本 skill 为准（圣经题材在时代考据上有总纲没有的硬约束）。
- **不覆盖**（总纲四条安全底线，任何 skill 不得绕过）：① 执行模式与审批门禁；② 一致性硬约束（`lockedPrompt` 逐字节复用、镜位版本 `replaces`）；③ 工具参数硬限制（`filename` 句柄约定、参考图数量、16:9 / 9:16）；④ 质检不参与过程。

**加载时机**：澄清第 ① 步确认产物形态之后、总纲第 2b 步「拍摄定稿创作」时加载。用户只说了故事名、还没澄清形态时，先按总纲走澄清。

## 2. 九步拆解流水线

| 步 | 动作 | 落到 | 依据分册 |
| --- | --- | --- | --- |
| S1 | 故事名 / 人物名 → 出处（书卷 + 章:节）+ 一句话摘要 | `§01` | `references/story-index.md` |
| S2 | 时代考据：时代标签 / 服饰 / 建筑 / 器物 / 人群 | `§01` | `references/period-guide.md` |
| S3 | 主题、情感弧线、结局处理（是否点明寓意） | `§00` | `references/narrative-framework.md` |
| S4 | 人物表：人读 `profile` + 机读 `gen.lockedPrompt` | `§05` | `references/storyboard-mapping.md` |
| S5 | 幕 → 场 → 节拍链，每拍标时长占比（Σ ≈ 目标时长） | `§04` 骨架 + `meta` | `references/narrative-framework.md` |
| S6 | 旁白逐句（中文，一句一镜，带时长） | `§03` | `references/storyboard-mapping.md` |
| S7 | 分镜表：镜号 / 景别 / 运镜 / 时长 / 衔接 / 画面 / 声音 | `§04` `scenes[].shots[]` | `references/storyboard-mapping.md` |
| S8 | 声音预算 + 素材清单 + 一致性硬约束 | `§06` `§07` `§08` | `references/storyboard-mapping.md` |
| S9 | 分笔 `write_storyboard`，写完停在落地门 | — | `references/templates.md` |

**S6 与 S7 的依赖是双向的**：旁白一句一镜（`§03.lines[].shotRef`），分镜反过来引用旁白（`§04.shots[].narrationRef`）。先出旁白再出分镜，两边 id 对齐——细节见 `references/storyboard-mapping.md` §「双向引用」。

## 3. 产出节奏（两段式，不可省）

**第一段 · 可读拆解稿**：S1–S8 全部先在对话里以表格给出（模板见 `references/templates.md`）。这一步不出工具调用，纯文本，用户改起来最便宜。

**第二段 · 分笔落盘**：随后动 `write_storyboard`，按四笔填满（与总纲 2c 一致）：

1. `meta` + `creative` + `visual` → 进度 3/9
2. `storyboard`（体量最大）→ 4/9
3. `characters` + `narration` + `sound` → 6/9
4. `facts` + `assets` + `constraints` → 9/9

每笔之间不要问用户——那是同一次任务内的连续动作。写完九节停下来请用户在画布顶条「拍摄定稿」覆盖层审阅。**落地是用户按钮，不是你的工具调用**；写完就停手，不要抢跑任何产线动作。

## 4. 圣经题材专项硬约束（`§08` 默认模板）

这五条是本 skill 相对总纲的全部增量，**逐字写进 `§08`**（用户明确要求删哪条才删）：

1. 时代锁定：画面为公元前近东/中东，**禁止**中世纪欧洲元素（骑士板甲、尖顶盔、城堡、哥特教堂、十字军、纹章盾）
2. 人群特征：闪米特/中东人群相貌，**禁止**金发碧眼白肤的默认脸；耶稣与门徒同理，不得欧化
3. 服饰器物：依 `references/period-guide.md` 的时代表，**同一片内不混用不同时代器物**（如埃及段不出现罗马军团）
4. 情节忠实：不增删人物、不改结局、不把神迹改写成自然现象；允许镜头语言自由（角度、节奏、光影）
5. 跨镜一致性：同一人物的服装 / 胡须 / 发型 / 年龄，同一场景的空间方位与关键道具，全集恒定

⚠️ **这五条为什么重要**：AI 生成圣经题材的默认失败模式就是出一堆中世纪欧洲骑士与文艺复兴天使。第 1、2 条是最容易翻车的两条，写 prompt 时的正向表述要落在 `§02` 的 token 里（如「unbleached linen tunics, Middle Eastern features, sun-baked mudbrick」），约束不能只躺在 `§08`。

## 5. 时长账与压缩策略

圣经故事普遍塞不进 30 秒——大部分是 2 分钟以上的材料。**默认档 60s / 8 镜 / 平均 7.5s**，档位表与三种压缩策略（单场景切口 / 三幕压缩 / 双线并置）见 `references/narrative-framework.md`。

硬顶：`STORYBOARD_MAX_SHOTS = 15`（超限告警），单镜 ≤15s ⇒ 理论上限约 225s，但常规不超过 120s（15 镜 × 8s）。

## 7. 自检清单（走进 S9 之前逐条过）

1. **出处**：`§01` 里有没有「书卷 + 章:节」？章号是不是从 `story-index.md` 取的（不是凭记忆写的）？
2. **考据**：`§01` 里的时代/服饰/器物条目是不是都来自 `period-guide.md`？有没有出现禁用元素？
3. **忠实**：有没有为了好拍而增删人物、改结局、把神迹写成巧合？
4. **时长**：各个节拍时长占比之和 ≈ `meta.targetDuration`？镜数 ≤15？
5. **旁白**：每句是否一句一镜、时长可控（中文口播约 4 字/秒，别写出念不完的长句）？
6. **一致性**：`§05` 每个角色的 `lockedPrompt` 是否足够具体到能锁住服装与面容？跨镜 `§08` 第 5 条是否覆盖了所有主要人物与场景？
7. **越界**：有没有顺手去生成图片、写 `promptEn`、或建大纲节点？有就删掉。

## 8. 停手规则

`write_storyboard` 九节写完 → **停**。等用户在「拍摄定稿」覆盖层点「确认落地」。用户提意见 → 改对应分节后重新 `write_storyboard`（分节合并：只传要改的节，没传的保留）。落地后的出图/出片是总纲的活，交回去即可。
