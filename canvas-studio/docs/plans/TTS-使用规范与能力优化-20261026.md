# TTS 使用规范与能力优化（2026-10-26）

> 依据：`docs/api-probe/tts-capability-2026-10-26T09-37-35/`（三轮实测 + 独立基频交叉验证），
> 代码核对 `src/host-tools.ts` / `src/remotion/manifest.ts` / `src/generate.ts`。
> 本文所有结论标注来源：**[实测]** = 本轮探针数据；**[代码]** = 读实现确认；**[工程]** = 由前两者推导的纪律。
> 目的：让 agent 每次调用 TTS 都走同一条可靠路径，不再靠试错烧额度。

---

## 0. TL;DR（三条最重要）

1. **多段旁白必须先造「音色锚」**：第一段合成出来后，后续每段都用 `refaudio: @ref[锚节点]`。
   只靠 `instructPrompt` 逐字复用**不足以保证一致** —— [实测] 同一串 instruct 连发 3 次，
   基频极差 **45.1%**、时长极差 **8.2%**。这是本文最重要的行为改变。
2. **时长只有两个确定性杠杆**：改文本长度（≈4 字/秒），或 `speed`（÷ 目标倍率，实测 ÷speed 精确到 1%）。
   自然语言写「慢速/快速」，[实测] 幅度 −3%~+60% 且跨轮不稳定，**不可当刻度**。
3. **多句旁白排帧只能走 `render_composition` 的 `audio.voiceOver[]`**；
   `compose_video` 的 `bgmNodeId` 只接一段音频、从 0 秒铺起，多句用它必然错位。

## 1. 能力边界（先认清上限，再谈用法）

### 1.1 后端契约只有 3 个字段 [代码]

`TTSRequest = { txt_prompt, instruct_prompt, refaudio }`（读 `/openapi.json` 确认）。

**没有**：`voiceId`、`duration`、`speed`、`format`、`emotion` 枚举、SSML、多说话人、字级时间戳。

⇒ 一切「音色 / 语气 / 方言 / 语言」都靠 `instructPrompt` 的自然语言；一切「时长」都靠文本或宿主后处理。

### 1.2 宿主侧多出来的两个确定性参数 [代码]

| 工具参数 | 实现 | 区间 | 作用 |
|---|---|---|---|
| `speed` | 本地 ffmpeg `atempo` | 0.5–2.0 | 变速**不变调** |
| `pitchSemitones` | 本地 ffmpeg `asetrate` + 时长补偿 | −12 ~ +12 | 变调**不变速** |

它们**不是后端字段**，走本地 `src/speech-post.ts` 后处理链；失败不阻断交付，结果里带 `warnings` [代码]。

### 1.3 本轮实测数字（只列能当依据的）

| 项 | 结果 | 结论 |
|---|---|---|
| 同一 instruct 连发 3 次 | 时长极差 8.2%，F0 极差 **45.1%** | 自然语言音色**不可复现** |
| 带 refaudio 三轮 | 106≈108 / 182≈191 / 152≈152（每轮锁住当轮参考） | **克隆真实生效**，且稳定 |
| 不带 refaudio 三轮基线 | 157 / 129 / 147 乱跳 | 不锚定 = 每次抽新音色 |
| `speed=0.9 / 1.15` | 时长 ×1.109 / ×0.876（理论 1.111 / 0.870） | **确定性，可直接反解** |
| `pitch=±3` 半音 | F0 ×0.85~0.91 / ×1.07~1.17（估计噪声 ±10%） | 方向与量级成立 |
| 正文写「（停顿两秒）」 | 多 4 字，时长反而更短 | **无效**，会被念出来 |
| 长文线性度 | 22 字 4.77 字/秒 → 89 字 4.14 字/秒 | 近似线性，**不能精确反推** |
| 语速词「慢速/快速」 | −3% ~ +60%，跨轮不稳定 | 仅方向性提示 |

> 生成耗时**不参与任何结论**（后端单任务串行，排队污染严重）。以上全部是 ffprobe / 解码得到的产物属性。

### 1.4 做不到的事（别承诺）

- 指定「正好 8.0 秒」→ 只能 `speed` 逼近，误差 ±1~2%。
- 字级时间戳 / 逐字高亮 → 需 forced alignment，本期无。
- 一次调用多说话人对话 → 只能分多次合成、各自 `startFrame`。
- 稳定 `voiceId` 跨项目复用 → 只能靠 refaudio 文件本身。

## 2. 标准使用流程（SOP）

### 阶段 0 · 判据：这件事该不该用 TTS

```
用户要的声音，是「画面里那个人开口说」吗？
├─ 是（要口型/对口型/角色说台词） → 不用 TTS
│    把 <d>[语言]原话</d> 写进视频提示词，交给 H3 原生出声（REQ-017）
└─ 否（旁白 / 画外音 / 旁白式解说 / 独立音频资产） → 用 TTS
```

⚠️ TTS 产物**进不了口型**。它只能作为独立音轨混进成片，或作为 `audioRefs` 音色参考（≤15s）。

### 阶段 1 · 造「音色锚」（本文核心）

**目标**：把「随机抽到的好音色」冻结成一个可复用的参考音频。

两种做法，优先 A：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 复用首句**（推荐） | 先合成正片第一句（**不传 refaudio**）→ 它就是锚 → 后续每段 `refaudio: @ref[第一句节点标题]` | 零额外合成 |
| B. 专用中性锚 | 单独合成一句 5–10 秒、**语气中性**的样音（如平静自述），标为「音色锚」不上时间轴 | 多 1 次合成 |

> 选哪种：正片首句语气中性（平静叙述）→ A；首句就是哭喊 / 耳语 / 嘶吼 → 用 B。
> 理由（[工程] 推断，未单独实测）：克隆会把参考音的**发声方式**一起带过去，用极端语气做锚，
> 后面每句都会偏。宁可多花一次合成，也不要给全片定错基调。

**锚的硬要求** [工程]：
- 单人人声、**无 BGM / 无环境声**（混响和配乐会被一起克隆）。
- 长度 2–15 秒（与 `audioRefs` 规格一致，顺带可直接当视频参考音）。
- 锚的 `instructPrompt` 就是全片人设，**之后不许改**。
- 锚节点命名固定：`音色锚 · <角色名>`，方便 `@ref` 命中和人工核对。

**验收**：锚合成后必须**实际听一遍**（或看 F0 是否落在预期音区）；
抽到不合适的声音就重抽一次，**锚定错了会让全片错**。

### 阶段 2 · 写稿与拆段

- 按 **4 字/秒** 估时长写稿；要 10 秒 ≈ 40 字。
- 单次调用 **≤120 字**；更长的旁白**按句拆段**（一句一段，便于独立排帧与重配）。
- `text` 里**只写要念的字**：不写括号、不写「停顿」「(笑)」、不写舞台指令 —— [实测] 会被念出来。
- 要停顿/语气：写进 `instructPrompt`（「说完稍作停顿」也只能弱引导），
  **要精准停顿只能靠排帧时留空白**（下一段 `startFrame` 往后挪）。

### 阶段 3 · 串行合成（每段都带锚）

顺序固定，**不许并行**（后端单任务，并发只会排队）：

```
段1(锚): tts_voiceover(text, instructPrompt=人设)              ← 不传 refaudio，它就是锚
段2:     tts_voiceover(text, instructPrompt=人设, refaudio=锚)
段3:     tts_voiceover(text, instructPrompt=人设, refaudio=锚)
```

> 若用方案 B（专用中性锚），则**每一段都带** `refaudio`，包括正片第一句。

- `instructPrompt` **逐字一致**（一个逗号都别改）—— 它控制语气/韵律，改了声音就飘。
- **全部合成完再进入下一步**：逐段核对工具返回的 `nodeId` / `duration` 是否齐全，
  缺段（首段丢失最常见）先补，别带着缺口排帧。

### 阶段 4 · 量真值、算帧号

工具返回的 `duration` 是 **ffprobe 真值** [代码]，直接用它，不要再估：

```
startFrame₀ = 0
startFrameₙ = round( (Σ 前面各段 duration + Σ 间隔) × fps )
```

- `fps` 取成片设定（支持 24 / 25 / 30 / 60），与 manifest `meta.fps` 必须一致。
- **间隔就是节奏**：句间留 8–15 帧（0.3–0.5s）自然；情绪转折留 20–30 帧。
- 下一段的 `startFrame` 必须 ≥ 上一段 `startFrame + round(duration×fps)`，**否则会叠字**（无自动避让）。

### 阶段 5 · 进成片（两条路，别选错）

| 场景 | 入口 | 要点 |
|---|---|---|
| **多句旁白 + 代码片**（字幕卡/数据卡/转场） | `render_composition` 的 `audio.voiceOver: [{src, startFrame, volume?}]` | 最多 **64 条** [代码]；`src` 必须是**同源 URL 原样抄**（`/canvas-studio/assets/...`），**不能写 `@ref` 或节点 id** [代码] |
| **单段旁白 + 已有片段拼接** | `compose_video` 的 `bgmNodeId=<旁白节点 id>` | 自动识别为旁白轨：满音量、无淡入淡出、允许短于成片 [代码]；但**从 0 秒铺起** |
| 单句旁白 + 代码片 | `render_composition` 的 `audio.voiceOverUrl` | 与 `voiceOver[]` **互斥**，同时给会拒收 [代码] |

其余音频字段 [代码]：

```jsonc
"audio": {
  "bgmUrl": "/canvas-studio/assets/bgm.mp3",
  "mix": { "bgmVolume": 0.35, "voiceVolume": 1.0 },
  "fadeInSeconds": 1.5, "fadeOutSeconds": 2.0,
  "duck": { "amount": 0.55 }        // 以字幕窗口为依据自动压低 BGM
}
```

### 阶段 6 · 交付前自检（6 条，逐条过）

1. 每段是否都带了**同一个** `refaudio`？（漏一段 = 多一个音色）
2. `instructPrompt` 是否**逐字相同**？
3. 每段 `startFrame` 是否 ≥ 前段结束帧？（防叠字）
4. `meta.durationInFrames` 是否 ≥ 最后一段旁白结束帧？（被截断=尾巴没声）
5. `audio.voiceOver[].src` 是否都是同源 URL（不是 `@ref`）？
6. `warnings` 是否为空？（非空 = `speed`/`pitch` 后处理没生效，必须如实告知用户）

## 3. 使用规范（硬规则）

> 违反任一条，产出就是「能听但不能用」。每条给出违反后的**可见症状**，便于自查。

| # | 规则 | 依据 | 违反症状 |
|---|---|---|---|
| R1 | 多段旁白**必须**先定锚，后段全部 `refaudio` 引用同一锚 | [实测] instruct 复用不足 | 30s 片出现 2–3 个音色 |
| R2 | 全片 `instructPrompt` 逐字一致，禁止按段重写 | [工程] 它控语气/韵律 | 情绪忽高忽低、语速跳变 |
| R3 | 锚必须纯净：单人、无人声外的 BGM/环境声 | [工程] 克隆会带上背景 | 每段都带同一层底噪/混响 |
| R4 | 一次调用一段，串行；不许并发 | [代码] 后端单任务 | 排队超时、部分失败 |
| R5 | 单段 ≤120 字；长旁白按句拆 | [实测] 长文语速漂移 4.1–4.8 字/秒 | 后半段明显变快/抢 |
| R6 | `text` 只写要念的字，禁括号/舞台指令 | [实测] 会被念出来 | 旁白里冒出「停顿两秒」 |
| R7 | 时长只用工具返回的 `duration`（ffprobe 真值） | [代码] 后端 `duration` 是耗时 | 排帧整体偏移 2–3 倍 |
| R8 | 排帧 `startFrame = round(秒×fps)`，与 manifest `meta.fps` 同源 | [代码] | 全片旁白整体错位 |
| R9 | 段间不重叠（下一段起点 ≥ 上一段终点），除非刻意叠声 | [代码] 无自动避让 | 两句糊在一起 |
| R10 | 多句进成片走 `audio.voiceOver[]`；`compose_video` 只接单段 | [代码] | 只有第一句有声 |
| R11 | `audio.voiceOver[].src` 写同源 URL，不写 `@ref`/节点 id | [代码] 校验拒绝 | 渲染前直接拒收 |
| R12 | 单句 `voiceOverUrl` 与多句 `voiceOver[]` 二选一 | [代码] 互斥校验 | 同一句播两遍 |
| R13 | 改词重配用 `replaces=<旧节点 id>` 原地重写 | [代码] | 画布堆满废弃卡、血缘断 |
| R14 | 音色不准时最多重试 **1 次**，之后转 `speed`/`pitchSemitones` 或如实告知 | [实测] 自然语言已到顶 | 烧额度、越试越飘 |
| R15 | `warnings` 非空必须转告用户 | [代码] 后处理失败信号 | 嘴上说「放慢了」实际没生效 |
| R16 | 要口型一律不用 TTS，写 `<d>` 给视频模型 | [代码] REQ-017 | 音画不同步、对不上嘴 |

## 4. 使用方法（参数速查）

### 4.1 `tts_voiceover`

| 参数 | 必填 | 说明 |
|---|---|---|
| `text` | ✅ | 要念的成品口语稿（≤120 字建议） |
| `instructPrompt` | — | 七维自然语言：语言/性别/年龄/语气/情感/语速/方言 |
| `refaudio` | — | **音色锚**：`@ref[音色锚 · 角色名]` / 节点 id / `lib:<资产id>` / `local:<文件名>` |
| `speed` | — | 0.5–2.0，变速不变调 |
| `pitchSemitones` | — | −12~+12，负数更低沉 |
| `replaces` | — | 旧音频节点 id，原地重配 |

**instructPrompt 七维模板**（缺哪维，模型就在那维自由发挥）：

```
<年龄><性别>，<语气>，<情感>，<语言/方言>，<语速>
例：32岁女性，压低声音说，克制而紧绷，普通话，中速
例：58岁男性，沙哑烟嗓，疲惫怀念，四川话，慢速
```

### 4.2 三个完整示例

**① 多句旁白（标准路径）**

```jsonc
// 1) 锚 = 第一句（不传 refaudio）
tts_voiceover({ text: "那天夜里，我又听见了敲门声。",
                instructPrompt: "32岁女性，压低声音说，克制而紧绷，普通话，中速" })
// → { nodeId: "aud_01", duration: 4.32, url: "/canvas-studio/assets/voxcpm_a1.mp3" }

// 2) 后段全部引用锚（instruct 一字不改）
tts_voiceover({ text: "我没有开门。",
                instructPrompt: "32岁女性，压低声音说，克制而紧绷，普通话，中速",
                refaudio: "aud_01" })        // 或用 @ref[第一句的节点标题]
// → { nodeId: "aud_02", duration: 1.85, ... }

// 3) 排帧（fps=30）
// aud_01: startFrame 0        (4.32s → 130 帧)
// aud_02: startFrame 145      (130 + 15 帧间隔)
render_composition({
  manifest: JSON.stringify({
    meta: { durationInFrames: 300, fps: 30, width: 1080, height: 1920 },
    audio: { voiceOver: [
      { src: "/canvas-studio/assets/voxcpm_a1.mp3", startFrame: 0 },
      { src: "/canvas-studio/assets/voxcpm_a2.mp3", startFrame: 145 }
    ] },
    tracks: [ /* 见 code-driven-explainer 的 manifest 契约 */ ]
  })
})
```

**② 单段旁白 + 已有片段**

```jsonc
compose_video({ clipIds: ["v1","v2","v3"], bgmNodeId: "aud_01" })
// 旁白自动按旁白轨处理：满音量、无淡入淡出、允许短于成片
```

**③ 音色不对（确定性补救）**

```jsonc
// 「再苍老一点、再慢一点」——不再重试 instruct
tts_voiceover({ text, instructPrompt: 原串, refaudio: "@ref[音色锚 · 父亲]",
                pitchSemitones: -3, speed: 0.9 })
```

### 4.3 时长反解（要「正好 N 秒」）

```
speed = 原始时长 / 目标时长        // 实测误差 ≤1%
```

先按 `speed=1` 合成一次拿到真值，需要时用 `replaces` 原地重配并带 `speed`。
不要在 instruct 里写「快速」来凑时长。

## 5. 反模式（含现存文档漂移）

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 每段各写一句「40岁男性，磁性嗓音」 | [实测] 同串词也会换音色 | R1 音色锚 |
| 用 `compose_video` 混 3 句旁白 | 只接 1 个节点、从 0 铺 | `audio.voiceOver[]` |
| 在 `text` 里写「（停顿两秒）」 | [实测] 被念出来 | 排帧留空 |
| 反复重写 instruct 求「更苍老」 | [实测] 音色不可控 | `pitchSemitones:-3` |
| 用估算的 4 字/秒直接排帧 | [实测] 4.1–4.8 漂移 | 用工具返回真值 |
| 把节点 id 写进 `voiceOver[].src` | [代码] 校验拒收 | 抄同源 URL |
| 想说台词却用 TTS 贴上去 | 无口型 | `<d>[语言]原话</d>` |

#### P1-1 为什么是这 6 步，压成 1 次调用解决什么

| # | 步骤 | 原先谁做 | 成本 | 最典型的错 |
|---|---|---|---|---|
| 1 | 造锚（合成首句/中性样音） | agent 1 次调用 | 1 次额度 | 忘传 `refaudio`、拿极端语气当锚 |
| 2 | 写稿 + 拆段 + 七维 instruct | LLM（token） | 无额度 | 每段各写一句声音设计 |
| 3 | 串行合成 N 段 | agent **N 次**调用 | N 次额度 | 漏段、并发、某段忘带锚 |
| 4 | 取每段真值 `duration` | agent 读 N 条结果 | 无 | 误用后端 `duration`（是耗时，差 2.8×） |
| 5 | **算 `startFrame`** | **LLM 手算累加 + round** | token | 累加错、fps 混用、漏间隔 → 叠字/错位 |
| 6 | 组装 `audio.voiceOver[]` + 渲染 | agent 1 次调用 | 1 次渲染 | `src` 写成 `@ref`、超 64 条、与 `voiceOverUrl` 同给 |

第 5 步可靠性最差（纯算术 + 单位换算，错了要整片重渲才发现）；第 3 步额度最贵；
第 2 步最容易违反纪律。**A' 把 1+3+4+5 收进代码，只留第 6 步给 agent 抄数组。**

取舍理由：不接管 manifest 组装，是因为 `src` 同源约束（`validateAssetRefField`）与
`durationInFrames` 一致性**已经由渲染器校验**，再写一份等于同一规则两处实现；
而且要接管就得处理回滚语义 —— 那是真正会失控的部分。

#### P1-1 实际入参 / 出参（与本节早期的草案有差异，以代码为准）

```ts
tts_narration({
  lines: Array<{ text: string; gapSeconds?: number; instructPrompt?: string }>,
  voice?: { instructPrompt?: string; refaudio?: string },  // refaudio 缺省 = 拿 lines[0] 当锚
  fps: 24 | 25 | 30 | 60,          // 必须与 manifest.meta.fps 相同
  startFrame?: number,             // 首段起点，缺省 0
  gapSeconds?: number,             // 全局段间隔，缺省 0.4（≈换气）
  speed?: number,                  // 0.5–2.0，宿主 ffmpeg 确定性变速
  pitchSemitones?: number,         // ±12 半音，变调不变速
})
// → { anchorNodeId, anchorSource: 'given'|'first-line', fps, clips[], voiceOver[], totalFrames, warnings[] }
```

与早期草案的差异（**记录原因，不做事后美化**）：
- **`replaces` 没做**：批量重配要么真事务、要么显式两阶段，半吊子的「按序替换」在
  中途失败时会把稿子与音频的对应关系搞乱（比不做更危险）。改词仍走 `tts_voiceover(replaces=)`。
- **`voice.instructPrompt` 改为可选**：只有 `refaudio` 时（纯克隆）完全合法，
  强制必填会逼模型编一句没意义的人设。
- **多了 `totalFrames`**：让 agent 能直接核对 `totalFrames ≤ durationInFrames`，
  不必自己取 `clips[last].endFrame`（那正是它容易算错的地方）。
- **多了 `warnings`**：时长探测失败（`duration = 0` 按 1 帧排）、段间隔为负（有意重叠）
  必须如实转告，静默处理会让「两句叠在一起」变成不可见的缺陷。

#### P1-2 音色槽：复用资产库 `voice` 分类，不新建数据结构（调研结论 2026-10-26）

- 已具备（无需重做）：`LibCategory` 含 `voice`（标签「音色」）、资产库左侧「音色」tab、
  音频节点可右键入库（`collectNodeMediaSources` 只拒视频）、参考音色候选支持 `lib:<id>`、
  `refaudio: "lib:<id>"` 经 `materializeLibraryMedia → promoteAssetFile` 可用。
- 真缺口：**agent 侧没有任何资产库工具**（当时 28 个工具里没有 `library_*`）⇒ 列不出音色、
  也存不进音色，「音色槽」只有人类点 UI 能用。
- 顺带修的硬 bug：`isLibCategory` 漏了 `voice`（见 P0-4）——不修的话 `voice` 条目根本写不进库。
- 实际交付：`list_library_assets`（只读，不接审批门）+ `add_to_library`（写入，接审批门）。
  拒收路径复用既有单点：视频节点 → B-3 文案；重名 → `CS-LIB-002` 指路；节点不存在 → `CS-LIB-003`。

## 7. 如何验证（自测方法）

1. **能力回归**：`node scripts/probe-tts-capability.mjs --report-only --out docs/api-probe/tts-capability-2026-10-26T09-37-35`
   重出报告，比对 §1.3 数字是否仍成立（后端换模型时第一时间发现）。
2. **全量重测**（需额度）：`node scripts/probe-tts-capability.mjs`（16 次合成，串行约 3–5 分钟）。
3. **流程验收**（P0/P1 改完必做）：跑一条 5 段旁白的 30 秒片 →
   人工听：是否同一人声、有无叠字、结尾是否被截；看渲染 `report{}` 的 `voiceOver` 条数与帧号。
4. **确定性参数**：同一文本 `speed=0.9` 两次，时长差应 ≤1%（若 >5%，说明后处理链有问题）。

## 8. 一页口诀（可直接塞进 skill 顶部）

```
先判口型：要口型写 <d>，不要用 TTS。
再定锚：首句语气中性就用它当锚，否则单造一条「音色锚 · 角色」（不上时间轴）。
三段起：一段一调用，串行不并发，每段带同一 refaudio。
instruct 不改：逐字复用，改一个字声音就飘。
要时长：只用 duration 真值，speed 反解（÷目标）。
排帧：startFrame = round(秒×fps)，句间留 10 帧。
进成片：多句走 audio.voiceOver[]，src 抄同源 URL；单句才给 bgmNodeId。
交付前：查锚、查帧、查尾、查 warnings。
```
