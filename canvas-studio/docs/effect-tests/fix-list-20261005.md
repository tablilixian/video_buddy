### M-1 镜位级取代判据误伤：多参考图跨镜时退化为全局串链

- **状态**：✅ 已落地（CV-277-a）。判据 `.some()` 交集 → `anchorCoveredBy`（旧 ⊆ 新）；锚点两侧同口径（`shotAnchorCardsOf` / `newNodeAnchorCards`，显式优先、血缘唯一回退）。守卫 5 条新增、原 16 条零回归；现场数据回放 3 段 15.00s。

- **位置**：`canvas-studio/src/shot-versions.ts:199-205`
- **现状**：

  ```ts
  if (anchorCards.size > 0) {
    for (const node of nodes) {
      if (node.kind !== 'video' || node.toolName === 'compose') continue
      if (!isActiveShot(node) || ids.has(node.id)) continue
      if (node.sourceIds.some((id) => anchorCards.has(id))) ids.add(node.id)  // ← 病根
    }
  }
  ```

  `.some()` = **有任一张分镜卡相同就判同镜位**。

- **为什么错**：CV-222 的设计前提是「一条视频只挂一张分镜卡」。但 `CV-031 关键帧继承`（`generate.ts:1505-1519`）会把每张参考图各自挂着的分镜卡**全部**继承进视频节点。而 `shot-format.md:29` 第 9 步要求「参考组合必须 ≥3 张」，agent 补位时引用了别镜关键帧 → 每条视频 `sourceIds` 含 2 张卡 → 任意两条共享「分镜卡1」→ 6 条串成 v1→v6 单链。

- **本次实证**：`canvas.json` 里 5 条视频带「已失效」，其中 2 条**实际在成片里**（`3b5faf9c` / `60fa2981`）。

- **修法（推荐 A，1 行）**：`some` 改为集合包含判定——旧节点的锚点集必须是新节点锚点集的子集或相等（反向的严格包含），即「旧节点不能有新节点没有的卡」：

  ```ts
  // 新节点锚点集覆盖旧节点锚点集 ⇒ 同镜位（含换参考组合重跑）
  // 反之（各自引用了对方没有的卡）⇒ 不同镜位，不取代
  ```

  语义：同镜位重跑时新旧锚点集相同（CV-222 原始用例成立）；跨镜互引时各有对方没有的卡 ⇒ 不触发。

- **必须补的守卫测试**（现有 16 条测不到）：
  - `tests/shot-versions.test.mjs` 现有 `:130`「不同镜位互不误伤」用的是**每镜只挂一卡**的干净形态，要加一条**双卡交叉**用例：镜1 视频 `sourceIds=[card1,card2]`、镜2 视频 `sourceIds=[card2,card3]`，两者锚点集各有对方没有的卡 ⇒ 互不取代。
  - 回归：CV-222 原始用例（同卡不同参考图）必须仍绿。

- **验收**：
  1. typecheck 两套 + tsdown 三段
  2. `test:smoke` 净增 0（基线 5 条红：studio-defaults ×4 + minimax-skill ×1）
  3. 新建一个 ≥2 镜的多参考图项目，各视频节点应**无** supersededBy
