## 4. 门槛 3 详证：`production_plan` 输出 → `video_composite` 参数

`plan.units[]` 每项字段：`id` / `shots[]` / `ranges[]` / `duration` / `mode`（multi_shot|single|split）/
`calls` / `refs[]`（`tag` + `what` + `user`）/ `prompt`（`镜头i（a–b s）：…` 拼装）/ `continuity`（S05 尾帧衔接）/
`image_prompt` / `prompt_missing`；`plan` 层另有 `model_limits` / `rules` / `calls` / `gen_shots`。

| 它的字段 | 我们的落点 | 适配量 |
|---|---|---|
| `prompt` + `镜头i（a–b s）` 多镜拼装 | `video_composite.prompt` | 中：纯文本可直接贴，但标签要改（下条） |
| `refs[].tag`：`@图片1` / `@视频1` | `filenames` 的 `<Picture N>` / `videoRefs` 的 `<Video N>` | 中：**标签语法不同**，需换名与换序 |
| `model_limits`（seedance2 单次 ≤10s、`video.multi_shot`） | `video_composite.duration` / `model: 'h3' \| 'seedance2'` | **大**：我们的 H3 单次只出一段，**没有 `multi_shot` primitive**；`mode:'multi_shot'` 必须拆成多次调用 |
| `refs` 数量 | `filenames` 1–9 张、`videoRefs` ≤3（单段 2–15s、合计 ≤15s）、`audioRefs` ≤3、图+视频+音频**合计 ≤12 文件** | 中：`_limits.ref_video` 只是布尔（顶多 `@视频1`），**没有合计 12 文件约束**，且它不区分视频/音频参考的时长上限 |
| `continuity`（S05 尾帧衔接） | `shotTransition: 'chain'` + `extract_last_frame` 取上一镜末帧填 `filenames` 首张 | 小：语义一致，有现成工具 |
| `mode:'split'` 超长切段 | 拆多次 `video_composite` + `compose_video` 拼接 | 小：我方本来就有拼接工具 |
| `image_prompt` / `prompt_missing` | 生图链路 / 交付前复述未决项 | 小：语义可直接用 |

**结论**：门槛 3 的「能读懂」成立；「不需改写直接贴进 `video_composite`」**不成立**——至少标签语法、
合计文件数、以及 `multi_shot` 能力缺失三处必须适配。这也印证评估文档 S3 的「上限参数换成我们
的实际规格」是必要而非可选。
