## 三、立即疑点（分析从这两条开始）

**P0-a · 报告为什么没落盘**（验收标准③直接不满足）。三个假设，按可判定性排序：

1. **Host 跑的是旧构建**（无 `POST /canvas-studio/test-report` 路由）→ `saveTestReport` 得 404，被执行器 catch 后只进了浮窗日志（「报告写入失败：…」）。验证：比对桌面实际加载的 `lib/index.js` 构建时间与提交 `cc3bfbd142` 的时间；或对运行中的 Host 直接 `curl -X POST http://127.0.0.1:<port>/canvas-studio/test-report` 看是 404 还是 400。**若坐实：这是「Host 与 client 必须同批更新」的发版纪律缺陷，记 bug-tracker**。
2. **追加指令回合未完成**（手动停止 / 等待超时 / 中断）→ 报告写于每轮断言之后，turn 0 的报告本应存在——除非中断发生在 turn 0 断言完成前。验证：用户回忆/截图浮窗日志最后几行（§七可选物料①）；对照 canvas 最后节点时间 20:53:55 与用户结束操作的时间。
3. **报告体被请求体积上限拒收**（报告折叠了全部节点 generationPrompt，可能上百 KB；`routes.ts` 的 `readJson` 有 bounded 上限）。验证：读 `routes.ts` readJson 的 MAX 值，离线 `buildAutoTestReport` 估算真实体长。

**P0-b · 镜位视频走了 `video_composite` 而非 `video_generate`**。机器断言 `videos-active` 只认 `video_generate`，必然 0/3 红——但这**不是断言库 bug，而是被测行为差异**，要给结论三选一：
- (a) `canvas-studio-creation` / shot-format 规范允许多图合成镜 → 断言口径该放宽（把 video_composite 计入镜位，同时校验来源数与时长）；
- (b) 规范不允许（应逐镜关键帧→video_generate）→ skill 纪律缺口，记 skill 修复项；
- (c) 剧本没写死「每个分镜先出关键帧，再出视频」的执行方式被 agent 自由发挥 → 剧本措辞收紧，出场景 v2。
注意成片结构（3 段、15.51s、来源充足）其实是对的——这条疑点测的是**工具选择纪律**，不是链路可用性。

**P0-c · 追加指令回合是否真跑了**。被取代的只有 1 个 image_generate（不像「孙女四视图重出」——那是 character_sheet 节点，一个都没被取代）。`supersede-chain` 检查点在 turn≥1 才参与；若 turn 1 没跑/没做完，它是「未执行」而不是「失败」，归因时勿混淆。

## 四、分析任务清单（按优先级）

- **P0 三个疑点归因**（§三）→ 各给结论 + 证据；报告缺失若坐实为构建/发版问题，用 `lib/auto-test-report.js` 的 `buildAutoTestReport` 从 canvas.json + history **离线补写**报告到项目目录（文件头标注「离线补写，非运行时产物」），把验收标准③的物料补齐。
- **P1 机器断言离线重放**：node 脚本直连 `lib/auto-test-checkpoints.js` 的 `runAutoTestCheckpoints(ids, snapshots, turnIndex)`。要点：
  - `snapshots = { project, nodes, history, queue, expectedImageResolution, expectedVideoResolution }`；expected 档位按跑批当时的设置页值（**待用户确认**，默认 schema 是 736p/480p）；
  - `queue` 是瞬时态，离线重放填 `{active:null,waiting:[],resumedJobs:0}` 并把 queue-settled 标注「后验重放，仅形式通过」；
  - turn 0 用场景 turn-0 检查点集（`AUTO_TEST_SCENARIOS[0]`），`supersede-chain` 只有 turnIndex≥1 才参与；
  - 路由前缀断言用节点 `filename`（后端产物名，如 `Qwen_image_2.1_*` / `krea2_*`），不是 history 的磁盘 uuid 名；
  - 逐条 PASS/FAIL + 证据写进分析报告，并与（离线补写的）test-report.md 对账。
- **P2 链路与失败分类**：jobs.json 3 条任务的状态/耗时/executionError；节点 createdAt 时间轴分段（澄清→剧本→分镜→定妆→关键帧→视频→旁白→BGM→成片各占多久）；失败归因沿用 effect-test-runner 的四分类（路由错/端点错/效果差/门禁拦截）。
- **P3 内容评估**（人工/外部大模型，机器不做）：test-report.md（或离线补写版）的「内容评估指引」四项——海报《山谷晨光》逐字正确 / 15s 节奏 / 美感 / 纪律遵守（形象一致、旁白同音色、无字幕）。
- **P4 会话流分析**（可选，需会话转录）：canvas-studio-creation 是否先行加载、风格纪律触发情况、ask_user_choice 违规次数（auto 模式下应为 0）、H3 六段式服从度、提交即停合规。位置 `~/.videobuddy/sessions`（结构现场确认）。
