# C-14 ｜ 生成角色四视图反复失败（CS-USER-002 重复触发）

> 优先级 P1 ｜ 风险 T1（描述/文档）｜ 依赖：无（红卡堆积已被批 5 修掉）
> 截图要点：两张「生成失败·点击重试」红卡 + 报错「6511…是画布节点 id（或本地产物文件名），不是 Drama Backend 的参考文件句柄」；agent 随后自行改用 @ref 成功。

## 现象
「多次在遇到生成 4 视图失败，像是文件引用错误」——agent 把画布节点 id 当 filename 传给 character_sheet，被 CV-238 预检拦下（行为正确），但反复触发浪费回合。

## 代码级原因
- 拦截链正确：`generate.ts:1198-1202` `looksLikeCanvasNodeId`（UUID 形态）→ `host-tools.ts:629-635` `resolveRefValue` 裸值校验 → `CS-USER-002`（catalog.ts:248-254，报错本身已可行动）。
- **描述层教错了**：`host-tools.ts:1287` character_sheet 的 `filename` 描述只有「角色设计图/定妆照的 Drama Backend 文件名（来自 upload_image 工具）」——无 @ref 形态、无节点 id 反例；而 `look_card.referenceFilename`（:1330）**明说可传画布节点 id**（它走 `findNodeByRef`，:667-684，合法）——不一致的描述让模型错误泛化。
- `skills/canvas-studio-creation/references/consistency.md` 第 4 步建卡句无句柄形态示例。
- 红卡堆积已由批 5 修复（`asset-capture.ts` PRE_EXECUTION_ERROR_CODES 含 CS-USER-002，占位直接移除）。

## 修复方案
1. `host-tools.ts:1287` 改写：「角色设计图/定妆照的 Drama Backend 文件名。合法形态：`upload_image` 返回的 `ref-*.png` 句柄，或 `@ref[画布节点显示名]`（Host 自动换句柄）。⚠️ 反例：不能传画布节点 id（形如 `6511xxxx-…` 的 UUID，会被 CS-USER-002 拒绝）；也不能传生成产物名（形如 `img_01287_.png`，CV-155）。」
2. `consistency.md` 第 4 步补示例：「filename 传 `@ref[女主设定图]` 或 upload_image 句柄（如 `ref-a1b2c3d4.png`）；画布节点 id 不是文件句柄，不能传。」
3. 不建议为「一致性」放宽 character_sheet 守卫——look_card 能收节点 id 是因其专用解析链，属结构性差异，描述里写清即可。

## 改动风险
纯描述/文档，不触行为；`tests/param-guard.test.mjs` 针对守卫行为而非描述文案，不受影响。

## 验收
无头：源码断言（character_sheet 描述含反例句）。桌面：新会话让 agent 直接建四视图资产卡，首轮即用 @ref 成功、无 CS-USER-002。
