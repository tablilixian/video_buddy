# A-10 ｜ 分镜与视频片段顺序不对（期望视频单独一列横向对齐分镜）

> 优先级 P2 ｜ 风险 T2 ｜ 依赖：建议在 A-4/A-5 之后（同用落位基建）
> 截图要点：分镜2/3 组内视频在左、关键帧在右并排；用户期望「分镜视频单独一个列，横向对齐分镜」。

## 代码级原因
- **组内成员从不被重排**：attachShotGroup（generate.ts:1354-1381）只 `groupBoxOf` 扩框（:1366），成员保持生成时「第一个不重叠格」的堆叠序（canvas-placement.ts:91-95）→ 视频/关键帧左右交错；「整理布局」时托盘整体只平移（canvas-view.ts:824-829 children 按 delta 平移）。
- 整理时混排：autoArrange 第二遍 tidyGroupLayout（project-store.ts:1079-1093 → canvas-view.ts:1015-1043）`columns = ceil(sqrt(n))` + readingOrder（:1050-1067，按 y/x）把视频与关键帧塞进同一网格，**不看 kind**。
- 泳道模型其实已有分列（LANE_CARD→SCENE→KF→SHOT→FRAME，canvas-view.ts:421-429），但只作用于**顶层**节点，进托盘即失效；镜位框只是包围盒（CanvasSurface.tsx:812-833）。

## 修复方案（最小落点：tidyGroupLayout 加角色分列变体）
1. `tidyGroupLayout`（canvas-view.ts:1015）加 `mode: 'grid' | 'shot'`；shot 模式按 kind 分组：视频单列纵排（X 对齐）、关键帧一行/一列、末帧辅助卡靠尾，列间距用 GROUP_TIDY_GAP，照旧 groupBoxOf(moved) 收框。
2. 调用点 project-store.ts:1085：组内节点 `sourceIds` 含分镜卡（或标题匹配「分镜 N · 素材」）→ mode:'shot'，其余托盘维持 grid（默认行为逐字节不变）。
3. （可选第二步，风险高）生成落位也按角色分列：generate.ts:2462 落新产物前查该镜组已有成员分布，给 deriveNodePlacement 传「首选偏移」——该函数是四条链路共用入口（canvas-placement.ts:1-15 文件头明示），**先只做 1、2，验证观感再评估**。

## 改动风险
- tidyGroupLayout 同时服务右键「整理托盘」与 autoArrange——用 mode 参数隔离，默认 grid 行为不变（既有测试全绿为硬门槛）。
- shot 模式重排会覆盖用户手工拖过的成员位置（与现有 tidy 语义一致，可接受）；重排后托盘框收缩是唯一合法收缩路径（canvas-view.ts:1009-1013）。
- deriveNodePlacement 全链路改动放二期。

## 验收
无头：tidyGroupLayout shot 模式单测（视频列 X 对齐、关键帧排另一列、grid 模式不变）。桌面：对分镜组右键整理 → 视频纵列对齐分镜右侧。
