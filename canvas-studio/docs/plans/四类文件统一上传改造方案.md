# 四类文件统一上传改造方案

> **状态**：方案已成稿·待拍板排期（本文档仅计划，不含代码改动）
> **范围**：Canvas Studio 插件本地上传链路（图片 / 视频 / 音频 / 文字）
> **立项提示**：实施时需在 [STATUS.md](../STATUS.md) 认领 CV 编号（写号前先 `grep -r "CV-2xx" docs/` 整目录确认未占用；当前编号规则以 STATUS.md §0「已编到 CV-xxx」为准），并在 [docs/README.md](../README.md) §二 确认本行索引。

---

## 1. 背景与问题

用户验收反馈两类现象，均属本地文件进入画布的入口链路：

| # | 现象 | 触发路径 |
| --- | --- | --- |
| P1 | **拖放音频没任何反应**；拖放 `.txt` 等文字文件时，宿主对话框弹「仅支持 PNG/JPEG…」 | 画布空白区 / 节点上拖放（drag & drop） |
| P2 | **画布工具栏上传按钮能传，但明显偏慢**（用户预期：本地上传 = 拷贝文件，应当秒回） | 工具栏「上传图片 / 音频 / 视频」按钮 → 文件选择框 |

P1 是**功能性缺陷**（音频静默失败、文字被上游 composer 白名单拦截）；P2 是**链路设计问题**（把「落盘本地」和「提升为 Drama 后端资产」耦合成了同步串行一步）。两者同源：四类文件没有一条统一的进入路径，而是图/音共用一条为「图片」设计的旧链路、视频单独一条较新的链路、文字根本没有画布侧入口。

**目标（一句话）**：图片、视频、音频、文字四类文件走**同一条上传入口**（一个按钮 + 拖放），按扩展名自动分类落卡；本地落盘**只做文件拷贝**（秒回），后端资产提升全部**惰性化**。

## 2. 根因分析（均带 file:line，已核实）

### 2.1 拖放音频被静默丢弃

`src/client/StudioFrame.tsx` 的 `handleDroppedFiles`（约 :654-657）按文件类型分发时只识别 **video / image** 两个分支，命中不了就直接 `return`——音频、文字拖放**没有任何提示**，用户感知就是「没反应」。

### 2.2 「仅支持 PNG…」来自宿主 composer 图片白名单

同一函数里的 capture 接管（约 :684-725）只拦截**视频**文件；文字文件不被画布接管，落到宿主（DeepSeek Harness 上游）composer 的图片附件路径，撞上其图片格式白名单，弹出「仅支持 PNG/JPEG…」。图片行为（走 composer 预览）是**有意保留**的既有 UX，不在本次改动内（见 §5 范围）。

### 2.3 「上传很慢」= 同步 promote，不是拷贝慢

图/音上传走 `POST /canvas-studio/upload` → `uploadLocalImage`（`src/generate.ts:767-777`）：先 `saveLocalImage` 落盘，**紧接着同步调用 `promoteAssetFile` 把文件推进 Drama 后端**。这一步包含 HTTP 往返 + 后端落库，大文件时秒级起步，而用户心智里这只是「选了个文件」。视频走独立的 `/upload-video`（`routes.ts`，128MB 上限、惰性语义），没有这个同步提升，所以视频上传体感正常。

仓库内**已有两段式先例**可直接复用思路：

- 对话附件旁路（见 [conversation-attachment-divert.md](./conversation-attachment-divert.md)）：先本地落盘，用到时再提升；
- 视频链路：`/upload-video` 只落盘，promote 由消费方惰性触发；
- 惰性提升兜底：`src/host-tools.ts:494` `resolveRefFilenames` 在素材被真正引用时才补齐后端文件名。

结论：**不是要发明新机制，是把图/音从「同步一步」改成与视频一致的「两段式」。**

### 2.4 超限与文案次因（同批顺手修）

| 问题 | 位置 | 影响 |
| --- | --- | --- |
| `MAX_BODY_BYTES = 16MB` + base64 膨胀 ≈ ×4/3 | `src/routes.ts:44`、`readJson` | 实际 ≳12MB 的音频/图片必失败（413） |
| 错误文案写死「图片上传失败」 | `src/routes.ts:997` `sendRouteFailure(..., '图片上传失败…')` | 传音频失败时提示误导 |
| 未知扩展名静默回退 `.png` | `src/generate.ts:812`（`saveLocalImage`） | 非图片文件落成假 png，后续全链路错位 |
| `ASSET_CONTENT_TYPES` 缺 text 类型 | `src/routes.ts:59-80` | 文字素材 MIME 不正确 |

### 2.5 UI 入口按类型拆分，无文字入口

`src/client/canvas/CanvasToolbar.tsx` 只有「上传图片 / 上传音频 / 上传视频」三个按钮，各自写死 `accept`；文字文件在工具栏**没有入口**（只能靠拖放，而拖放又被 §2.2 拦截）。

## 4. 目标与非目标

### 4.1 目标（In Scope）

1. **一条入口**：工具栏单按钮 + 拖放，四类文件均可进入；客户端 `classifyFile()` 按扩展名分类。
2. **秒回落盘**：本地上传端点只做「收 body → 校验 → 落盘 → 返回句柄」，**不做**同步 promote。
3. **分类型限额**：新端点按类型设上限（见 §6.2 表），替掉「一刀切 16MB + base64」。
4. **文字有画布归宿**：`.txt` / `.md` 等落素材 chip（D2）。
5. **拖放不再静默**：音频/文字拖放被画布接管；不支持的类型给出明确 toast，而不是无声 return。
6. **文案与类型诚实**：错误提示按实际类型措辞；未知扩展名**拒绝**而非伪装成 `.png`。
7. **测试可回归**：`classifyFile` 纯函数单测 + 新端点限额/类型测试 + 拖放分发用例。

### 4.2 非目标（Out of Scope，明确不做）

| 不做 | 原因 |
| --- | --- |
| H3 `audio-reference.ts:44` 的 mp3/wav 生成校验口径 | D4 明确排除；属生成链路格式约束，与上传入口无关。 |
| 上游 Harness composer 的非图片附件能力 | `deepseek-harness/` 是 pinned submodule，禁止修改；图片走 composer 的既有 UX 保留。 |
| 音频 `@ref` 对话引用（对话里 @ 出音频素材） | 独立需求（另见音频验收清单中的缺口），不在本链路。 |
| 视频上传链路重构 | 视频已是惰性两段式、128MB 独立端点，行为正确；本次只把它并进**同一个 UI 入口**，不动 `/upload-video` 内部。 |
| 素材编辑、富文本、多文件批量队列 UI | 超出「统一进入」的最小闭环。 |
| 修改 `deepseek-harness/` 子模块内任何文件 | 仓库铁律。 |

## 5. 统一链路设计

### 5.1 总览

```
                    ┌─────────────────────────────┐
  工具栏「上传文件」 │  classifyFile(name)         │
  拖放 drop        │  → image | video | audio |   │
                    │    text | reject            │
                    └──────────┬──────────────────┘
           ┌───────────┬──────┴─────┬────────────┐
           ▼           ▼            ▼            ▼
        image        video        audio         text
           │           │            │            │
           │      /upload-video     │            │
           │      (现有,128MB)      │            │
           ▼           │            ▼            ▼
    POST /canvas-studio/upload-media  (新,octet-stream)
      ?projectId=&name=               分类型限额
           │
           ▼
    saveLocalAsset()  —— 只落盘,白名单校验,未知扩展名 400
           │
           ▼
    客户端落卡:  image→addImportNode  video→现有视频节点
                audio→addAudioNode    text→素材 chip(D2)
           │
           ▼
    惰性 promote: 消费时 resolveRefFilenames / 现有 promote 兜底
                  (上传路径永不同步 promote)
```

### 5.2 客户端分类规则 `classifyFile(fileName)`

纯函数，放 `src/client/`（与 `media-extension.ts` 同层或并入该模块），按**扩展名小写**判定：

| 类别 | 扩展名（首版白名单，可表驱动扩展） |
| --- | --- |
| image | png jpg jpeg gif webp |
| video | mp4 mov webm mkv |
| audio | mp3 wav m4a aac flac ogg opus |
| text | txt md json csv log |
| reject | 其余 / 无扩展名 |

规则：**未知 → reject（用户可见 toast），绝不静默、绝不伪装类别**。工具栏按钮 `accept` 由四类白名单拼出；拖放入口对 reject 类型给「不支持的文件类型」提示。

### 5.3 落卡映射（与现有节点体系对齐）

契约依据：`StudioCanvasNodeKind = 'image'|'video'|'audio'|'sticky'|'text'|'prompt'|'group'`（`src/contracts/canvas.ts`），标签源 `src/client/canvas/labels.ts`。

| 分类 | 落卡函数 | 备注 |
| --- | --- | --- |
| image | `addImportNode`（现有） | 行为不变；promote 改惰性（Q1） |
| video | 现有视频节点路径 | 入口并入统一按钮，内部仍走 `/upload-video` |
| audio | `addAudioNode`（现有，CV-128） | 修复对象；落卡后可出波形（波形端点已有） |
| text | **扩展 `addImportNode` 一族支持 `kind='text'` 素材 chip**（D2） | 与图片 import 同级素材语义；详情面板只读预览（Q3） |

text 节点 `referenceRole` 保持省略（现有 `referenceRole?: 'image'|'character'|'style'|'frame'` 不扩——文字素材不参与构图/角色参考，避免污染参考托盘）。

### 5.4 惰性 promote 契约（不变量）

1. **上传端点（upload / upload-media / upload-video）一律不调用 `promoteAssetFile`。**
2. 提升只发生在消费侧既有路径：
   - `host-tools.ts` `resolveRefFilenames`（引用时补齐）；
   - 既有显式 `promote` 端点（如有对话/生成侧直接调用，保持可用）。
3. 验收判据：传一个 10MB 图片，工具栏点击到节点出现应为**本地拷贝级耗时**（无 Drama HTTP 往返）；Drama 侧文件在首次被生成引用时才出现。

## 6. 服务端改动

### 6.1 新端点 `POST /canvas-studio/upload-media`

| 项 | 约定 |
| --- | --- |
| Query | `projectId`（必填）、`name`（原始文件名，必填，用于扩展名与落盘名） |
| Body | `application/octet-stream` **原始字节**（不走 base64/JSON，避免膨胀与 `readJson` 的 16MB 天花板） |
| 实现 | 复用现有 raw-body 读取工具（`readRawBody` 一族）；按 §6.2 限额在读流阶段拒绝 |
| 成功 | `200` + 与现 `/upload` 同构的句柄 JSON（`filename` / 本地相对路径等，字段对齐现客户端解析） |
| 失败 | `sendRouteFailure(res, cause, 400, '<按类型>上传失败，请稍后重试。')`——**替换** `routes.ts:997` 写死的「图片上传失败」 |

### 6.2 分类型限额（Q2 默认）

| 类型 | 上限 | 备注 |
| --- | --- | --- |
| image | 16MB | 与现 `MAX_BODY_BYTES` 数值一致，但按**原始字节**计（base64 消失后实际可用变大） |
| audio | 32MB | Q2 默认 |
| text | 5MB | 纯文本远小于此，防御性上限 |
| video | 128MB | **不走新端点**，维持现有 `/upload-video` |

实现建议：限额表模块内常量 `MEDIA_UPLOAD_LIMITS: Record<Kind, number>`，读 body 超限回 413 并带类型化文案。

### 6.3 `saveLocalImage` → `saveLocalAsset`

`src/generate.ts`（现 :767-812 一带）：

1. 扩展白名单：在 png/jpg/… 之外纳入 audio/text 白名单（表与 `classifyFile` **同源**——抽公共常量到 `media-extension.ts` 或新建 `media-kinds.ts`，避免两处漂移）。
2. **未知扩展名直接 throw 400**，删除 `:812` 的 `.png` 静默回退。
3. 原 `saveLocalImage` 保留为薄别名或直接全量改名迁移（调用点全在本仓，一次改完）。
4. `promoteAssetFile` 调用**从上传路径移除**（§5.4）。

### 6.4 `ASSET_CONTENT_TYPES` 补全

`src/routes.ts:59-80`：为 text 扩展补 `text/plain; charset=utf-8` / `text/markdown` 等；audio 补常见 MIME（若已有则核对）。服务端返回素材时 `Content-Type` 与真实类型一致。

### 6.5 旧端点去留

| 端点 | 处置 |
| --- | --- |
| `POST /canvas-studio/upload`（JSON+base64） | 客户端切到 `upload-media` 后**保留一版兼容**（防热更新/旧客户端），标注 deprecated；确认无调用后下一批删除 |
| `POST /canvas-studio/upload-local` | 同上，随 `uploadLocalImage` 迁移评估 |
| `POST /canvas-studio/upload-video` | 不动（除错误文案核对） |
| `POST /canvas-studio/promote` | 保留（显式提升仍需要，只是上传不再自动触发） |

## 7. 客户端改动

### 7.1 `api.ts`

新增 `uploadStudioMedia({ projectId, file })`：`fetch` octet-stream 直传，按 `classifyFile` 不在此处分类（分类上提到 UI 层，api 层保持哑管道）；保留现有 `uploadLocalStudioImage*` 至旧端点下线。

### 7.2 `StudioFrame.tsx`（核心修复点）

1. **`handleDroppedFiles`**（:654 起）：改为先 `classifyFile`，四类全分发；reject 给 toast；**删除「未命中即静默 return」**。
2. **capture 接管**（:684-725）：从「只拦视频」扩为「拦 video + audio + text」（非图片文件统一进画布）；**图片仍走原路径**（composer 预览 UX 不变，见 §4.2）。
3. 上传按钮 handler 收敛为一个 `handleUploadFiles`。

### 7.3 `CanvasToolbar.tsx`

三个按钮 → 一个「上传文件」（`accept` = 四类并集）；删除分类型按钮与各自 handler 引用。图标/文案从 `labels.ts` 取（如需新标签「上传文件」加进标签源，不散写死字符串）。

### 7.4 `project-store.ts` 落卡

- 扩展素材落卡以支持 `kind='text'` 素材 chip（D2）；尺寸/布局沿用 `NODE_SIZE` / 既有 import 节点规格，不新开布局常量。
- 音频沿用 `addAudioNode`。

### 7.5 `error-toast.ts`

分类错误文案对齐新端点返回（「音频上传失败…」「文件类型不支持…」），去掉残留的「仅支持 PNG」依赖路径（该串来自宿主，画布接管后不应再到达）。

| # | 步骤 | 期望 |
| --- | --- | --- |
| A | 工具栏上传 10MB 图片 | **秒级**出卡；断网 Drama（或看请求）上传期间无 promote 请求；首次被生成引用时后端才出现文件 |

### 9.3 风险与回滚

| 风险 | 缓解 |
| --- | --- |
| 图片改惰性后，某条消费路径**只认同步 promote 后的文件名** | Step 1 前全仓 grep `promoteAssetFile` / `filename` 消费点；`resolveRefFilenames` 已是兜底；Step 5 验收 G 强制走一次真实生成 |
| 旧 `/upload` 删除后热更新客户端 404 | 先 deprecated 保留一版，grep 零调用后再删（§6.5） |
| 限额误伤正常大图（原 base64 16MB ≈ 原始 12MB，现 16MB 原始反而更宽） | 限额按原始字节，图片实际变宽；audio 32MB 覆盖常见 BGM |
| capture 扩到 text 后误抢宿主合法图片附件 | 接管条件明确「非 image 扩展名」；image 一行不动；验收 E 对照 |
| 两处扩展白名单漂移 | Step 1 强制同源常量 + 单测双向断言 |

**回滚**：每步独立提交；Step 2/3/4 可单独 revert 而不破坏 Step 1 的白名单加固（Step 1 是纯收紧，单独存在也正确）。
