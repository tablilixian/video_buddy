# CV-246 · BUG-006 生成历史面板（产物可回溯 + 彻底删除）

> **日期**：2026-09-27
> **BUG-006**：每次生成、合成、export 视频都会产生历史产物，但没有任何地方可被发现。
> 用户期望：保留历史上所有生成的图和片方便回溯；用户删除则从磁盘彻底删除。

## 1. 现状与根因

- 全仓无任何历史 UI（grep `HistoryPanel|mediaHistory` 零命中）。
- 产物全部落在 `<项目>/assets/`（`UUID.ext` 形态，文件名无语义）；`canvas.json`
  只登记画布上的节点，节点删除/被取代后线索即断，产物沦为「无主文件」。
- 与 CV-243 的关系：同一堆文件的两面——CV-243 管「没人要的怎么清」（已解决），
  本 bug 管「有人想要的怎么找回」。**GC 必须把历史登记表算作引用**，否则面板里
  还在展示的产物会被打开项目时的自动 GC 清掉。

## 2. 方案（已拍板）

| 决策点 | 结论 |
|---|---|
| 登记表位置 | `<项目>/assets/history.json`（独立文件，与 reference-manifest 同模式，模块级串行队列防撕档） |
| 记账范围 | 四类都记（图/视频/音频/文件）；UI 首期只展示图/视频（tab 过滤） |
| 重新挂回画布 | 首期不做（纯查看 + 删除） |
| 入口 | 画布工具栏**最右图标组**（图层与小地图之间）时钟图标——左上角与「参考图」浮动卡弹出区冲突（真机截图确认），弃用 |
| 面板形态 | 右侧滑出抽屉（画布区内侧，不盖 app「帮我对话」侧栏），边翻历史边看画布 |
| 删除语义 | 面板删除 = 移入 `assets/.trash/` + 登记表标 `deletedAt`；仍被画布引用的产物**拒绝删除**（防断链）；GC 物理清 .trash 时同步剪枝 |

### 2.1 记账埋点（全部产物落盘点）

| 落点 | 产物 | tool |
|---|---|---|
| `generate.ts` `saveLocalAsset`（:1001） | 上传四类文件 | `upload` |
| `generate.ts` 生成统一落盘（:2212） | 图 png / 视频 mp4 | 生成工具名 |
| `generate.ts` 角色四视图（:2529） | png | `character` |
| `generate.ts` 音乐落盘（:2923） | mp3 | `music_generation` |
| `compose.ts`（:530 finalOutput） | 成片 export-*.mp4 | `compose` |
| `audio-cut.ts`（:163） | 裁切 `<id>.mp3` | `cut_audio` |

### 2.2 数据结构（`assets/history.json`）

```jsonc
{
  "version": 1,
  "entries": [
    {
      "file": "<uuid>.mp4",       // assets 根下文件名（同 url basename）
      "kind": "image|video|audio|file",
      "tool": "video_generate",   // 来源工具（host 端映射中文 label 存库）
      "label": "视频生成",
      "createdAt": 1790000000000,
      "size": 8598321,
      "deletedAt": undefined      // 面板删除后写入；GC 只保护未删条目
    }
  ]
}
```

- `kind` 由扩展名派生（png/jpg/webp→image，mp4/mov/webm→video，mp3/wav/m4a/flac/ogg→audio，其余→file）。
- 同 `file` 重复记账幂等（不重复插条目）。

### 2.3 状态徽章（客户端派生，不落库）

对照画布 nodes 按 url basename 派生：**已挂画布**（存在引用节点）/ **已被取代**
（引用节点 retired/supersededBy）/ **未挂画布**（无引用）。

## 4. 自测与验收

- 单测 `tests/asset-history.test.mjs`：
  ① 记账/读回 + 同 file 幂等；② kind 派生；③ markDeleted 语义；
  ④ GC 不清 history 未删文件；⑤ GC 清已删文件并剪枝；
  ⑥ 删除路由：画布引用中→拒绝 / 未引用→进 .trash + 标记；
  ⑦ 生成落盘后 history 同步记账（复用 generate 测试桩）。
- 真机验收：
  1. 生成一张图 / 一段视频 / 裁切一段音频 → 打开历史面板，条目即时出现（重启应用后仍在）；
  2. 删除画布上某产物节点 → 面板中该条状态变「未挂画布」，条目仍在（可回溯）；
  3. 面板删除「已挂画布」的产物 → 拒绝并提示；
  4. 面板删除「未挂画布」产物 → 进 .trash，下次打开项目 GC 后彻底清除；
  5. 不点删除时，历史产物不被自动 GC 清掉（开项目多次后仍在）。

## 5. CV-246a · 真机反馈三连（2026-09-27 验收通过）

| 反馈 | 修复 |
|---|---|
| 预览 `window.open` 被资产路由 403 且跳出 app | 已挂画布 →「定位」：`selectNode` + `setDetailNodeId` + `setFocusNodeId`（与双击素材同一条详情链路 + 画布居中，CV-009 机制）；未挂画布 → app 内 lightbox 弹层（挂 `.csCanvasBody` 与抽屉同级，遮罩盖画布，点遮罩关闭） |
| 点击卡片定位到画布节点 | 缩略图主体可点，定位/预览按状态分流；hover 按钮文案随状态变（定位/预览）；多节点引用同一文件取最新活跃节点（重试旧版在场优先最新） |
| 面板打开后不自动刷新 | 依赖 url 集合签名（`nodes.map(url).join('|')`）：生成完成/上传/删节点改变 url 集合 → 立即重拉；拖动不改 url → 不重拉。状态徽章本就实时派生自 nodes |
