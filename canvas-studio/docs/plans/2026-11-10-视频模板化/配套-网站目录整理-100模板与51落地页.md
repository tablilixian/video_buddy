## 〇、一句话结论

> **100 个模板里，真正在 GitHub 上开源了源码的只有 1 个：`385712`（酷炫科技风 / Kinetic Tech）。**
> 其余 99 个的源码在 motiongit.com 账号下载的 `.motion` 包里（官网口径：下载到的包 100% 开源，但**包不在 GitHub 上**）。
> 另外 50 个 GitHub 仓库是**落地页**（README + 机器可读元数据 + Demo），**不含任何模板源码**。

这个结论有三重独立证据：

| 证据 | 数据 |
|---|---|
| 官网自己的机器可读口径 | `catalog.json` → `distribution.githubDirectTemplateIds = ["385712"]`；`sourceCode = "100%-open-source-in-downloaded-package"` |
| 官网自己的字段统计 | 100 条模板：`githubSourceIncluded` = **true 仅 1**、false 99；`download.type` = `direct-package` 仅 1、`official-page` 99；`availability` = `download-available` 仅 1、`check-official-page` 99 |
| 本次全量实测 | 51 个模板仓库逐个探测 `template/core/core.js` ⇒ **命中 1 个（385712）**；有 `template.json`（落地页元数据）的 50 个；两者皆无 0 个 |
| 仓库体积分布 | 385712 = **51.5 MB**；其余 50 个 = 0.18–13.7 MB（体积几乎全是 Demo 视频与预览图） |

### 关键认识

| 事实 | 影响 |

### 3.5 一个容易被忽略的点：`motion-spec`

**`github.com/motiontemplates/motion-spec` 是本项目最该看的开源仓库**（118 KB）：

- `.motion` 开放动画模板格式规范（候选版 `0.1.0-draft.1`，2026-10-12 更新）
- 明确写「格式本身不绑定任何创作模型或动画引擎；在线生成是可选的 —— 理解内容、校验输入、本地渲染动画**并不必然需要 MotionGit API 调用**」
- 三层协议：**模板内容**（源码/参数/素材/预设/预览/许可）→ **运行时适配器**（环境检查/输入处理/逐帧渲染/输出）→ **可选分发**（发布身份/签名溯源/个人凭据）
- 关键提醒（对我们直接适用）：
  > 「开放格式不意味着每个模板、字体、音轨或素材都是开放许可。」
  > 「实现方应精确声明支持的版本/配置/扩展，**而不是按前缀接受未知版本**；不支持的执行、权限或兼容性语义需要清晰警告或停止相关操作。」

⇒ 这与我们总纲里的「模板要声明 `contractVersion`，渲染器不认的版本**明确拒绝**」完全同构。

## 四、落地页 `template.json` 的结构（**对我们最有参考价值的部分**）

虽然落地页没有源码，但它的元数据是**机器可读、字段设计得很好**——正好是我们「模板应该声明什么」的现成参照。

```jsonc
{
  "format": "…", "repositoryId": "148294", "templateId": 148294,
  "version": "0.1.0-alpha8",
  "title": {"zh": "…", "en": "…"},
  "summary": {"zh": "…", "en": "…"},
  "technical": { "zh": ["声明的运行配置：native-python-node/1。",
                       "通过模板参数和预设，将本期文字、数据或素材映射到已有动画工程。"] },
  "availability": "demo-only",
  "materials": [                       // ← 素材/内容需求（6 项，逐条 required）
    { "zh": "本期主题、文稿与需要准确保留的信息。", "required": true },
    { "zh": "本期配音文件，或是否需要配音的安排。", "required": false }
  ],
  "dependencies": [ { "zh": "…" } ],
  "goodFor":     { "zh": ["消息与字形角色", "规则长卷", "…"] },   // ← 适合什么
  "boundaries":  { "zh": ["已声明输出为 1920 × 1080，60 fps；默认样片 155.983 秒。",
                          "按实际包的参数边界制作；增加素材不会自动增加场景。"] },  // ← 边界
  "capabilities": [ { "zh": "…", "status": "check-live" } ],    // ← 能力声明 + 状态
  "demo": { "zh": "…", "en": "…", "poster": "…" }
}
```

配套还有 `llms.txt`（给 LLM 的极简索引，823 字节）和 `ASSISTANT.zh-CN.md`（给 AI 的制作流程指南：先读包内 README → 查依赖 → 复用已有环境 → 把素材映射到槽位 → 展示真实预览）。

### 与我们总纲的对应关系

| MotionGit 落地页字段 | 我们的对应 | 我们的落点 |
|---|---|---|
| `materials[]`（逐条 required） | 槽位合同 | `slots.json` 的 `required` |
| `goodFor` / `boundaries` | 模板适用性说明 | `template.json` 的 `suitableFor` / `notSuitableFor` |
| `capabilities[].status` | 能力声明 + 校验状态 | `template.json` 的 `capability` + `contractVersion` |
| `technical[]`（运行配置声明） | 运行 profile | 我们的 `manifest-spec.json` + `theme` |
| `llms.txt` | LLM 选型入口 | **`list_templates` 工具的返回形状** |
| `ASSISTANT.md` | AI 制作流程 | 模板 `README.md` + `describe_template` 返回 |

⇒ **落地页元数据 = 我们 `list_templates` / `describe_template` 应当返回的东西的现成样板。** 这比 50 份落地页本身更有价值。

## 五、给我们项目的三条结论

1. **「整包引入」不可行**（已在总纲确立，本文件给出确数）：100 个模板里 **99 个的源码不在 GitHub**，须 motiongit.com 账号下载；个人包还要用自己的 Key。**整包引入连下载都做不到**，更别说两套渲染栈 + 违背「模型不写代码」原则。

2. **能白拿的有三样**（都已确认开源可读）：
   - `385712` 一个完整模板源码（MIT，已复刻过）
   - `motion-spec` 格式规范（**开源规范**）
   - **51 份落地页元数据**（`template.json` + `llms.txt` + `ASSISTANT.md`，**公开可读**）—— 作为 `list_templates` / `describe_template` 的字段设计样板，以及 Phase 3 选 10–15 个模板时的**体裁 / 画幅 / 素材需求 / 适用性** 分类依据

3. **注意许可分层**：`.motion` 规范说得很清楚——「开放格式 ≠ 每个模板、字体、音轨、素材都开放许可」。模板代码 MIT，但**字体 OFL、音效音乐须逐条核 `licenses/THIRD-PARTY-NOTICES.md`**（94+ 个模板 = 94+ 份许可要逐条核）。**若未来真引入模板资产，授权账本是第一道闸**（我们仓里已有 CV-371 的授权账本机制可复用）。
