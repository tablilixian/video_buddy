## 0. 一句话结论

把详情抽屉里那块**只读**的「生成时用的参考图」升级成可增 / 可删 / 可换 / 可重排的编辑区，把提示词编辑器搬到**画布节点旁**就地可用，并把「改完 → 重试」在**按钮层**合成一条流。全程**不动生成链路、不动 DSH、不新增画布契约**——唯一一处 Host 改动是新增一个只读解析端点（§4.3）。

在此之上按「**顺畅 / 舒服 / 可精确调整**」补齐三类边界（§1.4）：长提示词**分档 + 分段折叠**（不在画布上硬撑全文）、节点贴边时**四侧择优 + 最小平移画布**（面板不压住正在编辑的节点）、参考位变动时**`<Picture N>` 一致性提示**（参考顺序就是提示词语义，UI 不能装不知道）。

### 1.4 本批的设计目标（2026-09-30 追加，来自用户原话）

> 「考虑提示词如果比较长的话怎样展示更方便用户操作；节点在画布比较靠边的位置要怎样展示，是否需要移动画布让详情展示到合适位置……目的是让用户能**顺畅、舒服、可精确调整**当前节点内容。」

三句话拆成三条可验收的设计目标，贯穿 §3 的 D / E / F 三组：

| 目标 | 具体含义 | 落到 |
|---|---|---|
| **顺畅** | 不改的不要动：短改留在原地、零跳转；面板不遮住正在编辑的东西；视野不来回跳 | D1 D2 · E1 E3 E5 · F5 |
| **舒服** | 内容多时不靠"长得更大"来解决：读数、折叠、横滚、渐隐；窄窗有专门形态 | D1 D2 D3 · E4 E6 · F4 |
| **可精确调整** | 能定位到要改的那一句；参考图能选到某一张并调它的角色/强度；改了参考位不会让提示词里的编号悄悄指错 | D3 D5 · F1 F2 F3 F6 |

### 2.2 五个决定方案形态的关键事实

**① 客户端已经在写 `generationPrompt`，本批不需要新契约。**
[`NodeDetailDrawer.tsx:186-190`](../../src/client/canvas/NodeDetailDrawer.tsx#L186-L190) 的 `commitPrompt` 走 `withPromptField()` → `onUpdateNode(node.id, { generationPrompt })` → `handleUpdateNode` → `actions.updateNode` → 既有画布保存/合流链路。Step 1 只是加同族的纯函数。

**② 重试是「原样重放」，**不**做引用解析。**
`resolveRefValue` / `resolveRefFilenames` 只挂在 **agent 工具 execute** 路径上（[`host-tools.ts`](../../src/host-tools.ts) 十余处调用点）；重试读的是 `generationPrompt` 里已存好的参数，直接下发给供应商。
⇒ **推论：写进参考位的必须是可直接消费的句柄，绝不能是 `@ref[...]` 标记**（本方案 §1.3 红线 ⑤ 的由来）。

**③ 而画布节点的 `filename` 经常不是可消费句柄。**
生成产物节点存的是**后端产物名**（`img_*` / `z-image_*`），作带文件端点入参约 0.1s 内 500（CV-155 实测，见 `docs/api-probe/2026-09-11-filename-consumability.md`）。可用句柄由 [`resolveRefFilenames()`](../../src/host-tools.ts#L666) 惰性提升（`promoteAssetFile`）产生，并且**回写源节点**的 `filename`。
⇒ 这就是 D4 的存在理由：UI 自己去猜句柄必然踩 500。

**④ `routes.ts` 不 import `host-tools.ts`。**
所以「把 `resolveRefFilenames` 导出后直接从 routes 引入」会把整个工具层（含 DSH 依赖）拖进路由模块。§4.3 因此选择**抽独立模块**而不是加一个 `export`。

**⑤ 参考位在不同工具里形态不同，且位次是有语义的。**
`image_generate` 是 `filename`/`filenames` 二选一；`video_composite` 的 `filenames` **顺序就是 `<Picture N>` 位次**，且张数决定模式（1=首帧 I2VA / 2=首尾帧 FL2VA / ≥3=多参考 Ref2VA）。
⇒ 参考图编辑区必须**按工具名查槽位表**（§4.1 唯一事实源），不能写一套通用 UI 蒙上去。

### 2.3 一个纠正：`styleFilename` 不是死键

[`NodeDetailDrawer.tsx:136`](../../src/client/canvas/NodeDetailDrawer.tsx#L136) 读取 `params.styleFilename`，而全仓当前**没有任何生产者**。`git log -S styleFilename` 显示它出厂于早期的媒体工具集（`a3af2ffa46`），生产者随 **CV-147 工具集收敛 26→22** 退役。
⇒ 结论修正：**保留读取**（老节点的历史参数里可能仍有该键，删掉会让那些节点的参考图凭空消失），只标注为历史遗留；本批**不写入**它。

## 3. 交互条目清单（本批验收依据）

> 判定方式：每条给「可验收判据」，桌面可逐条过。**禁止**用「看起来像 libtv」当判据。

### A 组 · 图引用可编辑（核心缺口）

| # | 条目 | 可验收判据 |
|---|---|---|
| **A1** | 参考图可**删** | 删第 N 张后：缩略图数量 −1；`generationPrompt` 里对应槽位同步减少；重试使用新集合（产物可见地不受被删那张影响） |
| **A2** | 参考图可**增** | 从「画布节点 / 全局资产库」选中后：缩略图立即出现（**不是**「参考已断链」）；重试时该图真的参与生成（不是只改了 UI） |
| **A3** | 参考图可**重排** | 多图工具支持拖动改位次；`video_composite` 每条显示 `Picture N`；拖动后重试的产物/模式与位次一致 |
| **A4** | **位次与模式可见** | `video_composite` 在参考区显示当前模式读数（1 张=首帧 / 2 张=首尾帧 / ≥3 张=多参考）与上限（9 张，超出自动采样） |
| **A5** | 单槽**只换不空** | `image_fix` / `character_generate` / `character_sheet` 只提供「替换」，**没有**删除；`video_generate.filename`（可选槽）允许清空 |
| **A6** | **断链占位不被静默吞掉** | 已断链的句柄仍显示「参考已断链」占位卡，可被删除；编辑动作不把未命中句柄悄悄抹掉（CV-242 语义不得回退） |
| **A7** | 不可解析时拒绝写入 | `generationPrompt` 解析失败（老数据/手改）时，编辑区给出明确提示并**放弃本次写入**，不留半截状态（与 `withPromptField` 同契约） |

### B 组 · 就地编辑（少跳转）

| # | 条目 | 可验收判据 |
|---|---|---|
| **B1** | 画布节点上直接进编辑 | 不需要先开详情抽屉：一次操作进入可编辑态，**焦点落在正文**，可立刻打字 |

| **B3** | 参考图与提示词同屏 | 同一处可改提示词与参考图，不需要在抽屉 ↔ 画布 ↔ 参考托盘之间来回 |
| **B4** | 长文本不降级 | 长提示词的展开 / 聚焦两档仍可达（复用 `PromptEditor` 既有三档，不另写一个简版） |

### D 组 · 长提示词怎么展示（2026-09-30 追加）

| # | 条目 | 可验收判据 |
|---|---|---|
| **D1** | 就地档**按内容量分档**并显示读数 | ≤ 阈值（建议 **8 行 / 240 字**，真机定）→ 全文自增高，上限 260px；超过 → 就地档**不展开全文**，显示「长提示词 · N 行 / M 字」+ 前 3 行预览 + 「展开编辑」 |
| **D2** | 展开态有**高度上限**且不"长出面" | 展开后高度 ≤ `min(56vh, 520px)`；内部滚动；容器上/下缘出现渐隐，提示"还有内容"；任何情况下面板不高于画布可视区 |
| **D3** | 结构化提示词（H3 IR）**分段折叠** | 识别段名行（如 `integrated_multimodal_description` / `subject_definitions` / `detailed_description`）与 `<Picture N>`；段名常显、段体可折叠，展开某段时其余保持折叠 ⇒ 改一个词不用滚 2000 字 |
| **D4** | 整篇重写走**聚焦档** | 展开到上限后主按钮引导「聚焦编辑」；聚焦档 = 既有 1040×640 双栏（已保存基准 / 编辑），不新造第四档 |
| **D5** | 改动可见 | 就地档显示「未保存 / 已改 N 处」标记；聚焦档高亮本次改动并给「下一处改动」跳转 |

### E 组 · 节点贴边与视野（2026-09-30 追加）

| # | 条目 | 可验收判据 |
|---|---|---|
| **E1** | **四侧择优** | 优先节点**右侧**；右侧放不下换**左侧**；两侧都放不下才**上/下**（既有 `nodeActionAnchor` 是"上优先"的窄条逻辑，面板不沿用）；左右放置时**恒不遮挡节点** |
| **E2** | **夹取到安全区** | 浮层矩形完整落在视口内，含 8px 安全边距与既有抽屉让位 `bottomInset` |
| **E3** | **必要时最小平移画布** | 节点贴边导致四侧都放不下时，平移画布让优选侧放得下：位移取**最小必要值**、**不改缩放**、`|Δ| < 4px` 不动；平移动画 200ms 并走既有 `onViewChange` 通路 |
| **E4** | **不打断用户手势** | 自动平移期间用户滚轮/拖动 ⇒ 立即放弃自动平移，不抢视野 |
| **E5** | **不回弹 + 恢复视野** | 关闭编辑器**不自动回弹**（用户刚定位好的视野不被弹走）；浮层头部给「恢复视野」，回到打开前的视图快照 |
| **E6** | **窄窗降级** | 视口宽 < **720px** ⇒ 浮层改**底部抽屉**形态（高 ~46%），并在必要时抬升画布避免盖住节点（窄窗里浮层放哪都盖画布） |
| **E7** | 节点在视口外 | 不显示入口/浮层（沿用 `nodeActionAnchor.visible` 的相交语义）；只要求"节点与面板互不遮挡" |

### F 组 · 精确调整与一致性（2026-09-30 追加）

| # | 条目 | 可验收判据 |
|---|---|---|
| **F1** | 参考卡片**选中后出参数行** | 点某张参考 ⇒ 参考区下方出现该张的 role（构图/角色/风格/首末帧）与强度滑杆（复用既有字段），不必回抽屉 |
| **F2** | **`<Picture N>` 一致性提示** | 删/换/重排后若提示词里有 `<Picture N>`：编号超出现有张数 ⇒ amber 提示「引用了 `<Picture 3>`，现在只有 2 张」；顺序变化 ⇒ 提示「第 2 位现在是 X」 |
| **F3** | **同步编号 / 撤销这次改动** | F2 的提示里给两个动作；「同步编号」按当前顺序把提示词里的 `<Picture N>` 压成 `1..k`（**只手动触发**，可撤销）；**不阻断**生成 |
| **F4** | 参考区**不撑高** | 参考图 > 6 张 ⇒ 单行**横滚** + 「共 N 张」；面板高度不随参考数量增长（与 D2 同一类问题） |

| **F6** | **键盘可用** | `Esc` 关闭（保草稿）、`Cmd/Ctrl+Enter` = 保存并重试、`Tab` 在正文与参考区之间可达、`‹ ›` 重排与删除按钮可达（不是"只能拖"） |
| **F7** | 入口的出现规则 | 多选时不显示编辑器入口（避免"改哪张"的歧义）；托盘（group）无提示词字段 ⇒ 不出现（沿用 `promptFieldsOf`）；节点生成中可打开但提交禁用（沿用 `disabled`） |
| **F8** | 工具性改动要留**回执 + 撤销** | 「同步编号」这类**会改用户文本**的动作，执行后警告条消失，但必须留一条**中性**回执（做了什么 / 有几处是猜的 / 撤销入口）—— 撤销不能跟着警告一起收走 |

## 4. 技术方案

### 4.1 槽位表（唯一事实源）

落 `src/node-params.ts`（纯函数，可直测），**所有消费者（编辑区、缩略图反查、测试、未来 agent 侧）都查这一张表**：

| toolName | 引用键 | 形态 | 语义 / 位次 | 上限 | 本批行为 |
|---|---|---|---|---|---|
| `image_generate` | `filename` / `filenames` | 单 **或** 数组（**二选一**） | 多参考融合，顺序无语义 | 4 | 增 / 删 / 换 / 重排 |
| `video_composite` | `filenames` | 数组（必填） | 1=首帧 · 2=首尾帧 · ≥3=多参考；**顺序即 `<Picture N>`** | 9（超出自动采样保留首尾） | 增 / 删 / 换 / 重排 + 模式读数 |
| `video_generate` | `filename` | 单（**可选**） | = `<Picture 1>`（首帧） | 1 | 只换 / 可清空 |
| `image_fix` | `filename` | 单（必填） | 要修复的图 | 1 | 只换不空 |
| `character_generate` | `filename` | 单（必填） | 角色设计图 | 1 | 只换不空 |
| `character_sheet` | `filename` | 单（必填） | 四视图输入 | 1 | 只换不空 |
| 其余 `isReplayable` 工具（`music_generation` / `extract_last_frame`） | — | — | 不涉及图片参考位 | — | **不出**参考图编辑区 |

**归一化规则**（写入时强制，防两个键并存）：

- 0 张 → 删除 `filename` 与 `filenames`（仅限允许空的槽）；
- 1 张 → 只写 `filename`，**删掉** `filenames`；
- ≥2 张 → 只写 `filenames`（保序），**删掉** `filename`；
- 超上限时**拒绝写入并提示**（不静默截断——静默采样是 Host 侧行为，UI 不应该替用户做决定）。

### 4.2 纯函数层（`src/node-params.ts` 新增，零 IO）

```ts
/** 图片参考位槽位规格（§4.1 表 = 唯一事实源）。 */
export interface ReferenceSlot {
  readonly keys: readonly ('filename' | 'filenames')[]
  readonly required: boolean      // 必填单槽 ⇒ 只换不空
  readonly max: number
  readonly ordered: boolean       // 位次有语义（video_composite）
}
export function referenceSlotOf(node: StudioCanvasNode): ReferenceSlot | null
/** 按参数顺序抽出现有参考句柄（取代 NodeDetailDrawer 里的内联实现）。 */
export function referenceNamesOf(raw: string | undefined): readonly string[]
/** 归一化写回，返回新的 JSON 串；不可解析返回 null（与 withPromptField 同契约）。 */
export function withReferenceNames(raw: string | undefined, slot: ReferenceSlot, names: readonly string[]): string | null
```

要点：
- `referenceNamesOf` 直接**取代** [`NodeDetailDrawer.tsx:132-138`](../../src/client/canvas/NodeDetailDrawer.tsx#L132-L138) 的内联实现（顺带把 `styleFilename` 标为历史遗留、只读不写，§2.3）；
- `withReferenceNames` 必须**保留 `params` 里的其它键**（`prompt` / `sourceUrls` / `shotNodeIds` / `retryOf` 之外的重放参数都靠它）；
- 去重按「同名句柄只留一次」处理，但**保序**（`video_composite` 靠顺序）。

### 4.3 新增引用：取可消费句柄（D4 方案 A）

**模块抽取**（因为事实 ④）：把 `resolveRefFilenames` 从 [`host-tools.ts`](../../src/host-tools.ts) 抽到新模块 `src/reference-resolve.ts`，`host-tools.ts` 与 `routes.ts` 共同 import。抽取是**纯搬家**（函数体不变），`tests/lib-ref-resolve.test.mjs` + `tests/reference.test.mjs` 就是这次搬家的回归网。

**新端点**：

```
POST /canvas-studio/resolve-refs        （常量 ROUTE_RESOLVE_REFS）
body: { projectId: string, refs: string[] }        // refs = 画布节点 id 或 lib:<id>
resp: { items: Array<{ ref: string, handle: string } | { ref: string, error: { code: string, message: string } }> }
```

设计约束：
1. **逐项 try/catch**：一个失效引用不得让整批失败（用户一次选 5 张，坏 1 张只该坏那一张）；
2. 内部即 `resolveRefFilenames(registry, projectId, [ref], library)`，**惰性提升 + 回写源节点**全部复用，天然满足事实 ③；
3. 走既有同源守卫（`requestAllowed` / `mutationAllowed` / `sendRouteFailure` 家族），与 `/library` `/promote` 同一套；
4. **只读语义**（对目标节点只读；唯一的写是解析链自身的「回写源节点 filename」不变式），因此不改任何生成路径。

**客户端流**：选节点 → `resolveRefs()` → 拿到 handle → `withReferenceNames()` 写回目标节点 → 缩略图反查天然命中（因为源节点 `filename` 已被回写成同一 handle）。

### 4.4 单槽 vs 多槽（D5）

- **必填单槽**（`image_fix` / `character_generate` / `character_sheet`）：只渲染「替换」按钮，不渲染删除；
- **可选单槽**（`video_generate.filename`）：替换 + 清空；
- **多槽**（`image_generate` / `video_composite`）：增 / 删 / 换 / 重排 + 上限提示；
- 空集合写入在必填槽上被 `withReferenceNames` **拒绝**（返回 `null`），UI 给出理由。

### 4.6 三条语义红线（写进代码注释 + 测试）

1. **编辑不触发**：写字段与发生成永远是两个动作；合并只发生在**按钮**层。
2. **重试原样重放**：参考位只存可消费句柄，不存 `@ref[...]`；不新增重试期解析。
3. **断链不静默**：未命中句柄继续渲染占位卡（CV-242），编辑不得把它抹掉。

### 4.7 面板放置求解器（E 组）

**复用而不是另造**：既有 [`nodeActionAnchor()`](../../src/canvas-view.ts#L179) 已经把「画布坐标 → 屏幕坐标 + 夹取 + 抽屉让位」这套算清了，但它是**窄条的 1 维求解**（只在上/下翻转 + 横向夹取，横向永远与节点同轴居中）。面板（396×300~520）需要**2 维四侧择优 + 反向平移**，所以同族新增一个函数，共用 `clampTo` / `NODE_ACTION_MARGIN(8)` 与同一套坐标换算：

```ts
// src/canvas-view.ts —— 与 nodeActionAnchor 同族：同坐标系、同边距常量、同样纯函数
export interface EditorPlacement {
  mode: 'float' | 'sheet'          // E6 窄窗降级
  side: 'right' | 'left' | 'below' | 'above'
  rect: { x: number; y: number; width: number; height: number }  // 屏幕坐标
  pan: { dx: number; dy: number }  // 需要施加到 view 的**最小**平移（0 = 不动）
  visible: boolean                 // 节点完全在视口外 ⇒ 调用方不渲染（E7）
}
export function editorPlacement(
  node: CanvasBox,
  view: StudioCanvasView,
  viewport: CanvasViewport,
  panel: CanvasViewport,           // 面板期望尺寸（**先渲染后测量**，见下）
  narrow: boolean,
  bottomInset?: number,
): EditorPlacement
```

规则（编号即 §3 E 组）：

1. 屏幕矩形换算与 `nodeActionAnchor` **同式**：`left = box.x * scale + view.x`；
2. 候选序 `right → left → below → above`，取第一个满足「面板 ⊆ 安全区」**且**「面板 ∩ 节点 = ∅」的侧（E1/E2）；
3. 四侧都放不下 ⇒ 按"节点在视口左半就放右、右半就放左"选优选侧，算**最小平移**把该侧腾出来，**再算一次**面板矩形（只迭代一次，避免振荡）；平移必须**有界**：不得把节点推出视口（E3）；
4. `|dx|、|dy| < 4px` ⇒ 归零（防微抖动）（E3）；
5. `narrow === true` ⇒ `mode='sheet'`：底部抽屉，宽度占满、高 ~46%；若抽屉与节点相交 ⇒ 只用**垂直**平移把节点抬到抽屉之上（E6/E7）；
6. `visible === false` ⇒ 调用方**不渲染**入口与面板（E7）。

**先量再放**：沿用 `NodeActionBar` 已验证的手法（[`NodeActionBar.tsx`](../../src/client/canvas/NodeActionBar.tsx#L59) 的 `useLayoutEffect` + `offsetWidth/offsetHeight`）——以 `visibility: hidden` 渲染一帧 → 量出真实尺寸 → 求解 → 定位，用户看不到"摆错位置的一帧"。面板高度随内容变（长文本折叠/展开、IR 分段），**不能写死尺寸**。

**渲染层**：面板与 `NodeActionBar` 一样渲染在 **`.csCanvasLayer` 之外**（画布层带 `transform: scale()`，画在里面的东西会跟着缩放变形）。因此面板坐标是**屏幕坐标**，而平移作用在 **view** 上 —— 两者不要混。

**恢复视野**：打开时快照 `viewBeforeOpen`；关闭不回弹（E5）；面板头部「恢复视野」把 view 写回快照。

### 4.8 长提示词的渲染策略（D 组）

**为什么不能在就地面板里硬撑全文**：既有 [`PromptEditor.tsx`](../../src/client/canvas/PromptEditor.tsx#L21) 的立项理由写得很清楚 ——

> 「为什么不直接把单行 input 换成大 textarea：单行框的毛病不是「小」，而是**看不见自己在改什么也要一次改到位**。分档之后常见操作（改个词）留在原位、零跳转；只有真的要大改时才让界面让位。」

这条在"画布上的浮层面板"里更成立：面板一旦长到 800px，它本身就变成需要用户管理的对象。所以本批的策略是**"就地档只服务短改"**，而不是给长文本一个更大的框：

| 形态 | 判据（建议阈值，真机定） | 就地档表现 | 整篇改去哪 |
|---|---|---|---|
| **短** | ≤ 8 行 **且** ≤ 240 字 | 自增高 textarea，上限 260px | 不需要 |
| **长** | 超过上面任一 | **不展开全文**：读数「长提示词 · N 行 / M 字」+ 前 3 行预览 + 「展开编辑」 | 展开到上限后引导「聚焦编辑」（D4） |
| **结构化** | 命中 IR 段名（`*_description` / `subject_definitions` 等）或含 `<Picture N>` | **段名行常显 + 段体折叠**：默认只展开"要改的那段"；段内仍是 textarea | 聚焦档给全文 + 改动高亮 |
| **参考区** | > 6 张 | 单行横滚 + 「共 N 张」（F4） | — |

配套状态：`state.promptShape`（short/long/ir）由纯函数从文本算出（可测），**不由用户手选**；「未保存 / 已改 N 处」标记（D5）。

### 4.9 `<Picture N>` 一致性（F2/F3）

**为什么必须做**：`video_composite` 的参考数组**顺序就是** `<Picture N>` 的编号（见 `host-tools.ts` 的 `filenames` 描述），而 H3 IR 预检会对编号不连续出 WARN（CV-236）。也就是说：**用户拖动参考图的顺序，等于在改提示词的语义**。UI 如果对这件事一声不吭，用户会得到一张"参考全对、提示词指错"的图，而且很难归因。

纯函数（落 `src/node-params.ts` 或新 `src/prompt-refs.ts`，无 IO）：

```ts
export function pictureNumbersIn(prompt: string): readonly number[]      // 按出现顺序
export function pictureIssues(prompt: string, refCount: number): { dangling: readonly number[]; max: number }
/** 按出现顺序致密化为 1..k，并把**越界**的编号夹到 k；返回被夹的处数（供 UI 明确告知）。 */
export function rewritePictureNumbers(prompt: string, refCount: number): { text: string; clamped: number }
```

交互：删/换/重排后计算 `pictureIssues`，非空则在面板顶部出 amber 条（**不阻断**），两个动作：

- **同步编号**：`rewritePictureNumbers(prompt, refCount)` 按出现顺序把编号致密化成 `1..k`，**越界的夹到 k**（不改文本其余部分），并返回**被夹的处数** —— UI 必须把「这几处指向是猜的，请人工确认」说出来，不能静默改语义；**只手动触发**，走既有快照可撤销；
- **撤销这次改动**：回到改动前的 refs + prompt。

### 4.10 草稿与键盘（F5/F6）

- **草稿存哪**：`editorDrafts: Map<nodeId, { prompt: string; refs: readonly string[] }>`，**内存**（模块级表 + store 只存展示事实，与 `pendingBriefs` / `lobbyStash` 同一手法）；不落盘、不进画布契约。
- **生命周期**：关闭面板（点空白 / `Esc`）⇒ 保留；重新打开 ⇒ 回填 + 「未保存」标记；**显式「取消」** ⇒ 丢弃；「仅保存 / 保存并重试」成功 ⇒ 清除；**切换项目** ⇒ 清空。
- **键盘**：`Esc` 关闭（保草稿）、`Cmd/Ctrl+Enter` = 保存并重试、`Tab` 顺序 = 正文 → 参考区 → 页脚按钮；重排与删除都有按钮（不能只支持拖拽）。

## 7. 风险与回滚

| 风险 | 等级 | 处置 |
|---|---|---|
| 新端点被当成「万能句柄生成器」误用（例如 agent 侧也调） | 低 | 端点只对同源 UI 开放；agent 侧继续走 `resolveRefFilenames`（同一实现，不新增第二口径） |
| 参考位写入把 `generationPrompt` 里其它重放参数弄丢 ⇒ 重试行为漂移 | **中** | `withReferenceNames` 的「其它键原样保留」单测 + `withPromptField` 同款契约；坏数据一律 `null` 不写 |
| 老项目里 `filename`+`filenames` 并存，UI 首次编辑后形态变化 | 低 | 归一化是**有意**行为，但只在用户显式编辑时发生，不做后台批改 |
| `resolveRefFilenames` 抽取引入回归 | 中 | 纯搬家 + 既有 `lib-ref-resolve` / `reference` 测试即为回归网；抽取与功能改动**分两个提交** |
| 就地编辑器与 `NodeActionBar` 的手势冲突（画布空白 pointerdown 清选、双击适配视野） | 中 | 复用 `NodeActionBar` 已验证的 `onPointerDown/onDoubleClick stopPropagation` 三件套 |
| 范围蔓延到 CV-054/055 | 中 | §1.3 边界写死；评审时以「是否动 `contracts/canvas.ts`」为一票否决 |
| **自动平移被读成"镜头乱动"**（E3） | **中** | 位移取最小必要值 + 不改缩放 + `|Δ|<4px` 不动 + 动画 200ms + 用户手势立即打断 + 关闭不回弹 + 「恢复视野」；**桌面验收专门过一遍"贴边拖动时视野是否烦人"** |
| **长文本分段折叠对非 IR 提示词效果有限**（D3） | 中 | 无段名可折叠时的兜底是"展开 + 内部滚动 + 聚焦档"；不要把折叠当成对任意长文本的通用解 |
| **「同步编号」会改用户文本**（F3） | 中 | 只手动触发、可撤销；且 H3 IR 预检（CV-236）本来就对编号不连续只 WARN 不阻断 —— UI 提供便利，不承担正确性 |
| **多出一个"面板与工具条并存"的层** | 低 | 编辑器打开时隐藏 `NodeActionBar`（同一时刻只有一个操作面），避免两个浮层互相压 |

**回滚**：Step 1 / Step 2 / Step 3 各自独立可回滚（新端点 + 新纯函数 + UI 局部；Step 3 只加纯函数与渲染层，同样不动画布契约），不涉及数据迁移；最坏情况回退提交即可，画布数据形态不变。

## 8. 偏差与开放问题

1. **需求标题里的「抄 libtv」在本批被降级为「按我方条目自验收」**（D3）。若后续拿到 libtv 录屏，应作为**追加条目**评审，而不是推翻 §3。
2. **「优化提示词」的 AI 改写半边未设计**（D1）——Step 3 立项时要先回答：改写结果是否直接覆盖正文？是否需要 diff 预览？走哪个后端能力？
3. **音频 / 视频参考位在抽屉里完全不显示**（`audioRefs` / `videoRefs` 无 UI）。这是 REQ-010 的缺口，本批只是**不遮挡**它：参考图编辑区不与音频参考区抢位置。
4. **`music_generation` 的 `filename`**（Drama 侧 mp3 文件名）语义未核（可能是音乐参考输入，也可能是产物回填）。本批不纳入参考图编辑区，留待与 REQ-010 一并核。
5. **`styleFilename` 的历史数据规模未知**：本批保留读取；若确认线上已无该键，可另立一个「清死键」小批删除。
6. **资料库状态仍是「待评审」**：开工前需要把资料库需求表的 REQ-003 行改到「开发中」，并回填本方案链接（本环境无 library skill，需在具备该 skill 的环境执行）。
7. **阈值取值需要真机手感定**（本方案给的是建议值，全部集中在常量里便于一次调参）：短/长分界 `8 行 / 240 字`、就地展开上限 `min(56vh, 520px)`、自增高上限 `260px`、参考区横滚 `> 6 张`、窄窗断点 `720px`、平移死区 `4px`、抽屉高 `46%`。桌面验收时以"改一个词要不要滚屏"为判据逐项调。
8. **「同步编号」是否允许自动做**：本方案定为**手动**（改用户文本必须有明确意图）。若产品认为"重排参考就该自动跟改编号"，需要额外设计"提示词里 `<Picture N>` 与参考位的双向绑定"，属新需求。
9. **自动平移要不要给设置开关**：本方案不做开关（行为有界且可恢复）。若真机验收仍觉得视野被动，再加一个"永不自动平移"的设置项——但那时 E3 就退化成"面板可能不完整可见"，需要重新取舍。
10. **E6 窄窗断点与既有布局的关系**：`720px` 是 `StudioFrame` 栅格 `min-width: 696px` 附近的值（CV-173 左栏收起时的下限）。实现时要核对它与左/右栏收起的组合，别出现"窄窗 + 右栏展开 ⇒ 面板又变回浮层"的抖动。

| # | 现象 | 根因 | 实现时的硬要求 |
