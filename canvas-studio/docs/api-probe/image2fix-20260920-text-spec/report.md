## 3. 与 CV-212 自动模板的形态对照（**这是本报告的核心**）

CV-212 当前自动兜底模板（`src/text-detection.ts#buildTextFixPrompt`）：

```
确保画面中以下文字字符正确渲染（修正任何错字、缺笔画、字符替换）：
- "武侠" —— 保持原字体、字号、颜色、位置不变
只修正文字，其他画面元素（场景、角色、配色、光感、构图）保持完全不变。
```

| 维度 | CV-212 自动模板 | 本案例（正例） |
| --- | --- | --- |
| 输入内容 | **只有字符**（引号文本列表） | **每段文字 + 画出它在哪、什么字体、多大、什么颜色、怎么排** |
| 位置信息 | 只有一句笼统的「保持位置不变」 | 逐段写「顶部横向居中」「中上部两行」「左上角竖排」「底部三行」… |
| 段落结构 | 平铺列表，无画面层级 | 按画面空间顺序逐段（顶→左上→中上→中下→底→右下角） |
| 与画面的对照 | **没有对照** —— 模型不知道「武侠」两字原本在哪，只能自己看图猜 | 逐段一一对应，模型在做**受约束的排版重绘** |
| 动词 | 「确保…正确渲染」（= 重新渲染这些字） | 无祈使动词，是「按这份文字规格重排一遍」 |
| 负向约束 | 只有「其他画面元素保持不变」（不管文字本身） | 「**不得替换、增删**、乱码或自造汉字」 |
| 占位元素 | 未涉及 | 显式保留「二维码占位方框」 |
| 实测结果 | `武仔` → `武传`（**仍错**）+ 凭空多出两处「武侠」+ 曝光漂移 | 8 处错字**全对**、零漂移、零新增 |

**根因归纳（三条，均指向同一件事：上下文缺失）**

1. **丢位置** ⇒ 模型没有「该位置应是什么字」的对照锚点，只能按形近字猜 → `武仔` 猜成 `武传`；
2. **祈使式动词**（「确保…正确渲染」）⇒ 语义被读成「把这些字渲染出来」，而不是「把画错的字改对/不新增」；
3. **无「不得增删」约束** ⇒ 顺手在画面别处补写同样的字 → 凭空多出两处「武侠」。

> ⚠️ **重要对照**：`image_fix` **工具描述本身已经写对了** ——「从原出图 prompt 里只提取文字那部分描述，不要带场景/角色/画风描述」（`src/host-tools.ts`）。**手动调用路径的指导是正确的，只有自动兜底路径的实现没跟上**：`runTextAutoFix()` 只收到 `quotedTexts`，把原 prompt 丢掉了。

## 4. 可复用的改进方向（待拍板，未实施）

1. **原 prompt 是现成的** —— `image_generate.execute` 里 `a.prompt` 就在手上（`src/host-tools.ts` 约 L1015/L1028），当前却只传 `quotedTexts` 进 `runTextAutoFix`（L217-L264）。**改成把原 prompt 一并传入**，即可自动产出本例形态的修复 prompt。
2. **抽取规则（纯函数）**：按中文句号/分号/换行分句，**保留含引号文本的句子** + **保留含「逐字/准确还原/不得替换/不得增删」的约束句**，丢弃其余。对本例原 prompt 跑该规则，输出的正是 §1.2 那段（已人工核对一致）。
3. **误触发收紧**：`不要「水墨」风格` 这类**否定/修饰性**引号会被误当作待渲染文字。可在抽取时丢弃「引号前 3 字含 不要/不用/避免/不是/禁用/无」的句子。
4. **退化路径**：若抽取结果为空，回退到现有字符清单模板（保底不劣于今天）。

**失败机理一目了然**：旧模板交给模型的是「`武侠`」两个字 —— 它不知道这两个字写在**竖幡**上、什么字体、多大；而图上那面竖幡当时渲染的是形近的错字，模型没有对照锚点，只能「按最像的字猜」⇒ 猜成「武传」。新逻辑把**它自己当初写的那句规格**原样还给它：位置、载体、字体全在句子里。
