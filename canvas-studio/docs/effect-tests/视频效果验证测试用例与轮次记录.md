# 视频效果验证测试用例与轮次记录

> **用途**：验证 [video-effect-upgrade-plan.md](../video-effect-upgrade-plan.md) 中 P1 改动（参考组合路由 + 六段式 prompt + 关键帧组合参考 + 单镜模式）的实际效果，并作为**长期对比测试**的统一载体：用例固定，每轮结果追加到文末「五、轮次记录表」。
> **维护约定**：
> 1. 测试用例（第一～四节）原则上不改动；若流程变更需要改用例，在文末记录表中注明「用例版本」。
> 2. 每完成一轮测试，在「五、轮次记录表」追加一行，产物（prompt 全文 / 关键帧 / 视频）截图或文件存入本目录下以轮次命名的子文件夹（如 `R001/`）。
> 3. 评分一律用第四节评分量表（1–5 分），避免"感觉变好了"不可追比。
> **关联**：升级方案第六节 6.1（最小烟雾测试）、6.2（回退决策）、四（P1 验证方法）。
> **创建日期**：2026-09-02

## 二、测试用例（按执行顺序）

### T1 · Ref2VA 基础烟雾测试（最高优先，验证改动 1+2 联动）

| | 内容 |
| --- | --- |
| **目的** | 验证「参考组合路由 + Ref2VA 六段式 prompt」在后端真实跑通 |
| **前置** | 新建项目（逐步确认模式）；需求输入：单镜 8s，16:9，「一个穿蓝色风衣的年轻男人在雨夜街道奔跑」 |
| **步骤** | 1) 走单镜简化流程完成澄清与策划；2) 生成定妆照 + 场景概念图各 1 张并记录 filename；3) 提交单镜方案并批准；4) 观察模型调用 video_composite 的参数与 prompt 全文，等待出片 |
| **检测方法** | ① 看 video_composite 的 `filenames` 参数是否为 2 张参考（而非 1 张首帧）；② 复制 prompt 全文存档，逐段核对六段是否齐全；③ 看后端是否走 `image2videoref2va` 端点（抓工具返回 / 报错信息）；④ 播放成片人眼比对角色与场景 |
| **判定标准** | ✅ 2 张参考 + 六段齐全 + 端点成功 + 成片中角色脸/发型/风衣与定妆照一致、场景与概念图一致 → 通过；❌ 任一环节报错或产物角色明显不符 → 失败并分类记录（路由错 / 端点 404 / 效果差是三种不同问题，处置不同） |
| **失败处置** | 端点 404 → 停止 P1，先与后端排查；效果差 → 跑 T4 对比后再决定是否按 6.2 回退 |

## T2 · 六段式 prompt 质量检查（验证改动 2 骨架够用）

| | 内容 |
| --- | --- |
| **目的** | 确认总纲六段式最小骨架足以让模型写出合格 prompt，不需读全量 ref-en.txt 也不跑偏 |
| **前置** | T1 同一项目 |
| **步骤** | 取 T1 存档的 prompt 全文逐段检查 |
| **检测方法** | ① `<Subject 1>` / `<Subject 2>` 编号在六段中是否一致、无未定义标签；② `detailed_description` 是否为具体画面/动作/运镜描述（而非情节摘要）；③ 时长描述是否 ≈ 8s；④ 是否凭空出现 `<Video N>` / `<Audio N>`（本项目无视频/音频参考，出现即错） |
| **判定标准** | ✅ 四项全过 → 通过；❌ 标签漂移或出现摘要式描述 → 记录具体段落，考虑在总纲骨架中补强对应约束 |

### T3 · 关键帧组合参考（验证改动 3）

| | 内容 |
| --- | --- |
| **目的** | 验证关键帧阶段双参考（定妆照+场景概念图）能同时锁住角色与场景，且不稀释角色相似度 |
| **前置** | 新建多镜头叙事项目，主角出现 ≥3 镜，有明确场景（如"村庄晨雾"） |
| **步骤** | 1) 走全流程到第 6 步逐镜出图；2) 检查每镜 image_generate 的 `filenames`；3) 对每镜关键帧调 image2vl 做客观比对（prompt：「描述画面中人物的发型/服装/脸型特征，以及场景中的地标与光线方向」） |
| **检测方法** | ① 参数检查：每镜 `filenames` 是否 2 张；② image2vl 输出跨镜比对角色特征词与场景特征词是否一致；③ 人眼复核角色相似度是否因双参考下降 |
| **判定标准** | ✅ 每镜 2 参考 + 跨镜场景一致 + 角色相似度不低于旧路径单参考 → 通过；❌ 角色被稀释 → 记录，考虑把第 6 步改回单参考（回退改动 3 不影响改动 1） |

### T4 · 跨镜一致性 AB 对比（P1 拍板依据，成本最高，最后做）

| | 内容 |
| --- | --- |
| **目的** | 量化「新路径 vs 旧路径」的相对收益，作为 P1 通过 / 回退（6.2）的决策依据 |
| **前置** | T3 的项目与分镜表固定不动（同一分镜表是对比前提）；先跑一轮旧路径：git stash 本仓库 SKILL.md 改动（或切到改动前 commit）重新 build，按旧流程生成 |
| **步骤** | 1) 旧路径生成一轮，产物存 `R<轮次>/old/`；2) 恢复新版本 build，再生成一轮，产物存 `R<轮次>/new/`；3) 两轮各镜关键帧用 image2vl 比对；4) 视频按第四节量表人工打分 |
| **检测方法** | ① 角色：脸/发型/服装跨镜漂移程度（量表 A）；② 场景：地标/光位连续性（量表 B）；③ 单镜内运镜与动作幅度（量表 C）；④ 整片节奏（量表 D）。关键帧部分以 image2vl 输出做客观佐证，视频以人眼评分为主 |
| **判定标准** | ✅ 新路径 A、B 两项均分 ≥ 旧路径且至少一项高 ≥1 分 → P1 通过，进入 P2；❌ 新路径 A 项低于旧路径 → 按 6.2 回退：保留改动 3，视频退回 FL2VA，记录回退轮次 |

**方式 A · 一键按钮（推荐，2026-09-02 起）**：项目列表下方「▶ 跑效果测试」→ 勾选用例（T1/T1b/T3/T5/T6）→ 轮次号自动自增 → 开始。系统自动串行执行「建项目（按规范命名）→ 切放手跑 → 发测试指令 → 等回合结束」，进度显示在侧栏；结束后提示跑归集脚本。注意：运行期间会自动切换项目视图，请勿同时手动操作会话。

**方式 B · 手动触发**：

T1 / T2 / T3 / T5 / T6 五条用例可通过内置的 **效果测试执行器** skill 自动跑（固定假数据见该 skill 的 `references/fixtures.md`）：

1. **前置（人工，各一次点击/操作）**：为每条用例在 UI 建项目（命名 `效果验证-R<轮次>-<用例号>`）→ 进入项目会话 → 把工作流切到**放手跑**模式。
2. **触发**：在项目会话里说「跑效果测试 T1（记为 R001）」——执行器会先读 fixtures 取固定需求，再按 canvas-studio-creation 规范真实执行（不调 ask_user_choice、不等审批）。
3. **自动产出**：关键参数与 prompt 采集、canvas.json 交叉核对、image2vl 关键帧特征词比对、项目目录下 `效果测试报告.md`、最终回复附轮次记录表待粘贴行（人工粘贴到第五节的表）。
4. **仍需人工**：T4（AB 对比与评分）/ T7（需改名目录重建）/ T8（依赖逐步确认模式提问顺序）；所有用例的 C/D 维度（表现力/节奏）人工按第四节量表评分后补进记录表。
5. **注意**：每条用例只跑 1 次属单轮抽样；要更可靠的对比结论，同一用例跑 ≥2 次。

## 四、AB 对比评分量表（T4 专用，长期追比统一用这个）

每项 1–5 分（1 = 完全不可接受，5 = 接近网上 demo 水准），两项路径各打一次：

| 维度 | 1 分特征 | 3 分特征 | 5 分特征 |
| --- | --- | --- | --- |
| A 角色一致性 | 跨镜判若两人 | 发型/服装偶有漂移 | 全片像同一实拍演员 |
| B 场景连续性 | 每镜场景重画 | 地标一致但光位/细节漂移 | 地标/光位/道具全片连贯 |
| C 单镜表现力 | 静态 PPT 感，无运镜 | 有运镜但动作幅度小 | 完整动作弧线 + 运镜自然 |
| D 整片节奏 | 镜头碎、硬切突兀 | 节奏尚可但转场生硬 | 镜少而长、转场有意义 |

**判读规则**：A、B 是 P1 核心承诺（一致性），C、D 是副产品观察项。A 或 B 低于旧路径即触发 6.2 回退评估。
