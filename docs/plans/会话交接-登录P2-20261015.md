## 二、关键设计取舍（对 P1 交接文档的一处**落地偏差**，已认可逻辑）

- P1 交接里写「无 token 时返回 auth-required，登录成功后原操作继续」。落地为：**无 token 直接 fail-fast 抛 CS-AUTH-001 → client 立即弹登录窗 → 登录后 agent 按恢复提示原样重试**（即「原操作继续」靠重试达成）。
- 理由：Host 侧做「阻塞等待登录最长 5min」会让 agent 回合静默挂死 5 分钟，体验与可控性都差；fail-fast + 重试语义等价且链路短。
- 401 自愈链保持 P1 设计：静默续期重试一次 → 仍失败才弹窗。

## 附一、P2.1 修复：本地直连入口的登录前置闸（2026-10-15，未验收）

**症状（真机实测）**：退出登录后点画布节点的「发送/重试」——**完全没有反应**（预期弹登录窗）；而经 agent 调用后台工具时，登录窗照弹。

**根因**：同一个 `CS-AUTH-001`，两条通道的收口不同。闸本身是好的（Host fail-fast，零网络），坏的是**客户端这一段**：

| 环节 | 工具通道（能弹窗） | 画布节点卡通道（没弹窗） |
|---|---|---|
| 客户端收口 | `asset-capture.ts:384` 认码 → 移除占位 + `onAuthError` → `handleAuthError` → `requestLoginPrompt()` | `retryNode` 的 catch（`client/index.ts`）**只写 `node.error`** |
| 结果 | 登录窗 | 通道到头，无引导 |

判定依据：全仓 `requestLoginPrompt()` 原本**只有** `handleAuthError` 一个调用点 ⇒ 弹窗桥只挂了「工具事件」这一根线。而「点了没反应」的观感由三条叠加：未登录是零网络本地 400（`isLoading` 只闪一帧）+ 发送后输入卡自动关闭（视线在卡片上）+ 唯一反馈是**节点头部的红标**（常在视口外，且文案是错的：「生成失败」≠「需要登录」）。

**本轮改动（5 处，只动产生数据的路径）**：

1. `src/client/auth/auth-store.ts`：新增 `needsSignIn()`（纯判据，供后台任务用）与 `requireSignIn()`（判据 + 弹窗，供消耗型入口用）—— **L1 唯一前置闸**；`signOutAuth()` 补一次**等待落地**的 `SIGNED_OUT` 推送（原推送是 fire-and-forget，「退出登录 → 立刻操作」时 Host 还挂着旧 token）。
2. `src/client/api.ts`：新增 `isAuthRequiredError(cause)`（`CS-AUTH-001` 码字面量只剩这一处）。
3. `src/client/index.ts` `retryNode`：闸**前置**（刻意的位置：`isReplayable` 之后、写 `isLoading` 之前 —— 本地参数结论与登录态无关，先给用户准确的那条；不满足则不进加载态、不写节点）；catch 认码 → 弹登录窗 + **不写 `node.error`**（与 asset-capture 同语义：可恢复态不标红）。
4. `src/client/StudioFrame.tsx`：新增 `resolveRefsForProject`（**唯一实现**，画布浮层与详情抽屉两个调用点共用）并在其中挂闸；`resolveStudioRefs` 的直接调用点由 2 处收敛为 1 处（此前未登录时它会被 `resolve-refs` 路由的**逐项 try/catch** 收成「逐项解析失败」红字）。
5. `src/auth-session.ts` 语义与本文档 §一 表格对齐（漂移修正）。

**刻意不做（有实证，不是漏）**：

- `promoteDeferredAssets`（后台预热）**不加闸**：失败已被静默 catch，且 Host fail-fast 零网络 ⇒ 加闸纯冗余。
