## 四、待办池（按你关心的三类分组）

### A. Bug —— 正确性（**只剩 1 条**）

#### SB-05【P2】`resolveShotRefs` 不认契约钦定的语义引用

- **位置**：`src/host-tools.ts:1106`（调用点 :1263 / :1312 / :1334）。
- **现象**：`shotRefs` 只接受 ① 节点 id ② 分镜卡标题精确 ③ `分镜 N` 前缀。但 seed 产出的分镜卡自带 `sbRef='04:<scene>/shots/<shot>'`，而 `image_generate.storyboardRef` 的口径是**语义 shot id**（形如 `S1-Sh1`）——**第 4 种引用形态契约里有、数据里有、解析器不认**。agent 按故事板语义传 `shotRefs` 直接 `CS-USER-ERR`，且报错提示只提「卡片标题或节点 id」，进一步固化旧口径。
- **连带**：`landed` 时算出的 `bindings`（sbRef ↔ 画布 UUID）**全库无消费方**——双向映射建了不用等于白建（评审 G4）。
- **修法**：在既有三条匹配链后追加两条 —— ① `node.sbRef === raw` 精确命中（扫**全量**画布节点，不只分镜卡：角色/声音节点也可被引用）；② raw 为纯语义 id 时按 `sbRef.endsWith('/shots/' + raw)` 匹配分镜卡。报错提示补上新写法。
- **验收判据**：seed 后用 `04:S1/shots/S1-Sh1` 与 `S1-Sh1` 两种写法传 `shotRefs` 均解析成功；旧三种写法回归不变；新增单测覆盖全部写法 + miss 报错文案。
- **测试落点**：扩 `tests/shot-cards.test.mjs`（注意确认 `resolveShotRefs` 有导出，否则经工具 execute 路径测）。

### B. 展示 / 体验优化（4 条小 + 1 条中）—— **推荐优先做，用户能直接感知**

#### SB-09【P3·体验】iframe 每次 bump 整页重载，把用户的滚动位置打回顶部

- **位置**：`src/client/StudioFrame.tsx:2633-2634`（`src={... + '?rev=' + storyboardRev}`）；信号源 `src/client/storyboard-signal.ts`。
- **现象**：`write_storyboard` 每次结算都 bump rev → iframe 换 `?rev=` **整页重载** → 长文档被拉回顶部。而 skill 教的正是**分次写**（§00→§02→§04…）⇒ storyboarding 期反复打断阅读。
- **修法选项**（择一，写清理由）：
  1. **Host 侧内容指纹**：渲染路由算内容 hash 并返回/比对，**内容未变不 bump**（最干净，但要给 Host 加面）；
  2. **客户端滚动记忆**：重载前记 `scrollTop`，`onLoad` 后经 `contentWindow` 恢复（iframe 同源，可行；零 JS 约束不破，因为恢复逻辑在**父页**）；
  3. 记账不做（零 JS 约束下确无更优注入通道时，登记 backlog）。
- **验收判据**：连续写两节 → 第二节内容变化时 iframe 重载，**滚动位置保持**。

#### SB-10【P3·体验】覆盖层的「关过不再弹」不持久化

- **位置**：`src/client/StudioFrame.tsx:448`（`useState(new Set())`）+ `:720`（`storyboardAuto` 读它）。
- **现象**：只在内存。刷新页面后 storyboarding 态**强制重弹**覆盖层。
- **修法**：持久化到 `sessionStorage`（key 带 projectId）或项目级配置。⚠️ 它现在是 **state 不是 ref**（CV-302 为了让派生式可见性 `storyboardVisible` 生效而改的），持久化时必须仍走 `setState` 触发重渲染，**不要退回 useRef**。
- **验收判据**：关掉覆盖层 → 刷新页面 → 不再自动弹；换项目不受影响。

#### SB-12【P3·体验】落地失败只有一句通用 toast，缺项无可视化引导

- **位置**：`src/client/StudioFrame.tsx:1622-1638`（`handleLand` 的 `.catch` → `actions.setFailed(...)`）。
- **现象**：Host 的 `validateForSeed` 报的 blockers **逐项列了「缺什么」**（`handleLand` 的注释也承认这条文案很有用），但它落在一个通用失败条里；九节文档缺项在覆盖层里**没有任何标记**。用户看完 toast 仍不知道去哪一节补。
- **修法方向**：① 把 blockers 做成覆盖层内的一个区块（不占用通用失败条）；② 更进一层：给 `renderStoryboard` 加「缺项标记」参数，在 iframe 里把缺的节高亮（Host 已是纯函数渲染，加个入参即可，可单测）。
- **验收判据**：故意缺 §04 点落地 → 能在覆盖层里**看出缺的是哪一节**，而不是只有一句 toast。

#### SB-08【P3·注释】头注与实现不符
