## §1 C1 视频下载工具 `download_video`

### 1.1 问题

viral-remake 前置自检明确「链接 → 让用户给文件，不承诺抓取」。用户拿着抖音/B站链接说「复刻这条」，第一步就断。

### 1.2 需求

新增第 38 号宿主工具 `download_video`（编号前按惯例 grep `docs/` 复核，当前已编至 37=verify_teardown）：

| 入参 | 类型 | 说明 |
| --- | --- | --- |
| `url` | string | 视频页链接（http/https） |
| `expectedDurationSec` | number? | 可选，用于下载后校验（防错下成图集/短预告） |

出参：`{ assetPath, durationSec, width, height, hasAudio, source }`，产物落画布素材区，与 `upload_image` 落盘形态一致（后续工具链可直接引用）。

### 1.3 实现要点

- 内核 = yt-dlp 二进制（单文件可执行，含 ffmpeg 依赖探测）。新模块 `src/video-download.ts`（可单测纯函数 + 薄执行壳）。
- 二进制分发：**运行时按需下载**到用户数据目录（`userData/bin/yt-dlp/`），带版本号与 checksum 校验；下载失败给出手动放置路径指引。不进安装包（体积 + 合规）。
- 站点策略：白名单校验（v1：抖音 / B站 / YouTube），白名单外明确报错「暂不支持该站点」。
- 错误处理分类（可读文案，供 Agent 直接转述）：链接无效 / 站点不支持 / 视频需登录（v1 不带 cookie，直接报错）/ 下载超时（默认 120s）/ 产物校验失败。
- 版权提示：工具描述中注明「仅用于用户自备参考素材的拆解复刻，复刻产出默认替换原素材」。

### 1.4 验收

- 单测：url 白名单校验、错误分类映射、产物信息解析（用固定样本 ffprobe 数据 mock）。
- E2E：真机下载一条 B站公开视频 → `assetPath` 可被 `inspect_image` / 抽帧链路直接消费。

## §2 C2 证据网格工具 `evidence_grid`

### 2.1 问题

拆解靠 `inspect_image` 逐帧轮询，甜品会话实测几十次调用才拼出一段的画面变化；且**画面与口播对不上**——不知道哪个画面变化服务哪句话。hypit 的核心效率手段就是「一次调用返回带时间戳/台词标注的贴片网格」。

### 2.2 需求

新增第 39 号工具 `evidence_grid`，一次调用产出「时间标注网格图 + 结构化清单」：

| 入参 | 类型 | 说明 |
| --- | --- | --- |
| `videoPath` | string | 参考视频 |
| `passes` | Array | 采样计划数组，每项 `{ start, end, interval }`（秒）；省略 = 默认两段式 |
| `columns` / `rows` | number? | 网格布局，默认 4×3 |
| `cellPx` | number? | 单格边长，默认 480 |
| `transcriptPath` | string? | 可选，ASR 词级转写 JSON（schema 见后台需求文档）；提供时在每格下方叠加该时刻的台词词标签 |
| `markCuts` | boolean? | 默认 true，切点处网格加描边标记（复用 `verify_teardown` 的切换点检测） |

默认采样策略（Agent 未传 `passes` 时）：整片概览 1s/格 + 密集段需 Agent 二次调用 0.1–0.3s/格——与 hypit「宽窄两级、随问题调节」一致。

出参：
- 1–N 张网格 jpg（单网格 ≤48 格，超出自动分页，文件名带页码与时间范围）；
- 结构化清单 JSON：每格 `{ index, timestampSec, page, row, col, words? }`（words = 该时刻激活的台词词及窗口）；
- `cutPoints: number[]`（实测切换点，秒）。

### 2.3 实现要点

- 新模块 `src/evidence-grid.ts`（采样计划→抽帧清单→ffmpeg 批量抽帧→拼网格→标注），Host 侧合成标注（时间戳 + 台词词标签 + 切点描边）。
- **标注渲染方案（定死，消除实现歧义）**：网格拼合与文字烧录走 ffmpeg 滤镜链（`tile`/`xstack` 拼图 + `drawtext` 烧时间戳/词标签），不引入 node-canvas 类新依赖；`drawtext` 需要实体字体文件（woff2 不适用），随包新增一份 Noto Sans SC Regular TTF/OTF（约 10MB，进 `assets/fonts/`）。若 drawtext 词标签排版（换行/截断）不够用，退化方案 = `@napi-rs/canvas` 画整格再交 ffmpeg 拼图（预编译二进制，无编译链负担）。
- 抽帧用单次解码连续输出（同 hypit `tiles` 的连续解码分页思路），避免逐帧起进程；`-vsync` 处理 VFR 源，格时间戳取实测帧 PTS。
- 台词叠加规则：格中心时刻落在哪首个词窗口内 → 显示该句该词（词高亮）+ 本句前 8 字上下文；无转写时只显示时间戳。
- 与 `verify_teardown` 关系：后者保持不动（职责 = 回核校验）；本工具的 `cutPoints` 复用同一检测函数（抽公共纯函数，不许复制实现）。
- 产物登记进拆解证据目录（`teardown_store` 同源的跨项目目录），便签可回链。

### 2.4 与 ASR 的关系（无阻塞）

`transcriptPath` 为可选：**不传即出纯时间戳网格，能力立即可用**；后台 ASR（另立需求）上线后，Agent 在拆解时先转写再传路径，网格自动升级为台词标注版。两批交付互不等待。

### 2.5 验收

- 单测：采样计划展开（含 interval 边界、片尾截断）、分页计算、词标签选取逻辑（给定 transcript JSON + 时刻 → 期望词）。
- E2E：对固定样本视频出 2 页网格，断言页数、格数、cutPoints 与 verify_teardown 结果一致。
- skill 联动：`viral-remake/SKILL.md` §1 拆解步骤改为「证据网格优先、inspect_image 兜底」（文档改动，随本条交付）。

## §3 C3 媒体探针工具 `media_probe`

### 3.1 问题

拆解表头部需要时长/fps/音轨，响度对齐需要参考片 LUFS——现在散装在 ffmpeg 手工调用里，无统一入口（SKILL §4 的 ebur128 靠临场拼命令）。

### 3.2 需求

新增第 40 号工具 `media_probe`：入参 `videoPath`（或音频路径），一次返回：

```json
{
  "durationSec": 26.4, "width": 1080, "height": 1920, "fps": 30,
  "hasAudio": true, "audioLoudnessLufs": -11.4,
  "audioStreams": 1, "videoStreams": 1, "container": "mp4"
}
```

### 3.3 实现要点

- 新模块 `src/media-probe.ts`：ffprobe 元数据 + `ebur128` 响度测量（响度测量仅在 `hasAudio` 时执行，失败不阻塞探针，`audioLoudnessLufs: null` 并附原因）。
- 纯函数拆分：元数据解析 / 响度解析可单测。

### 3.4 验收

- 单测：ffprobe/ebur128 输出解析（固定样本输出 mock）。
- E2E：真 ffmpeg 对样本断言 duration/fps/lufs 数值范围。

## §4 C4 相对锚定（manifest 事件锚词）

### 4.1 问题

manifest 事件锚绝对帧：变体替换文案后词数变化 → 能量谷重排 → 时机漂移，只能人工重调（SKILL §5 已自曝此坑）。这是「批量裂变」质量不稳的根因。

### 4.2 需求

manifest 轨道事件（`animate` 起点等时机字段）新增可选 `anchor` 字段，二选一：

```jsonc
// 形态一：锚 caption 轨的句/词窗口（词级）
"anchor": { "ref": "cap-1", "phrase": 2, "word": 5, "from": "start", "offsetFrames": 0 }

// 形态二：锚旁白句窗口（句级，无需词索引）
"anchor": { "ref": "cap-1", "phrase": 2, "from": "end", "offsetFrames": 3 }
```

字段语义：

| 字段 | 说明 |
| --- | --- |
| `ref` | 目标 caption 轨 id（该轨须带 `src` 旁白） |
| `phrase` | 句索引，0 起 |
| `word` | 词索引，0 起；省略 = 整句窗口 |
| `from` | `start`（窗口起点，默认）/ `end`（窗口终点） |
| `offsetFrames` | 相对偏移，可负 |

解析规则：渲染期 caption 词级 timing（现有 `word-timing.ts` 输出）就绪后，anchor → 绝对帧；与现有绝对帧字段**互斥**，同时出现以 schema 校验报错。

### 4.3 实现要点

- 客户端渲染器（`client/remotion` 侧）在组合期完成解析：caption timing 先算，anchor 后解析，事件按解析帧执行。
- fail-fast：`ref` 轨不存在 / `phrase`/`word` 越界 / 被锚轨无 `src` → 渲染体检硬失败，错误信息含轨道 id 与索引（同「缺素材硬失败」先例，不许静默回退 0 帧）。
- 纯函数 `resolveAnchor(anchor, wordTiming): number` 放 `src/remotion/`（Host tsconfig 可测）。
- `scaffold_manifest` / `manifest-contract.md` 同步登记该字段；`timingSegments` 双闸无需改动（拆解段仍是绝对时间基准）。
- 变体联动：批量换装只换文案/素材时，锚词事件**不需要**人工重算——SKILL §5 的「文案替换不是盲替」提示保留，但时机漂移由锚定机制消除。

### 4.4 验收

- 单测：resolveAnchor 全分支（start/end/word/越界/offset 正负）；manifest schema 互斥校验。
- E2E（bench 探针新增 1 例）：双版 manifest——同一 anchor 结构 + 两套不同字数文案，断言两版成片中该事件均落在对应词窗口 ±2 帧内。
- smoke：新增红名单外 0 新增。
