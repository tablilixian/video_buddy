总览 · OVERVIEW

问题与拍板结论

定位澄清：故事板是一块随对话逐步清晰、随时可改的状态板——不是一份读完即定的文档。它要如实表达「哪些定了、哪些还在变、钱花在哪」，并在落地画布那一刻冻结、之后由画布回写。据此，除下列六项外，另做 P1–P3 三点重心修正。

产品定位对齐 · STATEFUL BOARD

它不是一份文档，是一块「逐渐清晰的板」

用户输入创意 → agent 边聊边把已确认的部分一步步搬上板 → 用户随时审阅、通过对话随时改 → 确认无误后落地画布 → 落地即冻结，之后由画布回写。前期几乎没有图片，唯一付费生成的是那张风格定稿图。据此对前面各项做三点重心修正。

P1 · 确认态分层：待讨论 / 草案 / 已确认

为什么

你的定位把「确认」当成主要动作，所以板子必须能表达“定了没、还在不在变”，而不只是“有没有内容”。这也天然形成落地门槛：只有已确认节才允许落地，把返工挡在落地前。

① 术语与命名

同一件事，用户撞见 4 个名字

名称混乱 + 过程面文案泄漏，是这页「不专业感」最主要、也最省力的来源。

现状问题
  • 阶段叫「拍摄定稿」，加载态叫「分镜推演」，画布叫「分镜」
  • 占位页一页之内自相矛盾：标题「还没有拍摄定稿」、正文「还没有产出故事板」
  • 错误提示错别字：「故事版里找不到版本」
  • 正文在讲系统机制：「这是唯一事实源 / 在画布顶条审阅 / 点确认落地会拆节点」
  • 页脚暴露实现细节：由 render() 从 storyboard.json 生成
  • 顶栏挂内部版本号 schemaVersion
建议方案
  • 立三层术语：拍摄定稿（阶段）/ 故事板（文档）/ 分镜（画布单元）
  • 文档面统一「故事板」；修掉「故事版」错别字
  • 正文改为内容开场，机制说明收进页脚 <details>「关于本页」
  • schemaVersion 与 render()/storyboard.json 一并下沉到「关于本页」
  • 九个空节文案压成一行 hint

⑥ 浅色主题与配色

为什么换了浅色，故事板还是深色

故事板是一份独立 HTML，:root 调色板写死深色、<meta color-scheme=dark> 写死、路由不下发主题、iframe 容器背景也写死 #141412。所以应用切浅色，它纹丝不动。

  • 容器 SC.column/full/frame（:108/117/148）的 #141412 改走主题 token，否则外框仍深
