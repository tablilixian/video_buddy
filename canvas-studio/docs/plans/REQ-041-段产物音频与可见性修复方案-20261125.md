## 2. 两个问题的直接回答

### Q1：段视频没声音，是设计还是没做好？

**是明确设计，两层叠加，不是功能缺陷。**

1. **渲染层（R11-C3 / D3）**：段 manifest 剥掉 `audio`，`muteAudio: true` 恒真，Remotion 靠 `muted: true` 关音轨。代码注释写明：直接写 `audioCodec: null` 会被 web-renderer 的 `?? default` 吃回 aac，产出 -91dB 静音轨与拼接点 40ms 定格；`concatShots` 用 `-c copy` 拼接，要求所有段流结构一致。
2. **交互层**：hover 自动播放必须 muted，浏览器硬限制。

**成片是有声音的**（回执 `音轨 BGM + 旁白`、`✅ 音频 2 个出声源`），无声的只有卡上那段预览视频。现在要用工具把它俩合起来——这不推翻设计，而是**新增一条面向预览的带声副本**，缓存里的无声段保持原样供 concat。

### Q2：为什么一个分镜视频也没生成？

**两个独立断点，必须都修，只修一个用户还是看不到。**

**断点① 渲染层没进分镜路径。** `shot-render.ts:267` 传 `allowShots: manifest.audio === undefined`；11 句旁白 ⇒ false ⇒ `shot-cache.ts:273` 直接 `mode:'whole'`，回 `outcome:null` + 空段清单，落回整片。会话回执里那句 `ℹ️ 分镜渲染未启用` 就是这条分支。而且会话里大多是 probe/spot 调用，在 `host-tools.ts:3983` 的 `if (!probe && !spot)` 之外，连 `runShotRender` 都不进；唯一主片 draft 又卡死在 RenderHost 31s。

**断点② 清单层 draft 没有数据源。** 14:27:08 磁盘上已有 11 个 `assets/seg-s*.mp4`，但没有 `deliver/card.json`：`host-tools.ts:4063` 只在 standard/high 写卡，draft 不写，而 L1 清单路由只读 `card.json` ⇒ 清单空 ⇒ 卡上依旧是文案。

**用户截图里的"声音跟分镜托盘对应上了"不假**：托盘是纯视觉框，卡和配音一一对应是布局算出来的；数据里 `edges` 为 0，没有真正的连线。这个对应关系另有更可靠的来源——`voiceOver[].startFrame` 落在段帧窗、src 与 tts 节点 url 完全相同（11/11 已验证）。

## 3. 设计约束（不可退让）

1. 成片路径零改动：`audio-compose` / `concatShots` / `runRenderJobWithStuckRetry` 一行不动。
2. 不写 `canvas.json`、不建段节点、不新增 surface、不改点击手势。
3. 匹配只认 `ref`（spec 原文 id 经 `segmentRefOf`），仅 `aligned` 时生成；**禁止按序号配**。
4. 段副本确定性命名、覆盖写，不用 `saveLocalAssetBytes`。
5. 存量不回填；旧文件缺 `ref` 就是缺，清单不猜。
6. hover 恒静音（浏览器硬限制）；点击手势不变。
7. **无声段与带声段分开存放**：concat 只用无声段，保证流结构一致；画布清单只指带声段。两者不共用文件。

## 4. 方案对比

| 方案 | 做法 | 成片声音风险 | 段自带声音 | 结论 |
|---|---|---|---|---|
| **D（推荐，用户提出）** | 段视频 + 对应 `voiceOver[].src` 用 `buildMuxArgs` 合成**带声副本**；清单指向副本 | **零**（整片一行不改） | **有**（就是那句台词） | ✅ 最直接；不依赖成片渲完 |
| A（原推荐） | 整片渲完后从成片按帧窗切段 | 零 | 有 | 退居备选：要等成片；受整片响度归一化影响 |
| B | 解禁 `allowShots` + concat 后配 | 中（混音全链路回归） | 无 | 留作 N1 备选 |
| C | Remotion 段渲染内嵌音频 | 中 | 有 | ❌ -91dB/40ms 回归；`manifestGlobalsFingerprint` 不含 `audio`，改旁白后声音是旧的 |

**方案 D 为什么更合理**：段与台词的配对在 `manifest.audio.voiceOver[]` 里已经是显式数据，不用等成片、不用反推；`buildMuxArgs` 让画面 `-c:v copy` 零重编码；带声副本独立命名，concat 路径与整片路径都不受影响。

## 5. 实施步骤

### P0-a · 清单层：draft 也能出清单（先修，直接解决"段显示不到托盘"）

- **改什么**：`src/segment-media.ts` 的清单来源增加**派生回退**：`deliver/card.json` 不存在或无指针时，读 `build/spec.json` 的 sections 原始 id 与 `build/manifest.json` 的帧窗，调用 `planSegmentArtifacts` 现场派生 `ref`（沿用 `aligned` 判据），再 stat `assets/seg-<id>.mp4`。只读、不写盘。
- **判据**：`ref` 只能来自 `planSegmentArtifacts` 的 aligned 结果；对不齐就不给 `ref`，清单空。**不得用文件名 `seg-sN` 反推 `spec:sN`**。
- **不动**：`allowShots` 与整片路径保持原样。
- **测试**：`tests/req041-segment-media.test.mjs` 加 3 条断言——无卡但 spec+manifest+段文件齐全时回 11 条且 ref 为 `spec:sN`；spec 与段表不对齐时回空；段文件 stat 不到时回空。反向变异：改成按序号 ⇒ 必须变红。
- **验收**：对 14:27 那个项目 curl 清单回 11 条、url 全 200（无需重渲）；托盘里 11 张分镜卡出现画面。

### P0-b · 渲染层：段产物旁路发布（保证"新产出"的段一定存在）

- **改什么**：`host-tools.ts` 整片渲染成功后新增只发段的旁路，帧窗用 `resolveShotBoundaries` + `sliceByShots`，与 `planShotRender` 同一口径。
- **产物**：沿用 `segmentArtifacts.ts` 的确定性 id / `ref` / `assetFile`，复制两份（`deliver/segments/` + `assets/`），覆盖写。
- **失败语义**：切段失败不阻断成片，只记一行 note；任一份副本缺失该段不给指针。
- **测试**：整片成功 + 切段失败 ⇒ 成片 outcome 原样、段清单空；反向变异：吞掉失败仍发指针 ⇒ 红。
- **注意**：此步解决"以后每次渲都有段"，但对 14:27 存量段不适用（不回填）。

### P1 · 工具合并：段视频 + 对应旁白 → 带声段副本（用户方案核心）

- **配对**：`voiceOver[]` 按 `startFrame ∈ [seg.startFrame, seg.endFrame)` 落窗；`src` 为项目内 `/canvas-studio/assets/...mp3`，经 `resolveAssetPathIn(assetsDir, ...)` 取本地路径。**优先用 manifest 的 voiceOver，不依赖画布坐标或连线**。
- **合并**：新增纯函数（建议 `src/segment-audio.ts`）：输入无声段路径 + 旁白路径 + 段时长，调 `buildMuxArgs(master, audio, output, durationSec)` 与 `runFfmpeg`。`-c:v copy` 画面零重编码；`-t durationSec` 保证段长严格等于帧窗时长；旁白短则尾部静音，跨段长句则在段边界截断（该屏听到的就是它那一段）。
- **输出命名**：`assets/seg-<id>-voice.mp4`（+ 可选 `deliver/segments/<id>-voice.mp4`），确定性、覆盖写。**不要覆盖无声段**——concat 与缓存仍用无声版。
- **清单**：`SegmentMediaItem` 的 `url` 指向 `-voice.mp4`；`ref` 不变；合并失败则回退无声版 URL 并记一行 note，不阻断成片。
- **触发**：段发布后在宿主侧自动合并（不是让用户手动点工具）；合并耗时随段时长，先实测。
- **BGM**：本期不进段——托盘里对应的是台词配音，BGM 是 110s 整轨。要"完整听感"可后续把 BGM 按帧窗切片再 `amix`，属增量，不混进本期。
- **客户端**：hover 仍 `<video muted>`，零改动；第 3 批 N3 从"video+audio 双向同步"降为"点开细看播带声段视频"，step plan 需改写。
- **测试**：落窗配对（含跨段边界）、`-t` 时长严格、合并失败回退无声版、带声与无声文件名隔离。反向变异：把落窗改成按序号 ⇒ 红。
