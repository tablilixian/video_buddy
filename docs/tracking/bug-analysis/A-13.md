# A-13 ｜ qwen 文生图「未挂画布」+ 下游视频 Picture 1 断链

> 优先级 P1（链路本身查无 bug，残余 = 删源节点无下游告警）｜ 风险 T2 ｜ 依赖：**B-4 先行**（同一删除协议）
> 截图要点：资产库两条「文字生图」，一条标「未挂画布」；另一视频的编辑抽屉里 Picture 1 显示「参考已断链」。用户批注：qwen image 生成的文生图没挂画布；本应图生图更佳。

## 现象与排查结论（如实）
- **落卡链路无缺口**：`image_generate_withtxt` 与 `image_generate` 走完全同一套 `runGeneration → persistGeneratedAsset → appendCanvasNode`（host-tools.ts:1227-1236 → generate.ts:2339 → :2520-2523），节点应当存在。
- **「未挂画布」是诚实的派生态**：HistoryDrawer `stateOf`（:111-116）按「当前画布节点 url basename」建索引（:97-109），查不到 → orphan。节点被删（文件进 .trash、历史条目保留、缩略走 .trash 兜底）是唯一常态路径；retired 节点仍留画布所以不算。注：派生用「当前已载入画布」——E-2 的启动多画布对齐期可能瞬时误报。
- **Picture 1 是槽位序号徽标**（ReferenceSlotEditor.tsx:215），断链判据 = 视频 generationPrompt.filenames[i] 在画布上找不到持有同句柄的节点（node-params.ts:70-78）——与「源图节点被删」同根因。
- **已覆盖**：重试换句柄（C-10/overwriteNodeAsset 下游改写）、生成期句柄漂移（A-1 自愈 + generationPrompt 同步）。
- **真缺口（本条要修的）**：删除源图节点时没有任何路径处理下游引用（`trashAssetsForRemovedNodes` 只搬文件）→ 下游悬空。属显式用户操作的合理结果，但用户应被事先告知。
- 「图生图更佳」是模型路由产品问题（该镜该用 i2i 而非 t2v 纯文生）——归 R-P0-09/10 的路由规范，不算 bug。

## 修复方案（低风险推荐：删除前下游引用告警）
1. 复用 B-4 的引用判定：删除画布节点（client removeNodes → 保存 removedIds）前，Host 或 client 计算下游 generationPrompt 引用该节点句柄/URL 的节点清单。
2. 告警形态：删除确认弹窗列「N 个视频/图片引用了它，删除后它们的参考将断链」（指名道姓），用户确认才删。实现位置建议 client 侧（project-store removeNodes 已有 pendingRemovedIds 账本，:780-787）——引用判定用 node-params 的 resolveReferenceSummaries 反查即可，不需要新 Host 路由。
3. 可选加固（同批）：HistoryDrawer 的 orphan 条目与「断链句柄」做联合提示（同一根因两处呈现）。
4. 不推荐删除时自动改写下游 prompt 为占位（改写历史记录语义有争议）；B-4 的「彻底删除」路径已覆盖「解引用」语义，两条入口（画布删节点 / 历史删资产）行为口径需在实现时对齐。

## 改动风险
低：只加告警不改删除语义；E-2 若采纳 homePinned，启动期 orphan 误报顺带缓解。

## 验收
无头：project-store 单测（removeNodes 返回/触发下游引用清单）。桌面：删一张被视频引用的图 → 弹窗列出引用方 → 确认后该视频详情显示断链卡（现状一致），但删除前有告知。
