## 2. 测试用例

> 标注：〔必测〕= 验收必须过；〔体感〕= 看成片主观判断；〔可选〕= 机制有单测钉死，有条件就验；〔观察项〕= 难单独触发，遇到再看。

### T1 分镜增量渲染主链〔必测〕（R11 全链）

**操作 1（首渲）**：新建项目「分镜验收」，对话框粘贴：

```
用屏表（screen-plan）spec 通道做一条 20 秒、1080p、30fps 的科普短视频《同温层为什么冷》，
meta.autoStages = true（自动屏数节奏），纯文字卡不用任何素材，三个 section：
s1 开场钩子：copy「飞机为什么飞不过 2 万米？」
s2 数据屏：两个单元——数据卡 copy「同温层顶部 −60°C」，要点卡 copy「客机巡航约 1 万米」
s3 收尾：copy「关注我，下期讲急流层」
写完 spec 后用 quality:"standard" 渲染成片。
```

**预期回执**（首渲）：
- 屏表回执：`**屏表**（3 屏 · N 单元 · M 块常驻层 · 600 帧 / 20s）：` + 每屏帧窗行
- 节奏行：`节奏：planStages 算出 3 屏（目标 3），屏长 6.x–7.xs`
- 密度自检行：`密度自检：本次 N 轨 / 20s = X 轨每秒…`
- 渲染成功 + **`🧩 分镜渲染：3 段（0 复用 / 3 重渲，边界来源 spec）`**
- `📦 权威交付：deliver/final.mp4 + card.json（版本 / 时长断言 / 未决项见卡）`
- `🎬 抽帧渲染计数：本会话第 N 次（口径：所有返回抽帧的渲染，含 draft）`
- **记下首渲总耗时：＿＿＿**

**操作 2（二渲）**：对 agent 说「**用同一个 spec、同一质量档（standard）再渲染一遍，其他不动**」。

**预期回执**（二渲）：
- **`🧩 分镜渲染：3 段（3 复用 / 0 重渲，边界来源 spec）`**，总耗时显著短于首渲（无 Remotion 渲染，只剩拼接+落盘+探测，通常秒级 vs 分钟级）

**通过判据**：
1. 两条 🧩 行格式与数字符合上述；
2. 二渲耗时 < 首渲的 1/2（理想秒级）；
3. 质量档必须同档（hash 含 quality，换档全脏是正确行为，不算失败但别在验收里混）。

### T2 改一处只脏受影响段〔必测〕（R11-C2 + 传递语义）

**操作**：对 agent 说「**把 s2 数据卡里的 −60°C 改成 −64°C，其他一切不动，重新渲染（standard）**」。

**预期回执**：`🧩 分镜渲染：3 段（1 复用 / 2 重渲，边界来源 spec）`

**通过判据**：
1. **s3 复用**、s2 重渲、**s1 也重渲**——s1 重渲是**正确的依赖传递**：s1 的活跃集含转场窗 [边界−10, 边界) 里 s2 的开头渐显帧，s2 内容变 = s1 尾帧画面变。三种错误形态都要报：
   - 3 段全重渲 = hash 粒度回归；
   - 只有 s2 重渲（s1 复用）= 转场窗依赖漏算，成片 s1 尾部会串旧帧；
   - 3 段全复用 = 改动根本没进 manifest。
2. 成片体感：s2 数字变了，s1 开头与 s3 与上一版逐帧一致。

### T3 改全局态全段脏〔必测〕（11-16 P1-2 回归面）

**操作**：对 agent 说「**把 spec 的 meta.title 改成《同温层为什么冷·二》，其他一切不动，重新渲染（standard）**」。

**预期回执**：`🧩 分镜渲染：3 段（0 复用 / 3 重渲，边界来源 spec）`

**通过判据**：全段重渲。title 只在 meta（globals 指纹）里、不在任何轨道里——如果 3 复用 = P1-2 回归（globals 没进 hash），报开发。
说明：改顶层 manifest id **不应**作废缓存（id 刻意不进指纹）——无需单独验，遇到「内容没变却全重渲」时先查是否只有 id 变了。

### T4 有音频走整片路径〔可选〕（R11 回退矩阵 D3）

**操作**：在**有背景音乐/配音轨**的既有工程（画布上有音频节点）渲 standard/high。

**预期回执**：**不出现**「🧩 分镜渲染」行（音频段整轨后配是 Phase 1.5，有音频一律整片渲染）。

**通过判据**：整片渲成功、成片有声音、无 🧩 行。
说明：spec 通道当前不产音频，这条只能在没有音频的 spec 工程之外验；验不了可跳过（回退矩阵有 plan-shots 7 条单测钉死）。

### T5 权威交付 deliver/〔必测〕（R9 P1a）

**预期**：

### T8 格位相交分级闸〔必测〕（R8-A1）

**操作 1（拦截）**：粘贴：

```
还是屏表 spec 通道、20 秒三个 section，但 s2 故意放两个相交的格位（这是验收闸用的，别自己修）：
数据单元 cell {x:30, y:40, w:40, h:40}，要点单元 cell {x:55, y:45, w:40, h:40}。

```

**预期回执**：spec 编译被拦，错误文案含（原文，% 数字按几何算约 33%）：

> `…的格位 units[0] 与 units[1] 相交 NN%（占较小格位）—— 同屏内容格位长期并存是遮挡不是动效（动效在格位内部）：把两个格位错开，或在刻意叠层的单元上写 "overlap": true 声明设计意图（≤5% 贴边自动放行）`

**操作 2（豁免放行）**：接着说「**按它说的，给要点单元加 `"overlap": true`，其他不动，重新渲染**」。

**通过判据**：拦 + 放两段都符合。≤5% 贴边相交不拦（无需单独造）。

## 4. 快速自查表（疑似失败时先对一遍）

| 症状 | 先查 |
|---|---|
| 二渲没有 🧩 行、走整片 | manifest 是否带了 audio（T4 语义）；或 spec.json 是否还在 `build/spec.json` |
| 🧩 行「边界来源 transition 末端」 | spec 边界派生失败（spec.json 缺失/过期），机制正确但复用会失效——恢复 spec 后应回到 spec |
| 🧩 行「边界来源 单段回退」 | 无可用边界（无 spec 且无 transition 轨）——整片回退是正确 fail-safe |
| 复用数与 T2/T3 预期不符 | 质量档是否同档；spec 是否被 agent 顺手重生成（结构变了边界就变） |
| 全段重渲但内容没变 | 是否只有 manifest id 变了（id 不进指纹，不该全脏——若全脏报开发） |
