| 缺口 | 核实结论 | 开发量 |
|---|---|---|
| 角色四视图定妆跨集引用 | **已成立**：全局资产库（REQ-001）锚点本就跨项目，物化幂等链路完整（`src/asset-library.ts` §物化 三档兜底）——角色定妆照入库一次、各集项目引用 + 物化即用 | **零开发**，纪律层引用 |

## 二、方案三问

**1. 状态存哪？** 注册表根 `series.json`（与 `groups.json` 同款独立文件模式：独立 version、损坏降级空、`sharedWriteQueue` 串写）。

```
SeriesDocument { version: 1, series: [{ id, title, episodes: [{ episodeNo, projectId, title?, recap? }] }] }
```

- **集 = 项目**：不发明「系列子项目」结构，一集就是一个普通项目；series.json 只存**有序索引**（episodeNo → projectId）+ 每集 `recap`（前情提要，≤2000 字）。
- 每集的画布 / 故事板 / 成片全在项目里，零迁移成本；系列只是注册表级的一张目录卡。

**2. 上下文怎么注入？** **工具给真值、纪律管使用**（与用户参考素材纪律同款，不做管线魔法）：

- 新集项目里 agent 调 `episode_brief(seriesId, episodeNo)` → 返回结构化开工上下文：系列名、本集定位、**前 N 集 recap**（缺省近 2 集）、**库内角色资产清单**（name + `lib:<id>` 句柄 + 描述，cap 12）；
- agent 把 recap 写进本集澄清/剧本上下文，把 `lib:` 句柄用于角色一致性（@ref / 物化走既有链路）。

**3. 资产怎么跨项目引用？** 既有资产库链路原样用（入库 → 各集 `@ref[lib:…]` → 物化幂等）；本方案零开发，只在 `episode_brief` 返回里把句柄递到 agent 手上。

| 测试 | `tests/series-store.test.mjs`（CRUD / 集序 / recap 钳制 / 损坏降级 / 绑定当前项目）+ 注册面守卫 |
| **不做** | 客户端剧集管理 UI（agent 工具面先闭环，UI 等 3.4 验收后按需补）；集间自动「剧情摘要生成」（recap 由 agent 写、人可改——不上模型自动摘要，避免编造） |

## 四、批量验收复核点（请重点看）

1. **集 = 项目**的口径（不做子项目结构）是否认可；
2. **recap 由 agent 撰写、存 series.json**（不上模型自动摘要）是否认可；
3. **客户端 UI 后补**（先工具面闭环）是否认可。

## 五、3.2 / 3.3 与本方案的关系

3.2 通用短剧 executor 手册（集结构 / 节拍 / 钩子密度）与 3.3 `drama-format-director` 壳在本文落地后开工；手册会把「开新集 = episode_brief → 角色资产物化 → 本集创作 → upsert_episode 登记本集 recap」写成流程纪律。
