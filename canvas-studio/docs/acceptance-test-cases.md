# Canvas Studio 全功能验收测试用例集

> 版本：2026-08-29（对应批次 0 + 1 + 2 首批全部落地后的代码状态，测试 116/116）
> 用途：桌面端手动回归的完整用例清单。每条用例给出**操作步骤**与**正常表现**（预期结果）；
> 「正常表现」之外的任何稳定复现现象都算缺陷，回填到 §十二 缺陷记录表。
> 用例编号规则：`模块-序号`，标注关联 backlog 条目（CV-xxx / HITL-x）方便追溯。

---

## 〇、验收前准备

1. 构建 + 重启桌面（**每次代码变更后必须重建**，桌面只加载 `lib/` 编译产物）：
   ```bash
   corepack yarn workspace canvas-studio build && corepack yarn dev
   ```
2. 打开一个已有内容的项目（含生成节点、参考图、血缘边的项目最理想）；没有就先跑一遍 §八 M 组造数据。
3. 记录桌面版本与分支提交号，缺陷记录需附带。

判定总原则：
- **通过** = 表现与用例「正常表现」列一致，且不引入新异常。
- **有条件通过** = 功能生效但有轻微瑕疵（如动画缺失），记录不阻塞。
- **不通过** = 功能不生效 / 报错 / 产生错误数据。

## 一、A 组：项目管理

| 编号 | 前置 | 步骤 | 正常表现 |
| --- | --- | --- | --- |
| A-1 | 无 | 新建项目 | 项目出现在列表并自动选中；画布为空但网格/工具栏正常渲染；无报错 toast |
| A-2 | 已有 2 个以上项目 | 点击列表另一项目 | 画布切换为该项目内容；当前会话跟随切换；左右栏不残留上一项目的选中态 |
| A-3 | 项目甲存在 | 删除项目甲 → 再新建同名项目 | 新建成功，**不报** `workspace rename failed: workspace-name-conflict`（CV-033） |
| A-4 | 有历史残留孤儿 workspace 的旧环境 | 重启桌面，观察画布映射 | 「对话有内容 ⇒ 画布跟随当前会话」「列表选中项与画布一致」，三者不互相矛盾（CV-034） |
| A-5 | 任一项目 | 重启桌面后打开 | 上次的项目与画布状态恢复；对话与画布对应关系正确 |
| A-6 | 两个 DSH 实例共享同一 home（可跳过，单实例环境验证不了） | 两边各新建一个项目 → 各自刷新项目列表 | 两个项目都在 `projects.json` 里（旧版后写方会拿内存副本整表覆盖、先建的项目从列表消失，CV-046）；删掉其中一个后，另一个实例再做任何操作都不会把它「复活」（墓碑） |

## 四、D 组：节点右键菜单（CV-037 修复回归，逐项必点）

前置：右键任一节点，菜单弹出。**通用关闭行为**（每条用例都隐含验证）：
- 点菜单项 → 菜单先关闭、动作**真正执行**（修复点：此前 14 项全部点击无效）；
- 按 Escape → 关闭；点菜单外任意处 → 关闭；右键另一节点 → 旧菜单关闭新菜单打开。

| 编号 | 菜单项 | 步骤 | 正常表现 |
| --- | --- | --- | --- |
| D-1 | 重命名 | 点击 | 出现改名入口（详情面板/行内编辑），改名生效 |
| D-2 | 复制 | 点击 | 副本出现；随后右键空白「粘贴」能粘贴该副本 |
| D-2a | 查看详情 | 点击 | 打开该节点的详情 / 编辑面板（媒体类节点双击已改为预览，详情查看走此入口，CV-045） |
| D-3 | 引用到对话 | 点击 | 对话输入框光标处插入 `@ref` 引用标记；失败时回退为复制（不静默丢失） |
| D-4 | 下载资产 | 右键**带图片/视频 url** 的节点 → 点击 | 触发浏览器下载，文件名为清洗后的节点标题 + 正确扩展名（CV-020） |
| D-5 | 下载资产（置灰） | 右键无资产的节点（便签/文本） | 菜单中**不出现**该项（`canDownloadNode` 为 false 时直接不渲染） |
| D-6 | 锁定 / 解锁 | 点击锁定 | 节点不可拖动、方向键微调跳过它；再点解锁恢复 |
| D-7 | 隐藏 / 显示 | 点击隐藏 | 节点从画布消失（图层面板仍有记录）；再点显示恢复 |
| D-8 | 置顶 / 置底 | 与相邻节点重叠后点击 | 层级立即变化，视觉遮挡关系正确 |
| D-9 | 上移一层 / 下移一层 | 同上 | 每点一次只动一层 |
| D-10 | 解组 | 右键 group 节点 | 子节点散开为独立节点；非 group 节点**不出现**该项 |
| D-11 | 打断 | 右键生成中（isLoading）节点 | 生成任务取消，loading 遮罩消失；非 loading 节点**不出现**该项 |
| D-12 | 重试（同参数重新生成） | 右键 agent 生成且有提示词的非 loading 节点 | 节点回到生成中态并重新生成；**双击/快速连点只触发一次**（防重复生成守卫） |
| D-13 | 修改提示词 | 右键 agent 生成节点 | 打开提示词编辑入口（steer），提交后生效 |
| D-14 | 删除 | 点击（红色危险项） | 节点删除且相关边消失；undo 可恢复 |

## 七、G 组：节点详情（CV-194 起 = 就近工具条 + 底部抽屉）

> G-1~G-5 是原「详情面板」时代的用例（内容仍然有效，只是打开方式改由工具条 / 右键进入）；
> G-6~G-11 是 CV-194（2026-09-17 验收通过）新增的交互用例。

| 编号 | 前置 | 步骤 | 正常表现 |
| --- | --- | --- | --- |
| G-1 | 打开生成节点详情 | 观察参数区 | 提示词单独成段可复制；参考图缩略图正确反查显示；参数为一行摘要；原始 JSON 折叠可展开（CV-012） |
| G-2 | 生成节点 | 点工具条「改提示词」 | 抽屉打开且提示词**预填当前值**（不用自己从 JSON 抠），光标落在编辑区 |
| G-3 | 上传的图片节点 | 查看分辨率 | 显示真实宽高（落卡前已探测），不是「未知」（CV-013） |
| G-4 | 媒体节点详情 | 点底部「下载资产」 | 与右键下载行为一致（CV-020） |
| G-5 | 失败的生成节点 | 打开详情 | 可见错误信息；有重放参数时提供重试入口 |
| G-6 | 画布上任一可操作节点 | **单击**它（不拖动） | 节点上方贴近处出现小工具条（重试 / 改提示词 / 引用到对话），抽屉**不**自动打开；多选、或正在拖动时工具条消失（CV-194） |
| G-7 | 把节点拖到画布最上缘 | 观察工具条 | 上方装不下时自动翻到节点**下方**；工具条始终贴在节点旁边（CV-194） |
| G-8 | 打开抽屉后缩放到 0.4× | 看工具条与抽屉里的字 | 工具条尺寸与 1× 时**逐像素相同**（不随缩放变形）；抽屉里的字号也不变（CV-194） |
| G-9 | 打开抽屉 | 看四条边 | 底边与时间轴顶边齐平、左右与画布等宽、**不覆盖**宿主右栏对话区；抽屉打开时工具条被夹在抽屉上缘之上（CV-194） |
| G-10 | 抽屉打开 | 拖上缘那条 6px 抓取带改高度 | 高度跟手变化；关掉再开、乃至重启桌面后**仍是上次的高度**；拖到最小仍看得见提示词区，画布另一侧至少留出可点区域（CV-194） |
| G-11 | 任一含提示词的节点 | ① 点提示词正文；② 点「展开」；③ 点「聚焦」 | ① 原位变自增高编辑框，**失焦即保存**；② 编辑器占满右栏并出现「保存 / 取消」；③ 居中大窗左「已保存」右「编辑」并排。三档中 Esc 均取消、Cmd/Ctrl+Enter 均提交；**保存不会触发重新生成**（提示语明说「改完再点重试」）（CV-194） |
| G-12 | 音频（BGM）/ 四视图（character_sheet）/ 抽帧 节点 | 打开工具条与右键菜单 | **出现「重试」**（CV-195 补齐了这三类的重放链路）；「改提示词」只对有自由文本提示词的节点出现——**只有 BGM 有**（音乐描述 / 歌词两个框），四视图与抽帧没有可改的自由文本，故不出现（CV-194/195） |
| G-13 | 同上三类节点 | 点「重试」 | **原地换一版**：节点 id / 位置 / 血缘 / 编组全不动，不新增节点。BGM：新音频落在同一张卡上（标题仍「BGM」、时长角标更新为实测值）；四视图：资产卡不新增（仍是同一张卡、冻结描述不变）；抽帧：末帧换成新图，仍指向同一源视频。过程中画布出现 loading 遮罩，失败时错误写回该节点（CV-195） |
| G-14 | BGM 节点 | 在抽屉里改「歌词」→ 点重试 | 新一版音频的歌词就是刚改的那份（参数来自节点自己保存的 `generationPrompt`，不是对话里的临时覆盖）；纯器乐留空时卡片显示「纯器乐」（CV-194/195） |
| G-15 | 四视图节点 | 手工删掉它的资产卡（或换成别的锚点）→ 点重试 | 明确报错「资产卡已不存在…无法重试」，**不会**悄悄新建第二张卡（CV-195） |

## 八、H 组：Agent 工作流 / HITL（造数据用，也是回归用例）

| 编号 | 前置 | 步骤 | 正常表现 |
| --- | --- | --- | --- |
| H-1 | 新会话输入一条创意 | 发送首条真人消息 | 画布原点自动出现「创意」节点（toolName=user_brief）；每项目至多一个，重复发消息不重复落（CV-023）；旧项目打开时经历史重放自动补落 |
| H-2 | 有创意节点 | 让 agent 提交分镜表 | 分镜**逐镜拆卡**（「分镜 N · 景别」），每行 3 卡横向排列，血缘指向创意节点并排其右侧；解析失败回退整表单节点（CV-024/025/026） |
| H-2b | H-2 的分镜已提交 | 点「驳回，继续修改」写点意见 → agent 重新提交（**连做两轮**） | 画布上**仍是每镜一张卡**（打回两次不会变成三套同名卡）；同镜号的卡 **id 与位置原地不动**、只有文案/时长更新；新镜号新建卡且不压在旧卡上；被删掉的旧镜号卡**保留**（不静默删，避免下游断链），工具结果里会写明「新建 N 张 / 复用 M 张」（CV-050） |
| H-3 | 分镜卡存在 | 让 agent 生成关键帧/视频，指定所属分镜 | 新节点连到分镜卡与素材来源，落位在来源右侧一列（重叠自动避让）；即使模型漏传 shotRefs，视频也继承分镜卡血缘（CV-027/031） |
| H-4 | HITL 逐步确认模式 | 分镜提交后 | 出现批准/驳回 UI；批准走分镜门禁；**已知现状：批准后 agent 不自动苏醒，需手打「继续」**（O1/HITL-B 未实施）——记录表现，不算新缺陷 |
| H-5 | agent 提问（allowFreeText） | 遇到开放性问题（如品牌名） | 点选卡片出现自由输入框 + 提交按钮；答案走同一通道；提交后锁定防重复提交（CV-002） |

## 十一、K 组：内置 ffmpeg（装机即全功能，CV-201）

> **必须在没装过 ffmpeg 的机器上验**（干净机器或新用户账户，`which ffmpeg` 为空）。开发机上装过 brew ffmpeg 的**验不出这条链路** —— 解析链会命中系统 PATH 上的 ffmpeg，现象与「随包生效」无法区分。
> 验前自检一条命令：`ls "/Applications/VideoBuddy.app/Contents/Resources/ffmpeg"` 应列出 `darwin-arm64` / `darwin-x64` 两个目录，且每个目录里有 `ffmpeg` 与 `LICENSE`。
>
> ⚠️ **K 组只证明「功能可用」，不证明「可以对外发」**：随包二进制实测带 `--enable-nonfree`（configure 行含 `--enable-gpl --enable-version3 --enable-nonfree`），触发 FFmpeg 随包 LICENSE 的 *"unredistributable"* 明文 ⇒ **内测 / 自用不受限，对外发布前必须换成 LGPL 构建**（详见 [STATUS.md](./STATUS.md) §7 B2 与 [plans/bundled-ffmpeg.md](./plans/bundled-ffmpeg.md) §8）。因此 K 组通过后状态是**「功能已就绪、发布前需换构建」**，不是「可直接发布」。
>
> 另注：出包命令 `dist:mac-smoke` 自身不设镜像变量，无 VPN 环境下会挂在 GitHub 下载上（单请求 600s 超时）。复跑前先导出 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 与 `ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/`。
> **拿包通道（本地构建跑不动时用这条）**：手工触发 GitHub Actions 的 `CI`（`workflow_dispatch`，分支选 `dev`）—— `desktop-macos` 任务产出 artifact `VideoBuddy-macOS-<sha>`（smoke DMG），`desktop-windows` 任务产出 `VideoBuddy-Windows-<sha>`（`Setup.exe` + `Portable.zip`）。⚠️ 都是**未签名**测试包：DMG 经浏览器下载会带 quarantine，装到 `/Applications` 后需 `xattr -dr com.apple.quarantine /Applications/VideoBuddy.app`（或右键「打开」）才能起。
>
> **转包给别人时的三条铁律**：① **下载 artifact 必须登录 GitHub**（匿名请求实测 401）⇒ **Actions 链接不能当公开下载口**，转发时先把包下到本地再走网盘/共享盘（Windows artifact 解压后是 `VideoBuddy-2.0.4-x64-Setup.exe` + `VideoBuddy-2.0.4-x64-Portable.zip`，单文件过大，微信类 IM 通常发不出去）；② 收包人第一次运行 Windows 包会被 **SmartScreen** 拦（未签名）⇒「更多信息 → 仍要运行」，浏览器下载可能需在下载列表选「保留」；③ **分发范围：仅限内部/自用** —— 包内 ffmpeg 含 `--enable-nonfree`（上游明文 *unredistributable*），而本仓是 public 仓库，**建公开 Release 等于对外分发**，换 LGPL 构建前不要做（见下方 K 组 ⚠️ 与 [STATUS.md](./STATUS.md) §7 B2）。

| 编号 | 前置 | 步骤 | 正常表现 |
| --- | --- | --- | --- |
