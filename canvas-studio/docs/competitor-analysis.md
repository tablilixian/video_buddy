### 1.3 差距清单（草案，合并时正式分配 CV 编号）

> 优先级建议基于：视觉感知度 × 实现成本 × 架构适配性。

#### DA-1 卡片动态预览（建议 P1，本轮核心）

- **差距**：竞品每张卡头图是动的（GIF/视频演示），我们是静态渐变 + 图标，观感差距最大的一项。
- **关键发现：素材已就绪** —— `assets/style-demos/` 已有 **8 个风格 GIF 且与 skill 目录同名一一对应**
  （3d-animation-short-generator.gif / brand-promo-video-generator.gif / co-op-game-intro-generator.gif /
  handdrawn-live-video-generator.gif / minimalist-product-ad-generator.gif / music-video-subtitle-generator.gif /
  paper-collage-explainer-generator.gif / papercraft-stop-motion-explainer.gif），10 个 skill 中 8 个可立即动起来。
- **方案**：① catalog entry 增 `demo?: string`（GIF 相对路径，sync 脚本/打包链路确认 assets 进 bundle）；② 卡片头图 hover 或常驻 `<img src=gif>`（GIF 自带动，无需 JS 播放器）；③ 性能：广场打开时全部加载 8 个 GIF 可能占带宽，建议 **hover 才注入 src**（懒激活）或 IntersectionObserver 进视口才加载；④ 无 GIF 的 skill（h3-prompt-writing、effect-test-runner 等）回退现有静态渐变。
- **适配性**：✅ 纯展示层，不碰数据链路。bundle 里 assets/** 已在 package.json files 中。

#### DA-2 悬停操作浮层 + 查看详情（建议 P2）

- **差距**：竞品 hover 头图浮现「查看详情 / 下载 Skill」双按钮；我们只有常驻「使用」。
- **方案**：① hover 浮层双按钮：「使用」（语义保留我们的激活）+「查看详情」；② 详情浮层 = 二级弹窗（标题 + 完整说明 + 分类/作者元信息 + 使用按钮），内容取 catalog entry（必要时补 `detail` 字段放长文案）；③ 纯 CSS hover（`.csSkillCard:hover .csSkillHover`）+ `prefers-reduced-motion` 降级常驻。
- **适配性**：✅ 纯前端。详情数据源浅（catalog），无 Host 改动。

#### DA-3 搜索框（建议 P1，高性价比）

- **差距**：竞品右上搜索框；skill 一多（竞品 50+）搜索是刚需，我们当前 10 个尚可但应先占位。
- **方案**：广场 header 加输入框，纯前端 `title/summary` 子串过滤（大小写不敏感），与分类筛选叠加（分类内再搜）；清空恢复。零新依赖。
- **适配性**：✅ 纯前端。

#### DA-4 「我的 Skill」视角（建议 P2）

- **差距**：竞品双 Tab 分「发现 / 我的」；我们激活后的管理只有 work 态 chips 行，广场里看不到哪些已激活。
- **方案**：广场内加「我的 Skill」视图（顶部 Tab 或侧栏顶部项）：列出 `activeSkills` 已激活条目（数据链路 CV-066 现成：`project-store.activeSkills` + `deactivateSkill`），支持在此卸载；未激活任何 skill 时空态引导。
- **适配性**：✅ 复用 CV-066 现成链路，无新 Host 改动。

#### DA-5 「官方精选」分区（建议 P2）

- **差距**：竞品分「官方精选大卡区 + 其他列表区」两级；我们平铺。
- **方案**：消费 catalog 已有的 `featured` 字段：网格顶部「精选」行（大卡或置顶）+ 其余常规网格；或按「官方（skills/ 内置）/ 社区（远期）」分区预留。
- **适配性**：✅ 字段已存在，纯渲染层分组。

#### DA-6 下载量 / 作者署名（**暂缓**，2026-09-02 用户拍板先不处理）

- **差距**：竞品每卡有作者 + 认证标 + 下载量，社交证明感强。
- **方案**：catalog entry 增 `author`（全部「Canvas Studio 官方」+ 认证 ✓）与 `installs`（假数）；**遵守 reserved 原则**：假数据仅作视觉演示需在 title/文案标注占位，或干脆只上「官方 ✓」不上假下载量（更诚实，推荐讨论）。
- **适配性**：⚠️ 假下载数据有「伪造热度」嫌疑，与项目「不伪造已生效」原则有张力 —— 合并时需拍板：只上作者署名（真实）vs 连下载量一起假。

#### DA-7 H3 能力角标（建议 P3，真实信息）

- **差距**：竞品卡左上角「H3」badge；我们 10 个 skill 中 8 个 H3 风格类 + h3-prompt-writing 实际都基于 H3 能力，这是**真实且有意义**的标记（对齐竞品命名）。
- **方案**：catalog entry 增 `h3?: boolean`，卡片左上角小 badge「H3」；纯展示。
- **适配性**：✅ 真实信息非伪造，成本低。

#### DA-8 「仅显示未激活」过滤 + 排序（建议 P3）

- **差距**：竞品「其他Skill」区有「仅显示未安装」单选 + 「排序：最近」下拉。
- **方案**：skill 数量小（10 个），优先级低；激活状态过滤复用 `activeSkills`，排序（按名称/分类）纯前端。可与 DA-4 我的 Skill 视图合并设计。
- **适配性**：✅ 纯前端。

#### DA-9 创作者社区 CTA 卡（建议 P3，reserved 展示）

- **差距**：竞品网格末尾虚线框「加入创作者社区」投稿激励卡，收尾呼应。
- **方案**：网格末尾加虚线框 CTA 卡（纯展示 + 「待接入」角标，文案对齐我们的 skill 扩展规范 docs/skill-expansion-spec.md：「按目录规范投放技能（规划中）」）。
- **适配性**：✅ 纯展示；与「新建技能（待接入）」按钮语义呼应。

### 1.4 布局差异（记录，不立条目）

- 竞品分类是**顶部横排 chips**，我们是**左侧竖栏**：竖栏可容纳更多类目 + 计数，且与现有全屏覆盖层结构一致，**保留现布局不改**。

### 2.3 差距清单（草案）

#### DA-10 生成产物自动编组（用户点 1，建议 P1，中大改动）

- **差距**：竞品按段编组（组标题栏 + 折叠 + 组内添加），我们生成物全平铺在画布，素材归类靠手动。
- **方案**：① Host 落盘自动建组——优先按**分镜卡聚合**（`shotRefs` 相同的关键帧 + 视频进「分镜 N · 素材」组），无 shotRefs 的按类型归组（关键帧组/视频组）兜底；② 组节点复用 `kind=group` + children `parentId`，组标题自动命名；③ 组内新产物落盘时自动并入既有组（防重复建组）。
- **前置依赖**：**CV-008 必须先修**（group 拖动带动 children，否则编组反而碍事）；组折叠能力（隐藏 children）需评估 group 渲染现状后决定是否并入。
- **适配性**：⚠️ Host 落盘 + 契约分组规则 + 组行为修复，建议单独批次设计（编组规则要和 CV-024 落点策略、CV-050 分镜复用协同）。

#### DA-11 节点/图层命名精准化（用户点 2，建议 P1，低成本高感知）

- **差距**：生成节点图层名是泛化标签（「图片」「视频」），同名不可区分；竞品显示真实文件名/序号。
- **方案**：落盘命名 helper（纯函数可单测）统一规则——① 关键帧/视频：`分镜 N · 关键帧` / `分镜 N · 视频`（shotRefs 解析可得镜号），无镜号取 prompt 前 12 字；② `upload_image`：原文件名（去扩展名）；③ 抽帧/风格归纳已有名，保持；④ compose 已有名，保持。LayerPanel 与节点标题天然同源（读同一 title）。
- **适配性**：✅ Host 侧纯函数 + 各工具落盘处调用，无契约变更。

#### DA-12 文本节点选中可滚动（用户点 3，建议 P2，小改）

- **差距**：`.csNodeBody` overflow:hidden，长文截断。
- **方案**：文本类节点选中态（或编辑态）`overflow-y:auto`；**侦察点**：滚轮事件不能冒泡到 CanvasSurface 触发画布缩放——需在节点内 wheel 处 stopPropagation 或缩放判定豁免节点内滚动。
- **适配性**：✅ 纯 CSS + 一处 wheel 豁免。

#### DA-13 视频 hover 自动播放（用户点 4，建议 P2）

- **方案**：hover 视频节点 `muted + loop + play()`，离开 `pause()` + `currentTime=0`；约束：同一时刻只允许一个 hover 播放、loading/失败态不播、`prefers-reduced-motion` 降级不自动播；双击仍开播放浮层（CV-044 语义不变）。
- **适配性**：✅ 纯前端（CanvasNode 生命周期管理，注意 hover 快速扫过多个视频时的 play/pause 抖动——加 150ms 延迟启动）。

#### DA-14 视频节点内联信息增强（截图发现，建议 P2，与 DA-13 合并设计）

- **差距**：竞品视频节点有时长角标（`0:16`）+ 内联完整控件；我们缩略图零信息。
- **方案**：① **时长角标**（推荐）：`loadedmetadata` 捕获 duration 落盘（复用 CV-013 分辨率回填同款链路），节点左下角 `m:ss`；② 内联完整控件**不做**——与 CV-044 结论冲突（原生 controls 被禁、画布节点尺寸小自绘控件拥挤），完整播放仍走浮层（CV-057 自绘控制条已覆盖）；③ 下载角标不做（右键 + 详情面板已有下载，避免入口重复）。
- **适配性**：✅ 时长角标低成本；内联控件明确排除。

#### DA-15 制作计划阶段清单（截图发现，建议 P2 但中大改动，单独排期）

- **差距**：竞品右栏「制作计划 3/3」步骤清单（勾选 + 点击定位节点 + 收起），执行进度可视；我们的执行进度是黑盒（只有 mode + 审批条 + loading 耗时）。

### 3.3 差距清单（草案）

#### DA-17 项目分组管理（建议 P3，项目多时价值才显现）

- **差距**：竞品项目按可折叠分组归类（「项目」「未分组」）；我们平铺。
- **方案**：① `projects.ts` entry 增 `group?: string`（缺省「未分组」）；② ProjectList 按 group 分组渲染 + 折叠头（折叠态可存 localStorage，不进注册表）；③ 新建表单可选分组名；④ 归组交互第一版用详情/右键「移动到分组」，拖拽归组后置。
- **适配性**：✅ 契约加可选字段向后兼容；但当前项目数少（个位数），**建议缓做**——等项目批量增多的真实痛点出现再上。

#### DA-18 项目封面缩略图（建议 P2）

- **差距**：竞品项目库卡有封面缩略图 + 日期，扫视识别效率高；我们纯文字行。
- **方案**：① 落盘侧：generate/compose 落产物时把最近媒体节点 url 写进注册表 entry（`coverUrl?`，增量更新）；② 打开项目时若 entry 无 cover，客户端从 canvas.json 找首个媒体节点补写一次；③ ProjectList 行（或卡片化）渲染缩略图 + 名称 + 日期；④ 无产物的项目回退首字母块（与 CV-069 头像同款）。
- **适配性**：✅ 注册表加可选字段 + 客户端补写，无 breaking；⚠️ 注意 canvas.json 加载时机（列表页打开时不该为拿封面全量加载所有画布——增量写注册表是关键，避免列表变慢）。

#### DA-19 Lobby 个性化问候（建议 P3，小改，依赖 CV-069）

- **差距**：竞品右栏「你好，{用户名} + 副标题」；我们 LobbyHero 是固定品牌文案。
- **方案**：LobbyHero 增问候语区：`你好，{persona.name}`（复用 CV-069 假 persona 常量）+ 副标题取 LOBBY_COPY；纯展示。
- **适配性**：✅ 小改；建议与 CV-069 同批实现（persona 常量同源）。
