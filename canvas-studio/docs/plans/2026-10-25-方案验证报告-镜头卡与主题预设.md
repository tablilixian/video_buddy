# 方案验证报告：在测试 Electron 上实测镜头卡与主题预设（2026-10-25）

> 验证对象：`plans/2026-10-25-shotcraft吸收方案.md` 的 **S1（卡片化）** 与 **S2（主题预设）** 是否可行。
> 验证方式：**不是纸面判断**——把 14 张卡写成真 manifest，在 `scripts/render-forensics` 的 Electron 渲染器里逐张渲出，
> 再抓帧做像素统计。跑在 Electron 43.4.0 / Chrome 150 / 本机 Intel x64。
> 一句话结论：**两条都可行；同时抓出 3 个真问题（含 2 个字段级 bug）。**

---

## 一、怎么验的（三层判定）

| 层 | 判据 | 手段 |
|---|---|---|
| **L1 结构合法** | 每张卡都过 `validateManifest` | 直接调校验器（0 成本） |
| **L2 真能渲出** | 测试 Electron 上成功产出 mp4 | 取证台 `--only=Q12,Q13` |
| **L3 真的在动** | **非黑像素 > 50%** 且 **相邻采样帧 MAE ≥ 0.5** | `entry.tsx` 在 6 个时间点（2%/15%/35%/55%/75%/96%）抓帧压到 64×36 灰度后统计 |

### 指标迭代过一次（值得记）

第一轮只统计"亮度均值"，结果 `orbit-badge`（公转）、`ken-burns`（推拉）、`chart-bars` 全被判"没动"（Δ=0.0）。
但它们改的是**位置/取景/形状**，平均亮度本来就不变 —— **均值不是"在动"的指标**。
换成 **MAE（相邻采样帧的平均绝对差）** 后，公转立刻显示 MAE=4.2。

> 教训：验收指标本身也要被验证。用错指标会把"对的实现"判成错的。

## 三、三个真问题（这次验证最大的收获）

### ① `kenBurns: true` 是**死字段**（类型里有、实现从不读）

- 实现判的是 `fit === 'kenburns'`（`ImageClip.tsx:13`），而 manifest 类型里同时存在
  `fit?: 'cover'|'contain'|'kenburns'` 和 `kenBurns?: boolean`。
- 后果：写 `kenBurns: true` **不报错、校验通过、渲染成功，但画面完全静止**（实测 MAE=0.0）。
- 这是第三例"字段撒谎"（前两例：报告里的 `warm`、`inspect_image` 的"唯一真值来源"）。
- 修法（建议）：**删掉 `kenBurns` 字段**（或让它成为 `fit:'kenburns'` 的别名并写进契约）。

### ② `animate` 不支持 `scaleX` / `scaleY`

- 我在 `chart-bars` 里写 `animate.from.scaleY`，全仓 `grep` 零命中 ⇒ 不生效（MAE=0.0），但**不报错**。
- 正确写法只有等比 `scale`（或改 `y` 位移）。
- 这条其实已经在契约里写过（"`shapeTransform` 只有 scale/rotate"），但**没写 `animate` 也不支持**
  —— 所以我自己都写错了。**需要补进契约**。

### ③ `ink-press` 主题太暗（设计问题，非 bug）

- 首帧亮度 5.2、整片非黑比例仅 37%（warm 版是 100%）。
- 根因：`backgroundColor #06080B` + `look.brightness 0.96` + `vignette 0.38` 三重压暗叠在一起。
- 建议：主题预设里 `brightness` 与 `vignette` 要有"互斥约束"（vignette>0.3 时 brightness 不许 <1.0）。

## 四、成本：卡片本身很便宜，贵的是冷启动

| 场景 | 14 张卡合计 | 平均 |
|---|---|---|
| 首轮（半冷窗口） | 266.8s | **16.7s/张** |
| 同窗口后续（热态） | **19.9s** | **1.4s/张** |

⇒ 90 帧 draft 的**真实渲染成本约 1.4s**；16.7s 里绝大部分是窗口冷启与预热
（与 Q1 的结论一致：第 1 次 3146ms → 后续 1698–2324ms，`raf` 从 2Hz 升到 61Hz）。

**对方案的含义**：卡片化不会让渲染变慢（每张卡只是 manifest 里多几条轨）。
12 张卡的验证总成本 ≈ 20 秒（热态），完全可以做成**提交前自检**。

## 六、复现命令

```bash
cd canvas-studio
RF_NO_SANDBOX=1 NODE_OPTIONS= node scripts/render-forensics/run.mjs --only=Q12,Q13
# 产物：scripts/render-forensics/out/<ts>/{report.json,REPORT.md,mp4/card-*.mp4}
```

判定口径（写进 report 的 `samples[]`）：

- `nonBlack`：灰度 > 8 的像素占比（< 50% 视为黑屏/几乎无内容）
- `mae`：与上一采样帧的平均绝对差（**< 0.5 视为静止**）
- 6 个采样点：2% / 15% / 35% / 55% / 75% / 96%（含首尾，才能抓到"入场"和"退场"）

## 七、结论

1. **卡片形态成立**：14 张常用镜头全部能用现有 manifest 字段写出来、渲出来、动起来。
   → **S1 可以直接开工**，不需要先补能力。
2. **主题预设成立**：换主题能改观感且不动内容轨 → S2 按 `meta.themeId` 做。
3. **顺手修掉 3 个真问题**（1 个死字段、1 个不生效属性、1 个设计缺陷）——这类问题
   **只有在真渲一遍才会暴露**，纸面走查发现不了。
4. 代价极低：热态 1.4s/张。建议把 `--only=Q12` 挂进"卡片改动后的自检"流程。
