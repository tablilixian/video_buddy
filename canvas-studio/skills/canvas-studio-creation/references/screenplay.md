# 剧本创作完整规则（工作流第 2b 步必读）

> 两种形态都必经；单镜精品短片为轻量版。
>
> **REQ-022 起落点变了**：剧本不再落成画布「剧本」节点（`write_screenplay` 已下线），
> 而是写进**拍摄定稿** `storyboard.json` 的对应分节 —— 创意前提与季节/地域前提进
> **§00**、逐句旁白进 **§03**（只写一次，分镜按句号引用）、角色设定进 **§05**
> （人读 `profile` 与机读 `gen` 分离）。本文其余规则（节拍链、情感锚点、时长分配、
> 一致性纪律）全部照旧适用，只是产出目标从节点换成 JSON 分节。
> 落盘统一走 `write_storyboard`。

剧本是创作依据：有了完整剧本，镜头内容、对白与时长分配才具体可靠。规则：

0. **单镜轻量版**：单镜精品短片同样走 `write_storyboard`，内容为**单镜故事板**（一条 shot）（半屏篇幅即可）：一段画面描述（主体/环境/光线/氛围）+ 主体动作时序（0–3s / 3–8s / 8–15s 三段）+ 文案/口播落点 + 声音设计（BGM/SFX）。单镜剧本不写节拍链与受众标注，总时长即单镜时长（≤15s）。

1. **时机**：需求澄清完成后 → **先确定视觉风格并加载对应风格 skill → 再写剧本**（风格决定剧本形态：广告类是镜头序列 + 卖点落点，叙事类是主角动机 + 节拍链 + 情感锚点）。
2. **必须执行**：无论风格 skill 加载成功与否，都要把叙事内容写进拍摄定稿（`write_storyboard` 的 §00/§03/§05）。skill 加载失败时按通用骨架兜底（开场铺垫 → 冲突/卖点展开 → 高潮/转化 → 收尾），不要因为加载失败跳过剧本。
3. **唯一落点**：上游风格 skill 里的「故事大纲 / story-outline / 叙事主轴」步骤就是拍摄定稿的 §00 创意前提 + §03 旁白——**写进 storyboard.json，禁止另建大纲节点**；上游大纲步骤自带的审批选项（批准 / 改节拍 / 改情绪曲线 / 回到前提）即用户意图，收到反馈时按对应维度改 `write_storyboard` 的对应分节后重新落地（**分节合并**：只传要改的节即可，没传的保留）。
4. **内容对齐预置**：结构节拍各自标注时长占比，**之和 ≈ 目标总时长**（项目预置值见系统提示「Canvas Studio 项目预置」小节，无预置按 30s 并标注「默认」）；分镜（视频条数）由叙事节拍决定、不按时长反推——后续每个分镜内部再按文戏 ≈2.5s / 武戏 ≈1.3s 一个 shot 细分节拍（R-P0-11），shot 只进分镜 prompt、不增加视频条数；受众在剧本 summary 里标注（澄清未问时自定并标「默认」）。
5. **落地门禁**：逐步确认模式下，`write_storyboard` 写完后**停下等用户**在画布顶条「拍摄定稿」覆盖层里点「确认落地」（不要调用任何把工作流设为执行态的手段 —— 门禁由 Host 管理）；用户有意见则改对应分节后重新 `write_storyboard`（分节合并：只传要改的节；整体重写九节全传，旧内容自动存版）。
6. 放手跑模式：`write_storyboard` 成功后由 Host 编排自动校验并落地（有缺项会报错停下，不猜测补数据）。
