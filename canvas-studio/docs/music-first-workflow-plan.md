## 0. 一句话方案

**有配乐需求的片子，把 BGM 从「第 10 步才贴上去」提前到「分镜之前先锁定」**——先生成一条与目标成片等长的主音频（Master Audio），再按它的拍格拆镜、对齐切点，最后用同一条主音频混音。

素材全部现成（项目里已接入的 `music-video-subtitle-generator` 就是这套规范），本次是把规范接进总纲主流程 + 少量代码配套。

## 1. 两个待确认问题的解释（卡在后端，决定 Phase 2 做不做）

### 问题 A：`filenames` 能否收 mp3？（决定「跨镜音乐连续」能不能落地）

**背景**：H3 的 `format-ref2va.md` 定义了一等公民 `<Audio N>` 参考和两种任务类型：
- `audio reference` —— 只引用音乐的**风格 / 音色 / 节拍 / 连续性**，不复制音轨；
- `audio reuse` —— 部分复制音轨。

这给我们一个官方解法：**把主音频作为 `<Audio 1>` 传给每一镜**，模型生成时就会让各镜跟随同一节拍，而不是各镜各跳各的。

**卡点**：我们的 `video_composite` 最终把 `filenames` 数组原样传给 Drama 的 `image2videoref2va`。要落地 `<Audio N>` 需要三件事：

| # | 事项 | 现状 |
|---|---|---|
| 1 | mp3 得有 Drama filename | ✅ 已具备——`generateMusic` 返回的 `filename` 就是 Drama 侧 mp3 名（不需要再走 upload_image） |
| 2 | 后端参考数组里能否混入 mp3 | ❓ **要问后台**——现有文档只描述图片参考，音频作参考是否被接受未知 |
| 3 | 预检 pictures 计数要排除音频项 | ⚠️ 我方改动——`assertH3IrPrompt` 现在用 `filenames.length` 当 pictures 数（`host-tools.ts:943-944`），混入 mp3 会把 2 图误判成 3 图从而按 Ref2VA 校验 |

**给后台的提问**：
> `image2videoref2va / image2videofl2va` 的参考素材数组（`filenames`）里，能否混入一个 mp3 的文件名作为音频参考？即 H3 Context-IR 里的 `<Audio N>` + 任务类型 `audio reference`。如果可以，音频项是否计入参考图数量上限（Drama 6 张）？

### 问题 B：后端是否计划接 `generateAudio`？（决定要不要禁止各镜自带音轨）

**背景**：`generateAudio` 是**视频生成时顺便生成原生音轨**（环境音 / 音效 / 可能含音乐）的开关。目前项目里是**占坑参数**——传 `true` 只返回一句提示，请求体根本不带这个字段（`generate.ts:930-937`）。

**为什么这问题重要**：这是把双刃剑。

| 若后端启用 | 影响 |
|---|---|
| 好处 | 单镜有环境音/音效，画面节奏更真实（长视频观感提升明显） |
| 坏处 | 各镜自带音轨拼接会互相打架——这正是 `music-video-subtitle-generator` L164 明令禁止的「Do not use independent disconnected clip audio」 |

所以一旦后端接了 `generateAudio`，音乐先行方案必须**额外规定**：音乐驱动型片子**关闭各镜原生音轨**，只用一条主音频。这个规定得写进总纲，否则方案会被原生音轨污染。

**给后台的提问**：
> 视频生成是否计划启用 `generateAudio`（原生音轨）？若启用，是否提供逐次调用关闭的手段（音乐驱动场景需要关掉单镜音轨，只用一条主音频）？

## 2. 现状 vs 目标

| 环节 | 现状（视频先行） | 目标（音乐先行） |
|---|---|---|
| BGM 时机 | 第 10 步成片时才贴 | **分镜之前**（第 2c 步）锁定主音频 |
| BGM 长度 | 默认 30s，与成片无关 | `duration = 目标成片时长` |
| 分镜粒度 | 每镜 7–10s，按内容拆 | 音乐驱动型 **2–5s**，按拍格拆（MV skill L63） |
| 切点依据 | 内容连贯性 | **1/4 或 1/8 拍格** / 歌词停顿 / 军鼓 / drop（L174） |
| 转场 | concat `-c copy` 硬切 | 保持硬切（L191 明确禁止溶解） |
| 音轨 | 各镜无音轨，后期贴一条 | 整片绑一条主音频（L164） |
| 音乐短于成片 | 后段静音（`amix=duration=first` + `-shortest`） | 不拉伸（L76）；循环仅作兜底并提示 |

## 3. 触发条件（不是所有片子都音乐先行）

避免一刀切拉高成本——短镜意味着更多镜头、更多生成调用。

| 判定 | 走哪条路 |
|---|---|
| 风格/形态 = MV 字幕、品牌宣传、音乐视频、强节奏广告 | **音乐先行**（强制） |
| 用户明确说「按音乐剪」「踩点」「有 BGM」 | **音乐先行** |
| 讲解科普、街采、剧情向（配乐只是背景） | 视频先行（现状，第 10 步贴 BGM），分镜维持 7–10s |
| `music_generation` 不可用（端点 404 / 无 BGM 需求） | 自动退回视频先行，并在需求摘要里说明 |

## 4. 工作流改动（总纲 `SKILL.md` + 分册，diff 级）

### 4.1 新增第 2c 步（剧本之后、分镜之前）

```
2c. **主音频锁定（音乐先行模式必经）**：判定为音乐驱动（见 workflow-music.md）时——
    ① music_generation 生成主音频，duration = 目标成片总时长（纯 BGM 传 language="unknown"），
       prompt 按 Music3 三段式写（Global Metadata / Vocal Details / Arrangement，见 music-caption.md）；
    ② 记录 bpm / keyscale / timesignature / 实际时长，写进分镜表头；
    ③ 端点不可用时退回视频先行（第 10 步贴 BGM），并在需求摘要说明。
```

### 4.2 第 3 步分镜规划增加「按拍拆」规则

- 音乐先行模式：单镜 **2–5s**，镜头数 = `总时长 ÷ 3–5s`（不再是 `÷ 8–10s`）；
- 切点标注拍格位置（如「0:07.5 = 第 4 小节第 3 拍，军鼓」），并在分镜表新增「拍点」列；
- 分镜表头记录主音频 bpm/keyscale，供第 9 步写 `non_diegetic_music`。

### 4.3 第 8 步文案：BGM 描述写进 `non_diegetic_music`

保持现状（base-en.txt 4.7 规范：只写乐器 / 速度 / 节奏 / 力度变化，**禁抽象情绪词**）。补充：音乐先行模式下，各镜的 `non_diegetic_music` 必须**与主音频描述一致**（同一条音乐的不同段落），不得各镜编各的。

### 4.4 第 9 步：音频作参考（**待问题 A 确认后启用**）

```
（条件）后端支持 mp3 作参考时：
- video_composite 的 filenames 首项追加主音频 filename，IR 里声明 <Audio 1> +
  任务类型 audio reference（引用其节拍/连续性，不复制音轨）；
- 预检会把音频项排除在 pictures 计数外（代码配套 P2）。
```

### 4.5 第 10 步成片

- `compose_video` 传 `bgmNodeId = 主音频节点 id`（现状已有该参数，无需改）；
- 明确纪律：**音乐短于成片时不拉伸**（L76）；循环兜底仅在两者都已确定且不匹配时启用，并在结果里提示用户。

### 4.6 新增分册

`references/audio-first.md`（约 2–3KB），收录：
- 触发条件判定表（第 3 节）；
- 音乐先行模式的分镜按拍规则（4.2）；
- Music3 caption 三段式精简版（从 T8 `music3-official` 转写，适配 ACE Step tags）；
- 「不拉伸 / 循环仅兜底」纪律；
- 硬切禁止溶解（L191）。

## 6. 风险与对冲

| 风险 | 说明 | 对冲 |
|---|---|---|
| 短镜推高成本 | 2–5s 镜意味着 30s 成片从 3–4 镜变 6–10 镜 | 触发条件严格限定音乐驱动型；讲解/剧情类维持 7–10s |
| 主音频不好听 | 一次生成成功率非 100% | 允许重生成 1–2 次（节点覆盖），选定后再分镜 |
| 音乐先行把流程变重 | 多一步 + 分镜规则更复杂 | 非音乐驱动型完全不走这条路，现状零影响 |
| 端点 404 期间 agent 卡住 | 调 music_generation 会失败 | 总纲写明「失败即退回视频先行 + 说明」，不阻塞 |
| 循环兜底违背官方「不拉伸」 | 官方是「音乐定长、视频对齐音乐」 | 循环≠拉伸（音乐本身可循环）；且仅兜底，主路径仍是生成等长 |

## 7. 验收方法（桌面）

跑一条 MV 字幕 / 品牌宣传片，观察：
1. agent 是否在**分镜之前**先调 `music_generation`，且 `duration` 等于目标成片时长；
2. 分镜表是否出现 2–5s 短镜 + 拍点列（对比现状 7–10s 无拍点）；
3. 成片是否只有一条 BGM 贯穿、无各镜独立音轨、无溶解转场；
4. 成片结尾是否有音乐（不出现后段静音）。
