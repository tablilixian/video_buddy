## 一、问题与动机

**R-P1-03 原文**：画布上的提示词按使用者语言呈现为优先，且为比较自然的描述；实际生成时按用户或系统要求使用 Krea2、qwen-image、或 H3、Seeddance2.0/2.5 规范翻译后提交后台。

**C-12 症状**：删掉提示词里的中文，仍旧走 qwen image 生图而不是 Krea2——期望「重新判断」。

两件事同根：**「用什么模型」的判断和「提示词长什么样」的呈现都缺一个统一决策点**。

## 二、现状盘点（代码级事实）

1. **路由现状 = 散文判据，散落各工具 description 与 skill**。今天的「选工具判据」是
   `host-tools.ts` 里各工具 description 的一段话（如 withtxt 工具：「画面里有要读的文字 →
   本工具；普通无字画面 → image_generate（Krea2）……」）。模型选哪个工具全靠读这些散文
   + 自由裁量。C-12 的机制就在这里：散文判据**不可重算**——agent 在某一轮依据「提示词含
   中文」选了 qwen，用户删掉中文后 agent 不会回头重读判据，路由不会自己改道。
2. **呈现现状：用户看到并编辑的就是提交给模型的规范串**。节点 `generationPrompt` 是
   `generationPromptOf(params)` 序列化的 JSON（`generate.ts:1260`，重试原样重放的契约）；
   就地编辑浮层（NodePromptEditor）与详情抽屉直接读写它的 `prompt` 字段
   （`node-params.ts` 的 `promptFieldsOf/promptValueOf`）。Agent / skill 翻译出的英文或
   规范化文本直接顶在前台，用户改自己的意图反而要改「模型的参数」。
3. **工具包装层已是唯一入口**：`wrapStudioToolDefinition`（`tool-error-boundary.ts`）包装
   全部宿主工具；`param-guard.ts` 的占位值守卫在 `execute` 前零副作用拦截，参数分类表
   「先登记后使用」（`tests/param-guard.test.mjs` 遍历全部工具参数名，未登记即红）。

## 三、方案

### A. 统一决策点：`src/model-route.ts`（新，Host 侧纯函数）

```ts
export interface ModelRouteRequest {
  tool: string                       // 发起工具（image_generate / image_fix / …）
  prompt: string                     // 规范化后的提交文本
  hasReferences: boolean             // 是否带参考图入参
  setting?: string                   // 设置页显式指定（优先级最高）
}
export interface ModelRoute {
  endpoint: string                   // Drama 端点（txt2image / txt2image_withtxt / …）
  reason: 'explicit-setting' | 'text-render' | 'default-t2i' | …   // 理由码（报错与日志可读）
}
export function routeImageModel(request: ModelRouteRequest): ModelRoute
```

**落点选层论证（action-plan 点名要回答的问题）**：决策放**工具包装层、execute 之前的参数
规范化段**——与占位守卫同一入口（`wrapStudioToolDefinition`），同一「唯一实现」纪律：

- 不落 skill 层：散文不可测、不可重算（C-12 的根因本身）；
- 不落各工具 execute：四条 image 链路各写一份就是「同一规则第二份实现」（CS-UNC-000 教训）；
- 落包装层：零副作用、可单测、**每次 tool call 现算**——删中文后下一次提交自然改道，C-12 直接收口；
- 工具 description 随之瘦身为「描述能力与边界」，判据摘要由路由表生成（一处事实，两处消费：
  执行时用 endpoint，模型可读文本用摘要），不再各自为政。

### B. 路由表留槽（Krea2 vs qwen = 表里的一行默认值）


- `t2iDefault` 先落现状（Krea2），拍板改一行即全局生效；设置页可加「默认生图模型」覆盖
  （`setting` 优先级最高，reason='explicit-setting'）。
- **video 侧刻意只留槽不收编**：H3 提示词规范已随 h3-prompt-writing skill 成型（R-P1-02
  附件解读确认了 IR 分段口径），Phase 3 才动，避免一次改两个域。

### C. 语言呈现数据流（「按使用者语言呈现」）

1. **节点新增 `promptDisplay?: string`**（contracts/canvas.ts，使用者语言的自然描述）：
   落卡时由 Host 从工具入参的 prompt **原文**带入（agent 收到用户中文时写的是什么就存什么）；
   不随生成结果改写（A-1 血缘改写只动 `generationPrompt`，互不干扰）。
2. **呈现优先级：`promptDisplay ?? generationPrompt 的 prompt 字段`**。就地编辑浮层与详情
   抽屉编辑 `promptDisplay` = 编辑**意图**；`generationPrompt` 保持机器规范串，重试/重放
   契约零变化。
3. **翻译时机 = 提交时**：工具包装层规范化段把 `promptDisplay`（若编辑过）交给对应翻译
   规范（Krea2 正向提示词约束 / qwen withtxt 逐字纪律 / H3 IR 分段）产出提交文本，再进
   路由函数。翻译**失败回落**：原样提交并附 reason 码记录（不阻塞生成）——待拍板：
   回落 vs 报错重试。
4. **旧节点兼容**：无 `promptDisplay` 的历史节点回落显示 `generationPrompt`（与今日一致，
   渐进迁移，不回填历史数据——铁律 §七.1）。

## 六、风险

- 路由函数改判**不改变任何工具名与入参契约**——agent 侧零感知，只换背后 endpoint；
- description 判据摘要是生成文本，需在 CI 断言「路由表与摘要同源」（防两处漂移，同一
  守卫手法已有先例：param-guard 的描述与错误文案共用字面量）；
- `promptDisplay` 引入「显示与提交不一致」的新心智——文档与浮层 UI 需标注「这是你的意图，
  生成时自动翻译」。
