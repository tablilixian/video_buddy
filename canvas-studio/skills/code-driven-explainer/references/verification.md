# 验收与交付纪律

> 这份分册管「**怎么验、怎么交**」——判据怎么取证、什么时候出片、交付前必须做什么。
> 契约坑（字段怎么写对）见 `references/pitfalls.md`；结构与卡片形态见 `references/explainer-patterns.md`。
> 证据来自科普 0.1 中文版 + 英文重制版两轮真机会话的验收（2026-11-04）。

## §1 首轮渲染就用 `spotFrames` 探针（P9）

**为什么**：实测单次探针 **1–2s**，全片 draft **24–29s**，而 45s 成片 standard 真机实测算 **282.4s
（≈209ms/帧）**——探针比全片便宜**两个数量级**。事故里 20 次渲染有 10 次是无必要的全片 draft，
前 6 次渲染**全是**全片 draft，第 7 次才首次用上探针。

> ⚠️「24–29s 全片」是内容期的失真基准（曾据此把 200ms/帧当安全值，交付档 4 次撞超时）。
> 现在的判据只看两个数：探针的 `msPerFrame`，和真机同规格成片的实测秒数。

**怎么做**：

- **首轮渲染就用 `spotFrames`**，一次性覆盖**每条判据的代表性帧**
  （字幕卡取首帧 + 末帧、转场取窗口首尾、reveal 取揭示前后、图表取出现帧）。
  服务端会自动并上结构帧（0 / 末帧 / 各轨起止 ±2），总数上限 8——你的自选只需补中段判据。
- **全片 draft 只用于交付前定稿**——用户要看的是成片，不是探针。
- 探针**不落画布节点**（工具语义）：用户在画布上**看不见**探针产物，必须主动交代；
  实测一轮会话静默「探针 → 看图 → 改坐标」循环了约 50 分钟才被用户叫停。
- **探针 ≤3 次、每次 ≤8 帧**：第 4 次必须转**全片 draft 落画布**，再把未决项列成清单随片交付。
  每轮修改后重渲草稿，别攒到「自认为好了」才出片。
- **裁决序**（CV-447 T0-A3）：用户的验收指令 > 本分册纪律，但两者都受**机器闸**约束
  （探针次数 / 帧数上限 / 时间预算）。与纪律冲突时先按用户指令走，把未满足项明写在交付里——
  不许静默跳过，也不许拿「纪律这么写的」挡用户。

## §2 画面类判据**必须看图本身**（P8）

**为什么**：事故里 render #7 采的帧**正好在 callout 窗口内**，也确实调了看图工具，
但看的是 **32×18 的亮度字符网格**，结论写成「地球区域出现了代表地轴的亮条…以及**引线起点**」——
**把别的东西误认成引线**。结论看着有据，其实证据不支持。

**能力前提（2026-11-04 起）**：网关模型行已声明 `input: [text, image]`，
`read_image(file_path=…)` 可直接读项目内抽帧 PNG。这条纪律从此**可执行**，不再是空话。

**怎么算合格**：

- **成片像素**是画面类判据的**唯一**依据。首选 `spotFrames` 出帧 → 逐张
  `read_image(file_path=…)` 直接看图 → 对照判据表逐条打勾；记录里写明帧号与结论。
- `inspect_image` 的 **grid / bbox 模式只用于「定位疑点」和取精确数值**（像素坐标 /
  颜色 / alpha）——它能告诉你「这一带有个亮条」，**不能**作为「引线 / 文字 / 图形
  **存在与否**」的结论依据。
- **`image2vl` 的文字转述不可当事实**：那是后端另一个 VLM 的复述，数字与非 ASCII
  字形抄录实测自相矛盾（同一帧先后报 1.15 / 1.2 / 0.68）；只作辅助参考，不得据此结案。
- **禁止以 manifest 字段自证画面效果**：manifest 里写了 `reveal` / `animate`，
  不等于画面上就有那个效果。事故 A4 正是凭 manifest 字段自证，漏检了整层不可见。
- 若 `read_image` 仍报 `does not declare image input` ⇒ 本次会话路由未声明图像输入；
  **在交付里明写「未做画面自检」**，不得拿亮度网格或 VLM 文字冒充看图。

**取证方式必须在记录里标注**，每条判据归到一类：

| 取证方式 | 用于 |
|---|---|
| `read_image` 看成片像素 | 元素存在 / 位置 / 遮挡 / 排版溢出（**首选**） |
| `inspect_image` 像素统计 | 精确坐标 / 颜色 / alpha / 定位疑点 |
| 音频实测（ffprobe） | 响度 / 静音段 / 音轨构成 |
| 工具调用实录 | 流程是否发生（探针是否发出、负例是否发出） |
| manifest 静态解析 | **只**用于结构性事实（字段、轨道重叠、时长） |
| 数据溯源比对 | 图表值 = 声明值 / 素材出处。**B-4 起契约层有落点**：chart 内联数值带 `dataSource`（数据集 + 入口）与 `baseline`（口径），dataCard 数值型事实带 `dataSource`（自测写 `'observed'`，占位写 `'inline'`）——**单一基准**是 L3 判据，混口径序列必须重做；storyboard 里 `pending` 事实不得进成片（渲染回执会点名） |

## §3 负例：验收阶段的可选测试手段（2026-11-04 纠偏）

**负例不是正常交付流程的一环。** 它的用途是**测试某个校验器 / 闸门是否真的会拦**：改完某项功能后，在**验收批次**里发一条故意违规的提示词，确认拒收回执符合预期。仅此而已。

- **不强制跑**、不要求每次交付都发、不影响结案；「未执行不得结案」的表述已撤销。
- 跑一次时要写清**预期拦截点**（例：anchor 指向不存在的词窗口 ⇒ fail-fast 拒收，提示先补字幕词，不得静默接受悬空锚点），并留下**拒收回执原文**（错误文案 / 拒收位置），不是「发出去了」就算。
- 三件套（提示词原文 + 拦截回执原文 + 探针产物路径）是**验收回填时的可选证据格式**，不是交付必填项。
- 真机回归里若安排负例，统一放在《后续执行计划》§5.3 的 C-4 验收批次。

> 〔2026-11-04 22:57 纠偏〕原「负例必发闸门（P5）」把测试手段误装成流程纪律，曾导致会话 15「读了纪律却不做、也不声明」被误判为缺陷。CV-431 中该条已撤销，探针前置与画面判据取证两条保留。

## §4 自验边界：机器判据归 agent，审美归用户

**机器判据**（有资格也有义务自检）：文字出画 / 轨道重叠（几何计算）/ 数据保真（图表值 = 声明值）/
响度（ffprobe 实测）/ 时长真值（`list_shots`）。
正面例：用响度实测推翻渲染报告的「纯 BGM」误报。

**美学判断**（没资格替用户做）：「好不好看」「风格喜不喜欢」。
看图工具可以查**错误**，不能替用户验收**审美**。

## §5 上下文预算（会话耗时的第一杠杆）

compaction 次数是健康度指标（实测一条片 3 次，每次后都要重读文档、重推状态）。

- references **按需取用**：只读当前链路要用的段落与分册，不要全部通读；
- bash 大输出写文件只回摘要（tail / 统计行），整段输出不进上下文；
- compaction 后只补读缺的部分，信任画布便签与 manifest 现状，**不重新考古**。
