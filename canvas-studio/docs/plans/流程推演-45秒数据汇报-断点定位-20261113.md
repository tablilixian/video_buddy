# 流程推演 · 45 秒数据汇报，断在哪一步

> 目的：把「规范流程」摆出来，拿一条真实需求逐站对照项目里的实现，指出**唯一断点**与它的四个下游后果，再给补法。
> 上游文档：`真机长片表现力差距-对比与优化方案-20261113.md`（现象与量化）、`视觉质量工程方法论-四件套闭环-20261113.md`（§4 已提出「缺屏这一层」，本文是它的**证伪与施工图**）。
> 证据来源：真机会话 `session-30385906`（45s 版 turn 1）+ 该会话产物 `build/manifest.json` / `build/gen_specs.py` / `build/skeleton.json`。

## 0. 一句话结论

流程里有 **36 个工具、15 条 lint 码、10 个模板、4 个配方**，但从「拍摄定稿」到「manifest 轨道」之间**没有「屏（stage）」这个对象** —— 于是模型拿到的是一个 45 秒的空轨道数组，它只能自己发明一套「一句旁白 = 一个整屏元素」的私编排器（`gen_specs.py`，29KB，102 次 bash），最终 45 秒里 **23 秒整屏只有 1 个元素**。

## 2. 例子：为什么用这条需求

用户原话（会话首条，一字未改）：

> `/Users/.../all-time.html` 这是我做的全量运营数据报告网页，帮我把它讲一遍，做成 45 秒的视频。要女声解说，感觉像运营员工给老板汇报。

选它的四个理由：

1. **时长正好卡在断层上**：45s 比任何模板（2.5–48s，多数 3–10s）都长，比配方（4 段：11s/段）都碎。
2. **必须多元素同屏**：指标 + 趋势 + 结论天然要同时在场，撞在「一屏一个点」教条上。
3. **有完整真机轨迹可逐条对账**（223 次工具调用，含 1 次 `list_templates`、1 次 `scaffold_manifest`）。
4. **不是长片特例**：304s 版是同一需求放大 6.7 倍，两版症状同源（见 §6）。

### 2.3 第 6 站实际拿到的东西

`scaffold_manifest({title:"全量运营数据报告 · 45 秒汇报", durationSeconds:45, theme:"cold-tech"})` 返回：


这就是项目能给出的全部「版面基座」：**一条铺满的渐变 + 一张标题卡 + 一张落版卡**。第 4 秒之后，画面里有什么、放在哪、跟谁共存，全靠模型自己决定。

### 2.4 模型自己补的第 4 站

模型没能力凭空补「屏」，于是补了一个**私编排器**：`build/gen_specs.py`（29KB）。它的数据模型是致命的：

```python
# 7 个硬编码盒常量 —— 版面 = 7 个常数
CHART_L   = {"x": 30, "y": 58, "w": 54, "h": 40}   # 图表贴左
CHART_C   = {"x": 50, "y": 58, "w": 88, "h": 40}
CARD_R    = {"x": 78, "y": 54, "w": 36, "h": 32}

# 每幕一个 vis 列表，第二个字段是**旁白句序号**，不是时间段
vis4 = [
  txt("a4-sec", 1, 102, ...),     # 第 1 句
  card("a4-ch", 2, 198, ...),     # 第 2 句 —— 换掉整屏
  card("a4-viu", 3, 194, ...),    # 第 3 句 —— 再换掉整屏
  hero("a4-take", 4, 174, ...),
  {"id":"a4-plat", "type":"chart", "at":5, "duration":183, ...},
]
```

`at` / `duration` 的单位是**句子**，且每个元素铺满一个整盒 —— 结构上排除了「两个元素同时在屏上」。这不是模型偷懒，是它能拿到的唯一起点（3 轨骨架）逼出来的数据结构：**轨道数组没有「屏」的概念，第一个自然会写的结构就是「一条时间轴串行替换」**。

### 2.5 第 8 站的量化结果

| 指标 | 45s 真机 | 判读 |
|---|---|---|
| 总轨 / 其中内容元素 | 32 / 14（另 5 条擦除） | 6 屏 × 2.3 元素 |
| 每秒非字幕元素 均值 / 中位 / 峰值 | **1.71 / 1 / 3** | 半数时间只有 1 个 |
| 只有 1 个元素的秒数 | **23 / 45 s（51%）** | 观感 = 一张卡慢慢换 |
| 屏长分布 | 7.7 / 12.7 / 10.7 / 5.0 / 3.4 / 5.5 s | 离散 3.7×，无节奏可言 |
| 平均停留 | 3.79 s | 短视频节奏没问题 |
| 末两屏元素数 | 1 / 1 | 结论段最空 |

第 7 站（lint）为什么一句没提：ML-01…ML-15 查的是「动画太短/太长/一起冒出来/硬切消失/字幕超行/叠字」——**全是元素内部与外部的时序**，没有一条问「这屏上有几个东西」。

## 3. 断点归因（落到代码，而不是观感）

| 层 | 有什么 | 粒度 | 能否编排 45s |
|---|---|---|---|
| `assets/templates/` | 10 个模板（2.5–48s，多数 3–10s） | **屏** | ❌ `scaffold_manifest({templateId})` 与 `durationSeconds` 互斥，一次只出一屏，无法落在时间轴某段 |
| `RECIPES`（`recipes.ts:58`） | 4 个配方 | **段** | ⚠️ `planRecipe` 永远切 4 段：45s→11s/段，304s→76s/段 |
| `layout-recipes.md` | 7 个屏内布局（split-lr 等） | **格** | ✅ 是「屏内」的，但没有屏 |
| `CompositionManifest` | 任意轨道 | **轨** | ✅ 自由，但等于把版面决策全丢给模型 |

**三层资产之间缺一层**：屏。屏级资产（模板）用不上，段级资产（配方）太粗，轨级资产（manifest）太自由。第 4 站空着，模型只能从「轨级」直接起手 —— 于是它发明了一个屏级对象，但只活在那次会话的 `gen_specs.py` 里，不可复用、不可校验。

## 4. 怎么补这一步（四件套对齐）

只补「屏」这一站，不碰渲染器、不新增轨类型。

### 4.1 原语：`src/remotion/stage-plan.ts`（纯函数）

```ts
export type StageGrid = 'full' | 'split-lr' | 'split-tb' | 'chart-focus' | 'cards-2' | 'cards-3'
export type StageUnit =
  | { kind: 'template'; id: string; slots: Record<string, unknown> }
  | { kind: 'card'; id: string; copy: string }
  | { kind: 'blank' }
export interface Stage {
  id: string
  startFrame: number
  durationInFrames: number
  grid: StageGrid
  unit: StageUnit
  carry?: string[]          // 跨屏常驻层（页眉进度 / 侧栏 / 四角括线）
}
export interface StagePlan { totalFrames: number; fps: number; stages: Stage[] }

/** 屏数 = clamp(round(seconds / 6.5), 2, 40)；边界吸附到旁白句起点。 */
export function planStages(input: {
  totalFrames: number
  fps: number
  lineStarts: number[]      // TTS 句起点（已有）
  units: StageUnit[]
}): StagePlan
```

- 屏长**不均分**：有模板的屏按模板固有长度走（2.5–10s，不拉伸），无模板的屏按句群时长走，落在 4–10s；45s → 6–7 屏，屏长离散 ≤1.6×（对照真机 3.7×）。
- 边界吸附句起点：TTS 已经给出句窗口，屏必须与句对齐，否则字幕压屏。
- 总时长对不齐时**只挪 card 屏**，不挪模板屏（模板一旦拉伸就失真，这是模板通道的核心优势）。
- **不做**自动选卡：`units` 由模型填，工具只算时间与格位。

### 4.2 编排：`src/remotion/stage-compose.ts` + 工具面

```ts
export function composeStages(plan: StagePlan, theme: Theme): { tracks: Track[]; warnings: string[] }
```

- `template` 单元 → `compileTemplate()` 拿 tracks，**整组 `startFrame += stage.startFrame`**，id 加 `stage.id` 前缀；
- `card` 单元 → `getCard(id).generate({ ..., cell })`（卡生成器多接一个 `cell` 参数，缺省 `{x:50,y:50,w:100,h:100}`，**不新增轨类型**）；
- `carry` → 一条轨跨多屏，只声明一次（这是手写版 9 块背景面板的来源）；
- 音轨不动：TTS / BGM 仍走既有 `audio` 段。

工具面走**唯一入口**：`scaffold_manifest({ stages: "build/stages.json" })`，与 `templateId` / `recipe` / `title` 四选一互斥。传路径不传对象（8 屏 × slots 内联体积大）。

### 4.3 判据：`motion-lint` 加两条（纯函数，不上渲染）

| 码 | 判据 | 阈值 | 45s 真机 | 手写 60s |
|---|---|---|---|---|
| **ML-20** | 「非字幕元素 ≤1」的帧占比 | >25% ⇒ warning | **51% ⇒ 报** | ~8% ⇒ 不报 |
| **ML-21** | 全片无 `carry` / furniture 轨 | 0 条 ⇒ warning | **0 ⇒ 报** | 9 条 ⇒ 不报 |
| ML-22（延后） | 内容盒并集覆盖率 <50% | 需 box 并集算法 | 40.5% | 68.8% |

前两条只用 `tracks[].startFrame/durationInFrames/box`，零渲染成本，能反向变异（把 45s manifest 喂进去必须报）。

### 4.4 闸：`template-gate.ts:127` 把「整片时长」拆成两个字段

```ts
// 现在：整片时长直接比模板窗口 —— 45s vs 3–5s 必死，10/10 全灭
if (durationSeconds < window[0] || durationSeconds > window[1]) → 拒

// 改成两个字段：
//  stageSeconds（必判）：我这一屏有几秒 —— 选型时由屏表给，直接比 window
//  totalSeconds（只提示）：整片多长 —— 只用来估屏数，不参与拒收
```

改完同一条 45s 需求的真实结论，比「全灭」有用得多：

| 模板 | 固有长度 | 45s 片里的判断 |
|---|---|---|
| `press/ink-open` | 9s | ✅ 可占 1 个 9s 屏（开场） |
| `outro/strip-away` | 5s | ✅ 可占 1 个 5s 屏（落版） |
| `ui/list-reveal` | 3.6s | ✅ 可占 1 个 3.5s 屏（要点罗列） |
| `data/gauge-readout` | 4s | ⚠️ 需 4s 短屏，本片节奏不允许 ⇒ 不选 |
| `science/three-cards` | 36s | ❌ 远超单屏上限 10s，本片不能用 |

**诚实结论：45s 片里模板最多吃 2–3 屏，主力必须是「卡 + 格位」。** 这与方法论 §4 一致 —— 模板方向对，但它的粒度是「一个镜头」，撑不起整片；所以屏表的 `unit` 必须允许 `card`，且卡生成器要能接格位（`cell`）。

## 6. 通用性验证：同一根因在 304s 片上是什么样

| | 45s 版 | 304s 版 |
|---|---|---|
| 私编排器 | `gen_specs.py` 29KB / 7 个盒常量 | 同一份放大到 216 轨 / 6 幕 |
| 症状 | 23/45 s 只有 1 个元素 | 同屏 2.21 / 包围盒 25.8% / 纯背景段 3 处 |
| 屏长 | 3.4–12.7s | 平均 9.88s，最长 30s+ |

## 8. 不做

- **不**新增轨类型（stage 是编排层概念，产物仍是 tracks）。
- **不**让 `planStages` 自己选内容（选内容会让「准确性」失去锚点，模型必须给出 `units`）。
- **不**改 `planRecipe` 的 4 段（它是体裁起点，不是长片结构；长片结构归屏表）。
- **不**回填历史 manifest（开发期只修产生路径）。
- **不**把 ML-22（包围盒覆盖率）排进这一批：它需要 box 并集算法，收益低于 ML-20。

## 9. 附：屏表与电影分镜的对应关系

一句话：**屏表 ≈ 分镜，但它是「排版单位」而非「拍摄单位」**。字段可以逐条对上，两处必须多、一处必须少。

| 分镜字段 | 屏表字段 | 关系 |
|---|---|---|
| 镜号 | `stage.id` | 同：可寻址、可返工、可 diff |
| 时长 | `durationInFrames` | 同量级：镜头 3–10s，屏 4–10s |
| 景别 / 运镜 | `grid`（格位） | **换词汇**：不是「相机怎么走」，是「内容怎么排」 |
| 画面描述（角色/场景） | `unit`（主视觉单元） | 同：内容主体 |
| 声音 | 旁白句窗口 + sfx 点 | 同：TTS 句起点就是屏边界 |
| 衔接 cut / chain / bridge | `transition` | 同 |
| —（无） | `carry`（常驻层） | **多出来的**：跨屏不变的底板 / 页眉 / 括线 |

三处不等价，每处都直接决定实现形态：

1. **执行单位 vs 组合单位**。一个镜头 = 一条视频（不可分割）；一屏 ≠ 一张卡 —— 一屏通常 3–6 条轨，且来自不同资产（模板 + 卡 + 标注）。所以屏表是**组合**层，必须比 `shot` 多一层编译（`composeStages`），不能像分镜那样「一条镜号直接换一条视频」。
2. **电影有连续性保证，代码没有**。同一个场景里角色不会自己消失，这是摄影机的物理连续性白送的；代码渲染每帧重算，**跨屏不变的底板必须显式声明**（`carry`），否则下一屏就没了。这就是手写版 9 块常驻底板 vs 真机 0 块的技术根源 —— 不是模型不想留，是没人告诉它要留。
3. **分镜可以含糊，屏表必须可算**。「压抑的氛围」是合法分镜描述，但渲染器消费不了。屏表的每个字段都要能算：占几 %、几个元素、持续几秒 —— 所以它是纯函数 + lint 码（§4.1 / §4.3），不是一张给人看的表。

**不要照抄的地方**：分镜的运镜词汇（景别 / 推拉 / 摇移）在代码路线里**没有对应物**。硬搬的结果就是现在 §04 的错位 —— 图文路线照抄分镜表，会写出「中景，缓慢推进」这种没有任何消费者（渲染器不认、模型也不生成）的描述。屏表的「运镜」是格位与节奏，不是相机。
