## 二、优先级路线图（对账修订版）

> 验证纪律（沿用本仓）：T1 渲染常量/视觉调参 → build + 定向 canvas 集 + **你桌面自主验收即放行**；T2 布局纯函数/几何 → build + 定向 + 相关 preview 组；T3 跨进程/守卫/错误系统/host 边界 → 全量 `node --test` + verify-previews + 反向变异。
> **「验证」列说明**：【无头】= 不开桌面即可完成开发自测，适合用户不在场的会话推进；【桌面】= 最终验收必须真机观感。

## 三、登记约定（落到本仓 SSOT）

- 编号：Bug / 需求条目需在 `canvas-studio/docs/STATUS.md`（SSOT，当前上限 **CV-276**）与两份镜像续登；日常写号直接 +1，**不要每轮 grep 整 docs 树**，仅跨多文档批量时复核一次。

- 报告时区分「修产生路径」还是「改存量」：本仓处于开发阶段，只动产生数据的代码路径，不回填历史数据。
- 两套编号的关系：`BUG-00X`/`REQ-00X` 是仓内跟踪号（权威），A-x/R-xx 是资料库行别名；新条目入库时在镜像里续号并在本目录底稿里加别名。
