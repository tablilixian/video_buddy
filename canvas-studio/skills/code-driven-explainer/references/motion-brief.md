# 动效五要素 brief（写 manifest 前过一遍）

本分册是**动效质量的思考清单**，来自 2026-10 动效质量调研的挂账补齐（P4）。它不规定字段
用法（那是 `manifest-contract.md` 的事），规定的是**动笔前该做的五个决定**。30–90 秒的解说片，
动效做得散 = 全部白做；按这五要素过一遍，能把「为动而动」挡在 manifest 之前。

## ① beat —— 节拍

- **先写节拍表再写轨**：这部片有几次「信息落点」？每个落点对应一张卡 / 一个数字 / 一次揭晓。
  60 秒片 4–7 个落点；少于 3 个是催眠，多于 8 个是轰炸。
- 落点之间的静默段是**留给呼吸的**，不要塞动画填缝。
- 落点优先级排序：只有第一名配得上**揭晓级动效**（`countUp` / `spotlight` / 指针甩弧），
  其余用普通入场（`fadeUp` / wipe）。

## ② 主次 —— 一屏一个主角

- 一屏只允许**一个运动主体**：主视觉动，配角（背景、网格、参照物）全部静止。
- 同屏独立动画 > 2 处 = 观众不知道看哪；用 `startAfter` 把第二主角排到下一拍。
- 强调手段的强度阶梯（从弱到强）：`fadeUp` 入场 → `reveal` wipe 擦除 → `callout` 指认 →
  `spotlight` 聚光 → `countUp` 数位滚动。**同一张卡只取一档**，两档叠加 = 没有层次。

## ③ 帧预算 —— 动效时长有默认值，别自造

| 动效 | 默认帧数（@30fps） | 出处 |
| --- | --- | --- |
| 入场 `animate`（fadeUp / slide / scale） | 15–24 帧（0.5–0.8s） | 本仓纪律 |
| `reveal` wipe / spotlight | 18 帧（缺省值） | reveal.ts |
| `callout` 引线生长 → 标签落位 | 20 帧 / 26 帧内置 | Callout.tsx |
| `dataCard` `countUp` | 45 帧 | count-up.ts |
| 指针甩弧（`animate.rotation`） | 视弧长 30–90 帧，easeOutCubic | 缓动白名单 |
| 退场 `exit` | 入场 × 0.6（引擎自动推导） | ExitMotion |

- 全片「屏上时间有东西在动」的占比 ≤ 40%：超了说明落点太密或该静的没静住。
- 卡片最短在屏 1.5s：动效预算（入场 + 揭示 + 退场）不得超过在屏时长的一半。

## ④ 进出场 —— 怎么来、怎么走

- **入场方式 = 信息的来源隐喻**：数据揭晓 → `countUp` / 揭示 wipe；重点指认 → `callout`；
  换视角 / 翻面 → wipe 方向对调；氛围铺垫 → `fadeUp` 即可，不要给铺垫信息配揭晓级动效。
- 退场永远比入场快（`exit` 缺省 0.6×）。收尾结论卡**不配退场**——它是最后一个画面。
- 转场差异化：全片同一种 `fade` = 幻灯片；`fade` / `slide` / wipe 混着用，但一段内不超过两种。

## ⑤ 禁用项 —— 这些写了会被拦或被记

- **禁 CSS `transition` / `@keyframes`**（组件层就没有这个口；插值一律走 manifest 纯帧函数）。
- **禁编假数**：`chart` / `dataCard` 的数字必须是显式声明的事实（校验只查形状，查不出真假 ——
  这条靠纪律）。
- `spotlight` 不吃 `direction`（告警忽略）；`shape:'path'` 的轴心按画布百分比解释（用 pivot 前
  核对 `manifest-contract.md` shape 节的语义表，盒形状与 path 口径不同）。
- 循环往复（呼吸 / 自转）不要跨卡常驻——轨道在屏期间才动，离屏即停（引擎本来就按轨内帧求值，
  别为了「一直转」把轨道拉满全片，会吃掉运动密度体检的预算）。
- `countUp` 只对 `dataCard` 生效；`12abc34` 这类多段数字静态容错（不滚动、不报错）——想滚就把
  数值写成一段连续数字 + 前后缀。
