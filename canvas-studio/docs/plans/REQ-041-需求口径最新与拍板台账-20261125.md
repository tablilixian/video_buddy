## 4. 执行单（未完成）

### 4.1 批次 P2：P0-3 方案 c + N1（主件）

**事实前提**（代码已核）：`shot-render.ts:267` `allowShots = manifest.audio === undefined`；
whole 模式在 269-275 直接 return、**不写 shot-cache**；`segment-publish.ts` 读不到缓存 ⇒ 新项目带旁白时一段都没有。

**目标**：不论有没有 audio、不论 draft 还是 standard，只要在分镜视图，每段都有可播产物（画面 + 旁白）。

**渲在哪一侧（已核实，不要重新设计）**：段渲染**本来就是客户端 CSR** 干的 ——
`renderManifestOnWeb` 支持 `frameRange`（**闭区间**，`endFrame - 1`）+ `audioCodec: null`（R11-C3 无声段），
产物回写走 `render-job-executor.ts`；宿主只负责「排计划 → 发布副本 → 合声 → 拼片」。

**做法**（与 N1 共用内核，不重复投入）：
1. 渲染计划**只取目标段**：复用 `planShotRender`（`shot-cache.ts:269`）/ `getDirtySegments`（`shot-cache.ts:113`），
   作业参数复用**纯函数** `segmentRenderJobOf`（`shot-cache.ts:193-227`），只跑这一段；
2. 跳过 concat / saveMerged / probe（那是整片的事），发布仍走 `publishSegmentArtifacts`（`shot-render.ts:163`，
   确定性名 `assets/seg-<id>.mp4`、覆盖写）+ 合声副本；
3. 清单接口照旧，客户端只认 `?v=` 变化 ⇒ 呈现层零改动；
4. **整片路径（`compose.ts` / 混音链）一行不动**，零回归。

**硬约束（真实事故）**：作业对象的 `frameRange` / `muteAudio` 必须来自纯函数 `segmentRenderJobOf`，
**禁止入口内联拼对象** —— C5 接线时漏传这两个字段，真机渲出的是整片且带声（`shot-cache.ts:203` 注释）。
单段入口同样必须走它，否则「只渲一段」会退化成「渲全片」。

**验收**：新建带 `audio.voiceOver` 的项目 → 渲一版 → 每镜一张段格、有画面、点预览有旁白；成片声音与改前逐项一致。

### 4.2 N1 新工具 `rerender_segment`（按 step plan，**只放 N1**）

- 入参 `{projectId?, shotNodeId?, segmentId?, quality?}`，后两者二选一、同给拒收；定位复用 `resolveSegmentIdFromNode`。
- 职责单一：只重渲并发布段产物，**不改 spec**；改 spec 是 `patch_spec_section(shotNodeId)` 的活。
- 结构性意见（拆屏 / 增删屏）由工具 description + agent 明示拒绝，**本期不做结构改**（D3 边界）。
- deps 必须与 `render_composition` **同源**：抽 `buildShotRenderDeps(...)`，禁止复制注入代码。
- 回执 `resultSchema` 是 `additionalProperties:false` ⇒ 新字段逐个显式声明，否则被静默剥掉。
- 刷新信号改常量集合 `RENDER_SETTLED_TOOLS = {render_composition, rerender_segment}`。
- 耗时先量后优：墙钟 ≈ 单屏时间（≤2×）即止；被整片拼接拖住再抽轻量路径（§十 5「实测前不做设计决策」）。
