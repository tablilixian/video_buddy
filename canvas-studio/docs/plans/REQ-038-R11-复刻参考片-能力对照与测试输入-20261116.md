### 结论（补齐后重估）

- **骨架 8/10**：竖屏、近黑底、眉标、大标题、数据卡、要点、动效节奏 —— 都能对上，出片气质会像。
- **表现层 7/10**：折线+标注、标题双色、结论条三件已到位；差的只有图标系统与卡片长宽比。
- 综合：**能做到「同系列、同气质、同款版式骨架」，剩下的是图标与卡形这两块**。

## §3 测试输入（可直接粘给 agent）

> **2026-11-16 修订（重要）**：本节原「输入 A」自相矛盾 —— 它要求每屏 5 个视觉元素，
> 却只给 2 个 `units` 且把格位钉死，而 `carry`（唯一的常驻层）`SpecCarry` 只有
> `id/box/color/radius`，**放不了文字**。第二轮真机会话因此卡在
> 「spec cards alone cannot deliver the requested visual」这句话上 45 分钟。
> 现在拆成两个变体，**把「考通道」和「考能力」分开**：
>
> | 变体 | 考什么 | 依赖 | 何时跑 |
> |---|---|---|---|
> | **A**（下面的 A） | spec 通道能不能出片（3 units） | 无 | 现在就能跑 |
> | **B**（§3.2） | `carry` 文字层（2 units + 3 条常驻文字） | M3 的 `carry` 文字支持 | M3 落地后 |
>
> 两个变体的**设计意图相同**（同一套版式、同一份文案），区别只在"多出来的三处固定
> chrome 用什么承载"：A 用第 3 个 unit + 眉标，B 用 `carry`。

### 3.1 变体 A · 考 spec 通道（3 units，现在就能跑）

```
帮我做一支竖屏科普短片，复刻小红书财经科普那种图文卡片风格。

画幅：9:16 竖屏 1080×1920，总时长 40 秒左右，6 屏。
主题：深色近黑底，用 neon-data。题材：量化基金 vs 散户 —— 为什么"涨了也拿不住"。

版式全片统一（6 屏同一套，不要变），每屏 3 个单元上下排（**格位不能相交，照抄这三个**）：
- 单元 1（标题）：A1 或 A2，cell {x:50, y:22, w:100, h:24}   ← 占 10%–34%
- 单元 2（主体）：每屏指定，cell {x:50, y:58, w:100, h:44}   ← 占 36%–80%
- 单元 3（结论条）：A1，cell {x:50, y:87, w:100, h:14}      ← 占 80%–94%
左上角那行灰字和「01 / 06」序号由卡自带的眉标出，用 section.label 写分组名，
不要另外加常驻层、也不要自己拼 chrome。

六屏（主体用哪张卡都写好了，按这个来）：
1. 量化基金 / 散户，两张并排对比 → 主体 B1（数据卡）
   copy 两行：规则先写死:100  /  临场决定:37
2. 到底，只有两个选项，两条路径 → 主体 A4（要点逐词落位）
   copy 两行：A 动量  /  B 均值回归
3. 99 买 / 101 卖，一条价格轴两个方向 → 主体 DAT3（柱状图生长）
   copy 两行：买入:99  /  卖出:101
4. 波动率也会回归 → 主体 DAT6（折线 + 峰谷标注 + 长期均值虚线）
   copy 六行：1月:2.1 / 2月:1.4 / 3月:1.0 / 4月:1.8 / 5月:2.6 / 6月:2.2（每行一个）
   label 一行：波动率 | 高→卖 | 低→买
5. 继续，还是回来，一个判断分叉 → 主体 A1
   标题里两个关键词换色，用 highlights：
   [{ "text": "继续", "color": "#F5A623" }, { "text": "回来", "color": "#2EE6A8" }]
6. 先问三件事 → 主体 A4，copy 三行（三条问题）

结论条（单元 3）每屏一句，12 字以内。
强调色：A 组（动量）#F5A623，B 组（均值回归）#2EE6A8。

流程：故事板 → spec → scaffold_manifest（传 aspect:"9:16"）→ 立刻 render_composition(quality:"draft")。
不要为了版式去读 src/remotion 源码，卡号与用法查 card-catalog.generated.md。
```

**这一版为什么能表达**：3 个单元是上限内的（`units ≤ 4`），每屏的"标题 / 主体 /
结论"三块各有一张真卡承载，左上灰字由眉标负责。原设计里的"右上描边标签"在这一版
**主动放弃**（它需要 `carry` 描边 + 文字，见变体 B）。

> **两条硬约束（不是风格建议，违反了会拒收或裁字）**
> 1. **格位不许相交**：校验按「内容长期并存 = 遮挡」判，相交 >5% 直接拒收。
>    上面三个 cell 的纵向区间是 10–34 / 36–80 / 83–95，已经留好缝。
> 2. **单元太矮会被「0–1 比例值」误判**：卡内小元素（结论文字占卡高 10%、眉标 6%）
>    投影进矮 cell 时会掉到 ≤1%，校验把它当成"写了 0–1 单位"拒收。
>    单张卡（或屏首单元）的 `cell.h` 要 **≥17**；上面结论条给 14 是因为它是**第 3 个单元**，
>    非首单元的屏级 chrome（眉标）会被裁掉。阈值见 `spec-geometry.generated.md` §6。
>
> **结论条为什么用 A1 而不是 A6**（2026-11-16 实测，`tests/req038-r11-test-input.test.mjs` 有守卫）：
> A6 卡名就叫「结论条」，但它的 `verdict` 只占卡高 10%、字号**恒 17px**，而它的 `kicker`
> 会把 `section.label` 用 82px 再打一遍 —— 同一屏里分组名出现两次（眉标 + 结论条），
> 真正的结论却是一行小字。换成 A1（标题卡）后：盒 821×81px、字号 **82px**、单行，
> 才是参考片那种结论条。

### 3.2 变体 B · 考 `carry` 文字层（M3 落地后再跑）

```
把变体 A 的版式换成 2 个单元 + 3 条常驻层，其余（画幅 / 题材 / 六屏内容 / 强调色）完全不变：

- 单元 1（标题）：cell {x:50, y:24, w:100, h:24}
- 单元 2（主体）：cell {x:50, y:64, w:100, h:54}
- 常驻层（carry，全片铺满，fadeFrames 0）：
  ① 左上灰字：text "所有策略，只有两个选项"，box {x:26, y:9, w:52, h:5}，textColor "#8fa3c4"
  ② 右上分组标签：text "A 组 · 动量"（第 1–3 屏）/ "B 组 · 均值回归"（第 4–6 屏），
     box {x:76, y:9, w:26, h:5}，textColor 对应强调色，letterSpacingEm 0.1
  ③ 底部结论条：这条**不要**用 carry（carry 是跨屏同文本的），仍用单元 3 的 A1
```

**这一版考的是**：`carry` 能不能承载跨屏固定文字、时间窗是否按 `fromSection..toSection`
并集铺满、`fadeFrames` 是否为 0（常驻层不能每屏闪一次）。
第 ② 条要跨两段文本 → 写成两条 carry（`toSection` / `fromSection` 各一），这正是
时间窗并集的验收点。

> **`carry` 能写什么（实测，2026-11-16 M3 之后）**：`text` / `variant`（缺省
> `subtitle`）/ `textColor` / `background` / `letterSpacingEm`，加上形状层原有的
> `id` / `box` / `color` / `radius` / `fromSection` / `toSection`。
> **没有** `fontPx`（字号由 variant 决定）、**没有** `border`（要"描边标签"就用
> `background` 半透明底 + 强调色文字）。完整字段见
> `skills/code-driven-explainer/references/spec-capability.generated.md` §2。

## §4 验收看点（对不上≠bug，先看这几条）

| 看什么 | 期望 | 若不对，说明什么 |
|---|---|---|
| 画幅 | 1080×1920 竖屏 | 还是 1920×1080 ⇒ `aspect` 没传到（本轮修复只在 `0094938a02` 之后） |
| 每屏元素数 | 标题 + 主体卡 + 结论条**同屏三块** | 只有标题没图 ⇒ agent 没用 `units`，可回它「用 spec 的 units 上下排，3 个单元」 |
| 标题与卡是否重叠 | 不重叠 | 重叠 ⇒ `cell` 的 y/h 没给对（告诉它「标题 cell y=22 h=24，主体 y=58 h=44，结论 y=87 h=14」） |
| 底色 | 近黑 | 深蓝灰 ⇒ 主题没走 `neon-data` |
| 第 4 屏图表 | **折线 + 峰谷标注 + 均值虚线**（`DAT6`） | 出柱状 ⇒ `DAT6` 被 `<3 点` 回落成标题卡（copy 必须给满 6 行）或 agent 自己换成了 `DAT3` |
| 全片一致性 | 6 屏同一套版式 | 每屏长得都不一样 ⇒ 密度/一致性体检要收（`density-audit` 已能提示） |
| 文案密度 | 每屏 20–40 字 | 全片不到 100 字 ⇒ 用 `targetStageSec: 4` 提密度 |
| **卡片长宽比** | 会比参考片**方一些** | 不是 bug：56 张卡的 `box` 是按 16:9 写死的百分比（`B1` 恒 52% 宽），投影进竖屏格位后 1080×1920 上约 562×473（近方）；参考片的卡是 900×420（宽扁）。要让竖屏卡变宽扁，得给卡加「竖屏专用 box」，不在本轮范围 |

### 实测过的格位数值（直接用，别让 agent 自己猜）

下表全部由 `planFromSpec()` 现跑得出（1080×1920，`§3.1` 那三个格位），不是手算：

| 单元 | cell | 投影后实际 |
|---|---|---|
| 大标题（A1/A2） | `{x:50, y:22, w:100, h:24}` | 标题盒 76% 宽 / **821×138px**；字号**随字数在 88–115px 之间浮动**（9 字含「，」88 / 9 字含「/」108 / 7 字 115，满号 149px 被盒高挡住） |
| 主体 · B1 数据卡 | `{x:50, y:58, w:100, h:44}` | 数据块 52% × 24.64% = **562×473px**；copy 走 `键：值` 两行，落进 `data[]`（`{k,v}` 对，实测半角 `:` 也认） |
| 主体 · DAT3 图表 | 同上 | 图表 76% × 22.88% = **821×439px** |
| 主体 · A4 要点 | 同上 | 要点框 64% × 20.24% = **691×389px**，字号 **85px**（短句），2–3 行不溢出（6 行上限）。**可用宽 616px**（容器按 box.w 算，P0-2 修复后）⇒ 85px 下约 7 字/行；长句会缩号（四条要点实测 85→60px，见 `spec-geometry.generated.md`） |
| 结论条（A1） | `{x:50, y:87, w:100, h:14}` | 标题盒 30% × 14% = **821×81px**，字号 **82px**，单行 |

`w` 必须给 **100**：卡自己的 `box.w` 还要再乘一次 cell 宽度，给 88 会把标题压到 66% 屏宽 ⇒ 换行或裁字。

> **`A6` 为什么没被选作结论条**（实测，2026-11-16）：它名字叫「结论条」，但 `verdict`
> 只占卡高 **10%**、字号**恒 17px**（`h:12` 盒 23px / `h:18` 盒 35px，字号都不涨），
> 写 2 行还会溢出（`fontPx` 被压到 9.35 且 `overflow=true`）；更麻烦的是它的 `kicker`
> 会把 `section.label` 用 **82px** 再打一遍 ⇒ 同一屏分组名出现两次（眉标 + 结论条），
> 真正的结论却是一行小字。改用 A1 后（盒 821×81 / 字号 82px / 单行）才是参考片那种结论条。
> 上表与 `tests/req038-r11-test-input.test.mjs` 的第 5、6 条断言钉的就是这个差异。

> **标题字号上限（实测，别再猜）**：`cell.h:24` 下盒高 138px，字号在 **88–115px** 之间
> 由**字数**决定（不是固定 115）；`h:30` → 123px；**满号 149px 需要 `h ≈ 60`**（那时主体卡
> 就没地方了）。所以竖屏标题的现实做法是**控制字数（5–9 字）接受 88–125px**，别为满号撑格位。
> 四档画幅 × 各种 cell 的完整数值见 `skills/code-driven-explainer/references/spec-geometry.generated.md`。

## §5 本轮补齐的三件（已落地，等真机验收）

1. **`DAT6` 折线 + 峰谷标注**（`recipe-cards-data.ts`）：`chart:line` + 2 `callout` + 均值虚线；
   少于 3 点回落成标题卡（两点只有一条直线，标不出峰谷）；全平序列不画均值线（会和曲线重合）。
2. **`textCard.highlights` 分段着色**（契约）：`manifest.ts` 字段 + 校验、`text-highlights.ts`
