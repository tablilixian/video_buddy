## 〇、一句话结论

两轮会话暴露的问题**分属七个层级**（原 L1~L6 六层 + 复核补录 L7 存量产出层），其中真正"必然复发"的有两处根因：

1. **契约层根本没有"数据出处 / 基准"这个概念** —— 混口径在语法上完全合法，校验器与体检都看不见；

## 一、问题清单

### L1 契约层（渲染前的硬闸）

#### P-01 数据轨没有「出处 / 基准」概念 ⇒ 混口径的数字合法通过

| | |
|---|---|
| **现象** | 折线前 8 点用 1951–1980 口径、后 3 点换 1850–1900 口径，校验器 0 error、体检 0 条，画面把 30 年升温画成 1.10 ℃（同口径真值约 0.83 ℃），偏高约 0.27 ℃ |
| **证据** | 原始表 `build/gistemp.csv`（NASA GISTEMP v4，J-D 列 = 索引 13）逐点比对：1995/1998 与原表**完全一致**，2019/2022/2024 分别高 +0.22/+0.26/+0.27 ⇒ 后三点被换过基准；`storyboard.json` 里该事实自身写着 `status:"pending"`、"本片未在线复核逐年小数" |
| **根因** | **契约层没有这两个字段** —— `ChartTrack` 只有 `labels/values/unit/color`，`dataCard` 只有 `data[].k/v`。"这条序列是什么基准、哪来的"**无处声明**，因此**无从校验**；storyboard 里唯一的溯源槽位（`facts[].source/status`）与成片 manifest 之间**没有任何桥**，`pending` 事实照样能变成 `chart.values` 和数据卡数字 |
| **方案** | ① `chart`（内联数值时）新增必填 `dataSource`（数据集 + 可复核入口）与 `baseline`（基准说明），缺失 ⇒ **error 阻断渲染**；`source:'timeline'`（片内真值派生）豁免。**dataCard 触发口径收窄（2026-11-04 复核实测后修正）**：仅当 `v` 为**数值型事实**（温标 / 量级 / 百分比等可溯源数字）时必填；`'58 BPM'`、`'24h'`、`'62 bpm'` 这类时长 / 节奏元数据**不触发** —— 原口径「`v` 含数字」会把 5 份 manifest 全打红、且 `baseline` 对 BPM 无语义，等于诱导 agent 编造出处糊弄硬闸（恰是本条要治的病）；或改为提供 `dataSource:'inline'|'observed'` 逃逸口 + `baseline` 可豁免。<br>② storyboard 的 `facts[].status` 与 manifest 之间建桥：`pending` 事实不得进成片（校验器读不到 storyboard，则由宿主在 `write_storyboard`→`render_composition` 之间做一次一致性检查）。<br>③ 配套技能纪律（见 P-09） |
| **成本 / 风险** | 破坏性收紧。**2026-11-04 实测复核**：存量 11 份 manifest 中 5 份会命中（`用 code-driven-explai` ×2、`code- 7`、`code- 4`、`我想做一个 45 秒…`）—— 其中 3 份有 `chart.values`；5 份 dataCard.v 均含数字，但 `code- 7`/`code- 4` 触发的全是 BPM 类元数据。**按收窄后口径仅 3 份需补字段**，各补两个字段即可 |

#### P-02 契约字段表与实现脱节 ⇒ **app 对 agent 谎报"这个字段不会生效"**

| | |
|---|---|
| **现象** | `gaugeMax`、`palette`、`sourceRect`、`hasAlpha` 这四个**被实现真实读取**的字段，不在 `KNOWN_TRACK_KEYS` 里 ⇒ 每次用到都被告警：「含契约外字段 "gaugeMax"（已忽略）。请核对字段名与写法 —— **它不会生效**」 |
| **证据** | 实跑 `validateManifest`：`chart{gaugeMax}` → 告警"不会生效"，而 `src/remotion/chart-pie.ts:118` 正在读 `track.gaugeMax`；`image{sourceRect,hasAlpha}` → 同样告警"不会生效"，而 `src/remotion/sprite.ts` 正在读 `track.sourceRect`、`src/remotion/components/ImageClip.tsx:46` 正在读 `track.hasAlpha` —— **`hasAlpha` 还是宿主自己写的**（`src/host-tools.ts:3608-3614`） |
| **根因** | 加字段时的落点只覆盖"类型定义 + 校验"，**漏了字段表登记**，且**没有任何检查能发现这个遗漏**。于是"登记"这件事全靠人记 |
| **方案** | ① 补登记这四个字段，**并同步重跑 `node scripts/gen-manifest-fields.mjs` 重新生成 `skills/code-driven-explainer/references/manifest-fields.generated.md` 一并提交**（改 `manifest.ts` 不重跑生成物 ⇒ `tests/manifest-fields-drift.test.mjs` 必红，第一批过不了 `yarn check` —— 2026-11-04 复核补充的**必做步骤**）；② **加一条字段表漂移检查**：扫描实现里读取的 `track.X`，与 `KNOWN_TRACK_KEYS` 交叉比对，漏登记即测试红 —— 让"加字段漏登记"从此不可能再悄悄发生 |

#### P-03 契约外字段的处理方式是「静默丢弃 + 一句不成立的断言」

| | |
|---|---|
| **现象** | 会话 15 里 agent 写了 `animOptions.revealFrames`（契约外字段），渲染静默忽略；它自己发现后删掉——**过程里没有任何工具提示它** |
| **根因** | 未知字段只有一条 warning，文案对**所有**未知字段统一断言"不会生效"。既没有"能力对照表"（哪些字段名接近真字段但写错了），也没有"静默"与"生效"的区分 |
| **方案** | 未知字段 warning 文案改为**不越界的表述**：「未登记字段（本版本不保证生效；字段全表见 `manifest-fields.generated.md`）」；对**拼写近似**的已知字段给定向提示（距离 ≤2 的编辑距离 ⇒ "你是不是想写 X？"）—— 替掉那句对 agent 不成立的断言 |

#### P-16（复核补录）reveal 进场方向告警对「没写 direction」误报 ⇒ 按建议改反而改了渲染

| | |
|---|---|
| **现象** | 右侧卡只写 `reveal:{kind:'wipe',...}`（作者**从未写过** direction）就报「请用 reveal.out.direction='right'」；作者按建议改会真的改掉渲染结果 |
| **证据** | 实证 `src/remotion/reveal.ts:263-276`（CV-428 引入；2026-11-04 复核确认代码原样在）：`:266` 对未写 direction 缺省取 `'right'`，`:269-273` 的 sameSide 判定**拿缺省值**参与比对 |
| **根因** | 告警把「引擎补的缺省方向」与「作者显式声明的方向」混为一谈，未区分二者 |
| **方案** | 只对**显式写了 `direction`** 的段触发该告警；缺省不告（或降为 info） |
| **成本 / 风险** | 极低；warning 级、零破坏性。**与 P-02 同属"app 对 agent 说的话不真"，按排序原则 ① 应进第一批**（来源：《改动生效性评估》§四 B3，原清单漏收） |

### L2 体检规则层（决定 agent 到底信不信体检）

#### P-04 ML-10 漏算两种"画面在动" ⇒ 把连续运动判成 0%

| | |
|---|---|
| **现象** | 3 张 `fit:"kenburns"` 的图铺满全片 120 帧 ⇒ 体检报「画面上有东西在动的时间只占 **0%**」 |
| **证据** | 实跑 `lintMotion`：`["ML-10"] 画面上有东西在动的时间只占 0%（整片 120 帧）`。组件层 `ImageClip.tsx:26` 是 `1 + 0.08*(frame/duration)` 的连续缓推；`reveal.out`（CV-428 新增的退场擦除）也完全没进分子 |
| **根因** | ML-10 的分子是**能力清单写死**的（video / reveal / exit / animate），而 `kenburns` 与 `reveal.out` 是**之后加的能力** —— 加能力时没回头扩口径。仓库自己的默认写法就是 `fit:"kenburns"`（`code-driven-explainer/SKILL.md`），等于默认写法必然触发 |
| **方案** | 分子补两项：`image` 轨 `fit==='kenburns'` 按整轨计入；`reveal.out` 退场擦除区间计入（口径与 `timing-segments.ts` 的 `trackIsAnimated` 对齐：纯 cover/contain 静帧**不算**动） |

#### P-05 ML-04 的"可见幅度"阈值在浮点边界上判反了方向

| | |
|---|---|
| **现象** | `opacity 0.9↔1.0` 的往复**被报 ML-04**；幅度更大的 `0.8↔1.0` **不报**；`scale 0.994↔1.006`（事故里的 1.2% 微幅假呼吸）报 —— 正是上一批想修的那个 |
| **证据** | 实跑三组对比确认。算术：`\|1.0-0.9\| = 0.09999999999999998`，×10 = `0.9999999999999998 < 1` ⇒ 恰好达到可见门槛的呼吸被判成"看不见" |
| **根因** | 幅度折算后**直接与阈值比较**，没有取整也没有 epsilon；文档写的是"opacity 0.1 = 可见"，代码算出来是 0.09999999999999998 |
| **方案** | 幅度按 1e-9 取整再比（或比较时加 1e-9 容差）。同时补三条边界表测（0.9↔1.0 豁免 / 0.8↔1.0 豁免 / 0.994↔1.006 照报） |

#### P-06 ML-02 不认退场擦除 ⇒ 把幕布误报成"凭空消失"

| | |
|---|---|
| **现象** | 成片回执恒报 `ML-02×11`，而其中 6 条是**转场幕布**（`reveal.out` 擦出），另外大量是同色背景轨的段边界硬切 |
| **证据** | 按体检同一判据实算：RUN-2 硬切轨 **54 条**（回执只露 11 条，`ML-00` 把其余折叠掉了）；其中 6 条带 `reveal.out` |
| **根因** | ML-02 判据写于 `reveal.out` 存在之前，只认 `exit` 与尾部转场 —— 新增的原生退场路径没进白名单 |
| **方案** | 有 `reveal.out` 的轨豁免 ML-02（内容是"擦出去"，不是"凭空没了"）；再把 `ML-00` 截断改成"计数 + 前 N 条 + 落盘全文"，别让体检结论本身失真 |

#### P-07 体检结论没人消费（回执折叠 + 无强制阅读路径）

| | |
|---|---|
| **现象** | 渲染回执只给「命中 13 条：ML-01 / ML-02×11 / ML-00（**逐条定位见 report.lint[]；文案已折叠以免挤占上下文**）」，agent 没去读 `report.lint[]`，最终交付说明**一个字没提这 13 条**；自己的推理里写的是「acceptable but let's not worry」 |
| **根因** | ① 回执为省上下文折叠明细，但**没有强制消费路径**；② 交付纪律里**没有"必须复述体检结论与未决项"**这一条 —— 交付模板只奖励"我改了什么" |
| **方案** | ① 体检全文落盘项目内 `report.lint[]`，回执保留计数 + 前 N 条 + 路径；② `SKILL.md` 交付段加硬性清单：**逐条复述体检结论的状态（已修/豁免/接受并说明理由）、未核源事实清单、未执行的闸门**，同一份写进 `write_note` |

| | |
|---|---|

#### P-09 技能层只覆盖「契约坑」，不覆盖「事实与数据坑」

| | |
|---|---|
| **现象** | `pitfalls.md` 8 节全是渲染契约（animate 相对帧 / duration=1 / reveal 方向 / exit 不支持 clip / subtitle 多行 / ML-04 / ML-10 / 素材时长）；对"数值出处 / 基准 / pending 事实"**零覆盖**（全文仅 1 处偶然提及"数据"） |
| **根因** | 坑位清单按"渲染契约"这一个维度组织，**缺"事实与数据"这一类**。上一批的教训是"别再重新发现同一批 bug"，但新沉淀的教训（数据溯源）恰好落在一个**没被清单覆盖的维度**上，于是它既没进项目 lessons.md 的通用段，也没进技能层 |
| **方案** | `pitfalls.md` 增「§9 事实与数据纪律」：数值必须来自一手表并**落盘原表**；一条序列只能一个基准；端点数字与序列必须同源同基准；`status≠verified` 的事实不得进成片。`references/verification.md` 增「数据判据取证」——与已有的"画面判据必须看图本身"同构：**数据判据必须看原表本身**，禁拿"manifest 字段齐"当通过 |

#### P-10 交付说明只讲"我改了什么"，不讲"还剩什么"

| | |
|---|---|
| **现象** | 会话 15 最终回复列了 5 处修复并逐条给证据，但**没复述 13 条体检告警的逐条状态**。〔2026-11-04 22:57 纠偏：原把「负例未执行」算成缺陷 —— 负例是验收测试手段、不进正常流程，**不构成缺陷**；相关表述已从 SKILL.md / verification.md 撤销〕〔2026-11-04 复核更正：终答**已经如实写了**「故事板仍标 `pending`（未逐条核源）」「构图美观度 / 字体渲染质感无自检能力」「VLM 数字抄录极不可靠」，原文把这三样算成「没提」与实录矛盾，不再作为本条论据〕
| **根因** | 交付纪律缺少「**必须复述未决项**」：证据纪律只覆盖「做过什么」，没覆盖「**没做什么**」（体检逐条状态 / 未核源事实 / 能力边界）。〔定级：单样本观测，中·待验证〕
| **方案** | `SKILL.md` 交付段加「未决项清单」硬性条目：**体检结论逐条状态**（`lint[]` 折叠时至少给计数 + 前 N 条 + 落盘路径）/ 未核源事实 / 模型自身能力边界；与 P-07 同批落地（同一份内容写进 `write_note`）。**不含负例**（见 P-15）

### L4 工具层

#### P-11 同一根因报两条 error ⇒ 模型被引导去改两个地方

| | |
|---|---|
| **现象** | 一条轨同时报「startFrame 40 已越出轨道（轨长 32 帧）—— 该动画段永不命中」与「animate 使整层永久不可见：opacity 全程读到 0」 |
| **证据** | 实跑 `validateManifest`：同一轨两条 error 并列 |
| **根因** | ①（段越轨 ⇒ error）与 ③（整层不可见 ⇒ error）**互不排斥**，两条判据各自独立判断"有没有病"，没判断"是不是同一个病" |
| **方案** | ① 命中时跳过 ③（或 ③ 文案改为"因上述越轨段导致"）。**拦截强度不降**：A4 事故轨（`startFrame:31` + `duration:1` 配 32 帧轨）**不命中 ①**（31 < 32），仍由 ③ 单独命中 |

#### P-12 `ask_user_choice` 兜底把原始故障整个丢掉

| | |
|---|---|
| **现象** | 兜底分支 `catch` 后不 rethrow、不打日志、不记错误码，`cause` 直接丢弃 ⇒ 内部故障对运维完全不可见，模型也只能看到一句"提问失败（内部错误）" |
| **根因** | 兜底只写了"把推荐项交回模型"，没写"**留证据**"。同文件其它 catch（3536/3824/3949/4575 行）一律 rethrow ⇒ 两处行为不一致 |
| **方案** | 兜底前 `console.error(cause)` 留痕；abort 判定维持现状（`signal.aborted` + `name==='AbortError'` 双保险，已验证可靠） |

#### P-13 行数棘轮只改了注释、没改数值 ⇒ 缩了却允许回涨

## 二、优先级排列

### 排序原则（四条，按此推导顺序）

1. **先修"会教坏 agent 的东西"**：误报与谎报让 agent 学会无视体检与契约 —— 真问题（ML-02 硬切、ML-13 叠字、P-02 那四个被谎报的字段）会**一起被跳过**。这类改动全是 warning 级或字段表登记，**零破坏性、成本最低**，先做。
2. **再补"契约层缺失的概念"**：P-01 能根治一整类必然复发的问题，但它是**破坏性收紧**（既有 manifest 报红）且需要配套的技能纪律与 storyboard 桥才闭环 ⇒ 独立成批，不与别的混做。
3. **最后补"载体"**：跨项目继承（P-08/P-09/P-10）成本极低，但**必须与 ①② 同批或紧随**——否则 ①② 的结论照样传不到下一个项目，①② 白做。
4. 工具层与编排层的小修收益确定、影响面小，放最后收口。
