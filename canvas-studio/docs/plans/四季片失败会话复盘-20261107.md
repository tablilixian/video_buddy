### 3.1 ③ 的细节：一次典型的"拿自己的计算验证自己的计算"

模型在写入 manifest 前做过一次几何自算（step 178）：

```
earth center px 332.8 345.6 diam 230.4
axis top px [272.5, 206.9] => pct [21.29, 28.74]
```

地轴是 `box{x:26,y:48,w:0.55,h:42}` + `rotation:23.5`。正确顶端 = 中心 + (+dx, −dy) = (333+60, 346−139) = **(393, 207)**。
模型取了 **(−dx, −dy) = (272.5, 206.9)** —— 这是 x 方向符号写反后的**镜像点**，旋转矩形上根本不存在这个角。

之后它把 `21.3 / 28.8` 写进 `anchor`，又在交付报告里用同一个数字"反算验证"通过。**这正是用户纪律③「画面类结论禁拿 manifest 字段自证」所禁止的动作**——只不过这次自证的是自己算错的数。

## 5. 代码级根因（可复现、可反证）

### R-01 【P0】`captionWordsByCharCount` 产出绝对帧，消费端按轨内相对帧比较

- `src/remotion/word-timing.ts:236` — `const origin = Math.max(0, Math.round(input.startFrame))`，窗口 `from = origin + …` ⇒ **绝对帧**
- `src/remotion/components/Caption.tsx:65` — 传入 `startFrame: track.startFrame`（如 V2 = 144）
- `src/remotion/components/Root.tsx:262` — 轨道被 `<Sequence from={track.startFrame}>` 包住 ⇒ 组件内 `useCurrentFrame()` 是**轨内相对帧**
- `src/remotion/components/Caption.tsx:170-175` — `frame >= w.end ? done : frame >= w.start ? active : todo`

⇒ 对 V2：相对帧 96 与窗口 [144…279] 比较，永远落 `todo` ⇒ **全句灰**。
⇒ 且 `charAligned !== null` 会让 `useEnvelope(src, false)`（`Caption.tsx:72`）**关掉解码兜底**，所以连"退回能量包络"都不会发生——这正是"全程灰暗"而不是"稍微不准"的原因。
⇒ V1 因 `startFrame = 0` 恰好正确，构成**天然对照实验**：同一次渲染里 V1 正常、V2 全灰，与"音频解码失败"无关。

**测试为什么没拦住**：`tests/word-timing.test.mjs:108-110` 断言 `startFrame:100 → spans[0].from === 100`，即**单元测试把"绝对帧"语义锁死了**，而组件按另一套坐标系消费。纯函数测试全绿、接线错误无人覆盖。

**修法**：`Caption.tsx:65` 改 `startFrame: 0`（显式 `words` 路径本来就是 0-based，语义一致）；补一条**接线级**测试：渲染一条 `startFrame>0` 的 caption，在轨内 50% 处断言"至少一半字符为 done"。

### R-02 【P1】`draw` 绘制动画在实拍中退化为虚线

- `src/remotion/components/Shape.tsx:82` — `strokeDasharray: 1, strokeDashoffset: 1 - progress`，配 `pathLength={1}`（注释声称"把路径长度归一化到 1"）
- 同一套机制在 `Callout.tsx`、`Chart.tsx` 也在用

实测：`draw` 结束后弧仍为约 10 段、周期≈45px 的胶囊（实段≈30px / 间隔≈15px）。按注释语义本应是一条实线。

**先复现再定修法**（一次 10 行渲染即可定论）：同一条 `d` 渲两帧——一帧带 `draw`、一帧不带——若不带 `draw` 为实线，则确认是 dash 归一化问题；再分别试 `strokeDasharray="1 0"` / 去掉 `vectorEffect` / 去掉 `pathLength` 定位组合因素。
**若确认，临时规避**：不需要绘制动画的弧线不传 `draw`（本片仪表盘弧完全可以首帧即成）。

### R-03 【P0·环境】RenderHost 隐藏窗口的 bundle 子资源从未执行，被误判两次后静默绕过

决定性日志（会话全程 10 次，最后一次 11:48:16）：

```
RenderHost 页面已加载：__csRenderHost=未定义 · 页面文字「Canvas Studio 渲染窗口 booting 等待宿主派单…」
⚠ RenderHost 建窗 8s 后仍不可接管：收到过自报但状态是 error（资源加载失败 SCRIPT
   http://127.0.0.1:43120/canvas-studio/render-host.js%EF%BC%89 —— 页面脚本没跑起来，本单回退画布页
```

**这行 body 文字证明**：页面本身 200 返回、DOM 正常渲染（标题「Canvas Studio 渲染窗口」在），但 `__csRenderHost` 从未出现 ⇒ **`/canvas-studio/render-host.js` 这条 module 脚本没执行**，故障在子资源加载，**不在 URL 里那个全角括号**。

模型先后给了两个相反结论：

1. **11:29:37**：「根因已定位：URL 被拼成 `render-host.js%EF%BC%89`（`）` 的 UTF-8 编码），项目目录名里的全角括号混进了 script src」
2. **11:34:36**：「`）` 只是日志句末的全角括号，我最初的假设错了」

两次相隔 5 分钟、中间还白跑了一次 90s 渲染，却都没做**能定论的检查**（`curl -I` 看 bundle 的 status 与 content-type），最后以"执行器链路的间歇故障"收口，用重试撞过去。

**关键漏检**：`src/render-host/window.ts` 的自查指引第②步写的是"看上一行「页面已加载」里的 body 文字"，而 agent 的取数命令是 `grep -a -i "render-host"` —— **`RenderHost`（驼峰无连字符）匹配不到 `render-host`**，那行最关键的证据被过滤器自己滤掉了。

**定论实验（App 运行时 30 秒内可做）**：

```bash
H='x-dsh-desktop-renderer: 1'
curl -s -D- -o /tmp/rh.html -H "$H" http://127.0.0.1:<port>/canvas-studio/render-host      | head -5
grep -o 'script[^>]*src="[^"]*"' /tmp/rh.html            # 看 src 是否真带 ）、是否被改写
curl -s -D- -o /dev/null   -H "$H" http://127.0.0.1:<port>/canvas-studio/render-host.js  | head -5
# 200 + content-type: text/javascript ⇒ MIME 无罪；403 ⇒ 准入闸；404 ⇒ 路径/括号；503 ⇒ bundle 缺失
```

**同时**：把日志里的 `RenderHost` 字样统一成含 `render-host` 的形式，或在指引里直接给现成 grep 命令（`grep -aE "RenderHost|render-host"`）。这条"指引依赖一个匹配不到的字符串"本身就是可修的工程缺陷。

### 6.2 值得肯定的部分（不是客套，是有方法论价值的三点）

1. **首轮即用 spotFrames**，严格遵守了用户纪律①，且首轮出片后就抓出 4 个真问题（79px 字幕占三行、卡拉OK 全灰、-24 LUFS、片尾重叠），全部修掉。
2. **空片对照实验**：3 轨无音频的最小 manifest 1.3s 通过 ⇒ 干净地把"环境故障 / manifest 故障 / 音频故障"切开。这是正确的排障姿态，可惜后续没有把这个结论用到底（它证明了"无音频可渲"，却没继续追问"有音频为何不渲"）。
3. **额度被拒后不硬闯**：第 4 次探针被拒，立刻转 `quality:"draft"` 全片 + 手搓 `ffmpeg` 抽帧兜底，没有再试错。交付时也确实逐条复述了未决项（隔年取样、23.44° vs 23.5°、首帧空、渲染器故障、V10 静默 4.6s）。

## 10. 定性收尾

这次会话最贵的不是 48 分钟和 10 次渲染，而是**"验证动作被执行了，但验证结论是错的"**：

- `read_image` 调了 18 次 —— 是执行了；
- 五条判据逐条打勾 —— 是执行了；
- 但③的坐标是自算自证、①的虚线没看见、②的末点裁切没看见、最终 high 版的 ①③④⑤ 根本没看。

对 Agent 而言，"看图"如果不配**量化锚点**（像素反算、连通域计数、边界比对），就退化成"看图然后写一段自信的描述"。本片 5 项判据里，凡是需要量化的（③锚点、②末点、④满屏），全部失守；凡是纯定性的（⑤有没有字幕、①指针在不在动），全部通过。

**这也是验收提示词需要补的一课**：判据必须写成"可测量"的形式（谁在哪个像素坐标、偏离多少算不过），否则模型会用形容词交卷。
