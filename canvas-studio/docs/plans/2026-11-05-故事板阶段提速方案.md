## 3. 设计目标 / 非目标

**目标**
- G1 turn 1 系统时间 20.19 min → **≤9 min**，模型步数 35 → **≤5（confirm）/ ≤4（auto）**；这是硬指标，由 §5.6 轮次预算保证。
- G2 用户只被打断 **1 次**，且这次打断有信息增益（不是「全选推荐」）。
- G3 每个推断都带**来源 + 置信度 + 默认标记**，用户看得见、改得动、能追溯。
- G4 数值冲突显式裁决并留脚注，不再靠联网反复论证。
- G5 全阶段只允许**一轮长 reasoning**（第 3 轮计划输出），其余轮次禁止重新规划 / 复述已裁决项。

**非目标（明确不做）**
- 不改模型档位 / 关 reasoning：插件层不持有 DSH 的 LLM 推理配置，碰不到。
- 不动 `generate-queue.ts` / 后端并发：单槽只影响 turn 2 的 TTS / 渲染，对故事板无效（上一轮判断已按日志修正）。
- 不引入 DAG 调度、不做蒸馏 / 量化 / kernel 优化、不碰 dsh 本体。
- **不回填 / 不修复任何历史数据**（项目铁律）：只改产生数据的代码路径，快照只对新建项目生效。
- 不改 `clarification.md:62`「禁止整体确认」背后的**真实约束**：一次性确认必须是**字段级可编辑**的意图卡，绝不能退化成「同意 / 不同意」的整包确认。

## 5. 详细设计

### 5.1 B1 一次性意图卡（拍板 1）

**为什么必须新建载体**：现有 `ask_user_choice`（`src/host-tools.ts:2950-2962`）schema 是**单题**（`question` + `options` + `multiSelect`），工具描述还明写「一次一个问题」；`pendingQuestion`（`src/contracts/project.ts:251`）也是单题记录。`src/client/confirm.ts` 的 `ConfirmHost` 是**破坏性操作确认**——同一时刻只挂一问、返回 `boolean`、取消为缺省，**不能**拿来承载多字段意图卡。CV-444 加固的是这套确认闸门，与点选卡片是两条链路。

**契约**：新增 `confirm_intent_card` 工具（位置与 `ask_user_choice` 同处 `host-tools.ts`），入参为结构化字段数组，返回一张可编辑卡片：

```
confirm_intent_card({
  fields: [
    { key, label, kind: 'choice'|'text'|'readonly',
      value, options?, source: 'explicit'|'inferred'|'default'|'project',
      reason, confidence }
  ],
  timeoutMs?   // 复用 host-tools.ts:1689 的等待上限，超时按默认值继续
})
```

**一次 LLM 调用产出的意图卡内容**（不是让用户填表，是让用户**核对并改**）：

| 分区 | 含义 | 处理 |
|---|---|---|
| `explicit` | 用户原话明说 | **锁定**，压过一切预置 / 配方 / 来源值 |
| `inferred` | 从原话或项目预置推断 | 每条标「默认」+ 依据；卡上可改 |
| `conflict` | 冲突项 | 按 `explicit` 优先裁决，落选值记来源脚注 |
| `needsUser` | 只有用户能答的项 | 通常 0~2 条（如音色人格），卡上必填 |
| `defaults` | 其余采用的缺省值 | 只读展示，供事后回退 |

**结果落点（复用现成通道，不新增持久化结构）**：
- 完整假设清单 → `write_note`（`src/host-tools-artifact.ts:196`，画布持久便签，`list_references.notes` 可读回）；`workflow-mode-prompt.ts:52-53` 已要求两种模式都写便签。
- 一句话意图 → `write_storyboard` 的 `creative.brief`（`host-tools.ts:3853/3866`，契约是字符串，**不塞对象**）。
- 冲突裁决 / 来源脚注 → `facts[]`（`host-tools.ts:3854`，已有 `claim/source/status`）。
- 硬约束 → `constraints[]`（`host-tools.ts:3861/3874`）。

> **实现落定（2026-11-05 22:0x）**：载体为新增 Host 工具 `confirm_intent_card`，**复用**
> `pendingQuestion` 落盘 / 轮询与 `answer` 路由（答案以 JSON 字符串回流），不新增契约结构、
> 不新增路由与 client API。三项待定按默认拍定：**字段上限 12**、**超时复用
> `QUESTION_WAIT_MS`（600s，超时按默认值继续）**、**卡片复用 `.csFieldInput` 设计令牌**。
> auto 判定单独放 `studio-defaults.ts` 的 `autoIntentCardAnswerFor`，与 `autoAnswerFor` 并列，
> 不内联 `mode === 'auto'`（同一规则两份实现必分叉）。`ConfirmHost` 仍不复用。

**模式兼容**：`auto`（放手跑）**不弹卡**，直接 `write_note` 落假设清单后继续（`clarification.md:81`、`studio-defaults.ts` 的 `autoAnswerFor` 已有此语义）；`confirm` 弹**一张**卡。`clarification.md:62` 与 `SKILL.md:38` 的「禁止整体确认」改写为：「禁止**整包同意式**确认；允许且推荐**字段级一次性意图卡**」。

**意图保真三保险**：① 每决定带来源与置信度（现状 5 次点选完什么都没记下）；② 假设清单进画布便签 + `storyboard.creative`，用户可看可改；③ 只把 `needsUser` 设为必填，其余直接执行——不是「不问用户」，是「不拿已经能推断的事去打断用户」。

### 5.2 B2 事实快照跟片走（拍板 2）

**落点**：`~/.videobuddy/projects/<项目目录>/build/fact-snapshot.json`
- 项目目录由 `src/projects.ts:301 projectDir()` 解析，与 `canvas.json` / `storyboard.json` / `jobs.json` 同级（`projects.ts:315-323`）。
- `build/` 沿用 `skills/code-driven-explainer/assets/manifest-builder.mjs` 的既有惯例（零依赖脚本可整段复制进项目 `build/` 直接跑），会话 cwd 已绑定项目目录。
- **放仓库内置的反例**：跨项目复用会污染版本库、且无法「跟片走」；用户已否决。

**格式**：
```json
{
  "schemaVersion": 1,
  "generatedAt": "...",
  "sources": [{ "id": "nasa-gistemp", "url": "...", "sha256": "...", "retrievedAt": "..." }],
  "constants": [{ "key": "axialTilt", "value": 23.5, "unit": "deg", "source": "user", "status": "verified" }],
  "claims":   [{ "claim": "...", "source": "...", "status": "verified|pending" }],
  "conflicts":[{ "key": "axialTilt", "userValue": 23.5, "sourceValue": 23.4,
                 "resolved": 23.5, "footnote": "NASA 23.4° 见脚注" }]
}
```

**生成方式（零新工具）**：新增 `skills/code-driven-explainer/assets/facts-builder.mjs`（与 `manifest-builder.mjs` 同构，零依赖），由 agent 在阶段一 `bash` **一次**生成到项目 `build/`；agent 只读一次结果写进 `write_storyboard` 的 `facts` 节。把 s11–s14 那种「用 4 轮 LLM 算 30 年区间」的活交回脚本——与 `manifest-builder.mjs` 注释里「**排版是确定性计算，不该由模型用 token 去算**」同理。

**裁决规则（写进 skill）**：`用户原话 explicit > 项目预置 > 快照 verified > 联网值`；落选值一律记脚注，不删、不反复论证。这补上 `SKILL.md:40` 缺失的数值外推。

**联网降级**：可选、**单次**、总时限（建议 20s），失败不改数值只标 `pending`；CV-440 的 pending 事实桥（`src/host-tools.ts:3756-3759`，`readPendingFactWarning`）负责在出片时点名，不必在故事板阶段穷尽核实。

**一致性**：`facts[].status` 保持现契约；快照文件带 `sha256` + 采集时间，陈旧可复查；**不回填历史项目**。

### 5.3 B3 短稿一笔写例外（拍板 3）

- 现状：`SKILL.md:55` 与 `references/screenplay.md:23-34` 强制四笔，理由是「让用户在覆盖层看到 3/9 → 4/9 → 6/9 → 9/9 逐节涨」。本次 4 笔参数合计仅 **6,505 字符**（≪ 32,768 token 单步预算，`manifest-builder.mjs:8` 记载该预算被思考吃满才出过事故），却多花 3 轮往返 65.6s + 每轮重新 reasoning。
- 改法：新增**短稿例外**——当 `targetDuration ≤ 60s` 且九节合计 ≤ 单步预算的 1/3（约 ≤10k 字符）时，允许**一笔九节齐写 + `awaitingLanding=true`**，覆盖层一次性 9/9；长片 / 复杂分镜仍走四笔。阈值写进 `screenplay.md` 第 7 条表格下方，总纲 `SKILL.md:55` 只留一句指针（遵守总纲体积闸）。
- `awaitingLanding=true` 的语义不变（`host-tools.ts:3875`）：中间笔不传、收尾笔必传，落地阻断项清零才结束回合。

### 5.6 B1\* 结构化执行计划与轮次预算（35 → 5，贯穿主项）

**为什么必须单列**：§5.1–§5.5 各项都在减轮次，但没有一条能保证减到 5。若只做 B0 / B2 / B3 而不约束编排，模型仍可能「读一批 → 想一轮 → 再读一批」「写一笔 → 复述一轮 → 再写一笔」，轮次会停在 12~18。本项是这些项的**上位约束**，也是 9~11 min 目标能否成立的前提。

**轮次预算（confirm ≤5 / auto ≤4）**：

| 轮 | 输入 | 输出 | 依赖 |
|---|---|---|---|
| 1 | skill 加载 + 分册白名单 | 一批 `read`（≤2 次调用） | B0-2 / B0-3 |
| 2 | 项目预置 + `fact-snapshot.json` | 一次 `read` + 一次 `facts-builder` | B2 |
| 3 | 以上全部 + 用户原话 | **一次性结构化输出**：意图卡五段 + 九节 storyboard + 事实裁决 + 工具序列（**JSON，非散文**） | B1 / B3 |
| 4 | 意图卡回流（confirm） | 落 `write_note` + `write_storyboard` **九节全传** + `awaitingLanding=true` | B3 |
| 5 | 工具结果回执 | 一句话交付说明，**不重新规划** | — |

`auto` 模式无第 4 轮的卡片回流 ⇒ ≤4 轮。

**三条硬规则（写进 skill，走行为断言）**：

1. **计划只产一次**：第 3 轮之后禁止「重新规划 / 复述全片结构 / 再核一次已裁决数值」；工具结果回来只做执行与回执。
2. **唯一长 reasoning 轮 = 第 3 轮**：其余轮次不得出现 >5k 字符的推理；`Hmm / Actually / Wait` 类自我修正只允许出现在计划轮。日志里 25 万字符 reasoning 的主因就是「每轮重述 + 反复核数」，禁复述即根治 R2。
3. **执行不新增工具**：复用 `write_storyboard` 既有的「九节全传 + `awaitingLanding`」（`host-tools.ts:3850/3875`）与 B2 的 `facts-builder.mjs`，**不新增 `apply_plan` 类 Host 计划执行器** —— 那是新的跨进程契约，收益不抵复杂度。只有真机验证发现「一轮输出后模型仍拆成多笔」时，才单独立项评估。

**与「限 / 关 reasoning」的边界**：插件层不持有 DSH 的 LLM 推理配置（§3 非目标），所以**不靠换模型档或关 reasoning**，只靠「减少需要推理的轮次 + 禁止复述」。这也是本项必须显式写进 skill、而不是寄望模型自觉的原因。

**不改 dsh 编排边界**：全部落在 skill 规则与既有工具用法，agent 仍是逐轮 tool call，只是轮数被约束。上一轮讨论中「LLM 规划与媒体渲染彻底解耦、本地 DAG 调度器」那版**不在本方案范围**——那是成片阶段的独立命题，待全量会话的 turn 2 数据到手再评估。

**反向验证**：同题重跑若出现 >5 步，或第 3 轮之后出现 `reasoning > 5k 字符` 的重新规划步，判本项**未落地**（不是「省了几分钟」就算过）。

## 8. 风险与回滚

| 风险 | 处置 |
|---|---|
| 模型不按「一次输出」执行，仍把九节拆多轮 / 事后重新规划 | 轮次预算写进 skill 并做行为断言；同题重跑 >5 步即判未落地，不靠「省了几分钟」放行；必要时才评估 Host 侧计划执行器（**当前不做**） |
