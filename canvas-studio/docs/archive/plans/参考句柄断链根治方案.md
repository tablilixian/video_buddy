## 1. 根因（两层）

### 1.1 直接原因：详情面板静默丢弃断链句柄
`NodeDetailDrawer` 按「参数句柄 ↔ 节点 filename」精确匹配反查缩略图，查不到的条目直接被
`filter` 掉——没有任何「断链」提示。CR-074 只兜了「命中但 url 缺失」，没兜「句柄无持有者」。

### 1.2 根本原因：canvas.json 双写者竞态
- **Host**：惰性 promote / heal 对**已有节点**做字段级回写（`host-tools.ts` 的
  `resolveRefFilenames`、`generate.ts` 的 `healReferenceFilename`）；
- **客户端**：任何画布变更（拖动/视图）走**整档覆盖保存**（`/canvas-studio/canvas` 路由 →
  `ProjectRegistry.writeCanvas`）。

`writeCanvas` 现有的 merge-protect 只保护「客户端不知道的**节点**」（Host 刚生成的产物节点），
不保护「客户端知道、但字段被 Host 中途回写过的**已有节点**」——客户端内存副本里的旧字段值
照样覆盖服务端。

**时间线还原**（本项目实测）：

| 时刻 | 事件 |
|---|---|
| 22:42 | agent 抽取「末帧·分镜 5」节点——创建时**无 filename**（本地产物，未上传 Drama）；客户端拿到无 filename 的副本 |
| 22:47 | 生成分镜 6 → 惰性 promote 末帧图 → 句柄 `ref-7516d08b` **回写进 canvas.json**（客户端副本未同步） |
| 22:47~之后 | 视频异步轮询窗口内用户拖动画布 → 客户端整档保存 → **filename 被旧副本冲掉** |

**铁证**：6 个分镜中断链的恰好是分镜 2/3/4/6 的 Picture 1（全部是「上一镜末帧」、全部经过
惰性 promote 回写）；而所有**创建时就自带 filename** 的节点（定妆照、场景概念图）零断链。

### 1.3 删除节点场景的连带缺陷
末帧类节点被用户删除后：
- 重试下游分镜时 `healReferenceFilename` 按画布反查不中 → 直接抛原始 500，**无自愈路径**；
  而本地 asset 文件仍在磁盘上（删除只改内存态，BUG-005），本可重传修复。
- 详情面板同样断链且无提示。

## 2. 修复方案（只保证新数据正确；老数据不做数据回填，仅显示兜底）

### W1 · 保存路由 filename 字段保护（根治竞态）
`ProjectRegistry.writeCanvas`：merge-protect 从「节点级」扩展到「同 id 节点的 filename 字段级」——
- 节点集合仍以调用方（客户端）为准：删除生效、新增生效、不复活已删节点（现有 preserved 逻辑不变）；
- 同 id 节点的 `filename`：**服务端值恒胜**（`prior.filename ?? node.filename`）。该字段为 Host
  专属（惰性 promote / heal 回写），客户端只**转达服务端签发的值**（上传/抽帧响应），从不编辑。

### W2 · 句柄→资产落盘映射 + heal 自愈（删除场景闭环）
- `promoteAssetFile` 成功时记录「Drama 句柄 → 本地资产文件名」到 `<项目>/assets/reference-manifest.json`
  （`{ version: 1, handles: { "ref-xxxx.png": "<assetFile>" } }`），写操作经模块级串行队列防并发撕档；

> **实施增量（比原计划多修一个既有 bug）**：自测中发现 `writeCanvas` 的 `preserved`
> 保护分不清「客户端还不知道」与「客户端已删除」——**客户端删除的节点会在磁盘上复活**
> （2026-08-25 的「删除复活」修复只治理了客户端读写竞态）。故方案升级为：
> ① `writeCanvas` 增加显式写者语义 `options.author`（仅画布保存路由传 `'client'`，
> filename 字段保护只对客户端保存生效，Host heal 写入不被自己弹回）；
> ② 显式删除协议——客户端 store 记「已删除账本」（`pendingRemovedIds`），随保存以
> `removedIds` 上送，`preserved` 排除之；删除真删、未知节点照旧保护。
- `healReferenceFilename` 节点反查不中时**落盘查映射**：能定位磁盘文件 → 重传拿新句柄返回
  （调用方换名重试）；定位不到 → 返回 null，调用方抛原始错误（不掩盖真因）。
- 旧项目无 manifest → 查不到走原路径报错，天然兼容。

### W3 · 详情面板断链占位卡（显示兜底）
- 参考匹配逻辑抽成纯函数 `resolveReferenceSummaries`（`node-params.ts`，node --test 可直测）：
  返回 `{ name, node | null }[]`；
- `NodeDetailDrawer`：命中的渲染缩略图（现状不变），未命中的渲染「参考已断链」占位卡
  （带句柄名），参考图数量恒等于参数句柄数，不再静默消失。

### W4 · 自测
- 单测：writeCanvas 字段保护（保字段/真删除/新节点不受影响）、manifest 记录与 heal 自愈、
  `resolveReferenceSummaries` 命中与断链；
- `tsc` 全量类型检查（host + client）+ 相关既有套件回归。

## 3. 明确不做（边界）
- **不回填老数据**：老项目已断链的句柄在 W3 中显示为占位卡，不重建映射、不改历史 canvas.json；
- **不做磁盘清理**：删除节点后的 asset 文件残留属 BUG-005，另行处理；
- **不动 Host 内部写路径**：Host 自身的读-改-写已安全，本方案只改 `writeCanvas` 的合并语义。
