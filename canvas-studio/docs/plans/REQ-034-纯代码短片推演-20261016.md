## 〇、一句话结论

**技术上能出片，但"全用 Remotion 代码生成"这条路目前被三件事挡住**：① 组件层**没有真运动**（`shape` / `textCard` 只有淡入淡出，`Transform` 字段只有 `video` 轨能消费）⇒ 「运行规律 / 行星位置」这类**动态图解做不出来**；② 幻灯片风险评分把"没有 video 轨"一律当缺陷，**纯代码片必然 ≥70 分并触发告警**（与 REQ-034「0 次视频模型调用」的目标正面冲突）；③ 总纲第 9 步（逐镜视频）是**无条件步骤**，没有任何入口分流说"这条可以跳过"⇒ 用户的意图在第 9 步就被违背了。

## 一、Remotion 发挥能力的前置条件

### 1.1 六条硬性前提（缺一即失败，且多数是**硬失败**不是降级）

| # | 前提 | 谁保证 | 违反的后果 |
|---|---|---|---|
| P1 | **拍摄定稿已落地**（`workflow.state === 'executing'`） | 用户在覆盖层点「确认落地」 | `render_composition` 在 `FORMAL_TOOLS`（`src/approval-gate.ts:78`）⇒ 未落地直接 throw |
| P2 | **故事板 §04 至少 1 个 scene、1 个 shot**（shot 要有 `visual` 且 `duration > 0`） | `write_storyboard` 写全 | `validateForSeed` blockers ⇒ 落地被拒（`src/storyboard-land.ts:191`） |
| P3 | **所有素材在本项目资产目录内** | 素材先落画布 / 导入项目 | `materializeManifestSources` 域外拒收 + `checkManifestAssets` 缺素材硬失败（`CS-USER-ERR`，不落节点不出片） |
| P4 | **素材轨 `id` = 该素材的画布节点 id** | agent 组装时对照 `list_shots` / `list_references` | 血缘错乱；换成素材轨时若不同步改 `transition` 的 from/to → **校验直接报「引用了不存在的轨道」** |
| P5 | **相邻轨必须有重叠**才能挂转场 | agent 排时间轴 | 首尾相接 → 转场退化为硬切（warning）；完全不相交 → **error 拒绝渲染**（`src/remotion/manifest.ts:368-413`） |
| P6 | **渲染在画布客户端（Electron 渲染进程）里跑** | 桌面 GUI 常开 | 宿主只建工单，客户端不轮询 → 白等到 `CS-RENDER-TIMEOUT`（10min） |

### 1.2 一条容易被忽略的顺序问题

宿主流水线是 **`validateManifest`（`host-tools.ts:2438`）→ `materialize`（:2446）→ `checkManifestAssets`（:2459）→ `reconcileManifestVideoDurations`（:2465）**。也就是说 **「按 ffprobe 真值校正 video 轨时长」发生在校验之后，校正完不再复校**。

实测复现（探针 §6）：模型为了让 video 轨与相邻卡有重叠区而声明 125 帧，素材真值只有 3.0s → 校正为 90 帧 → **用校正后的轨道重跑校验得到 `transition tr-0: from/to 两轨完全不相交，转场无意义`**。这条错误不会被任何环节拦住，渲染照常发生（该转场静默失效）。

### 1.3 能力边界（决定"能做什么"的真实上限）

| 轨 | 字段 | 组件里的实际行为 | 能不能做运动 |
|---|---|---|---|
| `video` | `src` / `transform` / `kenBurns` | `translate/scale/rotate` + 帧级 KenBurns | ✅ 唯一能声明变换的轨 |
| `image` | `src` / `fit` / `caption` | `fit:'kenburns'` → `scale(1 + 0.08·progress)` | ⚠️ **无 `transform` 字段**，只有匀速缓推 |
| `textCard` | `variant` / `text` / `data` / `accentColor` | **只有 `fadeOpacity`**（默认 6 帧淡入淡出） | ❌ 无位移 / 无逐字 / 无入场上浮 |
| `shape` | `shape` / `color` / `box` | **只有 `fadeOpacity`** + 静态百分比坐标 | ❌ **位置不能随帧变化** |
| `transition` | `effect` / `from` / `to` | `fade`/`dissolve` 只改 opacity；`slide` ±12% 位移；`zoom` 0.92↔1 | ✅ **全片唯一的"帧级运动"来源** |

> ⚠️ `manifest.ts:62-71` 的 `Transform` 注释写着「组件用 `interpolate` 对其做帧级动画」，但**实际只有 `VideoClip.tsx` 消费它**。`ImageClipTrack` / `ShapeTrack` / `TextCardTrack` 类型上根本没有 `transform` 字段。
> ⇒ **「行星绕太阳公转」「轨道逐段画出」「行星按距离排开再高亮」这类画面，当前做不出来。** 能做的只有「卡片序列 + 转场 + KenBurns 缓推」这一档。

## 三、四方案实测（探针输出）

创意固定：30s / 30fps / 900 帧 / 16:9 / 1280×720；旁白 112 字，真值 30.0s。

| 方案 | 构成 | `validateManifest` | 幻灯片风险分 | 音轨角标 | 血缘 sourceIds |
|---|---|---|---|---|---|
| **S1** | 纯代码：7 张卡首尾相接、无转场轨 | ✅ ok（0 错 0 警） | **80** ⚠️ 告警 | `bgm` | `[]` |
| **S2** | 纯代码：卡重叠 8 帧 + fade/slide/zoom/dissolve 轮换 | ✅ ok | **70** ⚠️ 告警 | `bgm` | `[]` |
| **S3** | S2 把两张卡换成静态图（KenBurns）—— **仍 0 次视频模型** | ✅ ok | **70** ⚠️ 告警 | `bgm` | 2 个节点 |
| **S4** | S3 再插入 1 条 ~4.2s 真视频轨（占 14%） | ✅ ok | **70** ⚠️ 告警 | `native+bgm` | 3 个节点 |

**S4 是最反直觉的一条**：加了一条真视频轨，风险分**纹丝不动（70）**。因为三个必清维度一个都没清掉：

```
● 静态占比   权重 30   图片+文本卡占 104%（阈值 70%）
● 运动密度   权重 25   video 轨 1 条、时长占 14%（阈值 20%）
● 镜头数     权重 15   video 轨 1 条（<60s 阈值 3）
```

**阈值反推**（30s / 900 帧）：要把分数压到 60 以下，需同时满足 —— ① 非 image/textCard 时长 ≥ 270 帧（9.0s）；② video 轨合计 ≥ 180 帧（6.0s）；③ video 轨 ≥ 3 条。**⇒ 现实门槛是"让出 30% 的时长给视频"。**

**而纯代码片（无 video 轨）必然命中 30+25+15 = 70 分 ≥ 阈值 60 ⇒ 必然弹告警**，告警文案是「成片偏向幻灯片（静态占比、运动密度、镜头数），**建议增加实拍/生成视频片段**」。

## 四、发现的问题

### A 类：产品缺陷（建议修）

| # | 问题 | 落点 | 证据 |
|---|---|---|---|
| **D1** | **静态占比可以 > 100%**：分子按各轨 `durationInFrames` 直接累加，重叠轨使它超过总时长，note 输出「图片+文本卡占 **119%**」这种不可能的数值 | `src/remotion/slideshow-risk.ts:67-68` | 探针 S2/S3 实测 119% |
| **D2** | **「节奏单调」这一维实际恒不命中**：`contentTracks` 把 `shape` 也算作内容轨，而每份合格 manifest 都有一条全长背景 shape（30s）⇒ 标准差被拉到 8.11~8.59s，永远大于阈值 0.5s | `src/remotion/slideshow-risk.ts:75-77` | 探针 S1 实测 8.59s / S2 8.11s |
| **D3** | **纯代码片必然告警，且告警建议与产品目标相悖**：无 video 轨 ⇒ 30+25+15 = **70 ≥ 60 恒定命中**；告警却建议「增加实拍/生成视频片段」—— 这正是 REQ-034 目标 G2 要避免的 | `slideshow-risk.ts:26`（阈值）与 :121-124（文案） | 探针 S1/S2/S3 全部 ≥70 |
| **D4** | **校验发生在时长校正之前，校正后不复校**：`reconcileManifestVideoDurations` 缩短 video 轨后，原本合法的转场交叠失效，无人拦截 | `src/host-tools.ts:2438` vs `:2465`；`src/remotion/timing.ts:170-212` | 探针 §6：校正后重跑 → `transition tr-0: 两轨完全不相交` |
| **D5** | **每句字幕交界会闪一次背景**：`deriveSubtitleTiming` 的呼吸间隔（0.15s）在句间留 **3~5 帧空档**；叠加每卡自带 6 帧 `fadeOpacity` ⇒ 交界处**两卡不透明度同时为 0** | `timing.ts:113-117,142`（间隔）+ `timing.ts:30`（fade=6） | 探针 §1：frame 129 叠合不透明度 = **0.00**；句间空档 4/3/4/5/4/4 帧 |
| **D6** | **纯代码片的音轨角标显示 `bgm`，用户看不出"这里有旁白"**：`voiceOver` 被并入 `bgm` 位（枚举里没有「旁白」独立位） | `manifest.ts:429-444` | 探针 S1~S3 角标全为 `bgm` |
| **D7** | **纯代码片血缘为空** ⇒ 成片节点在画布上没有一条连线，用户看不出这条片子是"从哪来的"（因为没有素材轨可指） | `manifest.ts:446-463` `collectManifestSourceIds` | 探针 S1/S2 实测 `[]` |

### B 类：组装陷阱（skill 侧应写进口径，否则模型必踩）

1. **换轨要同步改转场**：素材轨 `id` 必须是画布节点 id，所以"把一张 textCard 换成 image"要同时改所有引用它的 `transition.fromTrackId/toTrackId`。实测漏改 → **4 条 error**（探针首轮就踩了）。
2. **转场必须重叠**：首尾相接 → 退化为硬切（warning）；不相交 → error。
3. **不要"声明偏短"来截断素材**：video 轨声明偏长会被校正、偏短会截断画面，两端都不报错。
4. **不要给纯呈现轨填素材节点 id**（`t0` 这类占位照抄到素材轨会让血缘指向不存在的节点）。

### C 类：流程缺口

**D11 · 没有任何入口分流说"这条片子可以跳过第 9 步"。** `clarification.md §入口分流` 的五条判据里，纯文字创意一律「从工作流第 1 步全流程走」，而总纲第 9 步（逐镜视频）**无条件**；同时 `render_composition ∈ FORMAL_TOOLS` ⇒ 必须先落地 ⇒ **纯卡片片也要先编出 ≥1 个 shot**。结果：一个"全用 Remotion"的创意，在第 9 步就被违背了意图（agent 会去出关键帧 + 逐镜视频），第 10 步才有机会二择。

### D 类：能力缺口（本期范围外，但正是这个创意想要的）

**D8 · 组件层没有帧级运动**（见 §1.3）。"运行规律 / 行星位置"要的是**动态图解**，当前只能退化成：
- 用 `image` + `fit:'kenburns'` 出静态行星插画（要调图像模型，就不是"纯代码"了）；
- 或用 `shape` 的 `circle` 摆静态位置 + `transition` 的 `slide` 制造位移错觉（**是跳变，不是连续运动**）。

> 对照：资料库样例 "How Salt Made History" 用的是 *hand-authored motion graphics*（动画地图 / 词源揭示 / 时间线逐段画出），本期 §2.2 明确「动画地图**不在本期**」。本创意正好踩在这个缺口上。

## 六、这个创意在当前版本下的**最优写法**（可直接复制）

现状下"全用 Remotion"的意图**必须显式写出来**，因为它与总纲的默认路径相反。三句话缺一不可：

```
【先做一件事】在画布顶条勾选 code-driven-explainer 技能。
（作用：写入项目 skills.json → 经 order 154 注入 system prompt，
 模型第一轮就看到"用户已选定"，且规则明写"用户选定即视为已确认，不要再问"）

【创意】做一条 30 秒的科普短片《太阳系速览》，全部画面用代码合成（render_composition）：
1. 不要生成任何视频片段、不要逐镜出图；画面只由字幕卡、数据卡、要点卡、形状与转场构成。
2. 结构：钩子（前 3 秒一句定调）→ 主体 4 个要点（八颗行星 / 太阳质量占比 / 尺寸对比 / 著名卫星）→ 收尾一句。
3. 数字类信息用数据卡：太阳质量占比 99.86%、木星直径 ≈ 地球 ×11。
4. 旁白中文，一句一条字幕卡，每句 ≤18 字。
5. 画幅 16:9、30 秒、30fps。
```

**为什么第 1 条必须写**：总纲第 9 步（逐镜视频）是**无条件**步骤，不显式否掉，agent 会照常去出关键帧和逐镜视频。而总纲 `shot-format.md` 有「**用户计划优先（C-9）**：用户指定用什么工具就照做」—— 显式指定 `render_composition` 是被总纲承认的。

**为什么第 2/3/4 条值得写**：它们就是把 `explainer-patterns.md` 的「钩子 → 主体（3±2 要点）→ 收尾」「数字用 dataCard」「单卡 ≤18 字」直接喂给 agent，省掉一轮来回。

**改造（P0-B）落地后的理想写法**：一句话即可 ——
> `做一条 30 秒纯代码生成的太阳系科普短片，讲八颗行星、太阳质量占比、大小对比和著名卫星`

## 七、不要误判为缺陷（刻意为之 / 已知取舍）

- **幻灯片告警**：在纯代码片上是**语义冲突**，不是渲染错误；不影响出片，`warnings` 会转告用户。
- **词级字幕（KTV 式）**：后端 TTS 响应无时间戳 ⇒ 无数据源，用估算伪造成逐字高亮观感会明显脱节。
- **动画地图 / 真实素材语料库（Archive.org、NASA、Wikimedia）**：独立 P2 线，本期明确不做。
- **域外素材拒收**：CSR 渲染在浏览器环境取不到域外文件，拒收是为了避免"静默 404"；要不要支持"自动导入拷贝进 assetsDir"是独立决策。
- **成片不走 `runShotQc`**：镜头级质检对成片的适配性尚未取证（R2），当前唯一护栏只有风险评分。

## 八、能力上限由什么决定（2026-10-16 第二轮取证）

> 本节为**只读取证**，未改任何产品代码；结论全部来自读源码 + 一次 `node -e` 实测。

### 8.1 一条反直觉的实测

**Remotion 的动画引擎一次都没用上。** `interpolate` / `spring` / `Easing` / `random` / `useVideoConfig` 在 `src/remotion/` **零引用** —— `manifest.ts:61` 注释写着「组件用 `interpolate` 对其做帧级动画」，但从未 import。已安装的 `remotion@4.0.535` 整套 API 处于闲置状态。

⇒ **上限不是 Remotion 给的，是这个仓自己的 4 个文件给的。**

### 8.2 四道收窄闸门（皆为封闭白名单，串联）

| 闸 | 落点 | 现在卡在哪 |
|---|---|---|
| ① 契约 | `manifest.ts:153-157` | `TRACK_TYPES`(5) / `TEXT_VARIANTS`(4) / `SHAPES`(4) / `EFFECTS`(4) / `IMAGE_FITS`(3)，全是 `new Set([...])` |
| ② 组件 | `components/*.tsx`（共约 250 行） | 字段被**消费**才算数。全部帧级运动只有 3 处：`fadeOpacity`、`ImageClip` 的 `1+0.08·progress`、`transitionOverride` 的 opacity / translateX 12% / scale |
| ③ 时序 | `timing.ts` | 运动幅度是**常量**：`DEFAULT_FADE_FRAMES=6`、slide 12%、zoom `0.92+0.08p`、kenBurns `0.06` |
| ④ 渲染 | `client/remotion-render.ts` | CSR + `renderMediaOnWeb`，mp4/h264/aac 固定；**无 `z-index`**，层叠靠 `tracks` 数组顺序 |

**根因一句话**：agent 的唯一输出通道是**一段 JSON 字符串**（`host-tools.ts:2420` 的 `manifest: { type: 'string' }`）。JSON 只能表达**数据**（在哪里 / 多久 / 什么色），表达不了**程序**（怎么随时间变）。而「运行规律 / 行星位置」的实质是程序（位置 = 时间的函数）。

### 8.3 三处具体的天花板螺丝

1. **`Transform` 只挂在 `VideoClipTrack`**（`manifest.ts:77`）。5 种轨里只有 `video` 能设 `x/y/scale/rotation`；`Shape` 只有 `box`，`TextCard` 位置完全写死在组件内。
2. **`fadeOpacity` 是不可关闭的隐式行为**：每条轨被强制首尾淡入淡出 6 帧，契约里没有字段能关。`subtitle` 的「硬切」是 `TextCard.tsx:22` 传 `fadeFrames=0` 的**组件内特例**，不是契约能力。⇒ 「硬切入场 + 入场动画」这个最基础组合做不出来。
3. **越界字段静默丢弃**（实测）：给 `textCard` 塞 `animate` / `enterAnimation` / `motion` 三个字段 → `validateManifest` 返回 **`ok=true`、`errors=[]`、`warnings=[]`**。因为校验只查「已知字段是否合法」，**从不拒绝未知键**；而工具入参是 `manifest: string`，JSON Schema 也管不进字符串内部。

   ⇒ 后果比其他两条严重：**模型以为做了动画，成片里没有，且没有任何一方告诉它。** 这是最隐蔽的一种限制 —— 不是「做不到」，而是「做不到还不知道」。

## 九、扩展阶梯（L0~L4）

| 档 | 手段 | 能做出什么 | 性质 |
|---|---|---|---|
| **L0** | 现状 + 组合技巧（多卡错开 `startFrame` 拼 stagger） | 只能「切」与缓推 | 0 改动，东西不会「动」 |
| **L1** | `animate` 关键帧 DSL，落在 `BaseTrack` | 位移 / 缩放 / 旋转 / 变色；卡片滑入、尺寸对比、颜色渐变 | **建议先做**；也是 L2 的前置 |
| **L2** | 语义运动 primitive：`orbit` 公转 / `draw` 画线 / `wave` 脉动 | 行星绕太阳转、画轨道线、周期振荡 | 「关系与过程」的正解 |
| **L3** | 效果包 `effect` 枚举（粒子场 / 光扫 / 噪点） | 观感提升大 | 只能选名字，不可组合 |
| **L4** | 受控组件白名单：`component` + `props`，组件在仓库里由人审 | 任意预置场景 | 新增架构；是 devdoc §1.2「不做 LLM 生成 JSX」的**合规替代**，排最后 |

### 9.1 L1 契约草案（全 `optional` ⇒ 非破坏）

```ts
export interface VisualState {
  x?: number; y?: number; scale?: number; rotation?: number; opacity?: number
}
export interface Animate {
  from: VisualState
  to: VisualState
  startFrame?: number        // 轨内相对帧，缺省 0
  durationInFrames?: number  // 缺省 = 整个轨长
  easing?: 'linear' | 'easeIn' | 'easeOut' | 'easeInOut'
}
// BaseTrack 加一行 ⇒ 5 种轨全覆盖
animate?: Animate | Animate[]
```

**四条实现纪律**（不守会做出「看起来能跑其实不稳」的东西）：

1. **插值放 `timing.ts` 纯函数**，不写进组件 —— `manifest.ts` 文件头明写「本文件零 Remotion 依赖」，Host 侧要能算、`node --test` 要能覆盖、`probe-*.mjs` 要能验。
2. **严禁 CSS `transition` / `@keyframes`** —— Remotion 是逐帧截图，CSS 动画走真实时钟 ⇒ 同帧号拍到不同结果，同一 manifest 渲两次不一样。本仓已用「`document.fonts.load` 等就绪」回避过同类坑（等价 `delayRender()` 纪律）。
3. **easing 白名单四个 + 端点收敛**，不开放任意贝塞尔（模型会编非法控制点）。
4. **抽 `useAnimatedStyle(track, frame)` hook** 供 4 个组件各接一行 —— 避免重演「加了字段但组件忘了读」，那正是 `Transform` 的病根。

### 9.2 两条正交必修项（近零成本，建议随 L1 一起）

- **未知字段告警**：`validateManifest` 加「契约外键 → `warnings`」，**不阻断**（不破坏现有输入）。约 20 行，收益最大 —— 没有它，模型写 `animation`（少个 e）仍是静默失效。
- **`fadeFrames` 可配**：`BaseTrack` 加 `fadeFrames?: number`（0 = 硬切），默认 6 不变；把 `TextCard.tsx:22` 的 `subtitle` 特例收敛为「等价于 `fadeFrames: 0`」。
- 顺带把 `Transform` 从 `VideoClipTrack` 上提 `BaseTrack`，消掉不对称。

### 9.3 风险面与验证方式

**好消息**：`manifest` 是 `render_composition` 的**一次性入参**，渲完即弃、**不落库、无存量数据** ⇒ 这是本仓少数「改契约不需要任何回填 / 兼容处理」的地方。新字段全 optional，老写法行为完全不变。影响面 = `validateManifest` + 5 个组件 + 工具描述 + 4 处 skill 分册 + 2 个测试文件。

**必须如实说明的验证局限**：单测只能断言「纯函数输出正确」与「组件接线存在」，**断言不了「画面真的动了」**。可行做法是用本仓已有的 `scripts/remotion-verify/` 渲 2 帧（`startFrame` 与中段）比对像素差异 —— 这是能真跑的路径，也是建议的验收方式。

### 9.4 待拍板

1. 只做 **L1**，还是 **L1 + L2 的 `orbit`**？
2. 两条正交项（未知字段告警 / `fadeFrames` 可配）是否一起做？（建议一起）
3. 全量 `test:smoke` 现在跑，还是与 L1 批次合并后跑？

## 十、Remotion 能力盘查（2026-10-16 第三轮，只读取证）

> 数据来源：`node -e` 直接枚举已装包的运行时导出 + 全仓 import 盘点（非估算）。**未改任何产品代码。**

### 10.1 Remotion 自身的上限 = 三条轴，都不是「能画什么」

1. **绘图能力 ≈ 浏览器能画的一切**。核心 59 个运行导出里就有 `HtmlInCanvas`（任意 HTML/WebGL 进视频）、`CanvasImage`、`IFrame`、`createEffect`（效果栈）、`Interactive`（可视化编辑）⇒ 绘图不是约束。
2. **真正的硬约束是「确定性」**：帧 = 帧号的纯函数。派生三条纪律 —— `random()` 必须用 Remotion 的（带种子伪随机）、**不可用 CSS `@keyframes`/`transition`**（走真实时钟）、异步（字体/取数）必须走 `delayRender()` / `continueRender()`。这是 Remotion 与「随便写个网页」的分界线。
3. **规模与形态上限由渲染后端决定，共四条路线**（本项目只走一条）：

| 路线 | 包 | 本项目 |
|---|---|---|
| A · SSR（headless Chrome 逐帧截图） | `@remotion/renderer`（22 导出） | ⚠️ 已装、**零引用**；本机 macOS 14.6 < 15，加载即触发 Remotion 自身 `rendering may not work` 警告 |
| B · CSR（浏览器 WebCodecs） | `@remotion/web-renderer` | ✅ **唯一走的路线**，API 面用满 |
| C · Lambda / Cloud Run 分布式 | 未安装 | 未用；devdoc §1.2 明确不做 |
| D · 应用内预览 / 缩略图 | `@remotion/player` | 已装、**零引用** |

**补充认知**：Remotion 实为两套东西 —— 「渲染引擎」+「一整套视频原语库」（transitions / shapes / paths / media-utils / captions / player / renderer…）。本项目只用了引擎的最小子集，**原语库几乎完全没碰**。
