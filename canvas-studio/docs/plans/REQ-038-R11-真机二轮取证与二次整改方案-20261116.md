归总：**21 次是文档缺口**、**10 次是合法诊断**、**3 次是规则空白**。

### 2.1 纪律三重约束为什么没挡住

优先级从高到低的三个约束全都在场：

1. **用户原话**：「不要为了版式去读 src/remotion 源码」；
2. **SKILL 纪律节**：「禁止用 bash 读 `src/remotion/**` 推契约」+「生成物没覆盖到的：先点名缺口再读」；
3. **`scaffold_manifest` 工具描述**：「别用 bash 去 `grep src/remotion/**` 枚举卡或确认「能不能表达」」。

它仍然读了 34 次，而且**每一次的 reasoning 都能说清自己缺的是什么**（例：+03:54「B1 uses `键:值` separated by `;` or newline. Use newline?」）。

> **机制结论**：纪律只能阻止「不必要的查」，无法替代「不存在的答案」。
> 当模型面临「必须写对，但文档不给规则」时，违反纪律是**唯一能完成任务的选择**。
> R11 把空转诊断为「纪律问题」，这个诊断是错的。

### 2.2 一个更容易被忽略的事实

它读文档的顺序是对的（卡目录 → 内容规格 → 几何 → 屏表 → 能力边界，全在前 1 分钟），
说明**三份生成文档的入口位置没问题**。问题在**每份文档的深度**：
它们回答「有没有」，不回答「怎么写」。

## 3 三个真实产品缺陷（按严重度）

### 3.1 【P0·R11 回归】`render_composition` 输出 schema 漏声明 ⇒ 竖屏渲染回执被整条拒收

**现象**（+12:37 原文）：

```
Error: tool "render_composition" returned invalid output:
  "value.report.textFit[0].heightLimited" is not a declared property (additionalProperties: false)
  "value.report.textFit[1].boxHeightPx"    is not a declared property (additionalProperties: false)
  "value.report.textFit[3].fontPx"         must be an integer
```

**根因**：R11 给 `TextFitReportEntry` 加了两个字段（`text-fit-audit.ts:40-42`，`heightLimited` 是**必填**），
但 `host-tools.ts:253` 的 `textFit` output schema 只登记了 8 个字段，而该对象是 `additionalProperties: false`。
⇒ **只要有一条文字轨被盒高限号，整条渲染回执就被判非法。**

**这一条在竖屏下必然触发**：竖屏 `title` 单元 `cell.h:24` 投影后盒高 138px < 满号 149px，
`heightLimited` 恒 `true`（实测：7 字 → 115px / 9 字 → 88px，两条都 `heightLimited=true`）。

**`fontPx must be an integer` 是另一个独立成因**（实测确认，不是推测）：缩号循环 `timing.ts:1250`
用 `Math.floor` 递减，但**兜底值是小数** `minFont = base × 0.55`：

```ts
fontPx = Math.max(minFont, Math.floor(fontPx * 0.94))   // 缩到下限时返回 minFont
```

实测两条：`title` 极窄盒 ⇒ `fontPx = 81.95`（`atMinFont=true` / `overflow=true`）；
`bullets` 极窄盒 ⇒ `fontPx = 46.75000000000001`（还带浮点尾巴）。
⇒ 极端窄盒（正是「最严重档」）的回执**同时踩两个坑**，必然被拒。

代价：这一轮的**第 2 次渲染（14 秒 + 5 张抽帧）整条回执丢失**，模型在 +13:10 判断为
「平台返回 schema 的 bug，不是 manifest 的问题」并绕行 —— 它猜对了，但下一次不一定。

> 同一个坑已经踩过两次：`host-tools.ts:251` 注释写着 CV-146「漏声明 = 字段被静默剥掉」，
> `:272` 注释写着 RQ-19「8 次成功渲染 8 次回执全丢」。**这是第三次，而且是我在 R11 亲手引入的。**

### 3.2 【P0·真 bug】`bullets` 变体的容器宽度按画布宽算 ⇒ 窄盒必裁首字

**代码**（`src/remotion/text-fit-plan.ts:278-298`）：

```ts
if (variant === 'bullets') {
  const containerWidthPx = Math.min(
    fontPxOf(BULLETS_CONTAINER_MAX_PX),        // fontPxOf(900) = 1600 @1080×1920
    Math.max(fontPxOf(300), canvasW * 0.9),    // max(533, 972) = 972
  )                                            // ⇒ 972，完全不看 box.w
```

**与 `title` 分支的对比**（同文件 `:258-264`）——title 的注释就写着同一类事故：

```ts
// 0B-4 缺陷修复：旧实现**完全没看 box**（一律按画布 90% 算），窄盒里的标题
// 算出的字号偏大 ⇒ 折行后被盒子的 `overflow:hidden` 两侧裁掉。
const boxWidthPx = box === undefined ? undefined : (box.w / 100) * canvasW
```

⇒ **同一类缺陷，`title` 修了，`bullets` 漏了。**

**实测算式**（竖屏 1080×1920，A4 的 `box` 是 `{x:44,y:52,w:64,h:46}`，`recipe-cards.ts:331`）：

| 量 | 值 |
|---|---|
| `containerWidthPx` | `min(1600, 972)` = **972px** |
| 盒宽（投影进 `cell.w:100` 后） | 64% × 1080 = **691px** |
| 溢出 | 972 − 691 = 281px，居中 ⇒ **两侧各裁 140.5px** |
| 圆点占位 `BULLET_DOT_ALLOWANCE_PX`(42) × 1.778 | **74.7px** ⇒ 完全在裁剪区内 |

⇒ 圆点消失 + 首字被吃。抽帧证据：「规则写下了吗」→「**则**写下了吗」、「跌破怎么办」→「**破**怎么办」。

**16:9 为什么正常**：`fontPxOf(900)=900`、`canvasW*0.9=1728` ⇒ `container=900`；
盒宽 64%×1920=1228 > 900 ⇒ 不裁。**所以这不是「任何宽度都裁」**，模型在 +24:35
交付里写的「A4 的要点卡在任何宽度下都会裁掉首字」是**过度泛化**（它自己在 +19:11 已推算过 16:9 正常）。

**影响面**：所有 `bullets` 变体的卡（A4 及同类）+ 所有竖屏 / 窄盒场景。

### 3.3 【P1·真 bug】DAT3 卡内 `summary` 与 `chart` box 相交

`recipe-cards-data.ts:85-89`：

| 轨 | box | 占画布 |
|---|---|---|
| `chart`（柱状） | `{x:50, y:56, w:76, h:52}` | x 12–88% / y 30–82% |
| `summary`（数据卡） | `{x:22, y:30, w:34, h:26}` | x 5–39% / y 17–43% |

相交区 = x 12–39% × y 30–43% ⇒ **占 summary 自身 39.7%**。抽帧里就是「数据浮卡压在柱顶」。

**附带问题**：`ctx.label` 在同一张卡里被用了两次 —— `-title` 轨（`{x:50,y:12,w:40,h:6}` 的屏内小标题）
与 `-summary` 轨（数据卡标题）都写 `text: ctx.label` ⇒ **同一句分组名在一屏里出现两遍**
（用户给的 `label` 是 `波动率 | 高→卖 | 低→买` 这种长串时尤其明显）。

> 注意：spec 层的格位相交校验（>5% 拒收）**管不到卡内**，所以这个缺陷永远不会被闸发现。

## 4 一条假信息 + 一个能力空白

### 4.1 假信息：卡目录把 DAT3 的 `copy` 判成「多行」

`card-catalog.generated.md` 现状：

| 卡 | copy 列 | 源码实际 |
|---|---|---|
| DAT3 | **多行** | `copy.split(/[；;\n]/)` 后**每行再按 `lastIndexOf(':')` 拆成 k / v**，`v` 非数字则落 `i+1` |

⇒ 按目录写 `买入\n卖出`，会得到 `labels=['买入','卖出']`、`values=[1,2]`（自动编号），
**不是用户要的 99 / 101**。模型读源码后在 +07:35 才搞对（`买入:99; 卖出:101`）。

根因：`gen-card-catalog.mjs` 的 `probeSlotUsage()` 只探「这个 slot 用不用」，**不探「怎么拆」**。
这是设计缺陷，不是笔误 —— 同一漏洞还会在其他「多段 + 二级解析」的卡上复发。

### 4.2 能力空白：模板库 10 个对竖屏科普卡 0 命中

`list_templates` 返回 10 个，全部 ❌，理由高度一致：

```
❌ 内容约 130 字，而数据 · 仪表盘扫针 的必填槽位总共只装得下 34 字
❌ 这一屏分给模板的 6.7s 不在屏级适用区间 3–5s 内
❌ 你列了 6 条要点，只有 3 个卡片位
```

⇒ **10 / 10 全是 16:9 · 4–5s · 槽位 ≤7**。判据（`template-gate`）本身工作正常，
**是库里的货不匹配竖屏卡叙事**。模型的处理是对的（0 个 ⇒ 自由编排 + `write_note` 记录）。

## 5 根因分层（为什么 R11 的判断偏了）

| 层 | R11 的判断 | 本轮证伪 |
|---|---|---|
| L1 纪律 | 空转 = 纪律不够硬 ⇒ 加「三禁 + 预算 + 三级降级」 | 三重约束在场仍 34 次；每次都能说清缺什么 ⇒ **是答案缺失，不是纪律松弛** |
| L2 文档 | 生成「有/没有」的权威清单就够 | 模型要的是**规则**（怎么拆、认哪些分隔符、谁可替代谁），不是**存在性** |

| L4 反馈 | 渲染回执如实返回 | 回执自己会被 schema 拒收（§3.1）⇒ **最该可信的一环反而失效** |

## 6 整改方案

> 排序原则：**先修产生错误数据/回执的路径（P0），再补文档深度（P1），最后补能力（P2）**。
> 每条都给「反向变异」的验法 —— 守卫必须能变红，否则不算闸。

### P0-1 补 `textFit` 的 output schema 声明（R11 回归）

- **动作**：`src/host-tools.ts:253` 的 `textFit.items.properties` 补
  `heightLimited: {type:'boolean'}` 与 `boxHeightPx: {type:'integer'}`；
  `fontPx` 改 `{type:'number'}`（或让 `planTextFit` 返回前 `Math.round`，二选一，见下）。
- **同步加闸**：新增 `tests/tool-output-schema-drift.test.mjs` ——
  跑 `planTextFit` + `auditTextFit` 出一批真实条目，断言
  **「条目实际键集合 ⊆ schema 声明的 properties」**，对 `render_composition` 全套 output 都做一遍。
- **反向变异**：删掉 schema 里任一字段 ⇒ 该测试必须红。
- **为什么要做闸而不是只补字段**：`host-tools.ts` 有 **53 处 `additionalProperties: false`**，
  靠人记必然再漏。这是第四次同类事故（CV-146 → RQ-19 → R11），必须有机器守。
- **`fontPx` 怎么修**：**两处都做，各自治不同的病** ——
  1. `planTextFit` 返回前置 `Math.round(fontPx)`（治浮点尾巴 `46.75000000000001`，
     避免脏值流进 `textFitWarnings` 文案与报告）；
  2. schema 的 `fontPx` / `baseFontPx` 放宽为 `{type:'number'}`（**不要**指望 plan 层一定整型 ——
     `atMinFont` 判定依赖未取整的原值，契约上「渲染字号」本就不是计数量）。
  只做 1 不改 schema ⇒ 仍可能因为别的路径出小数；只做 2 不改 plan ⇒ 报告里出现 `46.75000000000001px`。

### P0-2 修 `bullets` 的容器宽度口径（照 `title` 的修法）

- **动作**：`text-fit-plan.ts:283` 的 `containerWidthPx` 改为「先按 `box.w` 算，再取 min 上限」：

  ```ts
  const boxWidthPx = box === undefined ? undefined : (box.w / 100) * canvasW
  const containerWidthPx = Math.min(
    fontPxOf(BULLETS_CONTAINER_MAX_PX),
    boxWidthPx !== undefined && boxWidthPx > 0 ? boxWidthPx : Math.max(fontPxOf(300), canvasW * 0.9),
  )
  ```

- **验收**（已实测现状，修后按此断言）：竖屏 A4（`box.w:64` / 1080 宽）——

  | 量 | 现状 | 修后应为 |
  |---|---|---|
  | `containerWidthPx` | **972**（实测） | **691** |
  | `maxWidthPx` | **897**（实测） | **616** |
  | 每侧被裁 | **140.4px**（实测 280.8/2） | **0** |

- **16:9 零回归**（实测）：`min(fontPxOf(900)=900, box 宽 1228.8)` = **900**，与现状相同。
- **反向变异**：把 `boxWidthPx` 那行删回原式 ⇒ 竖屏测试必红（`containerWidthPx > box 宽`）。
- ⚠️ **必读的连带影响（不是副作用，是正确的代价）**：可用宽 897 → 616（窄 31%），
  `bullets` 的缩号循环会把字号继续压低以装下同样文案。**这会打穿 R11 的实测数值表**：

  | 位置 | 现在写的 | 修后实际（已实测） |
  |---|---|---|
  | `spec-geometry.generated.md` A4 算例 | 85→**79**px | 85→**60**px（生成器已重跑） |
  | `tests/spec-geometry-drift.test.mjs` 硬编码 | `fontPx === 79`（且 box 是手写 w:100 的旧误差） | **60**，box 改用 `projectedBox()` 与生成器同源 |
  | `tests/req038-r11-test-input.test.mjs` 第 5 条 | 85px（第 2 屏 copy 短，不缩号） | **不变**（实测确认两种容器下都 85） |
  | R11 参考片文档 §4「A4 要点」行 | 85px | 85px（短句）+ 可用宽 616px、长句缩号说明 |

  ⇒ 修字号漂移必须和重跑 `gen-spec-geometry.mjs` 放在同一笔提交，
  否则下一轮真机会把「字号变小」误判成新 bug，重演本轮 §3.2 的 14 分钟。
- **另一个连带**：修完 A4 在竖屏可用后，本轮「A4 换 UI4」这个降级**不再必要**。
  R11 测试输入 §3.1 里 S2/S6 用的 A4 可以保留 —— 但要等 P1-3 的第 0 档上线后再决定，
  因为「换卡」作为兜底仍是合法路径。

### P0-3 DAT3 卡内相交 + `label` 复用

- **动作（最小）**：`summary` 的 box 从 `{x:22,y:30,w:34,h:26}` 移到 `{x:50,y:22,w:40,h:18}`
  （与 chart 的 y 30% 以上不重叠），并让 `summary.text` 只吃 `ctx.label` 的**第一段**
  （`label.split('|')[0]`），不再整段打两遍。
- **或（更保守）**：在卡目录与 `spec-capability` 里**显式登记「DAT3 卡内 summary 与柱图相交，
  窄格位会更明显」**，并给一个「只要柱图不要浮卡」的开关。
- **验收**：两轨 box 相交面积 = 0；抽帧里柱顶不被浮卡压。
- **反向变异**：把 box 改回原位 ⇒ 新增的「卡内轨不相交」断言必红。

### P1-1 卡目录升级到「解析规则」粒度（治 §2 段②的 12 次）

这是本轮性价比最高的一条：**12 次探查里有 12 次都在问同一件事——`copy` 到底怎么拆。**

- **动作**：`gen-card-catalog.mjs` 的 `probeSlotUsage()` 从「用不用」改成「**拆成什么**」：
  对每个 slot 喂一组**带标记的探针串**（如 `K1:V1; K2:V2`），直接 dump 产物里被取用的**每一段**及其**去向**
  （进了 `text` / `labels` / `values` / `data`），据此生成一列「**解析规则**」：
  - `多行（按 \n 或 ；；，每行一句）`
  - `键:值（按 ; ｜ ； ｜ \n 分段，段内 lastIndexOf(':') 拆 k/v；v 非数字 ⇒ 用序号）`
  - `标题 | 高点 | 低点（按 | 三分段）`
- **新增一列「能力」**：`highlights` / `dataSource` / `countUp` / `animate` 是否支持（探针：传了看产物里有没有）。
- **新增一列「同义卡」**：同 `variant` 或同视觉职能的卡互相点名（治段④的 5 次）。
- **体积**：现 4935 字符 / 7553 字节，闸是 **12000 字符**（`card-catalog-drift.test.mjs:45`）。
  加三列预计 +1500 字符 ⇒ 仍在闸内；但 58 张卡的解析规则会明显变宽，**建议拆两份**（见 §10-3）。
- **反向变异**：`DAT3` 的解析规则列必须包含 `键:值` 而非 `多行`（当前 bug 的回归断言）；
  给任一卡人为注入一个假分隔符 ⇒ 生成器必须产出对应规则而不是「多行」。

### P1-2 生成 spec 的全字段表（治段①的 4 次）

- **动作**：新增 `gen-spec-fields.mjs`，用 **TS AST** 抽 `ContentSpec` / `SpecSection` / `SpecUnit` /
  `SpecCarry` 四个 interface 的**全部字段 + 类型 + 注释首句**，产出
  `references/spec-fields.generated.md`（规格：字段名 / 类型 / 必填 / 默认 / 一句话）。
  与现有 `gen-manifest-fields.mjs` 同一套路，直接复用其 AST 抽取器。
- **为什么必须生成**：`SpecUnit` 的合法键是本轮段①的全部动机，而它**只存在于 TS 类型里**
  （编译后没有运行时读取面），手写必然漂移。
- **反向变异**：给 `SpecUnit` 加一个临时字段 ⇒ 生成物必须出现该字段，否则红。
- **顺带**：`content-spec.md` 顶部加一句「全字段表见 `spec-fields.generated.md`，本文只讲怎么填」。

### P1-3 给「渲染坏了」补一个合法出口（治段⑤的 3 次 + 7 分钟权衡）

三级降级只覆盖「表达不了」。本轮模型面对的是**表达对了但渲染坏了**，于是它在
「改源码 / 换卡 / 接受缺陷」之间反复权衡 8 段 reasoning。

- **动作**：在 SKILL 纪律节把降级扩成四级，**新增第一档**：

  | 档 | 触发 | 动作 | 时间上限 |
  |---|---|---|---|
  | **0** | 抽帧显示**内容缺失 / 被裁 / 互相遮挡**（不是风格不满意） | **换同义卡**（查卡目录「同义卡」列）→ `write_note` 记一句 → 继续出片。**不判断能否改源码** | ≤2 分钟 |
  | 1 | 想要的效果没有对应卡 | 加单元 | — |
  | 2 | 需要跨屏固定元素 | `carry`（含文字层） | — |
  | 3 | 都不行 | `write_note` 记一句 + 如实写进交付未决项 | — |

- **硬规则**：**诊断一个渲染缺陷时先设 2 分钟上限**；到点没定位就换卡，不追根因（根因归产品侧）。
- **落点**：`skills/code-driven-explainer/SKILL.md` 纪律节 + `scaffold_manifest` 工具描述
  （工具描述每步都在上下文，比 skill 只读一次更硬）。
- **反向变异**：无（纯纪律，无断言）；靠下一轮真机看「缺陷到换卡的时长」。

### P2-1 模板库补 3 个竖屏卡模板（治 §4.2）

- 不做 10 个，只做**竖屏图文卡**这一类的 3 个：`vertical/3band`（标题+主体+结论条，即本轮的格位）、
  `vertical/big-number`、`vertical/compare-two`。判据字段必须写清 `stageSeconds` 与 `cell` 预设。
- **前提**：P0-2 修完再定模板 —— 否则模板会把裁字 bug 固化进产品。

### P2-2 把「卡内几何」纳入生成物（治 §3.3 这类隐性缺陷）

`spec-geometry.generated.md` 现在只覆盖「单一主体 box 的投影」。本轮 DAT3 两条轨相交、
DAT6 折线被压扁（`box.h:26` 投影后仅 220px）都属于**卡内多轨相对位置**，
既不在几何表里，也不在相交校验里。

- **动作**：生成器对**每张卡的每对轨**算相交面积比，>20% 的登记进
  「卡内重叠」小节（附投影算式）。数据来源仍是真跑 `generate()`。

## 8 明确不做

- **不改「纪律」的力度**：本轮证明纪律不是瓶颈。再加禁止条款只会让模型偷着做、或者花更多时间权衡。
- **不把 A4 从卡表里删掉**：修宽度口径即可（16:9 本来就正常，删掉是过度反应）。
- **不追「渲染器为什么从 bundle 加载」**：那是构建链话题，与做片子无关。P1-3 的第 0 档就是
  为了**终止这类追问**。
- **不补 10 个模板**：竖屏卡叙事本来该走「卡 + 格位」，模板只补 3 个高频形态。
- **不动 `heightLimited` 的设计**：它是 R11 唯一被本轮证明有用的新字段（回执里「盒高只有 138px
  ⇒ 字号 149→115」这条警告直接解释了竖屏标题为什么不够大）。要修的是它没进 schema，不是它本身。

## 10 拍板结果与最终实施方案（2026-11-16，已定）

### 10.1 三个拍板点的决定

| 点 | 决定 | 理由 |
|---|---|---|
| P0-1 / P0-2 时机 | **现在修，同一批做** | P0-1 是回归（竖屏每轮必丢回执）、P0-2 是 14 分钟诊断的根因；都是小改动 + 反向变异守卫。分两批会让「R11 数值表重跑」做两次 |
| P0-3 路线 | **移 box + label 只吃第一段** | 保守方案（只登记）把可见缺陷固化进产品，每次用 DAT3 都出「浮卡压柱」。移 box 只影响一张卡；卡目录 box 列由生成器探真产物自动跟随，无文档漂移。回归闸 = 跑 `generate()` 断言两轨相交 = 0 的小测试，不依赖 P2-2 |
| 卡目录拆分 | **拆两份** | 混编后 12KB 闸只剩约 2KB 余量，下轮必破。两个文件的读者时机不同：catalog 服务「选卡」（要窄），rules 服务「写 copy」（要全）；拆开后各自立漂移闸 |
