# 按拍剪辑（beat-editing）—— S5 分册 · 2026-10-28

> 前提：节拍分析已产出 `beats.json`（`{bpm, beats: number[], confidence}`，落在音频
> 节点上）。本文写「拿到 beats 之后，切点怎么吸附」的机器口径与容许误差。
> **低置信禁用卡点**（confidence 低于阈值的曲子，beats.json 仅作参考信息，不吸附）。

## 一、读 beats

1. `beats` 是升序秒数组（拍点绝对时间坐标）；`bpm` = 60 / 相邻拍间隔中位数；
2. `confidence` ∈ [0,1]：电子/打击乐高，弦乐/氛围曲低。**低于 0.5（低置信）→ 卡点路径整体不启用**，并明确告知用户「本曲节拍置信度不足，已按普通节奏剪辑」。

## 二、切点吸附算法（写进你的剪辑规划，不要自己实现 DSP）

给一个期望切点 `t`（秒）：

1. 找最近拍点 `b* = argmin |b - t|`；
2. 误差 `|b* - t| ≤ 0.5 拍`（半拍）→ 吸附：切点取 `b*`；
3. 误差 > 0.5 拍 → **不吸附**（保持原切点）——硬吸会把镜头拉出明显跳变；
4. 吸附后**必须重算该镜 `durationInFrames`**（`frames = round(b* × fps)`，fps 用分镜
   声明的帧率），并过尾部完整性校验（最后一镜吸完，总时长 = Σ 各镜帧数 / fps，
   与 BGM 时长重新对账——吸附会让总时长漂移，这是正常代价，但要显式算出来）。

**容许误差口径**：吸附后的切点与拍点差 ≤0.1s（合成时按帧量化，25fps 一帧 0.04s，
两帧内都算落拍）；验收时用「切点落在拍点 ±0.1s 内」机器判定。

## 三、半拍吸附（进阶）

密集快切（一拍多切）时，先按整拍吸附；若仍需更密，用相邻拍点的**中点**（半拍）作为
吸附目标，误差容差同上。不要自行做 1/4 拍——置信度撑不住。

## 四、与 lyrics 的关系

歌词驱动的切点（跟唱行首）优先级**高于**拍点吸附：先按 `lyrics.json` 的行首时间定
主切点，再把无歌词约束的次要切点吸到拍点。两者冲突时（行首与拍点差 <0.3s）取行首。

## 五、失败判据

- `beats.json` 缺失 / `confidence` 低 → 不卡点，向用户说明；
- 吸附后总时长漂移 > 5% → 放弃吸附改回原时间轴（总时长稳定性优先）；
- BPM 估测与用户认知差 > 5（用户说 120、测出 138）→ 以本地分析为准但提示用户复核。
