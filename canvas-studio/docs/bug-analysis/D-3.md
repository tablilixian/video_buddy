# D-3 ｜ 角色形象更新后旧四视图未作废、下游视频仍引用旧图

> 优先级 P0（角色一致性是产品核心诉求）｜ 风险 T3 ｜ 依赖：**B-4 先行**（复用 manifest 句柄取数 + replaceValuesInPromptJson）
> 截图要点：女儿形象已由 agent 改出新版四视图（黄衣版），但视频「编辑提示词」抽屉 Picture 2 仍指向旧四视图句柄（ref-9e0c9f3a…），已生成的视频用的还是旧形象。用户要求：画布**先于**视频生成调整引用，旧三/四视图应作废。

## 现象
重生成角色四视图后：旧四视图节点仍 active（仍进参考池/list_references），下游视频 generationPrompt 里的旧句柄无人改写，新视频继续用旧形象。

## 代码级原因
- character_sheet 重生成**既不走 replaces 也不走 retryOf**：工具无 replaces/retryOf 入参（`host-tools.ts:1283-1322`）；同名重调走「整体覆盖」——`generate.ts:2632-2639` `resolveAssetSlot`（同名复用 assetId）→ `:2739` `releaseAssetNodes` → `projects.ts:405-414` **只摘旧节点的 assetId 字段**（不标失效、不改引用）→ `:2731` 新节点 append。旧四视图仍 `isReference:true, referenceRole:'character'` 且 active，`list_references`（host-tools.ts ~1519，filter active）**新旧两张同时列出**。
- 即便走图片显式 `replaces` → `applySupersede`（`shot-versions.ts:217-225`）也只写 `supersededBy`，无下游改写。全仓唯一的下游改写实现是 retry 路径 `overwriteNodeAsset`（generate.ts:1594-1612，批 1/C-10 落的）——supersede/资产覆盖路径确无等价物。
- 下游引用形态：视频 generationPrompt 的 `filenames` 元素是 `@ref` 解析后的旧四视图 Drama 句柄——正是 `replaceValuesInPromptJson`（generate.ts:1279-1310）的目标。

## 修复方案（推荐「自动改写 + 旧节点失效」；用户诉求即「先调整引用」）
1. `generate.ts` 新增共享 helper（紧邻 overwriteNodeAsset）`rewriteDownstreamForSupersede(persisted, newNode, oldNodes)`：对每个旧节点，若 old/new 的 filename、url 均存在且不同 → 组 replacements map（**纳入 reference-manifest 里该旧节点的全部历史句柄**，与 B-4 同一取数），对画布其余节点 generationPrompt 跑 `replaceValuesInPromptJson`。
2. 接入点 A（通用）：`generate.ts:2524-2528` —— `applySupersede` 同一次 writeCanvas 前对 `supersedePlan.supersedeIds` 的旧节点做改写（新节点 ：2519-2523 已落盘，基于 persisted 操作）。
3. 接入点 B（character_sheet 专属，无需 agent 传参）：`generate.ts:2668-2748` `slot.replacing` 分支——查出 `assetId === 旧卡` 且不在新 anchorNodeIds 的旧锚点节点（被 releaseAssetNodes 摘除的那批），标 `supersededBy: sheetNodeId` + 灌入 `{旧.filename → sheetDramaName, 旧.url → sheetUrl}` 下游改写。
4. 为什么自动改写而非标过时：旧句柄目前仍可解析（旧文件在盘、旧节点 active），CV-055 式「过时角标」改变不了已写进 prompt 的引用，后续视频照样用旧图；自动改写 + `supersededBy` 后 list_references 的 active 过滤立即让旧图退出参考池。CV-055（`docs/canvas-ux-backlog.md:86`，只标记不级联）保持 backlog，本修复吃掉其服务端「断链/漂移」部分，staleAt 角标可后续叠加覆盖手工改节点场景。

## 改动风险
- 一个旧图被多条视频引用时全量改写，「部分镜头保留旧形象」的意图会被波及——可接受（旧版节点可从失效态恢复），文档注明。
- 自愈换名后 prompt 里可能存的是新句柄——必须用 manifest 全历史句柄做 replacements（B-4 的取数）。
- `sheetDramaName` 是后端 temp 名，写进下游 prompt 与 overwriteNodeAsset 现行为一致，无新增风险。
- 单测对照 C-10/overwriteNodeAsset 用例形制：supersede 后下游 filenames 换新、list_references 不再列旧图、旧节点带 supersededBy。

## 验收
无头：接入点 A/B 各一组单测（stub registry）。桌面：改女儿形象 → 旧四视图卡标失效、抽屉 Picture 2 自动变新句柄、重新生成该镜视频用新形象。
