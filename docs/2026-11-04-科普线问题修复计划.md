## 一、P0 —— 阻塞 0.1 关闭

### P1. `animate` 越界导致整层永久不可见（无静态校验）

**问题**
`animate.startFrame` 是**轨内相对帧**，但校验层完全不检查它与轨长的关系。
`animateStateAt` 的命中窗口是 `localFrame >= start && localFrame < start + dur`，
因此 `startFrame:31, durationInFrames:1` 配 32 帧轨 ⇒ **唯一命中帧 progress=0 ⇒ opacity 恒 0**，
整条轨 32 帧全程透明。中文版 `s2_callout` 与英文版 `s2_callout` **都中招**。

**为什么是 P0**
这是**唯一同时具备"必然复发"和"零误报拦截"两个特征的问题**：
实测全 manifest 扫描，**唯一告警项精准命中 A4**。同批次还踩了第二次
（`animate.startFrame` 写成绝对帧 + `fill()` 抢占，把入场推到轨尾 65–92%）。
两版成片都带病交付，说明现有校验完全拦不住。

**落点**
- `canvas-studio/src/remotion/manifest.ts` → `validateAnimateList()`（约 1059 行）
  在既有 `startFrame` / `durationInFrames` 合法性检查之后，补**轨内窗口**校验。
- 需要拿到轨长：`validateAnimateList` 当前签名只有 `(value, at, errors)`，
  需扩为 `(value, at, trackDuration, errors)`，调用方传入 `track.durationInFrames`。

**规则（两条，均为 error，阻断渲染——与 anchor 契约同级的 fail-fast）**
```
① animate.startFrame + animate.durationInFrames > track.durationInFrames
   ⇒ error：动画段完全落在轨外
② 段整轨命中帧数 ≤ 1 且 from.opacity === 0
   ⇒ error：该段使整层永久透明（"整层不可见"）
```
规则 ② 是规则 ① 的语义化补充，直接对应 A4 的真实成因。

**验收方式**
- 新增 `canvas-studio/tests/manifest-animate-window.test.mjs`（仿 `manifest-animation-windows.test.mjs` 写法）
- 表测：越界段 / 整层不可见段 / 正常段（不误报）/ `from.opacity` 非 0 的单帧段（不误报）
- **反向变异靶**：拿英文版 `build/manifest.json` 跑校验，**必须报错且指向 `s2_callout`**

### P2. `reveal` 方向语义无断言（"右 wipe 出"做不出来）

**问题**
`reveal.ts` 的 `direction` 描述**揭示行进方向**（`right` = 从左往右揭开，可见区收在左侧）。
用户要"左 wipe 进、**右 wipe 出**"，但：
- 实现两个面板都写 `direction:"right"` ⇒ 都是从左往右揭开，**方向要求无法表达**
- `exit` 只支持 `opacity/scale/rotation/x/y`，**不支持 clip 退场** ⇒ 没有"wipe 出"的表达手段
- 两面板 reveal 起点差 104 帧（3.5s），并置对比的时序也错位

**为什么是 P0**
这是**能力缺口**而非配置失误——即使 Agent 想做对，契约也没有正确路径。
两版成片的右面板实测边界 66%→96.5% 恒为自左向右，**A5 在两版都 FAIL**。

**落点**
- `canvas-studio/src/remotion/reveal.ts` → `validateReveal()`（约 88 行，已有 `kind`/`direction`/`durationInFrames` 校验）
- `canvas-studio/src/remotion/manifest.ts` → `validateReveal` 调用点

**方案（两段，取 A 为主）**

**A. 语义断言（先做，成本低）**
在 `validateReveal` 增加 warning：当 `direction==='right'` 且该轨 `box.x > 50`（位于画布右半）时，
提示"右侧面板若要『右 wipe 出』请用 `direction:'left'`；当前为从左往右揭开"。
**不阻断**（不能猜用户意图），但把坑摆到眼前。

**B. 补 `reveal.out` 字段（表达"wipe 出"）**
在 `TrackReveal` 增加 `out?: { direction, durationInFrames, startFrame }`，
渲染侧在轨尾按 `out` 反向收窄 clip-path（`inset` 方向取反）。
这样"右 wipe 出"有了原生路径，不必靠 `direction:"left"` 硬凑。

**验收方式**
- `tests/remotion-callout-reveal.test.mjs` 已有 reveal 相关表测，**在同一文件追加**
- 表测：`direction:'left'` 产出 `inset(0 0 0 N%)`；`out` 生效；断言 warning 触发条件
- 端到端：改英文版 `s4_rPanel` 后重渲，**右面板边界必须自右向左推进**（像素实测）

### P3. 编排壳被跳过：两条 skill 规则冲突

**问题**
用户点名 `code-driven-explainer` 时，Agent 主动跳过 `explainer-format-director`。
第 2 步 reasoning 原文：

> The 科普讲解体裁 format director exists but user named code-driven-explainer directly.
> … User named the executor directly. I'll load code-driven-explainer and its references.

**不是没看见，是权衡后跳过**——因为插件通用规则「用户点名 skill → 直接调用」压过了体裁壳的「点名下游也要先过壳定向」。
结果：定向三问（受众 / 记住哪一件 / 时长画幅）**一项未问**，实际只问了音色与数据口径。

**为什么是 P0**
A1 在**中文版与英文重制版两次都 FAIL**。且这不是 Agent 能单方面修好的——
**光靠会话行为约定无效，必须在 skill 描述层消解冲突**。
更关键的是：**科普片的受众（小学生 vs 航天爱好者）直接决定叙述密度**，
不问受众就等于让 Agent 猜，这是 45s 科普片最不该猜的变量。

**落点**
- `canvas-studio/skills/explainer-format-director/SKILL.md` → frontmatter `description`
- 同批 `brand-format-director` / `data-viz-format-director` / `drama-format-director` /
  `social-ad-format-director` / `product-format-director` **同样问题，需一并修**

**修法**
在每个 format director 的 description 里补一句显式消解：

> **用户点名下游 executor 时本壳仍须先加载做定向**——点名 executor 只决定"用哪条链"，
> 不替代"受众/记忆点/时长画幅"三问；请先加载本壳完成定向，再加载 executor。

**验收方式**
- 新会话发同样的正例提示词，**回复中必须出现 `explainer-format-director` 的显式路由声明**
- 且**必须复述定向三问**（受众 / 记忆点 / 时长画幅）
- `tests/skill-tool-refs.test.mjs` 已存在 skill 引用表测，**追加断言**：各 format director 的
  description 必须含"点名 executor 仍须先过本壳"字样

## 六、优先级理由（为什么是这个顺序）

**P1/P2 排最前，不是因为它们最严重，是因为它们**
- **确定性最高**：不修就必然复发，且已有精确复现与零误报校验方案
- **修复面最窄**：两个纯函数模块，不牵动渲染管线
- **能立刻止血**：P1 一条校验就拦住 A4；P2 一条 warning 就挡住 A5 的下一次误用

**P3 排 P0 而不是 P1**：虽然它影响"编排纪律"而非"成片正确性"，
但它是**唯一需要改 skill 描述层**的问题——不改描述，下一批还会用同样理由跳过。
**描述层改动比代码改动更容易被后续任务继承**，所以必须在本轮落地。

**P4 排 P0 而非 P1**：它是**元问题**。P1/P2/P3 修完，若 P4 不做，
下一批仍会重新踩同样的坑——只是踩的时候快一些（因为有了 pitfalls.md 可查）。
**P4 是让前三个修复不白做的保险**。

**P5–P8 排 P1**：它们防的是"流程性复发"，不直接影响成片正确性，
但每一条都对应本批的一次真实失效（A8 漏发 / 方案丢失 / 假动效 / 亮度网格误判）。

**P9/P10 排 P2**：P9 是效率（省 3–5 分钟/批），
P10a/c 是成片观感（不影响判据 PASS），
**P10b 值得单列**——它是 `TextCard.tsx` 的通用缺陷，任何多行 subtitle 都会踩。

## 七、一句话总结

> **P1 + P2 把"必然复发的错"变成"编译期就报错"；P3 + P4 把"规则冲突"和"经验不传递"堵住；
> P5–P8 把验收流程的四个漏点补上；P9/P10 是效率和观感的收尾。**
> 做完 P0+P1，科普线才算真正具备"可复现、可验收、不会静默降级"的能力——
> **当前最要紧的不是把片子做得更好看，而是让错误在交付前自己暴露出来。**
