## 2. 新环境重建步骤

```bash
# 前置：Node ^22.19.0 / >=24，Corepack 提供 Yarn 4.18.0
git clone https://github.com/tablilixian/video_buddy.git && cd video_buddy
git checkout dev
git submodule update --init --recursive
corepack yarn install --immutable

# canvas-studio 构建 + 验证链（必须全绿再动手改代码）
corepack yarn workspace canvas-studio build   # sync skills → clean → tsdown → tsc ×2
corepack yarn workspace canvas-studio typecheck
corepack yarn workspace canvas-studio test:smoke   # 期望 204/204
corepack yarn workspace canvas-studio verify:loader

# 启动桌面（手动验收用）
corepack yarn workspace canvas-studio build && corepack yarn dev
```

**沙箱/受限环境下 build 不要跑整条 `build` 脚本**（`clean.mjs` 的 `rmSync('lib')` 与
`sync-minimax-skills.mjs` 的 `rmSync('skills/')` 会触发删除守卫；skills/ 已同步时脚本会跳过）。
逐步执行：

```bash
cd canvas-studio
node node_modules/.bin/tsdown
node node_modules/.bin/tsc -p tsconfig.json
node node_modules/.bin/tsc -p tsconfig.client.json --emitDeclarationOnly
```

管道 `| tail` 会吞退出码，判成败用 `echo $?`。

## 5. 工程铁律摘要（踩过的坑，新环境同样适用）

- **STATUS.md 是单一事实来源**；编号**已编到 CV-098，新条目从 CV-099 起**——写编号前先 grep STATUS.md 确认，不要凭记忆（已两次漂移）。
- 状态词汇：已完成=用户桌面验收通过；代码改完未验收=**已修复·待验收**。
- `skills-local/` 是手写源，`skills/` 是构建产物（sync 脚本合并）；**上游 9 个 skill 严禁改编**，同名覆盖走 file-level overlay；改完必跑 `sync-minimax-skills.mjs` + 护栏测试。
- 同一消息里对**同一文件的多个 Edit 并发执行会互相覆盖**——同文件修改一次一个串行发，不同文件可并行。
- macOS BSD grep 不认 `\|`，用 `grep -e A -e B`；**沙箱 Bash 里 grep 会静默失效**（返回空、exit 1），检索一律用 Grep 工具或 `node -e`。
- `test:smoke` 跑的是 `lib/*.js` 产物——**改了 src 忘了 build 测试照样可能全绿，绝不当编译闸门**；完整验证链 = build → typecheck → test:smoke → verify:loader。
- 纯函数可单测放 `src/*.ts`（`src/client/**` 被 Host tsconfig 排除）；CSS-in-JS（styles.ts 模板字符串）注释里**禁止写带反引号的选择器/变量名**（TS1005）。
- git：commit 落本地 dev；`git add` 用精确路径，不 add 目录（避免带入其他会话未跟踪产物）；`lib/` 构建产物按当次情况决定是否随提交（CV-097/098 均随提交了本次改动到的 lib 文件）。
- Drama Backend（`http://117.50.108.73:8082`）curl 必加 `--noproxy '*'`；服务易被连续请求打挂。
