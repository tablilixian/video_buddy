# 一次性意图卡与轮次预算（2026-11-05）

> 本分册是 `clarification.md` §「轮次预算」与 `SKILL.md` §「需求澄清」的细则载体。
> 立项目的：一份 45s 科普片的故事板阶段曾跑 **35 个模型步 / 23.35 min**，其中
> 5 次提问用户全选「（推荐）」、零信息增益，25 万字符 reasoning 主要在复述与反复核数。
> 提速与「把用户意图分析清楚」是同一件事：**少打断，把每个推断记下来。**

## 1. 轮次预算（硬指标）

阶段一（需求澄清 → 拍摄定稿写完）**confirm ≤5 个模型步 / auto ≤4 步**。

| 轮 | 输入 | 输出 |
|---|---|---|
| 1 | 总纲 + 阶段分册白名单 | 一批 `read`（≤2 次调用），读完再推理 |
| 2 | 项目预置 + 事实快照 | 一次 `read` + 一次快照构建（数据/科普片） |
| 3 | 以上全部 + 用户原话 | **一次性结构化输出**：意图卡五段 + 九节拍摄定稿 + 事实裁决 + 工具序列（JSON，非散文） |
| 4 | 意图卡回流（confirm） | `write_note` 假设便签 + `write_storyboard` 九节全传 + `awaitingLanding=true` |
| 5 | 工具结果回执 | 一句交付说明，**不重新规划** |

`auto` 无第 4 轮的卡片回流 ⇒ ≤4 轮。

**三条硬规则**

1. **计划只产一次**：第 3 轮之后禁止重新规划、复述全片结构、再核一次已裁决数值。
2. **唯一长 reasoning 轮 = 第 3 轮**：其余轮只做执行与回执（≤5k 字符）。`Hmm / Actually / Wait` 式自我修正只允许出现在计划轮。
3. **执行不新增中介**：直接调既有工具（`write_storyboard` 九节全传、`write_note`、`facts-builder.mjs`），不要为了「再确认一遍」多一轮。

> 不靠关 reasoning / 换模型档——插件层不持有 LLM 推理配置。只靠**减少需要推理的轮次 + 禁复述**。

## 2. 意图卡五段

一次 LLM 调用产出，交给 `confirm_intent_card` 卡片让用户**逐字段核对并改**（不是填表，也不是整包同意）：

| 分区 | 含义 | 卡片上的处理 |
|---|---|---|
| `explicit` | 用户原话明说 | **锁定**，压过一切预置 / 配方 / 来源值 |
| `inferred` | 从原话或项目预置推断 | 每条标「默认」+ 依据 + 置信度；可改 |
| `conflict` | 冲突项 | 按 §3 裁决序取值，落选值记来源脚注 |
| `needsUser` | 只有用户能答的项 | 通常 0~2 条（如音色人格）；**只有这些是必填** |
| `defaults` | 其余采用的缺省值 | 只读展示，供事后回退 |

**判据**：「只有用户能答」= 答案不在用户原话、项目预置、画布参考、题材惯例里，且猜错会导致整片返工。
受众 / 用途 / 画幅 / 时长 / 镜头数 / 节奏 / 记忆点 / 配色倾向**都不算**——它们进 `inferred` 或 `defaults`。

**必含字段「结构起点」（structure）**：`模板` / `配方卡` / `自由编排` 三选一，**裁决依据 = `list_templates({requirements})` 的五判据机器判定输出**（恰好 1 个 ✅ 自主选模板；≥2 个列给用户挑；0 个才自由编排），不许凭「这创意要代码绘制 / 要定制」的直觉静默选边——代码动效类创意（UI 动效 / 字卡 / 落版 / 图表 / 数据镜头）无论体裁**先查再判**。真机实证（session-15e9433a）：创意与 `outro/strip-away` summary 逐字相符，意图卡却直接锁「单镜精品短片（代码动效驱动）」、全程 0 次 `list_templates`，手写生成器重造 31+ 轨——字段值须写明判定来源（如「模板 outro/strip-away：五判据 5✅」或「自由编排：五判据 0✅」）。

**信息要留下**：意图卡结论分别落到
`write_note`（完整假设清单，画布持久可见、`list_references.notes` 可读回）·
`write_storyboard.creative.brief`（一句话意图，契约是字符串，**不塞对象**）·
`facts[]`（冲突裁决与来源脚注）· `constraints[]`（硬约束）。
5 次点选完什么都没记下，是旧流程最该修的地方。

## 3. 裁决序（补 `SKILL.md` §「需求澄清」的外推）

```
用户原话 explicit > 项目预置 > 事实快照 verified > 联网值
```

- 用户写 23.5°、NASA 写 23.4° ⇒ **直接用 23.5°**，来源值记脚注，不再推理权衡、不再联网复核。
- 落选值写进 `facts[]` 的 `claim`（注明来源与「未采用」），`status:"verified"`；确实查不到才 `pending`。
- 已裁决的项在后续任何一轮都**不得重开讨论**（对应硬规则 1）。
- 联网只作**单次、可选**复核（总时限 20s），失败不改数值、只标 `pending`；
  出片时由 CV-440 pending 事实桥点名，不必在故事板阶段穷尽核实。

## 4. 阶段分册白名单（压上下文）

一次读全 ≠ 全读。`clarification.md` 第 ① 步入口分流的结果决定本阶段所需分册：

| 入口分流命中 | 一批要读的分册 |
|---|---|
| 知识型图文 / 科普（第 6 条） | `clarification.md` + `toolchain.md` + `screenplay.md` + `shot-format.md` + 下游 explainer 的 `references/facts.md` |
| 单镜精品短片（第 1 条） | `clarification.md` + `toolchain.md` + `screenplay.md`（简化流程） |
| 带参考图 / 视频（第 3/4 条） | 上面 + `look.md` + `consistency.md` |
| 标准多镜叙事（第 2 条） | `clarification.md` + `toolchain.md` + `look.md` + `screenplay.md` + `shot-format.md` + `consistency.md` |

**禁止**把 93KB 规范一次读进来后每轮重发；实测这会把每轮固定开销从 6s 抬到 13.5s。
未命中白名单的分册等真正需要时再补一批，**不要为了「万一要用到」先读**。

## 5. 与既有审批语义的边界

- 意图卡是**需求澄清**，不是审批门；覆盖层「确认落地」与关键帧确认门原样生效，agent 不得自行推进工作流状态。
- `auto`（放手跑）**不弹卡**：按 `clarification.md` §「放手跑补完」自行假设、把假设清单用 `write_note` 落便签后直接继续。
- 一次性确认**不等于整包同意**：卡片必须字段级可编辑、默认值明示、无「全部同意」按钮。
  `clarification.md` 旧条款「禁止一次性整体确认」禁的正是整包同意，本分册只放宽载体、不放宽这条底线。
- 逐项 `ask_user_choice` 仅作意图卡不可用时的降级路径，且仍受「≤3 问、只问只有用户能答的项」约束。
