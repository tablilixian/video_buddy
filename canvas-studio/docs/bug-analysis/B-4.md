# B-4 ｜ 关联资产无法删除（409「仍被画布节点引用」拦死，无解引用路径）

> 优先级 P0（资产管理工作流被堵死）｜ 风险 T3（写画布协议）｜ 依赖：无；其 helper 被 D-3 / A-13 残余复用，**本条先行**
> 截图要点：生成历史面板点删除 → 红字「该产物仍被画布节点引用，请先移除画布上的对应节点」；用户批注「有点不智能，期望能删除并顺利断链」。

## 现象
历史面板删除被引用产物一律 409；客户端已有两段式「彻底删除/取消」确认 UI，但两步打的是同一个会 409 的接口——确认流形同虚设。

## 代码级原因
- 拦截点：`routes.ts:1250-1294` delete 路由；`:1273-1277` `collectReferencedBasenames(doc)` 命中即 `sendJson(res, 409, …)`。
- 判据：`asset-gc.ts:43-53` `collectReferencedBasenames` **只收集 `node.url` 的 basename**——直接挂该文件的节点才算「引用」，generationPrompt 内嵌句柄不管。
- 客户端：`HistoryDrawer.tsx:131-145` handleDelete、:238 删除钮、:220-224 两段确认（已存在）；`client/api.ts:592-606` 只发 `{projectId, file}`，无 force。
- 既有可用件：`generate.ts:1279-1310` `replaceValuesInPromptJson`（批 1 落的精确整值替换）；reference-manifest（CV-242）记账句柄历史。

## 修复方案（彻底删除 = 解除引用，二次确认）
1. **协议**：delete 路由接受 `force?: boolean`；409 响应体附引用清单（直接引用节点 id/标题/kind + 间接 generationPrompt 引用方数量），供确认框指名道姓。
2. **新 helper**（放 `asset-gc.ts`，与 collectReferencedBasenames 同居）`unlinkHistoryReferences(registry, projectId, file)`：
   - 直接引用者（`basenameOfUrl(node.url) === file`）→ 从画布移除这些节点（writeCanvas）。保护：任一直接引用者 `isLoading === true`（生成中）→ 终止 force，再次 409 列名。
   - 间接引用者 → 用 `replaceValuesInPromptJson` 改写 generationPrompt；**句柄集合从 reference-manifest 取该文件登记过的全部历史条目**（防 A-1 自愈换名后 prompt 里存的旧句柄对不上）。
3. **数组元素删元素而非置空**：`replaceValuesInPromptJson` 只做整值替换；`filenames` 数组元素应**删除命中元素**（新增变体如 `dropValuesInPromptJson`）——置空会把 `""` 传进重放打到后端。标量 `filename`（首帧位）替换为断链标记 `[已删除:<file>]`——「首帧没了」不得静默降级成文生视频，重放时指名道姓失败。
4. 解链后走既有 `:1279-1286` rename → `.trash` 与 `:1287` markHistoryDeleted；GC 物理清闭环不变。
5. 客户端：`api.ts` deleteStudioAssetHistory 加 force 参数；HistoryDrawer 409 → 展示引用清单 → 二次确认走 force。

## 改动风险
- 批量删直接引用节点可能误伤想保留的卡——确认框必须列名。
- isLoading 竞态必须拦截（删除生成中节点的产物）。
- 改写只影响重放参数，不撤销已生成的视频本体；`.trash` 阶段可手工救回，GC 后不可逆。
- 需补单测：force 删除后直接引用节点消失、间接 filenames 元素被删、首帧位变断链标记、isLoading 保护。

## 验收
无头：单测覆盖上述四点（stub registry）。桌面：历史面板强删一张被 2 个视频引用的图 → 确认框列名 → 删除后两视频详情显示断链卡、重放报「首帧已删除」类指名错误、文件进 .trash。
