## 〇、一句话结论

**路线方向对，但顺序要改一处**：「先补齐能力、再想办法用起来」这个串行顺序会让**最薄的那一层永远补不上**——因为本项目的瓶颈不在契约与组件，而在**表达层**（`manifest-contract.md` 里「动画」出现 **0 次**，而工具描述已经承诺"精确动画与排版"）与**反馈层**（agent 渲完只拿到一行 warning 文本，**看不到画面**）。正确做法是**以「一条目标成片」为锚，四层同批推、每档一验收**，而不是把能力堆完再看能不能用。

**还差多少**：按能力簇计，**8 簇里 6 簇全空**；但真正挡住「太阳系科普片」这类创意的只有 **2 簇**（帧级运动 + 语义关系）。补齐这 2 簇需要动 **1 个契约文件 + 1 个纯函数文件 + 4 个组件 + 1 本分册**，且**零安装成本**（需要的包已在 `node_modules` 里）。

## 一、路线判断：三处要改

### ① 「尽可能发挥 Remotion」是个没有边界的靶子 → 换成「在目标场景内发挥到位」

Remotion 核心 **59 个运行时导出** + 已装 10 个包族合计约 **133 个**。但其中大量与本产品定位**无关**：

| 能力 | 为什么对本产品无关 |
|---|---|
| Lambda 分布式渲染 | 本地桌面单机产品，无渲染农场需求 |
| SSR（`@remotion/renderer`） | 本机 macOS 14.6 < Remotion 要求的 15，一加载就自打 `rendering may not work` 警告；且当前 CSR 够用 |
| `HtmlInCanvas` / `IFrame` | 等于让 LLM 产出 HTML —— **破 devdoc §1.2「不做 LLM 生成 JSX」**，是既定范围外 |
| `@remotion/player` 的应用内编辑 | 若要做「可视化拖拽编排」，就与"agent 写 JSON"的产品主线冲突；只宜做**只读预览** |

⇒ 按"尽可能发挥"去补会补出一堆没人用的能力。**靶子应该是「30 秒零视频模型科普片能做出行星公转动画」这种具体目标。**

### ② 「能力」不是一层，是四层；现在最薄的是后两层

| 层 | 现状 | 薄在哪 |
|---|---|---|
| ① 契约（能表达） | `manifest.ts` 463 行、5 轨型、5 个白名单 | 无 `animate`、`Transform` 只挂 video 轨 |
| ② 组件（能渲染） | `components/` 8 文件 422 行 | 帧级运动只有 3 处常量 |
| ③ **表达（agent 会写）** | `manifest-contract.md` **「动画」0 次** | ⚠️ **工具描述承诺了动画，skill 一次没教怎么写** |
| ④ **反馈（知道自己错了）** | 只有 `warnings: string[]` | ⚠️ **未知字段静默丢弃**；agent 渲完看不到画面 |

**只补 ①② ⇒ agent 依然不会写（③）、写了错也不知道（④）⇒ 前面补的能力等于没接上。**

这一条有现成的讽刺证据：`manifest.ts:61` 契约注释写着「组件用 `interpolate` 对其做帧级动画」，而 `interpolate` 在全仓**只出现这一行注释、零真实引用**。**注释承诺的能力，从来没兑现过。**

### ③ 串行会浪费一次验收机会 → 每档一验

本仓已有 `scripts/remotion-verify/`（CSR 端到端验证器，支持 `S10_BUNDLE_ONLY=1` 在无 GUI 沙箱里只验打包）。**每补齐一档能力都能立刻真渲染验一次。**「全补完再验」会把问题积压到最后一次才知道，而本仓的纪律正是「守卫必须能反向变红」——能力补齐同理，**每档要有当场能红的验收**。

## 三、分档计划

排序原则：**「解锁用户可见能力」优先于「用现成库替换手写实现」**。前者是能力增量，后者是工程整洁。

### B1 · 让东西能动（L1 `animate` DSL）— 核心档

**目标验收**：太阳能做出「八颗行星依次滑入 + 尺寸对比缩放 + 要点卡侧滑」，且 `remotion-verify` 渲两帧像素有差。

| 步 | 落点 | 内容 |
|---|---|---|
| 1.1 | `src/remotion/manifest.ts` | `VisualState`（`x/y/scale/rotation/opacity`）+ `Animate`（`from`/`to`/`startFrame?`/`durationInFrames?`/`easing?`）；`BaseTrack.animate?: Animate \| Animate[]`；`BaseTrack.fadeFrames?: number`；`Transform` 从 `VideoClipTrack` **上提**到 `BaseTrack`；`validateManifest` 加 animate 校验 |
| 1.2 | `src/remotion/timing.ts` | `EASINGS` 白名单（linear / easeIn / easeOut / easeInOut）+ `interpolateState()` + `animateStateAt(track, frame)` —— **纯函数**（`manifest.ts` 头明写零 Remotion 依赖，Host 要能算、要能单测） |
| 1.3 | `src/remotion/components/` | 新增 `useAnimatedStyle(track, frame)` hook；`Shape` / `TextCard` / `ImageClip` / `VideoClip` 各接一行；`fadeOpacity` 支持 `fadeFrames`（0 = 硬切） |
| 1.4 | `skills/code-driven-explainer/references/manifest-contract.md` | 补 `animate` 段 + 3 个示例（滑入 / 缩放 / 循环）；`explainer-patterns.md` 补「用动画讲对比与过程」 |
| 1.5 | `src/host-tools.ts` | `render_composition` 字段清单补 `animate` / `fadeFrames` / 上提后的 `transform` |
| 1.6 | `tests/` + 验证 | `remotion-timing.test.mjs` 加插值单测（端点 / easing / clamp）；`manifest.test.mjs` 加 animate 校验；`remotion-verify` 加「两帧像素差异」 |

**四条实现纪律（不守就会做出"看起来能跑其实不稳"的东西）**：
1. 插值**必须是 `timing.ts` 的纯函数**，不能写在组件里。
2. **严禁 CSS `transition` / `@keyframes`** —— Remotion 逐帧截图走真实时钟 ⇒ 第 47 帧拍到的位置取决于机器快慢，**同一份 manifest 渲两次不一样**。（本仓已用 `document.fonts.load` 等字体就绪回避过同类问题。）
3. easing **白名单 4 个 + 端点收敛**，不开放任意贝塞尔（模型会编非法控制点）。
4. 抽 `useAnimatedStyle` 一处接线，避免重演「加字段忘接线」（`Transform` 的病根）。

### B2 · 让「关系」能表达（L2 语义 primitive）— 核心档

**目标验收**：做出「行星绕太阳公转 + 轨道线生长 + 数据条脉动」。

| 步 | 落点 | 内容 |
|---|---|---|
| 2.1 | `manifest.ts` | 三个语义 primitive：`orbit`（绕画布内某点公转：中心 / 半径 / 起始角 / 周期）、`draw`（沿路径生长）、`pulse`（周期脉动） |
| 2.2 | `timing.ts` | 对应纯函数：`orbitStateAt()` 等 |
| 2.3 | 组件 | 接线；**`draw` 的路径数学用已装的 `@remotion/paths`**（`evolvePath` / `getPointAtLength`），**不自己写** |
| 2.4 | 分册 | `manifest-contract.md` 补 primitive 段；`explainer-patterns.md` 补「天文 / 地理 / 物理类怎么用 orbit」 |

**为什么 B2 要跟 B1 分档**：B1 给的是"通用可动"，B2 给的是"关系的语义"。B2 依赖 B1（`orbit` 需要东西能"动"），但把两者合成一档会让契约一次扩太多、难以定位回归。

### B3 · 让 agent 知道自己在做什么（表达 + 反馈）— 与 B1 同批做

**这条不补，B1/B2 就是白补。**

| 步 | 落点 | 内容 |
|---|---|---|
| 3.1 | `manifest.ts` | **未知字段 → `warnings`**（约 20 行，**不阻断**，不破坏任何现有输入） |
| 3.2 | `host-tools.ts` | `render_composition` 描述与 skill 分册**对齐**（承诺 = 交付） |
| 3.3 | 可选 | `@remotion/player` 接**只读预览**：出片前先看，免走 10 分钟真渲染工单（HITL 收益最大的一条） |
| 3.4 | 验证 | 造一份含 `animate` 拼写错误的 manifest，断言拿到 warning 而非静默通过 |

### B4 · 效果包与手写替换（L3）— 工程整洁档，可延后

| 步 | 落点 | 内容 |
|---|---|---|
| 4.1 | 补装 `@remotion/transitions` | 替换 `Transition.tsx` 手写的 3 种转场（约 50 行） |
| 4.2 | 补装 `@remotion/shapes` | 替换 `Shape.tsx` 手写的 4 种 div 形状 |
| 4.3 | `manifest.ts` | `effect` 枚举（光晕 / 描边 / 阴影） |

⚠️ **这批不新增用户可见能力**，只是"用现成库替换手写"。所以优先级低于 B1~B3——除非手写实现出了 bug。

### B5 · 受控组件白名单（L4）— 建议先不做

`component` + `props` 的白名单组件机制，是 devdoc §1.2「不做 LLM 生成 JSX」的**合规替代**，也是"扩展上限"的终极方案。但它**没有场景牵引时做，就是纯投机**。建议：等 B1~B3 用一轮，发现"还有具体画面做不出来"再回头做——那时需求是具体的，白名单该放哪些组件也就自然清楚了。

## 四、每档的验收方式（**说清楚哪些机器能验、哪些不能**）

| 验收对象 | 手段 | 可信度 |
|---|---|---|
| 插值纯函数（端点 / easing / clamp） | `node --test` 单测 | ✅ 强 |
| 契约校验（animate 合法性 / 未知字段告警） | `node --test` 单测 | ✅ 强 |
| 组件**接线存在**（字段被消费） | 静态断言 `track.animate` 出现在组件里 | ⚠️ 中（能防"加了字段忘接线"） |
| **「画面真的动了」** | `scripts/remotion-verify/` 渲两帧（`startFrame` 与中段）比像素差异 | ✅ 强，**但须有 GUI 的终端跑** |
| 打包正确性（无 GUI） | `S10_BUNDLE_ONLY=1 node scripts/remotion-verify/verify.mjs` | ✅ 沙箱内可跑 |
| 成片观感 / 节奏 / 信息完整 | **人看** | ❌ 不可自动覆盖（本仓已明确） |

**必须如实说的一条**：单测断言不了「画面真的动了」。这是本仓「视觉/UX 不在自动覆盖内」的已知边界，所以 B1 的验收里**必须包含一次真渲染**，不能只靠单测绿。

## 五、明确不做（边界清单，避免范围蔓延）

| 不做 | 理由 |
|---|---|
| Lambda 分布式渲染 | 本地桌面产品，无渲染农场 |
| SSR 脱离 GUI（`@remotion/renderer`） | 本机 macOS 14.6 < 15，一加载自打警告；当前 CSR 够用。**仅在"批量渲染"需求出现时重估** |
| `HtmlInCanvas` / `IFrame` | 等于 LLM 生成 HTML ⇒ 破 devdoc §1.2 |
| `@remotion/player` 的可视化**编辑** | 与"agent 写 JSON"的产品主线冲突；只做**只读预览** |
| 词级字幕（KTV 逐词高亮） | 工具链已装（`captions` + `openai-whisper`），但**缺对齐数据源**（whisper 凭据）⇒ 属独立批次，不在本计划内 |
| `createEffect` 效果栈 | 待 B4 之后评估，现在无需求 |

## 六、依赖 / 阻塞（开工前须知）

1. **上一轮的 15 个文件改动仍未 commit**（D1~D5/D11 + P0-B）。B1 应在其之上继续，或先提交切一个干净基线。
2. **`manifest` 是一次性入参、不落库、无存量数据** ⇒ 本仓少数「改契约不需要回填 / 兼容」的地方；新字段全 optional ⇒ 老写法行为完全不变。影响面 = `validateManifest` + 5 组件 + 工具描述 + 4 处 skill 分册 + 2 测试文件。
3. **`remotion-verify` 需要 GUI 桌面**（agent 会话无 GUI）；无 GUI 时只能跑 `S10_BUNDLE_ONLY=1` 的打包验证。
4. **总纲 `SKILL.md` 硬闸 11264 B**（现 10913 B，余 351 B）+ 分册指针覆盖率 ≥50% ⇒ **B1~B2 的表达层改动只落 `code-driven-explainer/references/`，不动总纲**。
5. **测试入口只准 `yarn test:smoke`**，禁裸 `node --test` 扫全目录（`tests/test-discovery-hygiene.test.mjs` 守卫）。
