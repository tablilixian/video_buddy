# Canvas Studio — 修复 / 开发优先级路线图与交接

> 配套文档：`docs/tracking/bug-report.md`（40 条 Bug）、`docs/tracking/requirements.md`（20 条需求）。
> 本文件给出派单优先级与续接用交接提示词。导出时间：2026-10-02。

---

## 一、总原则：先稳地基，再修管线，后扩需求

- Bug 侧：2 致命 + 13 严重中，绝大多数仍是「新建」，**尚未进入系统化修复节奏**。优先打「阻断可用性」与「引用一致性」类缺陷。
- 需求侧：P0 有 12 条，其中 R-P0-01（两阶段 Storyboard）是**产品形态级改造、工作量大**，不应与现有画布阶段稳定性工作并行抢资源，建议后置。
- 验证纪律（沿用本仓）：T1 渲染常量/视觉调参 → build + 定向 canvas 集 + **你桌面自主验收即放行**；T2 布局纯函数/几何 → build + 定向 + 相关 preview 组；T3 跨进程/守卫/错误系统/host 边界 → 全量 `node --test` + verify-previews + 反向变异。

## 三、登记约定（落到本仓 SSOT）

- 编号：Bug / 需求条目需在 `docs/STATUS.md`（SSOT，当前上限 **CV-276**）与 `requirement-tracker` 续登；日常写号直接 +1，**不要每轮 grep 整 docs 树**，仅跨多文档批量时复核一次。
- 文档登记时机：**验收通过后**落（可与代码同一次提交），不预写、不抢在验收前。
- 报告时区分「修产生路径」还是「改存量」：本仓处于开发阶段，只动产生数据的代码路径，不回填历史数据。
