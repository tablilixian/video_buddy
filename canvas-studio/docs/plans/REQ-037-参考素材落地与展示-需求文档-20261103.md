# REQ-037 · 参考素材落地与展示（需求文档）

> **日期**：2026-11-03　**状态**：已拍板，待落码
> **立项痛点**（用户实测，2026-11-03）：用户在**首页**发**视频链接**让 agent 参考，事后想查看这条参考——画布上看不到、故事板上也看不到，**没有任何地方能回看自己提供的参考素材**。
> **拍板人**：用户（本轮对话三条拍板，见 §四）。

---

## 一、现状与根因（对照代码逐条核实，file:line 为 2026-11-03 快照）

### 1.1 现有展示面（4 个）与各自缺口

| 展示面 | 现状 | 缺口 |
|---|---|---|
| 画布节点 | 全类型可落；附件四类全部自动落卡（`src/client/index.ts:596-606`） | 落卡**静默**（`select=false`，2026-09-13 拍板），节点落在「来源右侧」防重叠位（`project-store.ts:1290-1293`），用户无感知即认为「没落」 |
| 参考托盘 | 左侧栏常驻（`ReferenceTray.tsx`） | **只收图片**（`host-tools.ts:2459`：`isReference && kind==='image'`）；视频/音频/文本参考无处可看 |
| 故事板 §07 素材清单 | 契约完备：`type: text/image/video/audio`、`source: user`、`ref: canvasNode/file`、缩略图渲染、状态 pill（`contracts/storyboard.ts:140-177`、`storyboard-render.ts` §07） | **零强制登记**：纪律提示词（`storyboard-discipline-prompt.ts`）、seed 模板、落地门禁（`storyboard-gate.ts`）、skill 总纲对「用户参考必须入册」均无要求；§07 实际只被 agent 当「还缺什么素材」的采购单用 |
| `list_references` | agent 读参考的入口 | 同托盘口径，只收图片；notes 仅 agent 可读，用户不可见 |

### 1.2 三条入口的断点

1. **首页 + 链接**（本次实测踩中）：首页无激活项目，链接在正文里不走附件改道；进项目后 agent 需 `download_video` 落画布（CV-399，已具备），但产物**无参考身份**（`host-tools-remake.ts:216-234` 无 `isReference`）、托盘不收视频、§07 无人登记 → 三道展示面全部落空。
2. **项目内附件**：四类自动落画布（CV-247 改道链路，`index.ts:861-885`）+ 图片自动标参考进托盘（`:574-579`）——但静默、且视频/音频/文本无参考身份。
3. **图片链接**：`upload_image`（`host-tools.ts:2417-2423`）只传后端拿 filename + 回写既有产物节点血缘，**不为外部 URL 建画布节点** → 图片链接参考画布无痕。

### 1.3 agent 可用性事实（拍板依据）

不落画布时：图片仅原生对话 vision 可「看」（产线工具全不可用：image_generate 要 filename、@ref 注入要节点 id）；视频/音频**基本不可用**（media_probe / evidence_grid / video2vl / cut_audio 全要落盘路径或画布节点）；文本内容直接在上下文可用。

## 二、需求范围（五条，已拍板）

### R1 · 参考身份泛化（治「托盘只收图」）

- `isReference` / `referenceRole` 从图片专属泛化到**视频 / 音频 / 文本**节点（契约 `canvas.ts:321` 注释同步）。
- 参考托盘升级为**素材托盘**：四类分区展示（image/video/audio/text），支持查看（图缩略、视频/音频点开播放、文本展开便签）。
- `list_references` 同步扩：references 段按 kind 分组返回（向后兼容：现有 image 条目形态不变）。

### R2 · 链接下载产物标参考（治「download_video 无身份」）

- `download_video` 产物节点默认 `isReference: true`（`referenceRole: 'frame'` 或新增 `'source'`，落码时定）。
- 用户发视频/图片链接 → agent 下载落画布 → 素材托盘立即可见 → agent 全链路工具可 @ref 引用。

### R3 · 图片链接落画布（治「upload_image 不建节点」）

- `upload_image` 收到**非本仓产物**的外部 URL 时，落一个图片节点（复用 `addImportNode` 同款形态与去重指纹），再传后端——保证「链接参考」与「上传参考」在画布上等价可见。
- 注意与 CR-01（跨项目拒读）和现有血缘回写逻辑的边界：只对外部新 URL 建节点，不重复建。

### R4 · 附件「点击再落」（反转 2026-09-05 / 09-13 两个拍板，已获用户点头）

- 项目内发附件：**发送时不再自动落卡**；聊天流里留附件 chip + 「落进画布」按钮，点击才落（四类同路径，复用 `landStudioFiles`）。
- 消息正文追加**附件占位说明**（如「（2 个附件，未落画布）」）——否则 agent 不知道用户发过附件，更不会提醒用户点击。
- agent 侧纪律（skill 总纲）：需要产线使用视频/音频附件而其未落卡时，**明确请用户点「落进画布」**，不要假装能用。
- 首页暂存（lobby stash）行为不变：发送时落，与本项目拍板不冲突。

### R5 · 故事板 §07 参考登记（治「§07 空转」）

- 纪律（skill 总纲 + `write_storyboard` assets 段口径补一句）：**用户提供的任何参考素材（上传 / 链接下载 / 口述文本），登记 §07**——`source:"user"`、`ref:{kind:"canvasNode", id:<节点id>}`、`status:"ready"`；口述文本先落便签节点再引用。
- §07 与画布对账（轻量版）：覆盖层渲染 §07 时，`ref.kind==="canvasNode"` 但节点已不存在 → 标红提示（`storyboard-render.ts` 渲染时按 MediaUrl 解析失败即可判定，无需新查询）。
- 不做「§07 pending 阻断」加码——现有门禁口径不动，避免 agent 反向少登记。

### R6 · 查看入口收口（验收视角）

用户查看自己参考素材的路径定型为两条：
1. **画布素材托盘**（R1）——项目内随时看；
2. **故事板 §07**（R5）——规划面看，带缩略图与状态。

## 三、非目标（本期不做）

- 聊天附件在**未点击落卡**时给 agent 提供产线级访问（vision 之外的）——成本高且与「点击再落」语义冲突；agent 提醒用户点击即可。
- 参考托盘的拖拽编排 / 托盘内直接生成——托盘本期只做「查看 + 引用」。
- 音频/视频参考的 `@ref` 注入语义细化（如音频参考进 BGM 候选）——沿用现有 reference-resolve 匹配池规则（`reference-resolve.ts:143`：音频不能唯一、视频可以；跨模态 ≤12），只扩身份标记不改匹配算法。

## 四、拍板记录（2026-11-03 用户原话口径）

1. **附件落画布形态**：点击「落进画布」时再落；前提（agent 不落也能用）经核实为「图片能看不能用、视频音频基本不能用」——用户确认接受，配合占位说明与 agent 提醒纪律。
2. **文字参考**：落画布便签 + 登记故事板；用户输入侧按现有流程（文本附件本就落便签）。
3. **download_video 产物**：需要参考身份（答「要」）。

## 六、验收清单（桌面验收窗口）

1. 首页发视频链接 → 建项目 → agent 调 download_video → 素材托盘视频分区可见该参考、可播放、§07 出现 `source:"user"` 条目带缩略。
2. 项目内拖入图片 + 视频 + 音频 + 文本各一件发送 → 聊天流出现 chip（未落卡）→ 点击「落进画布」→ 四类节点落卡、图片/视频/音频/文本均可在素材托盘查看。
3. 不点「落进画布」直接问 agent「用我刚发的视频做参考」→ agent 明确提示需要先落卡，不假装可用。
4. 发图片链接（非本仓产物 URL）→ 画布出现图片节点且进素材托盘。
5. 删除某 §07 引用的画布节点 → 覆盖层 §07 该条目标红。
