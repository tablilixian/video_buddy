## 0. 一页结论

文章的核心命题：**「装上 skill 就能做出好视频」是错的 —— 可复制的部分不在提示词里，在对画面的拆解里；skill 只管四步里的最后一步。**

对本项目，这句话要换个说法：

> 我们不缺拆解能力，也不缺制作能力。**缺的是把「按片归档的拆解成果」变成「开工前按需求可挑、可分层借用、能编译进制作指令」的那一层。**
> 四季片 `5b6dcfc6` 的失败不是渲染不够工程化 —— 恰恰相反，它的取证链比文章那套严谨得多。**它失败在开工前没有一支参考片做锚，五条判据全是现编的**，所以「整体别做得像 PPT 一样干巴巴的」这种形容词判据没有任何可对照的实物，最后靠 18 次 `read_image` 也没救回来。

**建议只补「挑选」一层，其余三步不动。** 这是最小对齐，也符合「只修产生数据的路径、不动历史数据」的既有原则。

### 1.2 前作（10-09）补的方法论正本

**拆解一部片子的流程**：两路抽帧 —— 一路视频理解模型挑重要时刻、一路按画面变化自动截关键帧 → 合并去重 → 逐张读图。《AGI概念MV》一部留 496 张，28 部共 **3781 张**。有源码/制作文档的先读源码再看画面。

**每片一份分析文档，三块**（这是最值得抄的一节）：

| 块 | 要求 |
|---|---|
| 内容理解 | 结构、时间线，**「作者说的」与「画面实证的」分开记**（片尾写「全部由 AI 制作」属作者说的；画面里能看到逐词卡拍才是实证） |
| 风格分析 | 画面基调、版式字体、运动与镜头、转场、节奏、声音、技术路线；**不写「很有质感」，写色值、字体名、缓动类型、发生在第几秒** |
| 复用指南 | 可直接用的风格描述 / 一眼认出出处的标志性元素 / **可迁移到别的题材的手法** / **本机做不到的部分** |

**类型表（10-09：28 部 → 11 类）**：分类口径只有一条 —— **结构由什么决定**（一首歌 / 一段旁白 / 一组知识点 / 一个意象 / 一段剧情 / 一个问题 / 一个产品卖点），**画面风格不用来分类**。MV·图解、MV·动态排版、科普长片、概念短片、叙事短片、思辨短片、口播·讲解、口播·插画叙事、片头·品牌短片、产品宣传·UI动效、短视频包装。类型决定的是**骨架起点，不是模板**。

**手法库（10-09：37 条 → 11-07：49 条）**，四组：

| 组 | 条数(10-09) | 代表手法 |
|---|---:|---|
| 贯穿线 | 7 | **数值脊柱**（一个递增的数藏进每个场景，最后涨破定义域，如 P(doom)）、**首尾回环** |
| 把概念变成画面 | 10 | **材料即主题**（讲「AI 只知道文字」就让世界由文字构成）、**数字做成可比的形状** |
| 结构骨架 | 11 | **每段换画风，锁死色板和字体**、**朴素方案逐级失败** |
| 节奏与文字进画面 | 9 | **情绪曲线等于速度曲线**、**歌词即画面**（词不是叠在画面上的字幕，而是被写出来/骑在曲线上/被盖章） |

每条三栏：**适合什么 / 不适合什么 / 出自哪部片子**。作者原话：**「手法库的价值在『不适合』那一栏」**（「每段换画风」放 MV 是亮点，放 30 秒资讯速览就乱）。

**三个结论**：
1. **技术路线按内容选，不按习惯选** —— 粒子/着色器/光线步进 3D → three.js；卡片/图表/文字动效 → **Remotion**；需角色场景插画 → 生图出静态素材再交给代码动起来。
2. **声音单独决策，三条路** —— 按歌做画面（分轨、测节拍、逐词对齐）/ **按旁白做画面（先有配音，字幕和切点跟着人声走）** / 画面声音一起做（读同一张时间表）。
3. **角色表演是代码做视频的结构性短板** —— 用剧本设计绕开：远景背影、遮挡、速度糊、情绪交给脸和符号。

**opus-video 六部分**：参考片拆解 / 视频类型表 / 手法库 / 声音方案 / 画面素材方案 / 渲染引擎。

**有参考片时 6 步**：① 拆参考片出风格摘要（色板、字体、材质、运动与转场、节奏、音画关系、标志性元素）→ ② 定类型 + 拆意图成 **7 维度**（内容 / 借哪几层 / 相似度 / 时长 / 声音 / 画面素材 / 规格，每格标「已知·可默认·必须问」）→ ③ **只问必须问的，一次问完最多四题，每题给选项和推荐理由**；最关键一问是**相似度三档**（照搬风格换内容 / 借骨架做差异 / 只取一两个手法），每次都问不替你假设 → ④ **方案书 + 风格圣经**（色值、字体角色、运动转场规则、**「这部片子不要什么」负面清单**；分场表每镜标**实现依赖：已有 / 需要新装 / 做不到**，做不到的方案阶段就说清改成什么画法）→ ⑤ **先静帧（每场景一张代表帧拼总览）→ 再样片（十几到四十秒）→ 后全片；静帧不过，不渲全片** → ⑥ **按风格圣经逐条自评**。

**无参考片时**：不问「你想要什么风格」。用户只答两件事（讲什么、声音从哪来），其余由模型出 2–3 个方向让用户挑；时长按信息量估（一个概念约 8–15 秒）。一句话动效走**快速档**（复述方案 → 一张静帧 → 直接渲染，不写方案书）。

**不适合**：剪辑实拍素材 / 细腻肢体表演的角色动画 / 文生视频模型。

> 注：作者 10-09 自述 skill 已开源（`github.com/liuzhaowei1/Digital-OPUS-VIDEO-SKILL`，渲染引擎改自 MIT 的 pdoom-video），11-07 说整套含选片台与样片库「打算开源」。**两个时间点的数字不同（28/37/11 → 33/49/12），本文按各自出处标注，不合并。** 仓库地址未核实，本方案不依赖它。

## 2. 提炼：六条可迁移的思路

| # | 思路 | 为什么值钱 |
|---|---|---|
| **T1** | **分类口径是「什么决定结构」，不是画风/平台** | 同画风可出现在完全不同结构的片子里；开工第一问是「这选题该做成什么结构」 |
| **T2** | **手法库的价值在「不适合」那一栏** | 只有「做法」的手法库会被无差别套用；负面约束才是防止翻车的部分 |
| **T3** | **分层借用 + 段落级借用 + 相似度三档** | 把「复刻」从布尔值变成一个可组合的向量；避免「照搬不像、不照搬没参考」 |
| **T4** | **筛选入口是「你手上有什么」** | 开工时已知的是输入物（一首歌/一段旁白/一组知识点/一个卖点），不是「要做哪种类型」 |
| **T5** | **风格圣经 = 可测量描述 + 负面清单 + 实现依赖标注** | 色值/字体/第几秒/缓动类型；「做不到」在方案阶段就换画法，不留到做到一半 |
| **T6** | **判据来自参考片，不是自造；静帧 → 样片 → 全片 → 逐条自评** | 自证的判据等于没判据；对照实物才谈得上「像不像」 |

**一句话**：文章把「审美」从形容词变成了**可检索、可组合、可测量、可编译的数据**。

## 4. 借鉴方案（三个落点，按投入排序）

> 原则：**先数据层、后装配层、最后验收层**；每一步都能单独停、单独验；不新增 skill、不改渲染器、不动历史数据、不重新拆外部样片。

### 落点 1 · 数据层：给拆解库加一层「可检索索引」

在 `src/teardown-store.ts` 的拆解记录上补一组**可选索引字段**（不改既有拆解表结构、不回填历史记录）：

| 字段 | 来源 | 对应文章 |
|---|---|---|
| `inputKind` | 一首歌 / 一段旁白 / 一组知识点 / 一个名字 / 一个卖点 / 一个意象 / 一段剧情 | T4「你手上有什么」 |
| `structureDriver` | 什么决定结构 | T1 |
| `techniques[]` | 手法名 + **适合 / 不适合 / 出自哪片** | T2 |
| `palette[]` / `typeRoles` | 色值、字体角色 | T5 |
| `layers` | 可借的五层（结构 / 风格 / 手法 / 节奏 / 声音）+ 段落级 I/O 起止秒 | T3 |
| `sourceUrl` | 原视频地址（**只挂地址，不搬视频**） | 作者开源口径 |
| `representativeFrames[]` | 代表帧路径 + 秒 + 一句话 | 静帧总览 |

**验收**：新拆的片自动带索引；老记录缺省字段不影响 `load/save`（符合「老 manifest 逐像素不变」同型纪律）。

### 落点 2 · 装配层：选片篮 → 编译成制作指令

出口挂在**既有** `skills/canvas-studio-creation/references/intent-card.md` / `confirm_intent_card` 上，作为其扩展字段，不新增工具：

```
styleBible:     色板色值 / 字体角色 / 运动与转场规则 / 音画关系 / 标志性元素
negativeList:   这部片子不要什么（可测量，逐条可判）
implDeps:       每镜 { 已有 | 需新增 | 做不到→改用 X 画法 }
borrow:         { layers[], segments[], similarity: 照搬|借骨架|取手法 }
```

**关键**：`implDeps` 的「做不到 → 改用 X 画法」必须在**方案阶段**产出，这是文章里最能直接减少返工的一条。

### 落点 3 · 验收层：风格圣经 → Q-C4 判据 JSON

`2026-11-07-渲染与成片质量统筹优化方案.md` 的 **Q-C4（批 2.4，已拍板立项）** 正在做「判据表 JSON 化 + 量化锚点强制」。文章补的正是它缺的那一半：

| | 项目 Q-C4 已有 | 文章补 |
|---|---|---|
| 怎么量 | 坐标 / 边界 / 阈值 / 形容词拒收 | — |
| **量什么** | 目前由用户现编 | **从参考片的风格圣经与负面清单编译** |

两者合并 = 「按风格圣经逐条自评」的机器版。**不需要新建验收链**。

### 明确不做（防 over-engineering）

1. **不建 GUI 选片台**。作者那个是本地 Obsidian 外的单机小工具；本项目先做「数据 + 文本」层，GUI 等真跑通一条片再议。
2. **不引入新 skill、不改 `code-driven-explainer` 主流程、不动 R0–R6 与 M1 硬线**。
3. **不重新拆 28/33 部外部样片**。项目内已有成片与拆解记录就是第一批样本。
4. **不动历史数据**（索引字段缺省即合法）。
5. **不把文章的类型表搬进来替换六体裁**。两套口径并存：六体裁是「内容体裁 + 平台」，`structureDriver` 是「结构由什么决定」，互为补充。

### 两个必须拍板的设计冲突（**这才是真要讨论的地方**）

| # | 冲突 | 文章 | 项目现状 | 建议 |
|---|---|---|---|---|
| **C1** | **打断次数** | 「相似度**每次都问**，不替你假设」+ 一次最多四题 | `code-driven-explainer` SKILL.md:35-39 **只打断一次**（合并进意图卡），auto 模式不问不弹卡；实测「拖到第 33 步才问，答案一变全返工」 | **不新增打断**：把相似度作为意图卡里的一个预置选项（缺省「借骨架做差异」），用户不挑就走缺省并在交付说明。**文章的「每次都问」是单机交互，本项目是长自主会话，多一次打断代价高得多** |
| **C2** | **静帧先行 vs M1 先出片** | 静帧不过不渲全片（先定审美） | `SKILL.md:47,53-69` 先出片再丰富，M1 = 故事板落地后 **20 分钟内必须有成片**，禁止「未出 M1 就做美化」 | **不推翻 M1**：把「每场景一张代表帧拼总览」降为**方案阶段的一张静态拼版**（不占渲染预算、`spotFrames` 额度不动），仅在「有参考片」时启用；无参考片时走现有 R0–R6 |

## 5. 四季片推演（按四步法走一遍）

> 样本：`《为什么地球公转产生四季》` 45s / 16:9 / 30fps / 1350 帧 / 中文配音 + 词级卡拉OK。
> 现有基准：`docs/demos/2026-11-07-四季片验收基准提示词-两版.md`（A 工程口径 / B 用户口径）。
> 失败证据：`docs/plans/四季片失败会话复盘-20261107.md`（D-01~09 / R-01~03 / P-01~06）。

### 步骤 1 · 收集与筛选：先答「手上有什么」

| 手上有什么 | 对应 `inputKind` |
|---|---|
| 一组知识点（黄赤交角 / 直射·斜射 / 回归线 / 公转） | `一组知识点` |
| 一段（待录的）旁白 | `一段旁白/配音` |
| 一组数据（GISTEMP v4，1995–2024，30 点） | 数据卡输入 |

→ 结构驱动 = **知识点 + 旁白** ⇒ 类型落在「**口播·讲解 / 科普长片**」，声音路线 = **按旁白做画面**（旁白先定稿 → TTS 真值 → 切点跟人声）。这条项目已经做对了，不用改。

### 步骤 2 · 挑选（现在完全没有的一步）

假设库里有 2–3 支可挑的参考片，选片篮拼出：

```
借：
  结构骨架  ← 科普长片《从现在看过去·AI简史》的「首尾回环」（开场提问 → 结尾回到同一构图）
  手法      ← 数值脊柱：23.5° 反复出现（地轴 → 回归线 → 仪表盘指针 → 引线图），最后收束在指针终值
  手法      ← 数字做成可比的形状（直射/斜射的能量密度用面积比，不写抽象形容词）
  手法      ← 每段换画风，但锁死色板与字体（三色 + 一套中文全局字体）
  节奏      ← 情绪曲线=速度曲线；切点跟旁白真值，不跟字数
  声音      ← 按旁白做画面
相似度：借骨架做差异（不照搬、不只取一两个手法）
时长 45s / 16:9 / 中文 TTS / 和参考 0.5 像
```

### 步骤 3 · 风格圣经 + 负面清单 + 实现依赖（**价值最大一步**）

**风格圣经**：色板锁 3 个色值（示意：背景 `#0b1220` / 主体 `#e8e4d8` / 强调 `#ff6b2c`），全片不许出现第 4 个主色；中文字体 1 套全局声明 + 数字 1 套等宽；转场只用「分区揭示」，禁止硬切黑帧；旁白 4–5 字/秒定稿后才合成 TTS，段边界取音频真值。

**负面清单**（逐条可测量，直接由四季片失败清单反推）：

| # | 不要什么 | 量化判据 |
|---|---|---|
| N1 | 不要「PPT 感」 | ≥3 类运动（仪表盘摆动 / 折线生长 / 分区揭示），每 3s 内画面必有变化 |
| N2 | 不要首帧/末帧裸画面 | 第 0 帧与第 1349 帧均有字幕或主体元素覆盖 |
| N3 | 不要 wipe 期间整屏空 | 两段揭示窗口内任一帧，左右可见区之和 ≥ 60% |
| N4 | 不要数据自相矛盾 | countUp 中间帧不得出现「终值年份 + 中间值」组合；30 点同源同口径 |
| N5 | 不要隔年取样冒称 30 年 | 数据点 = 30，标签可抽稀但**点数不变** |
| N6 | 不要引线悬空 | 锚点与目标端点横偏 ≤ 4px，且必须落在地轴线段上 |
| N7 | 不要弧线断续 | 仪表盘弧连通域 = 1 |
| N8 | 不要字幕与语音脱钩 | 每句词级窗口 / 音频真值漂移 < 5% |

**实现依赖表**（方案阶段就写死，对照 `2026-11-07-批0批1可执行实施计划.md` 的 Q 系列）：

| 需求 | 依赖状态 | 做不到时改用什么画法 |
|---|---|---|
| 30 点折线 + 末点标签 | **做不到**（Q-A3 `labelEvery` 缺） | 方案阶段即定：抽稀标签不改点数，或明写降到 16 点并**不许标「近 30 年」** |
| 图表标题 | **做不到**（Q-A4 `title` 缺） | 用独立 `textCard` 叠在图表上方，标题仍须出现在画面上 |
| 仪表盘弧 `draw` | **需修**（Q-A2 Chrome 150 dash 语义坏） | 不传 `draw`，首帧即成实线 |
| 引线锚点 | **已有但需量化锚点** | 像素反算必须由成片帧取得，**禁拿 manifest 自证**（复盘 P-03） |
| 词级卡拉OK | **需修**（Q-A1 坐标系 + Q-A7 音频真值等分） | 未修前不得承诺「逐字高亮」 |

### 步骤 4 · 制作与自评

代表帧拼版（方案阶段静态）→ R0–R6 出 M1 → `spotFrames` 一次取满 ≤8 帧 → 按 **N1–N8 + 风格圣经** 逐条判（复用 Q-C4 判据 JSON）→ 全片。

**关键差异**：现在的 A 版提示词里，B0–B7 是**用户现编的规格**；加了挑选层后，判据里多一组**「与参考片的对照项」**（色板是否锁死、贯穿线是否贯穿、首尾是否回环）。前者测「做对没」，后者测「像不像、散不散」。

### 推演结论：四季片的九条缺陷会被前移到哪一步

| 缺陷 | 现有发现时机 | 加了挑选层后 |
|---|---|---|
| D-01 首帧全黑 | 成片后像素复核 | **N2 风格圣经**，方案阶段入判据 |
| D-03 词级漂移 +131% | 成片后自己打印了却没判 | **N8 + 声音路线「按旁白」**，方案阶段定真值口径 |
| D-05 引线悬空却报精确 | 交付后复核（自证） | **N6 量化锚点 + 禁自证**，方案阶段 |
| D-06 末点裁切 / 无标题 | 成片后 | **implDeps 做不到**，方案阶段换画法 |
| D-07 卡片标 2025 显示 0.47 | 成片后 | **N4 负面清单**，方案阶段 |
| D-08 分区对比右半屏全空 | 成片后 | **N3**，方案阶段 |
| D-09 16 点冒称三十年 | 交付时被记为未决项 | **N5 + implDeps**，方案阶段 |
| D-02 卡拉OK 全灰 / D-04 弧线虚线 | 成片后 | **implDeps「需修」** —— 至少在方案阶段暴露，不会带着承诺开工 |

> **不要过度归因**：R-01/R-02/R-03 是**代码 bug 和执行器故障**，挑选层一个都修不了，批 0/1 该做还得做。挑选层解决的是另一类病 —— **复盘 §10 那句「判据必须写成可测量的形式，否则模型用形容词交卷」**：它补的是「判据从哪来」。
