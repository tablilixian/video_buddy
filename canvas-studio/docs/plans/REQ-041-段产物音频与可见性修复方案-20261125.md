## 2. 两个问题的直接回答

### Q1：段视频没声音，是设计还是没做好？

**是明确设计，两层叠加，不是功能缺陷。**

1. **渲染层（R11-C3 / D3）**：段 manifest 剥掉 `audio`，`muteAudio: true` 恒真，Remotion 靠 `muted: true` 关音轨。代码注释写明：直接写 `audioCodec: null` 会被 web-renderer 的 `?? default` 吃回 aac，产出 -91dB 静音轨与拼接点 40ms 定格；`concatShots` 用 `-c copy` 拼接，要求所有段流结构一致。
2. **交互层**：hover 自动播放必须 muted，浏览器硬限制。

**成片是有声音的**（回执 `音轨 BGM + 旁白`、`✅ 音频 2 个出声源`），无声的只有卡上那段预览视频。现在要用工具把它俩合起来——这不推翻设计，而是**新增一条面向预览的带声副本**，缓存里的无声段保持原样供 concat。

### Q2：为什么一个分镜视频也没生成？

**两个独立断点，必须都修，只修一个用户还是看不到。**

**断点① 渲染层没进分镜路径。** `shot-render.ts:267` 传 `allowShots: manifest.audio === undefined`；11 句旁白 ⇒ false ⇒ `shot-cache.ts:273` 直接 `mode:'whole'`，回 `outcome:null` + 空段清单，落回整片。会话回执里那句 `ℹ️ 分镜渲染未启用` 就是这条分支。而且会话里大多是 probe/spot 调用，在 `host-tools.ts:3983` 的 `if (!probe && !spot)` 之外，连 `runShotRender` 都不进；唯一主片 draft 又卡死在 RenderHost 31s。

**断点② 清单层 draft 没有数据源。** 14:27:08 磁盘上已有 11 个 `assets/seg-s*.mp4`，但没有 `deliver/card.json`：`host-tools.ts:4063` 只在 standard/high 写卡，draft 不写，而 L1 清单路由只读 `card.json` ⇒ 清单空 ⇒ 卡上依旧是文案。

**用户截图里的"声音跟分镜托盘对应上了"不假**：托盘是纯视觉框，卡和配音一一对应是布局算出来的；数据里 `edges` 为 0，没有真正的连线。这个对应关系另有更可靠的来源——`voiceOver[].startFrame` 落在段帧窗、src 与 tts 节点 url 完全相同（11/11 已验证）。

## 3. 设计约束（不可退让）

1. 成片路径零改动：`audio-compose` / `concatShots` / `runRenderJobWithStuckRetry` 一行不动。
2. 不写 `canvas.json`、不建段节点、不新增 surface、不改点击手势。
3. 匹配只认 `ref`（spec 原文 id 经 `segmentRefOf`），仅 `aligned` 时生成；**禁止按序号配**。
4. 段副本确定性命名、覆盖写，不用 `saveLocalAssetBytes`。
5. 存量不回填；旧文件缺 `ref` 就是缺，清单不猜。
6. hover 恒静音（浏览器硬限制）；点击手势不变。
7. **无声段与带声段分开存放**：concat 只用无声段，保证流结构一致；画布清单只指带声段。两者不共用文件。

## 9. 复审后补的两条（2026-11-25 下午）

### 9.1 P1-4 旁白偏移：段窗起点不是台词起点

原实现把整条旁白贴段首合流。真机数据暴露口径不一致（`fps=30`）：

| 段 | 段窗 `[start,end)` | 旁白 `startFrame` | 差 | 后果 |
|---|---|---|---|---|
| s1 | `[0,235)` | 0 | 0 | 恰好对齐，看不出问题 |
| s2 | `[235,480)` | 245 | 10 帧 / 0.333s | 预览里台词比成片晚 0.333s 开口、句尾多截 0.333s |
| s3 | `[480,687)` | 490 | 10 帧 | 同上 |
| s4 | `[687,...)` | 697 | 10 帧 | 同上 |

改法（三处，都不碰成片路径）：
- `segment-audio.ts`：`SegmentVoiceMatch` 加 `offsetSec`，`matchVoiceForSegment` 收 `fps`
  并按 `(voice.startFrame - 段首) / fps` 算；`matchSegmentVoices` 从 `manifest.meta.fps` 取。
  脏数据（fps 非正）兜底 0 ⇒ 退回旧行为，不拿 NaN 去算毫秒。
- `audio-compose.ts`：`buildMuxArgs` 加第 5 参 `audioOffsetSec = 0`，仅在 > 0 时插
  `-af adelay=<ms>|<ms>`。**默认不传 ⇒ 参数与改前逐字相同**（成片 `compose.ts` 调用点不动）。
  用 `adelay` 而非 `-itsoffset`：后者在音频重编码时产负时间戳，播放器可能吞掉开头；
  用 `ms|ms` 老语法（3.x 起支持），`all=1` 要 4.2+，不赌内置版本。
- `segment-voice-merge.ts`：合声时传 `match.offsetSec`。

真机验证（项目 2，s2 + b63b7c8d.mp3，段长 8.167s）：
`ffprobe` = h264 960×540 + aac 双流，视频 8.167s；`volumedetect` 前 0.30s 均值 −69.9dB /
峰值 −36.7dB，段内 0.35~0.80s 均值 −39.7dB —— 前置静音确实补上了（原旁白同段是 −49.5dB，有声）。

### 9.2 复审 #1 同帧窗多档缓存：不许按目录顺序取

`cacheIndexByWindow` 原先「同帧窗多 hash 取 readdir 最后一个」。draft 渲过、standard 再渲过后
两份缓存共存（文件名 = `hash(帧窗, quality, globals)`），取谁就成了文件系统顺序的函数 ⇒
卡上画质会在半分辨率与全分辨率之间跳，A1「逐帧一致」不成立。

改法：`QUALITY_RANK = { draft: 0, standard: 1, high: 2 }`，同帧窗只允许更高档覆盖；未知档
（旧 meta 无 `quality`）视为最低，同为未知时保持先到的。只有 draft 时照用（不许因此整段不发）。

**守卫踩到的假绿值得记一笔**：第一版测试把 draft 与 high 写进同一目录就断言，跑变异（退回
「取最后一个」）竟然全绿 —— 因为该机 `readdir` 顺序是名字序，`…draft` < `…high`，high 恰好
排在后面，「取最后一个」正好取对。改成「名字倒排（`z…draft` / `a…high`）+ 断言必须造出
『低档在末尾』的场景」后变异才红。教训：**对顺序敏感的守卫，必须自己构造出不利顺序，并
断言构造成功**，否则它只是个摆设。

### 验证

`tsc → 双 tsc → verify:loader → yarn test:smoke` = **3916 全绿**。三条反向变异逐条变红：
偏移恒 0 / 删掉 `adelay` / 择优逻辑退回无条件覆盖，恢复后均复跑全绿。
