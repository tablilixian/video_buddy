### 1.3 渲染链路（route B / CSR，6 步）

```
render_composition(manifest JSON)
  → 宿主：JSON.parse → validateManifest → materializeManifestSources
        → checkManifestAssets（ffprobe 探真时长，串行）
        → 审批门 → 建单入队（并发 1 / 队列 4 / FIFO）
  → 客户端 poll（1s 一拍）→ 预览闸门（Player 只读）
        → applyManifestFonts → probeManifestDurations（浏览器再探一遍）
        → canRenderMediaOnWeb → renderMediaOnWeb → getBlob
  → 回写字节 → 宿主 saveLocalAssetBytes → probeMediaInfo → 结算
```

**已有优势**：超时从**派发时刻**起算（排队不吃预算）；队列严格 FIFO；失败分类只重试 `encode` 类；进度按 3% 台阶节流回传。

## 二、诊断：为什么「能渲」但「不好看、不够快」

一句话：**过去两期补的是「表达得出来」，三期要补的是「表达得好」和「表达得起」。** 五个根因，全部有代码证据。

### 根因 1：枚举太窄 —— 模型写出的已经是「上限」

| 事实 | 证据 | 后果 |
|---|---|---|
| 缓动只有 4 档，且**全是二次曲线** | `timing.ts:355-360`：`easeOut = 1-(1-t)²` | 入场收尾「软塌」；没有 expo 的急速收束，也没有回弹 |
| 没有 spring | 全仓 `src/remotion/` 搜 `spring` 零命中 | 元素没有「重量」，一切都是匀速感插值 |
| 颜色不能动 | `shape.color` / `textCard.accentColor` 是静态字符串 | 品牌色渐变、氛围转暖做不到 |
| 没有混合模式 | 只靠 DOM 叠放 + opacity | 光晕、光泄漏、双重曝光做不到 |
| 没有全局调色 | 无 contrast/saturation/vignette/grain | 成片像「网页截图」，不像「拍出来的」 |

**这条最要命**：模型不是不会写，是**写出来也没用**。同一份 30s 片子，把 `easeOut` 换成 `easeOutExpo`、给 3 个元素加 spring 过冲、加 0.35 暗角 + 0.15 颗粒，观感差异远大于把 skill 文案改十版。

### 根因 2：缺编排原语 —— 「逻辑不严谨」是结构问题，不是文案问题

| 缺口 | 现状 | 后果 |
|---|---|---|
| 退场 | 只有 `fadeFrames`（首尾对称淡化），没有「退场动画」 | 元素只进不出，画面越叠越满，最后硬切消失 |
| 错峰 | 无原语，靠模型手算 `startFrame` | 6 个元素同帧入场 = 观感「假」的第一原因 |
| 顺序衔接 | 无 `Series` 等价物，每条轨自己算绝对帧 | 改一句字幕时长，后面全套帧号要重算，模型必然算错 |
| 编排体检 | 无 | 上面三类错误**没有任何一方告诉模型** |

### 根因 3：校验只查「结构合法」，不查「语义合理」

`validateManifest` 会拦 `easing: 'easeOutExpo'`（不在白名单），但**不会拦**：
- 3 条轨同帧入场；
- 动画只用 3 帧（观感是抖动）；
- 元素从 x=120 进场（画外，观众看不到）；
- 有入场、无退场、`fadeFrames: 0`（硬切消失）；
- 转场窗口 4 帧（肉眼看不见）。

这些全是「校验通过、成片难看」的典型案例。**把专业动效的 10 条纪律做成 lint，比写进 skill 有效 10 倍**——skill 是建议，lint 是回执。

### 根因 4：速度是黑盒 —— 没人知道一帧多少钱，所以不敢迭代

| 事实 | 证据 |
|---|---|
| 唯一性能基线是**卡片片**：13 ms/帧 @1280×720（暖机） | `remotion-spike-report-2026-10-15.md:376` |
| **视频轨的 ms/帧从未测过** | 同报告 §9.2 列为「待验」 |
| 27 个渲染参数只用 7 个 | `remotion-render.ts:88-109` 只传 container/codec×2/outputTarget/licenseKey/onProgress/signal |
| `pageResponsiveness` 默认 `medium` = **每 33ms 主动让出主线程** | web-renderer 包内 `PRESET_INTERVALS` |
| `mediaCacheSizeInBytes` 默认 `null` = 不缓存解码结果 | 包内默认值展开处 |
| 素材时长探测：宿主串行 ffprobe + 客户端串行 `<video>` **各一遍** | `asset-check.ts:51` / `remotion-render.ts:229` |
| 队列并发 = 1，且 web-renderer **模块级串行** | `render-queue.ts:26` + 包内 `onlyOneMediaRenderAtATimeQueue` |

**结论**：提并发无意义；真正的杠杆是「每帧更便宜 / 帧数更少 / 编码更快 / 少重渲」。

### 根因 5：没人看画面 —— 视觉问题只能靠用户发现

当前交付给 agent 的是 `{url, duration, width, height, warnings}`。**agent 看不到任何一帧**，用户要等到成片出来才知道「字压边了」「元素出画了」「字幕晚了 0.4s」。
`web-renderer` 提供了 `onFrame`（逐帧回调，能拿到 `VideoFrame`）和 `renderStillOnWeb`（单帧渲染），我们**都没用**。

### 6.1 W1 编排层（决定「逻辑严谨」）

#### W1-1 `exit`（退场）

**问题**：现在元素只有「进」和「硬消失」。`fadeFrames` 是首尾对称淡化，且固定在轨道两端——想做「先上浮淡出再离开」做不到。

**契约**：
```json
"exit": { "to": { "y": 44, "opacity": 0 }, "durationInFrames": 8, "easing": "easeIn", "gapFrames": 0 }
```
- 退场区间 = `[dur - gapFrames - exitDuration, dur - gapFrames)`；
- `from` **自动**取「入场动画在退场起点处的读数」（D-02 选 A）⇒ 不跳变；
- `durationInFrames` 缺省 = `clamp(round(入场时长 × 0.6), 4, 12)`（「退场比进场快」）；
- 与 `transition` 转场窗口重叠时：opacity 相乘（不叠加语义），lint 给提示。

**实现**：`timing.ts` 新增纯函数 `exitStateAt(track, localFrame)`；`resolveAnimatedStyle` 里作为**覆盖层**乘上去（opacity 相乘、位移相加）。绝不改组件。

**落点**：`manifest.ts`（类型 + `KNOWN_BASE_TRACK_KEYS` + 校验）· `timing.ts`（求值）· `animated-style.ts`（接线）· skill `manifest-contract.md`。

**风险**：与 `fadeFrames` 双淡出 → 视觉「灰一下」。缓解：`exit` 存在时 `fadeFrames` 尾部淡化自动让位（只保留首部）。

**验收**：V2；另加「有 exit + 有转场」的组合 fixture。

**预期效果**：30s 片里退场帧占比从 0 到 ~10%；观感从「PPT 切页」变「镜头语言」。

#### W1-2 `startAfter`（顺序衔接）

**问题**：每条轨填绝对 `startFrame`。改一句字幕时长，后面所有帧号要重算——模型必然算错 1–3 处，且错得「看起来像渲染 bug」。

**契约**：
```json
{ "id": "t4", "startAfter": { "trackId": "t3", "gapFrames": 4 } }
```
- 与 `startFrame` **互斥**（同时给 → error）；
- 引用必须指向**数组中更靠前**的轨（天然无环，无需拓扑排序）；
- 解析结果 = `ref.startFrame + ref.durationInFrames + gapFrames`；
- 解析发生在宿主 `normalizeManifestTiming()`（纯函数），**渲染器永远看不到 `startAfter`**；
- 工具结果里回一行「实际解析帧号」，让模型知道算成了什么。

**落点**：`manifest.ts`（字段 + 互斥校验 + known keys）· 新 `src/remotion/normalize-timing.ts` · `host-tools.ts`（校验前归一）· 单测。

**风险**：归一后的 manifest 与用户传入的不同 → 预览/落库口径分叉。缓解：`render_composition` 只把归一结果用于渲染，节点上存原始 manifest + 解析表。

**验收**：V3 + 反向变异（把 `trackId` 指向自身 → 必须报错）。

**预期效果**：「6 个元素同帧冒出」这类片子归零；模型改文案不再连带帧号错。

#### W1-3 编排体检（motion lint，10 条）

**问题**：结构合法 ≠ 观感合理。当前 `validateManifest` 只查结构，`collectUnknownFieldWarnings` 只查字段名。

**契约**：新 `src/remotion/motion-lint.ts`，纯函数 `lintMotion(manifest): {code, message, at, hint}[]`，**只产 warning**（D-10 选 A）。接入两处：`validateManifest` 末尾（并入 warnings）+ 工具结果置顶「编排体检」块。

| Code | 触发 | 回执文案要点 |
|---|---|---|
| ML-01 | ≥3 条内容轨同帧 `startFrame` 且都带 `animate` | 建议错峰 3–6 帧，或用 `startAfter` |
| ML-02 | 轨在片尾前结束、`fadeFrames:0`、无 `exit`、无尾部转场 | 「硬切离场」建议加 `exit` |
| ML-03 | `animate.durationInFrames < 6` | 低于 6 帧观感是抖动（30fps 下 0.2s） |
| ML-04 | `animate.durationInFrames > 45` 且位移 < 10% | 拖沓，建议 18–30 帧或加位移 |
| ML-05 | 有位移/缩放却用 `linear` | 建议 `easeOutCubic` 及以上 |
| ML-06 | 转场窗口 `< 6` 帧 | 肉眼几乎看不见 |
| ML-07 | 同帧 ≥4 条轨在动 | 主次不清，建议 1 主 2 次 |
| ML-08 | 全片 `exit` 数为 0 且轨数 ≥ 5 | 建议片尾统一退场 |
| ML-09 | `animate` 端点 `x/y` 超出 [0,100] | 元素会跑出画（除非刻意） |
| ML-10 | 静态时长占比 > 70% | 复用 `slideshow-risk` 的 motion ratio，整合输出 |

**风险**：lint 噪音（合法但刻意的写法被提示）。缓解：文案带 `hint` 而非命令式；上限 12 条；可用 `meta.lint: "off"` 关闭。

**验收**：V4（10 条各一个反例，逐条断言 code）。

**预期效果**：「逻辑不严谨」从主观抱怨变成 10 条可计数指标；每批成片前能拿到体检回执。

### 6.2 W2 表现力层（决定「好不好看」）

#### W2-1 缓动族扩档（P0）

**现状**：4 档、全二次（`timing.ts:355`）。**目标**：10 档 + 可选 bezier。

```ts
type AnimateEasing =
  | 'linear' | 'easeIn' | 'easeOut' | 'easeInOut'          // 老 4 档，实现不动
  | 'easeInCubic' | 'easeOutCubic' | 'easeInOutCubic'
  | 'easeOutQuart' | 'easeOutExpo' | 'easeOutCirc' | 'easeInOutExpo'
  | 'backOut'                                              // 过冲 1.10 倍，opacity 自动 clamp
```
- 全部纯函数、端点收敛、**老 4 档公式一字不改**（老 manifest 逐像素不变）；
- `backOut` 的过冲只作用于 `x/y/scale/rotation`，`opacity` 走 clamp；
- 白名单之外仍报错（防模型编曲线）。

**落点**：`timing.ts`（`EASINGS`）· `manifest.ts`（`AnimateEasing` + `ANIMATE_EASINGS` + 工具描述里的枚举串）· skill。

**预期效果**：入场收尾从「减速软塌」变「急速收束」。同一段 18 帧滑入，`easeOutCubic` 前 40% 走 70% 行程，`easeOutExpo` 前 30% 走 88%——「贵感」主要来自这个比例。

#### W2-2 spring（P0，D-01 选 A）

**契约**：`easing: 'spring'` + 可选 `spring?: { stiffness?: number; damping?: number; mass?: number }`（缺省 170 / 18 / 1 ⇒ ζ≈0.69、过冲约 5%）。
**实现**：阻尼谐振子闭式解 `1 - e^{-ζωt}(cos ω_d t + …)`，按**归一化时间**求值，settle 时间解析求出后做时间缩放。零依赖、可单测、确定性。
**验证**：对 20 组参数，与 `remotion` 的 `spring()` 采样对比，误差 < 1e-3（**测试里** import remotion，产品代码不 import）。

**预期效果**：元素「有重量」；卡片弹入不再是「匀速到位」。

#### W2-3 `colorShift`（P1）

```json
"colorShift": { "from": "#4f9cf9", "to": "#ff7a59", "durationInFrames": 60, "easing": "easeInOut" }
```
作用对象：`shape.color` / `textCard.accentColor` / `audioViz.color`。sRGB 线性插值（D-05 备注：OKLab 留 P2）。区间外取端点。

#### W2-4 `meta.look` 全局调色（P0，D-05 选 A / D-06 选 A）

```json
"meta": { "look": { "contrast": 1.06, "saturation": 1.12, "brightness": 1.02,
                    "temperature": 0.12, "vignette": 0.35, "grain": 0.16 } }
```
实现（三层，全部逐帧确定性）：
1. **色彩**：最外层 `filter: contrast() saturate() brightness() sepia() hue-rotate()`（温度用 sepia+hue-rotate 近似）；
2. **暗角**：`radial-gradient` 覆盖层，`mix-blend-mode: multiply`；
3. **颗粒**：随包噪点 tile PNG（512×512，~80KB，随包离线），`background-position` 按帧整数偏移 `(frame*37%512, frame*61%512)`，`opacity: grain`。

**为什么不逐轨**：调色是「全片统一」的事；逐轨调必然花，且模型会滥用。
**为什么不用 SVG `feTurbulence`**：每帧栅格化滤镜，成本不可控（D-06）。

**风险**：`filter` 在大图层上可能显著降速 → 纳入 W5 参数矩阵一起测；若 >15% 降速则闸门化（仅 `quality: high` 档启用）。

**预期效果**：从「网页截图」到「成片」最直接的一步。0.35 暗角 + 0.16 颗粒 + 1.06 对比，是最低成本的「电影感三件套」。

#### W2-5 `blend`（P1）

`tracks[].blend: 'normal'|'screen'|'multiply'|'overlay'|'soft-light'` → CSS `mix-blend-mode`。
用途：光晕叠加（screen）、双重曝光（soft-light）、纹理压暗（multiply）。**零运行时成本**（GPU 合成）。

#### W2-6 转场参数化（P1）

```json
"transition": { "effect": "wipeLeft", "fromTrackId": "a", "toTrackId": "b",
                "easing": "easeInOutCubic", "softness": 0.35, "direction": "left" }
```
- `softness` > 0 时用两段 `linear-gradient` 做**软边**（当前是硬 `clipPath`，观感廉价）；
- `easing` 复用 `AnimateEasing` 白名单；
- `direction` 只对 slide/wipe 生效，非法组合 warning。

#### W2-7 fx 扩展（P2）

`bloom`（双层 blur + screen）、`lightLeak`（斜向暖色渐变 + screen + 缓慢位移）、`colorWash`（单色 overlay）。**必须先测成本**再决定是否进主路径。

### 6.3 W3 媒体层（决定「素材用不用足」）

#### W3-1 裁剪 / 速率 / 静音 / 音量（P0）

```json
"video": { "src": "…", "trimBeforeFrames": 45, "playbackRate": 0.5,
           "muted": false, "volume": 0.8, "loop": false }
```
`@remotion/media` 的 `<Video>` 已支持 `trimBefore` / `durationInFrames` / `playbackRate` / `muted` / `volume` / `loop`（包内 `video/props.d.ts` 已核）。
**语义**：`trimBeforeFrames` 与 `durationInFrames` 同域，都是**帧**（包内实现为 `trimAfter = trimBefore + durationInFrames`，按合成 fps 折算到素材时间轴）。源素材 fps 与输出 fps 不同时，契约里由宿主换算成输出帧再写入；校验非负整数。**开工前先用一条 24fps 素材在 30fps 合成里做 3 组定点验证**（第 0/24/48 帧画面比对），别凭推断写文档。
**预期效果**：一条 8s 素材可用其中 2.5s；0.5× 慢动作是最便宜的「电影感」；原声终于能关。

#### W3-2 音量包络 + BGM 闪避（P1，D-09 选 A）

```json
"audio": { "bgmUrl": "…", "voiceOverUrl": "…",
           "fadeInSeconds": 0.6, "fadeOutSeconds": 1.2,
           "duck": { "amount": 0.55 } }
```
- 淡入淡出：整轨线性 ramp（`volume` 支持函数 ⇒ 传 `(f) => …`，仍是帧的纯函数）；
- 闪避：**以字幕轨窗口为依据**——字幕在屏时 BGM 降到 `amount`，前后各 6 帧过渡。确定性、零音频分析。
- 近似说明写进契约注释：旁白间隙不恢复（字幕连续时 BGM 全程压低）。

#### W3-3 audioViz 升级（P1）

- 改用 `@remotion/media-utils` 的 `getAudioData` / `useAudioData`（包已装），**删掉手写 `decodeAudioData` 与 512 格 RMS**；
- 保留 `waveformBars` 纯函数（它已经是确定性的一层，别动）；
- 新增 `mode: 'line'`（波形线）与 `gradient`（柱体渐变）；
- `smoothing`（0–0.9，帧间指数平滑）——仍是纯函数。

**风险**：`getAudioData` 是否严格确定性需实测（同一文件两次解码的浮点一致性）；若不一致，退回现有实现。

#### W3-4 预取（P0）

首帧前对全部 `video` / `image` / `audio` 调 `prefetch(src)` + `delayRender`（超时 8s 放行）。避免「前 3 帧黑、后面正常」这类只在慢机器上出现的缺陷。

### 6.4 W4 文本层（决定「信息读不读得进」）

#### W4-1 真实文本测量（P0，D-07 选 A）

**现状**：`charWidthRatio` 用「CJK 1.0 / 拉丁 0.55 / 空格 0.3」估算（`timing.ts:616`）。西文比例字体、标点、数字都会偏。
**做法**：新增可注入的测量器接口：

```ts
type TextMeasurer = (text: string, fontPx: number, family: string, weight: number) => number
```
- 浏览器侧：`canvas.getContext('2d').measureText`，结果进 `Map` 缓存（key = family|weight|px|text），首次测量用 `delayRender` 闸门；
- Host / node 测试侧：仍用估算器（现有实现降级为 fallback）；
- `fitTextPolicy` 改成接受测量器参数，**默认行为不变**（不传 = 估算）。

**验收**：同一段 42 字中文 + 12 词英文，估算器与真实测量行数差异 ≥1 行的样例必须被修正；老 manifest 渲染结果不变（`fitOrKeep` 已保证「没溢出就原样返回」）。

#### W4-2 文本动效预设（P1）

```json
"textCard": { "variant": "title", "text": "…", "anim": "wordStagger",
              "animOptions": { "wordDelayFrames": 3, "offsetY": 14, "blur": 4 } }
```
预设四种：`fadeUp` / `maskReveal`（遮罩自上而下揭示）/ `typewriter`（按字推进 + 光标）/ `wordStagger`（逐词淡入上浮）。
**实现**：纯函数把帧换算成「每个词/字的进度」，组件按词切 `<span>`。**不用 CSS 动画**。
**预期效果**：标题从「整块淡入」变「逐词落位」，是最容易被用户感知的「高级感」。

#### W4-3 字幕安全区校验（P1）

规则：`subtitle` 变体距底边 ≥ 画布高 12%、最多 2 行（1080p）/ 3 行（720p）、左右各留 8%。
违反 → lint warning（ML-11/12），不阻断。**引擎校验 + skill 文案双写**。

### 6.5 W5 渲染速度（决定「敢不敢迭代」）

#### 6.5.1 成本模型（先把账算清）

```
T ≈ 初始化(1–2s) + 帧数 × (渲染每帧 + 编码每帧) + 素材探测 + 字体就绪
帧数 = durationInFrames（= 秒 × fps）
渲染每帧 ≈ React reconcile + DOM/图层栅格化 + 视频解码
编码每帧 ≈ 编码器吞吐（受分辨率/码率/硬件加速/关键帧间隔影响）
素材探测 ≈ Σ 每段素材的 ffprobe / loadedmetadata
```

四个杠杆，对应四类动作：

| 杠杆 | 手段 | 典型收益 | 风险 |
|---|---|---|---|
| **每帧更便宜** | 减少大图层 `filter`、预取、解码缓存、限制同时动效数 | 10–30% | 视觉妥协 |
| **帧数更少** | 草稿档降 fps（30→24，-20%）、只渲必要区间 | 20–80%（分段） | 时间轴语义变化 |
| **编码更快** | `hardwareAcceleration: 'prefer-hardware'` / 降码率 / 拉长关键帧间隔 / `pageResponsiveness:'disabled'` | 10–40% | 画质/UI 卡顿 |
| **少重渲** | `frameRange` + 段缓存 + 素材/字体/探测缓存 | 迭代 5–10× | 拼接处音画不同步 |

**并发的真相**：web-renderer 在模块级用 `onlyOneMediaRenderAtATimeQueue` 串行化所有 `renderMediaOnWeb` 调用 ⇒ **同进程内多开不会并行**。想真并行只能开多个渲染进程（隐藏 BrowserWindow），那是 P2 实验，不是三期主线。

#### 6.5.2 基线测量（P0，E1）

新脚本 `scripts/probe-remotion-perf.mjs`（需 GUI，与 `remotion-verify` 同族）：

| 维度 | 取值 |
|---|---|
| 片型 | ① 纯卡片 30s ② 6 图 + KenBurns ③ 6 视频片段 ④ audioViz + BGM ⑤ 混合全要素 |
| 分辨率 | 1280×720 / 1920×1088 |
| 参数 | baseline / +hardware / +pageDisabled / +比特率low / +scale0.5 / +cache128MB |
| 输出 | `docs/remotion-perf-baseline-YYYY-MM-DD.json` + 表（ms/帧、总耗时、字节、码率） |

**纪律**：每档跑两遍取第二遍（暖机）；同机同版本；结果入库，后续每批对照。

#### 6.5.3 编码参数（P0，E2）

在 `renderManifestOnWeb` 里按 `quality` 档传参（缺省档 = 今天的默认值，保证不退步）：

| 档 | scale | videoBitrate | keyframeInterval | pageResponsiveness | 用途 |
|---|---|---|---|---|---|
| `draft` | 0.5 | low | 10s | disabled | 迭代预览（默认给 agent 用） |
| `standard` | 1 | medium | 5s | medium | 与今天完全一致 |
| `high` | 1 | high | 2s | medium | 交付/发布 |

`hardwareAcceleration` 在 `draft`/`high` 都设 `prefer-hardware`（失败自动回落，由 capability 探测兜底）。

#### 6.5.4 草稿档（P0，E3）

- 工具参数 `quality?: 'draft'|'standard'|'high'`（缺省 `standard`）；
- `draft` 产物仍走同一落盘与结算，但节点打 `draft: true` 标，UI 角标区分；
- 草稿档跳过「渲染前预览闸门」（它本身就是预览）——**省一次人工等待**；
- 目标：30s 卡片片从 ~12s → ≤5s；含视频按基线比例。

#### 6.5.5 素材探测优化（P0，E4）

三件事，全在既有文件里改：
1. **去重**：`asset-check.ts` 按 `src` 去重（现在同 src 两轨探两次）；
2. **并行**：`Promise.all` + 并发 4（ffprobe 是 IO）；
3. **透传**：`PendingRenderJob` 增加 `realDurations`，客户端**跳过** `probeManifestDurations`（现在宿主探完客户端再探一遍）；
4. **缓存**：`<assetsDir>/.remotion-probe.json`，key = `src + size + mtimeMs`，TTL 7 天。

**收益**：10 段素材从「最坏 8s + 1.5s」降到「首次 ~0.5s，之后 <50ms」。

#### 6.5.6 分段重渲（P1，E5）

- `render_composition` 加内部能力：按 `frameRange` 只渲变更段；
- 段文件用 `ffmpeg concat`（同参数 h264/aac）拼接；
- **适用**：改一句字幕 / 换一个镜头 / 调一段动效；
- **判据**：拼接产物与全量重渲的 4 张抽帧哈希一致（容差 0），音画时长偏差 ≤1 帧；
- **风险**：段边界关键帧对齐、音频重采样接缝。必须先做 20 次随机段拼接实验再上线。

#### 6.5.7 超时策略（P2，E7）

有了基线后，把 `renderTimeoutMs` 的下限从 10min 降到「基线 × 3 + 60s」（不低于 3min）。挂死时用户少等 7 分钟。

### 6.6 W6 闭环验证（决定「错漏能不能自己发现」）

#### W6-1 抽帧自查（P0，F1，D-08 选 A）

**这是三期唯一能闭合「视觉问题没人发现」的机制**，优先级等同表现力。

#### W6-2 渲染报告（P0，F2）

```ts
report: {

```

#### W6-3 预览增强（P1，F3）

#### W6-4 确定性守卫（P1，F4）

## 八、兼容性与铁律

三期加的是**新字段**，不是新语义层。三条护栏必须同时成立：

| 护栏 | 做法 | 守卫 |
|---|---|---|
| 老 manifest 逐像素不变 | 新字段缺省 ⇒ 走原分支；`meta.look` 缺失 ⇒ 不挂滤镜层 | `tests/remotion-backcompat.test.mjs` 串比对 |
| 枚举只增不改 | `AnimateEasing` / `EFFECTS` / `SHAPES` 只追加；老 4 档公式一字不改 | 单测锁定老 4 档采样值 |
| 唯一接线点 | 所有视觉折算仍只在 `resolveAnimatedStyle`；组件不新增插值 | code review + grep 守卫（组件内禁出现 `interpolate(` / `Math.sin(`） |

**另外三条项目铁律**（沿用）：
1. **禁 CSS `transition` / `@keyframes`**——包括 `meta.look` 的颗粒偏移与文本预设，全部按帧求值；
2. **纯函数优先**——新逻辑先进 `timing.ts` / `normalize-timing.ts` / `motion-lint.ts`，组件只贴样式；
3. **契约字段与 `KNOWN_*_KEYS` 同改**——这是二期最容易漏的一步，每条新字段都要在同一提交里补上。

## 九、不做清单（含理由）

| 不做 | 理由 |
|---|---|
| Lambda / CloudRun / 云端渲染 | 单机产品，且许可与成本模型都不支持 |
| Remotion Studio / `Interactive` 可编辑 | 没有 Studio，也没有编辑态需求 |
| `OffthreadVideo` | CSR 无此概念（`@remotion/media` 已覆盖） |
| 任意 JSX / 用户上传组件 | 安全边界 + 确定性都无法保证 |
| 真实运动模糊（多采样） | 成本 × N，收益可用「缓动 + 方向模糊近似」替代；留 P4 |
| Three / 3D / Lottie | 依赖体积与包体红线冲突；且当前需求未出现 |
| 词级卡拉 OK | 缺词级时间戳（TTS 只给句级）；先做「逐词淡入」近似 |
| 自定义 cubic-bezier 任意控制点 | 模型编非法控制点的概率高；10 档命名曲线覆盖 95% 场景，bezier 留 observation |
| 提高渲染并发数 | web-renderer 模块级串行，提高并发**不会更快** |
| 内联其它项目的历史数据修复 | 开发期只修「产生数据的路径」 |
