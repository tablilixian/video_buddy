# 画布自动整理算法 - 完整规则文档

## 一、核心约束（硬规则）

```
规则1: 所有子节点必须在父节点的右侧
       col(child) > col(parent)  ∀ parent ∈ refs(child)
       
       这是画布整理的最高准则。无论初始分配如何，
       最终结果必须保证每一条依赖边都满足此约束。

规则2: 同一节点不能同时出现在两个列中
       每个节点有且仅有一个列号

规则3: 节点不重叠
       任意两个节点的矩形区域不能相交（group 除外，group 包裹子节点）
```

## 二、算法流程

### 步骤1: 构建依赖图

```
输入: nodes 数组，每个节点有 id, kind, refs (sourceIds)
输出: 
  - refsOf[nodeId]    → 该节点依赖的父节点列表
  - childrenOf[nodeId] → 依赖该节点的子节点列表
```

### 步骤2: 计算拓扑层级

```
对每个节点，计算从根节点到该节点的最长路径长度:
  level(node) = 0                        如果 refs 为空
  level(node) = max(level(ref)) + 1      如果 refs 非空

示例:
  创意(16028e82)     → level 0 (根节点)
  剧本(ebb09566)     → level 1 (依赖创意)
  分镜1(b1523974)    → level 2 (依赖剧本)
  参考图·色彩(83b2b311) → level 0 (根节点, 无依赖)
  角色表(e402f62d)   → level 1 (依赖参考图·色彩)
```

### 步骤3: 按层级分组

```
将节点按 level 分组:
  level 0: [创意, BGM, 参考图·器材室, 参考图·色彩, 参考图·色彩2, 参考图·色彩3]
  level 1: [剧本, 角色表, 文案]
  level 2: [分镜1, 分镜2, 分镜3]
  level 3+: [视频v1, 视频v2, 末帧, ...]
```

### 步骤4: 每层内按原始 x 坐标排序

```
同层级内，保持原始的左右顺序:
  level 0 按 x 排序: 创意(40) → 参考图·器材室(1264) → BGM(2836) → ...
```

### 步骤5: 初始列号分配

```
从第0层开始，逐层向下分配:

  第0层: 按排序顺序分配列号 0, 1, 2, 3, ...
  
  第N层 (N>0): 对每个节点:
    maxParentCol = max(col(parent) for parent in refs(node))
    col(node) = maxParentCol + 1

  注意: 此步骤是初始分配，可能因多父节点、层内排序等原因
        导致某些边不满足 col(child) > col(parent)，需要下一步修复。
```

### 步骤6: 依赖关系正确性验证与修复（核心步骤）

```
目的: 确保画布上每一条依赖边都正确表达——子节点在父节点右侧。

这不是"同列修复"，而是全局正确性保证。

算法:
  changed = true
  while changed:
    changed = false
    for node in allNodes:
      for parent in refs(node):
        if col(node) <= col(parent):
          // 违反约束: 子节点不在父节点右侧
          // 修复: 将子节点移到父节点右侧一列
          col(node) = col(parent) + 1
          changed = true

  收敛保证: 有向无环图(DAG)最多迭代 V 次
  
  级联影响: 当节点 col 被修改后，其所有子节点可能也需要重新验证。
           while 循环自然处理了这种情况。

典型触发场景:
  1. 同列父子: 两个节点被分到同一列，但存在依赖关系
  2. 跨列反转: 子节点的列号意外小于父节点（多父节点竞争时可能发生）
  3. 多父节点约束冲突: 子节点需要同时在多个父节点右侧，
     而这些父节点分布在不同列
```

### 步骤7: 每列内分配 y 坐标

```
对每一列:
  1. 按原始 y 坐标排序
  2. 从 y=40 开始，依次向下排列:
     curY = 40
     for node in column:
       node.y = curY
       curY += node.h + ROW_GAP(20px)
```

### 步骤8: Group 节点处理

```
Group 节点的位置由其子节点决定:
  group.x = min(child.x) - padding
  group.y = min(child.y) - padding
  group.w = max(child.x + child.w) - group.x + padding
  group.h = max(child.y + child.h) - group.y + padding
```

### 步骤9: Deprecated 节点处理

```
标记为 superseded 的节点:
  - 缩小显示 (w=180, h=60)
  - 半透明 (opacity=0.4)
  - 虚线边框
```

## 三、参数配置

```
COL_W    = 420   // 列宽 (节点宽度上限)
COL_GAP  = 40    // 列间距
ROW_GAP  = 20    // 同列节点间距
PADDING  = 10    // Group 内边距
START_X  = 40    // 起始 x 坐标
START_Y  = 40    // 起始 y 坐标
```

## 四、特殊场景处理

### 4.1 多父节点

```
节点有多个父节点时:
  col(node) = max(col(parent1), col(parent2), ...) + 1
  
  示例: 分镜3视频(0e12c194) 依赖:
    末帧·分镜2v1 (eda08d28) → col ?
    角色表 (e402f62d) → col ?
    参考图·色彩3 (bc121d05) → col 0
    参考图·器材室 (006d3d02) → col 0
    分镜3 (7948bd51) → col 2
  → col(分镜3视频) = max(?) + 1
```

### 4.2 循环依赖

```
当前算法假设依赖图是 DAG (有向无环图)。
如果存在循环依赖:
  - 检测: 迭代次数超过节点数
  - 处理: 报错或打断循环中最弱的边
```

### 4.3 孤立节点 (无依赖)

```
无 refs 的节点:
  - 归入 level 0
  - 按原始 x 坐标排列
  - 不影响其他节点的列号
```

### 4.4 被多个子节点引用

```
父节点被多个子节点引用时:
  父节点位置固定
  每个子节点独立计算列号
  
  示例: 参考图·器材室(006d3d02) 被分镜1视频、分镜2视频、分镜3视频引用
  → 每个视频节点的列号独立计算
```

### 4.5 级联右移

```
当修复一个节点的列号时，其所有子孙节点可能也需要右移。

示例:
  参考图·色彩(col=0) → 角色表(col=1) → 分镜1视频(col=2)
  如果角色表被移到 col=3，则分镜1视频至少要在 col=4。
  
  while 循环自然处理了这种级联:
  第一轮修复角色表 col=3
  第二轮发现分镜1视频 col=2 < 角色表 col=3，修复为 col=4
  ...
```

## 五、输出格式

```
每个节点输出:
{
  id: string,
  x: number,    // 列号 × (COL_W + COL_GAP) + START_X
  y: number,    // 列内累计高度
  w: number,    // 节点宽度
  h: number,    // 节点高度
}
```

## 六、与现有画布的兼容

```
1. 保留节点的 w, h 属性 (节点大小不变)
2. 只重新计算 x, y (位置重排)
3. 保留节点的 kind, title, asset 等属性
4. 连线根据新的 x, y 自动重绘
5. Group 的 w, h 由子节点决定
```

## 七、算法复杂度

```
时间: O(V + E)  构建图 + 拓扑排序
      O(V × E)  依赖关系修复 (最坏情况，实际远小于此)
空间: O(V)      列号数组 + 层级数组

其中 V = 节点数, E = 依赖边数
当前画布: V=22, E≈30 → 计算量极小
```

## 八、正确性证明

```
终止性:
  每次修复只增大 col(node)，而 col 有上界 (V-1)。
  因此 while 循环最多执行 V 次。

正确性:
  循环结束后，对任意边 (parent → child):
    col(child) > col(parent)  成立
    
  因为如果存在违反的边，循环会继续修复。

完整性:
  所有节点都被处理，所有边都被验证。
  没有遗漏的情况。
