## 0. 一句话结论

**现在能跑一次「合成」，但不能做「同步测试」—— 缺的是可信的时间基准，不是播放按钮。**

画布上、`list_shots` 里、时间线上的所有时长数字**都是请求值**（agent 填多少就显示多少），
BGM 与成片的长度关系**没有任何工程校验**。用一把不知道准不准的尺子量不出「同步」。

代码侧要补的量很小（下面 P0 三项都在既有链路上），但**顺序不能颠倒**：
先有真值 → 再有判据 → 才谈得上测试。

## 1. 现状核对：哪些数字是真的

| 量 | 现在是什么 | 可信 |
|---|---|---|
| 镜头 `duration`（节点 / 画布 / `list_shots`） | `clampDuration(params.duration, 兜底)` —— 请求值原样落盘（`generate.ts:193`、`:1352`） | ❌ |
| 成片真实时长 | `ffprobe` 探测（`compose.ts:351`） | ✅ 但**合成之后**才出现 |
| BGM 真实时长 | `ffprobe` 探测（`compose.ts:330`） | ✅ 但**只用于淡出起点**，没有参与任何比对 |
| **concat 后的真实时长** | **已经探测了，只是没解析**（`compose.ts:331`，只取了 `hasAudio`） | ⚠️ **一行之差** |
| BGM 与成片长度关系 | 无校验、无裁剪、无补齐（`grep stream_loop` 为空） | ❌ |
| 时间线位置 ↔ 真实秒数 | 按顺序数 `kind==='video'` 节点，无时间刻度（`CanvasTimeline.tsx:40`） | ❌ |

### 1.1 关键发现：路线 B 在合成链路里**几乎零成本**

`compose.ts:331-332` 为了判断有没有音轨，**已经**对 concat 产物跑过一次 `ffmpeg -i`：

```ts
const concatProbe = await runFfmpeg(ffmpegPath, ['-i', concatOutput], FFMPEG_TIMEOUT_MS, composed)
const hasConcatAudio = parseFfmpegStreams(concatProbe.stderr).hasAudio
```

**同一个 stderr 里就带着 duration** —— 补一句 `parseFfmpegDuration(concatProbe.stderr)`，
「成片真实时长」在混音**之前**就到手了。这正是 `av-timeline-plan.md` §3 路线 B 的核心前提，
它不需要额外一次合成、不需要新依赖。

> 意义：P0-3（BGM 时长守卫）的前置数据**已经在手上**，属于「接线」而非「造轮子」。

### 1.2 ⚠️ 已实测确认：短 BGM 会**吃掉画面**（数据丢失）

`buildAmixArgs`（`compose.ts:171-206`）两个分支都带 `-shortest`。实测（本机 ffmpeg，
完全复刻 `buildAmixArgs` 的参数，素材 6s 画面 / 2s BGM）：

| 分支 | 输入 | 输出 | 结果 |
|---|---|---|---|
| **无 concat 音轨**（`-map 0:v -map [bgm] -shortest`） | 6s 画面 + 2s BGM | **2.000s** | ❌ **画面被裁掉 4 秒**，`exit=0`，**静默成功** |
| 有 concat 音轨（`amix=duration=first`） | 6s 画面 + 2s BGM | 6.000s | ✅ 安全 |
| 有 concat 音轨 | 6s 画面 + 20s BGM | 6.000s | ✅ 安全（BGM 超出部分被弃） |

当前 fl2va 产出自带 AAC 音轨（§4.5），正常路径走的是**安全分支**；
但一旦某条片段无音轨（改走 fal / 静音产物），短 BGM 就会**静默截断成片**。
→ P0-3c 从「待实测」**升格为已确认缺陷**。

### 1.3 ⚠️ 已实测确认：BGM 比成片长时，**结尾没有淡出**

`buildBgmFade`（`compose.ts:157-164`）把淡出点算在 `bgmDuration − 1s`：

```ts
const fadeOut = duration > BGM_FADE_SEC
  ? `,afade=t=out:st=${(duration - BGM_FADE_SEC).toFixed(3)}:d=${BGM_FADE_SEC}`
  : ''
```

`duration` 传的是 **BGM 时长**，而成片会被截到**画面长度**。当 BGM 长于成片时，
淡出区间 `[bgmDuration−1, bgmDuration]` **落在成片之外** → 成片结尾根本没有淡出。

实测包络（隔离 BGM 轨，`volume=0.8` + 淡入 + 淡出，BGM 20s / 成片 6s）：

```
   t(s)   现状(淡出点=19s)     正确(淡出点=5s)
   4.75       -23.5 dB            -23.5 dB
   5.00       -23.5 dB            -24.6 dB
   5.25       -23.5 dB            -27.5 dB
   5.50       -23.5 dB   ←结尾    -31.8 dB
   5.75       -23.5 dB   ←结尾    -40.3 dB
```

现状**恒定 −23.5 dB 到末帧**（硬切）；按成片长度算才对（−24.6 → −40.3 dB 平滑衰减）。

> 这与 `audio-acceptance-checklist.md` §4「首尾各 1 秒淡入淡出」的预期**不符**。
> 触发条件是 **BGM 比成片长** —— 而现实中用户/agent 为了保险通常会把 BGM 生成得偏长，
> 所以这不是边缘情况，**是最可能的默认路径**。
> 修法：`buildBgmFade` 的入参应改为 **`min(BGM 时长, 成片时长)`**。这需要成片时长 ——
> 正是 §1.1 那一行 `parseFfmpegDuration(concatProbe.stderr)` 能提供的。**两处修复是同一处数据。**

## 2. 缺的不是功能，是「判据」

「音画同步」不是一句话，它有三个可分别度量、难度递增的层级：

| 级别 | 判据 | 现在能测吗 |
|---|---|---|
| **L1 时长对齐** | `\|时长(音轨) − 时长(视频轨)\| ≤ 1 帧`（1/24s ≈ 41.7ms） | ⚠️ 数据拿得到，但**分离不出音轨**（见下） |
| **L2 起播对齐** | 音乐从 t=0 起（`afade=t=in:st=0` 已保证音量，但不保证落点） | ⚠️ 同上 |
| **L3 节奏对齐**（真正的「音画同步」） | 剪辑点落在音乐拍点上 | ❌ 无节拍数据（后端不回 bpm，需本地估拍） |

**L1 / L2 的障碍是同一个**：成片音轨 = **H3 原生音轨 + BGM 的 `amix`**（av-timeline-plan §4.5），
两条声音叠在一起 —— 既听不出 BGM 是否被截断，也量不出 BGM 的实际落点。
→ **测同步之前，必须先能选「合成时要不要各镜原生音轨」**（P1-4）。

## 4. 两个决策点（✅ 2026-09-10 已拍板）

1. **H3 原生音轨保留还是丢弃？** → **按成片形态自动分派**：**一镜整出保留**（同一次生成的画面连续、
   环境声前后一致，「最和谐」）、**多分镜拼接全丢**（各镜环境声互不连续，硬拼会「跳」）。
   判据 = 本次合成纳入的片段数。**前置**：单镜合成当前被硬卡「≥2 片段」，须一并解闸。
   → 落地 CV-141。
2. **BGM 短于成片时怎么办？** → **报错终止**（不循环铺满、不拉伸——两者都是「听得出错」的降级，
   报错让人做对）。报错须含**精确差额 + 建议时长**，且**不落半成品**。→ 落地 CV-138。
3. （新发现，待你拍板）**多镜 + 不给 BGM = 全片无声** —— 策略的直接推论。倾向「允许 + 结果里明确警告」。

详见实施计划 §1 策略矩阵 / §3 完整示例 / §5 待确认。

## 5. 最小可测路径（拍板前也能做）

**路径 A —— C 通道「音乐引导画面」，现在就能跑**
不需要 P0/P1 任何一项：`audio reference` 链路已端到端打通（CV-137 修好上传端点后，
mp3 能真的当 `audio1` 传给 ref2va）。可立刻验的是**感知层同步**：
一段 5s 音乐 + 一张参考图 → 出 5s 视频 → **动作/节奏是否跟得上音乐**（`audio-acceptance-checklist` §4 C 通道）。

**路径 B —— A 通道「时长对齐」，做完 P0-3a 即可粗测**
1. 手工让 BGM 时长 = 分镜声明时长之和；
2. 合成前用 `ffprobe` 拿 concat 产物真实时长（P0-3a 那一行）；
3. 比对两条流的时长差 —— 这就是 L1 判据的雏形。
   要让它变成**可回归的测试**，还需要 P0-1（真值落盘）与 P1-4（音轨可分离）。

## 6. 执行顺序（✅ 已定稿，见实施计划 §2）

```
CV-140（生成路径真值落盘：duration 真值 + declaredDuration 请求值）
  → CV-141（原生音轨策略：1 镜保留 / ≥2 镜全丢 + 单镜合成解禁 + amix normalize=0 配平）
  → CV-138（BGM 守卫报错 + 淡出锚点改 min(BGM, 成片) + -shortest 改 -t 成片真值）
  → CV-143（时长与音轨构成可见化，验收支撑）
  → CV-142（结构化时间轴校验，可与上一步并行）
  → 第一次正式 L1/L2 音画同步测试
  → P1-6 节拍实算 → L3 节奏对齐测试
```

**顺序理由**：CV-140 必须最先——BGM 要在合成前生成，agent 只有先拿到「成片 = 15.500s」这个真值，
才可能生成足够长的 BGM，否则每次都是「先报错、再重试」。

**P0-3a/b/c 仍是整条链上性价比最高的一步**：补一行 `parseFfmpegDuration(concatProbe.stderr)`，
「混音前的成片真实时长」立刻可用，淡出点与截断**都由它直接解掉**，
不需要额外一次合成、不需要新依赖、不阻塞任何后续设计。
