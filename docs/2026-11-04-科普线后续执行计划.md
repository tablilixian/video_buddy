## 0. 目标与工作对象（先对齐，避免再跑偏）

**终极目标**：**持续不断完善 6 种视频类型的制作能力**，包括但不限于 skill、tool、代码逻辑、验证机制。

- 六大体裁（SSOT = `canvas-studio/docs/六大体裁推进路线-20261103.md`，基准盘 reels.playsout.com）：**短剧 / 品牌宣传 / 产品讲解 / 数据可视化 / 社媒广告 / 科普讲解**。
- **交付物 = 可复用的工程资产**：`canvas-studio-creation` 总纲、各体裁编排壳（format director）与 executor、`references/` 分册、host 工具、manifest 契约与校验、体检规则、渲染链路、回执、单测与反向变异。

- **真机跑片只作能力探针**：验证工程改动是否生效；产物用完即弃，不交付、不回头修。
- **「持续」= 循环**：发现（会话取证）→ 工程修复 → 六体裁回归 → 更新能力矩阵 → 下一轮。计划末尾 §5.4 给循环节。

## 10. 卡点预案（全部预置解法，不需要临时问人）

1. **全量 `test:smoke` 沙箱 SIGTERM 137、日志 0 字节** ⇒ 沙箱豁免重跑；仍不行交用户终端跑，结果写 `/tmp/smoke-*.log`。**禁止裸 `node --test`**（唯一入口 `yarn test:smoke`）。
2. **绝不 kill Electron** ⇒ 所有重启由用户手动关/开；不做 `kill -9`、不用 TaskStop、不靠超时中断。锁残留只点名 `rm`：`~/Library/Application Support/VideoBuddy/identity/installation-id.lock` 与 `...lock.takeover-<hex>`。
3. **git push 必须用户手动** ⇒ H1/H2 已列为人工动作；助手只 commit。
4. **git 写被 0 字节 `index.lock` 卡** ⇒ 确认无真 git 进程后 `rm -f .git/index.lock` 重试；只读命令统一 `--no-optional-locks`。**git 写全挂** ⇒ 两档绕行：① index 可写用 plumbing（`GIT_INDEX_FILE=固定路径 read-tree HEAD && git add && write-tree && commit-tree -F msg文件 && update-ref`，`$$` 跨调用会变必须固定路径）；② index 也挂用 `hash-object -w`/`mktree`/`commit-tree` 重建 4 层子树 + `printf sha > .git/refs/heads/<branch>`。坑：`awk` 改 `$3` 会破坏 `ls-tree` 的 tab ⇒ 用 `sed` 按 sha 替换；`mktree` 要 `mode SP type SP sha TAB name`；事后用户终端 `rm -f .git/index.lock .git/refs/heads/*.lock && git reset`。
5. **测到旧码** ⇒ 测试 import `lib/**`（tsc emit），只跑 tsdown 会测旧码。验证链固定：`yarn build`（clean.mjs → tsdown → `tsc -p tsconfig.json` → `tsc -p tsconfig.client.json --emitDeclarationOnly`）→ `verify:loader` → `yarn test:smoke`。
6. **长中文行整行 Edit 不可靠** ⇒ 按行号 python 脚本 + `assert` 前缀校验；**同文件多条 Edit 串行**；模板串内禁反引号 / `${`；变异禁 `sed -i ''`；含反引号批量替换禁 `node -e`。
7. **BSD grep 不支持 BRE `\|`** ⇒ 用 `grep -E` 或 Grep 工具；`&&` 链首 grep 无匹配会静默中断 ⇒ 用 `;` / `|| true`。
8. **删除闸一次删 >50 必红** ⇒ `CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=100000 <cmd>`；`CODEBUDDY_SAFE_DELETE_ENABLED=0` 会 state lock timeout，别用。
9. **skill 硬闸** ⇒ 总纲 ≤14KB、每个 `SKILL.md` ≤12KB、指针覆盖率 ≥50%；B-0 删负例条后 `wc -c` 复核（当前 code-driven-explainer 11,665 B）。
10. **STATUS 三层登记** ⇒ §4.1（标题 ≤40 字符、整行 ≤400 B）/ `cv-details.md` 的 `#### CV-xxx` / `changelog.md` 一行；再改 §0 水位 + 文件头（只留最近 3 条）；`node scripts/status-summary.mjs` 重算 §1（**禁手改**）；单行 ≤2KB；闸 `tests/status-shape.test.mjs`。**不预领号**（取号前 `git log` + STATUS §4.1 复核）、**验收通过后才结项登记**。
11. **两份 checkout** ⇒ 代码改动只在**工作仓**做；运行时只 `pull`，不在运行时改代码。流程写死：工作仓改 → commit → push → 运行时 pull → 用户重启。
12. **能力声明被覆盖** ⇒ `index.ts:249-252` 指纹相等不覆盖；目录变化会覆盖。H1 同步后 `gatewayProfile()` 带 `input` 根除；每次真机验证前核对 `~/.videobuddy/canvas-studio/gateway-catalog.json` 的 `updatedAt`。
13. **网关凭据** ⇒ 令牌在 `~/.videobuddy/.credentials.yaml` 的 `refs.CANVAS_STUDIO_GATEWAY_TOKEN`（JWT），**`secret` 字段不是访问令牌**（用它会 401）；`GET /v1/llm/models` 可验。
