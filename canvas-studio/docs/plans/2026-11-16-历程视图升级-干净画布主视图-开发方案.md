### 2.3 形态差异（有意偏离，维持）

| 差异 | 理由 |
| --- | --- |
| Demo 是网页 feed（滚动条），实现是无限画布 + 自由缩放 | 画布是产品基座，历程视图是投影模式，不改成 DOM 滚动容器 |
| Demo 卡片 hover 操作浮在卡上；实现是选中后就近工具条 | 工具条在层外渲染不受 scale 影响（比例 0.3 时按钮不糊），且动作集更大 |
| Demo 文本卡 wide span 2 / 成片 focal | 实现统一网格，未做 wide 语义。低优，暂不补 |

### 2.4 多节点 / 少节点展示效果评估（重点结论）

**Demo 的适应性手段**（两档都有解）：
1. `auto-fill minmax(--card-min, 1fr)`：列数随容器宽度自适应——**节点少时卡片放大铺满行宽，节点多时自动加列折行**；
2. 密度切换（舒适 220px / 紧凑 168px）；
3. 12 镜高压档实测。

**实现的现状与问题**：`thumbWidth` 固定 360、`MAX_COLUMNS = 4`，CanvasSurface 调用时**不传视口参数**——

| 场景 | 表现 | 评价 |
| --- | --- | --- |
| **节点少**（早期 2~3 张卡） | 固定 360px 盒，整列居左，画布右半全空；卡片相对视口偏小 | ⚠️ 空旷、不饱满。Demo 同场景卡片会拉伸到大格 |
| **节点多**（12 镜全类型） | 内容固定宽 ≈ 1512px（4×360+3×24），纵向极长 + **superseded 全量平铺**（被取代节点紧跟取代者，逐版累积） | ⚠️ 两个失控项：横向要缩小缩放才看得全；纵向随迭代版本数线性爆炸。「不干净」的根源就是后者 |

**结论**：多节点场景的失控主因是 **superseded 平铺**（D2 版本堆栈折叠直接解决）；次要因素是 **无视口自适应**（thumbWidth 固定）。少节点场景的问题是 **盒宽固定不随视口放大**。两者同解：`thumbWidth` 从固定值改为**按视口宽度计算**（`computeFitView` 已有视口信息；每档给上下限钳制，避免极端窄/宽视口），作为 A 期附带项落地；密度切换（220/168 两档）暂不做，视口自适应够用。

## 三、目标形态

（示意：阶段进度条 → 托盘（镜 N + 分镜摘要 + 托盘状态）→ 卡面（缩略图 + 版本角标 + 状态 + 提示词摘要 + 操作按钮）；音频整行；空节塌缩；旧版本收进角标。）

- 托盘：`镜 3` 徽标 + 分镜卡摘要 + `3/5 · 生成中` 状态；running/fail 边框变色。
- 卡面：缩略图右上 hover 浮出 `改提示词 / 重新生成` 高频钮（其余动作仍在就近工具条与右键菜单）；缩略图右下版本角标 `v3 · 2 历史`。
- 视口自适应：进入历程视图按视口宽度定 thumbWidth（钳制 240~480），resize 不重排（进入时定档，避免频繁跳动）。

## 四、技术方案

### 4.1 A 期：默认模式反转 + 进度/状态层 + 视口自适应

1. **默认反转**：`normalizeCanvasView` 对 `waterfall` 的缺省值 false → true（老文档零迁移语义随之变化：缺省 = 开）。工具栏历程按钮语义反转 = 「自由画布」切换（激活态高亮 = 当前处于自由画布）。`aria/title` 文案同步。
2. **阶段进度层**（新组件 `WaterfallStatusBar.tsx`，浮层挂在画布顶部，历程模式才出现）：
   - 全局进度：`done/total` 由 `computeWaterfallLayout` 扩展产出（纯函数加只读字段 `progress`，不写盘）；失败数并入。
   - 活动行：复用 generate-queue 现有状态（「正在生成：镜 N · 关键帧」格式化，不新增状态机）。
   - 阶段 chips：`n/m` + done/running/fail 三态着色；点击 = `revealOffsetOf` 滚动定位到节（现成函数）。
   - 开关组：「显示文本类」（接 `waterfallShowText`，补上缺失的 UI 入口）/「显示辅助卡」（历程模式下传给布局函数 `showAuxiliary`）/「跟随新产出」（默认开，原 P2 项）。
3. **托盘/节状态**：`WaterfallSection` / `WaterfallTray` 增加只读统计（done/running/fail 计数）；托盘框边色按状态分流；节头与「镜 N · n 项」角标追加状态徽标。
4. **视口自适应 thumbWidth**：进入历程视图时按 `surfaceSize` 计算档位（钳 240~480），写入布局调用参数；不持久化。

### 4.2 B 期：版本堆栈折叠（D2 核心）

1. **数据层零改动**：superseded 关系已有（`supersededBy`），堆栈是**视图折叠**不是数据删除——生成历史抽屉仍看全量。
2. **布局层**：`computeWaterfallLayout` 把「被取代链」折叠为单盒：每个链只给**当前生效版本**分配格位，链长与各版本 id 进新只读结构 `stacks: Map<currentId, { count, supersededIds }>`。被折叠节点**不进 positions**（隐藏，而非钉扎）——「隐藏废弃素材」开关语义降级为只管 retired/superseded **链头**是否显示。
3. **渲染层**：当前版本卡右下角标 `vN · k 历史`（k>0 才显示）；点击角标弹出浮层（版本缩略图纵列 + 时间 + 「回滚为此版」）。回滚 = 既有 superseded 关系反转（写 `supersededBy` 指向新方向），走既有 Host 通路，不新增写盘格式。
4. **守卫**：折叠后 free-canvas 坐标逐字节不变（投影纪律照旧）；`stacks` 只读不落盘。

### 4.3 C 期：卡面高频操作（D3）

- CanvasNode 历程模式（或全模式）卡面右上 hover 浮出两项：**改提示词**（接 `promptEditNodeId` 受控 id，与右键/工具条同一浮层）、**重新生成**（接 `onRetry`，判据沿用 node-params.isReplayable 与失败态守卫）。
- 预览/下载/参考到对话等**不**上卡面：就近工具条与右键菜单已覆盖（D3 = 行为一致优先，卡面只放最高频两项，避免与工具条重复度过高）。
- 多选时不出卡面钮（与就近工具条同守卫：多选是另一种解释）。

### 4.4 分期与验收

| 期 | 内容 | 桌面验收要点 |
| --- | --- | --- |
| A | 默认反转 + 进度层 + 开关组 + 视口自适应 | 存量项目打开直接进历程视图；切自由画布记忆选择；chips n/m 与状态色准；showText/showAuxiliary 开关生效；窄视口 thumbWidth 变小不溢出 |
| B | 版本堆栈折叠 + 角标浮层 + 回滚 | 反复重生 3 版后画布只见当前版；角标点开三版齐全；回滚后投影/自由画布两侧一致；隐藏废弃素材开关不误伤链头 |
| C | 卡面高频操作 | 卡面改提示词与右键入口打开同一浮层；失败卡重试守卫一致；多选不出卡面钮 |

### 4.5 测试与守卫（沿用反向变异纪律）

1. `canvas-waterfall.test.mjs` 扩展：stacks 折叠全分支（链头/链中/多链/环防御）；progress 统计；showText/showAuxiliary/hiddenIds 组合。
2. `normalizeCanvasView`：`waterfall` 缺省 true 的用例更新（原「缺省 false」断言反转）。
3. 投影纪律静态守卫：`stacks` / `progress` 不出现在任何写盘调用链。
4. 回归：free-canvas 路径逐字节不变；`computeArrangeLayout` 既有测试零改动全绿。
