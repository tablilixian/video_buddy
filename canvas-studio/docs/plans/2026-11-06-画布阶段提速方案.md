## 3. 目标 / 非目标

**目标**
- G1 画布段 144.8 → **88~95 min**（P0+P1 全落地，保守值）；叠加体检步 → **50~60 min**。
- G2 高清档（1080p）45s 片**可交付**：一次成功，≤15 min，不靠运气重试。
- G3 整片渲染**一次成功**：standard 不再超时；若超时，重试明确受益于已渲帧。
- G4 模型在每次失败后**看得见诊断**（执行器、回退原因、已渲进度、该不该重试）。
- G5 交付 lint 与事实核验状态一致：verified 不再误报 pending。

**非目标（明确不做）**
- 不碰 `deepseek-harness/` submodule（反重复 guard 走组合配置豁免，超时 offload 机制保留——它是对的）。
- 不做 DAG 调度 / 多 agent 并行改 manifest（体检步另立项，本方案不内嵌）。
- 不动 `generate-queue` 单槽语义（TTS/音乐 2.7 min 占比小，收益不抵风险）。
- 不改模型档位 / 关 reasoning（与故事板方案同一边界）。

## 5. 详细设计（关键三处）

### 5.1 P0-A 主窗口节流（拍板项 1）

现状链路：`baseWindowOptions`（`dsh-plugin-desktop/src/window-options.ts:31-42`）的 webPreferences 不含 `backgroundThrottling` → 画布页被遮挡/切走时 Chromium 节流 rAF 与 `setInterval` 轮询（`render-job.ts:462-467` 已实测"节流到几十秒一拍"）→ 整片渲染从 209ms/帧膨胀到 ≈445ms/帧 → 330s 必超。

**推荐做动态开关而非常开**：渲染工单被画布页 claim 时 `webContents.setBackgroundThrottling(false)`，`settleAndForget` 后恢复 `true`。落点两处：`render-job.ts` 的 claim/结算回调已具备（liveness watchdog 同一拍），desktop 侧暴露一个受控 IPC 即可。常开方案的代价是主窗口常驻后台不吃节流（电耗/CPU），动态方案零常驻代价。

### 5.2 P0-C 超时公式分档（拍板项 4 前半）

`renderTimeoutMs(durationInFrames)` 增加第二参：`renderTimeoutMs(frames, { scale })`，scale 按 quality preset 的像素倍率取（draft 0.5 / standard 1 / high 2.3；2K 再 ×1.5）。依据：本会话成功 standard 实测 209.2ms/帧 = 公式预算的 105%，**裕度是负的零头**；任何慢机/遮挡波动即超。分档后：standard 330s（不变）+15% 安全带；high ≈760s（12.7 min，< 20min 上限）——一次渲完，消灭"3 次超时 + 1 次成功"的 23.6 min 轮盘。**scale 终值待卡点 ③ 实测回填。**

超时回执同步改造（P0-B）：`timeout after 330s · 已渲 742/1350 帧（55%）· 执行器=画布页（回退原因：…）· 重试将从帧缓存续渲，预计再需 Xs`。

### 5.3 P1-B 探针帧编码（先自查再落码）

`remotion-render.ts:185` 的 `convertToBlob({ type: 'image/png' })` 是探针静帧与整片抽帧共用出口。改 JPEG q0.85：单帧 670KB(base64) → ≈170KB，**2MiB 预算从装 3 张变装 12 张**，探针循环（每轮 2–5 张）不再触发 `IMAGE_OFFLOAD_REQUIRED`。判据类结论（元素存在/字号/位置）720p JPEG 足够；需要像素级精读数值时走 `image_crop`（其输出保持 PNG）。**开工自查**：同帧 PNG vs JPEG q0.85 三张对照，模型读图判定；不合格则调 q 或改"PNG 落盘 + 读缩略副本"。
