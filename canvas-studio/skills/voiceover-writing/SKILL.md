# 配音生成提示词规范（txt2speech / VoxCPM2）

适用：`tts_voiceover` 的每一次调用。

**能力边界（先记住）**：后端只暴露「文本 → 语音」最小子集——**没有**时长参数、
没有 `voiceId`、没有多说话人合成、没有 SSML 标记。一切声音特征都用
`instruct_prompt` 自然语言描述；**时长由文本长度决定**（中文中速约 **4 字/秒**，
要 10 秒配音就写 40 字左右）。合成产物为 mp3（实测口径），`voxcpm_*` 前缀，
属后端产物名（下游引用走 `@ref[节点标题]`，勿直接当 filename 传）。

**例外（O-09）**：语速与音高有**宿主侧**确定性参数 —— `speed`（0.5–2.0，变速不变调）
与 `pitchSemitones`（±12 半音，变调不变速）。它们由本地 ffmpeg 后处理实现，**不是**
后端参数，正确用法见 §六。

## 一、先定两件事

0. **反向判据（REQ-017）**：要**画面里的角色开口说**这句话（对白，要口型）→ 不要用 tts_voiceover，把
   `<d>[语言]原话</d>` 写进视频提示词（角色原生说出口、有口型）；本工具的产物是**独立配音音频**
   （旁白 / 画外音 / 配音资产），进不了口型——唯一进成片路径是 audioRefs ≤15s 烧录，且非口型驱动。
1. **这条配音是给谁的**：
   - **独立旁白 / 交付音频** → 直接合成，产物落音频节点交付；
   - **让视频里的角色「用这个声音说话」** → 合成后把音频经 `cut_audio` 裁到
     ≤15s，作 `video_generate` / `video_composite` 的 `audioRefs`（r2v 参考音频，
     官方规格：≤3 段、单段 2–15s、合计 ≤15s、**不能作唯一输入**）。
   ⚠️ **配音节点不能当 `bgmNodeId`**——compose_video 的 amix 只挂 BGM，把配音
   传进 bgmNodeId 会在混音里铺满全片。配音入成片的正路只有 audioRefs 一条。
2. **时长（无「时长」参数，只能靠文本）**：先按 4 字/秒估文本长度；太长的旁白**拆段
   合成**（一次调用一段），不要指望后端压缩语速（真要整体放慢用 `speed`，见 §六）。
   **多段旁白音色一致性（C-5 铁律）**：拆段前先定一次音色——有参考音就**每段都传
   同一个 refaudio**；没有参考音就只在第一段写 instruct_prompt 声音设计，之后每段
   **逐字复用第一段的 instruct_prompt**（七维一字不改）。严禁每段各写各的声音设计
   ——那是「30s 片旁白出现三个音色」的直接成因。多段旁白入成片走 audioRefs 时
   合计 ≤15s，超了先用 cut_audio 裁；合成前**逐段核对音频节点都已真实落卡**
   （首段丢失多半是漏检，生成完数一遍节点数再往下走）。

## 二、instruct_prompt（声音设计）七维写法

一段话把要的维度写全，**没提的维度由模型自由发挥**（想要稳定就写全）：

| 维度 | 写什么 | 示例词 |
|---|---|---|
| 语言 | 说话的语言 | 普通话 / 英语 / 日语 / 粤语（方言也算语言维） |
| 性别 | 男 / 女 | 女声 |
| 年龄 | 岁数或年龄段 | 30岁 / 老年 / 童声 |
| 语气 | 说话方式（含笑声等） | 笑着说 / 悄声说 / 一本正经地说 |
| 情感 | 情绪色彩 | 温柔坚定 / 悲伤压抑 / 兴奋激动 |
| 语速 | 快慢 | 慢速 / 中速 / 语速稍快 |
| 方言 | 中文方言（9 种，见分册清单） | 四川话 / 粤语 / 东北话 |

**写法示例**（一个逗号分隔的自然语言短句即可，不要写成参数表）：
- `30岁女性，温柔坚定，普通话，中速`
- `60岁女人笑着说，慢速，四川话`
- `青年男性，平静低沉，标准普通话，中速`
- `Elderly man, warm and slow, standard English`

完整语言 / 方言清单、维度词速查与示例库见 `references/voice-design.md`。

## 三、text（合成文本）写法

- 写**成品口语稿**：模型会逐字念出来——「嗯/啊」的填充词、括号注释、舞台指令
  （如（停顿））都会被念出来，**要么别写，要么写进 instruct_prompt**（如「说完停顿一下」不可控，尽量不依赖）。
- 数字与标点：中文稿用中文标点断句；阿拉伯数字多数情况能正确读，但**发音有歧义
  时直接写汉字**（如「三点五亿」别写「3.5亿」）。
- 长稿拆段：单次调用建议 ≤120 字；更长的旁白拆成多段分别合成，落多个音频节点。

## 四、refaudio（音色克隆）

- 传**上传句柄**（`upload_image` 返回的 filename，或 `@ref[音频节点标题]` 让 Host
  换句柄）；生成产物名不可直接作入参（全局 filename 纪律同型）。
- 提供后**克隆参考音色**生成后续语音；`instruct_prompt` 仍可写（控制语气/语速），
  但性别/年龄等音色特征以参考音频为准。
- ⚠️ 克隆通道**未实测**（探针只验证了声音设计路径）——遇到失败按报错处理并回退
  纯声音设计路径，不要反复重试。**回退时音色一致性不放松**：instruct_prompt 必须
  逐字沿用第一段（或用户参考音对应）的音色描述，不许按段重写、不许混入不同性别 /
  年龄的描述。

## 五、纪律与口径

- **串行**：后端同步单任务，多条配音逐个合成（等上一条返回再发下一条）。
- **时长口径**：工具结果里的 `duration` 是 ffprobe 实测**真值**；后端响应里的
  `duration` 是生成耗时（探针实测两者差 2.8 倍），勿混用。
- **改词 / 重配**：重新调用 `tts_voiceover` 传 `replaces=<旧音频节点 id>` 原地
  重写（保留节点与血缘），不要堆新卡。
- **逐字正确优先于文采**：配音是念给人听的成品，text 里的每个字都会被念出来。

## 六、超出音域怎么办（`speed` / `pitchSemitones`，O-09）

用户要「60 岁沙哑」「再低沉一点」「说慢一点」时，`instruct_prompt` 写一轮就该有
变化；**写了两轮还是同一个声音，就是后端这条路到顶了** —— 继续重试只会烧额度
（真机实测为「60 岁沙哑」重试 2 轮、外加一次 ffmpeg 手搓降调）。

此时换成确定性参数，两者都是**宿主侧 ffmpeg 后处理**（不是后端字段）：

| 参数 | 区间 | 效果 | 典型用法 |
|---|---|---|---|
| `speed` | 0.5–2.0 | 变速**不变调**（`atempo`） | `0.9` = 放慢 10%（沉稳叙述）；`1.15` = 紧凑口播 |
| `pitchSemitones` | -12 ~ +12 | 变调**不变速**（`asetrate` + 时长相抵） | `-3` = 低一档（更苍老）；`-6` = 明显低沉；正值更年轻 |

- **音色 ≠ 基频**：沙哑、气声、沙质感是音色，`pitchSemitones` 调不出来 —— 它只压基频。
  要沙哑仍在 `instruct_prompt` 写「沙哑烟嗓」，`pitchSemitones` 只负责把整体压低。
- 两者可叠加（先变调再变速）；**别用 `speed` 与 instruct_prompt 里的「慢速」重复描述同一件事**。
- 结果里的 `warnings` 非空说明**后处理没生效**（ffmpeg 不可用 / 越界被夹取）——
  必须如实转告用户，不要说「已按 0.8 倍速」却没生效。
- 后处理会重编码为 mp3 192k，`duration` 仍是 ffprobe 实测真值（变速后时长会变，按新值排轨）。
