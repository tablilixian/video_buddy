# A-4 ｜ 生成中占位节点孤立出现（无边、位置随机）

> 优先级 P1 ｜ 风险 T2 ｜ 依赖：无
> 截图要点：「生成图片中… 00:16」占位卡落在左下角空白处，与分镜卡无任何连线；成卡后跳到分镜组右侧。

## 代码级原因
- 占位创建：`client/index.ts:1410-1437`——`deriveNodePlacement(projectNodes, [], …)`（:1417，**sourceIds 恒空**）+ `sourceIds: []`（:1428）。空来源走 `canvas-placement.ts:98-106` 网格分支：`start = nodes.length`、格位 `(cell%4)*300 / floor(cell/4)*240`——102 节点时落到极远的空格（截图的孤立卡）。
- **arguments 里其实带着血缘**：tool/call 的 arguments 有 `shotRefs`/`sourceUrls`/`filename`（host-tools.ts:1185/1224/1269 声明，模型确实传）；但 `asset-capture.ts:245-258` 的 `sourceUrlFromArguments` 只抽 imageUrl 且只用于会话回执（:322），不进占位节点。
- 成卡后才有血缘：`generate.ts:2420-2435`（sourceUrls + filename 反查 + shotNodeIds + 继承分镜卡）→ :2462 带血缘落位 → 与占位必然不同位。

## 修复方案
1. 抽共享纯函数 `resolvePendingSourceIds(nodes, args)`（建议 canvas-placement.ts 或新 canvas-lineage.ts）：JSON.parse arguments（try/catch 防脏 JSON），解析 `sourceUrls`（URL 归一化匹配 node.url，同 generate.ts:1388-1399）、`filename/filenameTail/filenames`（匹配 node.filename，同 :1407-1419）、`shotRefs`（节点 id /「分镜 N」标题匹配——把 `host-tools.ts:1041` resolveShotRefs 的匹配逻辑抽成不依赖 registry 的纯函数；generate.ts 两个反查函数挪共享模块后 re-export 保兼容）。
2. `onToolCall`：`const placement = deriveNodePlacement(projectNodes, resolved, …)`，setPendingNode 传 `sourceIds: resolved`——占位期即画出血缘边（operationType 缺省回落 'import' 灰色，可按 STUDIO_TOOL_KINDS 映射近似色，非必须）。
3. 落位锚定自动继承 deriveNodePlacement 的分镜卡锚（canvas-placement.ts:85-89）——占位与成卡同锚，只差避让步数。

## 改动风险
- 占位与成卡位置仍可能差一步避让（成卡带 supersede/重试分支）——视觉上「在同一组附近」即达标。
- 挪动 generate.ts 函数碰 host 打包——re-export 保兼容，跑全量 smoke。
- setPendingNode 去重键是 runId（project-store.ts:1096-1100），不受影响。
- 客户端渲染层改动，不碰数据协议。

## 验收
无头：resolvePendingSourceIds 纯函数单测（shotRefs 标题匹配/URL 归一化/脏 JSON）。桌面：生成中占位卡出现在分镜组右侧且有线，成卡后位置基本不动。
