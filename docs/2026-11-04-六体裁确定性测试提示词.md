# 六体裁确定性测试提示词（计划 v4 §5.2 ① 的交付物）

> 用途：用户按本文件在 GUI 真机跑一条，把 `session.v4.jsonl` 交给 agent 做成果判定（真机落盘为 `.jsonl.zstd`，**原样交路径即可**，探针自动解压——2026-11-05 已实锤）。
> **确定性** = 同一提示词可复跑、可差分；换变体时必须显式写出差异。
> 顺序按 D11 默认：**科普讲解先行打样**，把判定框架跑顺后再推其余五体裁。
> 跑片是**能力探针**，产物不交付、不回头修；只用来判断工程改动是否生效。

## 通用交付规范（每轮）

用户给素材时附：① 会话文件路径；② 体裁 + 轮次；③ 提示词原文或「沿用第 N 轮」；④ 质量档。
agent 侧固定用 `canvas-studio/scripts/probe-session.mjs` 取证 + 《成果判定报告模板》出判定报告。

## 通用硬要求（所有体裁提示词都带这一段）

```
要求：
① 首轮渲染就用 spotFrames 探针取代表帧，逐张 read_image 看**成片像素**后，对照判据表逐条打勾；
   inspect_image 的 grid/bbox 只用于定位疑点与精确数值，不得当「元素是否存在」的结论；
② 交付前复述**未决项**：体检告警逐条状态（lint[] 折叠时给计数 + 前 N 条 + 落盘路径）、
   未核源事实、模型自身能力边界；
③ 画面类结论禁拿 manifest 字段自证；图表数值必须单一基准、可溯源，pending 事实不得进成片；
④ 负例不跑（它是验收阶段可选的测试手段，不是交付流程的一环）。
```

## 1. 科普讲解（code-driven-explainer）· 首轮打样

```
用 code-driven-explainer 做一条 45 秒、16:9 的中文科普片《为什么地球公转产生四季》，
中文配音 + 词级卡拉OK字幕。要求：
① 片中有一个仪表盘元素，指针随讲解推进摆动（太阳直射点纬度 -23.5°~23.5°）；
② 中段放一条「近 30 年全球均温距平」折线，最后一个数字数位滚动出现；
   数值必须来自同一基准（GISTEMP 1951–1980），数据卡标签写明基准，禁止混口径；
③ 对「黄赤交角 23.5°」用引线标注指向示意图上的地轴；
④ 「直射 / 斜射」两段对比用分区揭示切换（左 wipe 进、右 wipe 出）；
⑤ 片尾无裸画面（字幕或旁白覆盖到最后一帧）。

〈粘贴上面的「通用硬要求」〉
```

**覆盖的验证点**：读图能力闸（A-3）、总纲/编排壳纪律注入、抽帧回执消费、L2 画面判据（引线 / 擦除方向 / 不压字 / 片尾覆盖）、L3 数据保真（单一基准 + B-4 的 dataSource/baseline 观察期提醒是否被消费）、#11 运动口径（渲染报告 / 静态提示 / ML-10 结论一致）、体检回执可消费（B-3：计数 + 前 N 条 + 落盘路径）、reveal 缺省方向不再误报（P-16）。

## 判定循环

每体裁 2–4 轮：第 1 轮**只建基线不优化**（拿到会话 → 出判定报告 → 不改工程）；第 2 轮起按优化清单改工程 → 同提示词复跑 → 差分判定。单格连续 2 轮无实质提升 ⇒ 按 D13 停下出「卡点分析 + 建议方案」。
