## 一、和上一次测试的关系

**用的还是同一个项目和同一份 manifest**，但**验收点变了**：

| | 上一次（事故） | 这一次 |
|---|---|---|
| 看什么 | 能不能出片 | 工单**走了哪条路**、失败时能不能一眼定位 |
| 合格线 | 无（0 成片） | 全片 130–260s 出片；每次返回都有 `工单：…` 诊断行 |
| 失败时 | 只有一句"超时，请确认页面可见" | 必须说清「未认领 / 无首帧 / 进度 X%」 |

项目：`使用技能「代码驱动科普成片」（code- 2` ｜ manifest：`build/manifest.json`（61 轨 / 1800 帧）

## 二、用例

### Z-1 冷启首单必须走隐藏窗口（F-02d，最重要）

| 步骤 | 操作 |
|---|---|
| 1 | `Cmd+Q` 完全退出应用（不是关窗口） |
| 2 | 重新打开 → 进入上述项目 |
| 3 | 立刻让我用 `probe:true` + `quality:"draft"` 渲染一份 **60 帧**探针 |

**期望**
- 返回文本里有：`工单：隐藏渲染窗口 · 已于 HH:MM:SS 认领 · 已出首帧 · 进度 100%`
- 总耗时 < 10s（含 8s 冷启预算）
- **画布上没有新增节点**（probe 不落节点）

**不通过的样子**：`工单：画布页 · 未认领 · 无首帧` ⇒ F-02d 没生效（冷启仍被判给画布页）。

### Z-2 全片回归（同上一案的 manifest）

| 步骤 | 操作 |
|---|---|
| 1 | 让我用 `manifestPath` 指向 `build/manifest.json`，`quality:"draft"`，**不传** `probe` |

**期望**
- `工单：隐藏渲染窗口 · 已出首帧 · 进度 100%`，总耗时 **130–260s**（独立工程实测 129–182s）
- 产出 ~60s / 640×360 的 mp4，画布上**只多 1 个**成片节点
- 报告行应形如：`渲染报告：quality=draft · 1800 帧 · 总 160.0s · 准备 19.0s · 渲染 141.0s · msPerFrame=78.3 · 编码完成于 139.0s …`

**特别看两点**（这两条是事故里最误导人的）：
- `warm=` **不再出现**（假字段已删）
- `准备 XXs` 与 `渲染 XXs` 分开 —— 中文 textCard 的准备阶段应在 15–25s 量级，不是 0

## 三、跑完一条命令出结论

```bash
cd canvas-studio
node scripts/render-forensics/verify-live.mjs
```

它查 5 件事（L-1..L-5）：

| 检查 | 判据 |
|---|---|
| L-1 | `lib/client.js` 比应用启动更新 ⇒ **没重启**，直接拦下 |
| L-2 | 旧文案「请确认画布页面已打开且可见」出现 0 次 |
| L-3 | 改派日志 ≥1 次（仅在做过 Z-3 时要求） |
| L-4 | RenderHost 有创建、有回收 |
| L-5 | 每条超时都带工单诊断 |

**基线对照**：用事故当天的日志跑，会得到 `4 项未通过`（旧代码、旧文案、0 改派、39 条无诊断）——
这正是修复前应有的样子；修复后同样的用例应全绿。
