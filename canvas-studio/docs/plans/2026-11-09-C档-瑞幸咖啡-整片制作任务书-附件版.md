# 整片制作任务书 · luckin coffee（瑞幸咖啡）品牌短片

> 本文件是本次任务的**唯一完整指令源**。当用户消息为「按照文档要求，制作一段视频」时，
> 读完本文件与同批图片附件后**直接开工**：不反问、不等待补充、不要求用户确认。
> 不联网检索该品牌，不使用同批附件以外的任何品牌素材，不读取任何外部/本地对照视频。
> 若本文件与会话里的简略描述有出入，以本文件为准。

## 1. 成片规格

- 20 秒（±1s）、16:9、1280×720，中文配音与中文画面文案。
- 投放场景：官网 + 社媒信息流。
- 成品落到画布且可播放；交付时给出成片路径、实测时长、画幅。
- 全片 6–8 个主节拍：前 3 秒钩子 → 2–5 个语义挂钩的色彩状态（瑞幸蓝 / 白 / 咖啡棕）
  → 产品与制作佐证段 → 结尾 3 秒明确 CTA；片尾不留裸画面。
- 转场由真实素材或几何驱动，不做假 HUD、不做玻璃卡片堆砌。

## 2. 定向三问（已给全，开工前复述，不要反问）

- **素材现实**：同批附件中的 4 张官方图片（字标 logo / 蓝杯与咖啡豆 / 门店鹿标 / 咖啡师制作），
  身份资产齐备，溯源记为「用户提供 · 官方来源」。
- **投放场景**：官网 + 社媒信息流。
- **时长画幅语言**：20s / 16:9 / 中文。
- 开工前先显式声明本片走 `brand-promo-video-generator` 的**素材充足完整链**，
  并复述以上三项，然后再动手。

## 3. 同批附件（按画面内容辨认，不依赖文件名）

1. 白鹿头 + 小写 `luckin coffee` 字标、深蓝底 —— 官方字标 logo。**身份资产**，终版必须完整可读。
2. 横倒蓝杯 + 咖啡豆 + 英文文案横幅 —— 产品主视觉，也是蓝棕配色基准。
3. 门店实拍、左侧发光鹿标 —— 品牌场景佐证。
4. 咖啡师手冲制作 —— 制作过程佐证。
5. （可选）带奖项徽章的咖啡豆图 —— 仅作视觉参考。

- 开工前逐张读图确认以上内容，再决定各自落在哪个节拍。
- 附件上的英文文案与奖项徽章只作视觉参考，**不得照抄进成片**，
  也不得当可引用数据（除非标注 `dataSource=官网横幅`）。
- 若某类附件缺失，按实际收到的素材继续，不要因此停下，也不要改用外部图片补位。

## 4. 品牌事实表（唯一权威，防编造）

- 品牌名：`luckin coffee` / 瑞幸咖啡。
- 主标识：白色鹿头 + 小写英文字标。
- 主色：深蓝 `#212370` 与白，辅助咖啡棕。
- 可见资产：蓝杯、咖啡豆、门店、咖啡师制作（全部来自同批附件）。
- 附件是品牌**国际站英文物料**：不得写中国区产品名、门店数、销量、价格、口号、活动。
- 表外的一切数字、产品名、口号、CTA 一律视为**概念文案**，不得当作官方事实；
  未核源事实写进交付的「未决项」，不进成片。

## 5. 身份资产红线

- logo / 字标 / 包装 / 门店 / 人物**只用附件原件**，绝不重画、近似绘制、拉伸或裁切重建。
- AI 生成素材一律不得含品牌标识、包装、门店或人物，须标注为概念化氛围素材，
  不冒充官方产品证据。
- 「不重绘身份资产」不等于「不生成任何素材」：第 6 节的非身份类素材是**明确授权**的。

## 6. 三轨结合（必须同场，不得退化为纯代码轨）

1. **AI 生图**：`image_generate` 出 1–2 张 16:9 氛围锚点图（手冲水流 / 咖啡液 / 蒸汽光影）。
   画面禁任何文字与标识；prompt ≤500 字符、只写正向约束；一次一个串行调用。
2. **H3 视频**：`video_generate`（首尾帧）或 `video_composite` 出 1 段 5 秒英雄镜头，
   只给需要真实运镜的段落，禁止为「消静态提示」逐镜生成；单次 ≤15s，后端单任务串行。
3. **代码编排**：排印、色彩状态、转场、CTA 走
   `scaffold_manifest → 内容表 → manifest-builder.mjs → render_composition`；
   **禁止手写 `gen-*.mjs` 绕过 official builder**。

- AI 素材经 video / image 轨进 manifest：`id` = 画布节点 id、`src` 同源、时长取 `list_shots` 真值；
  禁外链、禁 `@ref`、禁把产物名直接作下游入参；合成后严禁再调 `video_generate` / `video_composite`。
- **目标：AI 素材占 6–10 秒**，其余为代码轨；成片不得是「图文卡片型（全片无视频片段）」。
- 付费生成若被审批闸拦下，**立即明确告知需要放行**，不要静默退化为纯代码轨，也不要假装已生成。

## 7. 通用硬要求（四条，逐条执行）

1. 首轮渲染就用 `spotFrames` 探针取代表帧，逐张 `read_image` 看成片像素后，对照判据表逐条打勾；
   `inspect_image` 的 grid/bbox 只用于定位疑点与精确数值，不得当「元素是否存在」的结论。
2. 交付前复述未决项：体检告警逐条状态（`lint[]` 折叠时给计数 + 前 N 条 + 落盘路径）、
   未核源事实、模型自身能力边界。
3. 画面类结论禁拿 manifest 字段自证；图表数值必须单一基准、可溯源，`pending` 事实不得进成片。
4. 负例不跑（它是验收阶段可选的测试手段，不是交付流程的一环）。

## 8. 交付前自检（逐条对照，在交付卡里说明结果）

- 是否显式声明并走了品牌宣传的完整素材链，而非零素材降级链。
- 定向三问是否已复述。
- logo / 字标 / 门店 / 人物是否全部来自附件原件、无重绘、无外部图混入，终版 logo 完整可读。
- 叙事骨架是否完整（钩子 / 色彩状态 / 佐证 / CTA），所有数字是否有出处或由代码渲染。
- 节拍数 6–8、色彩状态 2–5，无假 HUD，转场由素材或几何驱动。
- 20s / 16:9 / 中文、终版 logo 完整、产物落画布可播。
- 三轨各自实际用了哪些工具、AI 素材实际占多少秒、是否调用过手写生成器。

## 9. 交付内容

成片 + 简短交付卡：成片路径 / 实测时长 / 画幅 / 音频响度；
第 8 节逐条自检结果；三轨工具清单与 AI 素材秒数；未决项复述。
不要输出未使用的备选方案，不要为凑字数添加本文件未要求的内容。
