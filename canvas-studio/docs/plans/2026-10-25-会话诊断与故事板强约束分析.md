## D. 故事板强约束：现状与缺口

### 你要的约束

> 故事板必须先制作**完善** → 自动落到画布 → 才能进产线。**哪怕自动执行（auto）也不能省。**

### 现在的实现（读码，C 级证据）

| 环节 | 现状 | 位置 |
|---|---|---|
| 「完善」的判据 | `validateForSeed()`：标题 / 画幅 / 时长 / §02 至少 1 个 token / §04 至少 1 scene 且每 scene ≥1 shot… 不满足即 `blockers` | `contracts/storyboard.ts:810` |
| 落地闸 | `landStoryboard()` 前先跑同一份 `validateForSeed`，有 blocker 直接拒 | `storyboard-land.ts:191` |
| **落地入口** | **只有 UI 一个**：覆盖层点「确认落地」→ `POST /canvas-studio/storyboard/land` | `routes.ts:1900`、`StudioFrame.tsx:1805` |
| 落地前门禁（confirm） | `storyboarding` 态拦 `FORMAL_TOOLS`（含 `render_composition` / `compose_video` / `video_generate` / `tts_voiceover` / `music_generation` / `qc_shot` / `extract_last_frame` / `video_composite`）+ `write_script` | `approval-gate.ts` |
| **auto 模式** | **`if (mode !== 'confirm') return null`** ⇒ 门禁整体放行 | `approval-gate.ts:151` |
| **auto 自动落地** | **不存在**（`landStoryboard` 唯一调用点在路由里，由 UI 触发） | 全仓 grep |

### 三个缺口

| # | 缺口 | 后果 |
|---|---|---|
| **S1** | **auto 模式完全绕过门禁** | 放手跑时可以直接 `render_composition` / `compose_video`，故事板可完全不写 |
| **S2** | **auto 模式没有自动落地**（且承诺已发出、实现不存在） | 就算写了故事板，也没人点按钮。⚠️ 但 **skill 文档 `screenplay.md:21` 第 6 条已向 agent 明文承诺**「放手跑模式：`write_storyboard` 成功后由 Host 编排自动校验并落地」，`host-tools.ts` 的 `concludedForLanding` 注释也引此条 ⇒ **承诺-实现漂移**：auto 模式下 agent 不会卡住，而是按承诺继续跑产线（S1 门禁放行）⇒ 拿着未落地的故事板直接出片，画布与规划**静默脱节**（比"卡住"更糟） |
| **S3** | 门禁只看 `workflow.state`，不看 `storyboard.landed` | 状态被迁移/手工改过（或未来加别的入口）就能绕过；两套事实（state vs landed）迟早不一致 |

另外一个**秩序问题**：`image_generate` 只在「绑了分镜（shotBound）」时才拦，不绑分镜的自由出图
在 `storyboarding` 是允许的（Look 样张 / 定妆照，这是有意的）。但它没有上限 —— 本次会话在写
故事板之前已经出了 2 张图、做了 8 次像素分析。这些不算违规，但也说明
"先做故事板"目前只约束**产线工具**，不约束**素材准备**。

## E. 建议（三档，最小的先做）

### P0 · 把「已落地」变成数据前置，而不是状态判据

在 `render_composition` / `compose_video` / `video_generate` / `tts_voiceover` / `music_generation`
的 `execute()` **开头**加一个守卫：读 `storyboard.json`，`landed.at` 不存在 ⇒ 抛 `CS-USER-ERR`，
文案给唯一出路（"先去画布顶条「拍摄定稿」写故事板并落地"）。

- **为什么不是先改门禁**：门禁依赖 `mode` + `state` 两个可变状态，auto 一开就是 null；数据前置
  与 mode/state 无关，绕不过（顺带把 S3 也解决了）。
- **必须处理的兼容**：存量项目没有 `storyboard.json`（或从未落地）会被一刀切拦死。
  建议豁免规则二选一：① 画布已有节点但无 `storyboard.json` ⇒ 视为传统项目放行（打一次日志）；
  ② 项目上显式 `legacy: true`。**这条要你拍板**，否则上线即炸老项目。

### P1 · auto 模式自动落地

`write_storyboard` 在 `mode === 'auto'` 且 `validateForSeed` 的 `blockers` 清零时，
由 Host 直接调 `landStoryboard()`（复用同一份 `validateForSeed`），并把结果写进工具返回：
「已自动落地，生成 N 张分镜卡」。这样 auto 也能走完链路、且不阻塞用户。

- 判据用 `blockers.length === 0`（**注意 `readyToLand` 不是现有字段**——工具返回只有 `{ text }`，
  本期若要命名请新建；现成的对称位是 confirm 模式的 `concludedForLanding`：
  `awaitingLanding=true && blockers 空 → concludeTurn`，auto 分支把 conclude 换成 land 即可）。

- 没清零 blockers 时**不落**，照常返回阻断项让 agent 补 —— 这就实现了"先完善，再落地"。
- 落地是写画布，建议先在设置里留一个 `autoLandStoryboard`（默认开/关待定），便于回滚。

### P2 · 门禁与数据对齐

把 `approvalGateMessage` 的 `mode !== 'confirm' → null` 改成：**auto 也校验 `landed`**，
只是错误文案从"等用户点确认"换成"放手跑也需要故事板，Host 会尝试自动落地"。

### 补 G6（契约缺口，与上面独立）

把本次实际探索的 4 类知识补进 `manifest-contract.md`（或独立分册「动画与素材语义」）：
`textUnitProgress` 的逐字帧语义、`ImageClip`/`materialize` 的裁切与挂载、`asset-check` 的可用性判据、
`shape-geometry` 的顶点与 box 百分比换算。**这一条是"减少源码探索"的正解**，比继续删描述有效。
