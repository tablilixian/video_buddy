# A-9 ｜ 导入文本落到画布远角

> 优先级 P1 ｜ 风险 T1 ｜ 依赖：无
> 截图要点：拖入的 3504 字 md 卡出现在画布最右侧空白处（用户标注「导入的文本出现在莫名其妙处」），与现有内容相距数千单位。

## 代码级原因
- `StudioFrame.tsx:1638-1653` onDrop 只取 `event.dataTransfer.files`，**不读 clientX/Y**；:729-757 handleDroppedFiles 分发也无坐标参数 → handleUploadText（:663-688）→ `actions.addTextAssetNode`（:677）。
- `project-store.ts:1237-1264` addTextAssetNode 内 `deriveNodePlacement(existing, [], …)`（:1244）——空来源网格分支 `start = nodes.length`（canvas-placement.ts:98-106）：102 节点时 y = 40+25*240 = 6040，天然落到远端。drop 坐标从头到尾没人用。
- 换算函数现成：`client/canvas/canvas-math.ts:130-141` `screenToWorld(screenX, screenY, view.x, view.y, scale)`；容器 rect 用法参照 CanvasSurface.tsx:385-391（zoomAround）。

## 修复方案
1. onDrop **同步**捕获坐标（必须在 await uploadStudioMedia 之前闭包保存）：`rect = .csCanvasSurface.getBoundingClientRect()`，`world = screenToWorld(e.clientX - rect.left, e.clientY - rect.top, view.x, view.y, view.scale)`。
2. `handleDroppedFiles(files, at?)` → handleUploadText 等透传；`addTextAssetNode`（及 addImageNode/addAudioNode/addVideoNode，同病）签名加 `at?: {x,y}`（参照 addNode 的 at 参数，project-store.ts:1101-1115 已有先例），落位 `at ?? deriveNodePlacement(...)`，建议居中化 `x = at.x - width/2`（文本卡大，中心对光标比左上角自然）。
3. 工具栏上传（无 drop 点）回落 deriveNodePlacement 或视口中心。

## 改动风险
- drop 落点在工具栏/时间轴上时 world 会偏——判 target 是否在 surface 内，否则回落网格。
- 坐标必须 drop 当帧捕获（await 后 view 可能变）。
- 四个 add*Node 都改签名波及面广——最小改动只改 text（用户当前只报 text），其余同模式跟进。

## 验收
无头：project-store 单测（addTextAssetNode at 生效、居中偏移正确）。桌面：往画布某分镜旁拖入 txt/md → 卡落在松手点（居中）；往工具栏区拖 → 回落网格不炸。
