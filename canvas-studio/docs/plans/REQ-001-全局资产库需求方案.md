## 1. 背景与目标

### 1.1 需求原文

> 为 App 增加全局资产库页面，下设**角色、场景、物件、群像**资产库；在 agent 中通过自然语言或 `@` 符引用该资源，prompt 中修改也要能使用。

### 1.2 验收标准（来自需求表）

1. 资产库页面**四分类可见**；
2. **`@` 与自然语言**均可引用资产；
3. **prompt 修改后引用不丢失**，仍可解析。

### 1.3 现状缺口（2026-09-27 代码调研）

| # | 缺口 | 证据 |
|---|---|---|
| G1 | **无跨项目全局存储**。所有资产数据都挂在项目上：`canvas.json` 的 `assets[]`（`contracts/canvas.ts:301` `StudioAsset`）、`<project>/assets/`、`history.json`。根目录只有 `projects.json` / `groups.json` | `src/projects.ts:144,190-195`；`project-store.ts:179-229` 全部 `Record<projectId,…>` |
| G2 | **四分类中「物件/群像」全仓零命中**。现有 `StudioAsset.role: 'character'\|'scene'\|'style'` 与需求四分类不对齐；节点 `referenceRole: 'image'\|'character'\|'style'\|'frame'` 是引用强度分类，不是库分类 | `contracts/canvas.ts:307`、`:231` |
| G3 | **库条目不是画布节点 ⇒ `@ref` 链路不通**。`@ref[handle]` 句柄按节点 id 解析（`findNodeByRef` 仅在当前项目 `nodes` 内查），HTTP 资产路由是 `/<projectId>/<file>` 项目作用域 | `reference-token.ts:75-88`、`routes.ts:38,616` |
| G4 | **自然语言引用无解析通道**。agent 只能靠 `list_references` 工具 + skill 文档学 `@ref` 字面量；没有把「库里有什么」注入 system prompt 的机制（存在可复用 seam） | `host-tools.ts:1462`；`plan-prompt.ts:18` |

### 1.5 目标

- **T1**：跨项目全局资产库，四分类（角色/场景/物件/群像），独立全屏页面可浏览/搜索/管理；
- **T2**：画布节点可「注册入库」，库条目可在任意项目被 `@` 引用；
- **T3**：agent 通过自然语言（按名称/别名/描述）与 `@ref[lib:…]` 两种方式引用库资产；
- **T4**：引用经 chip 管道插入，prompt 增删改后引用不丢失、可解析。

## 2. 术语与分类

### 2.1 四分类定义

| 分类 | 枚举值 | 含义 | 典型内容 |
|---|---|---|---|
| 角色 | `character` | 单个人物形象（含定妆/多视图） | 「女主」「反派Boss」 |
| 场景 | `scene` | 环境/地点/氛围 | 「雨夜巷弄」「中式庭院」 |
| 物件 | `prop` | 道具/物件/服装/武器 | 「青铜古剑」「红色跑车」 |
| 群像 | `group` | 多人组合/群众/队伍 | 「街头人群」「侠客小队」 |

中文标签常量：`LIB_CATEGORY_LABELS = { character:'角色', scene:'场景', prop:'物件', group:'群像' }`（新增 `src/asset-library.ts`）。

### 2.2 与现有 `StudioAsset.role` 的映射（决策：新枚举 + 迁移）

现有 `role: 'character' | 'scene' | 'style'`（`contracts/canvas.ts:307`）。处置：

| 旧值 | 迁移去向 | 理由 |
|---|---|---|
| `character` | `character` | 一一对应 |
| `scene` | `scene` | 一一对应 |
| `style` | **读侧兼容，写侧停用**：`StudioAsset` 字段保留 `style` 以免破坏 `canvas.json` v4 与 look-asset 流程；**库分类不含 style**，`style` 卡不自动入库 | `style` 是「风格锚点」注入用途（`look-asset-plan.md`），与四分类正交；强行并入 `scene` 会污染语义 |

即：**库层用新四分类枚举，项目层 `StudioAsset.role` 不动**——两套枚举，但文档层明确 `character/scene` 同名同义，`style` 不进库。这避免了对 `canvas.json` v4、look 卡注册、prompt 注入强度逻辑的迁移风险（备选「全局改 role 枚举」需 bump `CANVAS_DOCUMENT_VERSION` 到 5 并写迁移，收益不成比例，不采纳）。

### 2.3 引用句柄命名空间

| 前缀 | 指向 | 解析位置 |
|---|---|---|
| （裸 uuid / 标题） | 当前项目画布节点 | `findNodeByRef` → `resolveRefValue`（现状） |
| `lib:<assetId>` | 全局库条目 | **新增** `resolveLibraryRef` 分支（`host-tools.ts:628`） |

`@ref[lib:<assetId>]` 形如 `@ref[lib:8f3a…]`。`formatRefToken` / `parseRefTokens` 无需改动（句柄本就是任意字符串；`lib:` 只是约定）。

## 3. 数据层设计

### 3.1 磁盘布局

```
<registryRoot>/                        # = assetsRoot（host-config.assetDir || $DSH_HOME/canvas-studio）
├── projects.json                      # 现有
├── groups.json                        # 现有
├── assets-library.json                # 新增：全局库注册表（唯一索引）
└── library/                           # 新增：库媒体文件
    └── <assetId>/
        ├── cover.jpg                  # 封面（可选，缺省用首个 media）
        ├── m_<n>.<ext>                # 媒体文件（锚点图/参考图等）
        └── …
```

- **CR-011 白名单扩展**：`projects.ts:143` 读白名单加入 `assets-library.json` 与 `library/`（只读扫描 + 显式写入口）。
- **路由**：媒体经新增 `ROUTE_LIB_ASSET = '/canvas-studio/library'` 提供（`routes.ts`，形如 `/library/<assetId>/<file>`），复用现有 loopback + same-origin + 路径穿越校验；**不复用** `ROUTE_ASSETS` 的 `/<projectId>/<file>` 形状（避免引入虚拟项目 `_library` 的歧义）。

### 3.2 `assets-library.json` schema

```ts
// 新增 src/contracts/asset-library.ts
export const LIBRARY_SCHEMA_VERSION = 1
export type LibCategory = 'character' | 'scene' | 'prop' | 'group'

/** 库条目引用的一个画布锚点（允许跨项目）。 */
export interface LibAnchorRef {
  projectId: string
  nodeId: string
}

/** 库条目的一份媒体（文件落在 library/<assetId>/ 下）。 */
export interface LibMedia {
  /** 库内文件名，如 m_0.png；HTTP 访问 /library/<assetId>/<file>。 */
  file: string
  kind: 'image' | 'video' | 'audio'
  label?: string            // 如「正视图」「侧视图」
  contentHash?: string      // 去重（对应节点 contentHash）
}

export interface LibraryAsset {
  id: string                // UUID，@ref 句柄 `lib:<id>` 的 id 段
  schema: number            // = LIBRARY_SCHEMA_VERSION，条目级版本
  category: LibCategory
  name: string              // 主名称（自然语言引用的主键）
  aliases: string[]         // 别名/外号（「女主」「Luna」）
  description: string       // 描述：自然语言匹配 + 列表副标题
  tags: string[]
  media: LibMedia[]         // 封面 = media[0]（或显式 coverFile）
  coverFile?: string
  anchors: LibAnchorRef[]   // 来源画布锚点（正/侧/背/全身），用于溯源与再生
  lockedPrompt: string      // 冻结 SAME 块（沿用 StudioAsset 语义，可空）
  negativePrompt?: string
  sourceProjectId?: string  // 首次入库的项目
  usage: { projectId: string; nodeId: string }[]  // 被哪些画布节点引用（回写）
  createdAt: number
  updatedAt: number
}

export interface AssetLibraryDocument {
  version: number           // = LIBRARY_SCHEMA_VERSION
  assets: LibraryAsset[]
}
```

**写入策略**：整体读-改-写 + `writeCanvas` 式合并保护；写操作全部走 Host 单一入口（客户端不直写文件）。

### 3.3 Host 服务 API

#### 3.3.1 HTTP 路由（`routes.ts`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/canvas-studio/library` | 列表（支持 `?category=` `?q=` 过滤，返回 `LibraryAsset[]`） |
| GET | `/canvas-studio/library/:id` | 详情 |
| POST | `/canvas-studio/library` | 新建（body: `LibCategory` + 元数据 + 可选 `anchors`） |
| PATCH | `/canvas-studio/library/:id` | 更新元数据/分类/media 顺序 |
| DELETE | `/canvas-studio/library/:id` | 删除（media 文件 GC 并入 `asset-gc.ts` 流程或复用 `.trash` 方案） |
| POST | `/canvas-studio/library/:id/anchors` | 追加锚点（从画布节点入库） |
| GET | `/canvas-studio/library/:assetId/:file` | 媒体文件（`ROUTE_LIB_ASSET`） |

#### 3.3.2 Host 模块（新增 `src/asset-library.ts`）

```ts
class AssetLibrary {
  constructor(root: string)                 // root = registryRoot
  list(filter?: { category?: LibCategory; q?: string }): LibraryAsset[]
  get(id: string): LibraryAsset | undefined
  create(input): LibraryAsset
  update(id, patch): LibraryAsset
  remove(id): void
  addAnchorFromNode(projectId, nodeId, opts): LibraryAsset
      // 读节点 → 拷贝媒体到 library/<assetId>/ → 写 anchors/media/contentHash
  resolveHandle(handle: string): LibraryAsset | undefined   // 'lib:<id>' 或裸 id
}
```

在 `src/index.ts` 随 `ProjectRegistry` 一并实例化，经 contracts 暴露给 client。

#### 3.3.3 Client contract（`contracts.ts` 新增）

`libraryList / libraryGet / libraryCreate / libraryUpdate / libraryRemove / libraryImportNode`，形态照现有 `persistCanvas`（`contracts.ts:197`）。

### 3.4 跨项目引用的文件解析（关键难点）

`resolveRefValue`（`host-tools.ts:628`）现状：`@ref` → 读当前项目 `canvas.json` → `promoteAssetFile` → Drama filename。库引用需两段式：

1. **解析**：`lib:<id>` → `AssetLibrary.get(id)`；
2. **落地**：库媒体在 `library/<assetId>/` 下，不在任何项目 `assets/`——按需 `promote` 到**当前项目** `assets/`（复用 `promoteAssetFile` 的文件拷贝 + Drama 注册路径），返回 filename，供生成工具使用；
3. **去重**：promote 前按 `contentHash` 查当前项目已有文件，命中直接复用（对齐 `canvas.ts:238` `contentHash` 与 CV-242 句柄自愈思路）；
4. **usage 回写**：成功解析后把 `{projectId, nodeId?}` 记入 `LibraryAsset.usage`（用于「被引用处」展示与防误删）。

`resolveCutAudioSource`（`:258`）、`resolveRefFilenames`（`:583`）、`resolveAnchorNodeId`（`:663`）等调用点统一先过 `lib:` 分支，再走原逻辑。

### 3.5 `@` 提及与 chip 管道

- `reference-source.ts` 新增 `LIB_ASSET_SOURCE = 'lib-asset'`，分区标题「**资产库**」（与「画布素材」「技能」并列）；
- `serializeReference` → `formatRefToken('lib:' + id)` = `@ref[lib:<id>]`；
- 显示名用 `asset.name`（chip 上显示中文名，序列化仍是 `lib:` 句柄——显示与模型文本解耦，同现有 codec 设计 `reference-source.ts:101`）；
- **候选取数**：`activeAssetHandles()`（`index.ts:406`）目前只读当前项目节点；扩展为「当前项目画布素材 + 全局库条目（四分类）+ 技能」三区，库条目来自 `libraryList()` 缓存；
- chip 的 occurrence 对账在上游 `machine.ts:215-227`，**owner 无关**，新 source 自动获得「prompt 修改不丢失」。

### 3.6 自然语言引用（agent 侧）

1. **system prompt section 注入**：新增 `asset-library-prompt.ts`，section 名 `canvas-studio:asset-library`（照 `plan-prompt.ts:18` 的注册方式，order 152），内容为库清单：

   ```
   ## 全局资产库
   - [角色] 女主（别名：Luna、女主A） id=lib:8f3a… — 乌发杏眼，常服白衣…
   - [场景] 雨夜巷弄 id=lib:2c91… — 湿石板路，霓虹反光…
   …
   ```

   注入量上限（如前 200 条 + 截断提示），避免撑爆上下文（与 REQ-007 上下文问题隔离）。
2. **skill 文档**：`skills/canvas-studio-creation/SKILL.md` 增补一节——按名称/别名在清单中找到 `id`，**逐字使用** `@ref[lib:<id>]` token，不得改写（与现有 `:47` 纪律一致）。
3. **工具兜底**：`list_references`（`host-tools.ts:1462`）返回体新增 `library` 字段（四分类分组），供 agent 主动查询（system prompt 截断时的第二通道）。

### 4.4 核心流程

**F1 从画布注册入库**
1. 节点右键 / 详情抽屉 → 「**加入资产库**」（新增菜单项，挂 `CanvasContextMenu.tsx:103` 同级）；
2. 弹内联对话：选分类（四选一）+ 填名称/别名/描述（名称默认节点 title）；
3. Host `libraryImportNode(projectId, nodeId, meta)`：拷贝媒体 → 建 `LibraryAsset`（`anchors=[{projectId,nodeId}]`、`contentHash` 去重）；
4. toast「已加入资产库 · 角色」。

**F2 `@` 引用（对话输入框）**
1. 输入 `@` → 菜单弹出三区：**资产库 / 画布素材 / 技能**；
2. 键入过滤（按 name/aliases/tags）→ 选中 → 插入 chip「女主」；
3. chip 周围增删文本、删除邻居 chip → 本 chip 不丢（occurrence 对账）；
4. 发送 → 序列化为 `@ref[lib:8f3a…]`；气泡显示「女主」（displayName 美化，修掉 CV-114 已知的裸 uuid 显示问题——至少对 lib 引用生效）。

**F3 自然语言引用**
1. 用户：「用女主那张侧脸和雨夜巷弄出一版分镜」；
2. system prompt 库清单 + `list_references.library` 让 agent 定位 `lib:` id；
3. agent 工具参数中逐字写 `@ref[lib:…]` → `resolveRefValue` → promote 进当前项目 → filename → 生成。

**F4 删除/防误删**
- 删除库条目时检查 `usage`：非空 → 二次确认「已被 5 处引用，删除后这些引用将失效」；
- 已失效引用在输入框标记 invalid（上游 `set-invalid` 机制，不删文本）。

### 4.5 状态与空态

| 状态 | 表现 |
|---|---|
| 库为空 | 网格区居中插画 + 「还没有资产」+ 「从画布加入」引导 |
| 分类无结果 | 「该分类暂无资产」+ 新建按钮 |

| 写入失败 | toast 错误（复用 `error-toast.ts`），错误码走 `errors/catalog.ts`（新增 `CS-LIB-001` 不存在 / `CS-LIB-002` 重名等） |
