# 爆款复刻流程

> **上游体裁壳（必读）**：本 skill 是 `social-ad-format-director` 的**下游 executor**。
> 用户点名本 skill 时**仍须先加载该壳**完成定向三问（平台场景 / 前 3 秒钩子 / 时长画幅多版本）——
> 点名只决定「用哪条链」，不替代定向。

适用：用户给一条参考视频，说「复刻」「拆解这条视频」「做个同款，产品换成 X」「照
这条批量出几版」。本质是把参考片的**结构**（节奏 / 镜头类型 / 转场 / 字幕形态 /
信息卡编排）映射成 `CompositionManifest`，素材与文案按用户要求替换——
**复刻结构，不复刻素材本身**。

编排定位：本文只做「拆解 → 映射 → 对照 → 批量」这一段；审批节奏与工具用法跟
`canvas-studio-creation` 总纲走，manifest 字段级契约的事实源是
`code-driven-explainer/references/manifest-contract.md`，本文不重复它们的参数细节。

## 0. 前置自检（三个都答上来再动手）

1. **参考片从哪来**：是链接（抖音 / B站 / YouTube 白名单）→ `download_video` 落盘再拆解
   （产物 assetPath 直接喂 media_probe / evidence_grid / verify_teardown 抽帧链路；首次
   调用按需下载 yt-dlp 组件，向用户如实告知；登录态 / 会员内容 / 直播流 / 其他站点
   不支持 → 让用户自备文件）；本地文件 → `upload_image` 落画布后抽帧看。
2. **复刻深度**：默认 = **结构复刻**（节奏/镜头/转场对齐，画面用自己的素材重做）；
   逐镜像素级还原做不到（见 §6）。用户说「像它那样」就是结构复刻，别承诺更多。
3. **替换什么**：产品/品牌/文案哪些换、哪些保留？没有清单就 placeholder 先行 +
   逐项登记素材需求（generated / user / library 标来源），不要停下来等。

## 1. 拆解：产「爆款拆解表」

逐镜过参考片，产出**拆解表**（模板与规则见 `references/remake-mapping.md` §1）：
**镜序 / 起–止秒 / 内容类型 / 制作方式 / 元素与动效 / 转场入 / 字幕与文案落点**，
外加一列素材需求。**「制作方式」判底层画面怎么做出来的，只用来选复刻路径**——
八类裁剪口径 / 叠加层分标 / 真实素材与参考素材两分见
`references/production-method.md`；判不出写「存疑 + 理由」，不要硬猜，也不要拿它承诺像素还原。

- **时间骨架用 `media_probe` + `evidence_grid`，不要逐帧轮询**（CV-402）：先
  `media_probe` 探参考片真值（时长 / fps / 音轨 / LUFS——拆解表头部直接抄，别拿声明值
  当真值）；再 `evidence_grid` 一次拿「逐秒时间标注网格 + 结构化清单 + 实测画面切换点」
  （缺省整片 1s/格概览，红框密集段二次调用传 `passes` 密采 0.1–0.3s/格）。切镜边界以
  实测切点为准，转场类型看切点前后两格的变化形态。
- **内容语义用 `video2vl`（缺省 shot-breakdown 官方模板，什么都别传 prompt）**：逐镜
  景别 / 机位 / 动作由它出；单点核对用 `image2vl`（对帧图）。`inspect_image` 只做像素
  定位（bbox / 主色），不再是拆解轮询手段。
- **同参考片已有拆解成果先读再拆**：拆解前先 `teardown_store`（`action:"load"` +
  videoPath）查跨项目拆解库 —— 命中就取回复用；本片拆解回核通过后 `save` 落库
  （产物不再随 project dir 蒸发）。会话/画布里已有本片的拆解便签或拆解表 → 同样
  核对后复用。禁止整表重拆——重拆不但烧时间，还会拆出与上一轮不一致的归段（甜品
  会话 v2 实测教训：v1 拆对了的段落 v2 拆错）。
- **「元素与动效」列是本表的灵魂**（甜品复刻会话实测教训：只拆版式不拆运动，复刻
  会退化成静态卡轮播）：逐元素回答「**什么在动 / 怎么动（方向·幅度）/ 什么曲线
  （弹跳？渐入？）/ 和谁联动**（如：底部菜单切换 → 商品与标题背景同步换）」。
  版式只回答"长什么样"，动效才回答"为什么像原片"。
- 时长精确到 0.1s；总时长直接决定 `durationInFrames`（fps 固定 30，秒数 ×30）。
- 内容类型只归六类（§2 映射表左列：实拍段 / 静帧图 / 口播字幕 / 文案卡 / 数据卡 /
  节奏装饰），拿不准按画面主体归。
- **拆解表一次定稿后先回核再进映射**：`verify_teardown`（参考视频 + 拆解段数组）
  机器实测段落边界——matched 回报实测切换时刻（偏差 >0.3s 按实测校准起点）；
  unmatched / extraSwitches（疑似漏段）先改表再核。**自评 verified 不算证据，
  带可疑拆解进渲染 = 整片返工**（甜品会话 v2 实测教训）。
- 回核过了**必须**用 `write_note` 把拆解表落成画布便签（标题「参考片拆解」；一行一段：
  段名 | 起-止 | 时长 | 元素与动效）。这是复刻流程的**硬检查点**：confirm 模式落完
  停下等用户过目；auto 模式不停，但便签照落，并在回复里一句话说明「拆出了什么、
  下一步要做什么」。不要边拆边渲。
- **AI 段生成前先出单元计划**：拆解表定稿后调 `plan_generation_units`（`shots` 传
  逐镜数组，`productionMethod`/`transitionIn` 直接抄表）——它把同场景硬切相连的
  AI 镜头合并成**最少调用次数**的生成单元（8 镜同场景片 3 次调用搞定），插入的
  代码/录屏/静镜不打断分组，单镜超 15s 在动作停顿处切段（后段用前段尾帧
  `shotTransition:'chain'` 衔接）。**只出计划不代执行**：返回的逐单元提示词（统一
  风格句 + `<Picture N>`/`<Video N>` 参考行）经用户逐单元确认后再贴进 `video_composite`，
  付费生成不抢跑。

## 2. 映射：拆解表 → 轨道

全表在 `references/remake-mapping.md` §2–§3。速记：

- **铁律：画面上每个会动的元素 = 一条独立轨**（禁止把整帧画面烤成一张静态图再
  fade 轮播——那是 PPT，不是复刻；甜品会话 v1-v7 就栽在这）。背景色块 / 大标题 /
  产品 / 装饰球星 / 底栏，各自成轨，各配 `animate`（+ `easing`）或 `orbit`。
- 实拍段/产品演示 → `video` 轨；静帧/产品图 → `image` 轨（`fit: cover/contain/
  kenburns`，kenburns 推近是白嫖节奏感的第一手段）。
- **拼贴/精灵图两种走法，别混**：同图多格**同屏引用**（一图多轨、各取子区域）→ 每格
  一条轨加 `sourceRect` 百分比子区域；某一格要**独立当素材**（去生图参考 / 抠图 /
  上传 / 单独引用）→ 先 `image_crop` 裁成独立文件（`grid:{rows,cols,row,col}` 从 1 起，
  产物自带尺寸 / 四边色 / 亮度图可自证），再对该文件做下一步。**不要写 PIL/numpy 裁切
  脚本** —— 上一轮实测自写 52 次像素脚本占掉 28% 模型时间，且手搓文件没有血缘。
- **产品/主体要融进场景（透明底）→ 四步工序缺一不可**：生图提示词固定「纯白背景」→ `image_matting` → `inspect_image` 核
  colorType=6 → alpha PNG 直引进 image 轨（平台已按 hasAlpha 免深底垫底，详见分册
  §2；伪透明拼贴会留棋盘格残边，实拍照抠不干净就回炉重绘）。
- 口播/歌词逐字 → `caption` 轨（词级卡拉OK，`src` 挂该句旁白，`tts_voiceover`
  逐句出）；句级字幕条/标题 → `textCard`（`anim` 四种入场动效）；**镂空描边大字**
  （品牌站常态）→ `fx: 'outline'`。
- 真数据表/对比 → `chart` 轨（`bars`/`dual`）；讲「每镜多长」这类结构数据直接
  `source: 'timeline'` 零手填。
- 节奏装饰（几何/光效/线条）→ `shape` 轨（9 种形状 × orbit/draw/fx）。
- **缓动速查**：弹跳/跃入 → `backOut`；柔性滑动 → `spring`；快出缓停 →
  `easeOutCubic`/`easeOutQuart`；淡入 → `easeIn`。**缺省 linear 没有生命感**，
  每条 animate 都要显式选档（全表在映射分册 §3.5）。**产品跳升/弹入直接套分册
  §3.6 的实测 preset**（曲线+幅度+时长现成，别现场重推参数）。
- 转场 11 式全表在映射分册 §3；参考片的转场名对不上就选**视觉最接近**的一式，
  别硬凑名字。
- 引擎能力与字段疑问查 `code-driven-explainer/references/manifest-contract.md`
  的 16 条实现细节——**不要读组件源码**（那是文档债复发，烧 token 还慢）。

## 3. 组装与渲染

- manifest 组装纪律、字段契约、尾部完整性自查全按
  `code-driven-explainer/references/manifest-contract.md`；长片必须走 `manifestPath`。
- **先 draft 档（480p）出对照版**，对照过了再 standard/high 出正片——复刻片要改
  几轮是常态，别在高清档上烧时间。
- **改一处先 spot-check 再整片**：`render_composition` 带 `spotFrames:[帧号…]`
  （≤8 个）只渲关键帧静帧、秒级回图，核对版式/文字/产品呈现后再整片渲——别把整片
  渲染当「看一眼」的工具（甜品会话 46 次整片渲，大多只为确认几个画面）。
- **渲完自动双闸**：渲染时传 `timingSegments`（拆解段数组，每段带 `elements`
  动效元素列，模板见分册 §1）—— 宿主渲完实测成片切换点比对拆解表（漂移超 ±0.3s
  报警）并核对每段动画轨数 ≥ 元素数（漏元素报警）。提示照改再出下一版，别攒到
  对照验收才发现整片漂移。
- **素材生成后组装前过一遍 `qc_shot`**：逐张核对是否满足拆解表素材需求列（主体/
  背景/风格）；不合格当场重生成，别让废片进 manifest 再靠整片渲染返工。
- 工单队列并发 1：一次只渲一条；修正 = 改 manifest 重渲，不抽卡。
- 渲染窗口一扇窗只渲一单（连渲稳定性由宿主保证），批量时逐条排队即可。

## 4. 对照验收（原片 vs 复刻片）

**先 `make_compare` 出并排对比片**（原片左｜复刻右，产物落在复刻片同目录
`compare.mp4`，零模型费用）——「哪一秒没对齐」变成看得见的错位，别靠记忆对。
然后并排五项，逐项 PASS 才算复刻完成：

| 项 | 判据 |
|---|---|
| 节奏 | 逐镜时长与拆解表偏差 ≤0.2s |
| 转场 | 形态与拆解表所选效果一致 |
| 字幕 | 出现时机与形态（词级/句级）一致 |
| 信息卡 | 数据与出现时机一致 |
| 整体观感 | 风格不跑偏（色调/密度/动效强度） |

偏差项按拆解表镜序定位到对应轨道改字段，不要整体重做。

有声片加第六项**响度对齐**：渲染报告 `report.loudnessLufs` 与参考片实测值差
≤2dB。参考片响度用 `media_probe` 探（ebur128 实测 LUFS，拆解时记进拆解表——
**不要临场拼 ffmpeg 命令，media_probe 是唯一入口**；复刻会话实测原片 −11.4 /
复刻 −15.3，差 4dB 没人发现就是缺了这一项）。差 >2dB → 调 BGM / 旁白音量重渲。

## 5. 批量换装（爆款裂变）

- 把「会变的」抽成变量表：产品图 URL / 品牌名 / 文案字段 / 价格数字（模板见映射
  分册 §5）。
- 循环 = 复制 manifest 骨架 → 按列替换变量 → 逐条 `render_composition`。一条爆款
  出 N 版、多条爆款换产品，都是这个做法。
- ⚠️ 文案替换不是盲替：caption 的词数变化会影响能量谷推导与折行，textCard 长文案
  会触发排版自适配——替换后看渲染体检提示再出下一版。
- 素材没齐的版本先 placeholder 出片占位并登记素材需求，不让整批等一张图。

## 6. 边界（如实告知用户）

- **任意代码级动效不复刻**（自由粒子 / 物理模拟 / 网页特效）：引擎是受控 manifest
  字段集，不是自由网页。CSS 级自由度看 html-in-canvas 档的落地进度。
- **渲染器已知边界**：conic 渐变遮罩、mix-blend-mode、真 3D 透视会被忽略或退化
  （能力基准归因 A2/A9）；映射分册 §3 给了最近似替代，差异要向用户说明。
- **素材质量不评**：placeholder 只验结构；实拍感取决于生图/生视频模型，与复刻
  流程无关。
- **版权默认换掉**：参考片里的真人脸 / 品牌素材直接复用有风险，默认替换或让用户
  提供授权素材。

## 画面判据取证（六体裁统一，2026-11-05）

本地产物（抽帧 / 素材）的画面判据**首选 `read_image(file_path=…)` 看图本身**，禁拿 manifest 字段自证；精确数值用 `inspect_image`；`image2vl` / `video2vl` 是 VLM 文字转述，仅保底且**不可当事实**。全契约见 `canvas-studio-creation/references/toolchain.md` §7。
