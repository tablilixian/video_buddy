# E-2 ｜ 打开 App 自动加载多个画布（期望停留首页）

> 优先级 P2（有 R-P2-02 需求背书：「每次进入 app 需停留在首页」——**不需要额外拍板，做就是履约**）｜ 风险 T2 ｜ 依赖：无（与 E-1 同区，建议同批）
> 无截图（资料库纯文字条目）。

## 代码级原因
- 订阅 wiring：`client/index.ts:1463-1488`——effect 初始跑一次，之后 `workspaces.list.subscribe`（:1468-1474）与 `sessionSvc.list.subscribe`（:1478-1483）**每次变化**都执行 syncActiveProject + alignStartupSession + maybeDraftLanding。
- `syncActiveProject`（:834-848）：非 homePinned 时 `resolveActiveProjectId()`（:278-299，当前会话 cwd → 项目，兜底 recentWorkspaceId）命中且 ≠ 当前选中 → `select + reloadCanvasQueued + refreshWorkflow`。宿主启动期逐个恢复 workspace/会话 → 映射目标跟着翻 → **连续加载 ≥2 张画布**，停在最后一个映射。
- `alignStartupSession`（:1001-1016）：当前会话缺失/blank 时 open 最近非空会话 → 又触发会话订阅 → 再映射再载入。
- 既有短路：`homePinned`（瞬时内存态，project-store.ts:233,570,631）——syncActiveProject 入口第一行 return（index.ts:839）；`goHome`（:1699-1705）即用它；手动 `openProject`（:1588-1632）自足（select+绑 workspace+reload），不依赖启动期自动 select。

## 修复方案（推荐：启动置位首页）
- 在 :1463 effect 注册前（bootstrap 处）调用 `setHomePinned(true)` 并 `maybeDraftLanding()`（homePinned 时 :927 也会建 draft 落点，首页宿主卡可用）。此后所有订阅事件在 :839 被短路，画布只在用户点项目时经 openProject 载入。
- **为什么不推荐只改 alignStartupSession**：载画布的不是它，是会话变化触发 syncActiveProject 的反应；要拦就得加「启动期只对齐不载画布」旁路——恢复出的会话若立即续聊，onToolCall（:1410-1436）用已选项目节点表算占位、asset-capture reload 指向该项目，无选中/未载画布会重演 CV-034「产物已落盘但画布空白」。
- 折中「启动 N 秒内抑制自动 select」确定性差（基线晚到就漏），不取。

## 改动风险
- 失去「打开 App 直接回上次项目」的自动跳转（需点一下项目行）——这正是 R-P2-02 的要求，非回归。
- homePinned 不持久化，天然只影响启动窗口。
- 对 E-1 无回归：载画布只发生在显式 openProject；tool/call 占位、asset-capture reload 都挂在已选项目上，首页落点是 draft 目录不产画布节点。
- 回归点自查：首页宿主卡（draft landing）、openProject 全链路、给既有项目发消息（claimAndSend）路径不依赖启动期 select——需全量 smoke + 桌面过一遍这三条。

## 验收
无头：无法模拟宿主多 workspace 恢复，靠全量 smoke 保证无回归。桌面：开 App → 停留首页、无任何画布加载闪烁；点项目 → 正常进入并恢复会话。
