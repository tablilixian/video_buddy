## 一、摘要（一页看完）

**事故不是"渲染慢"，是"渲染根本没被调度起来"。**

实测已封死三层嫌疑：Remotion 渲染层（全片 61 轨/1800 帧 **129–182s 渲通**）、产品包装层（+0ms）、
窗口环境（四种窗口档位 333–336ms 无差异）。会话里 39 次超时的错误文案是
"**画布客户端未返回结果**"——这是"没人取单"的文案，不是"渲染失败"的文案。

因此本计划的重心**不是优化渲染，而是让工单链路可观测、可快速失败、可自愈**；
其次才是工具契约（描述与能力不符，直接导致 agent 白干 3 小时）与字段语义（直接导致复盘得出错误根因）。

| 分期 | 目标 | 规模 | 完成后能回答 |
|---|---|---|---|
| **Phase 0** | 真机取证，锁定"认领失败"还是"结算失败" | S（0.5–1d） | 根因坐实，不再靠推断 |
| **Phase 1** | 出片链路：可观测 + 快速失败 + 字段与文案纠正 | M（3–5d） | 同类事故 **10 分钟内**能定位 |
| **Phase 2** | 工具契约与 agent 纪律 | M（5–8d） | 不再出现"照着工具描述做反而更慢" |
| **Phase 3** | 性能与长期（字体 19s、异步派发） | L（3–5d + 长期） | 全片 <60s，短片段 <3s |

## 四、根因树

```
成片未产出（7h28m / 49 次渲染 / 0 成片）
│
├─ 直接原因：39 次「画布客户端未返回结果」
│   └─ 渲染器没跑起来（A 级：同一批文件在本机 10/12 跑通，最慢 117s）
│       ├─ 待证：工单未被认领（client 路径页面不在该项目/不可见）  ← Phase 0
│       └─ 待证：已认领但未结算（回写丢失 / 轮询停表）
│
├─ 放大因素 1：工具把 agent 引向错误的诊断方向
│   ├─ C-1 inspect_image 承诺"一次给全"，实际给不了 → agent 写 9 个脚本
│   ├─ C-2 强制"先看图"，模型看不了 → 验证闭环断裂
│   ├─ A-3 文案互斥 → 3 小时"可见性节流"论证
│   └─ B-1/B-2 字段语义错 → 得出"冷启动 40–60s + 编码 20–34s"的错误模型
│
├─ 放大因素 2：反馈回路缺失
│   ├─ A-1/A-4 工单状态不可见 → 只能靠猜
│   ├─ F-2 阶段成功即停轮 → 36 分钟空转
│   └─ E-3 体检噪声 2.5KB/次 → 5 次 compaction，模型推理吃掉 39% 时间
│
└─ 真实存在的性能项（唯一一条）
    └─ 中文 textCard 固定开销 ≈19s（字体初始化 + 字形栅格化）
        └─ 解释 10 帧探针"几十秒"，解释不了 420s
```

### Phase 1 · 出片链路（P0，出片阻塞）

#### F-01 工单生命周期可观测 ★最高优先

- **现象**：39 次超时，agent 只能看到"超时"，看不到"有没有人接单"。
- **改法**：`render_composition` 返回体（成功与失败都）加结构化字段：
  ```ts
  job: {
    id: string
    path: 'render-host' | 'client'      // 谁认领
    claimedAt: number | null            // 未认领为 null
    firstFrameAt: number | null         // 首帧时刻（判断"跑了没跑"的唯一硬指标）
    settled: 'ok' | 'failed' | 'timeout' | 'cancelled'
    takeover: boolean                   // 是否发生过滞留改派
  }
  ```
- **改哪里**：`src/host-tools.ts`（结果拼装）→ `src/remotion/render-job.ts`（工单快照）→ `src/routes.ts:2990-3002`（改派标记）
- **验收**：人为让画布页离开该项目，发起渲染 ⇒ 返回体 `path='client'`、`claimedAt=null`、`settled='timeout'`，并在 15s 内返回（不是 420s）。
- **规模**：S

#### F-02 认领与改派（Phase 0 后重写：五个硬缺陷，一次修完）

Phase 0 证明"改派从未触发过"，根因是五个结构性缺陷叠在一起（详见取证报告 §三）：

| 子项 | 缺陷 | 改法 | 验收 | 规模 |
|---|---|---|---|---|
| **F-02a** | 派单闸与改派闸共用 `renderHostReady()`：闸关门时新单派给 client，**同时**禁止改派 ⇒ 死锁 | 改派判据降为"窗口存活（`alive`）"，不再要求 `ready`；`booting/error` 也能接管 | 窗口处于 `error` 态时仍能接管滞留单 | S |
| **F-02b** | `clientClaimedAt` 一次打点即永久放弃改派（"看过一眼就归它"） | 语义改为"取单即计时"：claim 后 20s 无首帧 ⇒ 允许改派 | 画布页取单后卡住，20s 内被窗口接管 | S–M |
| **F-02c** | client 单没有看门狗（`armHostWatchdog` 只给 host 单装） | 给 client 单也装，判据同 host（首帧/进度上报） | 画布页卡住 ⇒ 30s 内结算为失败，而非等 90–420s | S |
| **F-02d** | 冷启只等 3s（`pickExecutor`），首单几乎必然判给 client | 提到 8s，且窗口 `booting` 时**排队等**而不是立即判 client | 冷启首单 100% 走 host | S |
| **F-02e** | 工具超时不通知页面；页面 `currentJobId` 非空后 `pollOnce` 永久跳过 ⇒ 后续每单必挂 | 超时时下发 abort（或页面自带"宿主已放弃"判定）并清 `currentJobId` | 超时后下一单能正常取单 | S–M |

**改哪里**：`src/remotion/render-job.ts`（387-401 / 238-254 / 295 / 413）、`src/render-host/main.ts`（156）、`src/routes.ts`（3002）
**规模**：合计 M（同一模块，建议一次做完）

> 乙（取了没结算）靠 F-02b/c 解决，D-5 的雪崩靠 F-02e 解决。F-01 的价值是事后再也不用猜。

#### F-03 纠正误导性文案与描述

- **现象**：报错要求"页面已打开且可见"，工具描述说"可以切走/最小化"。实测四窗口档无差异（Q9）。
- **改法**：
  - `errors/catalog.ts:331` 改为："渲染工单在 {seconds}s 内未被认领或未结算。请查看应用日志中的 `render-job` 记录；这不是画面复杂度问题。"
  - `render_composition` 描述删掉"可以切走/最小化都不影响"这句**未被验证的承诺**，改为"渲染由宿主隐藏窗口完成，与画布页是否前台无关（实测四档窗口无差异）"。
- **验收**：`tests/render-timeout-copy.test.mjs` 断言文案不含"页面已打开且可见"、描述不含"最小化"。
- **规模**：S

#### F-04 修报告字段语义（`warm` / `encodeMs` / `msPerFrame`）

- **现象**：`warm` 硬编码 false；`encodeMs` 是"编码完成时刻"；`msPerFrame` 掺入准备阶段。
- **改法**：
  ```ts
  // 删掉 warm（或改为真实判定：同一 bundle 第二次渲染）
  metrics: {
    prepareMs        // 字体注入 + 时长探测（新增）
    renderMs         // renderMediaOnWeb 净耗时（新增）
    encodeDoneAtMs   // 原 encodeMs，改名，明确是"时刻"
    totalMs          // 保持：从进入函数到拿到字节
  ```

#### F-05 探针渲染隔离（`probe: true`）

- **现象**：探针与正式出片写同一画布节点，最终成片节点被 10 帧黑屏覆盖。

- **改哪里**：`src/host-tools.ts`（参数与结果）+ 节点落盘分支
- **验收**：连做 3 次 `probe:true` 后，成片节点内容哈希不变。
- **规模**：S–M

### Phase 2 · 工具契约与 agent 纪律（P1）

#### F-06 `inspect_image` 能力与描述对齐

两个选项（**建议选 B**，见 D4）：

- A：扩能力——加 `region`（矩形）、`components`（连通域）、`profile`（行列亮度剖面）、多阈值扫描。规模 M–L。
- B：收回承诺 + 最小增强——删掉"唯一像素真值来源、不要手写脚本"，加一句"本工具只给全图包围盒与主色；**要定位图上某个暗区请用 `region` 模式（新增）或改用 `image2vl` 粗定位 + 像素复核**"，同时补 `region`（S）。

- **规模**：M（B 方案）

#### F-07 抽帧提示条件化

- **现象**：`host-tools.ts:370` 强制"先看这几张图再向用户汇报"，文本模型无法执行。
- **改法**：改为条件式——"若你具备看图能力（可调用 `read_image` 且返回图片），先看这 N 张再汇报；否则跳过，并在汇报中说明'未做画面自检'"。
- **规模**：S

#### F-08 资产生命线：不删产物 + 缺失可重建

- **现象**：重启把裁切图删了，3 份素材永久丢失，2 份历史工件已无法重放。
- **改法**：
  1. GC 只删 `.trash` 里超过 TTL（建议 7 天）的文件，**不再删根目录孤儿**；
  2. 渲染前预检发现 `src` 缺失时，若血缘源图仍在 ⇒ 自动重建并提示；否则报"可重建"与"不可重建"两类。
- **改哪里**：`src/asset-gc.ts`（GC 策略）+ `src/remotion/asset-check.ts`（预检）
- **验收**：删除 `watch-hero.png` 后发起渲染 ⇒ 自动从源图重建，渲染成功；GC 后根目录孤儿仍在。
- **规模**：M

#### F-09 编排体检去重与静音

- **改法**：① ML-04 按 `trackId` 去重；② 对 `fx` 为呼吸/环境类的轨道豁免（或加 `intent:'ambient'` 标记）；③ `probe:true` 时整体跳过体检。
- **改哪里**：`src/remotion/motion-lint.ts:189-197` + 结果拼装
- **验收**：同一轨最多 1 条 ML-04；探针渲染返回体不含 `[编排体检]`。
- **规模**：S

#### F-10 `bash` 挂起分类

- **改法**：区分 `TIMEOUT`（命令自身超时）/ `HUNG`（无输出无退出）/ `OOM`，并附"改用脚本文件重试"的建议；不要在输出里静默裁剪。
