## 一、需求与动机

**R-P0-01 原文**：把制作过程分为 2 阶段产出。第一阶段产出故事板（Storyboard）——Agent 经过搜索后产出的详细拍摄故事面板，包含对用户创意的理解、视觉效果、拍摄的分镜设计、每个分镜的 shot 安排、人物设定、音乐设计、旁白对话设计等，使用良好排版的 HTML 给用户呈现。用户在此基础上不断调整，产出确认稿后再进入第二阶段画布产出（目前主要功能）。

**现状痛点（为什么这是一次形态级改造而不是加一个功能）**：

1. **创意→成片全程对话流，用户没有一张「总览纸」**。今天的创作链是：澄清（问句）→ 剧本文本 → 分镜 6 列表格 → 逐镜生成。所有中间产物都散在对话流与画布卡片里，用户无法在动手生成**之前**一眼看到「全片要拍什么、每镜几拍、角色长什么样、声音怎么设计」。
2. **质量纪律藏在 skill 里，用户不可见、不可调**。分镜密度（文戏 2.5s/武戏 1.3s）、一致性纪律（角色卡先行、Look 逐字节注入）、硬约束（禁雪、每 shot 一个运镜动词）都是 agent 侧纪律——用户看不到它们的存在，更无法在生成前修改。
3. **搜索缺位**。「素材需要从网上搜集」（揽月湾需求）这类真实诉求目前靠 agent 泛泛虚构，没有事实锚点。

## 二、精品参考拆解（chongli-30s 样板）

资料库附件样板（`chongli-30s-storyboard`，图证 `docs/assets/library-2026-10-03/req-R-P0-01-storyboard-stage-{1..4}.png`，文字件拆解见 requirements.md R-P0-01）有六个可迁移的**结构要素**：

| # | 要素 | 样板形态 | 迁移价值 |
|---|---|---|---|
| 1 | **顶部参数条** | 总时长 30.00s ｜ 分镜 6 ｜ shot 12 ｜ 画幅 16:9 ｜ 景点 9 个 ｜ 旁白 6 句 56 字 17.5s ｜ 留白 12.5s ｜ 角色一家三口 | 打开文档第一眼完成**量化对齐**——所有后续生成节奏都被这行数字锚死 |
| 2 | **分节 tab** | 00 季节前提 / 01 景点亮点清单 / 02~03 视觉规范·旁白 / 04 分镜脚本 / 05 角色设定 / 06 声音 / 07 素材 / 08 硬约束 | 长文档不迷路；每节就是一个可独立修改的「议题」 |
| 3 | **两级分镜结构** | 分镜 = 叙事单元（带旁白句 + 时长）；shot = 一次连续画面（画面/运镜/旁白/声音四要素 + 英文 prompt 段）；每分镜 2 条 shot 互为备份、可单条重出不牵连；全片上限 15 条 | 与 R-P0-11/C-16 的「一个分镜=一条视频，shot 是节拍」口径**同源**——这就是把 skill 纪律翻译成用户可见结构 |
| 4 | **角色卡先行锁死** | 3 角色各自单独出标准形象图并冻结（含微色偏/明度阶梯防糊脸），再进分镜生成 | 与现有 character_sheet/一致性纪律完全同构，只是把它提前到文档里可见 |
| 5 | **三条硬约束** | ① 每 shot prompt 只保留一个 camera motion 动词；② 暖要来自光不来自后期；③ 全片禁雪（季节前提决定全部 prompt 用词） | 硬约束 = **可执行的生成纪律**，确认稿后逐条注入每次生成的提示词纪律 |
| 6 | **声音设计量化** | 旁白仅 17.5s，其余 12.5s 全给音效配乐；响度 -16 LUFS；配乐侧链避让人声 1.5-3kHz | 声音不是「配个 BGM」而是一份**预算表**——直接映射 BGM/旁白工具参数 |

**设计原则提取**（本设计的评判标准）：参数量化先行、两级粒度（叙事 vs 画面）、一致性资产先锁后拍、约束显式化、声音有预算。

## 三、形态总设计

### 3.1 两阶段流程

```
阶段一：Storyboard（拍摄定稿）
  创意输入 → 澄清（复用现有 5 tokens + 素材/事实诉求收集）
          → 联网搜索（景点/素材/风格锚点，web-search 插件已在桌面端注册）
          → 产出 storyboard v1（HTML 呈现 + storyboard.json 结构化镜像）
          → 用户调整（对话式局部重写为主 + 行内微调为辅，版本可回看）
          → 确认稿（确认清单 → 用户拍板）
阶段二：画布产出（现有能力，零改动）
  确认稿 seeding → 分镜卡×N 落画布（含 shot 节拍计划）
                → 角色设定 → character_sheet 资产卡（冻结）
                → 视觉规范 → Look 卡（5 tokens）
                → 声音设计 → BGM/旁白生成参数
                → 硬约束 → 生成纪律（逐次注入）
                → 定妆 → 关键帧（条件）→ Ref2VA 逐镜 → 成片
```

### 3.2 与现有机制的关系（关键取舍）

- **画布 6 阶段轨道不动**（剧本/分镜/定妆/关键帧/镜头/成片）——存量项目兼容，阶段机零改动。
- **Storyboard 是项目级前置阶段**：`workflow.state` 增加 `storyboarding` 态（ drafting 之前）；产物 = 项目目录下 `storyboard.html`（人读）+ `storyboard.json`（机器读，SSOT）。
- **与三道审批门的关系（本设计最重要的拍板点，见 §九.1）**：
  - **方案 A（推荐）**：Storyboard 确认稿**取代「剧本门 + 分镜门」**——逐步确认模式的门序列变为「Storyboard 定稿 →（条件）关键帧确认」。理由：样板的分镜脚本已包含剧本级旁白与 shot 级四要素，再走一遍 6 列表格分镜门是重复劳动且两处可漂移。
  - 方案 B：保留分镜门做画布侧二次确认（Storyboard 只取代剧本门）。
  - 方案 C：Storyboard 纯前置顾问、不进门禁（改动最小，但「不断调整产出确认稿」的产品意图落不实）。
- **呈现入口**：画布顶部工作条新增「拍摄定稿」入口（确认前显示「草稿 vN」角标），点开全屏 HTML 预览（Host webServer 托管 `/canvas-studio/projects/<id>/storyboard.html`，客户端 iframe 加载，同源无 CORS）；同时在画布落一张「故事板」文档节点（同 BRIEF 文本卡形态）作血缘锚点，连线到由它 seed 出的分镜卡。
- **放手跑模式**：Storyboard 自动产出并自动确认，直接 seeding 进画布（不回合等待）——两阶段在放手跑下退化为内部流水线。

### 3.3 双形态产物：HTML 与 JSON 的关系

- `storyboard.json` = **SSOT**（结构化数据：§4 的 schema）；`storyboard.html` = 渲染视图（由 Host 模板从 JSON 渲染，用户行内微调写回 JSON）。
- 用户对话式修改（「把第 3 镜改成黄昏」）→ agent 用**局部重写协议**改 JSON 的对应节点（§6.2）→ 模板重渲染 → 版本号 +1。
- 确认稿冻结后，JSON 进画布 seeding；之后画布上的实际产出（节点、产物）**不回写** storyboard（它是「拍摄意图」的定稿，不是执行状态的镜像）。

## 四、Storyboard 文档规范

### 4.1 分节结构（对齐样板 00~08）

| 节 | 名称 | 内容 | 数据落点 |
|---|---|---|---|
| 00 | 创意理解 | 用户意图一句话 + 季节/时间/地域前提（决定全部用词，样板「全片禁雪」的来源） | `meta.premise` |
| 01 | 素材与事实 | 搜索得来的景点/事实/素材清单（每条带来源 URL），标注「已核实 / 待核实」 | `facts[]` |
| 02 | 视觉规范 | 5 tokens（色彩/光线/材质/镜头语汇/节奏）+ 风格参考图（可选） | `visual`（= Look 卡前置） |
| 03 | 旁白设计 | 逐句旁白（字数、起止时间、情绪）——只在这里写一次，分镜里引用句号 | `voiceover[]` |
| 04 | 分镜脚本 | 两级结构（§4.2） | `storyboard[]` |
| 05 | 角色设定 | 每角色：外貌冻结描述（SAME 块）+ 参考图占位 + 微色偏/明度阶梯策略 | `characters[]`（= character_sheet 前置） |
| 06 | 声音设计 | 旁白预算（字数/时长）、BGM 段落与响度（-16 LUFS）、音效点、侧链避让人声 | `soundscape` |
| 07 | 素材清单 | 需要上传/搜集的素材（图片/视频/音频），标注来源与用途 | `assets[]` |
| 08 | 硬约束 | 可执行纪律逐条列出（确认后注入每次生成） | `constraints[]` |

### 4.2 分镜脚本两级结构（§04 字段表）

```
storyboard[]: 分镜（叙事单元）
├─ id: "S1"                # 镜号
├─ narrative: "……"          # 这一段讲什么（一句话）
├─ duration: 5.0            # 该镜时长（秒）——锚定旁白长度
├─ voiceoverRef: 1          # 引用 03 节旁白句号
├─ shots[]: shot（节拍/连续画面）
│  ├─ id: "S1-Sh1"
│  ├─ visual: "……"          # 画面（中文化的用户可见描述）
│  ├─ camera: "Push in"     # 运镜——一个 shot 只允许一个动词（硬约束①）
│  ├─ duration: 2.5         # 节拍时长（文戏 ~2.5s / 武戏 ~1.3s，R-P0-11 口径）
│  ├─ sound: "……"           # 该拍的声音事件
│  ├─ promptEn: "……"        # 英文生成 prompt（阶段二直接消费；用户可折叠不读）
│  └─ status: draft | backup | confirmed   # 备份 shot 标记，单条重出不牵连
└─ …
```

- 全片 shot 上限 15 条（样板上限口径）；参数条实时汇总 `总时长 = Σ 分镜时长`、`旁白时长`、`留白 = 总时长 − 旁白 − 音效独占段`。
- **旁白只在 03 节写一次**，分镜/shot 引用——消灭「分镜表里旁白与剧本漂移」这类两处事实。

### 4.3 storyboard.json schema（草案）

顶层：`{ version, meta{title,totalDuration,aspectRatio,targetDuration,shotCount,characters…}, premise, facts[], visual{tokens[5],referenceUrls[]}, voiceover[], storyboard[], characters[], soundscape{}, assets[], constraints[], revisions[{v,at,summary}] }`。字段级校验复用 zod/schemastery 惯例（Host 侧 normalize + 未知字段保留）。

## 五、Agent 编排

### 5.1 搜索接入

- 桌面端已注册 `web-search-tinyfish` / `web-search-hybrid` 插件（cordis.patch.yml），agent 侧具备 web search 工具。
- 编排纪律（skill 增补）：澄清阶段收集「素材/事实诉求」（如「素材需要从网上搜集」）→ Storyboard 产出前对 01 节逐条搜索核实 → 每条事实带来源 URL；搜不到的标「待核实」并提示用户补素材（07 节），**不虚构事实**。

### 5.2 新工具（Host 侧）

| 工具 | 作用 | 形态 |
|---|---|---|
| `write_storyboard` | 产出/整体重写 storyboard.json + 渲染 storyboard.html（落项目目录） | 结构化入参（分节内容），与 6 列分镜表解析同源的校验纪律：解析不出 → 显式报错不落盘 |
| `revise_storyboard` | 局部重写：按 `section` / `shotId` 定位替换（§6.2 协议） | 入参 = 定位符 + 新内容；版本 +1 |
| `submit_storyboard_for_confirmation` | 确认门：提交 → 结束回合 → 用户在预览层拍板「确认进入画布」 | 复用审批门「提交即结束回合」机制与 UI 惯例 |

（逐步确认模式下 `write_storyboard` 首稿后即提交确认；放手跑模式下三连调自动确认。）

### 5.3 确认后的 seeding（一次编排，多工具消费）

确认动作（客户端拍板）→ Host `seedCanvasFromStoryboard(projectId)`：
1. 分镜卡 ×N（`STORYBOARD_NODE_TOOL`）逐镜落画布，卡面附 shot 节拍计划；shot prompt 直接进各镜生成参数缓存；
2. `characters[]` → 提示 agent 逐角色调 `character_sheet`（冻结 SAME 块已写好）；
3. `visual.tokens` → `look_card`（5 tokens 原样冻结）；
4. `voiceover[]` / `soundscape` → 旁白与 BGM 工具参数（响度/避让人声进请求体）；
5. `constraints[]` → 追加进该项目的生成纪律（每次工具调用的纪律注入段，来源标注「拍摄定稿 §08」）；
6. 落「故事板」锚点节点并连血缘线。

## 六、用户调整交互（HTML 演示对应的四件事）

### 6.1 阅读层（默认）

分节 tab + 顶部参数条 + 两级分镜卡（shot 的英文 prompt 默认折叠——用户读中文意图，机器读英文规范，这正是 R-P1-03 Phase 2 的呈现口径在文档层的同构）。

### 6.2 对话式局部重写（主修改通道）

预览层右下常驻「修改意见」输入条：`把第 3 镜改成黄昏` → agent 调 `revise_storyboard(section:"04", scope:"S3")` **只重写该镜**，返回变更摘要（改了哪几个字段）；参数条数字联动更新。定位协议：`section`（00~08）/ `shotId`（S3-Sh2）/ `voiceoverId`——**局部重写是默认，全文重写是例外**（防一处改、十处漂）。

### 6.3 行内微调（轻量通道）

点 shot 卡字段（时长/运镜/声音）直接编辑，写回 JSON 并高亮「用户手改」标记；agent 后续重写**不得覆盖**手改字段除非用户明说（纪律进 skill）。

### 6.4 版本与确认

- 每次改写版本 +1（v1/v2/v3…），可回看 diff 摘要、可回退（铁律：只修产生数据的路径，回退 = 新版本指向旧内容，不删历史）。
- 「确认进入画布」→ 确认清单浮层（将冻结角色卡 ×N / 分镜 ×N × shot ×M / 硬约束 ×K 注入纪律 / 旁白 X 字 Y 秒）→ 用户点「确认」→ 门通过 → seeding。

## 七、分期落地

| 期 | 内容 | 工作量 |
|---|---|---|
| P1 | schema + `write_storyboard` + HTML 模板渲染 + 预览层（只读）+ 确认门（方案 A 的门合并）+ seeding 最小集（分镜卡 + 角色/Look 提示） | 3~4 天 |
| P2 | `revise_storyboard` 局部重写协议 + 版本历史/回退 + 行内微调写回 + 手改字段保护 | 2~3 天 |
| P3 | 搜索接入（01/07 节实抓 + 来源标注）+ 声音预算→工具参数全量映射 + 素材清单上传闭环 | 2 天 |

依赖关系：P1 独立可开工；P2 依赖 P1；P3 的搜索依赖 P1 的 facts 节结构。与 R-P1-03 Phase 2（promptDisplay）天然衔接——storyboard 的「中文意图 vs 英文规范串」就是同一口径在文档层的演练。

## 八、风险

- **门合并（方案 A）是行为级变更**：skill 工作流第 3 步重写、既有测试（分镜表解析守卫）迁移量大——需要专门的回归批。
- **长文档渲染性能**：30s 片 ≈ 12 shot，文档体量可控；但 60s+ 片的 shot 数增长要预设分页/虚拟滚动（P2 观察）。
- **双形态漂移**：HTML 只是渲染视图 + 行内微调写回 JSON，严禁「HTML 可独立存在」——模板与 schema 同仓同测，源码闸防两处口径。
- **搜索质量**：事实节的可信度依赖搜索插件质量；「待核实」标尺必须诚实，宁缺毋假。

## 九、拍板清单（审核本设计时请逐条给结论）

1. **门方案**：A（Storyboard 确认取代剧本门+分镜门，推荐）/ B（保留分镜门）/ C（纯前置不进门禁）。
2. **呈现入口**：画布顶部「拍摄定稿」全屏预览层（推荐）vs 画布大节点内嵌。
3. **搜索工具**：web-search-hybrid（现注册）直用 vs 评估 tinyfish 直连。
4. **命名**：阶段中文名「故事板」/ 产物名 storyboard（可改「拍摄定稿」）。
5. **P1 排期**：确认后是否立即开工（当前队列：桌面验收攒批 → P1？）。
