## 1. 验证梯度（按代价从低到高，逐级放开）

不要一上来就跑全量。**每级绿了才进下一级**，这样出错时能定位在哪一层。

| 级 | 命令 | 何时必须过 | 失败处理 |
|---|---|---|---|
| **V1 语法/类型** | `npx tsc -p tsconfig.json --noEmit`<br>`npx tsc -p tsconfig.client.json --noEmit` | **每次改 `.ts` 后立刻跑**。这是用户的硬要求：「只需保证没有语法错误」 | 必须修到绿，不许跳过 |
| **V2 定向单测** | `node --test tests/<相关>.test.mjs` | 改某个模块后，跑**该模块的**测试文件（不要跑全量 324 个） | 必须修到绿 |
| **V3 契约/守卫** | `node --test tests/manifest*.test.mjs tests/sfx*.test.mjs` | 改了 `manifest.ts` / 新增校验后 | 必须修到绿 + **反向变异**（关掉守卫要变红） |
| **V4 构建** | `npx tsdown` + `node scripts/verify-client-loader.mjs` | 改了 `src/client/**` 或新增 client 入口 | 环境性失败 ⇒ 记入 §6 待人工 |
| **V5 真机替代** | `env -u ELECTRON_RUN_AS_NODE ELECTRON_DISABLE_SANDBOX=1 ../dsh-plugin-desktop/node_modules/.bin/electron scripts/probe/render-host-e2e.probe.mjs` | **0A / 1C / 1 收尾时必跑一次** | 见 §3 |
| **V6 全量冒烟** | `yarn test:smoke` | **不要求**（用户明确：环境问题推到最后） | 出现基线外新红 ⇒ 先判断是不是自己引入的；是则修，否则记 §6 |

> ⚠️ 铁律：测试 import `lib/**`（tsc emit 产物），`tsdown` 只产 client bundle。
> **只跑 `tsdown` 再测试 = 测旧码。** 改完 `src/` 必须先 `npx tsc -p tsconfig.json`。

## 2. 真机验证怎么替代（这是无人值守能成立的关键）

用户已确认：**`scripts/probe/render-host-e2e.probe.mjs` 用 Electron 自带 Chrome，跑通 ≈ 真机通过。**

它的三个阶段都是真实的：

| 阶段 | 验什么 | 对本需求的用处 |
|---|---|---|
| 1 | 隐藏窗口能否跑起来并自报 idle | 排除"窗口没跑" |
| 2 | 窗口能否取到工单并**真实渲出 mp4** | **出片能力**（0A 的音效要在这里验） |
| 3 | 滞留改派全链路 | 并发/超时路径 |

**跑法**（必须用 electron 跑，不是 node）：

```bash
cd canvas-studio
env -u ELECTRON_RUN_AS_NODE ELECTRON_DISABLE_SANDBOX=1 \
  ../dsh-plugin-desktop/node_modules/.bin/electron scripts/probe/render-host-e2e.probe.mjs
# 退出码 0 = 三阶段全过；报告落 /tmp/cs-render-host-e2e/report.json
```

**0A 专门的验法**：探针渲出 mp4 后，用 `ffprobe` + `ffmpeg ebur128` 按 `任务包-0A` §5.2.3 断言。
把这一步做成 `scripts/probe/sfx-e2e.probe.mjs`（新写，照 `render-host-e2e` 的结构）。

### 🚫 绝对不要做的事

- **绝不 kill Electron 进程**（`kill -9` / 超时中断都算）。跑完让它自己退。
- 锁残留要**点名删**：`~/Library/Application Support/VideoBuddy/identity/installation-id.lock` 与 `...lock.takeover-<hex>`，不要 `rm -rf` 整个目录。
- 不要起交互式 GUI（`yarn dev`）来验证 —— 用探针，它是非交互的。

## 3. V5 探针失败怎么办（三级降级，不许卡死）

| 现象 | 判断 | 动作 |
|---|---|---|
| 报缺 `electron` / `dsh-plugin-desktop` 找不到 | **环境问题** | 记 §6-ENV-1，跳过 V5，继续下一包 |
| 建窗成功但页面 403 / 白屏 | 会话/鉴权问题（有 `tests/render-host-window.test.mjs` 守着契约） | 先读那 4 条断言；仍不行记 §6-ENV-2 |
| 渲出 mp4 但**没音轨** | **这是真 bug**，不是环境 | 按 §5 修，最多 3 轮 |
| 渲出 mp4 有音轨但静音 | 真 bug（混音/增益/URL 三者之一） | 同上，先 `ffprobe` 确认流存在，再查 URL 是否 404 |
| 探针 5 分钟无输出 | 可能 idle 超时 | 等满 6 分钟再判死；**不要中途 kill** |

## 4. 默认决策规则（遇到歧义照此拍，不许问）

拍完**必须**追加到 `决策日志.md`（一行：日期 / 问题 / 选择 / 理由 / 可回退性）。

| 场景 | 默认选择 |
|---|---|
| 两种实现都合法，一种改动小 | **选改动小的**（可回退性优先） |
| 要不要新增一个工具/参数 | **不加**。先复用既有入口（本仓已因"两个结构起点工具"踩过坑） |
| 契约加字段 | **加可选项**，不给默认值，不破坏既有 manifest |
| 校验严格度 | **宁可 warning 不 error**，除非会静默出错（静默错必须 error） |
| 验收阈值拿不准 | 取**能证明方向的最小值**，并把阈值写成常量（将来好调） |
| 与既有拍板冲突 | 以 `决策-模板需求收口.md` 为准；若它是被这次实测推翻的，**改它并留痕**（写明被什么数据推翻） |
| 文档与代码不一致 | **改文档跟代码**，除非代码是 bug |
| 发现既有缺陷（非本次引入） | **不修**，记一行到 §6-DEBT，继续；只有它阻挡当前任务才修 |
| 只有 1 个模板能跑通 vs 多做 2 个 | 按 P-10 做满 **3 个**（少于 2 个时"选模板"逻辑根本没被触发） |

## 5. 失败处理预算（防止在一个坑里耗死）

```
同一个问题连续失败 3 轮 ⇒ 停止尝试，改做下面两件事之一：
  a) 绕过它（换实现路径），并在代码里留 TODO + 文档留痕
  b) 标记 BLOCKED，记 §6-BLOCKED（现象/已试过什么/下次从哪入手），继续下一项
```

**永远不允许**：为了一个点，把整个任务停在那里等人。
**永远不允许**：把测试改成通过（改断言来迁就实现）—— 除非断言本身写错了，且能在日志里说清"为什么原断言是错的"。

## 7. "全部完成"的判定（Definition of Done）

四条**全部**成立才算完成：

1. **0A**：`manifest.audio.sfx[]` 契约 + 校验 + `resolveSfxStartFrame` 唯一入口 + `assets/sfx/*.wav`（≥5 个）+ 只读路由 + `summarizeManifestAudio`/`StudioAudioComposition` 含 sfx 位；单测绿 + 反向变异绿
2. **0B**：`TextFitPlan.renderText` + `TextCard` 消费它 + `report.textFit` + 修 `title`/`bullets` 的已知缺陷；老 manifest 帧哈希不变（或说明为何无法验）
3. **1C**：`src/remotion/furniture.ts` 纯函数 + 确定性（禁 `transition`/`@keyframes`）+ 构件默认关闭时逐帧不变
4. **1**：`assets/templates/` 下 **3 个**模板（科普/产品/汇报）各含 `manifest.template.json` + `slots.json` + `meta.json`；`list_templates` 带筛选；`scaffold_manifest({templateId})`；`gateTemplate` 五判据接入；`skills/.../references/template-usage.md` 写好且 `SKILL.md` **体积不增**

外加：`npx tsc` 两个 config 全绿（这是用户唯一点名的硬要求）。

## 9. 上下文预算（长任务必须遵守）

无人值守的敌人不是难度，是**上下文耗尽**。

| 规则 | 原因 |
|---|---|
| **禁止整读** `PROJECT-NOTES.md` / `STATUS.md` / `cv-details.md` | 分别 100KB / 49KB / 280KB。按标题 Grep，或按行号 `sed -n` |
| 改大文件前先 `grep -n` 定位行号，再 `sed -n 'A,Bp'` 读片段 | 避免把整个文件灌进上下文 |
| 单文件超过 300 行时，**先写骨架再分段填** | 一次写完容易超输出上限被截断 |
| 每完成一包就 `git status` 确认改动范围 | 防止误改 `src/` 以外的文件 |
| 长中文行**整行 Edit 不可靠** ⇒ 用 python 按行号改（带 assert 前缀校验） | 本仓已验证的坑 |

## 10. git 纪律

| 项 | 规则 |
|---|---|
| commit | **可以** commit（自主推进需要原子提交），但**不 push**（push 由用户手动） |
| 粒度 | 一包一 commit，或多个小 commit。消息写清 `CV 号 + 做了什么` |
| CV 号 | 从 **CV-460** 起（STATUS §4.1 当前 max = CV-459）。取号前先 `grep` 复核，**不预领号** |
| 入库三层 | STATUS §4.1 索引行 / `cv-details.md` 的 `#### CV-xxx · 标题` / `changelog.md` 一行 |
| 不做什么 | 不改历史 commit、不 `--amend` 已 push 的、不跳过 hook |

> 若 git 写入被沙箱拦（index.lock / seatbelt），按 `PROJECT-NOTES.md` 的"git 写全挂"两档绕行法处理；
> 仍不行则记 §6-ENV-3，**代码改动留在工作区**，不强行提交。
