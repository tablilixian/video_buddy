# 科普 0.1 会话时间投向分析

> 分析对象：`session.v4 13.jsonl`（真机跑，223 步 / 231 次工具调用 / 20 次渲染）
> 方法：按 `callId` 精确配对 `tool/call` ↔ `tool/result` 求每步耗时，再按阶段、主题、工具三维归集
> 总跨度：**82.4 分钟**（turn1 23.5min + compaction 1.0min + turn2 57.9min）

---

## 〇、一句话结论

> **82 分钟里，工具只占 17%（14.2min），模型思考占 83%（68.2min）。**
> 而思考的**最大单一去向是 lint 告警（26.1min / 32.5%）**——为了消掉几条 warning 级别的告警，
> 反复改 manifest、反复渲染，**却漏掉了一个能让 callout 整层不可见、能被一条静态校验拦下的真 bug**。

**这批的效率问题是：把时间花在"让 lint 变绿"上，而不是花在"让成片正确"上。**

## 三、按主题：26 分钟花在 lint 上（占 32.5%）

| 主题 | 耗时 | 步数 |
|---|---|---|
| **ML-lint 告警** | **26.1 min** | **68** |
| 响度 / LUFS | 19.2 min | 26 |
| 折线 / chart | 8.0 min | 29 |
| 入场时序 | 3.7 min | 15 |
| 黑帧 / 空档 | 1.9 min | 7 |
| 字幕 / 时序 | 0.7 min | 3 |
| **引线 / callout** | **0.2 min** | **1** |
| 未归类 | 20.4 min | — |

### 这组对比就是全部问题

**`引线/callout` 主题只有 0.2 分钟 / 1 步**，
而 `ML-lint 告警` 有 26.1 分钟 / 68 步。

具体看 render #4 那一步的助手原话：

> ML-07、ML-10、ML-01 都已清除，剩下 9 条 **ML-04（我加的呼吸段被判断为"长而位移极小"）**。
> 我会让呼吸段首尾同值以获得豁免，改为三段的写法

于是有了 `fill()` 函数——给 19 条轨挂 `scale 0.994↔1.006` 的往复动画，
**唯一作用是让 ML-04 的"往复豁免"生效**（首尾同值 ⇒ 位移净值为 0 ⇒ 豁免）。
render #7 那一步又把它改回来：

> ±12% 的缩放会让仪表盘看起来像在"鼓包"，这是真实的视觉缺陷。**ML-04 只是 warning 级别，不值得为它牺牲观感**

**即：这 26 分钟里，有相当一部分是为了满足一条 warning-only 的 lint，最后又主动放弃了这道lint。**
而真正让 A4 塌掉的 `animate.startFrame` 语义错误，一分钟都没花。

### 讽刺的是：lint 的噪声直接挤掉了目检

render #6 之后，助手说：

> lint 告警已经全部消除。**现在检查画面，因为这才是关键**。先看第 338 帧（S2 机制段中的地轴与引线标注）

然后 render #7 采了 `spotFrames: [400, 470, 700, 1320]`——**第 400 帧正好落在 callout 轨的 384–416 窗口内**，
而且它**确实调了 `inspect_image` 看了这张图**。但它看的是 960×540 的**亮度网格**（32×18 字符），
不是画面本身。它的结论是：

> 地球区域出现了代表地轴的亮条（r8–r9 中部）以及**引线起点**

**"引线起点"被当成了引线存在的证据。** 实际上 callout 整层 opacity 恒为 0，
那点"引线起点"是地轴上的另一个元素。

**用亮度网格代替看图，在低对比度的暗色场景里必然漏检。**
这 0.2 分钟的"目检"，是整批 82 分钟里最便宜也最致命的一次判断。

## 四、20 次渲染的结构

| 形态 | 次数 | 单次耗时 | 用途 |
|---|---|---|---|
| spot 快速探针 | 7 | **1.5s** | 定点验证，几乎不花时间 ✅ |
| draft 全片 | 10 | 24–29s | 试错主力 |
| standard 全片 | 3 | 27–42s | 交付定稿 |

**spot 探针机制是好设计**——1.5 秒出一帧，比 draft 全片快 17 倍。
但它用得**晚了**：前 6 次渲染全是 24–29 秒的 draft 全片，第 7 次才第一次用上 spot。
前 6 次全片渲染（合计约 2.5 分钟机器时间 + 大量思考）本来多数可以用 spot 覆盖。

两次渲染之间的修改工具数也印证了返工密度：

```
render#2 → #3  之间: bash=32   ← 一次大改（重排入场）
render#5 → #6  之间: bash=15   ← 改呼吸/ML-04
其余各轮:        bash=0~8
```

## 五、时间花的值不值：一张账单

### 值得的（≈25 分钟）
- **抓 GISS 原始表 + 写便签 + 溯源核对**（P2，7.9min）——产出 100% 可溯源的数据，这是真本事
- **TTS 音色锚 + 逐段克隆 + 实测时长回排帧号**（P3，10.7min）——"用实测时长不用估算值"，专业
- **响度问题定位与修复**（19.2min）——从 −22.0 → −14.0 LUFS，根因找到"TTS 素材本身仅 −27 LUFS"，是**真问题真修复**
- **黑屏 116 帧修复**（1.9min）——真实缺陷，快速修掉
- **折线 `color` vs `lineColor` 修复**（8.0min 内）——真实缺陷

### 不值的（≈40 分钟）
- **ML-04 告警治理**（26.1min 里的主要部分）——为了 warning-only 的 lint 加 19 条假动效，最后又放弃
- **draft 全片试错**（前 6 次渲染 + 其间思考）——本可用 1.5s 的 spot 探针覆盖
- **callout 目检**（0.2min）——**省了 10 分钟，赔上一整条判据**

## 六、结论：时间不是花多了，是花偏了

| 该花在哪 | 实际花在哪 |
|---|---|
| 核对 4 条判据对应的画面 | 消 lint 告警（68 步） |
| 修会毁画面的真 bug | 加 19 条 0.6% 呼吸假动效 |
| 看画面本身 | 看 32×18 亮度网格 |
| 读懂 `animate.startFrame` 语义 | 反复试 `fill()` 参数 |

**核心机制缺陷**：这套流程把"lint 全绿"当成了质量代理，但 lint 恰恰在这次**与真实质量脱钩**——
它报的是真问题（入场时序错、满画布元素带动效），
也放过了真 bug（callout 整层 opacity=0、reveal 方向反、ancher 指向不存在），
还制造了假问题（ML-04 逼出的呼吸假动效）。

## 七、建议：把省下的 40 分钟投到哪

### 1. 补一条静态校验（一次性投入，换掉一整类返工）
```python
# animate 段整轨只命中 ≤1 帧，且该段 from.opacity==0 ⇒ 整层不可见
# animate.startFrame + durationInFrames > track.durationInFrames ⇒ error
```
这条能在 manifest 生成阶段直接拦下 A4，**省掉的不是一次返工，是"渲 20 次都没发现"的整轮盲区**。

### 2. 目检改"看图"，不要看亮度网格
`inspect_image` 的 grid 模式在暗色低对比场景里必然漏检。
判据核对应改为：spot 探针出帧 → **直接读图** → 对照判据表逐条打勾。
成本：多花 2–3 分钟看图；收益：A4 当场暴露。

### 3. spot 探针提前到第 1 次渲染
首轮就用 `spotFrames` 覆盖每条判据的代表性帧，而不是先渲 6 次 draft 全片。

### 4. 给 ML-04 一个正当出路
要么给"设计性静物"开豁免通道，要么把它降级为纯提示。
**否则下一批还会长出一批 0.994↔1.006 的呼吸假动效**——那是 lint 污染成片的典型路径。

### 5. 判据驱动的收尾清单
最后 8.2 分钟的"交付前质检"应该改成**按 8 条判据逐条列证据**（帧号 + 实测值），
而不是"四条需求都用实测数据核对过"一句话带过。
**A4 之所以漏，就是收尾没有按判据表逐条打勾。**
