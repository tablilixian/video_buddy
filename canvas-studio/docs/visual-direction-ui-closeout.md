## 6. 施工顺序（**并行闸门版**）

> **前提**：验收方（用户）与开发方（助手）**同时开工**。
> **核心规则 —— 一个区域验收通过前，不动这个区域。**
> 否则验收方验的是"移动目标"，刚看过的效果下一分钟就被改了，验收结论作废。
> 所以顺序不是一张列表，而是一条**流水线**：`你验完一个区域 → 放行 → 我开这个扇区`。

### 6.3 为什么这样排

1. **P0 先走**：它让"验收"和"开发"从第一分钟就能并行而不打架 —— 这是唯一能立即开工的扇区。
2. **闸门而不是队列**：把"开发顺序"绑到"验收放行"上，避免出现"你刚验完，我正好改了这个文件"。
3. **C5 拆成 a/b 是刻意的**：审批条动效属 D 区（要等 D），浮层动效属 C4（可早做）。
   不拆的话，一整批 C5 会被 D 区闸门卡住，白白闲置。
4. **C1/C2 排在闸门之后**：它们是"重做已验收区域"，本质是**新增一次验收**，不能混在收口里做。
5. **C3 单独排**：唯一带 Host 新能力，风险与验证方式都不同（要跑 `ffprobe` 对真值），不与其他批次混。
