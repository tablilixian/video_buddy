# REQ-029 画布 image 节点交互方案（开工方案 v1.0）

> 状态：**已拍板（2026-10-07）· 待用户过目后开工**。拍板记录与条目状态见 [tracking.md](../tracking.md) REQ-029/REQ-031 条目「拍板」段；本方案是其实施细化。开工时按 STATUS §0 规则领主线号（顺位 CV-281）。
> 同源方案：REQ-031（video 节点）复用本方案的组件基座作扩展形态，不另立方案骨架；差异见 §6.4。

## 一、目标与范围

**目标**：按拍板口径实现画布 image 节点的设计与交互——节点工具栏（悬停四项）、节点输入框卡（参考托盘 + 底栏 chips + 提示词区 + 积分预估行）、摄像机弹层、画布手势三项调整，并对交互演示 HTML 做 **1:1 精准还原（布局/颜色/交互）**。

**非目标（本方案不做）**：
- REQ-031 video 节点形态（排本方案基座落地后，同组件扩展迁入）；
- REQ-030 左侧菜单（除 Credits 占位口径已随拍板统一外，其余独立拍板）；
- 商业化计费后端（积分只做展示占位，「失败自动退回」不做）；
- BUG-053 本体修复（agent 可见档位口径同步随本方案清晰度命名落地，但工具描述修正单独走 BUG-053 条目）。

1. **像素级事实源**（实现时逐项对照，不得凭记忆还原）：

2. **裁决顺序**：拍板口径 > 演示 > 现状交互延续。演示与拍板冲突处（模型四选、8 种比例、双击复位、缩放范围、真实计费）按拍板裁剪，**裁剪只动「选项集合/语义」，不动「布局/颜色/交互形态」**——例如比例下拉面板样式 1:1 还原、项数按拍板 = 3。
3. **演示 HTML 是资料库存档件，不修改**；每处偏差在本方案 §9 偏差登记表留痕（沿用 CV-280「偏差登记 / 不可修清单」手法）。
4. **验收对照法**：沿用 CV-280 验收手法——逐组件截图对照演示稿，用户桌面验收。

## 三、演示设计规格速览（提取自 HTML，实现对照基线）

- **色板**（`:root` CSS 变量，暗色主题）：`--bg:#0a0b0e`；卡片渐变 `linear-gradient(180deg,#161a1f,#12151a)`；chips `--chip:#1e222a` / hover `#262c35` / 选中 `--chip-on:#2b323d`；描边 `--line:#252a33` / 弱 `#1c2027`；弹层 `--pop:#1a1e25` / 描边 `#2d343f`；正文 `--tx:#e9ecf1`；强调 `--accent:#ffb066`（选中工具栏项、发送钮、摄像机开启态、节点选中描边）；成功 `--ok:#4ade80`；警示 `--warn:#fbbf24`。
- **组件清单**（HTML 枚举 + 两图对照）：
  1. 节点工具栏（悬停浮出，节点上方药丸容器）：引用到对话 / 添加到资产库 / 预览 / 下载；
  2. 节点卡：选中态 accent 描边、右下角尺寸角标胶囊；
  3. 节点输入框卡（节点下方附着）：参考格（缩略图 +「参考图 N」标签）+「+ 1/4」添加格；右上角展开（↗↙）+ 关闭（×）双钮；提示词正文区（超 5 行框内滚动）；底栏 chips（模型 / 画幅·档位 / 风格 / 摄像机）+ 右侧（调参钮 / ✨积分 / 橙色圆形发送钮）；
  4. 参考托盘交互：三来源（本地上传 / 选择资产 / 画布导入）、上限 4 张超出拦截、悬停放大镜预览、× 移除；
  5. 摄像机弹层「摄像机制」：副标「参数已作为标记挂在输入框，与预设风格叠加生效」、四列（相机/镜头/焦距/光圈，上下步进）、「当前配置」读数行、↺ 重置参数 + 「开启」toggle；
  6. 下拉面板：模型四选（→拍板裁剪，§四）、比例 8 种 + 1K/2K（→裁成 3 种）、风格；
  7. 画布手势：左键拖动平移 / 滚轮光标中心缩放 / 单击开卡与工具栏 / 双击复位 / 点空白收起（→按拍板调整，§四）。

## 六、组件化设计

### 6.1 新组件 `NodeInputCard`（命名实现时可调）

- 壳：节点下方附着卡（放置复用 `canvas-view.ts` `editorPlacement` 思路），暗色渐变卡体，演示规格 §三。
- 内部三段：参考托盘 / 提示词区（复用 `PromptEditor.tsx` 编辑器与草稿持久化 `editor-drafts.ts`）/ 底栏 chips。
- 状态：未选中淡出（演示行为）、展开钮（↗↙ 放大态）、关闭（× / Esc / 点空白）。
- 两形态 API（§6.4）：`form: 'image' | 'video'`，托盘槽位配置由形态注入（image=4 图；video=9/3/3 + 模式 Tab，后续需求）。

### 6.2 浮层替换 + 迁移分批（拍板⑧）

1. Step 2~4 期间新旧**并存**（新卡管新建/编辑，浮层暂留），行为不回退；
2. Step 5：CV-272 两入口（`CanvasContextMenu.tsx:150` 右键「修改提示词」、`NodeActionBar.tsx:98` 工具条「改提示词」）改开 `NodeInputCard`；CV-265~267 能力逐项核对迁入（参考三来源、草稿、保存并重试、视口避让）；核对完 `.csNodePromptPanel` 摘除（styles + 渲染点零引用守卫）。

### 6.3 共享口径上提

`RESOLUTION_DISPLAY` 从 `lobby-spec.ts` 上提为共享模块（如 `src/resolution-display.ts`），lobby 与节点卡同源消费——防两处映射漂移；`lobby-spec.test.mjs` 既有 6 条守卫随迁。

### 6.4 REQ-031 预留（本方案只留缝，不实现）

- 托盘槽位配置化（image 形态 = 单类 4 槽；video 形态 = 图 9/视频 3/音频 3 + 合计 12 拦截 + 音频不能唯一——`video-reference.ts` / `audio-reference.ts` 校验已在，接 UI 即可）；
