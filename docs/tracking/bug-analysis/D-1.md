# D-1 ｜ 末帧卡不该出现在画布（extract_last_frame 产物对用户无用）

> 优先级 P1 ｜ 风险 T2 ｜ 依赖：无
> 截图要点：「未帧·分镜1·视频」卡挂在画布（参考首末帧 tag）；用户原话「本条对用户没啥用」。

## 代码级原因
- 落卡：`video-frames.ts:93-205` extractLastFrame——节点 :162-181（`referenceRole:'frame'`、`origin:'agent'`、generationPrompt={videoUrl,seek}），retry 原地重写 :184-195 走 overwriteNodeAsset。
- 展示位：`canvas-view.ts` laneOfNode `case 'extract_last_frame': return LANE_FRAME`（约 :469）——专属泳道，必然可见。
- **为什么不能简单不落卡**：chain 流程取句柄不依赖节点（工具结果直接回 url+filename，host-tools.ts:1391-1412，video-frames.ts:137-138），但节点+文件支撑四件事——① referenceRole:'frame' 进参考托盘/list_references 供 @ref 引用；② 断链自愈 healReferenceFilename 依赖项目 assets 里的帧图文件，而 extractLastFrame **不写 history.json**（无 recordAssetHistory，对比 generate.ts:2357/2683）——不落卡则文件成根目录孤儿，打开项目时被 gcProjectAssets 物理删除（asset-gc.ts:149 起）→ chain 断链无从恢复；③ CV-195 节点级重试依赖节点存在（generate.ts:1793 replayDetachedAsset 的 extract_last_frame 分支）；④ C-10 血缘连线与改写锚点。

## 修复方案（推荐 b：落卡但标辅助态默认收起；不要选 a 不落卡）
1. `contracts/canvas.ts` 节点字段区（约 :207）新增 `auxiliary?: true`；video-frames.ts:162-181 落卡携带；retry 重写路径（:184-195）补写该字段。
2. 渲染层默认收起：canvas-view.ts 布局输入过滤/折叠 auxiliary 节点（空栏收窄）+ 图层面板默认折叠；CanvasToolbar 加开关恢复显示（照 MENU_VISIBILITY/TOOLBAR_VISIBILITY 的「只隐藏入口、接线保留」模式，CanvasContextMenu.tsx:7-15）。
3. 选项 a（只回对话不落卡）若坚持：必须同时补 recordAssetHistory 防 GC 误删、放弃节点级重试、@ref 与 C-10 血缘全失效——代价大于收益，不推荐。

## 改动风险
- 新字段旧画布无值 = 照旧显示，渐进兼容；client contracts 同步。
- LANE_FRAME 过滤后空栏需收窄处理。
- agent 侧不受影响（Host 不变，句柄照常返回），仅人眼可见性变化——「引用末帧」入口折叠后用户找不到时靠开关，开关文案要写清。

## 验收
无头：contracts 字段往返单测 + 布局过滤单测。桌面：chain 流程正常出片；画布默认不见末帧卡，开关打开可见。
