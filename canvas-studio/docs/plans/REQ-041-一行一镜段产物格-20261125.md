# REQ-041 · 一行一镜「段产物格」纠正（2026-11-25）

> 起因：真机第二次反馈 ——「视频跟文字还是在一起」。上一版把段视频画进了分镜卡。

## 1. 正确形态（用户原话，作为唯一口径）

历程视图的分镜托盘，一行一镜，格序：

```
文字卡 → 关键帧 → 视频 → 音频 →（可能还有末帧）
```

段产物（Remotion 渲出的「这一屏」）属于**视频**这一格，不是分镜卡的附属画面。
效果图 `docs/demos/shot-rows-2026-11-24/index.html` 只取**布局部分**：
右侧展开的抽屉（`#sheet` 全文面板）**不做**；文字卡维持现状（两行 + 选中展开），
不按效果图改成 6 行 + 渐隐 + tags + 帧数脚部。

## 2. 上一版为什么错（结构错位，不是样式）

| 事实 | 数值 |
|---|---|
| 历程视图格宽 | 380（`thumbWidthFromViewport`，≤1700 档） |
| 分镜格格高 | `round(380 × 9/16)` = 214 |
| 卡内可用体区 | 214 − 头 48 − 脚 22 ≈ 144 |
| 段视频原始尺寸 | 960×540 |

把 16:9 画面塞进 144px 高的体区、再叠加 8 行分镜稿，两者只能互抢高度。
补丁（`min-height: 64px` + 压住选中态展开）只能把「重叠」变成「一条亮带」，
治不了根 —— 根是**放错了格子**。

## 3. 现在的实现

| 层 | 落点 |
|---|---|
| 布局 | `canvas-waterfall.ts`：`options.segmentRefsWithMedia`（有可播段的 ref 集合）；命中则在该镜行内插入合成格 `segment:<镜号>`，role 2.5（镜视频之后、末帧/配音之前） |
| 格位 | 进 `boxes` 与 `trays[].nodeIds`（行框、折行、「镜 N」角标右边界都算得上），**不进** `positions`（它不是节点，没有可拖坐标） |
| 渲染 | `client/canvas/SegmentCell.tsx`：复用 `.csNode` 三段式（头/媒体/脚），悬停静音循环播、双击开播放浮层 |
| 悬停单例 | `client/canvas/hover-video.ts`：视频卡与段产物格共用一份「全画布最多一个在播」登记（改前这份登记在 CanvasNode 里，两种组件各播各的） |
| 播放 | `StudioFrame`：`segmentPlayback { ref, shot }` → `VideoPlayerModal`；与节点播放器互斥 |
| 分镜卡 | 回到纯文案卡。工具条三项（引用 / 预览 / 下载）不变，`预览` 播清单里那一版（带旁白副本优先） |

**清单为空 = 不出格**：没渲过段的项目、段还在渲的瞬间，行形态与改前逐字相同，
不会每个分镜卡旁边挂一个空视频格。清单到达后重排一次（多一格），这是有意的。

## 7. 同日二次口径（2026-11-25 16:20 用户明确）

1. **文字卡完整显示正文，显示不下时卡内滚轮查看** —— 推翻 REQ-036 的两行钳制。
   - 旧规则的来历：它服务「托盘头 108 高」的头带形态（chrome 48 + 正文 60）。
     一行一镜把卡改成 380×214 的整格后，体区有 144px，钳两行等于把四分之三的
     高度空着，而分镜稿是这个产品里最长的一份文本。
   - 实现：`.csWaterfall .csNode:has(.csNodeText) .csNodeBody` 改 `display:block`
     + `line-clamp:unset` + `overflow-y:auto` + `min-height:0`，**不给 max-height**；
     `min-height:0` 不能省 —— flex 子项默认 `min-height:auto` 会顶到内容高，
     滚动条永远不出现。
   - 滚轮接线：`CanvasSurface` 的 wheel 豁免选择器由 `.csNodeSelected .csNodeBody`
     放宽为 `.csNodeBody`（未选中也放行），并**追加 overflowY 检查**。只放宽选择器
     会踩一个新坑：自由画布未选中的正文是 A-5 折叠态（`overflow:hidden`），
     `scrollHeight` 仍可能大于 `clientHeight` ⇒ 放行一个滚不动的元素，结果既不滚
     也不缩放，滚轮像坏了。
2. **一镜两处视频都保留**（H3 镜视频 + 段产物并排），遗留 1 关闭。
3. **所有内容有则显示、缺则左移**：格序不按列占位，缺一格后面的格直接补上。
   实现本来就按 role 排序后紧凑排布（`gridLayout` 顺序放置），本次补守卫钉住：
   缺关键帧时镜视频的 x 差必须仍等于 `格宽 + 间距`。
