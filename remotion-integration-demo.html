⚠️ 2026-10-15 修订说明（本页已按 Remotion 4.0.535 校正）
  • 渲染编码不再复用项目 ffmpeg：v4 已移除 ffmpegExecutable，Remotion 自带 ffmpeg+libav*（@remotion/compositor-*，≈17MB/平台）。项目 ffmpeg 只做混音与探测。
  • 渲染三步链：bundle() → selectComposition() → renderMedia({composition, codec:'h264'})；composition 传 对象不是 id 字符串，codec 必填。
  • 浏览器是 Remotion 自管的 Chrome Headless Shell（非完整 Chrome），参数名 browserExecutable；「复用 Electron Chromium」已排除。
  • 素材喂入统一为 renderDir 模型（publicDir 只在 bundle() 时生效，与「预构建 bundle」互斥）。
  • 动态时长靠 <Composition calculateMetadata>；无 @remotion/test-renderer（该包不存在）。
  • skill 侧（CV-317~326 新规）：新增 skill 需 platform.yaml（9 必填）+ skill-catalog 快照；入口 ≤12 KB；skill 不得自设审批门（审批语义归总纲，本路径由 render_composition 工具自身调 assertApprovalAllowed）。
口径以 remotion-integration-devdoc-2026-10-14.md（v1.3）为准；本页仅用于理解流程形态。
📌 路线进展（2026-10-15 实测）：另有更优路线 B
本页描述的是 路线 A（SSR：Node + headless-shell 逐帧截图） —— 已全链路验证通过。 同日 B0 Spike 另发现并实测了 路线 B（CSR：@remotion/web-renderer，在 Electron 自带 Chromium 里渲染）： 包体 ≈+0（无需浏览器 210MB / compositor 42MB / webpack）、性能 13 ms/帧（比 A 快约 7 倍）、 自托管字体与观感均已验证；代价是 z-index 等 CSS 子集限制（组件须靠 DOM 顺序控层叠）。 若采纳 B，本页 STEP 3 的渲染链与资产注入方式会改（详见 docs/remotion-spike-report-2026-10-15.md §2.7 / §9.1 与 devdoc §7.6）。

04 功能缺口：现在差什么

绿色 = 新增能力；琥珀/红 = 需要在集成时补的工程或风险。

P0 缺口

没有代码驱动合成引擎

现状 compose.ts 只是 ffmpeg 的 concat+amix+afade，做不了字幕卡/数据卡/动态图形/精确转场——这正是 REQ-034 科普视频的硬缺口。

P0 缺口

没有 CompositionManifest 契约

「成片结构」现在隐式写在 skill 的 STEP 里，没有结构化中间层。需新建 src/remotion/manifest.ts（devdoc §4 定稿契约）。

P1 工程

浏览器进包 / 搬运

Remotion 自管 Chrome Headless Shell（node_modules/.remotion/…，连 VERSION 一起收进 extraResources）；@remotion/compositor-* 须 asarUnpack。本机 agent shell 受 com.apple.provenance + 沙箱限制；universal 包须在用户终端跑，且要走 ELECTRON_MIRROR / ELECTRON_BUILDER_BINARIES_MIRROR。

P1 工程

长片阻塞 agent 回合

Remotion 渲染分钟级。MVP 先做同步工具（镜像 compose_video），长片/批量再接入 Drama 任务恢复轮询做异步。

P1 盲区

幻灯片风险评分缺失

有 quality-check.ts 但无 OpenMontage 式 6 维「一堆图假装视频」评分，需阶段 A 增量补。

P1 已定

字体方案（已定：混合 C）

随包思源黑体子集兜底（离线必出片）+ global.fonts 声明的字体从自托管源按需下载缓存到 userData（多语言可扩展，OFL 许可）+ 失败 fallback warning。详见 devdoc §8.3。⚠️ 下载源依赖 Drama 后端新增 /fonts/ 路由，属外部前置，不进 MVP 关键路径。

P1 已定

字幕时序（句级已定，词级二期）

Drama TTS 无时间戳（已核实）→ 句级用「探真值总时长 + 字数比例分配」（§10.3）；词级 KTV 式需 TTS 时间戳或 forced alignment，列二期。

P1 已补

素材轨时长口径（v1.1 新增）

video 轨时长必须取 list_shots 真值（禁止 LLM 估）：声明偏短会截断、偏长会末帧冻结，都是静默错误。宿主渲染前按真值核对修正 + warning，HITL 预览显示「声明/真值」两列（devdoc §10.4）。

P2 已定

资产喂法（已定：方式 B → renderDir）

publicDir 只在 bundle() 时生效（内容被复制进 bundle 目录），与「预构建 bundle」互斥 ⇒ 统一为 renderDir 模型：组件一律 staticFile('cs-assets/<name>')，素材用 硬链接优先（同卷零拷贝）注入（devdoc §8.1/§8.2）。

05 我的评估：这事儿咋样

结论：干净、低风险、值得做；MVP 约 3~4 周单人。

你们不是从零造视频引擎，而是给已有「模型驱动主干」并联一个「代码驱动旁路」。80% 的地基（agentic skill、Drama 模型层、ffmpeg 后期、storyboard 契约、HITL 审批、统一错误系统）都现成，Remotion 只补最薄的一层「逐帧渲染 + 卡片组件」，且 License 对两人公司免费。最大不确定性不在代码，而在打包期的浏览器与平台二进制进包（headless-shell 收进 extraResources、@remotion/compositor-* 解包）—— 路径明确，且都在阶段 0/6 有验证动作。

✅ 优势 / 利好

  • 复用度极高：ComposeResult 形状、HITL 门禁、资产反查、appendComposedVideoNode 全部直接复用，客户端零改动（ffmpeg 仅复用其混音/探测能力）。
  • License 零成本：两人公司落在 Free License，商业使用免费；服务端 renderMedia + LLM 生成代码均被允许（官方 automation 定义内）。
  • 与现有分层天然契合：render_composition 是纯 Host 工具（Headless Shell 跑在 Node 侧），不碰 Client 渲染。
  • 补课即 REQ-034：字幕卡/数据卡/转场正是「低成本科普视频」刚需，补完即达标；且是项目第一个真正烧字幕进画面的路径（现有 subtitle_burn 仅占位）。
  • 字幕与字体口径已定稿：句级字幕「探真值 + 字数比例分配」零新依赖；字体混合方案（随包子集 + 自托管下载缓存）天然支持多语言扩展。
  • 可灰度：新增工具并联而非替换，老流程 compose_video 不受影响。

⚠️ 风险 / 注意

  • 浏览器进包：headless-shell 目录须显式收进 extraResources（连 VERSION），@remotion/compositor-* 须 asarUnpack；须在用户本机 Electron 实跑验证，不能在 agent shell 验证 GUI。
  • 「双 ffmpeg」已不成问题（v1.1 修订）：v4 无 ffmpegExecutable，Remotion 用自己的编码器（@remotion/compositor-*，含 ffmpeg+libav*≈17MB/平台），我们只管混音与探测 —— 两条独立链。不要试图合并。
  • 测试需浏览器：集成冒烟须 gate 在「浏览器可用」，CI 无头环境跳过，仿 ffmpeg 真跑冒烟判定（跳过须显式打印理由，防空绿）。
  • 静默错误最危险：漏 calculateMetadata → 时长不对；素材时长估错 → 末帧冻结；publicDir 与预构建 bundle 冲突 → 素材读不到。三处均已写成显式机制 + 校验 + warning。
  • 别开放用户上传 Remotion 代码：License 禁区；我们只用自己生成的代码 + 服务端渲染。
  • 长片体验：同步渲染会卡 agent 回合，长片需异步化（二期）。
