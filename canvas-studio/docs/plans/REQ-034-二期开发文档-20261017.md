### D-01 · Remotion 商业许可（**发布阻断，不拦开发**）

**问题**：代码里 `src/client/remotion-render.ts:23` 硬编码 `licenseKey: 'free-license'`（注释写「两人公司 Free 档」）。而 `docs/remotion-license-snapshot-2026-10-15.md` 存档的条款是：Free 仅覆盖**个人 / ≤3 员工的营利组织 / 非营利 / 评估期**，其余需 Company License。

**为什么现在必须定**：二期把能力面做宽（A 档表达层 + D1 批量渲染），商业暴露面同步变大；且 licenseKey 是**发版字符串**，等到发布前才想会被卡死。

**选项**：
1. 认定主体 ≤3 人 ⇒ 保持 `free-license`，但在 devdoc §1.3 落一条「规模变化时复核」的触发条件；
2. 买 Company License ⇒ key 从设置注入（`remotion-render.ts:23` 的注释已预留「将来从设置注入」），需新增设置项 + 存储；
3. 只做内部自用、不对外分发 ⇒ 按 Free 评估期条款走，但产品定位需同步改口。

**建议**：选 1 或 2，**但要落一个显式决策记录**（写进 devdoc + 本文附录 C 勾选）。技术上无论选哪个，本期都该把 `licenseKey` 从硬编码提出成「可注入常量 + 缺省 `free-license`」——这是 5 行改动，做了以后换档不用改渲染逻辑。

**代价**：提注入 ~0.5 天；买证涉及采购流程，与本项目工期解耦。

### D-02 · A1 合成顺序与互斥策略（**必须先定**）

**问题**：现有语义是 `animate` 覆盖 `transform` 声明过的维度（`manifest.ts:73-74`），`resolveAnimatedStyle` 里 fade 与 `extraScale` 走**乘法**（`animated-style.ts:86-91`）。再引入 `orbit`（产出 x/y）必然与 keyframes 争同一维度。

**为什么现在必须定**：不定就会有两种实现，画面随实现顺序漂移；skill 也无法给模型稳定预期。

**选项**：
| 方案 | 规则 | 后果 |
|---|---|---|
| A 覆盖 | `animate` 有 x/y 就覆盖 orbit | orbit 静默失效，模型以为是 bug |
| B 叠加 | orbit 算偏移，animate 再叠加 | 两套坐标系，人算不清 |
| **C 互斥（建议）** | 位置维度三选一：`orbit` / `transform·animate` 的 x,y / 缺省 50,50；同时声明 ⇒ **校验报错** | 语义唯一，写错立刻知道 |

**建议**：**C**。合并顺序写死为：
```
① 位置来源：orbit 计算 (x,y) —— 或 transform/animate 声明值 —— 或缺省 50/50（三者互斥）
② 非位置维度：transform 打底 → animate 覆盖其声明过的维度（沿用现有语义）
③ 乘性叠加：scale × extraScale（kenBurns）、opacity × fadeFrames 淡入淡出
```
并在 `validateManifest` 加互斥检查（错误串必须带轨道 id）。

**代价**：契约文档 + 校验 ~1 天；不做的话返工成本是整批。

### D-04 · D1 队列参数（可并行定，1b 开工前）

**问题**：并发度、队列上限、超时策略。

**现状事实**：`pendingRenderJobFor(projectId)` 只返回该项目**第一张**工单（`render-job.ts:99`）；客户端同时只跑一个 `activeRender`（`client/index.ts:1371` 会 abort 上一个）。所以当前并发多单 = 隐式排队 + 无顺序保证、无进度、无上限。

**建议**：
- 宿主侧显式 FIFO 队列，**渲染并发 = 1**（客户端本来只能串行，多开只会互抢 CPU 与内存）；
- 队列上限 **4**，超出直接拒收（`CS-USER-ERR`，文案「渲染队列已满，请等当前任务完成」）；
- 超时改为**按片长自适应**：`timeoutMs = clamp(2 × 声明时长 + 120s, 10min, 30min)`，替换固定 10min（`render-job.ts:28`）。

**代价**：队列 ~2 天；超时公式 ~0.5 天（要连带改 `tests/remotion-render-job.test.mjs` 的注入值断言）。

## 三、批次 1a · A1 语义原语（`orbit` + `draw`）

> 建议取 **2 个号**：① 契约 + 纯函数 + 校验；② 组件接线 + 真渲取证 + skill 同步。开工时取号。

### 3.1 目标与边界

- **做**：`orbit`（公转关系）与 `draw`（路径生长）进 manifest 契约；补最小 `shape:'path'`（`draw` 的载体）。
- **不做**：`pulse`（退回 skill 范式，见路线图 A1 收窄）；不做通用路径变形（morph）；不做可视化编辑。
- **为什么值**：现在「行星绕太阳」要模型内联上百个关键帧（`motion-helpers.mjs` 手算像素），既贵又易错；原语化后一行声明。

### 3.2 契约草案（可直接抄进 `manifest.ts`）

```ts
/** A1：公转（帧级，纯函数求值）。坐标系与 VisualState 同域：0–100 百分比。 */
export interface OrbitMotion {
  /** 圆心（百分比坐标）。 */
  center: { x: number; y: number }
  /** 半径（与 x/y 同单位，> 0）。 */
  radius: number
  /** 起始角度（度）。0° = 正右（+x），角度增大 = 顺时针（屏幕 y 向下）。缺省 0。 */
  startAngle?: number
  /** 转一圈所需帧数（> 0）。缺省 = 本轨 `durationInFrames`。 */
  periodInFrames?: number
  /** 方向；缺省 'cw'。 */
  direction?: 'cw' | 'ccw'
}

/** A1：路径生长（仅 `shape:'path'` 轨可用）。 */
export interface DrawMotion {
  /** 生长到多少比例（0–1），缺省 1 = 全画出。 */
  to?: number
  /** 轨内相对起始帧（缺省 0）。 */
  startFrame?: number
  /** 生长耗时（帧，缺省 = 整轨）。 */
  durationInFrames?: number
  /** 缓动，沿用 `AnimateEasing` 白名单。 */
  easing?: AnimateEasing
}
```

`BaseTrack` 增一个可选字段（**只加不改**）：

```ts
  /** A1：公转。与 `transform` / `animate` 的位置维度**互斥**（见 validateManifest）。 */
  orbit?: OrbitMotion
```

`ShapeTrack` 增 `shape: 'path'` 分支与三个字段：

```ts
  /** 'path' 时必填：SVG path 的 d，坐标空间 = 0–100 双轴百分比。 */
  d?: string
  /** 'path' 时描边宽度（相对画布宽度的百分比，缺省 0.5）。 */
  strokeWidth?: number
  /** 'path' 时生长控制；缺省 = 全画出。 */
  draw?: DrawMotion
```

### 3.3 合成顺序（写死，对应 D-02）

| 顺序 | 规则 | 落点 |
|---|---|---|
| ① 位置来源 | `orbit` 算 (x,y) **或** `transform`/`animate` 声明的 x,y **或** 缺省 50/50；三者互斥 | `timing.ts` `orbitStateAt()` → `animated-style.ts` |
| ② 非位置维度 | `transform` 打底 → `animate` 覆盖其声明过的维度（**沿用现有语义，不改**） | `animateStateAt()` 不动 |
| ③ 乘性 | `scale × extraScale`；`opacity × fade(帧)` | `resolveAnimatedStyle` :86–91 不动 |

### 3.4 校验规则（`validateManifest` 新增）

| 规则 | 报错文案要点 |
|---|---|
| `orbit.radius` 必须是 (0, 100] 的有限数 | 指明轨道 id + 实际值 |

| `periodInFrames` 若给必须 > 0；缺省取轨道时长，轨道时长 ≤ 0 时直接报错（防除零） | 指明需要显式给 |
