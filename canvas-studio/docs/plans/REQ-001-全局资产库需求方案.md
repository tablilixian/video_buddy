## 1. 背景与目标

### 1.1 需求原文

> 为 App 增加全局资产库页面，下设**角色、场景、物件、群像**资产库；在 agent 中通过自然语言或 `@` 符引用该资源，prompt 中修改也要能使用。

### 1.2 验收标准（来自需求表）

1. 资产库页面**四分类可见**；
2. **`@` 与自然语言**均可引用资产；
3. **prompt 修改后引用不丢失**，仍可解析。

### 1.3 现状缺口（2026-09-27 代码调研）

### 1.5 目标

- **T1**：跨项目全局资产库，四分类（角色/场景/物件/群像），独立全屏页面可浏览/搜索/管理；
- **T2**：画布节点可「注册入库」，库条目可在任意项目被 `@` 引用；
- **T3**：agent 通过自然语言（按名称/别名/描述）与 `@ref[lib:…]` 两种方式引用库资产；
- **T4**：引用经 chip 管道插入，prompt 增删改后引用不丢失、可解析。

## 2. 术语与分类

### 2.1 四分类定义

| 分类 | 枚举值 | 含义 | 典型内容 |
|---|---|---|---|
| 角色 | `character` | 单个人物形象（含定妆/多视图） | 「女主」「反派Boss」 |
| 场景 | `scene` | 环境/地点/氛围 | 「雨夜巷弄」「中式庭院」 |
| 物件 | `prop` | 道具/物件/服装/武器 | 「青铜古剑」「红色跑车」 |
| 群像 | `group` | 多人组合/群众/队伍 | 「街头人群」「侠客小队」 |

中文标签常量：`LIB_CATEGORY_LABELS = { character:'角色', scene:'场景', prop:'物件', group:'群像' }`（新增 `src/asset-library.ts`）。

### 2.2 与现有 `StudioAsset.role` 的映射（决策：新枚举 + 迁移）

现有 `role: 'character' | 'scene' | 'style'`（`contracts/canvas.ts:307`）。处置：

| 旧值 | 迁移去向 | 理由 |
|---|---|---|
| `character` | `character` | 一一对应 |
| `scene` | `scene` | 一一对应 |
| `style` | **读侧兼容，写侧停用**：`StudioAsset` 字段保留 `style` 以免破坏 `canvas.json` v4 与 look-asset 流程；**库分类不含 style**，`style` 卡不自动入库 | `style` 是「风格锚点」注入用途（`look-asset-plan.md`），与四分类正交；强行并入 `scene` 会污染语义 |

即：**库层用新四分类枚举，项目层 `StudioAsset.role` 不动**——两套枚举，但文档层明确 `character/scene` 同名同义，`style` 不进库。这避免了对 `canvas.json` v4、look 卡注册、prompt 注入强度逻辑的迁移风险（备选「全局改 role 枚举」需 bump `CANVAS_DOCUMENT_VERSION` 到 5 并写迁移，收益不成比例，不采纳）。

### 2.3 引用句柄命名空间

| 前缀 | 指向 | 解析位置 |
|---|---|---|
| （裸 uuid / 标题） | 当前项目画布节点 | `findNodeByRef` → `resolveRefValue`（现状） |
| `lib:<assetId>` | 全局库条目 | **新增** `resolveLibraryRef` 分支（`host-tools.ts:628`） |

`@ref[lib:<assetId>]` 形如 `@ref[lib:8f3a…]`。`formatRefToken` / `parseRefTokens` 无需改动（句柄本就是任意字符串；`lib:` 只是约定）。

## 3. 数据层设计

### 3.1 磁盘布局

```
<registryRoot>/                        # = assetsRoot（host-config.assetDir || $DSH_HOME/canvas-studio）
├── projects.json                      # 现有
├── groups.json                        # 现有
├── assets-library.json                # 新增：全局库注册表（唯一索引）
└── library/                           # 新增：库媒体文件
    └── <assetId>/
        ├── cover.jpg                  # 封面（可选，缺省用首个 media）
        ├── m_<n>.<ext>                # 媒体文件（锚点图/参考图等）
        └── …
```

- **CR-011 白名单扩展**：执法点在 `generate.ts:627-635`（`readSourceBytes` 以 `registryRoot` 为界），扩展范围为 `assets-library.json` 与 `library/`（只读扫描 + 显式写入口）；`projects.ts:143` 的 `registryRoot` 只是被白名单消费的访问器。**副作用见 §8-K（库将进入 agent 可读的绝对路径范围）**。
- **路由**：媒体经新增 `ROUTE_LIB_ASSET = '/canvas-studio/library'` 提供（`routes.ts`，形如 `/library/<assetId>/<file>`），复用现有 loopback + same-origin + 路径穿越校验；**不复用** `ROUTE_ASSETS` 的 `/<projectId>/<file>` 形状（避免引入虚拟项目 `_library` 的歧义）。

### 3.2 `assets-library.json` schema

```ts
// 新增 src/contracts/asset-library.ts
export const LIBRARY_SCHEMA_VERSION = 1
export type LibCategory = 'character' | 'scene' | 'prop' | 'group'

/** 库条目引用的一个画布锚点（允许跨项目）。 */
export interface LibAnchorRef {
  projectId: string
  nodeId: string
}

/** 库条目的一份媒体（文件落在 library/<assetId>/ 下）。 */
export interface LibMedia {
  /** 库内文件名，如 m_0.png；HTTP 访问 /library/<assetId>/<file>。 */
  file: string
  kind: 'image' | 'video' | 'audio'
  label?: string            // 如「正视图」「侧视图」
  contentHash?: string      // 去重（对应节点 contentHash）
}

export interface LibraryAsset {
  id: string                // UUID，@ref 句柄 `lib:<id>` 的 id 段
  schema: number            // = LIBRARY_SCHEMA_VERSION，条目级版本
  category: LibCategory
  name: string              // 主名称（自然语言引用的主键）
  aliases: string[]         // 别名/外号（「女主」「Luna」）
  description: string       // 描述：自然语言匹配 + 列表副标题
  tags: string[]
  media: LibMedia[]         // 封面 = media[0]（或显式 coverFile）
  coverFile?: string
  anchors: LibAnchorRef[]   // 来源画布锚点（正/侧/背/全身），用于溯源与再生
  lockedPrompt: string      // 冻结 SAME 块（沿用 StudioAsset 语义，可空）
  negativePrompt?: string
  sourceProjectId?: string  // 首次入库的项目
  usage: { projectId: string; nodeId: string }[]  // 被哪些画布节点引用（回写）
  createdAt: number
  updatedAt: number
}

export interface AssetLibraryDocument {
  version: number           // = LIBRARY_SCHEMA_VERSION
  assets: LibraryAsset[]
}
```

**写入策略**：整体读-改-写 + **根级 JSON 合流保护（磁盘 ∪ 内存 + 墓碑）**——照抄 `commitRegistry`（`projects.ts:755-795`），**不能照抄 `writeCanvas`**（其合并保护是节点级，对另一个根级 JSON 无效；朴素读-改-写会被第二个共享同一 DSH home 的实例抹掉新条目，见 §8-B）。写操作全部走 Host 单一入口（客户端不直写文件）。

### 3.4 跨项目引用的文件解析（关键难点）

`resolveRefValue`（`host-tools.ts:628`）现状：`@ref` → 读当前项目 `canvas.json` → `promoteAssetFile` → Drama filename。库引用需**三段式**：

1. **解析**：`lib:<id>` → `AssetLibrary.get(id)`；
2. **物化**：`promoteAssetFile`（`generate.ts:848`）**只从 `registry.assetsDir(projectId)` 读盘**，够不着 `library/<assetId>/` ⇒ 必须先新增「库文件 → 当前项目 `assets/` 拷贝」一步（文件名需过 `/^[A-Za-z0-9._-]+$/` 校验），再走 `promoteAssetFile` 的 Drama 注册 + `reference-manifest.json` 路径；**不是**「复用 promoteAssetFile 做拷贝」（§8-C）；
3. **去重**：物化前按 `contentHash` 查当前项目已有文件，命中直接复用（`contentHash` 在 **`StudioCanvasNode`**（`contracts/canvas.ts:238`）而非 `StudioAsset`，取值从锚点节点读——v1 勘误）；
4. **usage 回写**：成功解析后把 `{projectId, nodeId?}` 记入 `LibraryAsset.usage`（用于「被引用处」展示与防误删）。

**`lib:` 分支的精确插入点与旁路清单**（v1 只写「统一先过 lib: 分支」，实测改动面如下，详见 §8-D）：

| 调用点 | 现状 | 处置 |
|---|---|---|
| `resolveRefFilenames` 循环内（`host-tools.ts:583`，`findNodeByRef(pool, token)` **`:590` 之前**） | 未命中即抛 `CS-USER-001` | **主分支插入点** |
| `resolveRefValue`（`:628`） | 无 `@ref` 的裸值**原样返回** ⇒ 裸 `lib:x` 今天会穿透到后端 | 分支需同时拦裸值形态 |
| `resolveCutAudioSource`（`:258`） | 完全独立链；`PLAIN_ASSET_NAME_RE` 不含 `:` 会误报「画布上没有可引用的节点」 | 单独加分支 |
| `resolveAnchorNodeId`（`:663`） | 未命中返回 null → warning | 单独加分支 |
| 其余 | `resolveRefValue` 直调 8 处 + `resolveRefValues` 6 处（共 15 处经 `resolveRefValue`） | 集中在上述分支内拦，不逐点改 |

### 3.5 `@` 提及与 chip 管道

- `reference-source.ts` 新增 `LIB_ASSET_SOURCE = 'lib-asset'`，分区标题「**资产库**」；**技能目前是 `trigger:'/'` 的独立 source（`reference-source.ts:248`），不在 `@` 下**——「三区」是否成立见 §8-E（开放问题 #5）；
- **source 注册硬约束**：`order` 取 **`-2`**（排在 canvas-asset `-1` 之前 → 资产库 / 画布素材 / 工作区文件）；分区标题必须 `showGroupTitle:false` + 每个候选项带 `section:'资产库'`，否则会把内部 id `lib-asset` 当标题显示（上游 `MenuView.tsx:84-95`）；注册必须走 `registerSourceWhenReady` 轮询（`reference-source.ts:216`），直接 `ctx.get` 会静默拿不到；`name` 在同 trigger 内唯一，重复注册抛错；
- `serializeReference` → `formatRefToken('lib:' + id)` = `@ref[lib:<id>]`（codec 固定 `formatRefToken(ref)`，序列化零改动）；
- 显示名用 `asset.name`（chip 上显示中文名，序列化仍是 `lib:` 句柄——显示与模型文本解耦，同现有 codec 设计 `reference-source.ts:143-146`）；
- **候选取数**：`activeAssetHandles()`（`client/index.ts:406`）目前只读当前项目节点；扩展为「当前项目画布素材 + 全局库条目（四分类）+ 技能」，库条目来自 `libraryList()` 缓存；注意 `AssetHandle.kind` 仅 `'image'|'video'`（`reference-handle.ts:21-28`），audio/text 装不下——首期按 §8-I 只保证 image；
- chip 的 occurrence 对账在上游 `machine.ts:214-228`，**owner 无关**，新 source 自动获得「prompt 修改不丢失」（**验收③由此天然成立**）；该文件在 pinned submodule 内，**只依赖、不修改**（AGENTS.md 红线）。

### 4.4 核心流程

**F1 从画布注册入库**
1. 节点右键 / 详情抽屉 → 「**加入资产库**」（新增菜单项，挂 `CanvasContextMenu.tsx:103` 同级）；
2. 弹内联对话：选分类（四选一）+ 填名称/别名/描述（名称默认节点 title）；
3. Host `libraryImportNode(projectId, nodeId, meta)`：拷贝媒体 → 建 `LibraryAsset`（`anchors=[{projectId,nodeId}]`、`contentHash` 去重）；
4. toast「已加入资产库 · 角色」。

**F2 `@` 引用（对话输入框）**
1. 输入 `@` → 菜单弹出「**资产库**」「**画布素材**」两区（技能在 `/` 下，是否并入 `@` 见开放问题 #5）；
2. 键入过滤（按 name/aliases/tags）→ 选中 → 插入 chip「女主」；
3. chip 周围增删文本、删除邻居 chip → 本 chip 不丢（occurrence 对账）；
4. 发送 → 序列化为 `@ref[lib:8f3a…]`；**气泡显示降级为已知限制**：上游 `projectUserText`（`MessageItem.tsx:156-213`）会把 token 渲染成 `ref[lib:8f3a…]` 形态，显示中文名需改 submodule 渲染层（禁改）——v1 不承诺「气泡显示『女主』」，chip 上仍显示中文名（§8-G）。

**F3 自然语言引用**
1. 用户：「用女主那张侧脸和雨夜巷弄出一版分镜」；
2. system prompt 库清单 + `list_references.library` 让 agent 定位 `lib:` id；
3. agent 工具参数中逐字写 `@ref[lib:…]` → `resolveRefValue` → promote 进当前项目 → filename → 生成。

**F4 删除/防误删**
- 删除库条目时检查 `usage`：非空 → 二次确认「已被 5 处引用，删除后这些引用将失效」；
- **失效引用标记降级**：原方案依赖上游 `set-invalid` 机制，但该事件在全仓**无生产侧 dispatcher**（facade 不暴露，仅测试可达）⇒ v1 降级为「提交时 codec 报错 → toast 提示 + chip 保留在草稿」（`facade.ts:456-500` 既有语义），不承诺输入框内联标红（§8-G）。
