# 中文文字渲染生图（`txt2image_withtxt`）取证报告

**日期**：2026-09-30 ｜ **后端**：`117.50.108.73:8082`（无鉴权、单任务串行）
**触发**：CV-270「接入后端 0.8.0 新端点 `txt2image_withtxt`（Qwen Image 2.1，中文海报 / 文字渲染特化）」—— 接线前确认耗时、产物纪律与错误形态，决定超时档位与工具描述口径。
**结论一句话**：**通道全通**（纯文生直打 200 / 20.8s，中文片名四字无一错字、版式符合描述）；**耗时约为文档示例的 2.4 倍但仍远低于 image 档 180s**，超时档位无需调整。

## 二、由探针直接决定的实现选择

| 选择 | 依据 |
|---|---|
| **超时维持 image 档 180s**（不另立档） | 实测 20.7s ≈ 文档示例 8.50s 的 2.4 倍，但距 180s 余量充足；steps=25 的最坏波动可覆盖 |
| **无需上传句柄、无文件名纪律问题** | 纯文生：入参只有 `prompt`/`width`/`height`；端点**没有文件入参**，CV-155「产物名不可直接入参」纪律在此不触发 |
| **`duration` 口径同既有结论** | 20.67 ≈ HTTP 墙钟 20.8s ⇒ 仍是「服务端生成耗时」，非媒体属性 |
| **工具描述强调「画面里有要读的文字」判据** | 探针证实其价值就在文字正确性；普通无字图走 `image_generate`（Krea2，steps=8，更快） |
| **422 可原样透传给模型自纠** | `loc` 精确指到 `body.prompt`，与既有「422 字段名可回显」结论一致 |

## 三、与后端 0.8.0 文档的两处出入（以实测为准）

1. **耗时**：文档示例 `duration: 8.50`，实测 **20.67**（同参数量级、同尺寸）。文档示例偏乐观，超时档位按实测留裕量。
2. **产物名形态**：文档示例 `Qwen_image_2.1_00001_.png`（序号前带下划线），实测 **`Qwen_image_2.1_00020.png`**（无尾下划线）。ComfyUI 命名模板不定式，前缀 `Qwen_image_2.1_*` 可作识别依据，尾缀样式不作承诺。

## 四、可直接复现的命令

```bash
# 探针 1：健康检查
curl -s http://117.50.108.73:8082/api/v1/health

# 探针 2：中文海报生成（约 20s，占后端单任务槽位）
curl -s -X POST http://117.50.108.73:8082/api/v1/generate/txt2image_withtxt \
  -H 'content-type: application/json' \
  -d '{"prompt":"一张中国武侠电影海报。片名《剑归江湖》用大字竖排在画面右侧，中央是白衣剑客的背影，冷峻水墨风格，4K，高清","width":1024,"height":768}'

# 探针 3：取回产物（换上一步返回的 filename）
curl -s "http://117.50.108.73:8082/view?filename=Qwen_image_2.1_00020.png" -o poster.png

# 探针 4：422 校验（快失败，成本≈0）
curl -s -X POST http://117.50.108.73:8082/api/v1/generate/txt2image_withtxt \
  -H 'content-type: application/json' -d '{"width":1024}'
```
