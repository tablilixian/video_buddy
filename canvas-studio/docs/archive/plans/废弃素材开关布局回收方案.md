# CV-244 · BUG-004 废弃素材开关的布局回收（隐藏不留洞、显示不叠压）

> **日期**：2026-09-27
> **BUG-004**：关「废弃素材」后，画布 UI 布局调整不明显，仍旧为废弃素材留有大量空间。
> **现状核查**：隐藏方向已有部分修复（`onToggleHideRetired` 开启隐藏时
> `autoArrange(可见 ids)` + fit），但重排仍留洞；显示方向完全没处理。

## 1. 根因（两个精确缺口）

### 缺陷 A：隐藏后重排仍留洞
`autoArrange` 内部是 `computeArrangeLayout(全部节点)` 再只对可见子集**应用**坐标：
- `retired:true` 的旧版本节点（视频重试时 `shot-versions.ts` 置标）**照常参与**
  行/槽位分配（行分配循环只跳过 `isSuperseded` 单元）——隐藏后这些槽位全是空洞；
- superseded 链钉扎会把取代者所在行**额外加高**（`rowHeights += height +
  ARRANGE_SUPERSEDE_GAP`）——隐藏后加高的空间也是洞。

### 缺陷 B：显示方向零处理
关闭隐藏 = 重新显示废弃素材时什么都不做——retired 节点带着**隐藏前的旧坐标**
回来，而可见节点已重排到新位置 → 新旧互相叠压，画布乱。

## 2. 方案

| 改动点 | 内容 |
|---|---|
| `canvas-view.ts` `computeArrangeLayout` | 加 `options.only?: ReadonlySet<string>`：只对子集计算排布（隐藏节点不占槽位、不撑行高、不参与钉扎加高） |
| `project-store.ts` `autoArrange` | 加第 5 参 `options?: { layoutOverVisible?: boolean }`：开启时以可见子集为排布输入；托盘 tidy 的成员表同样只取可见成员（组框不跟着隐藏成员的旧坐标跑） |
| `StudioFrame.tsx` 隐藏方向 + 整理按钮 | `hideRetired` 时传 `layoutOverVisible: true`（两处） |
| `StudioFrame.tsx` 显示方向 | 关闭隐藏时**对称触发 `autoArrange(全部节点)`** + fit——retired 节点按既有规则归位（钉在取代者正下方），不再叠压 |

**设计取舍**：显示方向选「对称重排」而非「快照恢复」——重排是开关的既有语义
（隐藏方向已如此）；快照恢复会与隐藏期间的手动拖动互相打架，复杂度高收益低。
代价：切换开关会重置手动摆位（与隐藏方向现状一致）。

## 3. 自测与验收
- 单测（`canvas-arrange.test.mjs` 风格，纯函数直连）：
  ① `retired` 节点夹在两个可见节点之间 → `only` 模式下不留中间槽位（两可见节点相邻行）；
  ② superseded 钉扎 → `only` 模式下取代者行高不加高、被删单元不进 positions；
  ③ 不传 `only` 行为逐字节不变（回归）。
- 真机验收：
  1. 有多个重试旧版本（retired/superseded）的画布 → 开隐藏 → 布局紧凑无空洞；
  2. 关隐藏 → retired 节点按序归位（钉在取代者正下方），不与可见节点叠压；
  3. 隐藏态下点「整理布局」→ 同样紧凑无洞；
  4. 无 retired 的画布：开关与整理布局行为与之前完全一致（回归）。
