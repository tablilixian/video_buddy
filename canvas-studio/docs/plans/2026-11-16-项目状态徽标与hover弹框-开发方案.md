> 日期：2026-11-16 ｜ 状态：**已落码（CV-467，2026-11-16 验证链四步全绿，待桌面验收）**
> 效果演示（已确认的视觉基准）：[`docs/demos/2026-11-16-项目状态徽标与hover弹框-demo.html`](../demos/2026-11-16-项目状态徽标与hover弹框-demo.html)

## 一、背景与目标

侧栏项目列表目前只有「副行文案 + 相对时间」，用户无法一眼回答三个问题：

1. 哪个项目**正在跑**？
2. 哪个项目**在等我决策**？
3. 哪个项目**刚刚出结果**？

参考主流 harness（Claude Code Agent View / Cursor Cloud Agents / Claude Desktop / GitHub Copilot）收敛出 **6 态模型**，在项目行上加**状态徽标**，行 hover 时浮出**详情弹框**。视觉效果已通过独立 HTML 演示页与用户确认（两轮反馈均已落地：徽标去文字、加弹框）。

## 二、已定稿的设计（用户已确认，不再讨论）

### 2.1 六态模型与排序

| 状态 | 触发时机 | 徽标视觉 | 弹框补充信息 |
| --- | --- | --- | --- |
| `waiting` 待你决策 | 权限确认 / 向你提问 / 决策点 | 琥珀呼吸点 + 已等待时长；行左侧琥珀标 + 微底色，**永远置顶** | 状态文案 + 问题原文 |
| `running` 执行中 | agent 正在生成/跑工具 | 蓝色呼吸点 + `mm:ss` 计时 | 进度条 + 百分比 + 计时 |
| `failed` 失败 | 出错结束（终态） | 红叹号 + 相对时间 | 失败原因 |
| `just-done` 刚刚完成 | 完成后的短时间窗 | 绿勾弹入动画 + 「刚刚」 | 成片就绪信息 |
| `done` 已完成 | 任务成功结束（终态） | 淡绿勾 + 相对时间，视觉退后 | — |
| `idle` 空闲 | 被停止 / 无事可做 | 灰暂停图标 + 相对时间，不打扰 | — |

排序权重：`waiting > running > failed > just-done > done > idle`，同状态内按 `updatedAt` 倒序。

### 2.2 两条用户拍板的硬约束

1. **徽标只含「图标 + 时间」，零文字** —— 状态文案全部收进 hover 弹框，为国际化留空间。图形（呼吸点/勾/叹号/暂停）跨语言可读，时间是数字，两者都不需要翻译。
2. **hover 弹框** —— 鼠标移入行即浮出（标题 + 状态胶囊 + 环境/目录/分支/更新时间/规格 + 状态专属行），移开即消失；纯展示（`pointer-events: none`），不拦截鼠标。

### 2.3 其它已确认的行为

- 段头计数摘要（`N 等你 · M 执行中 · K 失败`，图标+数字同样零文字），变化时闪烁一下。
- `just-done` 是瞬态：真实产品 **5–10 分钟**后回落为 `done`（演示页用 12 秒仅为展示）。
- running/waiting 的徽标时间每秒跳动（计时器），done/failed/idle 用相对时间（分钟级刷新即可）。

### 4.2 状态数据来源（本方案最大的缺口）

现状 wire 上**能直接推导的**只有：

- `waiting` ← `workflow.pendingQuestion != null` ✅ 零改动
- `idle` / 时间线 ← `updatedAt` ✅ 零改动

**推不出来的**（需要新信号，落码前须拍板方案）：

| 状态 | 缺口 | 可选方案 |
| --- | --- | --- |
| `running` | agent 会话只在**打开的项目**里跑，列表是全局的；生成队列（`generate-queue.ts`）是全局的、不带 projectId | A. 一期只对「当前打开的项目」显示 running（客户端本就知道 turn 在飞）；B. Host 侧按项目记「最近一次 run 活跃」并随 `registry.list()` 下发（需新字段） |
| `failed` | 无持久化的「最近一次 run 结果」 | 新字段 `lastRun: { status, endedAt, reason? }`，由 run 结算点写入（找 conversation/工具结算的统一落点，别加轮询） |
| `just-done` / `done` | 同上，完成时刻无记录 | 同上，`lastRun.status='done'` + `endedAt`；瞬态由客户端按 `endedAt + 5~10min` 推导，**不落瞬态字段** |

**推荐路径**：一期先落 **零契约改动**的部分（waiting 高亮置顶 + 段头计数 + 徽标框架 + 弹框 + idle/done 时间线），`running/failed/just-done` 用 `lastRun` 新字段二期接（字段设计见 §6 任务 T5）。这与 Cursor 的「双层状态」结论一致：项目状态由**最近一次 run** 推导，项目本身不发明状态。

### 4.3 仓库硬约束（踩过的坑，逐条对照）

- **纯函数放 `src/*.ts`，不放 `src/client/**`**（Host tsconfig 排除 client，放进去测不到）。状态推导 `projectStatusOf(project, now)` 必须是 `src/` 下的纯函数，`node --test` 直连。
- **`styles.ts` 行数棘轮**：`file-size-guard.test.mjs` 登记 `styles.ts: 11157`、`STUDIO_STYLES: 11140`，余量 `RATCHET_SLACK=300`。加样式超余量即红 → **同批在守卫里显式上调登记值并写 note**（先例：CV-444 +15 补登）。
- **client 引用新根级模块须显式追加 `tsconfig.client.json` include**，否则编译过但类型解析不到。
- **弹框定位逃不出 overflow 裁剪**：`.csProjectsScroll` 有 overflow，弹框必须 `position: fixed`（照 ProjectRowMenu 的 anchor 模式），渲染在列表末尾做单例。
- **键盘可达**：行是 `role="button"`（CR-053），弹框需支持 focus 显示（`onFocus/onBlur` 与 hover 同源），别只做鼠标。
- **一个时间基准**：列表级 `const now = new Date()` 传给所有纯函数（DD-08/R3），别逐行 `new Date()`。
- **UI 可见性判定与执行侧前置检查共用同一纯函数**；非幂等入口加状态守卫。

## 五、实施步骤（建议切分）

> 每步独立可验证；T1–T4 为一期（零契约改动），T5 为二期（新字段）。

- **T1 状态推导纯函数** `src/project-status.ts`
  `projectStatusOf(project, now, ctx?) → { state, since, label, detail? }`；`ORDER` 权重表、`badge` 图标选择、相对/计时格式化全在这里。附 `tests/project-status.test.mjs`（六态推导 + 排序权重 + 瞬态回落边界）。
- **T2 徽标渲染**（`ProjectList.tsx` + `styles.ts`）
  行右侧新增徽标列：呼吸点/勾/叹号/暂停 SVG + 时间，**零文字**。running/waiting 每秒刷新（客户端 `setInterval` 只在存在 running/waiting 行时启动，行数归零即清）。
- **T3 hover/focus 详情弹框**
  单例 `fixed` 弹框，`mouseover/focusin` 显示、`mouseout/focusout` 隐藏；位置贴行右侧、放不下翻左侧、视口夹紧（demo 的算法可直接移植）；内容按状态分派（进度条 / 问题原文 / 失败原因）。
- **T4 waiting 置顶高亮 + 段头计数**
  `project-sections.ts` 桶内排序改「状态权重优先、同权重 updatedAt 倒序」（头注同步改，排序口径仍只有一处）；waiting 行左琥珀标 + 微底色；段头计数 `N等你·M执行中`（图标+数字）+ 变化闪烁。
- **T5（二期，需拍板）`lastRun` 字段**
  契约 `lastRun?: { status: 'running'|'done'|'failed'; startedAt?: string; endedAt?: string; reason?: string }` + `normalizeLastRun` 宽松解析 + Host 侧 run 结算落点写入 + `registry.list()` 自动带出；客户端据此点亮 `running/failed/just-done/done`。**瞬态不落盘**，`just-done = status==='done' && now-endedAt < 5~10min`。
