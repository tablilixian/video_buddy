## 1. 批次 A · 让三期能力真正生效

### O-01 · `render_composition` 的 `frames` / `report` 没进模型可见文本

| 项 | 内容 |
|---|---|
| **现象** | 标准档渲染返回全文仅 357 字符，只有 url + 「纳入 15 段」+ ML-10 警告；`frames[]` 与 `report{}` 一个字都没有 |
| **证据** | 抽帧**确实跑通了** —— `assets/` 里 14:38:31 一次性落 8 张 png，与 `pickSampleFrames`「4 均匀 + 转场中点，上限 8」完全吻合 |
| **根因** | `host-tools.ts:2621-2623` / `:2628` 把 `frames` / `report` 塞进了 payload，但 `host-tools.ts:321-339` 的 `renderComposeResult` 只拼 `url + 段数 + 音轨 + warnings` ⇒ **schema 里有、文本渲染没写** |
| **连带** | 工具描述 `host-tools.ts:2489` 明确承诺「返回里有 frames[]/report{}，先看这几张图再汇报」—— 承诺与实现不一致，直接误导模型（它随后去 `ls assets | grep frame`、翻 `/var/folders` 与 `/tmp`，最后自己用 ffmpeg 重抽 9 张） |
| **修法** | `renderComposeResult` 补两段（`compose_video` 无这两字段时自动跳过）：① 逐行列出抽帧 url 与帧号；② 一行报告 `quality / 帧数 / 秒数 / msPerFrame / encodeMs / bytes / bitrate / warm` |
| **验收** | 断言返回文本**含每个 frame 的 url** 且 **含 `msPerFrame`** —— 纯字符串断言 |
| **反向变红** | 注释掉新增的两段 → 断言必须红 |
| **不变量** | 这一条补完，W6 闭环（先看抽帧再汇报、按 msPerFrame/warm/lint 决策）才真正成立 |

### O-02 · ML-10 对素材驱动片恒误报，会训练 agent 无视体检

| 项 | 内容 |
|---|---|
| **现象** | 连续 **7 次**渲染都报「动效覆盖仅占轨道总时长的 2%」，一次没消失 |
| **根因** | `motion-lint.ts:253-264`：分子只累加 `animate/exit/fade/draw`，分母把**所有轨**算进去。本次分母 ≈2321 帧（bg 600 + 三镜 465 + 波形 600 + 文字卡 656），分子 ≈116 帧 ⇒ 恒 5%，永远 `< 0.3` |
| **真正危害** | 不是这一次误报，而是**一条永远为真的提示 = 噪声**。这次 agent 正确忽略了它，代价是**学会了忽略 lint** —— 下次真出现 ML-02 这类硬问题也可能被一起跳过 |
| **修法**（三条都做，成本都极低） | ① 分母排除 `video` 轨（视频本身在动，不该要求 animate）；② 分母排除「常驻装饰轨」（满画布 `shape` 背景、整片长 `audioViz`）；③ 兜底：`video` 轨帧占比 > 40% 时直接不判 ML-10 |
| **验收（双向）** | 拿本次真机 manifest 断言 **ML-10 不出现**；再拿一份纯静态图文 manifest 断言 **ML-10 仍出现** |
| **反向变红** | 把分母改回"全部轨" → 第一条断言必须红 |

### O-03 · 契约文档的 `box` 示例是错的（照抄得四分之一底）

| 项 | 内容 |
|---|---|
| **现象** | agent 照抄 `manifest-contract.md:218-226` 的 `box:{x:0,y:0,w:100,h:100}`，片头卡大面积纯黑，白跑 2 次渲染 + 一轮取色排查 + 一次 VL 误判 |
| **根因** | `Shape.tsx:109-126` 是 `left: box.x%` `top: box.y%` + `transform: translate(-50%,-50%)` ⇒ **x/y 是形状中心**。`0,0` 只铺左上四分之一 |
| **实测取证** | 同一帧 0.6s、`crop=8:8` 均值：`(20,20)` 处 `box 0,0` = `4 2 0` vs `box 50,50` = `33 15 8`；`(300,20)` 处 `0 0 0` vs `20 10 4` |
| **修法** | 示例改 `{"x":50,"y":50,"w":100,"h":100}`，说明改成「`x`/`y` 是形状**中心**，`w`/`h` 是宽高，均按画布百分比；铺满全屏用 `50,50,100,100`」。**可选**：`box` 中心落在画布外时给 warning |
| **验收** | 文档示例字符串断言 + 一条几何测试：`box 50,50,100,100` 的渲染矩形等于全画布 |
| **反向变红** | 把示例改回 `0,0` → 字符串断言红 |

### O-14 · skill 第 8 步没覆盖「字幕是否需要配音」

| 项 | 内容 |
|---|---|
| **现象** | 用户第一句反馈就是「除了音效，没有听到念台词的声音」；TTS 直到第 88 次调用才出现 |
| **代价** | 多 1 轮渲染 + 3 次 TTS + 3 次重做 + 后处理 ≈ **30 分钟** |

| **验收** | 断言 SKILL.md 第 8 步段落含「配音/旁白是否」这一问 |
| **注意** | 总纲有 **11KB 硬闸**（实测 10,235B）⇒ 加字前先看余量，必要时压缩同段落 |

## 2. 批次 B · 后台渲染（RenderHost）

> **背景**：用户已拍板 —— D1 **不接受 +250MB**（⇒ SSR 出局）、D2 **不改 dsh**、D3 **单条串行 + 进度条**。
> **核心事实（v1 判断已被推翻）**：Canvas Studio 的 Host 与 Electron 主进程**同进程**（`dsh-plugin-desktop/src/main.ts:840` 同文件 `await boot(...)`），且 Electron **43.4.0** 有运行时 `webContents.setBackgroundThrottling(false)`（`electron.d.ts:18463`）⇒ **零 dsh 改动**。

### O-04 · S0 spike：四个必须回答的问题（决策闸）

| # | 问题 | 验法 | 不通过怎么办 |
|---|---|---|---|
| Q1 | Host 侧 `import('electron')` 能解析吗 | 在 host 插件里 `createRequire(import.meta.url)('electron')` 后打 `app.getVersion()` | 三级退化：`createRequire` → `process.mainModule.require` → `ctx.desktopRuntime` |

### O-06 · 执行者切换 + 心跳 + 超时口径

| 项 | 内容 |
|---|---|
| 契约 | **一改不改**：`pendingRenderJobFor` / `reportRenderJobProgress` / `recordRenderSample` / `commitRenderJob` / `cancelRenderJob` 全复用，只换「谁来取单」 |

### O-07 · 主窗口关节流（可选、便宜）

渲染期间对**主窗口**也 `setBackgroundThrottling(false)`（引用计数，结束即恢复）。只解决「用户留在画布页、但窗口被盖住」这类浪费，不解决页面被卸载 —— **不要把它当 RenderHost 的替代品**。

## 3. 批次 C · 能力缺口（需单独设计）

### O-08 · `startAfter` 与 `transition` 语义互斥

- **代码事实**：`normalize-timing.ts:85` 与 `manifest.ts:947` 都强制 `gapFrames >= 0`；`normalize-timing.ts:95` 是 `startFrame = 引用轨.startFrame + 引用轨.durationInFrames + gap`；而 `transition` 要求**两轨重叠**（首尾相接只会降级成硬切 warning）。
- **后果**：`startAfter` 只能产出「相邻」或「留空」，**产不出重叠** ⇒ 只要片子用转场，`startAfter` 就永远用不上（本次 9 次渲染 **0 次使用**，全部手算 65/210/355/500）。这与三期文档「6 幕用 startAfter 衔接，不要手算帧号」直接矛盾。
- **修法**：允许 `gapFrames` 为负，语义 = 「与引用轨**重叠** `|gap|` 帧」。`-10` 恰好等于 10 帧叠化窗口。比新增字段更小更自然，**只改两处校验的 `gap < 0` 判断**，解析公式不动。
- **同步**：`manifest-contract.md` 与工具描述补「要叠化就写 `gapFrames:-10`，与转场时长对齐」；`ML-06` 下限 6 帧要与重叠量对齐。
- **验收**：`-10` 解析出 `a.start + a.dur - 10`；归一后**删字段**（现有铁律）；带 transition 的 manifest 过校验。

### O-09 · `tts_voiceover` 没有音色/年龄/语速参数

- 用户连提两轮「要 60 岁沙哑」，最终靠 `ffmpeg` 降调 + `acrusher` 磨砂硬补，重试 2 轮。
- **修法**：至少给 `voiceId` / `speed` / `pitchSemitones`；短期先在工具描述承认「音色由文本引导，超出音域需后处理」，避免反复重试烧额度。

### O-10 · `audio.voiceOverUrl` 只支持单轨

- 本次 agent 自己用 ffmpeg 拼了 `voiceover-timeline-v4.mp3`（14.32s，三句按 2.60/7.07/11.90 落点）。
- **修法**：`audio.voiceOver` 支持数组 `[{src, startFrame}]`，宿主内部拼轨。**否则「多句旁白」永远要 agent 手搓 ffmpeg，而终端用户跑不了 ffmpeg。**

### O-11 · `qc_shot` 基准串味

- 手部微距被判 FAIL，理由出现「未呈现面部与发型」「与期望的中长焦中景交替、固定机位不符」—— 那是**另一镜**的语汇（`shotRefs:["分镜 1"]` 却用了 S2 的描述）。
- **修法**：QC 只取该镜自己的 `camera`/`shotSize`/`subject`；并允许镜头声明 `facesVisible:false`（微距/背影/空镜）跳过外貌核对。

### O-12 · 素材分辨率与交付分辨率无联动

- `video_composite` 三次都没传 `resolution` ⇒ 864×480，成片 1280×720 是上采样，白丢约 1.48× 细节。
- **修法**：`render_composition` 核对素材真实分辨率，低于成片 1.2× 以上给 warning，让 agent 有机会主动重出 736p。

### O-13 · 草稿成片每次都新增节点

- 7 次成功渲染 ⇒ 7 个 `video-composite` 节点并排（6 个 `draft:true`，各 0.9–1MB），无 `replaces` 关系，用户要手工清，画布随迭代线性膨胀。
- **修法**：同项目内 draft 成片默认「后一版替换前一版」，或折叠为一个「成片版本组」。
