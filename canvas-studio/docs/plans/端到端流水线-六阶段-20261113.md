# 端到端流水线 · 六阶段十四步 · 现状诊断与补强

> 本文回答一个问题：**用户的创意，到最终出片，到底经过哪些步骤，每一步起什么作用，哪一步现在是空的。**
> 定位：流程层的总览（对上：`视觉质量工程方法论-四件套闭环-20261113.md`；对下：`流程推演-45秒数据汇报-断点定位-20261113.md` 是本文 P3 阶段的实证）。
> 事实依据：`skills/canvas-studio-creation/SKILL.md`（总纲 §标准工作流）、`references/*.md` 分册、`src/host-tools*.ts`（工具注册）、`src/remotion/*`（校验与渲染），以及真机会话 `session-30385906`。

## 0. 六个阶段

```
P0 定题   → P1 定事实 → P2 定结构 → P3 定版面 → P4 出片 → P5 验收
路由/澄清    摄取/核验    拍摄定稿     屏表/编排     渲染/抽帧    交付/质检
```

判据不是「跑得通」，而是**每一步都有可检查的产物**：产物断了，后面所有步骤都会自己发明一套（真机里那一套叫 `gen_specs.py`）。

## 2. 逐阶段诊断

### P0 定题（第 1–2 步）：做得最好的两段

**作用**：把「一句人话」变成一份可审计的制作决定，且**只打断用户一次**。

**为什么算好**：有字段（`explicit / inferred / conflict / needsUser / defaults` + 必含 `structure`）、有预算（阶段一 ≤5 个模型步）、有留痕（结论落 `write_note` + `§00.brief` + `facts[]` + `constraints[]`）。真机 45s 会话里第 101 步一次 `confirm_intent_card` 就定完，没有出现历史上「5 次提问全选推荐、零信息增益」的空转。

**唯一的债**：`structure` 字段能记录「选了模板还是自由编排」，但**判据口径错**（见第 9 步）。

### P1 定事实（第 3 步）：字段齐了，工具没跟上

**作用**：整条链路的**准确性第一道闸**。数据说错，后面版面再美也是废片。

**现状**：`§01` 的契约很完整（`claim / source / status / 未采用值` 都留痕，`pending` 在 seed 时被显式丢弃）。但**摄取工具只有 `import_csv`**（CSV → chart 的 `{labels, values}`），网页 / HTML 内嵌 JSON / 表格页没有入口。

**真机怎么办的**：`bash python3` 手搓正则抽 `ALLDATA`（seq 29/36/331–351，六次），模型自己保证「数字逐一取自快照，不编造」。**结果没错，但不可复用、不可校验** —— 换一个页面就得重写一次正则。

**为什么该补**：这是「同一种错误形状反复出现 ⇒ 缺原语」的典型。补的不是 prompt 纪律，而是一个 `extract_source(path)` 原语：HTML/CSV/JSON → `§01 facts[]` + `data-provenance` 血缘，让 §2.4 的四个硬缺陷（数字与旁白打架）有机械拦截点。

### P2 定结构（第 4–8 步）：契约最稳的一段

**作用**：把创意变成「可拍摄 / 可排版」的规格，并锁定声音。

**为什么算好**：
- 九节契约 + **分节合并**语义，让「分四笔写」不会互相冲掉；`awaitingLanding` 把「写完」和「能不能落」分开，Host 侧用阻断项计数收口 —— 这是「停止指令不能只靠提示词」的正确做法。
- 声音规划**前置**（不是渲完再配）：`voiceOverNodeIds` 起点 = 镜头起始秒 + 入点留白，禁止模型自己算 ffmpeg；BGM 时长铁律有梯度表。

**待增强的是执行端**：真机 8 次 `tts_narration`（逐句，正确）+ 4 次 `music_generation` + 3 次 `media_probe` 才拿到够长的 BGM（300s 不够 → 330s → 循环拼接 → 手动覆盖资产）。**BGM 与成片时长的动态耦合没有闭环**：`music_generation` 不知道成片多长就生成了，只能靠人肉重试。补法：生成前先算 `预计成片时长 + 余量`，不足时自动 `cut_audio` 循环铺满（`cut_audio` 已存在，缺的是决策规则）。

### P3 定版面（第 9–12 步）：断点在这里

**作用**：把「讲什么」（定结构）翻译成「怎么摆在画面上」。这是**唯一决定「单调 vs 有层次」的阶段**。

**为什么断**：三层结构资产粒度全错位 ——

| 资产 | 粒度 | 为什么接不上 |
|---|---|---|
| 10 个模板（2.5–48s） | 屏 | 一次只出一屏，`templateId` 与 `durationSeconds` 互斥，落不到时间轴某一段 |
| 4 个配方（`recipes.ts:58`） | 段 | `planRecipe` 永远切 4 段：45s→11s/段，304s→76s/段 |
| `CompositionManifest` | 轨 | 自由，等于把版面决策全丢给模型 |

中间缺「屏（stage）」这一层，于是第 10 步空着，第 11 步只能给 3 轨骨架（`skeleton.json`：全屏渐变 + 标题卡 + 落版卡，737 字节），模型只能自己发明一个私编排器（`gen_specs.py`，29KB，7 个硬编码盒常量，102 次 bash）。结果：45 秒里 **23 秒整屏只有 1 个元素**。

**第 12 步的连带失效**：ML-01…ML-15 全查「元素内部与外部的时序」（动画太短/太长/一起冒出来/硬切消失/字幕超行/叠字），**没有一条问「这屏上有几个东西」**。所以 337 条 ML-02 会刷屏，而「画面空了一半」一条警告都没有。

### P4 出片（第 13 步）：工程上最扎实的一段

**作用**：把 JSON 变成 H.264，且**出错要说人话**。

**为什么算好**：
- 时长自洽硬校验（`meta.durationInFrames` = 最大结束帧）挡住手写 JSON 的第一大死因；
- `manifestPath` 通道解决 30KB 内联截断；
- 三档 quality + 草稿就地替换（不堆节点）+ `probe` 不落盘；
- 返回 `frames[] + report{} + 工单：…`，把「谁认领、有没有出首帧、msPerFrame」还给人。
- 真机 37 次渲染，**零次因契约失败卡死**。

### P5 验收（第 14 步）：有交付，缺判决

**作用**：判断「这片能不能发」。

**现状**：交付纪律很清楚（便签 + 1–3 行结论 + 无 `present` 类工具）。但**判决依据全靠模型自己挑帧看**（37 次 `read_image`），没有客观回读：同屏元素数、内容包围盒、静止段占比都算不出来，所以「单调」只能由用户肉眼看出来 —— 上一轮 5 分钟片就是这么被发现的。

## 3. 三档结论

### 做得好（4）
| 步 | 好在哪（可复用的机制） |
|---|---|
| 2 意图卡 | 字段级确认 + 轮次预算 + 裁决留痕。**可复用到任何「需要一次问清」的场景** |
| 4–5 拍摄定稿 / 落地 | 九节契约 + 分节合并 + `awaitingLanding`（停止指令落在 Host 而非 prompt） |
| 7 声音规划 | 声音前置，BGM 有预算表而不是「配个 BGM」 |
| 13 渲染 | 硬校验 + 双通道 + 三档 + 回执可诊断 |

### 待增强（5）
| 步 | 缺什么 | 归因（按判定法则） |
|---|---|---|
| 3 事实摄取 | 网页/HTML 无原语，靠 bash 正则 | 同一种错误形状 ⇒ **缺原语** |
| 8 声音执行 | BGM 时长与成片时长无闭环 | 缺**决策规则**（不是缺工具，`cut_audio` 已有） |
| 11 编排 | 三起点都只能出单屏 | 缺**原语**（屏） |
| 12 校验 | 只有动画维度 + 告警无上限 | 缺**判据** + 缺**抑制** |
| 14 验收 | 无客观回读（元素数 / 包围盒 / 静止比） | 缺**判据** |

### 缺失（1）
| 步 | 后果 |
|---|---|
| **10 屏表** | 后面所有步骤退化成「模型自造」，且不可复用、不可校验、不可审 |

**一句话**：这条链路「把想法写成规格」很强（P0/P2），「把规格渲成片」很强（P4），**中间「把规格排成版面」是空的**（P3 第 10 步），而且没有客观手段发现它空了（P5）。

## 4. 补强路线

### P0 · 版面层（唯一必须做的一档）

| 项 | 落点 | 判据 / 验收 |
|---|---|---|
| `planStages()` 纯函数 | 新建 `src/remotion/stage-plan.ts` | 45s→6–7 屏、屏长 5–9s、边界吸附 TTS 句起点；反向变异（6.5→20 必红） |
| `composeStages()` 组合器 | 新建 `src/remotion/stage-compose.ts` | 6 屏 → 一条 45s 成片；模板单元整组平移；卡接受 `cell`；**不新增轨类型** |
| 工具面 | `scaffold_manifest({ stages: "build/stages.json" })` 作第四起点 | 与 `templateId` / `recipe` / `title` 四选一互斥 |
| 版面判据 | `motion-lint` 加 ML-20（≤1 元素帧占比 >25%）、ML-21（无 carry 轨） | 喂 45s 真机 manifest 必报（51%）；喂手写 60s 必不报 |
| 模板口径 | `template-gate.ts:127` 拆 `stageSeconds` / `totalSeconds` | 45s 下 `three-cards`(36s) 仍拒、`ink-open`(9s) 通过 |
| 样例 | `references/screen-plan.md` + 一份真渲过的 6 屏屏表 + 3 张静帧 | 40KB skill 体积闸不破 |

### P1 · 事实原语（准确性第二道闸）

`extract_source(path)`：HTML（含内嵌 JSON）/ CSV / JSON → `§01 facts[]` + provenance。判据：同一份 `all-time.html` 抽出的 4 个关键数字与人工核对一致，且每条形如 `{claim, value, source, locator}`。

### P2 · 判据治理（让告警可处理）

- 告警**上限与聚合**：同类 ≥5 条合并为一条 + 计数（真机 337 条 ML-02 是无视告警的直接原因，方法论 §2 第 0 条已量化「告警有可处理量上限」）。
- ML-22（内容包围盒 <50%）：需 box 并集算法，收益低于 ML-20，排后。

### P3 · 声音闭环

BGM 生成前算 `预计成片时长 + 余量`；不足走 `cut_audio` 循环铺满（决策规则写进 `audio-first.md`，不新增工具）。

## 5. 度量：每阶段放行指标

| 阶段 | 指标 | 现状（45s 真机） | 目标 |
|---|---|---|---|
| P1 | 事实条目带来源比例 | ~100%（模型自觉） | 100%（工具强制） |
| P3 | 每秒非字幕元素 均值 | 1.71 | ≥4.0 |
| P3 | 只有 1 个元素的时长占比 | 51% | ≤15% |
| P3 | 屏长离散度（max/min） | 3.7× | ≤1.6× |
| P3 | 模板参与屏数 | 0 | ≥2 |
| P4 | 模型侧 bash 调用 | 102 | ≤15 |
| P5 | 客观回读项 | 0 | ≥3（元素数 / 包围盒 / 静止比） |

## 6. 判定法则（下次遇到新毛病怎么归类）

| 症状 | 该补什么 | 例 |
|---|---|---|
| 同一种错误形状反复出现 | **原语** | 每次都要手搓正则抽数 → `extract_source` |
| 错误随机分布、每次不一样 | **判据或闸** | 有时图表压左栏、有时数字打架 → ML-20 |
| 有工具但用不对/不用 | **样例**（1 个真渲过的参照物） | 有 `layout-recipes.md` 仍手算 `transform.scale` |
| 能跑但没人审 | **产物**（可 diff、可返工的中间件） | 屏表 |

## 7. 不做

- **不**重构 P0/P2/P4（它们是上表里唯一被评为「好」的三段，动它们等于把稳定的部分重新引入风险）。
- **不**用「更强的模型 / 更长的 prompt」替代缺的那一步 —— 方法论 §1 已证：有 lint 码的维度模型都修了，没码的维度一次都没碰。
- **不**新增轨类型（屏是编排层概念，产物仍是 tracks）。
- **不**回填历史 manifest（开发期只修产生路径）。
- **不**把模板从「屏级」改成「整片级」（那是把 10 个成品镜头改造成 10 个成片，收益低、复用性差）。
