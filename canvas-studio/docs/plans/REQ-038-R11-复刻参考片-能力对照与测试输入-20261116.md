## §2 能力对照（逐项，依据是本轮真机代码）

### ✅ 能对上（骨架与动效质感）

| 元素 | 我们的落点 |
|---|---|
| 竖屏 1080×1920 | `scaffold_manifest({ specPath, aspect: '9:16' })` —— **本轮刚修**，此前 spec 通道写死横屏且静默忽略 `aspect` |
| 近黑底 + 装饰 | 主题 `neon-data`（#05070A）；`dotGrid` / 径向光晕 / `vignette` 三件套每卡自带 |
| 眉标 | 所有卡自带 `eyebrow`（格式是「01 / 04 · 段名」） |
| 大标题 | `A1` 遮罩揭示 / `A2` 逐字打出 / `TYP1–TYP6` 压印·描边·渐变扫字等 6 种字效 |
| 数据行（涨跌配色） | `B1` 数据卡（`k:v; k:v` 行内格式 + `countUp` 数字滚动 + 每屏 `accentColor` 可覆盖） |
| 柱状图 | `DAT3` 图表生长 |
| 一屏「标题 + 主体」上下叠 | **spec 的 `units`（每屏 1–4 个单元，各带 `cell` 格位）** —— 单元 1 放 `y=22/24` 的标题，单元 2 放 `y=64/56` 的主体卡 |
| 序号列表（1/2/3） | `A4` 要点逐词落位（`bullets`） |
| 卡片堆叠对比 | `UI2` 卡堆展开 / `RHY4` 四分屏并行 |
| 时间轴 / 前后对比 | `DAT5` 时间轴飞行 / `DAT4` 前后对比拉杆 |
| 段级改一屏 | `patch_spec_section`（R11-B3） |

### ⚠️ 只能近似

| 参考片做法 | 我们的近似 | 差别 |
|---|---|---|
| 标题**按词换色**（「继续」橙 /「回来」青） | `textCard` 的 `label` 会以 accent 色渲染（0.62 倍字号） | 只能「一段高亮」，不能「两种颜色各一个词」 |
| 右上章节胶囊（描边圆角 + 文字） | `P3` 芯片条；或 spec 里放一个 `textCard` + 圆角 `shape` | 位置和样式要手工摆，不是卡自带 |
| 底部要点条（黑底块 + 单句） | `A4` 的 bullets / 单独一屏 `A2` | 没有「卡外独立强调条」这个原语 |

### ✅ 2026-11-16 当日补齐（原为缺口）

| 参考片做法 | 补齐方式 | 入口 |
|---|---|---|
| **折线示意图 + 标注气泡**（曲线 + 「高→卖」标签 + 长期均值虚线） | 新卡 **`DAT6`**：`chart variant:'line'` + 2 条 `callout`（峰/谷，带肘线）+ 均值虚线（`shape:'line'` + `dash`，本轮给 `line` 补了描边/虚线支持） | `card: "DAT6"`，copy = `标签:数值; …`，label = `标题 \| 高点文案 \| 低点文案` |
| **标题按词换色** | 契约新增 **`textCard.highlights`**（spec 侧 `sections[].highlights` / `units[].highlights`）；渲染按段包 span 并用 unit 偏移接续逐字节奏 | `highlights: [{ text: "继续", color: "#F5A623" }, …]` |
| **卡外要点条**（黑底圆角单句） | 新卡 **`A6`**（`label` = 上方标题可空，`copy` = 条上那句话） | `card: "A6"` |

### ❌ 仍做不到

| 参考片做法 | 缺口 | 代价 |
|---|---|---|
| **大号线性图标**（锚、手机、网络节点） | 无图标系统。`shape:'path'` 要手写 SVG path，模型写不对 | 只能用素材图（走 `E1`/`C2` 的图槽）或省略 |
| 卡片长宽比完全一致 | 56 张卡的 `box` 按 16:9 写死百分比，竖屏下偏方 | 见 §4 最后一行 |
| 真配乐 / 讲解配音对齐屏切点 | `tts_narration` + `stageBoundarySec` 吸附已有 | 可用，但第一轮建议先不配音，先看画面 |

### 结论（补齐后重估）

- **骨架 8/10**：竖屏、近黑底、眉标、大标题、数据卡、要点、动效节奏 —— 都能对上，出片气质会像。
- **表现层 7/10**：折线+标注、标题双色、结论条三件已到位；差的只有图标系统与卡片长宽比。
- 综合：**能做到「同系列、同气质、同款版式骨架」，剩下的是图标与卡形这两块**。

## §4 验收看点（对不上≠bug，先看这几条）

| 看什么 | 期望 | 若不对，说明什么 |
|---|---|---|
| 画幅 | 1080×1920 竖屏 | 还是 1920×1080 ⇒ `aspect` 没传到（本轮修复只在 `0094938a02` 之后） |
| 每屏元素数 | 标题 + 主体卡**同屏** | 只有标题没图 ⇒ agent 没用 `units`，可回它「用 spec 的 units 上下排」 |
| 标题与卡是否重叠 | 不重叠 | 重叠 ⇒ `cell` 的 y/h 没给对（告诉它「标题 cell y=22 h=24，主体 y=64 h=56」） |
| 底色 | 近黑 | 深蓝灰 ⇒ 主题没走 `neon-data` |
| 第 4 屏图表 | **柱状图** | 出折线 ⇒ 那是它手写 manifest 绕过了卡（我们会补折线卡，但这一轮不指望） |
| 全片一致性 | 6 屏同一套版式 | 每屏长得都不一样 ⇒ 密度/一致性体检要收（`density-audit` 已能提示） |
| 文案密度 | 每屏 20–40 字 | 全片不到 100 字 ⇒ 用 `targetStageSec: 4` 提密度 |
| **卡片长宽比** | 会比参考片**方一些** | 不是 bug：56 张卡的 `box` 是按 16:9 写死的百分比（`B1` 恒 52% 宽），投影进竖屏格位后 1080×1920 上约 562×559（近方）；参考片的卡是 900×420（宽扁）。要让竖屏卡变宽扁，得给卡加「竖屏专用 box」，不在本轮范围 |

### 实测过的格位数值（直接用，别让 agent 自己猜）

| 单元 | cell | 投影后实际 |
|---|---|---|
| 大标题（A2） | `{x:50, y:22, w:100, h:24}` | 76% 宽 × 7.2% 高；9 字 84px 刚好一行（不换行） |
| 主体卡（B1/DAT3） | `{x:50, y:62, w:100, h:56}` | 52% 宽 × 31% 高（近方） |

`w` 必须给 **100**：卡自己的 `box.w` 还要再乘一次 cell 宽度，给 88 会把标题压到 66% 屏宽 ⇒ 换行或裁字。

## §5 本轮补齐的三件（已落地，等真机验收）

1. **`DAT6` 折线 + 峰谷标注**（`recipe-cards-data.ts`）：`chart:line` + 2 `callout` + 均值虚线；
   少于 3 点回落成标题卡（两点只有一条直线，标不出峰谷）；全平序列不画均值线（会和曲线重合）。
2. **`textCard.highlights` 分段着色**（契约）：`manifest.ts` 字段 + 校验、`text-highlights.ts`
   切分（唯一实现）、`TextCard.tsx` 分段渲染（`unitOffset` 接续逐字节奏）、spec 侧两处透传。
3. **`A6` 结论条**（`recipe-cards.ts`）：黑底圆角 + 白字单句，`label` 空时自动上移。

配套：`shape:'line'` 支持 `stroke` / `strokeWidthPx` / `dash`（此前只有 4px 实心 div，
均值虚线无处可落）；`radius` 在 line 上仍只 warn。

测试：`tests/req038-r11-visual.test.mjs` 16 条；5 处反向变异全红
（重叠检查 / 坐标单位 / 全平不画线 / A6 上移 / highlights 白名单）。
**已知未覆盖**：`line + dash` 的 SVG 分支只有契约断言，没有渲染断言（无组件渲染测试设施），
靠真机肉眼验收 —— 如实登记。
