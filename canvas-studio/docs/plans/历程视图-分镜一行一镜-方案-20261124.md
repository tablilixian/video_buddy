# 历程视图 · 分镜「一行一镜」布局方案

- **状态**：方案已定（用户 2026-11-24 拍板：4 格、一行一镜），待实现
- **编号**：REQ-036 迭代（暂未领 CV 号；当前水位 CV-449，验收通过后再取）
- **改动面**：`canvas-studio/src/canvas-waterfall.ts`（主）+ 渲染层两处 + 计数文案
- **效果预览**：`docs/demos/shot-rows-2026-11-24/index.html`（真实项目数据，可切 4 格 / 5 格 / 音轨条）
- **不改数据**：历程视图是渲染层投影，从不写回 `node.x/y`，存量画布不动

---

## 1. 结论

分镜节从「每镜一个卡头 + 若干竖排产物」改为 **一行一镜的行式表格**：

1. **行 = 镜**，镜号升序；行框即该镜的容器，左侧状态色边。
2. **行内单排网格**，格序固定：`分镜卡 → 关键帧 → 末帧 → 镜视频 → 配音`，其余按 createdAt 追后。
3. **格宽统一**取视口档位（≤1700 视口 = 380），**行内上限 4 格**，第 5 件折到**同一行框内的第二排**。
4. **卡不再是 108 高的头带**，改成网格第一格，与媒体等高（380×214），正文能露 5–6 行。
5. **配音不再是独占整行的横条**，改成行内普通格。
6. **行框等宽**（都在节宽内），单排时等高（246）。

380 档实测：节宽 **1624**、行高 **246**、4 行总高 **1056**。视口 1600 时 fit 一次缩 ~2.4%，视觉等价。demo 用 370 档（1584×1032）只是为了截图不触发缩放。

## 2. 为什么改（现状的三处问题）

### 2.1 三个数字口径不同，不是数据错

| 位置 | 显示 | 实际含义 | 代码 |
|---|---|---|---|
| 故事板时长行 | `2 分镜 / 4 主拍` | 2 = **场**数，4 = **镜**数 | `storyboard-render.ts:385` |
| 故事板摘要图 | `2 分镜 · 4 shot` | 同上，文字重复计一次 | `storyboard-render.ts:1023,1034` |
| 画布分镜节 chip | `分镜 8/8` | 8 = **节点数**（4 卡 + 4 视频） | `WaterfallStatusBar.tsx:105` ← `statsOf()` |

同一个词「分镜」在三处指三样东西。**布局改完必须同步改计数文案**，否则「8/8」还会被读成 8 个分镜。

### 2.2 细长条的根因

`canvas-waterfall.ts:461-511`：

- 每个托盘的宽度 = `TRAY_PAD*2 + max(网格宽, 单格宽)`，**由内容决定**；网格列数 = `min(成员数, 4)`。
- 真实项目每镜只有 1 条视频进网格 → 1 列 → 托盘宽 332。
- `:574` `trayY += tray.height + TRAY_GAP` **只做纵向堆叠** → 4 个 332 宽叠成 332×1364。
- 创意/音频节是 4 列 1272 宽。中间那条窄带就是这么来的。

### 2.3 卡与音频占了两个「整行」位置

- 卡是 `TRAY_HEAD_H = 108` 的扁头带（`:159`），不进网格，横向独占一行。
- 音频被 `:471` 单独摘出来，`audioOffsets` 宽度 = 托盘内宽，又独占一行。

两处叠加的结果：一镜的产物被拆成「头带 + 视频格 + 音轨条」三段，纵向拉长、横向不齐。

## 4. 布局规格

### 4.1 行结构

```
分镜节 ──────────────────────────────────────────── 4 镜 · 16 卡
┌ 镜1 ─────────────────────────────────────────────────────────────┐  ← 行框(状态色边)
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐                      │
│ │ 分镜卡 │ │ 关键帧 │ │ 镜视频 │ │ 配音   │  ← 单排 4 格，格宽 380 │
│ │ 380×214│ │ 380×214│ │ 380×214│ │ 380×214│     gap 24 / pad 16    │
│ └────────┘ └────────┘ └────────┘ └────────┘                      │
└──────────────────────────────────────────────────────────────────┘  ← 高 246
                     ↓ gap 24
┌ 镜2 ─────────────────────────────────────────────────────────────┐
```

### 4.2 尺寸常量

| 量 | 值 | 来源/变更 |
|---|---|---|
| 格宽 `cellW` | `thumbWidthFromViewport()`：240/300/380/480 | 不变（`:340`） |
| 格高（媒体） | `cellW * 9/16` = 214 | 不变（`cellHeightOf`） |
| 格高（分镜卡） | **= 媒体高 214** | 改：现返回 `TEXT_H=140` |
| 格高（音频） | **= 媒体高 214**（或 168 居中，见 §8） | 改：现返回 `AUDIO_H=168` |
| 格间隙 `GAP` | 24 | 不变 |
| 行内边距 `TRAY_PAD` | 16 | 不变 |
| 行间距 `TRAY_GAP` | 24 | 不变 |
| 行内列上限 `MAX_COLUMNS` | 4 | 不变（语义从「托盘内网格」变「行内网格」） |
| `TRAY_HEAD_H` | **删除（退役）** | 卡进网格后无头带 |

### 4.3 格序

`ROLE`（`:170`）已定义 `keyframe:1 / video:2 / lastframe:3 / voice:4`，卡固定 role 0。排序沿用现有 role 优先级即可，但**卡要进 grid**（当前被 `card` 单独摘出）。

### 4.4 行框

- 宽度 = 节宽（所有托盘统一到 `max(trayWidth)`），不从内容缩。
- 高度 = `TRAY_PAD*2 + 网格高`；单排恒 246，折行时随内容变高（**不做强制等高**，否则两排的行会留大片空白）。
- 边框颜色沿用 `trayBorderColor(stats)`（`CanvasSurface.tsx:54`：失败红 / 生成中亮色 / 完成绿）。
- 行框右上 chip 现在贴 `box.x + box.width - 8`；宽度统一后会跑到很右边，**需改为贴最后一个格子的右边界**（`lastCellRight`），或直接删除（节头已有计数）。

### 4.5 折行

`gridLayout`（`:304`）已支持「列数上限 + 行高取该排最大」：

- ≤4 件：单排。
- 5 件（如将来末帧齐全）：4 + 1，第二排 1 格，该行框变高 214 + 24。
- 折行时**同镜产物仍在本行框内**，「一行=一镜」不破。

### 4.6 缺失与空态

**不做幽灵格**：缺末帧就不画格子。产品已有「空节点 = 可点击生成」的语义，再加虚线占位会变成两套空态打架。代价：产物少的镜行变窄（但行框已统一到节宽，视觉仍齐）。

### 4.7 角标

沿用现有机制，不加新角标：

- 版本折叠：`v4 · 3 历史`（`WaterfallStack`，不动）
- 状态：`已失效 / 草稿`
- 格内脚注：时长 / 分辨率（渲染层已有）

### 4.8 计数文案

| 位置 | 现在 | 改成 |
|---|---|---|
| 节头 | `分镜 8/8` | `4 镜 · 16 卡` |
| 全局 chip | `分镜 8/8` | `分镜 4 镜` |
| `WaterfallSection` | 只有 `stats` | 增 `shotCount`（= trays.length，节内已有 trays 可直接派生，**不必改布局输出**） |

## 5. 实现改动点

### 5.1 `canvas-waterfall.ts`（主）

| 位置 | 现状 | 改法 |
|---|---|---|
| `:159` `TRAY_HEAD_H` | 108，头带保留高 | 删除常量与所有引用 |
| `:181` `cellHeightOf` | text→140 / audio→168 | `isShotCard(node)` 先判 → 返回媒体高；audio 也返回媒体高（或保持 168 + 居中，见 §8） |
| `:461-511` 托盘计划 | 卡摘出单独定位；音频摘出整行 | 卡与音频**都进 `gridItems`**，按 role 排序；`cells` 只由网格产生 |
| `:481` `audioOffsets` | 整行横条 | 删除 |
| `:485` 托盘高 | `TRAY_HEAD_H + PAD + content + PAD` | `PAD + grid.height + PAD` |
| `:502` 节宽 | 各托盘宽取 max 但**不统一** | 统一：先算 `sectionWidth = PAD*2 + max(innerWidth)`，回填每个 tray.width |
| `:530-570` 落位 | 卡单独写 `positions`/`boxes`；音频宽 = 内宽 | 卡走 `grid.offsets`；所有格 `width = cellW`；音频不再特判宽度 |
| `:574` 纵向堆叠 | 保持 | 保持（行间距 24） |

**关键点**：`positions` / `boxes` 的语义不变（画布空间左上角），只是取值来源从「头带 + 音轨条」变成「网格格位」。这是本次唯一的结构性改动。

### 5.2 渲染层

| 文件 | 位置 | 改法 |
|---|---|---|
| `CanvasSurface.tsx` | `:1615-1625` 托盘框 | 不改变（继续用 `tray.box`），宽度自动变宽 |
| `CanvasSurface.tsx` | `:1758-1773` 托盘 chip | 位置改贴最后格右边界，或删除（节头有计数） |
| `CanvasSurface.tsx` | `:1278-1290` 投影 | 不变（`box → node.width/height`） |

### 5.3 契约

`WaterfallTray` 不加字段（`shot / cardId / nodeIds / stats / box` 已够）。节计数 `shotCount` 由渲染层用 `trays.filter(t => t.shot)` 派生，不进布局输出，避免契约扩散。

### 5.4 术语（P2，不在本次）

「场 / 镜 / 条」替换现有「分镜 / 主拍」共 5 处（`storyboard-render.ts:385,1023,1034`、`contracts/storyboard.ts:902`、`host-tools.ts:4418`）。**不要**动卡片标题 `分镜 N · S1-Sh1`：`^分镜 N` 是镜号解析的硬依赖（`canvas-placement.ts:189`、`reference-resolve.ts:260`、`host-tools.ts:1888`），改了会全线断索引。术语与布局分开两轮做。

## 6. 明确不做

1. **不写回 `node.x/y`**：历程视图仍是只读投影。
2. **不填存量数据**：不写脚本迁移、不改历史画布的 `sourceIds`。
3. **不做幽灵格/空槽**。
4. **不改 `thumbWidthFromViewport` 档位**：380 档 4 格 1624 略超 1600，由进入视图时 fit 一次吸收（现行为）。
5. **不动自由画布的整理布局**（`arrangeCanvas` / `computeArrangeLayout`）。

## 8. 风险与待定

| 风险 | 说明 | 处置 |
|---|---|---|
| 音频卡拉高到 214 | 音频卡固有 480×168，布局拉高后内部是否自适应未知 | 首选「盒高 = 168，y 居中偏移 20」；真机看效果再决定是否拉满。**不改卡内部布局** |
| 分镜卡拉高到 214 | 卡内文本 `-webkit-line-clamp` 行数固定，拉高可能只多留白 | 若只留白，接受（视觉等高优先）；真机确认后可调 clamp |
| 行框统一宽后右侧留白 | 只有 1 件产物的镜会很空 | 接受（表格感），空行框本身也是信息：「这镜只有一条视频」 |
| 5 件折行 | 单排 4 格装不下「卡+帧+末帧+视频+配音」 | 折行，行框变高；若末帧成为常态再评估 5 列 + fit |
