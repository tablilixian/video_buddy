## 一、实机评估：跑通了什么，差在哪

### 1.1 硬数据

| 项 | 实机成片 | MotionGit ground truth | 判定 |
|---|---|---|---|
| 规格 | 1920×1080@60，1080 帧，18.07s | 1920×1080@60，1080 帧，18.00s | ✅ |
| 契约校验 | `validateManifest` 0 error 0 warning | — | ✅ |
| 编排时刻 | 0.117 / 0.500 / 1.100 / 1.250 / 8.100 / 8.350 / 8.900 / 9.067 / 9.217 | 同一组 | ✅ 逐条吻合 |
| 三卡错峰 | 9.0s 帧 01/02 已就位、03 仍在淡入 | 8.90 / 9.07 / 9.22 | ✅ |
| 路径生长 | 1.5s 起笔 → 2.0s 完成 | 1.25→2.45s easeInOut | ✅ |
| **音频** | **非零采样 0 个，mean/max −91.0 dB（纯静音）** | 7 个音效点，mean −33.1dB / max −3.7dB | ❌ **纯静音** |
| B1 左右亮度（7 点均值） | 左 7.84 / 右 1.35 → 右侧占 **14.7%** | 左 10.68 / 右 9.25 → 右侧占 **46.4%** | ❌ 右侧亮度只有 GT 的 **14.6%** |

| 4 | 序号「01」在深色方块里，GT 是裸彩色文字 | 同 #2（序号被当成 subtitle 用） | 契约限制 |
| 5 | 卡片是直角实色块，GT 是圆角+描边+半透明玻璃 | shape 无 `radius`/`stroke`/`opacity` 字段 | 契约限制 |
| 6 | 背景是**硬边蓝圆盘**（像行星），GT 是柔焦径向光斑+星点 | `shape:'circle'` 无径向渐变/羽化；无星点背景层 | 能力缺口 + 契约限制 |

| 8 | B1→B2 硬切、元素直接消失；路径不反向收回 | `exit`/`reveal.out`/`transition` **能力全有**，但没有模板把它们固化下来 | **能力已有，模板没用** |
| 9 | 全帧 UI 装饰层缺失 | 四角括线、时间码、章节标签、底部进度条、玻璃卡描边 —— GT 是**一帧设计**，我们只是**一条元素流** | 能力缺口（见 §1.3） |

**关键判断**：
- **#1 / #6 / #9 = 能力缺口**（真缺的东西）
- **#2 / #3 / #4 / #5 / #7 = 契约表达不了**（组件把外观写死了，manifest 关不掉）
- **#8 = 能力已有、但没有任何东西把它们固化下来**

### 1.3 结构性的洞：GT 是「一帧设计」，我们是「一条元素流」

逐帧比对（`vf_2.0.png` vs `_gtB1_2.0.png`、`vf_9.5.png` vs `_gt9.5.png`）后发现的**最重要一件事**：

> 我们复刻成功的是**内容层**（文字、卡片、路径、错峰、时机）。
> GT 里还有整整一层**场景装饰（scene furniture）**，我们一个都没有做。

GT 每帧都有、我们完全没有的构件：

| 构件 | GT | 我们 |
|---|---|---|
| 四角括线（corner brackets） | ✅ 每帧 4 个 | ❌ |
| 右上时间码 `00:00:02:00` | ✅ 逐帧跳变 | ❌ |
| 左上/左下章节标签「一个想法」 | ✅ | ❌ |
| 底部进度条（刻度 + 橙色游标） | ✅ 随进度推进 | ❌ |
| 右上圆形图标 | ✅ | ❌ |
| 柔焦径向光斑 | ✅ 中心偏右 | ❌（硬边圆盘） |
| 星点背景 | ✅ | ❌ |
| 玻璃卡（圆角+描边+半透明） | ✅ | ❌（直角实色） |
| 发光实线 | ✅ | ❌（虚线段） |

⇒ **「模板」必须携带的不只是「内容槽 + 时序」，还得携带「装饰构件层」。**

这解释了一个之前想不通的问题：为什么「三卡结构复刻对了，画面还是不像」。**因为我们把 GT 当成「几个元素」，而 GT 是「一帧完整的版式」。**

⇒ 计划必须新增一层：**构件库（primitives）**。`themes.ts` 现在只提供颜色 token，不提供版式构件；模板要声明「这一帧有哪些构件」，构件要可参数化（半径/描边/羽化/字号/对齐）。

> MotionGit 的对应物是 `core/style.css` + `core/lib.js`（`place()`/`cam()`）+ `core/scenes/*.js` —— **它把「怎么摆」也做成了可复用代码**。我们不能照抄代码（违背「模型不写代码」原则），但**可以照抄它「构件可复用」这个结构**。

## 二、根因：系统里没有「模板」这个一等公民

「只改内容和参数就能还原效果」要求模板**同时携带六样东西**。逐样对照本仓现状：

| 模板必须携带 | 本仓现状 | 差距 |
|---|---|---|
| ① 版式参数（字号/对齐/圆角/配色/坐标） | 散落在**组件源码**里（84px 写死、居中写死、直角写死） | 参数化不了 |
| ② 编排时序（段长/错峰/缓动/相机） | `recipes.ts` 只固化「段序列 + 卡片编号 + 素材需求」；`shot-cards.md` 是可粘 JSON 片段 | 没有一个东西同时带时序**和**版式 |
| ③ 出入场与转场 | **能力全有**（`exit` / `reveal.out` / `transition` 11 式） | 能力在，没被任何模板固化 |
| ④ 槽位合同（能填什么/多长/必填） | **零** | 无 → 静默裁切 |
| ⑤ 声音事件表 | **零** | 无 → 静音 |
| ⑥ **装饰构件层**（括线/时间码/进度条/光斑/玻璃卡/星点） | **零**（`themes.ts` 只给颜色 token） | 无 → GT 是「一帧设计」，我们是「元素流」 |

⇒ **结论：不是缺某个能力，是缺「模板」这个容器。** 现在的 `recipes.ts` + `shot-cards.md` + `themes.ts` 是模板的三块碎片，谁都没有把它们装进一个可复用、可参数化、可校验的对象里。

### MotionGit 的解法（可直接抄的结构）

```
.mmotion/
  motion.json            # 身份 + 运行 profile + 输出声明
  params.schema.json     # ① 可替换内容合同（每字段 maxLength）
  content.schema.json    # ④ 槽位合同（469 槽，每槽 maxChars/format/required/source 行号）
  core/catalog.json      # 内容单元表（分组 / 时间窗 / 字段集 / 素材位）
  core/audio-events.json # ⑤ 音效事件表（t / type / gain / pan）
  core/lib.js            # ② 动效原语（EZ 缓动集 / place() / cam()）
  core/style.css         # ① 视觉风格 + ⑥ 装饰构件（括线/时间码/进度条/光斑）
  core/scenes/*.js       # ② 场景实现
  guide.json             # 给 AI 的使用指南（firstResponse/fit/duration/materials/routes）
  examples/*.json        # 示例填充值
  licenses/ integrity.json
```

**它的六样东西全部有独立文件、都是声明式、都有机器可校验的合同。** 本仓要建的是同构的东西。

## 三、目标与验收标准

### 3.1 目标（用户口径）

> LLM 只改内容和参数，就能快速、准确地还原这些效果。

### 3.2 量化验收

| 指标 | 现状 | 目标 |
|---|---|---|
| **还原一个已知效果的工具调用数** | 人工拆参考片 + 手写 manifest（分钟级、几十次试错） | **2 次**（`list_templates` → `render_composition(templateId, slots)`） |
| **还原耗时** | 分钟级 | **≤ 5 分钟**（含渲染） |
| **文字容量合规率** | 静默裁切（0 层拦截） | **100%**（编译期拦截，给出可执行建议） |
| **带声成片** | 0 个音效点 | 与模板声明的音效点**逐点对齐**（时刻/类型/增益） |
| **版式降级项** | 5 项（#2 #3 #4 #5 #7） | **0 项**（Phase 2 完成后） |
| **装饰构件层还原度** | 0/9 构件（见 §1.3） | 模板声明的构件 **100% 出现**（可逐构件比对） |
| **标题/正文层级比** | 1.9 : 1 | 与模板声明一致（误差 ≤ 5%） |
| **模板可编辑性** | — | 只改 `slots` 内容 + **≤3 个参数**，即可还原 |
| **模板自检** | 靠人眼看 | 模板自带参考帧基线，spot-check 自动比对并给出差异结论 |

### 3.3 非目标（本轮不做）

- 不移植 MotionGit 的 JS 引擎（两套栈 + 违背「模型不写代码」架构原则）
- 不 vendor `.motion` 包（93/94 拿不到源码；单包 17–51MB）
- 不做 94 个模板（精选 10–15 个，按体裁）
- 不做交互式模板（视频里没有交互）

## 四、架构：模板 = 一等公民

### 4.1 模板目录形态

```
templates/
  motiongit/kinetic-b1b2/
    template.json      # 身份、契约版本、能力声明、适用体裁、所需素材
    spec.json          # ★ 声明式版式规格（轨型/坐标/字号/对齐/圆角/段长/出场入场/音效事件）
    slots.json         # ★ 槽位合同（类型/必填/字数/行数/语义/**版式角色**/示例/失败处置）
    furniture.json     # ★ 装饰构件声明（括线/时间码/进度条/章节标签/光斑/星点/玻璃卡）+ 参数
    assets/            # 私有资产（贴纸/音效/纹理/卡面）
    frames/            # ★ 参考帧基线（帧号 → PNG，供 spot-check 自动比对）
    preview.mp4        # 样片（含声音）
    README.md          # 给人和 LLM 的说明（含「这条模板适合什么/不适合什么」）
    LICENSE
```

### 4.2 编译链

```
template.spec ─┐
template.slots ─┼─→ [ 编译器 ]─→ manifest ─→ [ 校验层 ]─→ render ─→ 成片
本期内容 ───────┘                    ↑ limits 合同 + fit 预检 + overflow 上报
                                                  │
                     template.frames ──→ spot-check 自动比对 ─┘
```

**LLM 只动「本期内容」这一层。**

### 4.3 关键决策：`spec.json` 复用已有形状，不新造机制

实证（`VideoOut/new3`）：真实生产里已经有

```
storyboard.json → manifest-spec.json → (make-spec.mjs) → manifest.json → 成片
```

**`manifest-spec.json` 就是模板 spec 的形状**（`title/fps/aspect/filmFrames/theme/captions[]/visuals[]/audio`）。所以：

> **Phase 1 不需要新机制** —— 把「一次性的项目 spec」升级成「可复用、可参数化的模板 spec」，再补一个 `slots` 合同层。

这是本计划最重要的省力点：**复用已被生产验证的 spec → manifest 编译链。**

### 4.4 两阶段（能力边界必须诚实）

| | Phase 1（零契约扩展） | Phase 2（契约扩展） |
|---|---|---|
| 模板 = | 现有 manifest 骨架 + 槽位注入 | 同上 + 可覆盖外观参数 |
| 外观 | 受现有 variant 限制：**84px 标题、居中字幕、字幕强制底块、直角形状** | textCard 加 `fontSize`/`align`/`fontWeight`/`background`/`radius`；shape 加 `radius`/`stroke`/`opacity`/`radial`；新增 `chip`/`topTitle`/`bare` variant |
| 装饰 | **无**（Phase 1 先用最简构件集） | **完整构件层**（9 类构件，逐构件比对） |
| 能还原 | 编排时序、结构、槽位、出入场、音效 | **+ 版式 1:1** |
| 工期 | 2–3 周 | 2–3 周 |

**建议先做 Phase 1** —— 它把「模板」这个容器落地、把 LLM 工作流跑通、把声音缺口补上；Phase 2 只是把外观参数打开。

## 五、能力缺口清单（开发项）

### P0-A · SFX 事件轨（用户点名的真实功能缺口）

**现状（精确定位）**
- `manifest.audio` 只有 `bgmUrl` / `voiceOverUrl` / `voiceOver[]` / `mix` / `fadeInSeconds` / `fadeOutSeconds` / `duck`
- **渲染路径的音频层是 `src/remotion/components/AudioTrack.tsx`**，它只渲染 BGM 与旁白（`<Audio>` from `@remotion/media`）—— **没有 sfx、没有事件、没有 pan**
- `src/audio-timeline.ts` 里有完整的 `AudioSegmentRole`（含 `'sfx'`）与 `buildAudioGraph`（支持 pan / duck），**但那只被 `compose_video` 用**（`compose.ts:669`）；`render_composition` 根本不进 ffmpeg 混音
- ⇒ **「实机成片完全没声音」不是「忘了写 sfx」，而是渲染路径的音频模型里压根没有「音效事件」这个概念**
- 另：`storyboard` 的 `sound.sfx` 是 `string[]` 文字描述（如「雨声床」），不是可执行事件

**要做**
1. **契约扩展**：`manifest.audio` 增加
   ```jsonc
   "sfx": [{ "src": "...", "startSec": 0.58, "gain": 0.55, "pan": 0, "fadeInSec": 0, "fadeOutSec": 0.2 }]
   ```
2. **音效点 → 可执行事件的编译**：storyboard `06_sound.sfx`（自然语言）+ 模板的音效事件表 → 音频时间轴的 sfx 段
3. **音效来源两条路**（建议都留）：
   - **素材库路线**：沿用 CV-371「SFX 12 个 + 授权账本」，需逐条授权
   - **程序化合成路线**（MotionGit 路线）：`thud`/`write`/`swoosh`/`card`/`swipe` 用 numpy/WebAudio 合成，**零授权、四参数可调**（type + gain + pan + 时长）。在 Node 侧重写 `native_audiolib.py` 的那套（FFT 滤波 + ADSR + 声像 + 混响）
4. **渲染侧接线**：**在 `AudioTrack.tsx` 里把 sfx 渲成 `<Sequence from={frame} layout="none"><Audio/></Sequence>`**（不是走 `buildAudioGraph`——那是 compose 路径）
5. **pan**：`<Audio>` 没有声像参数 ⇒ **pan 在合成期烘进 WAV 文件**（等功率公式 L=x·√((1−p)/2), R=x·√((1+p)/2)）；manifest 里的 `pan` 只作声明与校验，指向外部素材时发 warning

**验收（用实测起音基线，不是 JSON 推断）**
GT 音频（18.000s）实测可听事件：

| 组 | 时刻(s) | 峰值 dB | 性质 |
|---|---|---|---|
| A | **0.580** | −8.8 | B1 起始，最响 |
| A′/A″ | 0.690 / 0.850 | −28.3 / −41.3 | |
| B | 1.410 → 2.290（步长 ~0.095） | −38.2 … −30.1 … −38.6 | **打字簇**（11 个 ~100ms 间隔的峰） |
| C | **7.760** | −14.8 | B1→B2 转场 |
| D | **9.060 / 9.220 / 9.360** | −20.4 / −20.8 / −20.1 | **三卡错峰音**，间隔 0.160s |
| E | **17.710** | −25.8 | 收尾 |

⭐ **D 组是强交叉验证**：三个音峰与三卡**视觉**入场 8.900 / 9.067 / 9.217 严格对应 ⇒ 声音与画面共用同一套时序基准。

**通过标准**：每组起音**偏差 ≤ 1 帧（0.0167s）**；D 组三点间隔仍为 0.160s；整片 mean ∈ −40..−25 dB、max ∈ −12..−2 dB（GT 实测 mean −33.1 / max −3.7）。

> 详细规格见 [`任务包-0A-SFX事件轨.md`](任务包-0A-SFX事件轨.md)；基线数据见 [`视频模板化-基线与代码事实索引.md`](视频模板化-基线与代码事实索引.md)。

### P0-B · 槽位合同 + 容量校验（已实测，见配套文档）

**现状**：零。文字放不下时被 `overflow:hidden` 静默裁掉，`validateManifest` 报 ok。

**要做**（三层，对齐 MotionGit 的两段式）
| 层 | 位置 | 做什么 |
|---|---|---|
| L1 静态 | Node，`make-spec` 之前 | 字数 / 行数 / 数量（spec 层 `limits`，按 variant 声明） |
| L2 折行预检 | 渲染前（浏览器） | `canvas.measureText` 实测折行 vs 轨高 |
| L3 溢出上报 | 渲染报告 | **把已有的 `fitTextPolicy` 的 `overflow` 标志接出来** —— 机制 2026 年就在 `timing.ts:1142`，缺的只是出口 |

**已实测的证据**：本方案自己的 manifest 初稿（B1 正文盒 900×105px）用仓库真实的 `subtitleFitBudget` + `fitTextPolicy` 验算 = **24.2px / 2 行 / maxLines=1 ⇒ overflow=true**，而 `validateManifest` 同时报 **0 error 0 warning**。**零层拦截。**

**验收**：超限文案在编译期被拒并给出「改短到 N 字」的建议；真实四季 spec 全库回归 4/4 通过。

### P1 · 模板库机制

**要做**
1. `templates/` 目录规范 + 模板清单注册
2. **编译器**：`template.spec` + `template.slots` + 本期内容 → manifest（复用现有 spec→manifest 链）
3. **工具：`list_templates`** —— 返回模板清单（id / 名称 / 体裁 / 适用场景 / 槽位摘要 / 样片首帧 / 参考帧数 / 所需素材）。**这是 LLM 能「快速准确选对模板」的前提**
4. **工具：`render_composition` 加 `templateId` + `slots` 便捷通道** —— 内部编译 + 校验 + 渲染
5. **模板参考帧基线** + **spot-check 自动比对**：模板存 N 张关键帧，LLM spot-check 后自动算差异（像素差 + 元素位置差），返回可读结论
6. **模板自检**：模板自带「必须满足的验收项」（如「3 张卡必须在 0.16s 内错峰」），编译期断言

**验收**：LLM 零人工干预完成「选模板 → 填内容 → 出带声成片」，且 spot-check 比对给出结论。

### P1-B · 版式参数化（契约扩展，Phase 2）

**要做**
| 轨 | 新增字段 | 解决 |
|---|---|---|
| textCard | `fontSize`（基准字号） | #7 标题偏小 / 正文偏大 |
| textCard | `align`（左/中/右） | #3 卡片文字居中 vs GT 左对齐 |
| textCard | `background`（`'none'` / 色值）、`radius` | **#2 文字自带底块**（现在写死 `rgba(0,0,0,0.62)` / `0.35`）、#4 序号带方块 |
| textCard | `fontWeight` | 标题字重（GT 是粗黑体） |
| shape | `radius` / `stroke` / `opacity` | #5 玻璃卡（圆角 + 半透明 + 描边） |
| shape | `shape:'radial'`（径向渐变 + 羽化） | #6 硬边圆盘 → 柔焦光斑 |
| 新 variant | `chip`（小标签）、`topTitle`（顶部标题）、`bare`（裸文字无底） | #2 #4 的版式角色 |
| 位置互斥 | 允许 textCard 的 `box` 与 `animate.x` 共存 | 卡片面板 + 文字联动入场（GT 的卡片是一整个 DOM 元素一起动） |
| 新轨 | `camera`（全片级相机） | 统一推拉摇移（我们只有 `animate.scale` + `orbit`） |

**新增「层级字号 token」**（治 #7 的比例失真）：不要让每个 variant 各写一套字号，改为「主题层给 `title/body/caption/number` 四个**角色字号**，variant 只声明角色」。GT 的 111 : 34.5 = 3.2 : 1 就能被一个 token 描述。

**新增 P1-C · 装饰构件层（治 #9，本次新发现）**：

| 构件 | 形态 | 参数 |
|---|---|---|
| `cornerBrackets` | 四角括线 | 线宽/长度/颜色/内缩 |
| `timecode` | 右上时间码 | 格式（`00:00:02:00`）、字号、位置 |
| `progressBar` | 底部刻度条 | 刻度数/游标色/是否随进度推进 |
| `chapterLabel` | 左上/左下章节标签 | 文本槽/位置 |
| `radialGlow` | 柔焦径向光斑 | 中心/半径/羽化/颜色/强度 |
| `starfield` | 星点背景 | 密度/亮度/视差 |
| `glassCard` | 玻璃卡（圆角+描边+半透明） | 复用 shape 外观字段 |

> 实现形态：**不是新造一套渲染管线**，而是把已有能力组合成「构件」，用 manifest 现有轨型承载（`shape` 承载 radialGlow/starfield/glassCard，`textCard` 承载 timecode/chapterLabel，`shape`+`path` 承载 progressBar/cornerBrackets）。**关键不在渲染，在「模板能声明并复用它们」。**

**风险**：动 `KNOWN_TRACK_KEYS` 要过字段漂移机检；`textCard` 加 `fontSize` 要与 `fitTextPolicy` 的自动缩排**共存不打架**（谁优先？—— 建议：显式 `fontSize` 是上限基准，自适应只在未显式给出时接管）；`background` 缺省值必须等于现值（`subtitle`→`rgba(0,0,0,0.62)`，`title`→`rgba(0,0,0,0.35)`）⇒ 老 manifest 逐像素不变。

### P2 · 版式角色与占位语义

GT 的核心版式是「**左对齐 + 右侧留主播位**」，`dx` 逻辑：有无主播内容都左移 300px。模板要能表达：

- **版式角色**：`left-column` / `center` / `right-column` / `full`
- **占位语义**：`presenter` 槽可为空；为空时版式自动重排（而不是留一个洞）

⇒ 直接消灭 #6 的「右侧空洞 + 光斑缺失」一半（另一半靠 `radial` 形状与星点构件）。

### P2 · 出入场与转场进模板（能力已有）

`exit` / `reveal.out` / `transition`（11 式）**全都有**，只是没人把它们固化进任何东西。模板 spec 必须能声明：
- 段边界的转场（GT 的 B1→B2 是硬切 + swoosh，我们照做即可）
- 元素的退场（GT 的 B1 元素在 T1 前淡出）
- 路径的反向收回（GT 的 `1 - pr(t, T1-.5, T1)`）

⇒ 消灭 #8，**零契约扩展**。

## 七、LLM 工作流（目标形态）

```
用户：「做一条 20 秒的口播包装，讲 XX」
  ↓
LLM → list_templates()                     # 拿候选：体裁/时长/槽位/样片
  ↓  LLM 选 kinetic-b1b2
LLM → describe_template(id)                # 拿完整 spec + slots 合同 + 参考帧
  ↓  LLM 按槽位填内容（受字数/行数约束）
LLM → render_composition(templateId, slots)  # 内部：编译 → 校验 → 渲染
  ↓  返回：成片 url + 抽帧 + 校验结论 + 与模板参考帧的差异
LLM → 如差异超阈值，改内容再渲（只改 slots）
```

**关键设计**：`render_composition` 的返回值里带**与模板参考帧的自动比对结论** —— 这是「准确」二字的落点，也是「只改内容」的底气。

## 九、与既有工作流的关系

- **不是替代 `recipes.ts`**：`recipes.ts` 固化「段/权重/卡片/素材需求」，模板固化「完整版式+时序+内容槽」。**模板是 recipes 的超集**，可从 recipe 派生。
- **不是替代 `shot-cards.md`**：镜头卡是「可粘片段」，模板是「可复用对象」。模板内部可以引用镜头卡。
- **不是替代 `themes.ts`**：主题是「视觉 token」，模板是「一整支片」。模板引用主题。
- **是 `themes.ts` 的升级方向**：现在 `themes.ts` 只给颜色/字号 token；Phase 2 的「层级字号 token」和「构件库」让主题开始提供**版式构件**，但**构件本身是模板级的**（一条模板用哪些构件，是模板的决定，不是主题的决定）。
- **补的是 `manifest-spec.json` 的模板化**：把一次性项目 spec 升级为可复用模板 spec。

⇒ 一句话：**`recipes.ts` + `shot-cards.md` + `themes.ts` + `manifest-spec.json` 四块碎片，装进一个叫「模板」的盒子。**
