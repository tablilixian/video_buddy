# 素材轨时长口径（硬口径，别估）

Manifest 里 `tracks[].durationInFrames` 是渲染的硬输入。若留给模型「目测」，会出现最难查的一类静默错误：

- 声明**偏短** → 素材被截断（画面在动作中途断掉）；
- 声明**偏长** → 渲染器在素材末尾**冻结最后一帧**（Remotion 的行为：视频结束后保持末帧），观众看到"卡住的画面"，且**没有任何报错**。

所以按时长来源分档（与总纲 `toolchain.md` 的平台事实一致）：

| 轨类型 | 时长来源 | 允许偏差 | 违反判定 |
| --- | --- | --- | --- |
| `video` | **`list_shots` 返回的真实时长**（Host 已用 ffprobe 探过真值）→ `durationInFrames = round(真实秒数 × fps)` | ±1 帧（取整） | 偏差 > 0.5s：宿主在核对阶段计入 warnings；与相邻轨 / 转场窗口冲突 → 直接报错拒绝渲染 |
| `image` / `textCard` / `shape` | 按解说节奏与字幕时序自主排布（无真值可言） | 自由 | — |
| `transition` | 由相邻两轨的重叠窗口决定 | — | 见 `references/manifest-contract.md` 转场一节 |

## 纪律

1. **不许"目测"视频时长**——必须来自 `list_shots`；手里没有该字段就先调它，**不许编**。
2. video 轨取整时统一用 `round`，不要 `floor`（避免系统性偏短导致截断）。
3. 时长核对把「声明 vs 真值」变成**用户可见决策**：在 `ask_user_choice` 预览时，video 轨要同时展示「声明时长 / 真值」两列，让人一眼看出是否被宿主修正过。
4. 若某段素材真值明显长于叙事需要，**先 `cut_audio` 裁音频 / 重新出更短的视频**，不要靠"声明偏短"截断画面。

## 与旁白的关系

有旁白时，成片总时长通常由旁白真值总长决定（见 `references/subtitle-timing.md`），video / image 轨按叙事节拍切分铺满；**末轨吸收舍入误差**，保证 `meta.durationInFrames` 与全部轨道末端对齐。
