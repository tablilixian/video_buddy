# 动态思考强度 · 分层策略与实施（讨论稿 v1 · 2026-11-08）

> **问题**：思考强度目前是一个「全局静态档位」（设置页手选），但三场真机会话证明：
> **不同阶段的工作性质完全不同**——一刀切的档位要么在规划段爆预算（会话 19），
> 要么在判断段变浅（A2 探针规划浅 / ML-13 收口不彻底 / 会话 20 下载卡死不自愈）。
> **主张**：思考强度应该匹配「当前步骤的工作性质」，而不是用户的一个静态偏好。
> 达成手段两根杠杆：**① 把判断类工作确定化**（playbook / 内容表 / 模板——沉淀后降级为装配类，低档可做）；
> **② 按阶段动态切档**（缺省↔低 两态，失败触发升级、恢复后降级）。
> **状态**：讨论稿。证据全部来自已分析会话；机制已查证到写入点。未领 CV 号。

## 3. 核心框架：两根杠杆

```
        ┌─────────────── 杠杆 A：确定化降级 ───────────────┐
        │  把「判断类」工作沉淀成 playbook / 内容表 / 模板，  │
        │  使其降级为「装配类」——低档即可完成。              │
        │  每沉淀一条，动态档位的切换点就少一个。             │
        └──────────────────┬───────────────────────────┘
                           │
        ┌─────────────── 杠杆 B：动态档位 ─────────────────┐
        │  观测（session/event + probe budget + 失败信号）  │
        │   → 策略表（§4）→ 写 reasoningEffort → 下一请求生效 │
        │  失败触发升级（低→缺省），恢复后降级（缺省→低）。    │
        └───────────────────────────────────────────────┘
```

**两根杠杆的关系**：A 做「静态确定化」（一次沉淀永久受益，切换点减少）；B 做「动态兜底」（沉淀没覆盖到的判断时刻，档位补上）。**只有 B 没有 A** = 档位切换频繁、上下文里全是升级事件；**只有 A 没有 B** = 沉淀盲区里的判断类步骤会躺平（会话 20 实证）。

### 杠杆 A · 确定化清单（已具备的沉淀素材）

### 杠杆 B · 分相策略表 v1（动态档位）

| 触发条件（观测） | 切换动作 | 依据 |
|---|---|---|
| 会话开始（创作任务路由命中） | **low**（A2/B0-B7 内容表在场，装配为主） | A2 全程 low 质量达标 |
| write_storyboard 成功 | 维持 low（spec 装配段——低是唯一能活的档） | 会话 19：spec 段缺省必爆 |
| **探针预算第 1 次拒收** | **升级缺省**（覆盖规划需要深度）+ 通知 | A2：5 次探针浅规划 |
| **任一工具连续 2 次失败** | **升级缺省**（失败恢复需要判断）+ 通知 | 会话 20：低档不自愈躺平 |
| 升级后首次成功 + N 步 | **降回 low**（恢复装配） | 有界，防升满一轮 |
| 成片交付（finalize） | low（交付复述装配） | — |
| B 版拟真会话（无内容表标记） | **全程缺省**（创作判断为主，不降） | 会话 19 反例是「缺省+无纪律」双因，缺省本身没错 |
| 手动设置优先级 | 用户显式设置 = 该会话的**基线**；动态切换只在其上做**临时升级**（有界），降级不超过用户基线 | 尊重用户成本意图 |

**失败触发升级**比「纯阶段触发」更优的证据：探针规划浅（A2）与下载躺平（会话 20）都不是「阶段开头」能预判的——是**失败发生的那一刻**才知道这里需要深度。阶段触发做初值，失败触发做修正。

## 5. 失败恢复专项（会话 20 案例 → 三层沉淀）

**根因链**：GitHub 直连 30MB 二进制挂 1886s（组件下载无超时，Bug A）→ 报错文案给的放置路径与运行时 DSH_HOME 一致但模型 bash 沙箱解析不同（Bug C，双 home）→ 低档模型重试一次即中止（工作性质：失败归因是判断类，低档躺平，**根本问题**）→ 默认档 14 分钟自愈（探代理→镜像→校验→放置，**技巧链完整可沉淀**，杠杆 A-A1）。

| 层 | 动作 | 效果 |
|---|---|---|
| 工具层（治本） | `video-download.ts`：组件下载加超时（≤120s）+ 探测系统代理（`scutil --proxy`）+ 镜像 fallback（ghfast.top 等一进一备）+ 失败文案直接带「已自动尝试 X/Y，剩余手动路径」 | 组件下载对任何档位零思考 |
| skill 层（兜底） | 收集层 playbook：直连挂→探代理→镜像→校验→放置（路径**抄报错原文**，勿用沙箱 HOME 推算）→ `--version` 验证 | 低档照做，3 步收敛 |
| 模板层 | 拆解表样例（11-03 十段格式）挂翻拍清单 | 产出物有对照基准 |

## 6. 成功判据（动态思考强度上线的验收）

| 指标 | 基线 | 目标 |
|---|---|---|
| max-tokens 回合死亡 | 会话19：3 | 0（低档+内容表已达成，动态档不得回退） |
| 探针次数（出片前） | A2：5（3+2 拒） | ≤3（升级缺省后首轮覆盖规划变深） |

| reasoning 总量 | A2：298k | ≤450k（升级段会增加，但步数/返工减少对冲） |

## 7. 开放讨论点

1. **升级的边界**：失败触发升级有界（N 步降回）——N 取多少？建议 5 步（一次返工循环的量级）；
2. **用户意图冲突**：用户显式选低 = 成本意图，Host 升级是否违背？建议：升级仅发生在「失败恢复」与「探针规划」两个实证需要深度的时刻、有界、且通知（批 1.1 同款）——透明且可关（设置项）；
3. **B 版钉死缺省**是否成立？（会话 19 反例 = 缺省×无纪律双因，纪律已由批 2 闸兜住后，缺省的 B 版理论上不会重演 19）；
4. **网关 medium/high 无差异**是否提上游需求？若 medium 未来真有中间档，「探针规划=medium、失败恢复=缺省」可以更细；
5. **杠杆 A 的沉淀边界**：哪些判断类工作**不该**确定化？（拆解表的内容判断、读图后的审美取舍——沉淀过度会把测试变成填空，B 版的测量使命就失效了）。

## 7.5 档位实测定论（2026-11-09，落定）

| 档位关系 | 结论 | 证据 |
|---|---|---|
| **缺省 vs low** | **有实效**——同一管线下 reasoning P95 61k（缺省，会话 19）vs 12.7k（low，A2）；A2 全程 low 质量像素 5/6 | 三场会话 analyzer |
| low / medium / high 三档之间 | **未见差异**（2026-11-06 探针测试）——medium/high 按「未验证」记账，动态策略不依赖它们 | `model-directory.ts:127` 注记 |
| minimal（=none） | reasoning=0 真关 | 同上 |

**⚠️ 机制修正（用户实测澄清，2026-11-09）**：翻拍会话（fab7582b）中用户**中途手动调整过思考强度**，但 5 个 request/header 的档位均为 None（=缺省快照）——说明 `agent-default-model.reasoningEffort` 的中途修改**对运行中的 agent 不热生效**（命名语义「default」= 新 agent 的缺省快照）。两个推论：
1. **杠杆 B（Host 动态档位）从「可选项」升为「唯一可行路径」**——手动改设置影响不了运行中的会话，只有写运行中 agent 的请求配置才能中途切档（写入 API 形态查证不变）；
2. **转录可观测性缺口**：request/header 只记请求时刻的快照，手动调整不留事件——analyzer 无法归因手动变化。Host 动态写入则每次切换自带事件（可观测优势，v2 设计加分项）。

**因子矩阵修正**：fab7582b 的 turn1/2 档位标记由「低（口述）」改为「不确定（快照=缺省；用户中途有手动调整，转录不可见）」——该场「低档躺平 vs 缺省自愈」的对照降级为**轶事证据**，低档不自愈的主判据改依 A2 场的探针浅规划 + ML-13 收口不彻底。
