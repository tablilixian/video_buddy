整理画布 · 推进阶梯

用「项目走到哪一步」组织画布，而不是用「节点是什么类型」；血缘用 来源 chip + 聚焦链路 表达，不再画全屏回环线。

血缘方向恒左→右 孤立节点不隐藏 版本折叠 v3 · 2 历史

1推进过程 = 阶段节，不是类型桶

现有历程视图按「创意/分镜/音频/成片/其他」分节，是分类而非流程，还留了个垃圾桶。改为按生产顺序排 6 段，每段写清「这一步在做什么 · 产出几个 · 卡在哪」。

2父子关系 = 三层分级，不是全屏连线

同镜靠托盘框；跨一步靠来源 chip（↑ 分镜 3 · 关键帧）；深链靠选中后的聚焦视图。任何一条线都不跨越 3 个以上的节点，杜绝反向回环。

3孤立节点 = 显式区域，不是隐藏开关

无血缘、断链（来源已删）、无镜号三类分开列，每条给原因与动作（挂到镜 N / 设为参考 / 归档 / 删除）。默认可见，避免「我的素材去哪了」。

页签结构（替换现有的「整理布局 / 历程视图」两个入口）： 整理画布页签 = 一个只读投影层 + 两种模式。默认进推进阶梯（本节，按阶段排布、不写盘）； 需要手工摆位时切自由画布（写 node.x/y，坐标照旧落盘）。 推进阶梯从不改数据 —— 与现有历程视图同一纪律：布局只是投影，切模式不动任何节点。

处置动作：挂到镜 N（写 parentId + 补镜号）· 设为参考素材（isReference）· 归档（retired，保留可恢复）· 删除（二次确认）。 这三类判据与整理布局同源，不新增状态：sourceIds.length === 0 且未被引用、sourceIds 指向已删 id、isShotCard 但标题解析不出镜号。

进度口径：待归档节不计入顶部 done/total —— 它不进主链，计进去会让"还差 6 个"永远清不掉。节头单独给"4 项待处置"，处理完该节自动塌缩消失。
为什么不做全屏连线：自由画布的血缘边是「来源右缘 → 目标左缘」的贝塞尔曲线，一旦来源被排到目标右侧（例如定稿便签落在成片栏），曲线就会横穿整个画布形成回环 —— 这正是现在整理后「箭头从右往左」的成因。 推进阶梯把连线降级为三种低成本表达，只在用户主动选中时才展开单条链。

竞品光位拆解表便签无来源、也无下游引用设为参考素材 · 归档 · 删除

判据全部复用既有字段（sourceIds / supersededBy / isShotCard / parentId），不新增持久化格式；"归档"即 retired: true，可恢复。
