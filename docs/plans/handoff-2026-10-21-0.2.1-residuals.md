## 二、本次修好的三层根因（commit `95e244b2ea`）

排查路径：**不要**再靠 CDP 猜。三层都是「静态可证」的：

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 页面只有 framed shell 底座 | `dsh-client-ui-workspace@0.2.1` 的 inject 新增了 `layout`（0.1.1 是 `[slots,sessions,workspaces,locale,connection]`，现在是 `[…,layout,shortcuts,remoteAccess]`），而 `ui-layout` 行被桌面 patch 关掉 ⇒ `layout` 只能由画布 provide。画布顶层 inject 又含 `uiWorkspace`/`uiConversation` ⇒ **成环**，两边 fiber 永不 ACTIVE | 拆两个座位：顶层 `inject=['slots']` 只提供 `layout`；原清单改名 `STUDIO_CLIENT_INJECT` 交给 `ctx.inject()` 起子 fiber |
| 2 | `plugins: Unknown client plugin` + 30s 超时进恢复模式 | 桌面客户端 inject 里的 `settingsScope` 是 **0.1.x 孤儿**（0.2.1 全仓无人提供）⇒ fiber 永不 ACTIVE ⇒ 上报器不启动 ⇒ 主进程零上报 | 删掉该项；同时给 `loader.await()` 加 20s 上限（<30s 宿主门），超时也上报并**点名卡住的插件** |
| 3 | 修完 1、2 后仍 `dsh-plugin-desktop: failed` | `applyDesktopSettings` 一进来就 `ctx.configForms.get(...)`，而 `configForms` **不在 inject**；0.2.1 的 proxy 对未声明服务**直接抛**（`cannot get property "x" without inject`），0.1.x 不校验 ⇒ 升级后静默炸 | inject 补 `configForms`；`ctx.loader`→`ctx.get('loader')`、`ctx.uiWorkspace`→`ctx.get('uiWorkspace')?.`；`apply` 每步包 `step()` 打步骤名+栈 |

### 可复用判据（已写进 `MEMORY.md` 铁律）

1. `ctx.<svc>` 只要 `<svc>` 不在 inject 就**直接抛**，且 boot 汇总对 `failed` **只打插件名、吞异常**。扫描法：`\bctx\.([A-Za-z_$][\w$]*)` 扫 `src/client/**`，减去 inject 名单与 cordis 内建。
2. inject 成环 ⇒ 双方永不 ACTIVE ⇒ 空壳。「先 provide 再等」的服务**必须拆两个座位**。
3. 上报器里 `loader.await()` **必须加超时**，否则一个 fiber 卡住 = 一个字节都发不出去 = 报错里啥也没有。

## 六、是否需要合并到 dev（结论 + 依据）

### 事实

| 事实 | 数据 |
|---|---|
| 分支规模 | 相对 `origin/dev` **24 commits / 123 files / +13945 −11519**，其中 `yarn.lock` 单文件 ±19.6k 行，`patches/` 整体从 `0.1.1-rc.2` 换到 `0.2.1-rc.2` |
| 拓扑 | `origin/dev` 是 HEAD 的**直接祖先**（可 fast-forward，0 behind）；dev 最后一次提交 2026-10-20 14:05，分支从 14:29 起 —— 期间 dev 没动过，**无并发冲突** |
| 门禁 | 项目门 `yarn check` 含各 workspace 的 `check`（canvas 含 `test:smoke`）⇒ 当前必红。CI 只在 **master**（push/PR）触发，**dev 无自动保护** |
| 运行环境耦合 | 运行时 checkout 就在 `dev`。合进 dev + 用户 pull ⇒ 日常运行环境**整体换代**（需重 `yarn install`、新 patch 集、0.2.1 包） |

### 判断

1. **不是「能不能合」的问题，是「合了什么时候生效」的问题。** 技术上随时可 FF 合入；但 dev 是你的日常运行线，合入即换代，剩下的红会直接落在你每天用的环境里。
2. **也不能等「所有小问题都修完」。** 17 红里 13 条是断言追平（半天量级），而 `web-search-hybrid` 要等**上游**发版，可能几周 —— 拿它当阻塞项等于把分支无限期挂着，24 commits 继续长，`canvas-studio/src/client/index.ts` 还会和 dev 上的功能开发分叉（这个文件本次刚被大改）。
3. **分两步合，中间不动 dev：**

| 步骤 | 动作 | 出口条件 |
|---|---|---|
| 第一批（现在 → 1 天内） | 在 `upgrade/dsh-0.2.1-rc.2` 上清红：修 4 条真问题 + 改 13 条断言 + 登记必须等上游的项 | `yarn check` 全绿（或红项**只**剩明确登记「等上游」的，且写进 `baseline-red.json` 并注明原因） |
| 第二批（绿后立刻） | `git switch dev && git merge --ff-only upgrade/dsh-0.2.1-rc.2`，随后打 tag `v0.2.1-rc.2-upgrade` | 用户在运行时 checkout `git pull` + `yarn install` + `yarn dev` 跑通一次真机冒烟 |
| 收尾 | CV 号登记（三层入库）+ 本文档归档进 `docs/plans/` | — |

**为什么不用 merge commit**：dev 是 HEAD 的直接祖先 → FF 合入保持线性，回滚只需 `git reset --hard <tag 前>` + force push（可接受）；真要留痕就打 tag。

## 七、本次踩过的坑（别重复）

1. **测试输出接 `grep | head` = 全程看不见进度，也无法判断卡没卡。** 本次桌面全量跑到 21 分钟仍无输出、进程也查不到，实际是管道缓冲把一切吞了。**正确姿势**：`corepack yarn vitest run --reporter=dot > /tmp/x.log 2>&1`，再 `tail`/`wc -l` 看增量。
2. **桌面全量在沙箱里会长时间停滞**：`--reporter=dot` 直写文件后，日志曾在 25KB 处**冻结 6 分钟以上**（101 个 spec，单文件只需 3~20s）。原因未查明（疑似某个 spec 在并发下不退出，或 file-parallelism 在沙箱里失衡）。**工作法：逐文件单跑**，别跟全量搏斗。
   ```bash
   for f in tests/*.spec.ts; do echo "$(date +%s) $f"; ./node_modules/.bin/vitest run "$f" >/dev/null 2>&1; done
   ```
3. **`--reporter=basic` 在这个 vitest 版本不存在**（会报 `Failed to load custom Reporter`，看起来像全军覆没，其实是参数错）。可用：`dot` / `default` / `verbose` / `json`。
4. **`ps` / `pgrep` 在受管 shell 里看不到别的进程树**，据此判断「进程没了」会误判。
5. **`git add` 带不存在的 pathspec 会整体失败**；暂存后必须 `git diff --cached --stat` 复核条数与文件。
6. **长中文行整行 Edit 匹配不可靠** ⇒ 用 node 脚本按行号改（带 assert 前缀校验）。本机 `python3` 可能报 `No usable temporary directory`（`sitecustomize` 报错），此时改用 node。
