# 制作方式分类学分册 —— 拆解表「制作方式」列 / 复刻路径选择

> 本文是 `viral-remake` 的细则分册，服务 `references/remake-mapping.md` §1 拆解表的
> **「制作方式」列**。判制作方式**只为了选复刻路径，不是为了炫技，更不是像素还原承诺**
> （边界见 `SKILL.md` §6）。本册只写分类口径与路径选择；轨道字段级映射一律以
> `references/remake-mapping.md` §2 为准，不重复字段契约。

## 1. 为什么要单列一列

同一个「数据卡」镜头，底层是三维渲染还是图文模板，决定它该走生视频还是直接铺轨道；
一支片里「实拍 + 后期字幕」混着出现，若「内容类型」只写「实拍段」，字幕层该用哪条轨
在 §2 映射时就会丢掉。所以拆解表把「画面主体是什么」与「像素怎么来的」分开：

- **内容类型**（既有列）：画面主体是什么 —— 实拍段 / 静帧图 / 口播字幕 / 文案卡 / 数据卡 / 节奏装饰。
- **制作方式**（本列）：底层画面的像素从哪来 —— 见 §2 八类。
- **叠加层**（写进本格备注）：底层之上后期加的字幕 / 花字 / 贴纸 / 版式底图，与底层分开标。

## 2. 八类标签（本仓裁剪口径）

外部参考实现给 10 类；本仓**没有数字人口播、2D 动画、定格动画的对应生成通道**，
故裁成 8 类，三类兜底合并为「AI/其他」，不硬猜子类。

| 标签 | 含义 | 典型画面特征 | 拿不准时 |
|---|---|---|---|
| 实拍 | 摄影机拍的真实画面 | 人物 / 实物 / 场景，镜头运动与颗粒感自然 | 平台转码会让实拍显得「平」，**别据此改判渲染** |
| AI 视频 | 文生 / 图生视频模型产出 | 运动连贯但细节漂移，常带平台生成标识 | 与三维难分 → 写「AI 视频（存疑）」 |
| 3D 渲染 | 三维引擎渲染 | 材质均匀、边缘干净、光照物理一致 | 与模板渲染难分 → 归 3D |
| 代码/模板渲染 | 代码、图文模板、动效图形直接出画 | 纯色块 / 规整排版 / 文字层清晰 / 大面积平坦区域 | **本仓最强项**，符合特征优先判 |
| 录屏/截图 | 真实界面被录下或截下 | 窗口边框、光标、界面控件、密集小字 | 截图贴在卡片里也算，备注「嵌入」 |
| 静图推拉 | 一张静图 + 缓慢推近或平移 | 全画面同步位移，画面内部无独立运动 | 与静帧的区别只有一个：有没有动 |
| 静帧 | 一张图定格不动 | 连续多帧几乎无变化 | — |
| AI/其他 | 2D 动画 / 定格 / 数字人 / 确实判不出 | 无对应生成通道 | **允许写「存疑 + 理由」，禁止为填满列硬猜** |

**叠加层单独记**，格式 `底层=AI视频 / 叠加=代码字幕 + 静态图形`。叠加层的像素是后期
由代码或编辑器加的，不算进底层制作方式。落地时底层走 video / image 轨，叠加层走
caption / textCard / shape 轨，逐层对应 §2 映射表。

## 3. 真实素材 vs 参考素材（「素材需求」列必须两分）

最容易混的一处，两者对复刻的约束力完全不同：

| | 真实素材 | 参考素材 |
|---|---|---|
| 是什么 | 画面里**真实存在的像素**：实拍片段、照片、界面截图、录屏、嵌在卡片里的视频 | 生成画面里「画的是什么」：商品长相、Logo、人物外形、场景氛围 |
| 复刻时 | **必须向用户要文件**，模型重造不出来 | 只作生成条件 / 提示词约束，不给文件也能出 |
| 拆解表写法 | `user:<文件名或来源>`（真实素材） | `ref:<描述>`（参考素材） |
| 缺失后果 | 整段复刻失真，且无法靠提示词补 | 观感偏移，可后补 |

判据一句话：**像素是不是从外部真实世界搬进画面的**。是 → 真实素材；只是「长得像什么」
→ 参考素材。嵌入区域（照片贴进三维场景、界面里播的一段视频）也要单列，别被底层
标签盖掉；`素材需求` 列沿用既有 `user` / `generated` / `library` 来源标，两分写在括注里。

## 4. 制作方式 → 复刻路径（本列的唯一用途）

| 制作方式 | 复刻路径 | 备注 |
|---|---|---|
| 实拍 | 生视频近似 / 给用户拍摄方案 | 结构复刻，别承诺像素还原 |
| AI 视频 | 首尾帧生视频 或 多参考合成 | 参考素材走 `ref:` 条件 |
| 3D 渲染 | 轨道近似（形状 + 动效）或生图打底 | 复杂度高时如实说明退化 |
| 代码/模板渲染 | 直接铺 CompositionManifest 轨道 | **优先走这条，不要绕去生视频** |
| 录屏/截图 | 登记真实素材，让用户自备文件 | 模型不该重造界面 |
| 静图推拉 | 一张图 + 测得的推拉幅度 | 本地零成本，优先复用 |
| 静帧 | 一张图定格 | — |
| AI/其他 | 先按最接近的通道试，并向用户说明不确定 | 不准把「存疑」写成确定结论 |

## 5. 填写纪律

- **逐镜一值**，复合镜用 `底层=X / 叠加=Y` 写在同一格，不拆行（拆行会打乱镜序与转场接续）。
- 画面判据**看图本身**：本地抽帧 / 素材先用 `read_image(file_path=…)` 看图给语义，
  精确数值用 `inspect_image`；`video2vl` 的文字转述仅作保底且**不可当事实**。
  **禁拿 manifest 字段自证画面**。全契约见 `canvas-studio-creation/references/toolchain.md` §7。
- 平台转码样片容易把实拍误判成渲染；判不出就写「存疑 + 理由」，不要靠猜补齐。
- 本列**不参与时序回核**：`verify_teardown` 只管段边界，制作方式判错是在 §2 映射时改路径。
- **制作方式 ≠ 复刻承诺**：填了「实拍」不等于能还原那台摄影机的画面，见 `SKILL.md` §6。
