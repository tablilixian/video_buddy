## 0. 结论摘要

| 项 | 现状 | 目标 |
| --- | --- | --- |
| 风格的载体 | 澄清问卷里的一个选项（一次性文字） | 项目级 **Look 卡**，与角色卡平级、逐镜自动注入 |
| 风格入口 | 固定一条：先选大类 → 再选具体风格 | **两种采集方式**（文字反推 / 参考图·视频归纳）汇入同一张卡，用户不选分类 |
| 风格首次可见 | 工作流第 6b 步（关键帧审批），隔几十次生成 | **第 2a 步一张样张**，成本 1 张图 |
| 改风格的成本 | 逐镜改 prompt、逐镜重出 = N 次生成 | 改 tokens → 只重出样张 = 1 次生成 |
| 长尾需求（古装电影 / 真实战场） | 落空，无出口 | 走反推，永远有出口 |
| 预设的地位 | 必经关卡（入口） | 对样张不满意时才摆出来（出口） |

**实施路线**：Phase 0（澄清改造，纯文档）→ Phase 1（采集接线，含补掉「参考图无归纳」的缺口）→ Phase 2（Look 卡资产化 + 注入纪律）→ Phase 3（预设降级 + UI 收口）→ Phase 4（风格质检，可选）。

Phase 0 + 1 即可交付可用版本；Phase 2 是"与角色卡平级"的完整形态。

## 1. 问题诊断

### 1.1 四个困扰其实是同一个根因

| 用户原话 | 表面现象 | 真实落点 |
| --- | --- | --- |
| 「动画叙事」我总以为是拍动画片 | 标签语义误导 | 大类名是"行业+形态"混称，实际含 3D 动画 / 合作游戏开场 / 东方神话三类 |
| 想拍古装电影风格，找不到合适的 | 无预设 | = **写实 look + 剧情用途**，11 条里没有这个组合 |
| 想拍真实战场风格 | 无预设 | = 写实 look + 战争题材；且**"题材"这个维度压根没被问过** |
| 想照参考图那个风格 | 无入口 | 机制**已存在**（贴图 = role=style；参考视频 → 抽帧 + VLM 归纳），但澄清流程里没有这条路 |

**根因**：**视觉 / 用途 / 题材三个维度被压进了一个枚举里。** 于是继续加条目永远追不上长尾 —— 枚举是给**已知组合**准备的，参考是给**未知组合**准备的。

### 1.2 现有设计的合理性与代价

现在这套（4 大类 + 11 预设）不是"名字起得差"，它是**当时的合理解**，因为它同时背了三个约束：

1. 用户要点按钮 → 选项必须 ≤2–4 项；
2. 必须 1:1 映射到一个上游 skill **和**一张画布预览图；
3. 不让模型自造风格名（否则画布匹配不到预览图）。

三者挤在一起，就收敛成了「品类枚举」。代价正是上文四条：**只覆盖"有专属流水线"的 11 种组合，长尾全落空。**

关键区分：**古装电影、真实战场不是"风格"，是"题材"。** 它们不需要专属流水线，只需要一份可复用的视觉约束。

有一个现成论据支持改造：11 条预设里**只有「东方神话视觉导演」是偏"视觉方法论"而非品类**（`style-presets.md:34`）—— 兜底范式其实已经存在，只是没被当成通用出口。

### 1.3 附带发现：编号漂移（CV-116 同类）

`style-presets.md:7` 与 `:54` 还写着「需求澄清**第 ④ 步**从这里点选 / 按**第 ④ 步**的风格大类推断」，但澄清早已从 6 问收敛成 3 问（① 形态 → 2a 大类 → 2b 具体风格），**根本没有第 ④ 步**。会让模型在"该读哪一步"上产生歧义。

> 注意别误改：`SKILL.md:66`、`consistency.md:9` 的「第 4 步」指的是**工作流第 4 步「建一致性资产卡」**，那个是对的。

## 2. 行业对标

| 产品 | 风格怎么表达 | 对我们的启示 |
| --- | --- | --- |
| Midjourney `--sref` / 风格码 | 参考图 + 编码，表达空间无限 | **从不需要覆盖"古装电影"** —— 参考本身就够 |
| Runway Gen-4 `@Hero` / `@Texture` / `@Location` | 显式命名分工，不靠自动猜 | 我们 `role` 已是 character/scene/style，只缺 style 的建卡路径 |
| Google Flow | 情绪板（Whisk）**先于**生成；preset 非必经 | 风格是"先定后产"的资产，不是"先选后判"的选项 |
| LTX Studio | preset 自我描述为 "quickly explore creative directions" | 预设是**加速器**，不是**入口** |
| 中文生态（即梦 / 可灵） | 风格基准卡沉淀进资产，系列短剧复用 | 与我们痛点最像，做法最接近我们缺的那一环 |

**三条硬共识**：

1. **never describe what you can reference** —— 视觉风格由视觉锚点承载，文字只负责"内容"。
2. **preset 是加速器，不是入口** —— 我们把它做成了必经关卡，这才是"容易被名字误导"的根源：用户被迫在一个自己不需要的分类体系里做选择。
3. **look / 角色 / 题材是三次独立操作** —— Flow 里 look 归情绪板、角色归 Ingredients、题材归 prompt。我们把它们压进了一次点击。

## 3. 目标设计

### 3.1 核心：不做两套流程，只做两种采集

用户提的两种情况（① 只给一句创意 ；② 创意 + 参考图）**唯一的本质差别**只在于 Look 的信息来自**文字**还是**图像**。所以不做两套流程，而是让两条路**汇入同一个产物**。

```
情况 1：一句创意 ──┐
情况 2：参考图  ──┼──▶  5 项 tokens（同一份）  ──▶  Look 卡  ──▶  逐镜自动注入
       参考视频 ──┤
       预设选择 ──┘
```

**四种输入 → 同一份 5 元组 → 后面完全同路。** 这就是"一套产品线覆盖两种情况"的实现方式。

### 3.2 5 项 tokens 规格（含「从创意反推」的定义）

**"从创意反推 5 项 tokens"** = 用文字走一遍 `video-style.ts` 已经在图像路径上做过的事。

- 视频/图片路径：**看**一帧画面 → 归纳出 5 类参数；
- 创意路径：**读**用户一句话 → 归纳出同样 5 类参数。

**"反推"的方向**：用户说的是**具体**（民国、雨夜、旗袍、弄堂、老电影），tokens 是**抽象**（色彩 / 光线 / 材质 / 镜头语汇 / 节奏）。**从具体推出抽象 = 反推。** 方向与现状相反：

| | 信息流 |
| --- | --- |
| 现状 | 用户想法 → **归类进已有分类** → 预设 → prompt（分类问题） |
| 目标 | 用户原话 → **拆成 5 个视觉自由度** → tokens（提取问题） |

**为什么是这 5 项**：色彩 / 光线 / 材质 / 镜头语汇 / 节奏是视觉风格的一个**完备基** —— 任何一种 look，无论 11 条预设里的还是长尾的"真实战场""古装电影"，都只能用这 5 个自由度表达，多一个不多、少一个不够。正因如此，它才能当**汇合点**。

**这 5 项不是新发明的**。`src/video-style.ts:39-41` 的 `STYLE_PROMPT` 已经在要：

```
覆盖：色调与调色、光线、构图与镜头语言、材质质感、美术设定
```

**维度是现成的**，缺的只是产物形态 —— 它现在输出"不超过 6 条"的自由要点文本，而不是可寻址的字段。

**判定标准（tokens 必须同时满足）**：

1. **完备** —— 任何风格都能塞进这 5 个格子，不出现"其他"；
2. **可改** —— 改一项不影响其他项（"再暗一点"只动「光线」一行）；
3. **可复用** —— 逐镜注入同一份字段，措辞不变；
4. **可定位** —— 样张不对时能指到具体哪一项（"不是光线的问题，是材质太新了"）。

**为什么必须结构化、而不是让模型直接写一段风格描述**：自由文本一改就牵连全段、跨镜复制会漂移、样张不对说不清问题项。结构化把这三个缺陷同时消掉。

**反推的固有风险（必须承认）**：反推是**推断**，就可能推得平庸或推错。你说"老电影"，它可能给一套很泛的"复古胶片感"，而你想要的是特吕弗那种。**这正是"样张"存在的理由** —— tokens 不对时不必跟它争论文字，直接看一张图说"不是这个感觉，光线再硬一点"。**文字反推负责给起点，样张负责给判据。少了样张，"5 项 tokens"就只是一段听起来挺像那么回事的文字。**

### 3.3 四条关键机制

**① 样张回显（把首次可见从第 6b 步提到第 2a 步）**
Look 草稿出来先出**一张样张**（不是全套），落画布让用户看，再问「就是这个感觉 / 换一批 / 我来说说 / 你按题材帮我定」。成本 1 张图，换掉后面几十次生成的跑偏风险。

**② steer 作用于 Look，不作用于镜头**
"再暗一点"改的是 tokens，只重出样张。**一次审美判断从 N 次生成降到 1 次。** 过了样张阶段再改 look，必须提示影响面（定妆照与已出关键帧要重出），让用户选"只影响后续 / 全部重来"。

**③ 两段式注入（与角色卡完全对称）**
每镜 prompt = `Look lockedPrompt` + `角色 lockedPrompt` + 本镜动作。不再靠"用第一张成图做参考"这种口口相传。

**④ 预设从"入口"降级为"出口"**
只有用户对样张不满意时才摆出来。这时他是**拿预设跟一张具体的图比较**，而不是凭空选名字 —— 这才是真正解掉"被名字误导"的地方。而且"有没有参考图"可以自动检测，**所以连起点问题都不用问**。

### 3.4 与风格 skill 的关系（最容易出 bug 的地方）

现状：2b 选中预设名 → 加载对应风格 skill → 该 skill 的 STEP 流程接管（`style-presets.md:11`）。

改造后必须写死的规则：

| Look 的来源 | 是否加载风格 skill |
| --- | --- |
| 用户直接点名（"使用技能『3D 动画短片』"） | **是**（既有行为不变） |
| 用户在"出口"处选了预设 | **是**（预设 ↔ skill 1:1） |
| 参考图 / 参考视频 / 一句描述反推 | **否** |

不加载的理由：不命中专属流水线时加载风格 skill，会把错误的流程约束套上去（**给古装电影套"纸艺定格"的 STEP**）——这是必须防的灾难。

### 4.3 三个必须注意的实现细节

1. **`resolveAssetSlot` 只按 `name` 匹配，不看 `role`**（`src/generate.ts:1450`）→ 若 Look 卡与角色卡同名会互相覆盖。规则：**Look 卡命名加固定前缀**（如「Look · 民国雨夜」），并在文档里写死。
2. **`character_sheet` 里 `role` 是硬编码的 `'character'`**（`src/generate.ts:1526`）→ Look **走独立工具**，不要在这个工具里加 role 分支（保持单一职责，也避免破坏角色卡既有语义）。
3. **参考图超出 3 张会被静默丢弃** —— `src/generate.ts:1104` 的 `(params.filenames ?? []).slice(0, 3)` **不报错、不警告**：第 4 张图凭空消失，外部表现为"风格/角色没生效"却毫无线索。这是本项目最容易误诊的一类故障（与 CV-145 的"1×1 占位图误判"同类 —— 都属于**证据缺失导致的错误归因**）。
   - **Phase 1 顺带加固**：`filenames.length > 3` 时**显式告警**（工具结果 `warnings[]` 或工具错误），并说明"仅前 3 张生效"。
   - 该加固独立于 Look 功能的价值：任何调用方多传一张都会中招，属**潜伏缺陷**（当前靠 `host-tools.ts:668` 的描述文字约束 agent 行为，**无代码兜底**）。

### 4.4 参考图席位的取舍：视觉锚点应取代 `image3` 而非新增第 4 张

一个容易搞错、但结论很有用的细节：**Look 若要视觉锚点，不需要新席位 —— 它可以取代现有的 `image3`。**

| | `image3` 当前占用者 | Look 样张 |
| --- | --- | --- |
| 内容 | **首镜成图**（含角色与场景，有内容） | **基调样张**（中性主体，只承载视觉） |
| 可用时机 | 第 6 步首镜出图**之后**才存在 | 第 **2a** 步就有 |
| 用途 | 全局风格统一（顺带带入首镜内容） | 纯粹的风格锚点 |

**结论**：做风格锚点时，**样张严格优于"首镜成图"** —— 它更早可得，且**不把首镜的内容混进风格参考**。因此规则应是：

- 走 Look 卡、且需要视觉锚点 → **占 `image3`，取代"首镜成图"**（不是插入第 4 张）；
- 走 Look 卡、但不需要视觉锚点（tokens 已足够）→ 不占任何席位（**已拍板的默认**）；
- 两者都不改变 3 个槽位的**总数**，因此不触碰后端契约。

> 记入 `look.md`；`consistency.md:23` 的"第 3 张传首镜成图"改为"第 3 张传 Look 样张（未建 Look 卡时退回首镜成图）"。

## 5. 分层落地路径

| 层 | 内容 | 架构风险 | 依赖 | 建议 |
| --- | --- | --- | --- | --- |
| **L0** | 澄清改造：加出口、删风格两问、补编号漂移 | 无（纯文档） | — | **先做** |
| **L1** | 采集接线：参考图归纳 + tokens 化 + 样张 | 低 | L0 | **先做** |
| **L2** | Look 卡资产化 + 两段式注入纪律 | 中（增工具、注入席位） | L1 | 第二轮 |
| **L3** | 预设降级为出口 + 风格库 tokens + UI 收口 | 中（动 `STYLE_DEMO_MAP` 四处联动） | L2 | 第三轮 |
| **L4** | 风格质检（`qc_shot` 支持 style 基准 / `qc_look`） | 中 | L2 | 可选 |

**L2 为什么不能省**：L0+L1 解决了"入口"与"可见性"，但风格仍是**单次、易失**的 —— 只有落成卡，才真正做到"只定义一次、逐镜自动注入"，也就是与角色卡平级。

## 7. 契约草案

### 7.1 Look 卡数据形状：两个选项

**选项 A（推荐，L1/L2 采用）—— 不扩契约**

复用 `StudioAsset`，`role: 'style'`，把 5 项 tokens 序列化进 `lockedPrompt`：

```
色彩：低饱和青灰打底 + 钨丝灯暖黄点缀，保留「彩色里的旧」
光线：单一实用光源（路灯 / 门灯），大光比，湿地面反光当补光
材质：湿青砖、木质窗框、旗袍绸缎的低光泽
镜头语汇：中长焦、浅景深、固定机位或极缓推，门窗框景
节奏：慢、留白、长镜头呼吸
```

理由：`lockedPrompt` 的语义本来就是"逐字节复用的冻结文本"，**5 行带标签文本天然满足**。零契约改动、零迁移、`list_references` 原样返回、`version` 不用 bump。符合"最小对齐"。

**选项 B（L3/L4 再考虑）—— 加 `tokens?: LookTokens` 结构化字段**

```ts
export interface LookTokens {
  color: string      // 色彩与调色
  light: string      // 光线
  material: string   // 材质
  camera: string     // 镜头语汇
  rhythm: string     // 节奏
}
// StudioAsset 增加： tokens?: LookTokens
```

只在**需要"逐项 diff / 逐项可编辑 UI / 逐项质检打分"**时才值得加 —— 那时收益明确，且需 bump `StudioCanvasDocument.version` + 迁移（缺失视为无 tokens）。**不要预先加**。

## 8. 必须定死的边界（无论走哪个 Phase）

1. **走 Look 路径时不加载任何风格 skill** —— 否则会把错误流程约束套上去（给古装电影套"纸艺定格"的 STEP）。
2. **tokens 里不写预设名** —— 名字写错会让画布匹配不到预览图与 skill。
3. **参考图席位规则（必须选一个并写死）**：
   - 上限的**来源**：后端 `image2image` 端点只有 **3 个具名槽位** `image1` / `image2` / `image3`（权威契约见 `docs/api-probe/contract-20260910/contract.md`：`POST /api/v1/generate/image2image` → `image1("")` / `image2("")` / `image3("")`，**没有 image4**）；本地 `src/generate.ts:1104` 用 `(params.filenames ?? []).slice(0, 3)` 对齐，`host-tools.ts:668` 的描述同步声明"最多 3 张"。
   - **静默截断风险**：`slice(0, 3)` **不报错、不警告** —— 第 4 张图会凭空消失，表现为"风格没生效"但无任何线索（见 §4.3 第 3 条）。
   - **当前占用**：`image1` = 角色锚点拼图、`image2` = 场景概念图、`image3` = 首镜成图（仅"需要全局风格统一时"，`consistency.md:23`）→ 常规 2/3，多角色同镜 3/3 吃满。
   - **推荐（已拍板）**：**Look 优先走文字注入（tokens 已在 prompt 里），不占参考位。**
   - **若要视觉锚点，应取代 `image3` 而非新增第 4 张** —— 见 §4.4。记入 `look.md`，并同步 `consistency.md:23`。
4. **贴图可能是"内容参考"而非"风格参考"**（"我要拍这个人"）→ 回显时 role 选「角色」→ 该进 `character_sheet` 而不是 Look 卡。这一步顺带把两套资产接上。**附件 role 目前是自动标记的**（`src/client/index.ts:338`，`role=image`），所以必须在对话里**显式确认一次**，不能沿用自动假设。
5. **多张参考图风格冲突**（一暖一冷）→ 行业经验：1–3 张且必须说明每张管什么。
6. **用户说"你定吧"** → 样张照出，但默认要**可见**，不能静默假设。
7. **样张反复不满意** → 限 3 轮，然后引导"给我一张参考图"（与 CV-141 的 `budget=2` 同一精神）。
8. **样张文案必须说清"这是基调样张，不是最终画质"** —— 否则用户会拿它当成品预期。
9. **未命中组合没有画布预览图**，不能假装有（需求摘要如实写「未匹配专属风格，按通用规范执行」）。
10. **`lockedPrompt` 必须经用户确认后再冻结**（照 `consistency.md:10` 的角色卡纪律）。
