## 4. B3 / B4 / B5 解释（用户要求）

### 4.1 B3 · 文本纪律下沉宿主硬闸

**现象**：会话 15 把 `SKILL.md` 三条纪律（首轮探针 / 看图取证 / 负例必发）**全读了一遍**，结果：负例没发、13 条 `report.lint[]` 没读、数据仍混基准。结论是「写了、读了、不做」——纯文本纪律对模型没有强制力，尤其当遵守纪律要花时间时。

**「宿主硬闸」是什么**：把纪律从 skill 文档挪到**工具层的状态位**。模型无法用一句「我认为不必」绕过，因为工具回执 / 结案动作会直接拒收或带缺口标记。三个候选：

| 候选 | 落点 | 成本 | 风险 |
|---|---|---|---|
| ① 负例必发闸 | 交付/结案动作检查「本次会话是否有拦截回执」，缺则不给结案 | 低 | 需定义什么算「拦截回执」 |
| ② 体检复述 | 渲染回执强制输出「计数 + 前 N 条 + 落盘路径」，交付文案必须复述 | 低 | 别把 warning 变成噪音（P-06 同批修判据） |
| ③ 数据核源 | `write_storyboard → render_composition` 桥校验 `dataSource`/`baseline` | 中 | 会让存量 manifest 报红 ⇒ 先 warning 观察期 |

**选项**：(A) 只做 ①②；(B) 三条全做；(C) 先只做 ①。**默认 A**（见 §5 D2）：①② 成本低、直接对应会话 15 的两个缺口；③ 与 P-01 契约同源，放到 B-4 一起做，避免重复改桥。

## 6. 卡点预案（全部预置解法，不需要临时问人）

1. **全量 `test:smoke` 被沙箱 SIGTERM 137、日志 0 字节** ⇒ 用沙箱豁免重跑；仍不行就把 `corepack yarn test:smoke` 交用户终端跑，结果写 `/tmp/smoke-*.log` 再读。**禁止裸 `node --test`**（唯一入口 `yarn test:smoke`）。
2. **绝不 kill Electron** ⇒ 所有重启由用户手动关/开；不做 `kill -9`、不用 TaskStop 停进程、不靠超时中断。锁残留只按点名 `rm`：`~/Library/Application Support/VideoBuddy/identity/installation-id.lock` 与 `...lock.takeover-<hex>`。
3. **git push 必须用户手动** ⇒ H1/H2 已显式列为人工动作；助手只 commit。
4. **git 写被 0 字节 `index.lock` 卡** ⇒ 确认无真 git 进程后 `rm -f .git/index.lock` 重试；只读命令统一 `--no-optional-locks`。**git 写全挂** ⇒ 两档绕行：① index 可写时用 plumbing（`GIT_INDEX_FILE=固定路径 read-tree HEAD && git add && write-tree && commit-tree -F msg文件 && update-ref`，`$$` 跨调用会变必须固定路径）；② index 也挂时用 `hash-object -w`/`mktree`/`commit-tree` 重建 4 层子树 + `printf sha > .git/refs/heads/<branch>`。坑：`awk` 改 `$3` 会破坏 `ls-tree` 的 tab ⇒ 用 `sed` 按 sha 替换；`mktree` 要求 `mode SP type SP sha TAB name`；事后 `rm -f .git/index.lock .git/refs/heads/*.lock && git reset` 由用户终端清。
5. **测到旧码** ⇒ 测试 import `lib/**`（tsc emit），只跑 tsdown 会测旧码。验证链固定：`yarn build`（clean.mjs → tsdown → `tsc -p tsconfig.json` → `tsc -p tsconfig.client.json --emitDeclarationOnly`）→ `verify:loader` → `yarn test:smoke`。
6. **长中文行整行 Edit 不可靠** ⇒ 按行号 python 脚本 + `assert` 前缀校验；**同文件多条 Edit 串行**；模板串内禁反引号 / `${`；变异禁 `sed -i ''`；含反引号的批量替换禁 `node -e`。
7. **BSD grep 不支持 BRE `\|`** ⇒ 用 `grep -E` 或 Grep 工具；`&&` 链首 grep 无匹配会静默中断整条链 ⇒ 用 `;` / `|| true`。
8. **删除闸一次删 >50 必红** ⇒ `CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=100000 <cmd>`（yarn install 的 link 步必用）；`CODEBUDDY_SAFE_DELETE_ENABLED=0` 会报 state lock timeout，别用。
9. **skill 硬闸** ⇒ 总纲 ≤14KB、每个 `SKILL.md` ≤12KB、指针覆盖率 ≥50%；改 `SKILL.md` 后 `wc -c` 复核（当前 code-driven-explainer 11,665 B）。
10. **STATUS 三层登记** ⇒ §4.1 索引行（标题 ≤40 字符、整行 ≤400 B）/ `cv-details.md` 的 `#### CV-xxx` / `changelog.md` 一行；再改 §0 水位 + 文件头（只留最近 3 条）；`node scripts/status-summary.mjs` 重算 §1（**禁手改**）；单行 ≤2KB；闸 = `tests/status-shape.test.mjs`。**不预领号**（取号前 `git log` + STATUS §4.1 复核）、**验收通过后才结项登记**。
11. **两份 checkout** ⇒ 所有代码改动只在**工作仓**做；运行时只 `pull`，不在运行时改代码。不 push 运行时看不到。流程写死：工作仓改 → commit → push → 运行时 pull → 用户重启。
