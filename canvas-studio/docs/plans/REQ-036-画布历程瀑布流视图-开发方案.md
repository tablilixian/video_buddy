## 一、背景与目标

现状：创作产物以「血缘链式」落在自由画布上（[canvas-placement.ts](../../src/canvas-placement.ts)），阶段感弱；「整理布局」是横向泳道（CV-223）且需手动触发。用户希望有一个**纵向创作历程视图**：阶段明确、归属明确、画布整洁，能直观感受"项目在不断产出、进度在推进"。

**用户已拍板的口径**（2026-10-26 讨论）：

1. **双模式**：在现有自由画布基础上**新增**一种展示模式，二者切换，不替换。
2. **排序主轴**：阶段优先（创意 → 分镜 → 音频 → 成片），节内按生成时间。
3. **节点交互不变**：历程视图里的节点仍可点击修改（改提示词、预览、重试等）。
4. **同镜资源聚在一个托盘**：分镜卡升格为托盘头部（归属锚点）。
5. **支持手动拖拽重排**（P2）。
6. **默认隐藏纯文本类节点**（创意需求 / 剧本 / 口播文案 / 便签等），分镜卡除外——它是结构锚，必须显示。

## 二、影响面分析（结论先行：纯增量，不动现有数据与功能）

### 2.1 不影响现有数据的保证

| 现有机制 | 本功能是否触碰 | 说明 |
| --- | --- | --- |
| 节点坐标 `node.x/y`（canvas.json） | **否** | 瀑布流坐标是**运行时投影**，只替换渲染层的 transform，从不写回节点，也不落盘 |
| 节点尺寸 `node.width/height` | **否** | 历程视图用标准缩略盒渲染，不改节点真实尺寸 |
| canvas-placement 落点算法 | **否** | 自由画布的落点逻辑原样保留 |
| CV-223 整理布局 / 镜位框 | **否**（复用不修改） | `computeShotLanes` 等纯函数只读复用 |
| 血缘边（sourceIds / CanvasEdges） | **否** | 历程模式下隐藏连线、改用「镜 N」角标表达归属；自由画布模式不变 |
| canvas.json 版本（`CANVAS_DOCUMENT_VERSION = 6`） | **否，不升版** | 仅给 `view` 增加可选字段（见 §4.1），老文档缺字段 = 关闭 = 现状，零迁移 |

### 2.2 唯一接触点（全部向后兼容）

1. `StudioCanvasView` 增加可选字段（`waterfall` / `waterfallShowText` / `waterfallOrder`）。
2. `normalizeCanvasView`（[canvas-view.ts L97-125](../../src/canvas-view.ts#L97-L125)）按既有容忍策略解析新字段（非法整体丢弃、缺省 false）——与 `timeline` / `composeExcluded` 同一写法。
3. `CanvasToolbar` 最右侧图标组加一个切换按钮。
4. `CanvasSurface` / `CanvasNode` 渲染层读一个布尔值分流：**关闭时走现有路径，逐字节不变**。

## 三、入口设计

### 3.1 模式切换入口

**位置**：[CanvasToolbar.tsx](../../src/client/canvas/CanvasToolbar.tsx) 最右侧图标组（CV-059 图标化区，L148 起），紧邻「整理布局」按钮——两者同属"布局/视图"语义。

- 按钮：图标 + `title="历程视图：按阶段自上而下浏览创作产出"`，`aria-label="历程视图"`，激活态高亮（与小地图/图层按钮同款交互）。
- 状态：`view.waterfall`，随视口持久化（下次打开项目回到上次模式）。
- **默认关闭**：所有存量项目打开仍是自由画布，行为零变化。

### 3.2 历程模式内的附属控件（历程模式激活时才出现）

一条悬浮在画布顶部的窄条（与 StyleHintBar 同层的浮层，不进工具栏）：

| 控件 | 行为 |
| --- | --- |
| 阶段跳转 chips | `创意 n/m · 分镜 n/m · 音频 n/m · 成片 n/m · 其他 n/m`，点击滚动定位到对应节 |
| 「显示文本类」开关 | 默认关（用户拍板）。开启后显示 创意需求/剧本/口播文案/便签/提示卡 |
| 「显示辅助卡」开关 | 默认关，复用现有 `showAuxiliary` / `isAuxiliaryNode` 语义 |
| 「跟随新产出」开关 | 默认开：新节点开始生成时自动滚动定位 |
| 「恢复默认排序」按钮 | 清空 `waterfallOrder`（P2 拖拽后使用） |

### 3.3 交互不变式（历程模式内）

- 点击节点 → 现有弹层（ImageZoomModal / VideoPlayerModal / NodeDetailDrawer）原样可用。
- 就近操作条 / 右键菜单 / 改提示词浮层：原样可用（`nodeActionAnchor` 按**布局盒**计算即可，接口不变）。
- 生成中的占位卡、失败重试：原样可用，只是渲染位置由布局函数给出。

## 四、技术方案

### 4.1 数据契约变更（contracts/canvas.ts）

```ts
export interface StudioCanvasView {
  // …现有字段不动…
  /** REQ-036：历程瀑布流视图开关。缺省/非法 = false = 自由画布（老文档零迁移）。 */
  waterfall?: boolean
  /** 历程模式是否显示纯文本类节点（user_brief/write_screenplay/write_script/sticky/prompt）。缺省 = false。 */
  waterfallShowText?: boolean
  /** P2：手动拖拽后的节点顺序覆盖（id 有序列表），语义同 P9.1 timeline。缺省 = 按 createdAt。 */
  waterfallOrder?: string[]
}
```

`normalizeCanvasView` 增加三行解析（`boolOr` / 字符串数组白名单），非法整体丢弃——与 L104-114 现有写法同构。

### 4.2 布局纯函数（新文件 `src/canvas-waterfall.ts`）

仿 `canvas-view.ts` 的纪律：**零运行时依赖、Host 与 client 共用、`node --test` 直测**。

```ts
export interface WaterfallBox { x: number; y: number; width: number; height: number }
export interface WaterfallSection { stage: 'creative'|'shots'|'audio'|'film'|'other'; nodeIds: string[]; box: WaterfallBox; title: string }
export interface WaterfallTray { shot: number; nodeIds: string[]; box: WaterfallBox }   // 对齐 ShotLane 语义
export interface WaterfallLayout {
  positions: Map<string, { x: number; y: number }>
  boxes: Map<string, WaterfallBox>            // 含标准缩略尺寸
  sections: WaterfallSection[]
  trays: WaterfallTray[]
}
export function computeWaterfallLayout(
  nodes: readonly StudioCanvasNode[],
  opts?: { showText?: boolean; showAuxiliary?: boolean; order?: readonly string[]; thumbWidth?: number },
): WaterfallLayout
```

**归节规则**（判定顺序 = 优先级，查不到 → `other` 兜底，绝不丢节点）：

| 节点特征 | 归属 |
| --- | --- |
| `toolName === 'submit_storyboard_for_approval'`（isShotCard） | 分镜节 · 该镜**托盘头部** |
| image 且血缘引用分镜卡（现有 keyframes 判据，canvas-view.ts L511-521 同源） | 分镜节 · 该镜 · 关键帧位 |
| `toolName === 'extract_last_frame'` | 分镜节 · 该镜 · 末帧位（受 showAuxiliary 门控） |
| video 且镜号可解析（血缘/标题，复用 shotNo 传播三趟） | 分镜节 · 该镜 · 视频位 |
| audio 且绑镜 | 分镜节 · 该镜 · 配音位 |
| `toolName === 'music_generation'` | 音频节 |
| `toolName ∈ {user_brief, write_screenplay, write_script}` 或 `kind ∈ {sticky, prompt}` | 创意/文案位（受 showText 门控） |
| 其余 image（未绑镜 look 图）/ 手动上传素材 | 创意节 |
| `toolName === 'compose'` | 成片节（恒排最后） |
| 解析失败 | 其他节 |

> 实现注意：镜号传播、关键帧判据在 `arrangeCanvas` 内是私有逻辑（canvas-view.ts L487-521）。**抽公共**：把 `shotNoOf(nodes)`（三趟镜号传播）与 `keyframeIdsOf(nodes)` 提为 `canvas-view.ts` 导出纯函数，`arrangeCanvas` 与 `computeWaterfallLayout` 共同调用——禁止抄第二份实现（仓库既定纪律，见 CV-224 注释）。

**坐标算法**：

1. 每节点按 kind 映射标准缩略盒：image/video = `thumbWidth × thumbWidth*9/16`（缺省 360，后续可接视口自适应）；audio = `thumbWidth × 96`；托盘头部不占独立卡位（渲染为 tray 头）。
2. 分镜节：每镜一个 tray，tray 内按 头部→关键帧→视频→末帧→配音 网格排列（列数 = 可用宽 ÷ (盒宽+gap)，gap=24）；tray 间纵向排列，镜号升序。
3. 创意/音频/成片/其他：单节网格，节内 `waterfallOrder`（P2）优先，否则 createdAt。
4. 各节独立纵向游标（避免跨节硬对齐，复用 CV-223「每栏独立游标」的验收教训）；整列**居左对齐**（x=0 起排，2026-10-27 复核拍板，原方案为居中）。托盘内配音/音频**独占整行**铺满托盘内宽（对齐交互原型）。
5. 被取代节点（`supersededBy`）：钉在取代者正下方（复用 CV-223 钉扎语义），受隐藏废弃素材开关约束。

### 4.3 渲染接线（client）

- **分流点**：CanvasSurface 取节点列表后，若 `view.waterfall === true`，调 `computeWaterfallLayout` 得到 `boxes`，渲染时以 `boxes.get(id)` 替代 `node.x/y/width/height`（CanvasNode [L592-609](../../src/client/canvas/CanvasNode.tsx#L592-L609) 的 transform 与宽高来源替换为布局盒 prop）。**不修改 store，不触发持久化**。
- **连线**：历程模式不渲染 `CanvasEdges`（血缘由「镜 N」角标 + 托盘框表达）。角标复用 stage-chip 既有样式。
- **托盘框**：渲染层按 `trays[].box` 画容器与头部（视觉对齐现有 group 托盘 / 镜位框风格）；**不创建 group 节点、不写 parentId**——纯视觉。
- **chrome 不变量**：`chromeScaleOf`、就近操作条以布局盒宽度计算，接口不变。
- **适配视野**：进入历程模式时调 `computeFitView`（canvas-view.ts L58，现成）定位到内容顶部；「跟随新产出」用 `revealOffsetOf` + `fitsViewport` 现成函数。

### 4.4 与生成流程的关系

- 占位节点（308×228 生成占位）在历程视图中渲染为其归节的下一空位，状态徽标复用现有 RenderProgressBadge / generate-queue 状态——**不新增状态机**。
- P1 不做「预计步骤占位」（预生成灰卡依赖流程可预测性，列为开放问题 §七）。
