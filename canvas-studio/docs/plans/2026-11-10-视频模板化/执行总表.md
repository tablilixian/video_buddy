## 2. 真实推进顺序（三波，不是两波）

原 INDEX 写的「四块可并行」是错的。按**文件抢用**重排：

```
第一波（可并行）    0A（SFX）        ∥  1C（构件）
                    改 manifest.ts      只新建 furniture.ts
                    改 routes.ts        ★ 不碰 manifest.ts

第二波（串行）      0B（文本上报）
                    改 manifest.ts + TextCard.tsx + host-tools.ts

第三波（串行）      1（模板库）
                    改 manifest.ts + host-tools.ts    ← 必须等 0B 的 report schema 定稿

贯穿（任意波次）    模板内容 3 个（assets/templates/）
                    ★ 纯数据，不碰 src/，可与任何波次并行
```

**关键约束**：

- `src/remotion/manifest.ts` 被 **0A / 0B / 1** 三处改 ⇒ 三者**不能同时进行**
- `src/host-tools.ts` 被 **0B / 1** 改（`report` schema）⇒ 必须串行
- 1C 只新建文件，是**唯一真正零冲突**的包
- 3 个模板是纯数据，`assets/templates/` 不参与 src 编译 ⇒ 谁有空谁做，不占波次

## 5. 验收闸门（可机器判，逐包）

每个包完成时**必须全绿**才算结束。闸门不是"人工看一眼"。

### 5.1 通用（每包都要过）

```bash
cd canvas-studio
yarn clean.mjs && yarn tsdown \
  && npx tsc -p tsconfig.json \
  && npx tsc -p tsconfig.client.json --emitDeclarationOnly \
  && yarn verify:loader
yarn test:smoke
```

> ⚠️ 只跑 `tsdown` 再测试 = 测旧码（测试 import `lib/**`，tsdown 只产 client bundle）。

### 5.2 0A

| 断言 | 判据 |
|---|---|
| 7 条事件起音 vs 视觉三卡（534/544/553 帧） | 偏差 **≤1 帧** |
| 事件窗口峰值 | 逐点比对 GT |
| 整片 LUFS | **−24 ~ −18**（GT 实测 −21.1） |
| 仅 sfx 的片 | 画布角标**不得**显示"无声"（`StudioAudioComposition` 已含 sfx 位） |
| 反向变异 | 删掉 sfx 锚定 ⇒ 校验必须报错（不能静默忽略） |

### 5.3 0B

| 断言 | 判据 |
|---|---|
| 老 manifest 逐像素不变 | 同一份历史 manifest 出片，**帧哈希相同** |
| `renderText` 缺省 = 原文 | 单测：未溢出的文本，`plan.renderText === raw` |
| 溢出上报 | 超长时 `report.textFit` 出现，且 `code` 用户可读 |
| 反向变异 | 把 `renderText` 改成 `lines.join('\n')` ⇒ 逐像素断言必须变红 |

### 5.4 1C

| 断言 | 判据 |
|---|---|
| 逐帧不变 | 加构件前后，同一帧像素哈希相同（构件默认关闭时） |
| 确定性 | 同输入两次渲染，帧哈希相同 |
| `msPerFrame` | **只记录，不设上限**（会涨 2–4 倍，属预期） |

### 5.5 1

| 断言 | 判据 |
|---|---|
| 同 slots 编译两次 | 逐字节相同 |
| **不同 slots 编译两次** | 除 `text` 外**结构逐字节相同**（"只改内容不动结构"的机器证明） |
| 骨架不替换直接校验 | `ok=true` |
| 工具调用数 | **≤3 次**（已从 ≤2 改） |
| 五判据 | `gateTemplate` 6/6 + 反向变异两条变红 |
| 静默丢内容 | 用户说 4 条、模板 3 卡 ⇒ **必须拒绝**且提示合并方式 |
| 内容不足 | 一句话需求 ⇒ **必须拒绝**且提示补素材 |

## 7. 风险登记（真机两项按用户要求不做，但必须留检查点）

| # | 风险 | 触发信号 | 缓解 / 检查点 |
|---|---|---|---|
| **R-1** | 0A 音效在真机不出声（URL 404 已修，但编码/混音可能另有问题） | 出片后 `ffprobe` 无音轨，或音轨静音 | **第一个真机检查点**：0A 做完先出一个 3 秒测试片，`ffprobe` + `volumedetect` 确认有声音，再继续 |
| **R-2** | 1C 69 轨后渲染慢到不可接受 | `msPerFrame` > 100ms（约 18s 片 > 110s） | 允许上升，但超过此值需评估是否降轨道数。**不要因此改"逐帧不变"目标** |
| **R-3** | 容量审计估算 vs 真机实测差 1 字 | 真机出现"填满 `maxChars` 却被裁" | 全中文无差异；中英混排的槽位在 `slots.json` 留 1 字余量 |
| **R-4** | 真实模型填参成功率低于 AI 扮演 | 接真模型后 p1–p6 通过率 < 3/6 | 重跑 `原型-llm-fill-test.mjs` 的用例；若下降，优先改 `usage` 文案而非加槽位 |
| **R-5** | 用户不接受"删字也不缩字号" | 用户抱怨"我的词被砍了" | 这是**设计选择**（模板价值 = 审美已验证）。若抱怨集中在某槽位，说明该槽位容量设计过小，应改模板而非放松判据 |
| **R-6** | 3 个模板里有一个"没人用" | 上线后该模板选择率为 0 | 正常，模板库本来就要淘汰。3 个的目的就是尽早知道哪个方向对 |

## 10. 明确不做（防止范围蔓延）

| 不做 | 原因 |
|---|---|
| `render_composition(templateId, slots)` | 模板产物必须能被模型继续改；且会新增第三路互斥入参 |
| spec → manifest 编译器 | 本仓无 `ManifestSpec`，纯投入；`text` 只校验非空字符串，占位符零阻力 |
| G2 段组合实际实现 | 本期只留接口（`meta.family` + 段四约束），Phase 2 做 |
| 模板编辑 UI | 并入 `REQ-033` |
| 复用 `assets/audio/sfx/` 那 12 个 mp3 | 全 `src/` 零引用、无路由服务；且来源与授权未核 |
| 把 `compose_video` 路径也接 sfx | 本轮只做 `render_composition`；两条路径不一致需在校验里明写，不在本轮统一 |
| 改 `assets` 路由支持子目录 | 该路由服务**全部项目资产**，动它影响面远大于新增一条只读路由 |
