## 三、完整集成四档（逐条）

> 每条含：目标 / 落点 / 依赖（安装状态） / 验收 / 优先级 / 来源。

### A 档 · 表达层补全（让 agent 能声明更多画面）

#### A1 · B2 语义 primitive（核心，价值最高）
- **目标**：把「公转 / 沿路径生长 / 脉动」变成 manifest 一等字段，agent 一行声明即表达关系类动画，而非像 CV-336/337 那样靠 `motion-helpers.mjs` 逐帧手算像素坐标内联成上百关键帧。
- **落点**：`src/remotion/manifest.ts` 新增 `orbit{center,radius,startAngle,period}` / `draw{path,growth}` / `pulse{cycles,lo,hi}`；`src/remotion/timing.ts` 加纯函数 `orbitStateAt()` 等（**零 Remotion 依赖**，可 Host 算、可单测）；`src/remotion/components/*` 接线；`draw` 路径数学用 `@remotion/paths`（`evolvePath`/`getPointAtLength`，已可解析）。
- **依赖**：`@remotion/paths`（传递可解析，建议提升直接依赖）。
- **验收**：构造含 `orbit` 的 manifest → 真渲染两帧像素有差；`remotion-timing.test.mjs` 扩 orbit/pulse 纯函数断言。
- **优先级 P1** · 来源：原 B2。

#### A2 · 效果栈（`glow`/`stroke`/`shadow`/`blur`/渐变遮罩）
- **目标**：组件可声明视觉效果，提升成片质感。
- **落点**：`src/remotion/manifest.ts` 加 `effect` 枚举；`components/*` 接线（用 `@remotion/animation-utils` 或手写 CSS filter/`boxShadow`）。
- **依赖**：`@remotion/animation-utils`（**需安装**）。
- **验收**：含 `effect` 的 manifest 渲染出对应视觉；单测校验枚举合法。
- **优先级 P2** · 来源：原 `createEffect` 评估项。

#### A3 · 形状库补全（arrow/triangle/star/polygon/…）
- **目标**：现 `Shape.tsx` 手绘 **circle / line / gradient / rect 共 4 种**；扩到常用几何（arrow / triangle / star / polygon 等）。
- **落点（设计二选一，开工定）**：① 扩展 `Shape.tsx` 手绘分支（零新依赖，纯 SVG）；② 补装 `@remotion/shapes` 用其 `<Circle>/<Triangle>/<Square>/<Star>/<Path>` 替换手写 4 种 + 扩新种。`manifest.ts` 形状白名单（现无枚举，形状在组件层 case 分支）需同步扩。
- **依赖**：方案②需 `@remotion/shapes`（**需安装**）；方案①无新依赖。
- **验收**：新形状渲染正确（真渲两帧验证）；`manifest.test.mjs` 扩白名单。
- **优先级 P2** · 来源：原 B4.2。

#### A4 · 转场库补全（wipe/clock/flip/…）
- **目标**：现转场 **fade / slide / zoom / dissolve 共 4 种**，由 `timing.ts:transitionOverride`（纯函数）算出 `opacity / translateXPercent / scale` 覆盖，再由通用壳 `TransitionShell.tsx` 套用（路线 B 不用 z-index，层叠靠 DOM 顺序）。扩到 wipe / clock / flip 等。
- **落点（设计二选一，开工定）**：① 扩展 `timing.ts:transitionOverride` 纯函数（新增 `TransitionEffect` 枚举值 + 算更多变换原语，如 clip-path 做 wipe、rotate 做 clock）；② 补装 `@remotion/transitions` 用其 `<LinearTransition>/<ClockWipe>/<Flip>` 等组件替换当前纯函数方案。⚠️ 选②需评估是否破坏「零 Remotion 依赖纯函数 + 唯一接线点」纪律（见 §六铁律①④）。
- **依赖**：方案②需 `@remotion/transitions`（**需安装**）；方案①无新依赖。
- **验收**：新转场渲染无闪帧；单测校验 `transitionOverride` 新分支（方案①）或组件接线（方案②）。
- **优先级 P2** · 来源：原 B4.1。

#### A5 · 文字排版增强（文本测量/自动换行/多列）
- **目标**：长文案/数据卡排版更稳，避免溢出/截断。
- **落点**：补装 `@remotion/layout-utils` 做文本测量；`TextCard.tsx` 消费。
- **依赖**：`@remotion/layout-utils`（**需安装**）。
- **验收**：超长文本自动换行/缩放；单测测量函数。
- **优先级 P2** · 来源：新规划。

#### A6 · B5 受控组件白名单（`component`+`props`）
- **目标**：合规的「扩展上限」方案（devdoc §1.2 不做 LLM JSX 的替代），让 agent 在白名单内选组件+传 props。
- **落点**：`manifest.ts` 加受控组件机制；`validateManifest` 校验 props schema。
- **依赖**：无新包。
- **验收**：白名单外组件被拒；白名单内正常渲染。
- **优先级 P3（放最后）** · 来源：原 B5（等 A1~A5 用出具体缺口再定）。

## 四、KTV 专项（本周期暂缓 · 候补 B3）

**是什么**：字幕随配音逐词高亮（已读词变色/放大，未读暗色），即卡拉OK/抖音式高亮。技术本质是**词级时间戳**：渲染时按 `useCurrentFrame` 对比当前帧时间决定点亮哪个词。`@remotion/captions`（已在 node_modules 可解析）提供 `Caption` 组件 + `getCaptionsFromWhisperJson`/`getCaptionsFromSrt` 等解析器，把词级时间戳转成逐词高亮结构。

**瓶颈不在渲染，在「对齐数据源」**：当前 TTS 链路（Drama 后端）**不返回词级时间戳**，所以渲染侧就绪但无输入。获取途径：
1. **OpenAI Whisper API**（需 `OPENAI_API_KEY`）：音频发过去，开 `timestamp_granularities=["word"]` 拿 `whisper.json`（`words[].start/end`）。最直接。
2. **自托管 Whisper**（faster-whisper / whisper.cpp）：本机/内网跑，避外网 key，需部署 ASR 服务。
3. **其他 ASR**（Azure Speech、GLM 等）：只要返回词级时间戳，均可喂 `@remotion/captions`（支持 SRT/WebVTT/Whisper JSON）。

**性质**：独立于 TTS 的对齐步骤（TTS 出音频 → ASR 拿词时间戳 → 拼进 manifest 字幕轨）。**本周期状态**：用户 2026-10-17 确认暂无 ASR 源 ⇒ B3 **暂缓**，不占批次、保留为未来候选；§五批次表已移除 B3。待将来有 ASR 源（OpenAI key / 内网 ASR / 其他支持词级时间戳的 ASR）时，按 §四重新激活。
