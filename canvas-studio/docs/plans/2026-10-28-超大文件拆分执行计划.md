## 1. 执行总则（每个阶段都一样，先读这节）

### 1.1 三层用例

| 层 | 定义 | 何时写 | 拆分时允许改动吗 |
| --- | --- | --- | --- |
| **画像（characterization）** | 在**现结构**上跑绿，把「当前行为/形态」钉死：工具清单快照、路由清单枚举、导出面快照、CSS 字节级一致、源码文本锚点 | **搬动之前**，且必须先跑绿存档 | **禁止改动**。这是「行为不变」的证据。例外：清单/本计划明示的「登记式修改」（如 atomic-json-write 的按文件计数），必须在 PR 描述点名 |
| **结构（structural）** | 约束拆分后的新形态：文件/函数大小闸、依赖方向、子模块禁止的 import、导出面不缩水 | 随拆分 PR 落地 | 随白名单/路径变化登记更新，每次更新在 PR 描述点名 |
| **变红验证（mutation check）** | 不是新测试，是**每条新测试的出厂检验**：故意改坏一次 → 红 → 还原 → 绿 | 每条新测试落地时当场做 | 验证结果写进测试文件头注释（哪一行改坏、红在哪条断言） |

### 1.2 七步工作流（每个域一轮，域 = 一个子模块 / 一组路由 / 一段 CSS）

```
① 写画像测试（若已有等价测试，先盘点复用，只补缺口）
② 全量 gate 跑绿，记录基线 commit
③ 搬这一个域（只搬，不顺手改逻辑、不改名、不重排）
④ 画像测试一行不改跑绿 + 结构守卫绿
⑤ 反向变红抽验（本域至少抽 1 条）
⑥ 包内四连 + 根 gate 全绿
⑦ changelog.md 登记 + 大小闸白名单/棘轮更新
```

**中途红 = 回滚本域**，不是继续搬。一次只搬一个域，绝不「搬 A 顺手修 B」。

### 1.3 门禁命令（分包）

## 2. 阶段 0 · 文件大小闸（PR-0，先行，独立提交）

> **✅ 已落地（2026-10-28，未领 CV 号）**：三包守卫已提交。§2.3 为**预期**白名单，**实测以守卫内白名单为准**：canvas-studio 文件白名单 13 项与预期一致；函数白名单为成员级实测（新增清单未列的 CanvasSurface 1,295 / CanvasNodeInner 819 / ModelSettingsPanel 674 / errors/catalog SPECS 990，P0 六函数与清单一致 ±1）；desktop / market 与 §2.3 预期一致。变红验证 7 处已实证；desktop 全量 vitest 的 mac-x64arch 2 例为既有失败（与本次无关）。详见 changelog 2026-10-28 条。

**为什么最先**：不立闸，拆完必回涨；且这是唯一零风险的 PR。**产出同时是后续所有阶段的结构守卫。**

### 2.1 闸规格

- **单文件 ≤ 1,200 行**；**单函数 ≤ 600 行**。
- 函数切分口径（守卫自己声明，避免争议）：
  - 顶层 `function` / `export function` / `export async function` 声明体；
  - `class` 内 2 空格缩进的方法体；
  - `.tsx` 内顶层 `useEffect(() => {` 块（`DesktopSettingsSection.tsx` 的 429 行 effect 是真实病灶，必须计）；
  - 例外：`styles.ts` 整文件是一个模板字面量，按**文件行数**管，函数闸对它豁免并在白名单登记豁免原因。
- **棘轮**：白名单条目是 `{ path: 当前行数 }`，只准减不准增；超标文件必须先入白名单才准继续生长（实际上生长即红）。
