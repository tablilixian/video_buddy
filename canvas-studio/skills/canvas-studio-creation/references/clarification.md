# 需求澄清完整规则（澄清开始前必读）

> 本文件是 SKILL.md「需求澄清」骨架的完整版；与骨架冲突时以本文件为准。

开始策划前用 **ask_user_choice 工具**确认「形态 + Look」，规则：

1. **一次只调一次 ask_user_choice，只问一个要素**；收到工具结果（用户的选择自动回流）后再问下一个。**禁止**一次性输出完整方案让用户整体确认，也**禁止用纯文本列表提问**——用户要点按钮，不是打字。
   - **唯一的「非提问」步骤是第 ②-1 步 Look 提取**：它是**读取与归纳**（`list_references` + 反推原话），不弹卡片、不占提问位；只有 ②-2 样张确认才用 `ask_user_choice`。
2. options 给 2–4 个短标签候选项，推荐项末尾加「（推荐）」。**推荐判定规则**：只有当用户已说出的内容能命中时才标推荐，并附一句理由；**没命中或拿不准就不标推荐**，让用户自己选，禁止照搬示例里的推荐位。列举类问题（如「需要调整哪些视觉细节？」「要保留哪些元素？」）传 multiSelect=true 让用户勾选多项，不要拆成多次单选提问。
3. 提问顺序：① 产物形态 → ② **Look 采集**（②-1 提取 → ②-2 样张确认 → ②-3 预设出口）→ ③ 画幅 / 总时长。
   - **编号范围（别混淆）**：`②-1 / ②-2 / ②-3` 是**澄清提问顺序第 ② 项**的三个小步；SKILL.md 工作流里的「**2b. 剧本创作**」属于另一个编号体系（工作流步骤序），两者无关。
   - **项目预置跳过规则**：画幅与目标总时长若已由项目预置（系统提示「Canvas Studio 项目预置」小节里有列），视为用户已确认的事实——**不要**就画幅、总时长或镜头节奏提问，直接采用；用户在对话中明确给出不同值时以用户最新指示为准。
   - **已点名风格跳过规则**：用户消息里已点名具体技能（如「使用技能『3D 动画短片』」开头的软激活提示词）或已明确说出风格/品类（如「做一支产品广告」「拍个街采短片」）时，**Look 采集整体跳过**，直接采用点名或最匹配的预设风格；形态题仅在消息未含形态信息时问。点名技能的加载照常执行，不要因跳过提问而漏掉 `skill(name=…)`。
   - **画布已有参考的跳过规则**：先 `list_references` —— 若画布上已存在 `role=style` 的参考（含用户对话贴图，附件会被自动标记为参考）或参考视频的风格归纳便签，说明**风格信息已经由用户给出**：②-1 直接归纳，**不要再问「想要什么风格」**；已有便签时直接用便签结论，不重复归纳。
   - **节奏/镜头数不问**：镜头数按「目标总时长 ÷ 单镜 8–10s」推导（单段视频上限 15s）；无预置时按 30s 惯例推导并在需求摘要里标注「默认」。
   - **受众与用途不问**：由你从创意自行推断，并在需求摘要里标注「默认」。
   - **无预置时补问**（当前会话没有「Canvas Studio 项目预置」小节才做，一次问完画幅、一次问完时长）：画幅 options: ["16:9 横屏（推荐）", "9:16 竖屏"]；时长 options: ["15s 快节奏", "30s 标准短片（推荐）", "45s+ 完整叙事"]。
   - **第 ① 步形态题**：question「成片想要什么形态？」options: ["多镜头叙事短片", "单镜精品短片"]（推荐项按用户需求加「（推荐）」；**单镜精品短片** = 一镜 ≤15s 直出，适合社媒传播，走下方「单镜简化流程」；**多镜头叙事** = 标准工作流全流程）。
   - **第 ② 步 Look 采集（已替代旧的风格两级追问）**——目标是产出一份可逐镜复用的 **5 项 tokens**（色彩 / 光线 / 材质 / 镜头语汇 / 节奏），完整规格、反推示例与样张规则见 `references/look.md`（**执行前必读**）：
     - **②-1 提取（不是提问）**：先 `list_references` 判断来源，四种来源汇入同一份 5 项 tokens —— ① 画布已有参考图 → 归纳；② 已有参考视频便签 → 直接用结论；③ 已建 Look 卡 → 直接用其 tokens；④ 都没有 → **从用户的创意原话反推**。
     - **②-2 样张确认**：用 `image_generate` 出 **1 张基调样张**（中性主体、只承载视觉），落画布后 `ask_user_choice`：options ["就是这个感觉", "换一批", "我来说说", "你按题材帮我定"]。**文案必须注明「这是基调样张，不是最终画质」**。**限 3 轮**；仍不满意则引导用户「给我一张参考图」。
     - **②-3 预设出口（仅当 ②-2 未通过时才摆出来）**：列出风格预设（表见 `references/style-presets.md`）——此时用户是**拿预设与一张具体的图比较**，而不是凭空选名字。选中即按既有规则加载对应风格 skill。
     - **不加载风格 skill 的三种情况**：参考图路径 / 参考视频路径 / 反推路径 —— 一律**不加载任何风格 skill**（否则会把错误流程约束套上去），只把 tokens 注入后续 prompt。
4. 用户回答「你定 / 随便 / 按你的建议」时，该项采用推荐项并在最终摘要里标注「默认」。
5. 全部确认后，输出一段简短需求摘要（含：形态、**Look 来源与 5 项 tokens 摘要**、画幅、目标总时长、建议镜头数——预置来源标「项目预置」，推断或推荐项标「默认」）；**未命中任何预设组合时如实写「未匹配专属风格，按通用规范执行」，不要假装有预览图**。然后进入分镜规划；分镜表仍须经 submit_storyboard_for_approval 审批。
6. **放手跑模式**跳过提问：自行假设未预置要素并在回复开头列出假设清单。
7. ask_user_choice 会阻塞到用户点击或超时；收到超时提示时按推荐项继续并说明是默认假设。
