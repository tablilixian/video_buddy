## 0. 一句话结论

10 条片全部 5/5 硬检查通过、两次渲染逐帧 md5 全等，**但用像素证据抓出 5 个"代码看着正常、渲染器根本不读"的属性**（`mix-blend-mode` / `conic-gradient` 遮罩 / `perspective` / `backdrop-filter` / `object-position`）。**前 3 个影响产品**：2 个直接在被用（`blend` 字段、`clock` 转场）、1 个在内部 look 层（暗角 / 颗粒的混合模式）；后 2 个产品零依赖，只需记档。

真正值钱的不是"能做什么"，而是：**产品里有 25% 的转场是坏的，而这条以前只能靠"感觉有点生硬"去猜**。

## 3. 逐条落点

### 3.1 B-01 · `blend` 五档全失效（P0）

**实测**：`mix-blend-mode` 在 4.0.535 的 web-renderer 里**一次都没被读取**。同批探测的对照组 `transform` 命中 140 次、`borderRadius` 129 次，排除了"探测脚本本身坏了"。#08 的 B1 格（`difference`）全程是一块纯品红——若生效应整格反相。

**产品依赖 7 处**（`src/remotion/` 内）：

| 位置 | 用途 | 失效后果 |
|---|---|---|
| `manifest.ts:236`（类型）、`:630`（`TRACK_BLENDS`）、`:1358`（校验） | 对模型/用户暴露的 5 档白名单 | 设了任何一档，画面**毫无变化**且不报错 |
| `ImageClip.tsx:38` / `VideoClip.tsx:47` / `Shape.tsx:24` / `TextCard.tsx:176` / `AudioViz.tsx:121` | 轨道级 `anim.blend` 落到样式 | 同上 |
| `Root.tsx:190` | 暗角 `multiply` | 退化为普通黑色径向渐变叠加，**仍是"压暗"**，肉眼差别小 |
| `Root.tsx:203` | 颗粒 `overlay` | 退化为普通叠加，颗粒更"浮"一点，不崩 |

**结论**：轨道级 blend 是纯装饰且完全无效；look 层的两处是**温和降级**，不是错误。

**处置：静默降级（不删字段、不报错、不写样式）**。
1. 新增 `src/remotion/blend.ts`，只放一个函数，作为唯一写样式的地方：
   `export const BLEND_SUPPORTED = false`（注释写明实测证据、版本号、恢复条件）；
   `export function blendStyle(b: TrackBlend | undefined): CSSProperties { ... }`（`BLEND_SUPPORTED === false` 时恒返回 `{}`；`normal` / `undefined` 也返回 `{}`）。
2. 7 处改成调用它（5 个组件的 `...(anim.blend === 'normal' ? {} : ...)` → `...blendStyle(anim.blend)`；`Root.tsx:190/203` 同样）。
3. `manifest.ts:236` 的 `TrackBlend` 与 `:630` 白名单**原样保留**（存量 manifest 不受影响，`tests/manifest-phase3.test.mjs:216` 的断言继续通过），只在 JSDoc 里加一句"4.0.535 实测无效，当前静默降级；`BLEND_SUPPORTED` 置 true 即恢复"。
4. 同步改 skill 侧的 manifest 契约说明（该字段标"保留 · 当前不生效"），避免模型继续拿它当效果承诺。

**为什么不选另外两条路**：
- *校验层直接拒收*：会让存量项目里已存的 `blend:'screen'` 一存就报错，等于拿用户数据换一个提示，违背"不动历史数据"。
- *新增 warning 通道*：校验器只有 `errors: string[]`（`manifest.ts` 全篇无 warning 概念），加通道要动返回结构 + 所有调用方 + 一批测试，收益只是多一句提示。
- *升到 ≥4.0.540*：见 D-02，不值。

**改动面**：1 个新文件 + 7 处调用 + 1 处注释。**零行为风险**（都是"少写一个本来就没用的样式"）。
**验收**：`yarn test:smoke` 绿；跑一次 `S10_BUNDLE_ONLY=1 NODE_OPTIONS= node scripts/remotion-verify/verify.mjs` 确认打包通过；真渲一条带 `blend` 的 manifest，与改前成片逐帧 md5 **应完全相同**（证明降级没改变像素）。

### 3.2 B-02 · `clock` 转场等于硬切（P0）

**实测**：`clock` 靠 `maskImage: conic-gradient(...)` 做扇形扫描（`timing.ts:399-403`），而 web-renderer 的 `parseMaskImage` **只认 `linear-gradient` 与 `url()`**。#09 里 `clock` 格在 A/B 两个相位截图上都是整层铺满 ⇒ 转场实际表现是**整层突现**，不是"快了一点"。

**修正解已被同片证明**：`clock-poly` 用 `clip-path: polygon()` 画扇形（`parseClipPath` 认 polygon），视觉上与扇形扫描等价，且**零新依赖**。

**处置：`timing.ts` 的 clock 分支从 `maskImage` 改为 `clipPath`**。
- 保留原 `deg = progress * 360`；
- 生成顶点：中心 `50% 50%` + 外圈半径 `150%`（必须超过 100%，否则四角露底），从 12 点（角度 −90°）开始，按 `deg` 顺时针取 `N=24` 段；
- `incoming`（淡入那侧）显示**已扫过**的扇形，`outgoing` 显示**剩余**角度（`deg → 360`）；
- `deg` 极小时多边形退化为一点，视觉即"不可见"，正确。
- 该分支不再写 `maskImage`，但 **`maskImage` 字段与 wipe 的软边分支（`linear-gradient`）必须保留** —— 它俩是当前唯一让 `parseMaskImage` 走到 `linear-gradient` 的地方，删了会连带废掉软边 wipe。

**风险声明（必须知道）**：这是**渲染结果的实质变化** —— 存量 manifest 里用了 `clock` 的片子，重渲后从"硬切"变成"扇形扫描"。不重渲不受影响；重渲只会变好。按项目铁律这是"修产生数据的路径"，不是改历史数据。

**顺带的坏消息**：`clock` / `flipX` 在 `tests/` 里**零断言**（`grep clock tests/*.mjs` 为空）。这次必须补测试，否则下次改坏没人知道。

**改动面**：`timing.ts` clock 分支（约 25 行）+ 新增 `tests/remotion-timing-transition.test.mjs`。
**验收**：新测试断言 4 个点 —— ① `progress=0/0.25/0.5/1` 的 `clipPath` 都是 `polygon(...)` 且顶点数恒定 ② 顶点坐标变化单调（角度递增）③ `maskImage` 为空串 ④ `progress=0` 时 incoming 的所有外圈顶点都等于中心点（退化）。真渲验收：渲一条含 `clock` 的片，抽 `progress=0.1/0.5/0.9` 三帧，**画面应依次是"小扇形 → 半圆 → 近乎全屏"**，不是三帧完全相同。

### 3.3 B-03 · `flipX` 中点压成一条线（P1）

**实测**：`flipX` 走 `rotateY` + `transform: ... perspective(1200px) rotateY(...)`（`Transition.tsx:31`）。`perspective` 在过渡计算里丢失 ⇒ `rotateY` 退化成水平挤压，转场中点是**一条竖线**，没有翻面感。

**处置：保留 `effect` 名，改实现为"卡片翻面错觉"** —— `scaleX` 收缩 + 中点暗化 + 前半段淡入。
- `timing.ts`：`TrackTransitionOverride` 加 `scaleX: number`（缺省 1，加到 `identity` 判据里）；`flipX` 分支返回 `scaleX = |cos(θ)|`（θ 从 90° 到 0°），`rotateY` 固定 0。
- `Transition.tsx`：`transform` 串里 `scale(${scale})` 后接 `scaleX(${scaleX})`；`scaleX < 0.4` 时叠 `filter: brightness(...)`（`filter` 链路在 #08 已证全可用）。
- 结果：中点仍是一条线，但**两侧有明暗分离**，观感从"压扁"变成"翻过去"，且不再依赖任何 3D 能力。

**为什么不追求真 3D 翻面**：唯一能拿到真 perspective 的路径是 `html-in-canvas`，而该模式已证丢 WebGL（B-04）且需要启动 flag，做一个装饰性转场不值这个稳定性代价（见 D-05）。

**改动面**：`timing.ts`（约 15 行）+ `Transition.tsx`（约 8 行）+ 同批测试。
**验收**：抽 `progress=0.5` 帧，宽度应接近零但**不是纯白/纯黑一条**（有暗化）；`progress=0.1/0.9` 两侧亮度不同。

### 3.4 B-04 · 全量捕获丢 WebGL 内容（不做）

**实测**：#03 里 conic 光环、`backdrop-filter` 玻璃卡、颗粒层**三件都出画**（证明 `allowHtmlInCanvas` 接线可用），但 WebGL `<canvas>` 区域是纯紫平色，`GL` 程序自报 `ok`。也就是**捕获路径对 WebGL canvas 内容失效**。

**处置：不产品化**。三条理由：① 需要 Chromium flag（`CanvasDrawElement`），发布环境不可控；② 丢 WebGL ⇒ 不能和 3D 能力共存；③ 单帧 17ms，比默认模式慢约 25%。
**准入条件（将来真要用必须满足）**：目标画面**不含任何 WebGL canvas**；渲染耗时预算放宽 30%；启动参数与 `verify-previews` 一起回归。
**已记档位置**：本条 + `docs/plans/渲染环境与Remotion能力上限测试方案-20261029.md` §11.2 R1。

### 3.5 B-05 · 视频贴图在 CSR 不可用（不做）

**实测**：`useVideoTexture` 的 `loaded` 事件在 CSR 下永不触发，重试 2 次确定性失败（#01 P3 段因此降级为自发光脉冲）。
**处置**：不做。但**写成 3D 轨的设计约束**（若将来立 B-12）：**3D 轨只支持静态图片贴图**，任何"视频贴材质"的需求一律改走"视频轨叠在 3D 层上方 + 遮罩"。这条要进 skill 文档，否则模型一定会试。

### 3.6 B-06 / B-07 · `backdrop-filter`、`objectPosition`（不做）

两者都**无产品依赖**（`grep objectPosition src/remotion/` 为空；产品无玻璃卡）。仅记档，防止将来有人以为是可用能力。#03 顺带证明 `backdrop-filter` 在开启全量捕获后可用——若哪天要做"毛玻璃"，先看 B-04 的准入条件。

### 3.7 B-08 · `backgroundImage: url()` 跨端口不加载（已结案，不改）

**容易误判的一条**：bench 里颗粒层缺失，看起来是"`url()` 背景不加载"。但产品条件不同：`GRAIN_TILE_URL = '/canvas-studio/remotion/grain'`（`Root.tsx:42`）是**同源**，且 `Root.tsx:127` 在渲染前已经 `preloadBackgroundImage(GRAIN_TILE_URL)`。跨端口才是 bench 的失败条件。
**结论：不改，不验证，不需要动作。** 若哪天有"颗粒不见了"的反馈，先查这一条而不是查 blend。

### 3.8 B-09 ~ B-12 · 四个"还不存在"的能力

## 7. 负面清单（别做）

1. **别用 `html-in-canvas` 去救 `blend`**：它丢 WebGL（B-04）、要 flag、慢 25%，拿稳定性换一个装饰效果。
2. **别急着升 Remotion 版本**：见 D-02 的触发条件。
3. **别把 bench 的 composition 当产品代码**：`scripts/capability-bench/compositions/*` 是独立实现，验证的是渲染器边界，不是产品组件。产品要的是"把结论接进 manifest 契约"，不是把 TSX 搬过去。
4. **别在 `Root.tsx` 里逐处判断 blend**：唯一入口是 `blend.ts` 的 `blendStyle()`，否则又是 7 处各写一份。
5. **别顺手"修"暗角和颗粒**：它们不是 bug，是温和降级（§3.1 表格最后两行）。
