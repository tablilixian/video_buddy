# REQ-041 · F6 设计提案：让「改一屏表现」有合法的持久化入口

> 状态：**已拍板并实现**（2026-11-26）。拍板结论：方案 C + B、主键用 `ref`、托盘角标本期做。
> 实现记录与两处偏差见 §7。来源：`REQ-041-第2批-真机复盘-20261125.md` §5.1 / §5.4。

## 1. 问题（不是 bug，是缺一层载体）

真机会话（超级月亮，2026-11-25）的三条原话：

- 「若用 `writeTo` 重编 manifest，会把第 2 屏手工编写的椭圆轨道重建成旧文字卡，所以我只改 spec 与对应的那一条轨道」
- 「拆分要重新生成 spec 段表，这会覆盖 manifest，所以我会在重编后恢复第 2 屏的椭圆轨道和音频」
- 「spec 只能表达卡 + 文案 + 格位；沿路径运动 / 分段停顿 / 引线标注表达不了」

即：**用户的真实诉求（「这一屏效果不够，改成动画」）在产品里没有合法路径**。模型只有两条
坏路 —— 手改生成物 `build/manifest.json`（下次重编必丢），或放弃表达力。

补充事实（本批已修的部分）：重编覆盖时丢的手工轨，现在会在回执里点名（`droppedTracksNote`），
但那只是**让丢失可见**，不是让手工轨活下来。

## 2. 三个方案

| | 方案 A：`spec.section.extraTracks` | 方案 B：`patch_segment_tracks` 工具 | 方案 C：段级覆盖文件 |
|---|---|---|---|
| 载体 | 手工轨写进 spec 的屏对象 | 新工具把手工轨写进 spec（不写 manifest） | `build/overrides/<segmentId>.json`，scaffold 时合并 |
| 重编行为 | `planFromSpec` 一并产出这些轨 | 同 A（最终仍落在 spec） | scaffold/plan 时按段合并，spec 不动 |
| 手工轨的来源 | 模型手写 JSON（沿路径 / 停顿 / 引线） | 工具校验字段（zIndex / 时间窗 / 幅度） | 同 A/B，但独立文件 |
| 优点 | 一处事实源，spec 可版本化、可 diff | 有 schema 校验，错误在写入时就被拦 | 不动 spec schema（对老项目零迁移）；手工轨与模板产物物理分离，覆盖风险最低 |
| 缺点 | spec 体积与校验复杂度上升；`section` 语义被扩宽（「卡 + 文案 + 格位」变成「+ 任意轨」） | 需要新工具 + 新 schema + 段级定位（`segmentId` / `shotNodeId`） | 两个事实源（spec + overrides），要定义合并优先级与冲突告警 |
| 缓存影响 | 无（hash 按产物轨算） | 无 | 必须把 overrides 纳入 `segmentHash` 输入，否则改 override 不重渲 |

## 3. 推荐：C 为骨架，B 为写入口

```
模型/用户: patch_segment_tracks({ shotNodeId, tracks: [...] })
   → 校验（时间窗在段内、box 在画布内、id 唯一、zIndex 语义）
   → 写 build/overrides/s3.json（diff 前先存一版 overrides/versions/）
重编/出片:
   scaffold_from_spec(writeTo) 生成基础轨 → 合并 build/overrides/*.json
   → segmentHash 纳入 overrides 内容（改 override = 该段 stale，其余段命中）
   → 回执点名「s3 有 2 条手工轨来自 overrides（不在 spec 里）」
```

理由：

1. **不扩宽 spec 的语义**。spec 是「屏级编排合同」（卡 + 文案 + 格位），把任意轨塞进去会
   让 `validateContentSpec` 变成渲染器的一部分。
2. **覆盖风险最低**。手工轨不在 spec 产物里，任何一次 scaffold 都不会碰到它；这正好反过来
   消灭了「重编把我手写的东西冲掉」这个真机高频事故。
3. **段级颗粒度与 REQ-041 的段缓存天然对齐**：override 属于某一段 ⇒ 改一屏只重渲一段
   （F1/F2 已经把这个能力做实）。
4. **写入口用工具而不是手改文件**：zIndex / 时间窗 / 画布边界这些校验必须有一次实现，
   和 `wrapStudioToolDefinition` 的「脏参数在入口拒收」是同一条纪律。

## 4. 影响面（预估 3–4 个工作日）

| 层 | 文件 | 改动 |
|---|---|---|
| 契约 | `src/segment-overrides.ts`（新） | override 文件 schema + 归一化 + 合并（纯函数，可单测） |
| 工具 | `src/host-tools.ts` / 新 `host-tools-overrides.ts` | `patch_segment_tracks` 收参（`segmentId`/`shotNodeId` 二选一、tracks 数组）+ 回执 |
| 渲染 | `src/shot-cache.ts` | `segmentHash` 输入加 `overrides`（改 override ⇒ 该段 stale） |
| 渲染 | `src/shot-render.ts` / `segment-render.ts` | 合并点是 `renderManifest` 之前还是段内切片时（建议段内，理由：整片路径与段路径共用一份合并逻辑） |
| 图面 | 分镜托盘 | 有 override 的段打角标（「本段有 N 条手工轨」），否则用户看不出差异来自哪 |
| 文档 | skill `code-driven-explainer` | 「一屏效果不够 → `patch_segment_tracks`，不要手改 manifest」 |

**不做**：可视化轨道编辑器；override 支持任意 Remotion 组件（只开放 manifest 已有的轨类型 + `orbit`/`path`/`animate`）。

## 5. 验收标准（真机一轮可判）

1. `patch_segment_tracks({ shotNodeId, tracks })` 写盘后，该段渲染画面变化，**其余段 mtime 不变**；
2. 随后 `scaffold_from_spec({ writeTo })` 重编：手工轨仍在（回执点名来源），没有 `droppedTracksNote` 告警；
3. 改 override ⇒ 只有该段 stale；不改 ⇒ 命中（`lookupSegmentsCache` 回执可读）；
4. 非法轨（出画布 / 时间窗越段 / id 重复）在写入时拒收，零副作用；
5. 托盘角标与实际 override 数量一致。

## 6. 与 F5 的关系

F5 已落地的「覆盖时点名丢失轨」是**过渡护栏**：F6 上线后它不该再触发（因为手工轨不在被
覆盖的那份产物里）。保留它作为回归哨兵 —— 一旦又出现，说明有人绕过了 override 通道。

## 7. 实现记录（2026-11-26）

| 项 | 拍板 / 落地 |
|---|---|
| 载体 | `build/overrides/<ref>.json`（`overrideFileName` 把 `spec:s2` → `spec-s2.json`；非白名单字符按码点编码，中文段 id 不会撞名） |
| 写入口 | `patch_segment_tracks`（`set` / `add` / `remove` / `clear` / `show`） |
| 主键 | `ref`（`spec:<段 id>`）+ `anchor { startFrame, frames }`；段窗一变 ⇒ **不合并**并点名两个窗口 |
| 合并点 | `render_composition`（`normalizeManifestTiming` 之后、`expandGroups`/`validateManifest` 之前）与 `rerender_segment`，共用 `mergeProjectOverrides` |
| 缓存 | 合并发生在切段之前 ⇒ `segmentHash` 自然包含手工轨（**无签名改动**）；加 override 只有该段 stale |
| 渲后快照 | `build/manifest.json` 剔除手工轨（`withoutOverrideTracks`） |
| 图面 | 托盘 `SegmentCell` 角标「手工轨 ×N」，数据由 `/remotion/segments` 的 `overrides` 字段带来 |
| 覆盖护栏 | `droppedTracksNote(…, { exempt })` 不再把 override 轨算作「被重编丢掉」 |

**偏差 1：只做新增（提案里允许的同 id 替换去掉了）。**
替换会让「这条轨来自 spec 还是 override」不可判定，且 `build/manifest.json` 重写时无法把被替换的
原轨还原 —— 一旦 override 被删，那一屏就缺一条轨且没有任何报错。真机要做的「椭圆轨道」本身就是
新增一条 `shape` + `orbit` 轨，不需要覆盖。要改 spec 产出的轨，正确入口是 `patch_spec_section`。

**偏差 2：段窗零容忍（不设容差）。**
绝对帧号一旦错位，画面错在别的屏上 —— 用户看到的是「改错了」，比「没生效」难查一个量级。
