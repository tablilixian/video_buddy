§3 节点贴边：面板放哪儿、什么时候动画布 E1 E2 E3 E4 E5 E6 E7

规则是固定的四步；§1 的读数会实时显示它选了哪一侧、平移了多少。注意：平移的是画布（view），不是面板；缩放永远不变。

求解顺序（自上而下，第一个成立就用它）
步做什么为什么
1 四侧择优右 → 左 → 下 → 上；左右放置恒不遮挡节点面板不该压住你正在改的东西；左右并列天然不遮
2 夹取面板矩形夹进安全区（8px 边距，并给底部抽屉让位）贴边时面板不能露一半在视口外
3 最小平移四侧都放不下 ⇒ 平画布把优选侧腾出来，位移取最小必要值节点贴在角落时，与其让面板挤成一条，不如让画布让一点
4 死区位移 < 4px 就不动；平移动画 200ms；用户手势立即打断几像素的抖动和"镜头乱动"比不动更烦人
两个容易踩的坑
关闭时不要回弹。用户刚把画面挪舒服，一关面板又弹回去，等于每次编辑都被"镜头晃一下"。 所以：关闭不回弹，但面板头部给「恢复视野」（回到打开前的快照）。
窄窗里不要硬撑浮层。视口宽 < 720px 时，浮层放哪都盖住画布 ⇒ 改底部抽屉形态（高约 46%）， 必要时把画布往上抬，保证节点不被抽屉压住。
节点完全滚出视野时不显示任何浮层（沿用现有 nodeActionAnchor.visible 的相交语义）—— "钉在屏幕边缘的按钮"只会让人不知道在操作谁。

§5 四种槽位形态（同一套 UI，按工具名换规则） A3 A4 A5

用 §1 控制面板下面的「当前节点」切换；这里也可以直接切。

当前节点
槽位规则（唯一事实源 = node-params 的槽位表）
工具形态可做的操作上限

video_generatefilename（可选单槽）换 / 清空1
image_fix · character_generate · character_sheetfilename（必填单槽）只换不空1
为什么这样定
image_fix / character_sheet 的参考图是必填的：删成空之后重试必然报参数错， 而错误发生在用户已经点了「重试」之后。所以必填单槽只提供「替换」；可选单槽（video_generate 首帧）才给「清空」。
位次为什么必须显示：video_composite 的 1 张 = 首帧（I2VA）、2 张 = 首尾帧（FL2VA）、≥3 张 = 多参考（Ref2VA）， 数组顺序就是提示词里 <Picture N> 的编号。

§6 添加参考图：为什么要多一步「解析句柄」 A2 · 方案 §4.3

点「+ 添加参考」会滚到这里。注意那张红色标记的候选：它代表「画布上刚生成、只有后端产物名的节点」—— 直接拿它的名字作参考，后端会 500。这正是要新开 POST /canvas-studio/resolve-refs 的原因。

选择器（§1、§4 的「+ 添加参考」共用这一个实例）
添加参考图 已选 0
选中后点「加入」→ 解析句柄 → 写入参考位
为什么不直接写 node.filename
实测过的坑（CV-155）：生成产物节点上存的是后端产物名（img_01287_.png）， 当参考传回去约 0.1s 内 500。可用的是 ref-xxxxxxxx.png 这种上传句柄， 要靠 Host 的惰性提升（resolveRefFilenames → promoteAssetFile）现造，并回写源节点。
所以「加入」不是瞬间的：先 POST 解析 → 拿句柄 → 再写进参考位（UI 上就是那行「解析句柄…」）。 好处是缩略图能立刻反查到图，而不是一加进去就显示「参考已断链」。
失败要逐项：一次选 5 张、坏了 1 张，只该坏那一张。
