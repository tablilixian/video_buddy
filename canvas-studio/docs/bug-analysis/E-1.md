# E-1 ｜ 新建项目首页异常 + 空项目目录 .draft-202610-N（致命）

> 优先级 P0（致命，但**需运行时取证定案**——两个嫌疑点已代码定位）｜ 风险 T3 ｜ 依赖：用户机取证
> 截图要点：首页本身能渲染、项目列表 6 条；大预览区是近乎空白的 draft 落点画布。用户描述：来回切换几个项目后点新建 → 首页异常，重启依旧，出现空 .draft-202610-4。

## 嫌疑点 1（与「重启不复原」最吻合）：registry 坏记录永久抛错
- `projects.ts:838-891` `ProjectRegistry.readDocument`——registry 损坏/记录非法/dir 越界一律抛 `CS-DEV-ERR`（:854/:863/:868/:875），**故意不降级为空表**。
- 一旦 `projects.json` 出现一条坏记录：`list()` 永久抛错 → 首页项目列表加载失败（client/index.ts:982）、draft-landing 500（routes.ts:539「首页准备失败」）、新建项目也失败。坏文件在磁盘上 → 重启依旧。
- 「空 .draft-202610-4」本身是设计态：draft 落点不进 registry、无 canvas.json；启动清扫豁免当月目录（projects.ts:603-626，CV-260）所以跨重启留存——**空目录不是异常本体，首页异常才是**。

## 嫌疑点 2：认领失败 → 强制重建落点的自增循环
- `client/index.ts:741-768` claimAndSend 失败（撞名重试失败 /「该目录已被其它项目占用」）都 `ensureDraftLanding(true)`（:759/:766）→ `ensureDraftDir` 顺延新后缀目录（projects.ts:563-580）→ 连续失败即连续产出 `.draft-202610-4、-5、-6…`。
- **Windows 特有诱因**：`ensureDraftDir`/`createClaimingDir` 的互斥判据是 `resolve()` **字符串严格相等**（projects.ts:528,564,606）——Windows 路径大小写/短路径表示不一致时永不匹配 → 落点永远顺延、认领永远报「已被占用」，坏 dir 字符串持久化进 registry，重启不愈（与嫌疑点 1 汇合）。

## 取证指引（定案用，发给用户即可）
1. 取运行时机器 `$DSH_HOME/canvas-studio/projects.json`（重点看：是否可解析、有无 dir 指向不存在路径/大小写异常的记录）。
2. 插件日志 grep：`CS-DEV-ERR` /「首页准备失败」/「项目列表加载失败」/「该目录已被其它项目占用」。
3. 命中嫌疑 1 → 修复案 A；命中嫌疑 2 → 修复案 B；两者都命中 → A+B。

## 修复方案
**案 A（registry 容错）**：readDocument 对单条非法记录**隔离而非整体抛错**——坏记录跳过 + 记 warning（日志给出被跳过的 dir 原文），registry 文件不自动改写（下次 save 时自然收敛）。注意：当前「硬抛」是刻意设计（防止静默吞掉损坏），折中是**只对「可明确识别的单条记录错误」（dir 非字符串/id 重复/dir 越界）降级跳过，文件级损坏（JSON 解析失败）仍硬抛**。
**案 B（认领闭环）**：① 路径比对归一化——`resolve()` 后再统一小写比较（Windows）/用 fs.realpathSync 处理短路径（仅互斥判定用，存储保留原样）；② `ensureDraftLanding(true)` 强制重建前先诊断上次失败原因，连续 N 次失败改抛可行动错误而不是无限顺延新目录；③ 顺延前检查旧落点是否可复用（磁盘存在且未 claimed → 直接复用）。

## 改动风险
- 案 A 触碰「防静默损坏」的既有设计——降级范围必须窄、必须留日志与 warning 面（T3：全量测试 + 反向变异）。
- 案 B ① 的平台分支要防 macOS 大小写不敏感盘的行为差异（统一走「比较时归一、存储时原样」）。
- 两案都不动「空 .draft-* 是设计态」的事实；E-3 的到秒命名会改变目录名形态，与本案清扫/认领逻辑无冲突。

## 验收
无头：案 A——坏记录（dir:null / dir 非字符串）list() 不抛、跳过并告警；文件级损坏仍抛。案 B——大小写不同路径认领互斥命中；连续失败 N 次抛可行动错误。桌面（取证后）：用户机上复现路径消失。
