# 句级字幕时序口径（MVP）

**现状约束**：后端 TTS（`tts_voiceover` / Drama `txt2speech`）响应**没有任何字级 / 句级时间戳**，仓库也无 forced-alignment / 转写对齐代码。因此**词级同步无数据源**，MVP 只做**句级**，按下面的纯口径派生，零新依赖。

## 派生流程

1. `tts_voiceover` 产出旁白后，取它结果里的**真值时长 T**（秒）——该字段是 ffprobe 实测，**不是**后端响应里的"生成耗时"（两者实测差约 2.8 倍，勿混用）。
2. 按**字数占比**把 T 分配给每句：`句i时长 = (字数i / 总字数) × T`。
3. 句间可加固定呼吸间隔（默认 **0.15s**，**从相邻句时长内扣**，不额外拉长总长）。
4. 折算帧：`startFrame = round(累计秒 × fps)`，`durationInFrames = round(句时长 × fps)`；**末句吸收舍入误差**，保证末句 `endFrame` 与旁白总帧对齐。
5. **无旁白**（纯 BGM / 无音频轨）时回退 **字数 × 0.25s（4 字/秒）**估算——沿用 `voiceover-writing` 现行惯例。
6. **兜底校验**：末句 `endFrame` 与旁白总帧偏差 > 0.5s → 会在结果 `warnings` 里出现（不阻断渲染），要转告用户。

## 卡片形态与断句

- 一条字幕卡 = 一句（`variant: "subtitle"`）。长句按标点（，。！？；）再切，单卡中文建议 **≤ 18 字**，与展示时长匹配。
- 断句要顺着语义停顿，不要机械按字数等分；旁白稿里的逗号是天然切口。
- 数据 / 数字类信息优先用 `variant: "dataCard"` 的 `data` 键值对呈现，比塞进字幕条更清楚。

## 误差预期

总长精确（实测值），误差只在句边界（受语速不均影响，典型 ±0.3s/句），显著优于裸 4 字/秒估算。

## 词级字幕（二期，有前置条件）

需要后端 TTS 响应增加 word / sentence 时间戳，**或**引入 forced alignment（本地转写对齐）。在前置条件满足前，不要尝试用估算伪造成逐字高亮——观感会与音频明显脱节。
