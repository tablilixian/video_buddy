判据只有回执那一行：

| 回执 | 判定 |
|---|---|
| `3 段（2 复用 / 1 重渲，边界来源 段表）` | ✅ 通过，隔离成立 |
| `3 段（1 复用 / 2 重渲，边界来源 段表）` | ❌ s1 被 s2 带脏，段窗还有重叠 |
| `3 段（0 复用 / 3 重渲，边界来源 段表）` | ⚠️ 先排除几种正常情况，见下 |
| `边界来源 spec` / `transition 末端` | ❌ 段表没生效 |

`0 复用 / 3 重渲` 的三种**正常**情形（别误判）：
1. **第一次带段表的渲染**——段窗从 200/400 变成 190/390，旧缓存 hash 全变，必然 0/3。
2. 这次 scaffold 顺带改了 `meta` 里的全局项（`look` / `fonts` / `durationInFrames`）。
3. 上一轮把 `deliver/segments/` 手删了但缓存还在 —— 反过来不会导致重渲，只会复制。

所以正确顺序是：**先渲一次确认是 0/3（可接受）→ 再只改 s2 渲一次，看是不是 2/1**。

## 4. T20 / T15 —— 抽帧与成片时间戳

回执里应出现两块新内容（都在 warnings 通道，前面带 `⚠️` 只是通道位置，不是错误）：

- `抽帧 3 张（…）`，帧号 **94 / 289 / 494**（各段中点），路径形如 `assets/…qc-s1.png`；
- `📦 段产物已落交付目录：s1（deliver/segments/s1.mp4）、s2（…）、s3（…）`。
