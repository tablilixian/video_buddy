# Look 采集完整规则（澄清第 ② 步执行前必读）

> 本文件规定：**怎么把「参考图 / 参考视频 / 一句创意 / 预设」四种输入，统一产出一份 5 项风格 tokens，并用一张样张确认它。**
> 与 SKILL.md 骨架冲突时以本文件为准。相关：澄清顺序见 `references/clarification.md`，预设出口见 `references/style-presets.md`，注入纪律见 `references/consistency.md`。

## 0. 一句话定义

**Look = 全片统一的视觉基调**，用 5 项 tokens 承载，产出于澄清第 ② 步，之后逐镜复用。

「**从创意反推 tokens**」= 用文字走一遍 `video-style.ts` 已经在图像路径上做过的事：视频路径是**看**一帧画面归纳出 5 类参数，创意路径是**读**用户一句话归纳出同样 5 类参数。同一个问题，换个输入源。

## 1. 5 项 tokens 规格

固定这 5 项，**不增不减、顺序不变**、每行一个标签：

| 字段 | 含义 | 反推时问自己 |
| --- | --- | --- |
| **色彩** | 色调与调色倾向 | 画面主色是什么？饱和度高低？冷暖对比？ |
| **光线** | 光源性质与光比 | 光源是单一还是多源？硬光还是柔光？大光比还是平光？ |
| **材质** | 表面质感与新旧 | 主体与环境的材质？磨损/崭新？反光强弱？ |
| **镜头语汇** | 焦段、景深、机位、运镜倾向 | 广角还是长焦？浅深景深？固定还是手持/缓推？ |
| **节奏** | 剪辑与呼吸感 | 快切还是长镜头？留白多不多？ |

**输出格式**（逐字节可复用的冻结文本）：

```
色彩：低饱和青灰打底 + 钨丝灯暖黄点缀，保留「彩色里的旧」
光线：单一实用光源（路灯 / 门灯），大光比，湿地面反光当补光
材质：湿青砖、木质窗框、旗袍绸缎的低光泽
镜头语汇：中长焦、浅景深、固定机位或极缓推，门窗框景
节奏：慢、留白、长镜头呼吸
```

**判定标准（必须同时满足）**：

1. **完备** —— 任何风格都能塞进这 5 个格子，不出现「其他」；
2. **可改** —— 改一项不影响其他项（「再暗一点」只动「光线」一行）；
3. **可复用** —— 逐镜注入同一份字段，措辞不变；
4. **可定位** —— 样张不对时能指到具体哪一项（「不是光线的问题，是材质太新了」）。

**为什么必须结构化**：自由文本一改就牵连全段、跨镜复制会漂移、样张不对说不清问题项。结构化把这三个缺陷同时消掉。

**维度不是新发明的** —— `src/video-style.ts` 的 `STYLE_PROMPT` 已经在要「色调与调色、光线、构图与镜头语言、材质质感、美术设定」，只是它输出「不超过 6 条」的自由要点，而不是可寻址的 5 行。

## 2. 四种输入来源（②-1 提取）

先 `list_references` 判断来源，**四种来源汇入同一份 5 项 tokens**：

| 优先级 | 来源 | 判断依据 | 归纳手段 |
| --- | --- | --- | --- |
| ① | **已建 Look 卡** | `list_references` 的 `assets` 里 `role=style` 且 `lockedPrompt` 为 5 行 | **直接用其 `lockedPrompt`**，不重新归纳 |
| ② | **参考视频便签** | 画布上有「风格归纳」便签 | **直接用便签结论**（便签末尾已内嵌「【5 项风格 tokens】」段，照抄即得），不重复归纳 |
| ③ | **参考图** | 画布上有 `role=style` 的参考图（含对话贴图，自动标记） | `image2vl` 分析该图 → 归纳 5 行 |
| ④ | **一句创意** | 以上都没有 | **从用户原话反推** → 5 行 |

多个来源同时存在时按上表优先级取第一个可用的；若用户明确说要「综合起来」，把各来源分别归纳后再合并成一份（合并规则见 §5）。

### 2.1 从创意反推的做法

「反推」的方向是**从具体推出抽象**：用户说的是具体（民国、雨夜、旗袍、弄堂、老电影），tokens 是抽象。

- **只提取，不新增设定**：用户没说的维度按题材惯例给一个克制默认，不要凭空加戏（用户说「雨夜弄堂」，不要自作主张加「霓虹」）。
- **保留用户原话里的独特措辞**：用户说的「彩色里的旧」「冷得发蓝」这类形容**原样保留**，它们比通用词更有区分度。
- **先把用户原话列在 tokens 之前**作为依据，再给 5 行 —— 让用户能看出每行是从哪句话推出来的。

**示例**（用户原话 → tokens）：

> 「民国、雨夜、旗袍、弄堂、老电影」

```
依据：民国 + 雨夜 + 旗袍 + 弄堂 + 「老电影」
色彩：低饱和青灰打底 + 钨丝灯暖黄点缀，保留「彩色里的旧」
光线：单一实用光源（路灯 / 门灯），大光比，湿地面反光当补光
材质：湿青砖、木质窗框、旗袍绸缎的低光泽
镜头语汇：中长焦、浅景深、固定机位或极缓推，门窗框景
节奏：慢、留白、长镜头呼吸
```

**反推的固有风险**：反推是**推断**，可能推得平庸或推错（用户说「老电影」，可能给一套很泛的「复古胶片感」，而用户想要的是特吕弗）。**这正是样张存在的理由** —— tokens 不对时不必争论文字，直接看一张图说「不是这个感觉，光线再硬一点」。

### 2.2 参考图归纳（`image2vl` 调用规范）

参考图**必须走一次归纳**，不能只把它当一张图传下去 —— 否则风格只留在图里、不在 prompt 里，逐镜复制必然漂移。

调 `image2vl`，参数**逐字节照抄**下面三段（与 `src/style-tokens.ts` 的 `LOOK_TOKENS_PROMPT` / `LOOK_ANALYST_SYSTEM_PROMPT` 同源，由测试守护一致）：

- `filename`：该参考图的 Drama 文件名（取自 `list_references` 的 `filename`；对话贴图可直接传 `@ref[显示名]`）

- `prompt`：

```
请从电影摄影角度归纳这段画面的视觉风格，严格按下面 5 行输出（顺序固定、不增不减、不要序号、不要额外说明，每行给出具体结论而不是字段解释）：
色彩：
光线：
材质：
镜头语汇：
节奏：
```

- `systemPrompt`：`你是一个专业的影视视觉分析师，擅长从画面中提炼可复用的风格要素。`

**一次调用只分析一张图**（多张各调一次，再按 §5 合并）。返回文本应已是 5 行；若模型没守格式，按 §7 降级，**不要自己编 5 行**。

## 3. ②-2 样张确认

tokens 草稿出来后，**必须出一张样张让用户先看到风格**，不要等到关键帧审批（第 6b 步）才第一次暴露风格。

| 项 | 规则 |
| --- | --- |
| 出图 | `image_generate` 出 **1 张**（不是全套），`style` 按 §4 画风规则 |
| 主体 | **中性主体**（人物剪影 / 静物 / 空镜），**只承载视觉**，不含本片具体剧情 |
| 落画布 | 出图即落画布，并作为 `role=style` 的参考（参考托盘中可见） |
| 确认 | `ask_user_choice`：options `["就是这个感觉", "换一批", "我来说说", "你按题材帮我定"]` |
| 轮数 | **限 3 轮**；每轮**只改 tokens、不改样张内容**（见 §6）；3 轮仍不满意 → 引导用户「给我一张参考图」，转为来源 ③ |
| 文案 | **必须注明「这是基调样张，不是最终画质」** —— 否则用户会拿它当成品预期 |

**「你按题材帮我定」**：照出样张，但明确说明是默认假设，并在需求摘要里标「默认」。

**用户说「你定吧」**：样张照出，但**必须可见**（不能静默假设）。

## 4. 画风（realistic / anime）与 tokens 的关系

`image_generate` 的 `style` 参数（`realistic` / `anime`）**独立于 tokens**，在出样张时就定下：

- 用户要「动漫 / 二次元 / 日式动画 / 漫画风」→ `anime`（**仅支持纯文生图**，带参考图会回退写实）；
- 其他（写实 / 电影感 / 3D 动画）→ `realistic`（默认）。

tokens 描述的是**在选定画风之内的视觉基调**，不承担画风选择。

## 5. 多来源冲突的处理

多张参考图风格冲突（一暖一冷）时：

- **1–3 张为限**，且每张都要说明它管什么（「这张管色彩、这张管光线」）；
- 逐张归纳后在 tokens 里**逐项择优合并**：哪张在哪一项更权威就用哪张，并在回复里说明「色彩取自 A，光线取自 B」；
- **合并结果统一出 1 张样张**再确认，不要并行出多张让用户挑（会分散表述）。

## 6. steer 语义（改 Look ≠ 改镜头）

用户在样张阶段说「再暗一点」「别那么冷」时：

- **只改 tokens 的对应行**（「再暗」→ 只改「光线」），**只重出样张**，不动任何镜头；
- **一次审美判断 = 1 次生成**（不是 N 次）。

**过了样张阶段再改 Look** 必须提示影响面：定妆照与已出关键帧都会与新风向不符，要重出。让用户在「只影响后续镜头 / 全部重来」之间明确选择，**不要自作主张**。

## 7. 能力边界与降级路径

| 情况 | 降级做法 |
| --- | --- |
| tokens 反推明显跑偏且用户也说不清 | 引导用户给一张参考图（转来源 ③），或直接看样张逐项指正 |
| 参考图无法分析（`image2vl` 失败） | 按用户原话反推，并说明「参考图未能分析，按你的描述先行」 |
| 归纳结果未守 5 行格式 | **不要替它编 5 行** —— 如实说明「这张图的风格未能结构化归纳」，改走反推（来源 ④）或让用户口述风格 |
| 参考视频便签末显示「未能按 5 项格式归纳」 | 同上：改走反推，或引导用户提供参考图 |
| 样张小图不足以判断 | 说明「样张只承载基调，细节在逐镜阶段体现」，不要反复加大样张尺寸 |
| 未命中任何预设组合 | **如实写「未匹配专属风格，按通用规范执行」**，并明确**没有画布预览图**，不要假装有 |

## 8. 硬约束（必须遵守）

1. **Look 路径（参考图 / 参考视频 / 反推）一律不加载任何风格 skill** —— 只有「用户点名」或「出口处选预设」才加载。否则会把错误的流程约束套上去（给古装电影套「纸艺定格」的 STEP），这是必须防的灾难。
2. **tokens 里不写预设名** —— 名字写错会让画布匹配不到预览图与对应 skill。
3. **贴图可能是「内容参考」而非「风格参考」**（用户说「我要拍这个人」）→ 在回显时**显式确认一次** role：选「角色」则进 `character_sheet`，不进 Look。附件 role 是自动标记的，不能沿用自动假设。
4. **样张不等于最终画质**，文案必须说清。
5. **`lockedPrompt`（tokens 冻结文本）必须经用户确认后再冻结**（与 `consistency.md` 的角色卡纪律一致）。

## 9. 落卡 + 注入纪律（逐镜复用）

### 9.1 落卡（②-2 样张确认通过后立刻做）

tokens 与用户确认后（§8 硬约束 5），调 **`look_card`** 把 tokens 冻结成项目级 Look 卡：

```
look_card(name="雨夜霓虹", lockedPrompt="色彩：…\n光线：…\n材质：…\n镜头语汇：…\n节奏：…",
          referenceFilename="@ref[样张节点标题]")
```

| 项 | 规则 |
| --- | --- |
| 时机 | **②-2 样张确认通过后**（确认前不要落卡 —— 用户还没认，冻结没有意义）；样本阶段还要改 tokens 就同名重调 |
| `name` | 短名即可（如「雨夜霓虹」），`Look · ` 前缀工具会自动补；**同名重调 = 整体覆盖**，改 tokens 不用另建卡 |
| `lockedPrompt` | **5 行原样**（`色彩：`/`光线：`/`材质：`/`镜头语汇：`/`节奏：`）；工具会把行序归一成权威顺序，缺项会返回 warning（按原样落卡） |
| `referenceFilename` | **锚点**：传 ②-2 那张样张（推荐 `@ref[节点标题]`，也可传节点 id 或 `upload_image` 的文件名）。工具**复用既有的样张节点**作锚点，不重新出图、不新建节点 |
| 锚点缺省 | 不传也合法 —— **Look 默认走文字注入、不占参考图席位**（§11）。解析不到节点时会返回 warning，不阻断落卡 |

### 9.2 注入（每镜都做）

```
每镜 prompt = Look tokens（卡片 lockedPrompt，逐字节原样） + 该角色 lockedPrompt（逐字节原样） + 本镜 NEW ACTION / CAMERA
```

顺序为 **Look 在前、角色在后**。

**纪律要点**：

- 每回合先 `list_references` 读 `assets` 里 **`role=style`** 的卡（跨会话继续时尤其重要），**不凭记忆复述 tokens**；
- 同一份 tokens 在**所有镜头**里逐字节相同，不因镜头内容而改写措辞（镜头差异只体现在后面的 NEW ACTION / CAMERA 段）；
- tokens 与角色的 `subject_definitions` 关系：**Look 管画面整体，角色 lockedPrompt 管人物识别**，两者都要有；
- 无 Look 卡时（用户跳过 Look 采集 / 走预设出口）按 §9.3 处理。

### 9.3 没有 Look 卡时的回退

预设出口路径（§8 硬约束 1 的另一支）与「用户点名风格技能」都**不建 Look 卡** —— 风格约束由所选风格 skill 承担。此时不要凭记忆编 tokens，按该 skill 的规范执行即可。

## 10. 与其它步骤的衔接

| 步 | 衔接 |
| --- | --- |
| 澄清第 ① 步 | 形态题（多镜头 / 单镜精品）先问，再进入本文件 |
| 澄清第 ③ 步 | 画幅 / 总时长；项目预置则不问 |
| 工作流第 4–5 步 | 建角色资产卡、出定妆锚点与场景概念图；**Look 不占参考图席位**（见 §11） |
| ②-2 样张确认通过后 | **立刻落卡**（§9.1）—— 确认前不落：用户还没认，冻结没有意义 |
| 工作流第 6 步 | 逐镜出图，按 §9.2 注入 |
| Look 卡（CV-157，**已落地**） | `look_card` 把 tokens 与样张锚点资产化；本文件的采集/样张/steer 规则不变 |

## 11. 参考图席位规则（与 `consistency.md` 对齐）

`image_generate` **最多 3 张参考图**（后端 `image2image` 只有 `image1`/`image2`/`image3` 三个具名槽位，第 4 张会被**静默丢弃、不报错**）。当前占用：

| 槽位 | 占用者 |
| --- | --- |
| `image1` | 角色锚点拼图（四视图整图） |
| `image2` | 场景概念图 |
| `image3` | 首镜成图（仅「需要全局风格统一时」） |

**规则**：

- **Look 优先走文字注入（tokens 已在 prompt 里），不占参考位** —— 这是默认；
- 若确需视觉锚点（风格明显漂移时），**应取代 `image3` 而非新增第 4 张** —— Look 样张严格优于「首镜成图」（样张内容中性、且第 2 步就有，首镜成图含具体内容且第 6 步才有）；
- 两条路都**不改 3 个槽位总数**，不触碰后端契约。
