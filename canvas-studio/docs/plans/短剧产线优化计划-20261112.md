# 短剧产线优化计划（2026-11-12）

> 依据：`《雪林晓拳》`会话审计（3 轮 / 149min / 119 次工具调用 / 17 次视频生成）+ 代码核实。
> **无 CV 号**（未取号，按铁律不预领）。本文不进 STATUS，验收通过后按三层登记。
> 定位：把「已经存在但没被用上」的短剧能力接进路径，再补三个结构性缺口。

## 一、根因链（一条线，逐环给证据）

上次复盘把「短剧做成文艺短片」归因到执行层，**这个归因是错的**。真实因果链从项目预置开始，五环相扣：

| 环 | 现象 | 证据 | 归属 |
|---|---|---|---|
| K0 | 项目预置把「30 秒 / 2–3 镜」锁成事实，并**禁止就时长提问** ⇒ 短剧从错误的量级起跑 | `src/project-context.ts:106` 生成本段；`contracts/project.ts:217` `suggestShotCount` | 产品预设 |
| K1 | 题材 skill 靠关键词触发（短剧/连续剧/多集…）。本次输入是「把小说改编成视频」，**零命中** ⇒ `drama-format-director` / `drama-episode-executor` 全程未加载（31 个可用 skill 里就在列） | 会话 `available_skills` 含二者；`skills/canvas-studio-creation/SKILL.md:28` 只有一句「题材 skill 是知识型」，**无题材路由表** | 路由缺失 |
| K2 | 故事板只在 `storyboarding` 期可写，落地后整体重写被拒；「结构修订」工具 REQ-022 P2 **至今未实现**（代码注释自认）⇒ 用户要「更完整」时只能即兴追加，规划与产物脱钩 | `src/host-tools.ts:4107` 拦截文案 + 上方注释 | 已知欠账 |
| K3 | 分镜 `shot` 上限 15 ⇒ 117s 用 14 镜已贴天花板，短剧 20–30 镜直接撞墙 | `write_storyboard` 参数描述「全片 shot 上限 15」 | 硬约束 |
| K4 | 一致性全靠自觉、**无任何机器闸**：`tts_narration` 已返回可直接抄的 `voiceOver` 数组并明写「不要再自己加一遍」，仍被重排成 9/207/510（tts 报 15/208/372）⇒ 1 处重叠 −0.24s、第 16/17 句间隔仅 0.35s 被 ASR 听成一句；「Look tokens 逐字节复用」只存在于文案 | `src/host-tools.ts:1110`；`src/storyboard-render.ts:88`（无校验） | 校验缺失 |
| K5 | 视频出厂默认 **480P**，模型不主动升档 ⇒ 全片 480p 交付，中途「720p 渲染→上采样告警→回退」白烧一版 | `src/resolution-resolve.ts` 头注（图片 720P / 视频 480P） | 默认值错配 |
| K6 | 观感体检只提示不拒收，ML-08（无 exit）三版渲染都带着，`PROGRESS.md` 的「已知未决」仍是空的 | `src/remotion/motion-lint.ts:360` | 纪律执行 |
| K7 | 无对白管线：`tts_narration` 单音色锚，只能做旁白。短剧核心是**对白**，本次 17 句全旁白 | `src/host-tools.ts:3427` 起 | 能力缺口 |

**一句话**：短剧的手册（`drama-episode-executor`：单集 1.5–3 分钟、前 3 秒钩子、收尾断点、角色 ≤4、`lib:` 跨集）**早就写好了**，但没有任何一条路径保证它会被告知。

## 二、目标指标（下一部单集的硬指标，用于验收）

| 指标 | 目标 | 本次实际 |
|---|---|---|
| 单集时长 | 90–120s | 117.5s ✅（意外达标） |
| 镜头数 / 单镜时长 | 18–24 镜 / 3–5s | 14 镜 / 8.4s ❌ |
| 前 3 秒 | 有事件（非空镜） | 6.58s 纯雪夜空镜 ❌ |
| 收尾 10% | 断在动作/信息上 | 弱（收在「种进心里」抒情句）⚠️ |
| 对白 | ≥8 句（题材需要时） | 0 句 ❌ |
| 旁白 | ≤3 句（转场用） | 17 句 ❌ |
| 四视图锚点使用率 | 100% | 0%（全用原始参考图）❌ |
| 交付分辨率 | ≥720p | 480p ❌ |
| 单镜返工预算 | ≤2 次 | 17 次生成 / 14 镜 = 1.21 ✅ |

### P1 · 结构性缺口（需拍板后动）

- **P1-1 结构修订 / 追加镜头**（K2）。建议**最小版**：只允许 `append`（追加镜头/场次，不改已铸卡），不做任意重写。工作量最大，价值最高。
- **P1-2 分镜上限 15 → 30**（K3）。牵连画布排布、落地性能、`storyboard` 渲染。
- **P1-3 对白管线**（K7）：台词表（谁对谁说）→ 多音色 TTS → 逐句落位 → 与镜头/正反打绑定。
- **P1-4 短剧体检 lint**：钩子（前 3 秒有事件）/ 镜长 ≤5s / 收尾断点 / 旁白句数 ≤3。可与 P0-3 合并进同一套 lint。

### P2 · 可选

- **P2-1** 9:16 竖屏模板 + 字幕轨（短剧发布形态）。
- **P2-2** 抽帧读图自动降采样（长边 ≤768），消除本次 7 次 `IMAGE_OFFLOAD_REQUIRED` 失败请求。

## 五、不做清单

- 不做模型自动生成 recap（会编造），沿用 agent 写、人可改。
- 不做客户端剧集管理 UI（先工具面闭环）。
- 不允许故事板整体重写（这条纪律是对的，别为方便拆掉）。
- 本批不动 `deepseek-harness/` 本体，全部改动在 `canvas-studio/` 与 `dsh-plugin-desktop/` 侧。

## 六、验收纪律

- 每条闸必须有**反向变异**用例：故意写错，必须变红（项目铁律）。
- P0 全批跑 `yarn test:smoke` + `tsc` 双配置 + `verify:loader`。
- 真机复验：用本次同一段小说 + 同一句 prompt（「把这段小说改编成视频」）重跑首轮，判据是**是否加载 `drama-format-director` 并问集时长**——这是 P0 是否能救回短剧产线的唯一硬指标。
