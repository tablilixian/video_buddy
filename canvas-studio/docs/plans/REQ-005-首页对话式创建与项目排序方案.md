# REQ-005+ — 首页对话式创建（合并新建项目弹窗）与项目排序方案

> **需求来源**：产品讨论（2026-09-28）。把「新建项目弹窗」与「首页对话窗口」合并为**一个首页**：
> 用户在首页描述创意并回车，项目自动创建、首条消息自动发出，直接进入对话流。
> 覆盖 `docs/requirement-tracker.md` REQ-005 的未完成部分（项目按改动时间排序）。
> **文档性质**：交互 + 流程 + 技术方案，评审通过后进入开发。
> **已拍板决策**（产品确认，2026-09-28）：
> - D1 首条创意消息**自动发送**（创建项目 → 切入 → 消息自动进会话）；
> - D2 项目名称**自动生成**（创意摘要，不留手填输入框）；
> - D3 规格（画幅/时长/执行模式/分组）以**常驻一行 chips** 形式摆在输入框下方；
> - D4 旧弹窗**彻底删除**，新建入口唯一（首页）。
> **版本**：v1（2026-09-28）

---

## 1. 背景与目标

### 1.1 需求原文（产品讨论纪要）

> 能不能把新建窗口（图1）和第一个对话窗口（图2）结合起来，只保留图2。新的新建项目页面就是图2融合增加一些图1的信息。这样节省一个窗口，还能给 app 一个首页。

- **图1** = 新建项目弹窗（`ProjectList.tsx:529-702`，CV-092/099/196 迭代产物）：名称（必填）、所属分组、画幅、目标时长、执行模式。
- **图2** = lobby 首页（`StudioFrame.tsx:1311-1324` + `LobbyHero.tsx`）：中栏居中的**宿主 conversation 槽**（大输入框）+ 品牌条 + 推荐技能横滚。

### 1.2 现状痛点

| # | 痛点 | 证据 |
|---|---|---|
| P1 | **两条路径割裂**：开工必须先弹窗填表（名称必填），再切到对话里描述创意——同一个意图拆成两个窗口两步操作 | 弹窗入口三处：欢迎屏 `LobbyHero.tsx:48`、左栏 `ProjectList.tsx:377`、分组头 `:769` |
| P2 | **首页聊天发不出有用消息**：lobby 态无项目/工作区绑定，对话槽只是摆设；`LOBBY_COPY.hint` 却引导用户「在下面描述你的创意」 | `brand-copy.ts:49`；lobby 无 `createProject` 联动 |
| P3 | **名称必填在最先**：用户此刻往往没想好名字，表单是「开工前的一道墙」 | `ProjectList.tsx:256-257`（name 为空禁止提交） |
| P4 | **项目列表无时间排序**：`resolveVisibleSections` 分桶后保持 registry 创建顺序 | `project-sections.ts:39-70`；REQ-005 未完成项 |

### 1.3 目标

- **T1**：首页 = 唯一新建入口。输入创意回车 → 项目自动创建（摘要命名）→ 切入项目 → 首条消息自动发出 → 进入对话流。
- **T2**：图1 的规格信息不丢失——画幅/时长/执行模式/分组以常驻 chips 形式摆在首页输入框下方，默认「不锁定/跟随设置」。
- **T3**：旧弹窗删除，左栏「+ 新建项目」/分组头「+」改为跳首页并预选分组。
- **T4**（REQ-005 收口）：项目列表按 `updatedAt` 倒序；点品牌区回首页稳定可用。

## 3. 交互设计

### 3.1 首页布局（lobby 态）

```
┌──────────────────────────────────────────────────────┐
│  LogoMark  Canvas Studio 创意工坊                      │
│  你好，林小满 —— 从一句话创意开始                        │
│                                                      │
│  ┌────────────────────────────────────────────┐      │
│  │ 描述你想构建的内容…（大输入框，textarea）      │      │
│  │                                            │      │
│  └────────────────────────────────────────────┘      │
│  [画幅 ▸ 不锁定] [时长 ▸ 不锁定] [模式 ▸ 逐步确认] [分组 ▸ 未分组]   │
│  ↳ 回车即开工：项目自动创建，创意直接发给 agent          │
│                                                      │
│  推荐技能横滚（保留现状）   [+ 创建示例项目] [🗂 资产库]  │
└──────────────────────────────────────────────────────┘
```

- **LobbyComposer（新组件）**：大输入框（textarea，自增高、Enter 发送 / Shift+Enter 换行）+ 规格 chips 行 + 说明句。替代 lobby 态中栏的宿主对话槽。
- **规格 chips（D3）**：从 ProjectList 弹窗抽取的 `ProjectSpecChips` 共享组件——画幅四选（不锁定/16:9/9:16/1:1）、时长五选（不锁定/15/30/60/自定义）、执行模式二选（复用 `ModeSwitch` variant="choice"）、分组下拉（未分组 + 用户分组）。**默认值**：画幅/时长 = 不锁定（空串），模式 = 设置页「默认执行模式」（沿用 `getDefaultMode` 惰性读取模式），分组 = 未分组。
- **LobbyHero 简化**：「+ 新建项目」按钮删除（首页即创建页）；「创建示例项目」「资产库」保留。
- **提示句**（brand-copy 更新）：`hint` 改为「描述创意，回车即开工——项目自动创建，agent 直接开始」。

### 3.2 三态布局变化

| 态 | 判据（`StudioFrame.tsx:1488`） | 中栏内容 | 宿主对话槽 |
|---|---|---|---|
| lobby | `projectId === null` | **LobbyComposer**（替代） | **CSS 隐藏**（保持挂载，见 §5.1） |
| lobby-pending | 有项目、`!hasConversation` | SlateBar + 聊天居中 | 显示（现状不变） |
| work | `hasConversation` | 画布 + 右栏聊天 | 显示（现状不变） |

> **约束**：宿主 conversation 槽**永远不能条件卸载**（`LobbyHero.tsx:1-9` 模块注释：卸载重建丢草稿/滚动/会话绑定）。lobby 态隐藏走 CSS（`display:none`），`renderSlot('conversation')` 保持常驻 JSX。

### 3.3 入口变化（D4）

| 现入口 | 现行为 | 新行为 |
|---|---|---|
| LobbyHero「+ 新建项目」 | 打开弹窗（`projectFormOpen`） | **删除按钮** |
| 左栏「+ 新建项目」 | 打开弹窗（未分组） | `goHome()` + 预选分组 = 未分组 |

## 4. 核心流程

### 4.1 创建时序（T1 主链路）

```
用户在 LobbyComposer 输入创意，回车
│
├─ ① 前端摘要命名（§5.2）：summarizeName(idea) → dedupeName(name, projects)
├─ ② createProject(name, groupId, plan, mode)         # index.ts:1236 现有
│     └ createStudioProject → refreshProjects → openProject
│         └ select → 绑定/建 workspace → 会话 clear → resume|startSession
│           → reloadCanvas → syncHasConversation        # 全部 await 完成后才 resolve
├─ ③ 自动发送（复用 wakeAgent 模式）：
│     sessionId = sessionSvc.list.getSnapshot().current
│     sessionSvc.scope(sessionId).get('conversation').send(idea)
├─ ④ 首条 prompt ACCEPTED → blank 翻转 → hasConversation=true
│     → 布局自动 lobby-pending → work（CV-064 二期机制，零改动）
└─ ⑤ Composer 清空草稿、规格复位
```

- **就绪保障**：`openProject` resolve 时 `startSession`/`resumeLatestSession` 已 await 完成（`index.ts:1207-1214`），当前会话应已就位。发送前仍检查 `sessionId !== undefined`；未就位时等 `sessions.list` 订阅触发（超时 3s，见 §5.4）。
- **blank 翻转自动切 work** 是既有机制（`index.ts:1034-1039` 订阅），本方案零改动。

### 4.2 交互细节

- **输入为空**：发送按钮禁用、Enter 无效（与弹窗 `createName.trim()` 同规则）。
- **创建中**：`creating` 态下 Composer 输入与 chips 禁用，按钮显示「开工中…」。
- **发送失败降级**：项目已建但 `send` 抛错/超时 → toast「项目已创建，创意未能自动发送」+ 文本注入对话输入框（`insertReferenceToken` 能力，`StudioFrame.tsx:867-896`）+ 布局停在 lobby-pending，用户回车即发。
- **ESC / 点外部**：Composer 是常驻页面不是弹窗，无关闭语义；草稿保留在本地 state（lobby 态切走再回来不丢——组件保持挂载即可，不需要 localStorage）。

## 5. 技术设计

### 5.1 LobbyComposer 与对话槽共存

- `StudioFrame` lobby 分支（`:1311-1324`）改为渲染 `<LobbyComposer …>`；`<LobbyHero>` 收缩为顶部品牌区（删双 CTA 里的新建按钮）。
- styles.ts 新增：`.csFrame[data-mode="lobby"] .csConversation { display: none }` + `.csLobbyComposer` 布局段（居中、最大宽度约 720px，对齐宿主输入卡视觉）。
- `renderSlot('conversation')` 的 JSX 位置**不动**（`:1806-1808`），仅靠 data-mode 切换可见性。

### 5.2 自动命名（D2）

新纯函数（放 `src/` 根，可单测，Host/Client 两侧无关）：

```ts
// src/project-naming.ts（新）
summarizeName(idea: string): string
// 1. 折叠空白（换行/制表 → 单空格）、去掉控制字符与 / \（validateProjectName 的黑名单，projects.ts:94）
// 2. trim 后取前 20 个码元（≤80 上限留重名后缀余量）
// 3. 结果为空 → 兜底「未命名项目」

dedupeProjectName(name: string, taken: readonly string[]): string
// 大小写不敏感比对（对齐 projects.ts:440 的 toLowerCase 口径）；
// 撞名追加「 2」「 3」…（与 uniqueDirName 同思路，但作用在 name 上）
```

- **去重的责任在客户端**：store 里已有全量 `projects`，`createProjectFromIdea` 调 `createProject` 前先 dedupe。Host 的重名校验（`:440-442`）保持不变，作为最后防线。
- **不采用的替代**：Host `create` 加「自动命名模式」跳过校验——改动 Host 契约、且重名语义变成隐式，收益不成比例。

### 5.3 回首页的稳定性（goHome 抑制）

现状缺口：`actions.select(null)` 后，`workspaces.list` / `sessions.list` 任何变化都会触发 `syncActiveProject`（`index.ts:598-607`）→ `resolveActiveProjectId()` 从最近 workspace 解析出项目 → **重新 select，把用户踢回 work 态**。品牌区回首页因此时灵时不灵（REQ-005「已具备」的说法只对了一半）。

方案：store 增加瞬时标志 `homePinned: boolean`（不持久化）：

```
goHome(): actions.setHomePinned(true) + actions.select(null)
syncActiveProject 开头：if (snapshot.homePinned) return
openProject / createProject 成功路径：actions.setHomePinned(false)
```

- 左栏「+ 新建项目」/分组头「+」与品牌区点击（work 态）都走 `goHome()`。
- 回首页时**不清当前会话**（用户可能马上点回项目继续聊）。

### 5.4 自动发送的就绪重试

```ts
async function sendFirstMessage(idea: string): Promise<boolean> {
  // 最多等 3s：sessions.list 订阅 + current 就位即发；超时返回 false 走降级
}
```

- 成功：静默。
- 失败：toast + 文本注入输入框（§4.2），**项目不回滚**（建好的项目是资产，不是垃圾）。

### 5.5 REQ-005 排序收口（T4）

- **比较器**：`resolveVisibleSections` 内分桶后，每桶按 `updatedAt` 倒序（`String.prototype.localeCompare` 对 ISO 时间戳即字典序=时间序；不可解析的记录排最后）。模块注释「排序口径只有一处」由此延续。
- **写回点补齐**：
  - 打开项目写回 `updatedAt`（语义：「最近在用」正是列表要回答的问题）。Host 新增 `touchProject(projectId)`（registry 单字段 patch，复用 `updateWorkflow` 的落盘模式 `projects.ts:622-635`），`openProject` 成功路径调用。
  - `moveProjectToGroup`（`projects.ts:601-615`）现不写 `updatedAt`——顺手补上（移动分组是显式改动）。
  - 其余写点已覆盖：create / updateWorkflow / setPendingQuestion / answer（`projects.ts:453,630,649,673`）。
- **分组段顺序**：维持 `groups.order`（不在本需求范围）。
