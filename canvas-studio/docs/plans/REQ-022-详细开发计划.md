### 二.1 为什么把原批 1/3/4 重新编组（实施时撞到的硬约束）

**3 态迁移与「三 submit 工具下线」是同一个原子变更的两半，不能拆批**：

- 状态翻转点全在待删工具里：`host-tools.ts:1930`（`submit_storyboard_for_approval` → `awaiting_approval`）、`:2174`（`submit_screenplay_for_approval` → `script_review`）、`:1989`（关键帧，保留）。
- 审批 UI 按旧态 keying：`client/StudioFrame.tsx:2064`（`script_review`）、`:2083`（`awaiting_approval`）；`routes.ts:1712/1716/1718`（reject / approve_script / reject）落 `drafting`；`client/index.ts:1215-1279` 的 approve/reject 处理器同源。
- ⇒ **只删状态、留工具**：confirm 模式提交后没有审批条可点 ⇒ **死锁**。**只删工具、状态未改**：类型报错。
- ⇒ 落地按钮（依赖 overlay）必须与原子批同期在场，否则原子批本身就会开一个「无门可过」的缺口。

**故新顺序**：先把**纯增量**的部分做完（数据层 + 渲染 + overlay 只读路由，零破坏、可独立验收），再上原子大批。这样原子批上场时 overlay 与渲染函数已在，切换没有缺口。

> 下文 **§四~§七 是「落点库」**，按 §二.1 重新编组归属：§五（数据层）+ §七（overlay 只读部分）→ **CV-293**；§四（状态机）+ §六（seed/工具下线）+ §七（落地按钮部分）+ §八 纪律小节 → **CV-295**。落点行号仍然有效，只换了编排。

| 客户端 | `client/StudioFrame.tsx` 顶条加按钮（状态角标：草稿 vN / 缺 N 项 / 已落地 vN）+ 全屏覆盖层容器 + `postMessage` 监听 + 落地成功后关 overlay + `reloadCanvas` |
| 落地路由 | 三层校验（schema / `validateForSeed` / 确认清单）→ `seed(final)` → 写 `executing`；**按钮永不 disabled**，缺项弹 blocker modal；**单向终点**（落地后版本入口消失） |
| 纪律注入 | 新增 `storyboard-discipline-prompt.ts`（照抄 `plan-prompt.ts`，order **153**；`§00` 禁令 + `§08` 进 system prompt；未落地缓存空不注入） |

**验收口径**（端到端）：
- 桌面：设计期点按钮 → overlay 打开（非只读，版本可切）；缺项时 blocker modal 列出「缺什么 + 在哪分节 + 跳转」；补齐 → 确认清单 → 落地 → 转 `executing`。
- 落地后：按钮角标变「已落地 vN」，overlay 转只读，版本入口消失；**整体重落被拒**。
- iframe 同源：无跨域报错、`postMessage` 直通、overlay 内点按可用。

**风险**：overlay 内按钮 → 外壳的事件协议（`postMessage` 消息形状）需与 `client` 侧约定一致，否则「点了没反应」；建议本批先只做「打开 + 只读」，落地按钮作为第二步落（便于二分定位）。
**回退点**：overlay 路由与 client 入口各自独立，可单独回退为「藏在 URL」的手动打开。
