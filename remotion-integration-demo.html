04 功能缺口：现在差什么

绿色 = 新增能力；琥珀/红 = 需要在集成时补的工程或风险。

P0 缺口

没有代码驱动合成引擎

现状 compose.ts 只是 ffmpeg 的 concat+amix+afade，做不了字幕卡/数据卡/动态图形/精确转场——这正是 REQ-034 科普视频的硬缺口。

P0 缺口

没有 CompositionManifest 契约

「成片结构」现在隐式写在 skill 的 STEP 里，没有结构化中间层。需新建 src/remotion/manifest.ts（devdoc §4 定稿契约）。

P1 工程

Chromium 打包 / 搬运

本机 agent shell 受 com.apple.provenance + 沙箱限制；universal 包须在用户终端跑，且要走 ELECTRON_MIRROR / ELECTRON_BUILDER_BINARIES_MIRROR。

P1 工程

长片阻塞 agent 回合

Remotion 渲染分钟级。MVP 先做同步工具（镜像 compose_video），长片/批量再接入 Drama 任务恢复轮询做异步。

P1 盲区

幻灯片风险评分缺失

有 quality-check.ts 但无 OpenMontage 式 6 维「一堆图假装视频」评分，需阶段 A 增量补。

P1 已定

字体方案（已定：混合 C）

随包思源黑体子集兜底（离线必出片）+ global.fonts 声明的字体从自托管源按需下载缓存到 userData（多语言可扩展，OFL 许可）+ 失败 fallback warning。详见 devdoc §8。

P1 已定

字幕时序（句级已定，词级二期）

Drama TTS 无时间戳（已核实）→ 句级用「探真值总时长 + 字数比例分配」（§10.3）；词级 KTV 式需 TTS 时间戳或 forced alignment，列二期。

P2 已定

资产喂法（已定：方式 B）

落地拷贝到 publicDir + src 重写 + staticFile()（devdoc §8），隔离 / 离线 / 可复现；放弃 webServer URL 直连。

05 我的评估：这事儿咋样

结论：干净、低风险、值得做；MVP 约 3~4 周单人。

你们不是从零造视频引擎，而是给已有「模型驱动主干」并联一个「代码驱动旁路」。80% 的地基（agentic skill、Drama 模型层、ffmpeg 后期、storyboard 契约、HITL 审批、统一错误系统）都现成，Remotion 只补最薄的一层「逐帧渲染 + 卡片组件」，且 License 对两人公司免费。最大不确定性不在代码，而在打包期 Chromium 进 electron 包——但这有「复用 Electron 自带 Chromium」的规避路径。

✅ 优势 / 利好

  • 复用度极高：ffmpeg 二进制、webServer 资产路由、ComposeResult 形状、HITL 门禁全部直接复用，客户端零改动。
  • License 零成本：两人公司落在 Free License，商业使用免费；服务端 renderMedia + LLM 生成代码均被允许。
  • 与现有分层天然契合：render_composition 是纯 Host 工具（Chromium 跑在 Node 侧），不碰 Client 渲染。
  • 补课即 REQ-034：字幕卡/数据卡/转场正是「低成本科普视频」刚需，补完即达标；且是项目第一个真正烧字幕进画面的路径（现有 subtitle_burn 仅占位）。
  • 字幕与字体口径已定稿：句级字幕「探真值 + 字数比例分配」零新依赖；字体混合方案（随包子集 + 自托管下载缓存）天然支持多语言扩展。
  • 可灰度：新增工具并联而非替换，老流程 compose_video 不受影响。

⚠️ 风险 / 注意

  • Chromium 打包：唯一硬骨头。须在用户本机 Electron 实跑验证，不能在 agent shell 验证 GUI。
  • 双 ffmpeg 陷阱：务必显式传 ffmpegExecutable，禁用 Remotion 自带，否则打两份且版本打架。
  • 测试需 Chromium：集成冒烟须 gate 在「浏览器可用」，CI 无头环境跳过，仿 ffmpeg 真跑冒烟判定。
  • 别开放用户上传 Remotion 代码：License 禁区；我们只用自己生成的代码 + 服务端渲染。
  • 长片体验：同步渲染会卡 agent 回合，长片需异步化（二期）。
