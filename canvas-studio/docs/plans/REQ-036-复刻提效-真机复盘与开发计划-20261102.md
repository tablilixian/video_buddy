## 1. 问题清单（证据 → 代码 → 根因 → 修法）

### 缺陷 1 · `parseLufs` 取第一个匹配，响度恒读 -70 LUFS（P0 · 确定性 bug）

- **证据（已实测复现）**：对参考片 mp3 跑 `ebur128`，stderr 共 152 行 `I: … LUFS`，首行是 `I: -70.0 LUFS`（前 400ms 无门控块），真值在 Summary 段 = **-11.4**。会话里 `analyze_beats` 回填出 -70。
- **代码**：
  - 错：`src/beat-analyze.ts:366-371` —— `/I:\s+(-?\d+(?:\.\d+)?)\s+LUFS/u.exec(stderr)` 取**第一个**匹配。
  - 对（同一事实的另一次实现）：`src/ffmpeg-run.ts:312-317` —— 行锚 `^\s*I: … LUFS\s*$` + **取最后一个**匹配。
  - 测试：`tests/beat-analyze.test.mjs:110-126` 只喂 3 行 Summary 段，**fixture 里没有进度行** ⇒ 该函数等于零覆盖。
- **根因**：同一事实两份实现，正确的那份没被复用；测试只覆盖"理想输出"。
- **修法**：删掉 `beat-analyze.ts` 私有实现，改为导出并复用 `parseEbur128IntegratedLufs`；fixture 补"≥5 行进度 + Summary"；反向变异：把"取最后一次"改回"取第一次"必须变红。
- **影响面**：`06_sound.bgm.lufs` 回填、拆解表"参考片响度"列、以及 skill §5「成片 vs 原片 ±2dB」这一整套对照判据，全建立在这个错值上。**注**：成片侧的 Q1 响度闸走 `probeLoudnessLufs`（`src/ffmpeg-run.ts:328`），用的是正确实现，**未坏**。

### 缺陷 2 · 抠图没有机器判据，CV-394 被误判弃用（P1）

- **证据**：会话唯一一次 `image_matting` 产出的 `split/1_caramel-alpha.png` 被判"失败"弃用，判据是"角上 alpha=255 ⇒ 白底没抠掉"；但那是**圆角白卡**，圆角本来就该保留不透明。随后改用自写 alpha 蒙版。
- **代码**：`src/host-tools.ts:4300-4306` 返回纯文本，第 3 行写「把产物叠在任何深色卡上**目视**边缘」—— 对没有视觉的模型是不可执行指令；`src/image-matting.ts` 共 127 行，**无任何 alpha 统计**。
- **根因**：「质量自查」这一步的判据既不在代码里、也不在工具返回里，只能由模型自己发明，于是发明错了。
- **修法**：抠图后用已有零依赖解码器（`src/inspect-image.ts:94 decodePng`）算四项真值随结果返回 —— ①透明像素占比 ②残留底色占比 ③四角 alpha ④colorType；并给阈值，如"透明率 <15% ⇒ 明确写没抠到，调 similarity 或换 key"。删掉"目视"措辞。
- **验收**：两种 fixture（lavfi 白底红方块 / 圆角白卡）断言返回数值；反向变异：把判据改成"四角必须为 0"必红。

### 缺陷 3 · 没有"从大图切子图"的工具 → 52 次 PIL 脚本 + 手工伪造资产（P1）

- **证据**：52 次 bash 含 PIL/numpy（29.8 分钟）。步 84/92/110 自写脚本探测拼贴格边界并裁出 `p1_in.png`…`p6_in.png`；最后一步用 `shutil.copy` 把 5 张裁好的图以**手搓 uuid** 塞进 `assets/`——无画布节点、无血缘、asset-gc 看不见。
- **代码**：38 个工具（`tests/tool-registry.test.mjs:39`）里**没有任何裁剪类**。CV-392 的 `sourceRect` 只解决"渲染时取子区域"，解决不了"要一张独立素材去 `image_generate` 当参考 / 去 `image_matting` 抠底 / 去 `upload_image` 上传"。
- **根因**：REQ-036 方案里 R-3 的原话是「精灵图可先由 Agent 预裁切」—— 这一条把 40 分钟脚本成本写进了流程，且没有任何"产物必须登记"的约束。
- **修法**：新工具 `image_crop`：`filePath` + `rect{x,y,w,h}`（百分比，与 `sourceRect`/`box` 同口径）或 `grid{cols,rows,col,row}`；ffmpeg crop 落地；产物走 `saveLocalAssetBytes` **建画布节点**（有血缘、可复用、可被 GC 看见）。skill 明令禁止手写 PIL 裁剪与 `cp` 进 assets。
- **验收**：1280×480 九宫格 fixture → 9 次 crop 得 9 张 426×480（±1px）；产物节点的 `sourceIds` 指向源图节点。

### 缺陷 4 · 契约只能靠读源码（73 次 grep/sed = 40.5% 模型时间）（P1）

- **证据**：`src/remotion/manifest.ts` 被读 **18 次**、`src/host-tools.ts` **15 次**、`src/contracts/storyboard.ts` **6 次**、`src/compose.ts` **5 次**；读法 42 次 `sed -n` 段读 + 37 次 `grep`。
- **代码**：`src/remotion/manifest.ts` 2175 行；手写契约 `skills/code-driven-explainer/references/manifest-contract.md` 39.6KB；CV-365 已手工补过 16 条"读源码才看得到"的实现细节，本轮**仍然读 18 次**。
- **根因**：手写文档与源码之间没有机器约束 ⇒ 文档永远少一条；而且模型对"手写文档是否最新"没有信任依据，宁可直接看实现。
- **修法**：`scripts/gen-manifest-fields.mjs` 从源码（接口 / 常量 / 枚举）**生成** `manifest-fields.md`（每轨字段 / 类型 / 必填 / 默认 / 枚举），门禁测试：重新生成与仓库文件 diff 即红；skill 指向生成物，`manifest-contract.md` 只留"怎么写 / 为什么"。
- **验收**：生成物覆盖全部 7 类轨道；改 `manifest.ts` 任一字段不重生成 ⇒ 门禁红。

### 缺陷 5 · 「落便签过目」无通路，模型自我说服跳过（P1 · 流程断裂）

- **证据**：
  - `skills/viral-remake/SKILL.md:48-49`：「回核过了再**落便签给用户过目**，不要边拆边渲」。
  - 模型步 78：`grep -rn "便签\|note" src/host-tools.ts` → 只找到"读画布 notes"；步 79：`grep -rn "appendTextNode|createTextNode|noteNode"` → 空。
  - 步 70/88/99/108/111/114 六轮纠结「要不要停」，合计约 11 分钟，最终选择直接跑。
- **代码**：唯一能写 text 节点的是 `write_script`（`src/host-tools.ts:2932`），语义是"成片文案"，且被 `src/storyboard-gate.ts:62` 锁在故事板 landed 之后；`src/workflow-mode-prompt.ts:47-48` 规定 auto 模式「ask_user_choice 不提问、不等待」。
- **根因**：三条约束互相封死 —— skill 要求落便签 / 工具集没有落便签的手 / auto 模式不许问。模型**没有"交付中间成果"的合法动作**，只能二选一：违反 skill 或违反模式。
- **修法**：新工具 `write_note`（画布 text 节点，标题"拆解表"，**不受** storyboard 门，纯信息不触发产线）；viral-remake 拆解阶段写成显式检查点：`verify_teardown` 通过 → `write_note(拆解表)` → confirm 模式停等 / auto 模式**落便签 + 一行文本说明后继续**（不许静默跳过）。
- **验收**：auto 模式跑一次复刻，画布必须出现拆解表便签节点；transcript 必须有 ≥1 个 `text` 块。

### 缺陷 6 · 全程 0 条可见文本（P1）

- **证据**：172 条 assistant 消息 → `text` 块 0、`reasoning` 152 段、`tool-call` 195 次。用户看到 195 张工具卡，没有一句人话。
- **代码**：无任何提示词禁止输出；`src/workflow-mode-prompt.ts` 只规定"不打断用户"。
- **根因**：模型把"不打断"理解成"不汇报"，且没有任何"阶段收尾要交代"的纪律；平台也没有"必须交代"的位置。
- **修法**：总纲 + 复刻 skill 各加一条：每阶段收尾 1–3 行文本（做了什么 / 结论 / 下一步），停手前必须有；与缺陷 5 的便签配合。
- **验收**：同一任务 `text` 块 ≥ 阶段数（≥4），单块 ≤5 行。

### 缺陷 7 · 单 turn 173 步、两次压缩（P2）

- **证据**：一个 turn 跑 173 步；48 min / 76.5 min 各压缩一次；压缩后同一决策重推一遍。
- **修法**：阶段切分（拆解 → 停/汇报 → 映射 → 渲），拆解完成点用 `exec.concludeTurn()`；skill 写"拆解完成后结束本回合"。
- **验收**：同类任务 turn 数 ≥3、单 turn 步数 ≤60。

### 缺陷 8 · 运行时落后，验收等于没验（P0 · 流程）

- **证据**：运行时 `~/Desktop/job/git/playsout/videobuddytest` HEAD = `fe280aed5e`（批三）；dev/origin = `ce2e6e34c5`（批四）；`teardown-store.ts` / `timing-segments.ts` 运行时**不存在**；`render_composition` 参数表无 `timingSegments`。
- **根因**：开发 checkout 与运行时 checkout 是两份，push 不等于运行时有。
- **修法**：验收前置自检三条（工具表 40 个 / `render_composition` 有 `timingSegments` / 批四新文件存在），升级后重建重启再验收。

### 缺陷 9 · 模型无视觉（根因，待拍板）

- **证据**：`read_image` 直接报 `model does not declare image input`；reasoning 里 29 次"我看不到图"；所有视觉问题只能走 `image2vl`（10 次）或自写像素脚本（52 次）。
- **代码**：`src/gateway.ts` 的模型行由 DramaServer `/v1/models` 目录动态生成 —— 是否存在支持图像输入的模型取决于目录；`src/host-tools.ts:711` 已诚实写了「具备读图能力时先看图；看不了就说明未做画面自检」。
- **修法（两条路，待拍板）**：① 目录里有视觉模型 ⇒ 增加"看图位"模型行，专供 `image2vl` / `qc_shot` 这类子任务；② 没有 ⇒ 给 `image2vl` 加 `region`（服务端裁切后送 VL），让拼贴图逐格可问。短期由缺陷 2/3 的工具兜住。

### 缺陷 10 · TTS 重复合成（P2 · 新观察，待确认）

- **证据**：该项目目录 24 条 `tts_voiceover` 节点 / **14 条唯一文本** / 旁白仅 6 句，全部在 184 秒内生成（`1793621133172 → 1793621317574`），可归为 4 稿改词。

- **待确认**：4 稿是刻意 A/B 还是反复改稿。

## 5. 优先级与理由

1. **1-a 先做（parseLufs）** —— 唯一确定性错值，1 行 + 1 条 fixture，且它污染的是"复刻像不像"的核心判据（响度对齐）。留着它，后面所有"响度对了没有"的结论都不成立。
2. **1-b 紧随（运行时升级 + 补验收）** —— 不升级，第二批起的任何改动都验不了；本轮 6/7 项验收其实是空的，成本只有 10 分钟。它同时堵住"新代码没生效"这个反复出现的根。
3. **第二批在第三批前** —— 二批消掉的是 28.2%（python）的模型时间**和** 5 个无血缘资产；收益是"每次复刻都省"（复利）。三批的收益是"人被看见"，价值同样高但属流程正确性，因此只做最小集（`write_note` + 检查点 + 收尾一句话），不铺开。
4. **第四批最后** —— 收益最大（40.5% 的源码税）但最重：要写生成器 + 门禁 + 改 skill 指针，且需要二/三批的产物稳定后才知道"哪些字段该进生成物"。手写文档已试过（CV-365 补 16 条），本轮仍读 18 次 —— 说明**必须机器生成**，不能再加一段散文。
5. **不做的事**：不加"想少一点"的提示词（治症状，反而漏判）；不预领 CV 号（验收后才取）。
