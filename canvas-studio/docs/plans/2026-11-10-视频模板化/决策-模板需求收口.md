## 一、一句话定义

**模板 = 一份「已经验证过审美、且带参数合同」的 manifest 骨架。** 模型填参数即可出片；填不动就退回自由编排。

它**不是**：

- 不是 Remotion 工程（不搬 TSX，不 vendor `.motion` 包）
- 不是"只能填文案的死板模板"（骨架可继续改，改完还能出片）
- 不是模型的第一选择（是**候选起点**，见 §3 决策树）

### 1.1 模板要解决的三个问题（对应总原则）

| 总原则 | 转成架构约束 |
|---|---|
| **① 用户明确选模板 → 走模板；否则除非非常确定，模型自己编排** | 模板通道必须 **opt-in**；"非常确定"必须是**机器可判据**（§5），不能靠模型自觉 |
| **② 降低 agent 最耗时的那部分，同时解决审美不稳定** | 省的是**模型侧试错**（实测：会话 #5 = 187.6 分钟，渲染只占 40 秒）；审美靠"整片已验证"保证，**组合会削弱这一点**（§4.3） |
| **③ 模板可再拆分、可组合** | 拆成**段**（不是任意块）；段必须带四个约束才能组合（§4.2） |

## 二、模板到底是什么形态（已定）

### 2.1 三层分工，LLM 只认中间那层

| 层 | 内容 | 谁看 | 形态 |
|---|---|---|---|
| ① 模板源文件 | `manifest.json`（真实可渲，文本写成 `{{slotId}}`） | 模板作者 | **不写编译器**，见 §6 P-3 |
| ② **参数合同** | `slots.json`（id/type/maxChars/maxLines/required/usage/example）+ `meta`（体裁/时长档/素材需求/风格族） | **LLM** | 这是模板对 LLM 的唯一接口 |
| ③ 渲染产物 | 替换占位符后的 manifest | 引擎 | 走现有 `validateManifest` |

**为什么①不用 spec + 编译器**（推翻 `任务包-1` 的默认路）：

- 实测 `text` 只校验「非空字符串或非空字符串数组」（`src/remotion/manifest.ts:1597-1599`），**不检查内容** ⇒ `{{b1.keyword}}` 合法
- ML-11/ML-12 字幕检查只针对 `variant:'subtitle'`，且**只告警不阻断**（`src/remotion/motion-lint.ts:394-418`）⇒ 占位符不误报
- 省掉编译器 = 省掉 `任务包-1` 里最重的一块（2–3 周里的大头），且**不改变 LLM 体验**（LLM 本来就只填 slots）
- `任务包-1:281` 自己写着「LLM 不该手写 spec —— 它只该填 slots」，即 spec 那层对 LLM 不可见

**代价（必须接受）**：占位符方案不能表达"参数改变轨道数/段数"。这类需求由 §4 的段组合承担，不由编译器承担。

### 2.2 模板目录（落在 `assets/templates/`）

```
assets/templates/<style-family>/<template-id>/
  manifest.json     # 真实可渲骨架，文本字段是 {{slot.id}}
  slots.json        # ★ 参数合同（对 LLM 的唯一接口）
  meta.json         # 体裁/时长档/素材需求/风格族/授权/版本
  audio.json        # 音效事件表（锚定到轨，非绝对帧，见 §7 K-8）
  frames/           # 参考帧基线（同源可访问，见 §7 K-1）
  preview.gif       # 预览（复用 style-demos 的 prefix 路由先例）
  README.md         # 给模板作者
```

**为什么是 `assets/templates/` 而不是包根 `templates/`**：`package.json` 的 `files` 白名单是 `[cordis.patch.yml, assets/**, lib/**, skills/**, README.md]` ⇒ 包根 `templates/` **不会被打包发布**。

## 三、入口：唯一链路 + 三个起点（本次最重要的架构决定）

### 3.1 不做第二套出片入口

```
起点 A：模板        scaffold_manifest({ templateId, slots, writeTo })
起点 B：体裁配方    scaffold_manifest({ recipe })            ← 已有
起点 C：从零        scaffold_manifest({ title, durationSeconds }) 或直接写
                              ↓  都是「产出一份 manifest 并落盘」
                     build/manifest.json
                              ↓
                     render_composition({ manifestPath })     ← 唯一出片口
```

**理由**：模板产出的 manifest **可以继续被模型编辑**（加轨、改配色、换文案）。这正好实现"模板不够就自己编排"——而且是从一个高质量起点改，不是从零。

若另开 `render_composition({templateId, slots})`：

- 模型拿不到中间产物，**无法微调** ⇒ 模板变成"要么全接受要么全弃"的二值选择
- 与既有 `manifest` / `manifestPath` 形成三路互斥（`src/host-tools.ts:3670` 现有二选一），多一条必错的分支
- 内联 >30KB 被截断拒收（`src/host-tools.ts:3650`）⇒ 必须落盘，绕回同一条路

### 3.2 工具增减（比原计划少一个工具）

| 工具 | 动作 | 说明 |
|---|---|---|
| `list_templates` | **新增**（只读） | 支持按 体裁 / 时长档 / 素材需求 / 风格族 过滤，返回摘要不返回全文 |
| `scaffold_manifest` | **改** | 加 `templateId` + `slots`（与 `recipe` 同层互斥）+ `dryRun`（= 原 `describe_template`） |
| `describe_template` | **不做** | 合并进 `scaffold_manifest({templateId, dryRun:true})` |
| `render_composition` | **不动** | 仍是双通道 |

### 3.3 用户入口（原计划的硬缺口）

`任务包-1:400` 明文「❌ 不做模板编辑 UI（先让 LLM 能用）」⇒ **用户今天没有任何途径"明确选择模板"**。

分两步，MVP 不写 UI：

| 阶段 | 用户怎么说 | 实现 |
|---|---|---|
| **MVP** | 对话内：「用那个 XX 风格的」「给我 3 个样式选」 | `list_templates` 结果由模型在对话里呈现，用户回复选择 ⇒ 零 UI 代码 |
| 后续 | 画布侧模板墙 | 独立需求，与 `REQ-033`（toolbar 三入口）合并排期 |

> MVP 的"对话内选择"完全满足总原则①：用户的话就是明确选择，不需要点按钮。

## 四、粒度：整片 + 段（回答"能否拆分组合"）

### 4.1 三级粒度，能力递增、风险递增

| 粒度 | 形态 | 解决什么 | 状态 |
|---|---|---|---|
| **G1 整片模板** | 一份完整 manifest + 槽位 | 审美稳定 + 省时 | **本期做** |
| **G2 段模板** | 按段（hook / body / outro）声明，可跨模板拼 | 内容长度不匹配（G1 最大硬伤） | 本期留接口，Phase 2 做 |
| **G3 构件/卡片** | 24 张卡 + 9 构件 + 4 主题 | 组合空间放大 | 1C / Phase 2 已在做 |

**G1 的硬伤必须承认**：模板固定 18s、固定 6 个槽位，遇到 60s / 12 个要点的内容就套不进去。这是"50 个模板也不够用"的根因。G2 就是解决它的。

### 4.2 段要能组合，必须带四个约束（缺一必出烂片）

| 约束 | 字段 | 为什么必须 |
|---|---|---|
| ① **时长弹性区间** | `duration: { min, preferred, max }` 帧 | 段内容长短不同，固定时长会崩；但无限弹性会拉坏节奏 |
| ② **入口/出口视觉状态** | `enter: {from}`, `exit: {to}` | 段 A 的出场元素必须能被段 B 的入场接住，否则跳帧 |
| ③ **槽位命名空间** | `slots[].id` 带段前缀，组合时重写 | 两段都叫 `keyword` 会撞 |
| ④ **风格族** | `meta.family` | **同族才能拼**。跨族拼（冷科技 + 暖叙事）必然丑 |

### 4.3 组合的技术成本：比预期低得多（关键实证）

本仓已有工业级的顺序衔接，**拼段不用手算帧号**：

| 能力 | 实现 | 证据 |
|---|---|---|
| 段按序拼接、自动算 `startFrame` | `startAfter: { trackId, gapFrames }` | `src/remotion/normalize-timing.ts` |
| 叠化转场 | **负 gap**（`-10` = 重叠 10 帧） | `manifest.ts:264`「10 帧叠化就写 -10」 |
| 前向引用 / 自环 / 负起点 / 转场窗口不足 | 全部有校验与告警 | `normalize-timing.ts` 逐条检查 |
| 转场效果 | 11 种（fade/slide/zoom/dissolve/wipe*/clock/flipX/blur*/crossWarp） | `manifest.ts:563` |
| 时机锚定（不写绝对帧） | `anchor` 锚 caption 轨的句/词窗口 | `host-tools.ts:4430` |

⇒ **组合器要做的事只剩四件**：① 段拼接（用 `startAfter`，免费）② **重算 `meta.durationInFrames`**（`normalize-timing.ts` **只重算 track 的 startFrame，不动 meta**，必须自己 reduce 一遍）③ 槽位命名空间重写 ④ 音效事件随段位移。

### 4.4 但组合会削弱"审美稳定"（总原则②的边界）

G1 的价值是「整片被验证过」。G2 组合后，**每段都好看、拼起来难看**是常态（节奏断、配色跳、转场多余）。所以：

- **不建议**做成"任意段自由拼"（会退化成让模型自己编排，还多了套壳成本）
- **建议**做成"**风格族内、按段序模板拼**"：即一个模板声明"我由哪几类段构成"，组合时只在**同族、同段位**之间替换。例：`hook` 槽位只能换同族的 hook 段，不能把 outro 塞进去。

**结论**：G2 的形态不是"乐高任意拼"，而是**"骨架固定 + 段位可换肤"**——这既保住审美，又让 N 个模板产生 N×k 种表现。

### 4.5 组合矩阵：这是"从 10 个扩到 50 个效果"的可行路径

```
表现数 ≈ 骨架数(10) × 主题(4) × 卡变体(4→7，Phase2) × 构件组合(9)
维护面 = 10 个骨架 + 1 个段库 + 1 个构件库   （不是 50 份各自腐烂的 manifest）
```

每新增一个构件，**同时给所有骨架升级**；而新增一个整片模板，只影响自己。这是可持续扩充的唯一形态。

## 五、回退：必须机器判定，不能靠模型自觉

### 5.1 五条可计算的判据（后两条是实测新增，见 §12）

| # | 判据 | 算法 | 触发后 |
|---|---|---|---|
| 1 | **容量** | Σ(内容必需字数) > 候选模板 Σ`slots[].maxChars` | 排除该模板 |
| 2 | **素材** | 模板 `meta.assets` 需 N 张，用户实际 0 张 | 排除（复用 `recipe` 的 `status:'pending'` 阻断思路） |
| 3 | **时长** | 内容时长 ∉ [模板 `minDuration`, `maxDuration`] | 排除或走 G2 重排 |
| **4** | **条目数** | 用户原话列举 N 条 > 模板 `cardN.*` 的条目位数 M | 排除，提示"合并到 M 条或换模板" |
| **5** | **信息充足度** | 用户原话显示字数 / 必填槽位容量总和 < **35%** | 排除，提示"先补素材或改自由编排" |

**为什么必须有 4 和 5**：§12 实测出 `compile()` 只判格式 —— 用户说 4 条而模板 3 卡时，第 4 条被**静默丢弃**且 `ok=true`；用户只说一句话时，其余槽位全靠**编造**且 `ok=true`。这两条靠提示词治不住（模型宁可硬套也不肯说"模板不合适"），只能机器判。

五条都在**选模板阶段**算，不需要模型思考；任一不通过 ⇒ 走起点 B/C。
实现见 `原型-template-fit-gate.mjs`（6/6 判定正确 + 反向变异两条都能变红）。

### 5.2 模型什么时候可以"自主选模板"

总原则①的「非常确定」= **以下全部成立**：

1. 用户没指定模板，但指定了体裁 / 时长 / 素材
2. `list_templates` 返回**恰好 1 个**通过五条判据的模板（0 个 → 自由编排；≥2 个 → 把候选列给用户选，不要自己拍）
3. 该模板的 `meta.family` 与本片体裁一致

**≥2 个候选时不许模型自己挑**——这正是"审美不稳定"的来源：模型的偏好不可复现，让用户选才是稳定解。

### 5.3 回退必须显式

返回里写清「未匹配模板，已按自由编排生成」+ 原因（容量/素材/时长/条目数/信息充足度）。静默降级会让用户以为是模板效果差。

### 11.2 途中发现的两条关键规律（会直接改实现）

**规律 1：`maxChars` 不能按"不 overflow"定，必须按"字号不降"定。**

实测对照：`b1-badge` 的 box 只有 137.9px 宽、基准字号 19px。

| 判据 | 能塞字数 | 实际字号 | 可用性 |
|---|---|---|---|
| 只看"不 overflow" | 13 字 | **10.5px（基准的 55%）** | 不可读 |
| **判据加 `fontPx >= baseFontPx`** | **7 字** | 19px | 版式稳定 |

⇒ `auditCapacity()` 的判据必须是 `!overflow && !overBox && fontPx >= baseFontPx`。
这条同时解释了为什么模板能"解决审美不稳定"：**它宁可让用户删字，也不让字缩水**。

**规律 2：字符计数必须按显示宽度加权，不能按字符数。**

`card1.no` 的值 `"01"` 是 2 个字符但只占 1 个字宽（两个半角 = 1 个全角宽）。
按字符数算会把它判成超长（实测踩到：原文回填三组全红）。

⇒ 统一口径 `displayLen()`：**全角 = 1，半角 = 0.5**，`slots.json` 的 `maxChars` 与编译校验同口径。
usage 里对用户/LLM 的表述也要一致：「压到 N 个全角字内（半角算半个）」。

### 11.5 容量审计已抽成可复用件（第 2~50 个模板不再人拍数字）

产物：

| 文件 | 作用 |

| `原型-audit-text-fit.mjs` | 模块 + CLI。`auditTrack` / `auditTemplate` / `reconcile` / `scanSlots`；直接 import 仓库真实函数（`subtitleFitBudget` / `dataCardMetrics` / `fitTextPolicy`），不复制公式 |

#### 发现 1（设计错误，已修）：四个 variant 是**两套**排版模型

`b1b2` 模板只用到 `subtitle` + `title`，另外两个分支此前**一次也没被真实数据检验**。抽模块时逐条对源码才发现：

| variant | 排版方式 | 容量算法 |
|---|---|---|
| `subtitle` | `fitTextPolicy` 折行 + 缩号 | 二分（`maxWidthPx` **已扣** `padX` 16×2） |
| `title` | 同上，但 `maxWidthPx = canvasWidth*0.9`，**完全不看 box** | 二分 + **容器裁切检查** |
| `bullets` | `fitTextPolicy` + 内层写死 `width:900` + 每行 42px 圆点 | 二分（**必须扣 42**，否则每行多算 0.9 字） |
| `dataCard` | **不走 `fitTextPolicy`**：`lines.join(' ')` 单行、字号固定 `40×scale` | **公式** `940/40 = 23`，与 scale 无关 |

第一版把 `dataCard` 归到 `bullets` 规则（48px / 6 行），会算出「能折 6 行」的假容量 —— 而组件物理上只有一行。

#### 发现 2（规则，已落）：容量必须留安全余量，「刚好等于」判不安全

`heading` 的 `box.w=21.88%` → 420.096px，5 个 84px 全角字正好 420px。几何上"放得下"，但比例字体的实际字形宽 ≠ `fontPx`（`fitTextPolicy` 无实测器时也走估算），**零余量在真机必然裁掉一点**。

⇒ 判据改为 `widest > containerWidth - 4px` 即算裁。`heading` 因此收敛到 **4**，与作者手写的 4 一致。

这条同时纠正了我自己的一次误判：旧实现给 `title` 减了 32px padding（那是从 `subtitle` 抄来的，`title` 的 div **根本没有 padding**），得出 4 是**错误原因碰巧对了**。现在是正确理由。

#### 发现 3（既有缺陷 ×3，模板化会把它固化，建议记入任务包但不阻塞）

| # | 缺陷 | 后果 | 本模块处置 |
|---|---|---|---|
| a | `title` 的 `maxWidthPx` 用 `canvasWidth*0.9`，**完全不看 box**，而 box 在场时容器只有 `box.w` 且 `overflow:hidden` | `title` + 窄 box ⇒ 文字被**裁**（不缩号）。与 `subtitle` 2026-11-04 修的是同一类事故，`title` 尚未修 | 审计器用 `clipWidthPx` 兜住；组件修复建议并入 0B |
| b | `bullets` 内层 `width: 900` 写死，不随画布/box 变；且 `maxWidthPx` 未扣每行 42px 圆点 | 窄盒被裁；1080p 下每行少算 0.9 字 ⇒ 填满必溢出 | 审计器已扣 42，窄盒按 `min(boxW,900)` |
| c | `dataCard` 容量恒 23 字，但矮盒把 `scale` 压到 0.28 ⇒ 标题只剩 **11.2px** | 容量审计**看不出**"字太小" | 已加可读性判定：`scale<0.6` → warn，`<0.4` → error |

#### 发现 4（语义）：审计器是守门员，不是独裁者

审计值 = **几何硬上限**（超过必然裁/缩）；作者声明 = **设计判断**（常常故意更小）。所以：

| 关系 | 判定 |
|---|---|
| `declared > 上限` | **违规**，必改成上限 |
| `declared < 上限` | **合法收紧**，保留作者值，只提示余量 |

实测 `b1b2`：`maxChars` **10/10 一致**，只剩 2 处 `maxLines` 是作者主动收紧（`keyword`/`heading` 物理能折 2 行，但主标题不该折行）。

#### 残余风险（诚实边界）

审计走 `fitTextPolicy` 的**估算**口径，真机用 Canvas **实测器**（`measureOptions`），中英混排可能差约 1 个字宽。
- 全中文文案：估算 = 实测（中文字宽恒等于 `fontPx`），可直接用。
- 中英混排：把审计值当上限，`slots.json` 可再留 1 字余量。
这条只能靠真机消除，已知且已记录。

## 12. LLM 填参验证与适配闸门（2026-11-10 夜）

P-3 只证明了「模板数据形态成立」。但模板的**价值前提**是另一件事：

> LLM 只读 `slots.json` 的 `id / label / maxChars / maxLines / usage`，就能把一段用户原话改写成合格的槽位值。

这一节就是验它。**结论：格式层面成立，内容层面不成立——必须补两条机器判据。**

### 12.1 六个用例与结果

6 段真实用户原话，覆盖 3 个正常体裁 + 3 个边界。填写时**不参考 `example`**（那是 6–8 字短句，对"15 字槽位怎么压"没有指导性）。

| # | 体裁 | compile 判定 | 人工判定 | 一致 |
|---|---|---|---|---|
| p1 | 产品介绍 | `ok` | 内容完整 | ✓ |
| p2 | 知识科普 | `ok` | 内容完整 | ✓ |
| p3 | 工作汇报 | **被拦**（`keyword` 8 > 7） | 超字数 | ✓ |
| p4 | 技术分享（含英文术语/数字） | `ok` | 内容完整 | ✓ |
| p5 | **用户说 4 条，模板只有 3 卡** | `ok` | **第 4 条被静默丢弃** | ✗ |
| p6 | **需求极短（一句话）** | `ok` | **9 个值全是编造** | ✗ |

一次过 3/6，正确拦截 1/6，**机器判 ok 但实际有问题的 2/6**。

一个附带结论：**p4 证明半角计 0.5 是对的**。`PostgreSQL`、`800ms` 这类术语按字符数会立刻爆表，按显示宽度却能放下 —— 这条口径不是理论推导，是实测需要。

### 12.2 两个机器看不见的缺口（本节最重要的产出）

| 缺口 | 表现 | 为什么提示词治不住 |
|---|---|---|
| **内容静默丢弃** | 用户列举 4 条，模板 3 卡 ⇒ 第 4 条消失，`compile` 返回 `ok=true` | 模型的失败模式是可预见的：宁可硬套模板，也不肯说"这个模板不合适"。它会挑 3 条最像的填进去，看不出丢了东西 |
| **内容不足时编造** | 用户只说"做个视频介绍新 logo"，模板强制 10 个槽位 ⇒ 其余 9 个全靠编 | `required` 加得越严，编造压力越大。这是"模板越完整，幻觉越严重"的反向效应 |

**这两条不能靠"在提示里写一句请自行判断"。** 必须在填槽之前用机器判据挡掉。

### 12.3 两条判据（已实现并验证）

`原型-template-fit-gate.mjs`：

| 判据 | 算法 | 处理 |
|---|---|---|
| **条目数匹配** | 扫用户原话的列举标记（`第一/第二`、`一是/二是`、`①②③`、行首 `1.`），去重计数；与模板 `cardN.*` 的 N 数量比较 | N > M ⇒ 拒绝，提示"合并到 M 条，或换条目位更多的模板" |
| **信息充足度** | `用户原话显示字数 / 必填槽位容量总和`；`< 35%` ⇒ 拒绝 | 提示"先补素材，或改自由编排" |

实测 6/6 判定正确（`p5` 4/3 拒绝，`p6` 16% 拒绝，其余放行）。

**反向变异（按本仓铁律，守卫必须能变红）**：

| 变异 | 结果 |
|---|---|
| 关掉条目数判据 | 变红 1 个（`p5` 被误放行）✓ 说明该判据不是空转 |
| 关掉信息充足度判据 | 变红 1 个（`p6` 被误放行）✓ |

途中抓到一个真实 bug：`p3` 实际 3 条却数出 6 条 —— `第一是` 同时被 `第(一)` 和 `(一)是` 两个模式命中，**翻倍**。加负向后视 `(?<!第)` 修正。

### 12.4 误判方向（有意保守）

判据 A 会把"第一次""第二步"这类**非列举**的序数词也算进去 ⇒ 偶尔多算、多拒一次。

这是有意选择：**多问一句的成本，远低于静默丢内容后用户发现"我说的第四点没讲"。**

### 12.5 对拍板项 P-9 的修订（必须改）

原 P-9 是三条判据（容量 / 素材 / 时长）。实测后应改为：

| # | 判据 | 来源 | 性质 |
|---|---|---|---|
| 1 | 槽位容量（内容压不进 `maxChars`） | 原 | 编译期拦（已有） |
| 2 | 素材（模板要 N 张图，用户 0 张） | 原 | 装配前 |
| 3 | 时长（模板 18s，内容需 60s） | 原 | 装配前 |
| **4** | **条目数（用户 N 条 > 模板 M 位）** | **本节实测新增** | 装配前，**必须机器判** |
| **5** | **信息充足度（内容 < 容量 35%）** | **本节实测新增** | 装配前，**必须机器判** |

并且：**5 条全过 + 候选恰好 1 个**，才允许模型自主选模板；否则回退自由编排，且**必须显式告知用户**（"没有匹配模板，已按自由编排生成"），不能静默降级。
