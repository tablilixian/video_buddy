## 四、总结论

1. **主字修复能力上，两版没有稳定差别**（旧模板也能修对）。不能用「修对没修对」判形态。
2. **真正的差别是「凭空增字」：旧模板 2/2 轮命中，新逻辑 0/1 轮命中。** 机理清楚 ——
   旧模板的开场句是**祈使式**（`确保画面中以下文字字符正确渲染 - "武侠"`），把「武侠」
   说成**要渲染出来的东西**，模型只能在画面里另找地方安置它；新逻辑给的是**位置规格**
   （「摊后竹架上挂一面写着毛笔字 "武侠" 二字的红色竖幡」），语义是「这个位置上的字要写对」，
   不产生「再放一个」的动机。
3. **样本量如实交代**：新逻辑只拿到 **1 次**成功样本（第二轮被后端排队挤超时），
   旧模板 2 次都增字。⇒ 结论方向明确，但**建议后端空下来后补 1~2 轮 B**，把样本补到 2~3。
   补跑命令（复用句柄、跳过 17s 上传）：

   ```bash
   node scripts/probe-image2fix-ab.mjs \
     --out docs/api-probe/image2fix-20260921-ab \
     --handle ref-311d500e.png --tag -r3
   ```

4. 附带一条**独立收获**：`queue_task_count` 的语义在本次两轮里被实测钉死 ——
   **含正在执行的那个**（独跑 = 1、再加一个排队 = 2、空闲 = 0、被并发占满 = 5）。
   判「有活在跑」用 `> 0`，判「空闲」用 `=== 0`。
