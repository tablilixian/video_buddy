## 1. 问题

逐帧比对（`/tmp/vf_check/vf_2.0.png` vs `_gtB1_2.0.png`、`vf_9.5.png` vs `_gt9.5.png`）后确认：

> 我们复刻成功的是**内容层**（文字、卡片、路径、错峰、时机）。
> GT 里还有整整一层**场景装饰**，我们一个都没做。

| 构件 | GT | 我们 | 能不能零扩展做 |
|---|---|---|---|
| 四角括线（corner brackets） | ✅ 每帧 4 个 | ❌ | ✅ **能** |
| 底部进度条（刻度 + 橙色游标） | ✅ 随进度推进 | ❌ | ✅ **能** |
| 右上时间码 `00:00:02:00` | ✅ 逐帧跳变 | ❌ | ❌ 需要动态文字 |
| 左上/左下章节标签 | ✅ | ❌ | ❌ 需要「裸文字」变体 |
| 柔焦径向光斑 | ✅ 中心偏右 | ❌（硬边圆盘） | ❌ 需要径向渐变形状 |
| 星点背景 | ✅ | ❌ | ✅ 能（但轨数多） |
| 玻璃卡（圆角+描边+半透明） | ✅ | ❌（直角实色） | ❌ 需要 shape 外观字段 |
| 发光实线（vs 我们的虚线） | ✅ | ❌ | ❌ 需要 dash/辉光 |

**差距 #9 的根因不是「画不出这些」，是「没有任何东西把它们固化下来、复用」。**

## 2. 档位划分（**先把边界划清，别一上来就扩契约**）

### 1C-min · 零契约扩展（**Phase 0 做这个**）

只用现有轨型组合出来：

| 构件 | 展开成 | 备注 |
|---|---|---|
| 四角括线 | **8 个 `shape:'rect'`**（每角 2 条） | 细长矩形定位即可；`shape` 轨豁免 box/animate 互斥与出画布检查 |
| 底部进度条 · 刻度 | **N 个 `shape:'rect'`**（GT 约 40 条） | 极窄 rect，`box` 给中心+尺寸 |
| 底部进度条 · 游标 | **1 个 `shape:'rect'`** + `animate.x` 走全程 | `shape` 轨可以同时有 `box` 和 `animate.x` ✅ |
| 星点背景（可选） | N 个 `shape:'circle'` 极小点 | 轨数多（40–80 条），**可选**，先不做 |

> **为什么用 rect 而不是 path 画括线**：`shape:'path'` 的坐标空间是 0–100 双轴百分比 + `preserveAspectRatio="none"` ⇒ 16:9 下**非等比**，一条竖线和一条横线的像素长度没法取同一个值。8 个 rect 更笨但更准，且零契约扩展。

### 1C-full · 需要契约扩展（**Phase 2 做**）

| 构件 | 需要什么 |
|---|---|
| 裸文字（无底块） | `textCard` 新 variant `bare`（现在 `subtitle` 写死 62% 黑底、`title` 写死 35% 黑底 —— 见 `TextCard.tsx:222-228` 与 `:253`） |
| 章节标签 | 同上（`bare` + 左上/左下定位） |
| 动态时间码 | `textCard` 新能力（可参照既有 `countUp` 的动态数字机制） |
| 柔焦径向光斑 | `shape` 新 kind `radial`（径向渐变 + 羽化） |
| 玻璃卡 | `shape` 加 `radius` / `stroke` / `opacity` |
| 发光实线 | `shape` 加 `dash` / 辉光参数 |

## 3. 架构：构件 = 声明式配方 → 展开成现有轨道

**关键：不新造渲染管线。**构件是一个**纯函数**，输入「构件规格 + 画布尺寸」，输出**普通 manifest 轨道数组**。渲染器完全不知道构件的存在。

```
furniture.json（模板声明）
   { "id": "cornerBrackets", "params": { "inset": 2.4, "arm": 1.2, "thickness": 0.08, "color": "#5b6b86" } }
        ↓  expandFurniture(spec, canvas)  ← 纯函数，可单测
   manifest.tracks[]（普通 shape 轨）
```

### 3.1 新文件 `src/remotion/furniture.ts`

```ts
/** 构件 id（1C-min 落地 3 个；1C-full 补齐其余）。 */
export type FurnitureId =
  | 'cornerBrackets'   // 四角括线
  | 'progressBar'      // 底部进度条（刻度 + 游标）
  | 'starfield'        // 星点背景
  | 'bareLabel'        // 裸文字标签（1C-full）
  | 'timecode'         // 动态时间码（1C-full）
  | 'radialGlow'       // 径向光斑（1C-full）
  | 'glassCard'        // 玻璃卡（1C-full）

export interface FurnitureSpec {
  id: FurnitureId
  /** 构件参数（各构件自己的字段，见 §3.2）。 */
  params?: Record<string, unknown>
  /** 起始帧（绝对）。缺省 0。 */
  startFrame?: number
  /** 结束帧（绝对）。缺省 = 到片尾。 */
  endFrame?: number
}

export interface FurnitureContext {
  canvasWidth: number
  canvasHeight: number
  fps: number
  totalFrames: number
}

/** 展开成普通 manifest 轨道。纯函数、零 IO、可单测。 */
export function expandFurniture(spec: FurnitureSpec, ctx: FurnitureContext): FurnitureTrackDraft[]
```

> `FurnitureTrackDraft` 用 manifest 的轨道字段形状（`type/id/box/color/…`），**不新建类型** —— 展开完直接塞进 `manifest.tracks`。

### 3.2 构件参数（1C-min 的三个）

**`cornerBrackets`**
```jsonc
{
  "inset": 2.4,        // 距画布边缘的百分比（GT 约 2.4%）
  "arm": 1.2,          // 单边长度（画布百分比）
  "thickness": 0.08,   // 线宽（画布百分比）
  "color": "#5b6b86",
  "corner": "all"      // "all" | "tl" | "tr" | "bl" | "br"
}
```
展开 = 8 个 rect（每角 2 个：一条竖、一条横）。矩形的 `box` 用**中心 + 尺寸**语义：
- 左边那条竖线：中心 x = `inset`，中心 y = `inset + arm/2`，宽 = `thickness`，高 = `arm`
- 上边那条横线：中心 x = `inset + arm/2`，中心 y = `inset`，宽 = `arm`，高 = `thickness`
- 右侧 / 底部镜像。

**`progressBar`**
```jsonc
{
  "bottomInset": 3.2,   // 距画布底部的百分比
  "left": 4.4,          // 起点 x（百分比）
  "right": 95.6,        // 终点 x（百分比）
  "ticks": 40,          // 刻度数
  "tickWidth": 0.16,    // 单条刻度宽（百分比）
  "tickHeight": 1.1,
  "tickColor": "#2a3648",
  "cursorWidth": 0.55,
  "cursorColor": "#f2a33c",
  "cursorTravelFrames": 1080   // 游标走完全程的帧数
}
```
展开 = N 个 rect（刻度）+ 1 个 rect（游标，`animate.x` 从 `left` 走到 `right`）。

> **游标用 `animate.x` 走全程**：`animate.x` 是 0–100 百分比位置，`translate((x−50)%, (y−50)%)`。游标 rect 的 `box` 给 `y` 与高度，`animate.x` 给 `from`/`to`。**`shape` 轨豁免 box/animate 的 x/y 互斥**（契约文档明写），所以两者可共存 ✅。

**`starfield`**（可选，成本高，轨数多）
```jsonc
{ "count": 60, "seed": 11, "maxRadius": 0.05, "color": "#cfe4ff", "alpha": 0.7 }
```
展开 = N 个 `shape:'circle'`。**注意 `shape` 轨没有 `opacity` 字段** ⇒ 亮度只能靠 `color` 本身（写死一个偏暗的色值），或等 1C-full 的 `opacity`。

### 3.3 构件的「帧内动态」怎么表达

- 括线 / 刻度：**静态**（可整段出现/消失，用 `startFrame`/`endFrame`）。
- 游标：**帧内连续移动** ⇒ 用 `animate`（既有能力）。
- 光斑：**帧内呼吸** ⇒ `animate.opacity` 或 `animate.scale`（既有能力）。
- 时间码：**帧内内容变化** ⇒ 1C-full 的新能力。

⇒ **1C-min 完全不需要新契约。**

## 5. 验收

### 5.1 单测

| 断言 | 期望 |
|---|---|
| `expandFurniture(cornerBrackets, 1920×1080)` | 返回 **8** 条 `type:'shape'` 轨 |
| 括线 8 条轨的 `box` 中心 | 都在画布四角内侧；左边两条 x = `inset`；上边两条 y = `inset` |
| `expandFurniture(progressBar, …)` | 返回 `ticks + 1` 条轨；**最后一条是游标**且带 `animate.x` |
| 游标 `animate.x` 的 from/to | 映射到 `left` / `right`（百分比） |
| `expandFurniture(starfield, …)` | 返回 `count` 条轨，**位置确定**（同 seed ⇒ 同结果，**确定性**） |
| 同一 spec 展开两次 | 结果**逐字节相同**（无随机、无时间依赖） |
| `expandFurniture` 未知 id | 抛错 or 返回空数组 + warning（**选一种并写进文档**，别默默返回空） |
| `expandFurniture` 缺 `ctx` | 抛错（不许静默出 0 尺寸） |
| 展开出的轨道过 `validateManifest` | `ok=true, 0 error`（**零契约扩展的证明**） |

### 5.2 端到端

1. 把 `cornerBrackets` + `progressBar` 展开成轨道，加进 `原型-manifest-b1b2.json`。
2. `render_composition` 渲一次，抽帧：
   - **四角**各有 L 形括线，位置与 GT 观感一致（GT 参考帧：`/tmp/vf_check/_gtB1_2.0.png` / `_gt9.5.png`）。
   - **底部**有刻度条 + 一个橙色游标，且**游标位置随时间从左走到右**（抽 3 个时刻验证游标 x 单调递增）。
   - **原画面的所有元素位置逐像素不变**（构件是纯追加 ⇒ 不影响既有轨）。
3. 与 GT 视觉比对：括线 + 进度条在位后，「GT 是整帧设计、我们是元素流」的观感差距**明显缩小**。

## 6. 与任务包 1（模板库）的接口

| 谁 | 负责什么 |
|---|---|
| **1C** | 构件库（`expandFurniture`）+ 构件参数规格 |
| **1（模板库）** | 模板目录 `templates/<id>/furniture.json` 声明「本模板用哪些构件 + 参数」，由**模板编译器**在生成 manifest 时调 `expandFurniture` 展开 |

⇒ **1C-min 不需要知道模板目录长什么样，1 需要知道 `expandFurniture` 怎么调。** 两者可并行，接口点就是 `expandFurniture(spec, ctx) → tracks[]`。

如果任务包 1 决定在 `manifest` 顶层加 `furniture?: FurnitureSpec[]` 字段由渲染器展开 ⇒ 那 1C 需要改 `manifest.ts` + 渲染侧；**建议不要**（渲染器不认识构件 ⇒ 等于把机制塞进热路径）。**推荐：模板编译器期展开，渲染器只吃普通轨道。**

## 8. 已知的坑

1. **`shape` 轨的 `box` 是中心语义**（`x`/`y` 是中心百分比，不是左上角）⇒ 括线算位置时**极易算错半屏**。写完先用单测锁住 8 条轨的中心坐标。
2. **`shape` 轨豁免 box/animate 互斥** —— 这条是**有利条件**（游标能同时用 `box` 定 y、用 `animate.x` 动 x），但别因此以为其它轨也能这样（`textCard` 不行）。
3. **`shape:'path'` 是 0–100 双轴百分比 + 非等比** ⇒ 画 L 形括线别用 path，用 8 个 rect。
4. **`shape` 轨没有 `opacity`** ⇒ 星点亮度只能写死在 color 里。
5. **构件展开必须确定性**（星点要固定种子）⇒ 不能用 `Math.random()`。
6. **构件是纯追加** ⇒ 追加到 `tracks` 末尾，别插在中间（轨序影响叠放层级）。
7. **GT 括线颜色是低饱和蓝灰**（约 `#5b6b86`），别用纯白 —— 太亮会盖过内容。
