# 错误码对照表（遇到就查这里，别去读源码）

> 目标：**看到错误码就知道该改什么**。每条都写清「谁的问题」——画面内容、素材、环境，还是参数。
> 全文只覆盖组装 / 渲染这条链路上模型会撞到的码；更全的定义在 `src/errors/catalog.ts`（那是开发侧文档，不用你读）。

## 三个通用原则

1. **不要原样重试**。同一个 manifest 再提交一次，只会再失败一次；先按下面的「该改什么」改一处。
2. **报错里的定位是准的**（`tracks[i]` / 字段名 / 轨 id），按点改，别整段重写。
3. **区分"内容问题"和"环境问题"**：内容问题改了就能过；环境问题（工单没被取走、渲染组件不可用）改画面没用，**直接告诉用户并建议重启客户端**。

## 渲染链路

| 错误码 | 什么时候出现 | 该改什么 | 别做什么 |
|---|---|---|---|
| `CS-RENDER-TIMEOUT` | 工单在预算内没结算。文案里带 `{diagnosis}` 与 `工单：…` 行 | 看诊断分三种：**从未取走 / 已取单但没渲染** = 环境问题（重启客户端，别改画面）；**已渲染 Ns、进度 X%** = 内容问题（缩时长 / 降分辨率 / 减轨道） | 不要反复提交同一份 manifest；不要按"加长超时"思路改 |
| `CS-RENDER-002` | 客户端渲染失败（素材读不到、格式不支持、渲染器崩） | 先核对素材：同源 URL 是否还在、格式是否受支持（PNG/JPG/MP4）；`list_shots` 复查片段是否仍有效 | 不要换 manifest 结构硬试 |
| `CS-COMP-002` | 某片段转码失败（该片段被跳过，合成继续） | 用 `extract_last_frame` 或重新生成该片段；确认源视频没有损坏 | 不要以为"整片失败"——降级信息在 warnings 里 |
| `CS-COMP-001` | 没有任何可合成片段 | 先 `list_shots` 选片；确认节点没被废弃 / 取代 | —— |
| `CS-FFMPEG-001` | 宿主缺视频处理组件 | 环境问题：告诉用户，别继续试 | 不要改 manifest |

## 入参与校验

| 错误码 | 什么时候出现 | 该改什么 | 别做什么 |
|---|---|---|---|
| `CS-USER-ERR` | 通用入参 / 内容校验失败（**最常见**） | 按 message 指出的字段改一处；manifest 结构问题会指出 `tracks[i]` | 不要整段重写；不要忽略 message 只重试 |
| `CS-PARAM-002` | 参数里写了占位值（`TODO` / `xxx` / `待定` / `...`） | 换成真实值；确实还没定就先用 `ask_user_choice` 问 | 不要留占位值蒙过去 |
| `CS-GEN-206` | 生成接口返回后端错误 | 看 `safe` 里的原因；**产物名不能当输入**（要引用画布节点 `@ref[标题]` 或先 `upload_image`） | 不要把 `filename` 直接喂给下一个生成工具 |
| `CS-DEV-ERR` | 内部缺陷 | 如实告诉用户"这是产品 bug"，附上报错原文 | 不要自己猜着改画面掩盖 |

## 什么时候该停下来问用户

- 报错里出现**"环境"**字样（渲染窗口/组件/权限）且重试一次仍一样；
- 需要用户决定内容取舍（时长、旁白、素材替换）；
- 同一个错误码连续 **2 次**改不动 —— 第三次之前先汇报，而不是继续试。
