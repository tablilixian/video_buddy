**⚠️ 源字体换源（许可驱动）**：思源黑体带 OFL **保留字体名（RFN）`with Reserved Font Name 'Source'`**，子集属 Modified Version **须改名**，而实测 `preserveNameIds: []` **仍保留保留字体名**（name 表 9 条照旧）⇒ 改用 **Noto Sans SC**（族名本身不含 `'Source'`，无 RFN 债，`OFL.txt` 原样随附）。

## 三、四个设计问题的定论（速查）

### 3.1 字体系统怎么落地 / 交互是什么
见 **§R1**（✅ **R1 已落地，2026-10-16，CV-328**）。一句话：**构建期子集中文随包 + 运行期 `fonts.ts` 解析 / `@font-face` 同源注入 / `document.fonts.load` 闸门 + 缺省离线兜底**；用户默认零交互，只有「声明了未随包字体」时在结果 `warnings` 里出现一行回退提示。

### 3.2 是否已能跟现有视频生产流程结合
**契约层已结合、流程层半结合。**
- **已结合**：`render_composition` 已注册为真实工具（8 处登记全绿）；产物复用 `appendComposedVideoNode` 落**同一种 `video-composite` 节点**（血缘指向 manifest 素材）；返回结构与 `compose_video` **完全相同**（客户端零改动即可展示）；共用同一审批门口径与错误目录。
- **半结合**：总纲第 10 步仍只认 `compose_video`（见 §R6）；B4 skill 与总纲是"下游分支 / 定稿之后"关系，未写进总纲工作流编号。
- **未结合**：成片质量门（R2）、打包发行态（R5）。**字体（R1）已于 2026-10-16 落地（CV-328）**，成片侧中文与 manifest 字体声明**现已接上**（待桌面观感验收）。

### 3.3 什么情况下触发 Remotion 线路
三条并行触发路径（**任一即可能**）：
1. **工具描述自选**：`render_composition` 的 description 明写「字幕卡 / 数据卡 / 标题卡 / 形状 / 图文幻灯片 / 转场……需卡片/逐帧精确控制时用；纯片段拼接仍用 `compose_video`」——模型按任务语义自选。
2. **skill 激活集**：用户在画布顶条勾选 `code-driven-explainer` → 写入项目 `skills.json` → 经 order 154 小节注入 system prompt（CV-323）→ 模型可见并按其五步工作流走。
3. **catalog 自加载**：`code-driven-explainer` 的 frontmatter description 带触发词（科普 / 教育 / 讲解 / 知识短片 / 数据可视化 / 带字幕卡·数据卡的视频 / 代码合成），模型可自行 `skill(name=...)` 加载。
> ⚠️ **未闭环处**：因总纲第 10 步只写 `compose_video`，在未勾选 skill、且用户措辞没踩到触发词的"灰区"（如只说"把这几段素材做成一条片"），模型可能仍走 `compose_video`。这正是 §R6 要修的路由。

### 3.4 Remotion 线路的设计步骤是否体现在故事板上
**不体现，且是刻意设计。** devdoc §4.6 定稿：**storyboard（§00–§08）仍是全片规划的"事实源"，`CompositionManifest` 只是渲染层派生**，两者**不双向同步**。
- B4 的「设计步骤」= 组装 manifest 的过程；其对用户的可见形态是**澄清环节的对话预览**（`ask_user_choice`：轨道时序表、video 轨「声明/真值」两列、字幕卡每句起止帧），**不是**故事板里的新章节。
- 数据来源方向是 **storyboard → manifest**（读 `narration.lines` + `storyboard.scenes[].shots` + 已落画布素材）。
- 成片出来后，作为**画布上的 `video-composite` 节点**呈现（含血缘分镜卡 → 锚点 → 创意）。
- ⇒ 若产品希望「卡片 / 转场规划也进故事板让用户拍板」，那是**新增设计**（需扩 storyboard 契约 + 落地映射 + skill 流程），**当前 devdoc 未规划**，不在 R1–R6 内。
