## 0. P0 之后还缺什么（一句话诊断）

P0 把「锚点」和「纪律」做出来了，但都长在**模型可见的文本里**：

- 时钟行只追加在工具返回末尾 → 原本只挂本插件工具，`bash` 风暴时完全看不见（**P1-2 已修**）；
- 锚点文件由宿主写 → 但没有任何界面读它；
- 段边界只冻结在 builder 里 → 模型绕过 builder 直接写 JSON 就失效。

所以 P1 的主题是：**把纪律变成界面与机器判据，而不是靠模型自觉**。

### 0.1 三条被实测推翻的判断（2026-11-05 晚复查源码后修正）

| 原判断 | 实测 | 影响 |
|---|---|---|
| P2-3「跨仓读源码探测」需 dsh 侧钩子，属跨仓 | `tools/execute` 是 **ToolRuntime 上的 waterfall**，对**所有**工具（含 `bash` / `read`）触发，`exec` 带 `name` + 解析后的 `arguments` | **无需改 dsh 本体** ⇒ 已并入 P1-2 落地（`src/milestone-guard.ts`） |
| P1-1 需要新增 `GET /canvas-studio/progress` 路由 | 客户端 `api.ts` 已在 `normalizeWorkflow(response.workflow)`，P0 加进契约的 `landedAt` / `firstDraftAt` **已经随项目数据到达客户端** | 路由可省；只差「1s ticker + 展示组件」。若要做「最佳版本」再加字段，仍不必新增只读路由 |
| P2-2「压缩摘要指针化」只是 dsh 侧改动 | `compaction-basic` 的配置只有 9 项（`thresholdRatio` / `headroomTokens` / `retainRatio` / `retainTokens` / `summarizationProvider` / `summarizationModel` / `maxTokens` / `compactionRetries` / `maxOverflowRetries`），**没有 prompt 注入点**；改 prompt 必须动 submodule（违反仓库铁律） | **硬卡点**：只能降 `maxTokens` 从物理上封顶，或放弃 |

> 附带修复（P0 冒烟时暴露，已在同批处理）：`tests/video-jobs.test.mjs` 的 `rm(dir)` 与
> `tests/remotion-render-report.test.mjs` 的 `timeoutMs: 5_000` 在**满负载 / 沙箱收紧**下会
> 假红（前者实测 EPERM：沙箱拒绝递归删除 `$TMPDIR`；后者 5s 预算在高并发下不够）。
> 已按 `withProject` 的既有取向处理：清理失败忽略、工单预算 30s、轮询预算 15s ——
> 判据仍是「最终会发生」，真卡死照样红。

## 1. P1（下一批，建议顺序 P1-1 → P1-3 → P1-2 → P1-4）

### P1-1 里程碑看板（用户可见）★ 最高优先

| 项 | 内容 |
|---|---|
| 现状 | `landedAt` / `firstDraftAt` 只进工具返回文本（模型侧） |
| **修正** | **不需要新增 HTTP 路由**：`api.ts` 已 `normalizeWorkflow(response.workflow)`，两个时间戳随项目数据到客户端。缺的只是「1s ticker + 一条状态条」 |
| 要做 | 新增 `src/client/milestone-store.ts`（模块级 store，抄 `render-progress.ts` 范式）+ `MilestoneBar.tsx`（54 行的 `RenderProgressBadge` 即模板）；`StudioFrame.tsx` 只加一行挂载（**行数棘轮：该文件 3,286 行，不许内联**） |
| 展示 | `T+13min · 尚无成片 · M1 剩 7min`；有片 → `已达成 · v1 · 45.0s`；超线 → 红色 + `已超硬线 6min` |
| 为什么 | 今天 3h37m 里用户唯一的信号是"滚动的思考"。**界面上看得见 T+ 与「尚无成片」，用户 20 分钟就能当场叫停** |
| 验收 | 真机：落地后顶条出现计时；渲出首片后变「已达成」；把系统时间前进 21 分钟 → 变红 |
| 反向变异 | 删掉 `overDeadline` 判定 → 顶条应永不显示"超线"（测试必须红） |

### P1-3 `scaffold_manifest({ writeTo })`✅ 已实现（2026-11-05）

| 项 | 内容 |
|---|---|
| 实现 | `src/milestone-guard.ts`（纯函数）+ `tool-error-boundary.ts` 放开「只挂本插件工具」的闸门 + `index.ts` 组装 |
| 口径 | 计数 = **距上次成功出片以来的工具调用数**（含 dsh 自带工具）；`renders === 0` 才出警；探针/快验/失败渲染都不算成片；计数只在**已落地**之后推进 |
| 阈值 | 空转 40 次（+20 退避）、读 `src/remotion/**` 8 次（+8 退避）；两条可同时命中，空转在前 |
| 为什么不重置就误报 | 正常 R0–R6 每轮都出片，单轮 40–60 次调用 ⇒ **不重置会把健康的片子判成空转**，所以出片即归零 |
| 单测 | `tests/milestone-guard.test.mjs` 9 条；反向变异两处：阈值 40→400（3 红）、删掉出片重置（8 红） |
| 已知边界 | 计数按 cwd 维度（≈项目），上限 8 条；`write` 不算读源码（防误伤正常改码）；阈值 40 待真机分布校准 |

### P1-2 原规划（保留以备对照）

| 项 | 内容 |
|---|---|
| 现状 | 模型可以连续几十步只读不产出，没有任何机器信号 |
| 要做 | 内存计数器（按 projectId）：自 `landedAt` 起记录 **canvas 工具**调用数与 `render_composition` 成功数；当 `调用数 > 40 且 render 成功 = 0` 时，在每次 canvas 工具返回末尾追加一行强提示（含三条建议动作） |
| 改哪 | `src/tool-error-boundary.ts`（时钟提供者旁边）+ `src/milestone-counter.ts`（新文件，纯函数可测） |
| 边界 | 只统计**本插件工具**（`STUDIO_TOOL_NAMES`）；dsh 的 `bash` / `read` 看不到 —— 所以阈值按"canvas 工具调用"算，不是按步数。已知盲区：模型全程只跑 bash 时不触发（记为 P2 的跨仓项） |
| 验收 | 单测：喂 41 次 canvas 调用 0 次渲染 → 返回提示；喂 41 次 + 1 次渲染 → 不提示；真机：故意只读不渲，应看到提示 |
| 反向变异 | 把阈值改成 400 → 测试红 |

### P1-3 `scaffold_manifest({ writeTo })`

| 项 | 内容 |
|---|---|
| 现状 | 骨架 JSON 只能回显到对话里，模型再抄一遍写盘（60KB 级回显 + 截断风险） |
| 要做 | 新增可选参数 `writeTo`（绝对路径，须落在项目目录内）；给了就直接落盘，返回 `path` + `trackCount` + `bytes`，**不回显完整 JSON**（只回显前 40 行供人核对） |
| 改哪 | `src/host-tools.ts` 的 `scaffold_manifest`（+ 路径校验走 `registry.projectDir` 前缀判断） |
| 收益 | R0 从「3 次调用 + 60KB 输出」降到「2 次调用 + 1KB 输出」；同时消掉"抄错一个括号"这一类失败 |
| 验收 | 单测：传 `writeTo` → 文件存在且过 `validateManifest`；传项目外路径 → `CS-USER-ERR` 拒收（零副作用） |

### P1-4 段边界 diff（不拒收，只报告）

| 项 | 内容 |
|---|---|
| 现状 | builder 有断言，但模型绕过 builder 直接写 manifest 时没有任何检查 |
| 要做 | `render_composition` 成功时，把它与 `build/versions/v1.json` 的段边界比对；不一致则在 `warnings` 里追加一条：`段边界相对 v1 变了（8 段 → 9 段，V3@300 变了）：如果是重排，请在汇报里说明` |
| 为什么只报不拒 | 重排有时是合法的（旁白重新合成）。拒收会把合法的返工挡死；报告能让"重排"从静默变成可见 |
| 改哪 | `src/render-anchor.ts` 加 `diffSegments(baseline, current)` 纯函数；`src/host-tools.ts` 接线一行 |
| 验收 | 单测：段数变化 / 起点变化 / 完全一致三种判断；真机：改一句帧数后渲一次，warnings 必须出现 |

## 2. P2（跨仓 / 观察后再做）

| ID | 事项 | 为什么不在 P1 |
|---|---|---|
| P2-1 | **G4 max-tokens 兜底**：`turn/end reason=max-tokens` 且该步 0 工具调用时，强制落 `build/NEXT.md`（本次计划 + 下一步）再结束 | **半卡点**：触发点可观测（今天会话第 2、3 turn 的 `turn/end.reason.kind` 实测就是 `max-tokens`），但 ① `agent/turn-stopping` 载荷只有 `{agent, turn, signal}`，**没有 reason**，得靠 assistant 流自己记「上一次停止原因」；② **宿主替不了「落草稿」** —— 计划在模型脑子里，只能 `steer()` 注入一条「立刻写 NEXT.md」续同一 turn。`steer` 会改变 turn 语义，**验收只能真机**（要真跑到 max-tokens），单测只能测决策函数。建议降级为「不 steer，只写宿主观察段」再观察 |
| P2-2 | **G5 压缩摘要指针化** | **硬卡点**：`compaction-basic` 只有 9 个配置项，无 prompt 注入点；改 prompt 必须动 `deepseek-harness/` submodule ⇒ 违反仓库铁律。**替代方案**：把 `dsh-plugin-desktop/cordis.patch.yml` 的 `maxTokens: 32768` 调到 ~8k，从物理上封顶摘要膨胀（今天 8,886 → 29,420 字符就是这口子）。代价是该配置**全局生效**（非 canvas 会话的摘要也会变短），需你拍板 |
| P2-3 | ~~跨仓读源码探测~~ | **已作废并并入 P1-2**（`tools/execute` 对所有工具触发，无需 dsh 钩子） |
| P2-4 | **项目目录 slug 化**：今天 24/24 项目名 = prompt 前 N 字符（含全角冒号），每条 bash 都要加引号 | 涉及已有项目路径迁移，属"存量"，按纪律不做回填；新项目命名规则可在创建时加 slug 字段 |
| P2-5 | **builder `--append` 子命令**：不重写整个 spec，追加一条 visual | 目前 spec 只有 8–12 条，重写成本低；等真机确认"模型改 spec 时改错"再补 |
| P2-6 | **多版本成片对比 UI**（v1 vs v5 并排） | 先把 PROGRESS + 版本快照用起来，没有证据说需要对比 UI |

## 3. 验收路线（P1 做完后一起跑）

| 门 | 判据 | 测法 |

## 4. 不做（P1/P2 也不做）

- ❌ 不做「自动替模型渲一版」：manifest 是内容，宿主凭空造内容等于替用户做审美决策。
- ❌ 不把门槛从 20 分钟调成"可配置"：先跑 3–5 条片子看真实分布，再谈档位。
- ❌ 不做 P1 的审批门：M1 是产出纪律，不是需要用户点头的门。
- ❌ 不回填历史项目的 `landedAt`（老项目顶条显示"未记录起点"，不推断）。
